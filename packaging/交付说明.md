## 一、交付物是什么

发给人的就是仓库根的 **`StoryGraph-1.0.0-win64-2026-10-28.zip`**
（**67.8 MB / 279 个条目**），解压得到一个 `StoryGraph\` 文件夹（**146.7 MB**）：

**不需要装 Python，也不需要装任何依赖。**

## 二、怎么启动

### 图形界面

双击 `StoryGraph.exe`。

也可以带上参数，直接进到某一章：

```bat
StoryGraph.exe                                :: 空图，自己「➕ 导入章节 .rpy」
StoryGraph.exe D:\mygame                      :: 只加载该项目的资源表（xlsx）
StoryGraph.exe D:\mygame\game\script\ch01.rpy :: 把这一章导进剧情图并载入
```

> 「打开项目」**只影响资源表**（立绘 / 音乐 / 角色候选与缩略图），
> 不会把整部戏铺到剧情图上 —— 剧情图里只出现你自己导入的章节。

### 命令行

```bat
StoryGraph-CLI.exe validate D:\mygame
StoryGraph-CLI.exe build D:\mygame --engine unity --out D:\out
StoryGraph-CLI.exe table rpy2xlsx D:\mygame\game\script\ch01.rpy
StoryGraph-CLI.exe compile ch01.xlsx --source D:\mygame\game\script\ch01.rpy
StoryGraph-CLI.exe selfcheck
```

退出码：`0` 通过 · `1` 有错误/被门禁拦下 · `2` 用法或环境问题。

## 四、崩溃了去哪看

窗口程序没有控制台，所以崩溃会写进日志文件：

```
%LOCALAPPDATA%\StoryGraph\crash.log
```

（一般是 `C:\Users\<你>\AppData\Local\StoryGraph\crash.log`；
写不进去时退回 `%TEMP%\StoryGraph\crash.log`。）

日志里除了 traceback，还会带一段**静默失败清单**（`safeguard.report()`）——
那是"被兜住但出过错"的地方，排查时很有用。

想换位置就设环境变量 `STORYGRAPH_CRASH_LOG`。

## 五、重新打包

改完代码重新出 exe：

```powershell
pip install -r requirements.txt pyinstaller
powershell -ExecutionPolicy Bypass -File packaging\build_exe.ps1
```

脚本按顺序做五件事，**任一步失败就中止**（不产出可疑产物）：

1. 跑全量测试（不通过就不打包）；
2. `PyInstaller packaging\storygraph.spec`；
3. **用打出来的 exe 跑一遍自检**；
4. 报告体积；
5. `python packaging\make_release.py` —— 组装 `dist\release\`（exe + 模板 + demo +
   `快速上手.md` + `新手快速操作手册.md` + `manual_img\` + LICENSE）并压成 zip。
   **清单少一样就报错**（2026-10-21 那版 zip 的 xlsx/md/demo 全是 0，就是没有这一步）。

> 第 1 步在仓库约定里改成 **`python tools\fasttest\run.py`**（并行全量，4 分钟；
> 裸 `pytest` 串行约 21 分钟，且与别的 pytest 并发会互删临时目录）。
> 2026-10-27 这次就是：fasttest 全绿 → PyInstaller → `selfcheck` → `make_release`。

只想要产物、跳过前面的检查的话：


## 六、10-18 重打包修掉的两处"产物级"缺陷

这两条都是**拿真机项目（`D:\千连万理\RenPyTest\sr_general`，55 个脚本）跑全量
`cli.py build`，再把产物丢给 Ren'Py SDK 8.4.1 lint** 才暴露的 —— 单测全绿时它们就在，
因为没有任何用例把"整份产物"和"原文"对齐比过。

### 1. 去重把顶格 `}` / `##` 当成了"重复内容"（产物加载即崩）

- 现象：`screens.rpy` 里 8 个单独成行的 `}`，产物里只剩 1 个 →
  引擎报 `'{' was never closed`，**加载即崩**（退出码 1）。
- 根因：去重键是"单条语句的内容"，于是"内容相同的行"被当成"重复登记"。
- 附带伤害：另有 33 条 `##` 和 12 条 `####…` 分隔横线一起被吃掉 ——
  它们不影响语法，只把文件结构悄悄抹平，所以前几轮保真体检全是绿灯。
- 修法：**只有整段与上一段完全相同才跳过**（那才是"同一份块被挂了两次"）。
  产物顶格 `##` 从 9 条回到 95 条，顶格 `}` 从 24 条回到 28 条。

### 2. `show` / `scene` 的 ATL 块体被静默丢弃（35 处语法错）

- 现象：`show lan agreeable at right:` 下面空了 → `show statement expects a non-empty block`。
- 根因：这两条语句只建模了头行，`zoom` / `yoffset` 这些 ATL 属性**没有任何载体**，
  解析时静默丢掉。
- 修法：结构判据 —— 解析出来的节点**没有块体载体，就不许吃这条语句的块**，
  整块交逐字保真；`show` / `scene` 同时进"标准流程块头"表（它们是 Ren'Py 标准写法，
  不是"用户自定义语句"，不该催人去教工具）。
- 代价：**可编辑覆盖率 100% → 98.0%**（1757/1792，剩 35 条按逐字保真渲染）。
  那个 100% 本来就是假的：35 条被算成"完全可编辑"，而渲染时块体是丢的。

### 同一次里顺带修的（不算 P0，但都会骗人）

- **引擎 lint 闸门改成按"出处"判，不看措辞**：`File "…", line N:` 是加载/编译抛了异常 →
  阻塞；`game/x.rpy:N` 是脚本读进去了、lint 的意见 → 提示；只有 traceback 帧
  （`init python` 把 lint 跑崩，退出码还是 0）→ 阻塞。判据用 14 条真实引擎输出回归。
- **模板路径不再参与对账**（`{image}` 这类占位行）：从前「同步」会把它们当垃圾删掉（数据丢失），
  体检会把它们列进"文件丢了"。现在占位行与模板行共用同一判据。
- **`screens.rpy` 第 2 轮渲染 ≠ 第 1 轮**：保真块之后的注释每轮往上跳一拍，已修成幂等。

## 七、初版（2026-10-05）交付修掉的三个真实缺陷

以下三节是**初版交付时**的质检记录，保留作为历史；修法至今有效。

交付质检期间实测出来的，都不是"代码风格"问题：

### 1. Godot 导出的引擎中立 IR 被静默覆盖（数据丢失）

`export_ir('godot', …)` 先写 `story_ir.json`，紧接着写 `STORY_IR.json`。
在 **Windows / macOS 这种大小写不敏感**的文件系统上，这两个名字**是同一个
文件** —— 第二刀把引擎中立 IR 原地覆盖，而返回值仍然报了两个不同的路径
（消费者照单去读会读到错的那份）。

修法：Godot 适配数据改用**独立文件名** `GodotDialogueData.json`（与 Unity 的
`UnityDialogueData.json` 对齐），并且加载器 `dialogue_importer.gd` 里的
`res://` 路径与产物名**来自同一份常量**，改名不会再漂移。

> 这个缺陷此前**测不出来**：老测试只查 `story_ir.json` 存不存在 ——
> 而在 Windows 上它当然存在（就是被覆盖后的那一份）。

### 2. 打包后的命令行 `--help` 直接崩溃（功能不可用）

```
StoryGraph-CLI.exe --help
UnicodeEncodeError: 'gbk' codec can't encode character '\u2194'
[PYI-49864:ERROR] Failed to execute script 'cli_entry'
```

`--help` 文案里有「Excel ↔ .rpy 双向联通」。源码运行时开发机常常开了
`PYTHONUTF8`，看不出问题；打成 exe 后 Windows 控制台是代码页 936（GBK），
于是**连帮助都打不开**。更麻烦的是 CI：`validate` 崩掉时退出码是 `1`，
看起来像"校验不通过"，排查方向完全是错的。

修法：新增 `core/consoleio.py`，入口在**任何输出之前**把 stdout/stderr
换成 UTF-8；换不上就退到 `backslashreplace`（打不出的字符写成 `\u2194`，
信息不丢、绝不抛）。

### 3. 窗口程序崩溃后没有任何痕迹

`--noconsole` 把 stderr 接到空设备：Qt 起不来就是"双击没反应"，
一行日志都没有。修法：新增 `core/crashlog.py`，冻结环境下挂
`sys.excepthook` / `threading.excepthook` / `faulthandler`，
**只加痕迹、不改行为**（原来的钩子照常调用，退出码不变）。

### 顺带加固

- **导出的写盘改成原子的**（先写 `.tmp` 再 `os.replace`）：
  被中断 / 磁盘满时，产物要么是旧的完整版、要么是新的完整版，
  不会是**半截的 JSON** —— 半截产物比没有产物更坏（消费方读到语法错误，
  人却看到"文件明明在"）。改名失败会把临时文件清掉，不留残渣。

## 八、已知限制

- **只支持 Windows x64**（本次只在 Windows 上打包）。跨平台需要各自
  在目标系统上跑一次 PyInstaller —— PyInstaller 不做交叉编译。
- 首次启动比源码版略慢（Qt 插件从 `_internal\` 加载），之后正常。
- 未做代码签名：Windows SmartScreen 可能提示"未知发布者"，
  点「更多信息 → 仍要运行」即可。
- `OUTSIDE_BUILD_DIR` / `LABEL_COLLISION` 这类提醒是**设计内的**：
  生成物写到 `game\` 下会和原文抢 label，工具会拦下来并让你改到
  `build\renpy\`。这不是故障。
- **但"改到 `build\renpy\`"之后就没人再查重名了**（`labels_in_danger` 在那个位置返回空集）。
  所以「构建成功」至今只证明**这份产物自己语法对**，不证明拷进 `game\` 后不与原文抢 label。
  这是当前唯一还没收的 P0，交付时会口头说明。

## 十、10-28 这次重打包：带上了什么、修掉了什么

### 带上的（上次 10-27 那版之后新做的）

- **控制流导出只生成结构，不再把章节代码搬过来**：以前会把整章 **247 行**

- **「导出只能删掉再导」有正路了**：目标是手写/混杂内容时对话框会问一句，
  旧文件先备份成 `<名>.bak`（第二次是 `.1.bak`，绝不覆盖上一份）再覆盖；
  `force` **只**越过"目标配不上产物"，label 重名 / 语法错照拦。
- **「语法检查」会点名拼错的变量**：条件里读 `Plotnodes214`、节点里写的是
  `Plotnode214` —— 从前三种检查（`ast.parse` / Ren'Py lint / 真跑一遍）全都
  看不见，四条个人线永远不成立、全掉进同一个出口。现在导出与「语法检查」
  都会说一句"差一个字符"。
- **接线不再退化成草图**：编排层以「终局语句」收尾、或章节还没接进控制流时，
  接一条线是**改接**而不是画草图（10-27 夜那两轮）。
- **自动布局改回「分层 + 到头拐弯」**：同一层一直横着排、碰到舞台右缘才拐弯，
