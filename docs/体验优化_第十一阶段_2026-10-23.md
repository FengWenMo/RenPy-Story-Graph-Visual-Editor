## 一、那张图值钱的是哪四件事

把参考界面的截图拆开，只有四件事是"结构"，其余都是皮肤：

| 结构（抄） | 皮肤（不抄） |
| --- | --- |
| ① 顶部一行**模式标签**（剧本 / 资产 / 叙事地图…） | 它的品牌色、圆角、毛玻璃 |
| ② 左侧常驻**章节树 + 搜索**（文件 → 片段，永远看得见项目全貌） | 它的粉色选中、标签小圆点 |
| ③ 中间是**带行号与类型牌的正文**（不是表格、不是日志） | 它的行高、悬浮工具条 |
| ④ 右栏是**检查器**（`节点 / 片段 / 定位状态` 一行一个，值可复制） | 它的预览视频窗、时长预设 chips |

为什么皮肤一条都不抄：这个工具的颜色/字号/间距**只从 `ui_qt/tokens.py` 取**
（对比度按 WCAG 2.2 AA 核算过，有一批判据盯着）。抄一套新配色等于把那套
审计作废，换来的只是"看起来像另一个工具"。

## 二、学过来的四件事

### 2.1 左侧「章节导航」（新）

以前想打开项目里的另一章，只有两条路：剧情图（**只显示导入过的** label），
或卡片页顶上那个下拉框（**只显示当前这个文件**里的 label）。项目里另外几十个
文件在界面上等于不存在 —— 用户得先去 `game/` 目录里翻文件名。而剧情图里
没有块是**刻意的**（用户 2026-10-03 明确要求过），所以图也不能当目录用。

- `storygraph/app/chapter_index.py`（纯数据，不碰 Qt）：`build_index(root)`
  → `FileEntry{rel, path, labels[(name, line)]}`。
  **没有 label 的文件不列**（`options.rpy` / `gui.rpy` 这类只是噪音），
  读不出来的记进 `errors` 并在提示里说一声（不假装项目只有 39 个文件）。
- `storygraph/ui_qt/navigator.py`：`QDockWidget`（`objectName=chapterNavDock`），
  **不属于任何一页** —— 切页不丢。这正是它最大的用处：在卡片页改台词时，
  也想跳去别的章。
- **双击 / 回车才打开**，单击只选中。理由很实际：这一栏紧贴拍列表，
  手一滑就会换章，而换章 = 重读磁盘。
- 搜索按"文件路径 / 文件名 / label"过滤（大小写不敏感）；**搜文件命中时
  带它全部 label**（想看的是"这个文件里有什么"，不是一条空结果）；
  搜 label 命中时只留命中的那几个。
- `●` = 这个 label **已经在剧情图里**（`window_nav._sync_nav_marks` 由
  `_set_graph` 这个唯一同步点驱动，不会有"图变了导航没变"的路径）。
- 折叠状态**记住**（按文件路径），刷新后保持折着；搜索时一律展开
  （搜完还得点开才看得到，等于白搜）。
- 空状态说下一步："用「📁 打开项目」选项目根之后，这里会列出 game/ 下的章节。"

### 2.2 中间「剧本行」（`ui_qt/shot_list.py`）

拍列表原来一行是纯文字：

```text
  3 ◆ play_music · 播放音乐  track=bgm
```

读起来像日志。现在画成：

```text
 003  [语句]  play_music · 播放音乐   track=bgm …
 007  [跳转]  → ch01_roof
 002  [对白]  e： 还行，就是雨下了一整晚。
```

- **只换画法，不换控件**：`QStyledItemDelegate`。模型、`Qt.UserRole` 里的拍号、
  `item.text()`、`setCurrentRow`、分组标题行（`UserRole == -1`）**一个都没动** ——
  这些被几十条既有用例按"存错拍"级别的语义判过，换控件等于重写一遍。
- 类型牌判据与 `window_card._row_text` **同源**（先控制流、再语句、最后前缀），
  两边漂移会出现"列表写着跳转、牌子写着对白"。
- `☁ ⚑ ➜` **不再抄进正文**：牌子已经说了是旁白/分支/选项，而这三个符号在
  微软雅黑里没有字形（`⚑` / `➜` 会变豆腐块，与 2026-10-18 那个 `⚙` 同类）。
- 行号是 `拍号 + 1`，**不是列表行号** —— 有分组标题行时会差几行，
  不要混着用（`_beat_rows` 仍是唯一的"拍 ↔ 行"映射）。

### 2.3 右栏「属性表」（`ui_qt/inspector.py`）

以前右栏一上来就是卡片表单，"我在哪一拍、这一拍的源在第几行"**任何地方都没显示**，
想回源文件对照只能数拍号。现在顶上是一行一项：

```text
定位（这一拍在文件里的位置）
  文件      ch01.rpy
  label     ch01
  这一拍    1 / 13
  类型      对白
  源位置    .rpy 第 14–17 行
  说话人    e
```

- **空值那一行不显示**：写 `—` 和"这一拍没有说话人"长得一样，而后者才是有信息的。
- 长值**中略 + tooltip 全文 + 可选中复制**：`.rpy 第 217 行` 这种信息唯一的
  用途就是拿去搜/贴给同事。
- 数据由 `window_nav._sync_inspector` 从会话取，`_show_index` 每翻一拍刷一次。

### 2.4 顶部「模式条」

原来切页只有工具栏里的「✎ 编辑这一章的卡片」和「← 返回剧情结构」两个按钮，
夹在二十几个功能里。现在最上面一行是两个模式标签（🗺 剧情结构 / ✎ 卡片编辑），
与 `_set_page` **双向同步**（`blockSignals` 防环，`_set_page` 仍是唯一改页号的地方）。

## 三、不抄的四件事（明确写下来）

| 参考界面有 | 为什么不做 |
| --- | --- |
| 「纯文本 / RenPy / JSON / 多语言」多视图切换 | 我们的卡片就是结构化编辑器，再开一个"纯文本编辑"等于第二个编辑器（两套写回路径 = 两套 bug）。要看产物用「剧本表」与「演出预览」 |
| 右栏的视频预览窗 | 我们有独立的「🎬 演出预览」窗口（按拍合成、帧缓存、播放）。塞进右栏会把右边挤成两条 200px 的窄栏 |
| 「时长 + 200/500/1000ms 预设」 | Ren'Py 的时长写在 `pause 1.0` / `with dissolve` 这些**语句**里，不是拍上的一个字段。做成 chips 等于发明一个不存在的模型 |
| 它那套配色/字体/圆角 | 见 §一：我们的色值有单一真源与对比度审计 |

## 四、踩到的坑（都是真的发生过）

1. **Dock 标题与自绘标题重复**：第一版导航自带一行「章节」+ 计数 + ↻，而
   `QDockWidget` 的标题栏也写着「章节」——同一个词并排出现两次，白占 24px。
   现在数量写进 dock 标题（`章节 · 1 个文件 · 4 章`），↻ 贴到搜索框右边。
2. **模式条和这一页的十几个动作挤在同一行**：`addToolBar` 默认都进同一行，
   第一版截图里模式标签被挤在最左边、后面拖一长串按钮。加 `addToolBarBreak()`
   之后模式条独占一行。
3. **QSS 把 `QTreeView` 的展开三角吞掉了**：整个应用套着 QSS，`::branch`
   没有样式时分支箭头不画 —— 界面上文件行左侧一片空白，想折叠都找不到点哪儿。
   改成自己在文件名前写 `▾ / ▸`（`setRootIsDecorated(False)`）。
4. **双击文件行 = 打开第一章**：那是第一版的写法，于是"想收起来"的人被换章。
   现在文件行单击 = 折叠/展开，双击只对 label 行有意义。
5. **`↻` 字形**：`U+21BB` 在这台机器的 offscreen 字体里是个点。改成文字「刷新」。
6. **`isVisible()` 在还没 `show()` 的窗口上一律 False**：恢复布局时窗口通常还没
   显示，用 `isVisible()` 同步工具栏那个勾选框 → 启动就"没勾"。改 `isHidden()`。
7. **`QListWidget` 没有 `QApplication` 直接 abort**（不是抛异常）：新用例的前
   14 条跑过、第 15 条整个进程消失，没有任何 traceback。测试类补 `qapp` autouse。
8. **信号审计抓到一条真规矩**：`textChanged(str)` 接到带默认值的槽
   （`_on_search_changed(_text='')`）会被 `tools/audit_qt_signal_slots.py` 判可疑
   —— 默认参数正是"Qt 的 bool 被当成第一个实参"那个坑的形状。改成显式收下
   `text`：清空时立刻还原全表（不用等 120ms 防抖）。
9. **自己给自己挖的坑**：用 `Get-Content | Set-Content` 批量替换源码里的
   `ROW_H` —— PowerShell 默认按 ANSI 读、按 UTF-8 写，整个
   `ui_qt/inspector.py` 的中文注释变成了乱码。**教训：中文源码只用
   edit/write 工具改，不用 shell 文本管道。**

## 五、P1-5 状态流：把"到哪一步了"接到界面上

第十阶段的收尾写着「`collab_store.set_status` 有（draft/待审/定稿），
界面仍然没有入口」。用户上一轮也点过这条："状态比锁更接近团队流程：
锁解决同时改，状态解决到哪一步"。

**形状选择：按章，不按句。** `set_status` 是逐行的，而真实动作是按章的 ——
策划不会为 284 句一句句点"定稿"。所以新增
`collab_store.set_status_range(db, label, status, actor)`：

- **只动这一章、只动未删的行**；
- 已经是这个状态的行**不算 changed**（回执里的数字要能对账）；
- **不碰锁**：锁管"内容谁在改"，状态是审阅元数据；认可别人锁着的那句
  "文案没问题"不需要抢她的锁；
- **权限与 `set_status` 同一条**（`_can(role, 'approve')`）——
  另写一套判据，两处漂移就会长出"只读能定稿"这种洞；
- 一次改动写一条 `status_range` 审计（章 / 状态 / 改了几行 / 共几行）。

界面上不再新开一个对话框，而是把它放进已有的「协作」窗（同一个协作库、
同一个用户名）：上半是锁，下半是**状态表**（章 / 行数 / 草稿 / 待审 / 定稿 /
锁着）+ 三个按钮（标为草稿 / 送审 / 定稿）。没选章时作用于**当前这一章**
（窗口打开时就把当前 label 传进去，并自动选中它）。

`session_collab.collab_status_overview` 沿用 `collab_locks` 那条铁律：
**库不存在就直接说，不去碰盘** —— `connect()` 会建库 + 跑 DDL，
"看一眼总览"不该悄悄造出一个空库。

落地后：`docs/shots/ui_11_collab_status.png`。

判定：`tests/test_collab_status_ui.py`（20 条，四层：存储规则 / 会话薄壳 /
对话框 / 窗口入口）。
