# 台词后缀（`with dissolve`）从"内部列"升为可见列（2026-11-03）

> 用户："有没有加 say 语句后面的 with transform 的自定义模块？其实它都不是
> 自定义的，而是 say 本身的属性。"

## 一、结论：**早就支持，只是被藏起来了**

`with` 不是自定义语句，是 Ren'Py say 语句的**语法子句**：

```
say 语句 ::= [说话人] "文本" [with 转场] [(kwargs)] [id 名字] [nointeract]
```

解析侧 2026-10-18 就做过了（`renpy_parser_stmts._say_clause` 认四种：
`(kwargs)` / `with` / `id` / `nointeract`），字段名 `SayTail`（`beat.say_tail`），
渲染时原样拼回引号之后。

**测下来保真完美**（`tests/test_patch_escaped_say.py` 之外另验）：

| 写法 | `.rpy → 表 → 写回` |
|---|---|
| `jc "带转场" with dissolve` | 逐字节相同 |
| `"旁白带转场" with vpunch` | 逐字节相同 |
| `jc "参数和转场" (what_color="#f00") with dissolve` | 逐字节相同 |
| `jc "带 id" id line_01` | 逐字节相同 |
| `jc "nointeract 的" nointeract` | 逐字节相同 |
| `jc "带行尾注释" with dissolve  # 备注` | 逐字节相同 |

问题在于它被标成 **「台词后缀（内部）」**，`hidden=True`，排在第 32 列 ——
策划既看不见也改不了，只能手改脚本。

## 二、这轮改了什么

| 改动 | 位置 |
|---|---|
| 表头 `台词后缀（内部）` → **`台词后缀`** | `beat_fields.FieldSpec` |
| `hidden=True` → 可见（卡片/表里都是一等公民） | 同上 |
| 旧表头进 `LEGACY_BEAT_HEADERS`（老表照样读得回来） | `beat_fields` + `beat_model._HEADER_ALIASES` |
| 「列说明」归属从"高级区 / 程序"改为"基础列 / 策划" | `excel_export._COLUMN_DOCS` |

**位置一个字没动**（还是第 32 列）—— 原因见第三节。

## 三、差点闯的祸：`to_row()` 的列序契约是硬编码的

第一版把 `FieldSpec('SayTail', …)` 挪到了「台词」旁边（第 8 列），想让用户
一眼看到。结果：

```
Beat(text='带转场', say_tail='with dissolve').to_row()
→ zip(BEAT_FIELDS, row) 得到   CameraHeader = 'with dissolve'   ← 错位！
```

根因：`beat_fields.py` 的注释写着"列顺序 = `BEAT_FIELDS`，**一条都不许在这里
另写**"，而 `Beat.to_row()` 实际返回的是**硬编码的位置列表**
（`self.line_id, self.seq, …, self.camera_header, self.say_tail, …`）。

也就是说：**注释与实现不符，任何"移动 FieldSpec"的改动都会静默错位** ——
写表时一点异常都没有，要 `zip(BEAT_FIELDS, to_row())` 才露出来。

这轮的处理：**不改位置**，只改可见性；另加守卫
`tests/test_beat_row_order.py`（8 条）：

1. **给每个字段灌 `Z<字段名>Z`，它必须落在自己那一列**（错位立刻现形）；
2. `len(to_row()) == len(COLUMN_SPECS) == len(BEAT_FIELDS)`；
3. 表头不重复（两个列同名 → `from_row` 按名匹配时后写的赢，另一列永远读不到）；
4. 别名不许与现用表头撞车；
5. 老表头（`台词后缀（内部）`）/ 英文列名（`SayTail`）/ 新表头三种都能读回
   `say_tail`。

## 四、验证

| 项 | 结果 |
|---|---|
| 六种 `with`/`id`/`nointeract` 写法往返 | 逐字节相同 |
| 新表第 32 列「台词后缀」 | 值 = `with dissolve` |
| 表里改成 `with vpunch` | 产物 `jc "带转场" with vpunch` |
| 老表（表头 `台词后缀（内部）`） | 照样读回 `with dissolve` |
| 「列说明」 | `基础列 / 策划 / …with dissolve…` |
| 回归 | beat + 往返 + excel + 切行 **220 + 128** passed |
| 棘轮 | 27 / 192 没涨 |

## 五、重排 UI：`with` 挪到台词下面，只选转场名（同日第二轮）

用户："说话人是 say、摆在上面的；然而我想要 with 的 say 却必须要在下面的
高级模式点，并且还要重新打整句，这不合理吧？我打了整句那上面那个 say 怎么办？
要不你给个 say 后面紧跟一个 with？去掉现在这个高级模式？"

三点都对，逐条落到代码：

### ① 位置：从高级区挪到**台词正下方**

`app/editor.py` 里 `SayTail` 从 `ADVANCED_FIELDS` **移进 `PRIMARY_FIELDS`**。

⚠ **关键不是挪控件，是挪分组**：`collect_fields()` 只在高级区**展开**时才收
`ADVANCED_FIELDS` —— 只挪控件的话，界面看着在台词下面，高级区一收起
`with dissolve` 就**不写回**（静默丢）。判据
`test_value_survives_with_the_advanced_box_closed`。

### ② 不用打整句：显示"转场名"，写回"整段"

| 层 | 值 |
|---|---|
| 控件里（用户看到的） | `dissolve` |
| 存进 `say_tail`（写进 `.rpy` 的） | `with dissolve` |

两个纯函数负责转换（`card_editor.split_say_tail` / `join_say_tail`）：

```
split: 'with dissolve' → 'dissolve'      'nointeract' → 'nointeract'
       '(what_color="#f00") with dissolve' → 原样（剥了就没法编回去）
join : 'dissolve' → 'with dissolve'      'nointeract' → 原样
       '(what_color="#f00") with dissolve' → 原样（不猜）
```

所以"上面那个 say"就是**同一格**：用户只选一个 `dissolve`，台词格的内容
一个字都没动 —— 不会出现"两处各写一半"。

### ③ 候选仍是"变换表"，但只列**转场名**

`（无）` → 14 个内置 transition → 项目自己的 transform（去重，上限 150）
→ `nointeract`。真机 166 条。

高级区里那一格**去掉了**（分组移走后 `_build_advanced` 不再为它建控件，
判据 `test_advanced_box_has_no_duplicate_combo`）；只在用户手写了
**下拉表示不了**的子句（`(kwargs)` / `id`）时，台词下面给一行只读提示。
