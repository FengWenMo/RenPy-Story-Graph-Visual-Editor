> 查**卡片编辑器界面上的检测器**能不能认出来且不报错；再造一批只差一个定义的
> 双胞胎（`base` → `based`），查它会不会**正确报错**。

## 一、结论（TL;DR）

| 问题 | 结果 |
|---|---|
| 项目自己定义的词（各种写法）认不认 | **修完都认**：`init python` 4 格/2 格/tab、行尾注释、BOM、`if/for/with/try` 里、函数/类里、推导式、`define`、`image` 语句、`renpy.image()`、`layeredimage … at …:`、别名属性 |
| 双胞胎 `based`（没定义）报不报 | **报**：`「lan」没有「based」这个属性 —— 项目里声明的是：base / happy… 认不出的词运行时会被忽略，实际显示 …/base.png`；卡片上同一句话 |
| `at` / `@` / `transform` 会不会被当属性 | **不会**：`lan base@left`、卡片 `at` 列、整条 show 尾巴（`at / with / behind / as / onlayer / zorder`）都不参与属性校验 |
| `show expression …` | **闭嘴**（判不了不猜）——`holo("lan base")` 不再被切成 `holo("lan` 去报"不是立绘标签" |
| 服装代号 `aa`（有变量、没 png） | **闭嘴**：真机 `lan aa happy` 不报；只有"项目没声明过这个 tag"才引用 lint |
| 新增判据 | `tests/test_sprite_hint_hell_structures.py` **50 条** |
| 回归 | 相关 11 个测试文件 **219 passed**；全量最终 **9422 passed / 6 failed**（6 条均为并行未完成改动，见 §六） |

## 二、怎么造的"自定义结构"

工程零件（每个用例一个独立临时项目）：`game/definitions.rpy`（`layeredimage lan` 声明
`base` / `happy`）+ `game/extra.rpy`（自定义结构）+ `game/script.rpy`（`show` 调用）。
全部走真链路：`AssetRegistry` → `Symbols` → `known_tag_warning()`，
界面那组再真建 `SpriteCardWidget` 读 `_hint_text`。

### A 批：应该"认出来"的写法（节选）

```python
# 1. 真项目那种（但变量名换成不常规的）
init python:
    ＬＯＯＫＵＰ_９ = ({"ЗЕТА": ["sigil_77", "base"]},)

# 2. 2 空格缩进 + 多行 + 行尾注释
init python:  # 换装循环，别删
  _9QZ = {
      "lan": ["sigil_77", "base"],
  }

# 3. 定义藏在控制流 / 函数 / 类 / 推导式里
init python:
    if True:
        HELL = {"lan": ["sigil_77"]}
    def _hell():
        return {"lan": ["sigil_77"]}
    class _H:
        TABLE = {"lan": ["sigil_77"]}
    NAMES = {_w for _w in ("sigil_77",)}

# 4. define 语句
define HELL_77 = ["sigil_77", "base"]

# 5. 直接声明图像名（引擎认；不是 layeredimage 的 attribute）
image lan based = "images/characters/lan/base.png"
image lan based:
    "images/characters/lan/base.png"
image lan 符_77 = "images/characters/lan/base.png"

# 6. 运行期注册
init python:
    renpy.image("lan sigil_77", "images/characters/lan/base.png")

# 7. 声明头带 at（引擎认；旧解析器只认 `layeredimage qing:`）
transform hell_pose:
    xalign 0.5
layeredimage qing at hell_pose:
    attribute base default:
        'base'
```

### B 批：只差一个定义的"双胞胎"

同一份文件，把定义里的 `base` 留着、剧本里写 `based`；
或把 `image lan based` 那一行删掉。判据一律是：
**提示必须点名 `based`，且不许把好词（`happy` 等）一起点名。**

## 三、真 bug（都是"项目合法、检测器误报"）

| # | 触发写法 | 旧行为 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | `init python:` 块体 2 空格缩进、多行容器 | 词表空转 → 报"没有这个属性" | `_python_blocks` 固定 `[base+4:]`，把 `  _9QZ = {` 切成 `9QZ = {`（SyntaxError） | 按**块体第一行的缩进**剥（2/4/tab 都行） |
| 2 | `init python:  # 注释` | 整块跳过 | 块头正则要求行尾只有空白 | 允许 `#…` 行尾注释、`+1` 偏移 |
| 3 | 文件开头 BOM | 块头不匹配 | `\ufeffinit python:` | `_python_blocks` 先剥 BOM |
| 4 | 定义在 `if/for/with/try`、函数/类、推导式里 | 一个词都收不到 | `_literal_words_of` 只处理顶层 `Assign` | 改成通用 AST 遍历（仍只收 dict 键 / 容器元素，不收 dict 值） |
| 5 | `define HELL = ["aa"]` | 不认 | 只扫 `python` 块 | 新增 `define`/`default` 字面量扫描（括号配平支持多行） |
| 6 | `image lan based = …` / `image lan based:` | 报"没有 based" | 声明层只读 `layeredimage` | 新增 `image_statement_words()`，把字面量图像名的 tag/属性收进声明层 |
| 7 | `image lan 符_77 = …` | 报"没有 符_77" | 同上，且词表只收 ASCII 开头 | 图像名按引擎的 `[\w.]+` 收（Unicode 合法） |
| 8 | `renpy.image("lan sigil_77", …)` | 报"没有 sigil_77" | 只读静态声明 | 解析 `init python` 里的字面量 `renpy.image()` 调用 |
| 9 | `layeredimage qing at hell_pose:` | 整个声明读不到 → "不是已知角色立绘" | `_RE_LAYERED` 要求 tag 后立刻冒号 | 允许 tag 与冒号之间有子句 |
| 10 | `attribute base default: 'base'` 与 `attribute 符_77: 'base'` 共用一张图 | 只剩一个属性；另一个报"没有" | `declared_sprite_words` 是 `{图片 stem: 属性名}` 反查表，同 stem 互相覆盖 | 新增 `declared_attr_names()`（`LayeredImage.all_attrs()`），提示层用**属性名本身** |
| 11 | 整条 show 尾巴 `lan base at hell_pose` / `lan base with dissolve` | 把 `at` / `hell_pose` 当属性报 | `known_tag_warning` 只按空格切 | 先切出图像名那一截（到 `at/with/behind/as/onlayer/zorder` 为止；去尾部 `:`） |
| 12 | `holo("lan base")`（`show expression`） | 报「holo("lan」不是立绘标签 | 把表达式当图像名 | 带引号/括号或 `expression ` 前缀 → 判不了就闭嘴 |

改动文件：`storygraph/assets/asset_identity.py`、`storygraph/story/layered_model.py`、
`storygraph/story/dsl.py`、`storygraph/ui_qt/sprite_hints.py`；

## 四、引擎实测（真跑 lint，不是猜）

最小项目逐个跑 `renpy.exe <镜像> lint`（`engine_images.verdicts`，SDK 8.4.1 实际
8.5.3），确认"哪些写法引擎真的认"：

| 写法 | 引擎裁决 |
|---|---|
| `layeredimage lan:` + `attribute base`，`show lan base` | 不报 |
| 同上，`show lan based` | `'lan based' is not an image.` |
| `init python: WORDS = {"lan": ["sigil_77"]}`，`show lan sigil_77` | **报**（即使 dict 里有；引擎只认 image 注册表） |
| `image lan based = …`，`show lan based` | 不报 |
| `image lan 符_77 = …`，`show lan 符_77` | 不报 |
| `renpy.image("lan sigil_77", …)`，`show lan sigil_77` | 不报 |
| `transform based:` + `show lan based` | 报（transform 不是图像属性） |
| `layeredimage qing at hell_pose:` / `attribute … at …` | 不报 |
| `show lan base at <未定义变换>` | 不报 `is not an image`（lint 只看图像名） |

真机 `D:\千连万理\sr_general`（96 个 `.rpy`）：

```
lan aa happy          → （不吭声 —— aa 是 CC_OUTFIT_CYCLE 的服装代号）
lan happy aa          → （同上，顺序无关）
lan close_happy happy → （不吭声）
lan based             → 「lan」没有「based」这个属性 … 实际显示
                        game/images/characters/lan/indifferent.png
```

`aa` 在 `charactercenter.rpy` 的 `CC_OUTFIT_CYCLE` 里，静态层认它
（`project_literal_words` 真机 221 个词，含 `aa` / `base_hand_up`）。
上一版让**引擎压过静态层**，于是 922 处合法写法全被报错；现在引擎只在
"项目没声明过这个 tag"时说话（见 `docs/引擎裁决_自动问lint_2026-11-04.md`）。

## 七、还没钉住的（信息边界，不是这次漏掉的 bug）

1. **`init python` 里 dict 的"值"仍不算词**（`{"aa": "普通"}` 的"普通"）——
   这是故意保留的：值多是中文说明。另外 Unicode 键 / 超过 32 字的键仍被
   `_WORD_RE` 挡掉；引擎认的 Unicode 名字请用 `image` 语句声明（已支持）。
2. **非字面量**一律不猜：`dict(sigil_77=1)`、`renpy.image(f"{tag} {attr}", …)`、
   `for` 里拼出来的名字 —— 猜一个名字比说"不知道"更坏。
3. **表里只有 tag、没有 `layeredimage`/`image` 声明时**，没有"完整属性词表"
   可比，未知属性不会报（只当作"判不了"）。这是既有取舍，这次没改。
4. **引擎缓存新旧**：`bad_keys()` 只读缓存、不校验指纹；脚本改了以后，
   卡片可能先显示旧裁决，等后台 lint 跑完、**下次打开项目**才翻过来
   （`_kick_engine_images` 的文档已写明这一档）。
5. 证据脚本与 JSON 在 `.pip-tmp/hell_detector/`（不进版本库），
   真机 lint 缓存写在 `%LOCALAPPDATA%/StoryGraph/engine_images/`（不写用户项目）。
