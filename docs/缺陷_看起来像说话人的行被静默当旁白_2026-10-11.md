# 缺陷记录：看着像"谁在说话"的行被静默当旁白（2026-10-11 做 S3 时抓到）

## 现象（可复现）

拿**真项目角色表**（28 条）跑纯文字转换：

```python
res = T.convert_text('lyj：好。\n小明：谁啊？\n', filename='d.txt', characters=chars)
```

结果：

```
lyj "好。"            ← lyj 正确识别（大小写也认）
"小明：谁啊？"         ← ⚠ 整行当**旁白**，而且
unmapped = {}   warnings = []   dropped = []   ambiguous = {}   conflicts = []
```

那一行对象上：`kind='narration'`、`speaker_token=''`、`ambiguity=None`
—— **没有任何地方说"这行看着像谁在说话，但我不认识 小明"**。

## 为什么这是缺陷（不是"设计如此"）

1. 本仓立场（契约 H1 / safeguard 开头）：**静默失败比报错坏得多**；
2. 路线图 §七 自己写着："**撞车必须报**……**不许静默取第一个**"；
3. 用户是**编剧**：`小明：谁啊？` 是"小明说"的意思。工具把它当旁白，
   等于**把作者的意图悄悄改掉**，而作者要翻到导出的 `.rpy` 里才可能发现；
4. 与已修过的同类问题同源（【⑩】曾把 ATL 块冒号当属性、中文参数名被静默漏报）
   —— 都是"看着像 A，被当成 B，且不吭声"。

## 建议的修法（**下一轮做，别急着改分类器**）

`classify_line` 现在只对"全大写缩写"那条判据产出 `unmapped`。要补的是**另一类**：

- 在 `convert_text` 末尾加一个**只增不改**的后扫描：
  对每条被判成 `narration` 的原始行，若匹配 `^\s*([^：:\s]{1,12})[：:]\s*\S`
  （"短名字 + 冒号 + 内容"）且该名字**既不在 id 也不在显示名/别名里**
  → 记进一个新的 `suspect_speakers`（并进 `warnings` 的人话摘要）；
- ⚠ **不要**因此把这一行改成对白（那会猜错 —— 它真的可能是旁白里带冒号）；
  只要求**报出来**，让用户决定：加别名，或者确认它就是旁白；
- 门槛要保守（名字长度、内容非空），并且**新字段只增不改**——
  免得动到 S1/S2 那 60 条判据。
