## 3. 实测：选项体里插 call，写回会骗你（P0，已修）

**复现**（真机形状，`main` 里有 `menu`，两个选项）：

```
卡片里选中选项头 "去屋顶": → 插一张控制流卡 call roof → 导出
```

**三个"真相"**：

```
模型（ChapterDocument）   这一拍 nest_path = 'menu:1>A'        ← 在选项体里 ✅
全量渲染（render_beats）    "去屋顶":\n    call roof\n    e "上去了"   ← 在选项体里 ✅
增量补丁（patch_export）    menu 之后、选项同级：\n call roof      ← 跑到块外 ❌ 且 ok=True
```

**根因**：`_insert_anchor`（2026-10-05 为"产物语法合法"而设）的规矩是
"锚点是块头 → 退到**最外层包围块之后**"。它把两种卡当成了一类：

- **选项体的兄弟卡**（模型里在 menu 之后）→ 退到块外，对；
- **放进选项体的卡**（模型里 `nest_path` 就在体里）→ 退到块外，**语义改了**：
  `call roof` 变成"不管选哪项都执行"，分支没了。

这正是审计 §二十一"模式三：错误互相抵消"的同族 —— 语法合法、测试绿、语义错。

**修法**（`storygraph/story/patcher.py`）：

- `_insert_points_for` 标出"这一拍的 `nest_path` 含 `>`"（= 在某个选项体里）的锚点；
- `_apply_sequence_edits(..., into_body=…)`：这类锚点**紧贴块头插、缩进深一级**（体里已有语句就借它的缩进）；
- `menu:1`（菜单层、不属于任何选项）**保持老规矩**：那种状态连整份渲染都会写出
  `# TODO` + 非法行，补丁跟它对齐反而会把文件写坏。

**证据**：

- 新用例 `tests/test_patch_option_body_insert.py` —— **先红**（`assert 7 < 5`：`call roof` 跑到下一个选项之后），改完绿；
- 老用例 `test_incremental_export.py::TestInsertIntoBlockStaysStructurallyValid`（"退到块外"那条）仍绿 —— 两类没有混；
- 相关面 149 条 + 19 条修复的 221 条全绿。

**它回答了 21:31 报告里的开放问题**："三级内容层今天通不通" → **模型通、渲染通、写回不通**。
也说明"先做实验再画 UI"是对的，而且实验抓到的往往不是能力缺口，是**一致性缺口**。

**剩下一个小刺（没修，登记）**：把卡插在 `menu:` 本身之后（`nest_path == 'menu:1'`，
即"菜单层、还不属于任何选项"）时，全量渲染会把它塞进**第一个选项的体里**并写一行
`# TODO: 这一拍在菜单层、却不属于任何选项`；门禁的 `structure_loss` 会把整份拦下
（实测菜单签名 `1 → 2`），所以**不会静默写坏文件**，但用户看到的是"结构丢失"这种
文不对题的拒绝。正解应该在插入那一刻：`nest` 恰为 `menu:N` 时拒绝（或改插到 `menu:` 之前）。

## 4. 五个真问题 + 我的裁决

### (1) 入口之争：图 / 卡片 / 弹窗，谁说了算？

**判据：落点由剧本结构决定，入口只决定"你在哪看见它"。**
同一个动作，两个入口必须调**同一个会话命令**（`insert_flow_beat` / `update_beat_flow`），
落点自然一致 —— 然后"图能不能插""要不要弹窗"就不再是路线之争。

| 落点 | 例子 | 位置唯一吗 | 图 | 卡片 | 弹窗 |
|---|---|---|---|---|---|
| **编排层**（零碰源） | 章末去下一章 | **唯一**（就是章末） | 能发起 | 能发起 | **不弹** |
| **拍**（碰一行） | 走到一半 call 子过程 | 有歧义（第 N 拍） | 能发起 | 能发起 | **告知型**：默认章末 / 上次位置 + 前后一句预览 |
| **结构体**（最贵） | 选项体里 call | 还要选"哪个选项" | **只画不插** | 能发起 | 卡片里的插入流程 |

这样 21:08 的"必须问"、21:19 的"零弹窗"、21:44 的"告知型弹窗"三者并不冲突：
**弹窗不按"动作"开关，按"位置有几个可能值"开关。**

### (2) 没有编排层的项目（形状 B/C/D），一级接线去哪？

**答：那种项目没有一级。** `placement.control_flow` 为空 = 这项目没有编排层，
工具**不许**自动建文件；所有接线退回"改章末那一行 `jump`"（二级），
卖点变成 **diff + 撤销**，不是"零碰源"。

这条比 22:02 报告更收窄：报告说"项目没有就建，名字听项目的"，
我认为默认应该是"**不建**，除非清单里写了 `control_flow`"。凭空多一个 `.rpy` 是侵入，
而"改一行章末 jump"至少是项目里本来就有的形状。

### (3) `_control` 与原文件章末 `jump` 并存？

**答：有章末 `jump` 的章不生成 `_control`**，生成前体检报"这章有两个'去哪'"。
（21:19 §八-2 已经提了，这里只是定死。）你项目里全是 `return`，这条暂时用不上，但通用化必须答。

### (4) 变量归置

**答：不是 A/B/C/D 四选一，是两类。**

| 类 | 去哪 | 判据 |
|---|---|---|
| **声明**（`default` / `define`） | `placement.declarations`；认不出**问一次**写进清单 | 打开章节文件找不到 `default`/`define` |
| **剧情时刻的 `$`** | **留现场**、一拍一行 | 搬走 = 删剧情时刻（真机 `msg_add` 就是台词） |

21:44 的 A/B/C/D 可以留着当"项目已经在用的形状"，但**不要做成策略菜单** ——
工具真正会写变量的场合很少（生成声明 + 插一张 `$` 拍），一条落点规则就够。

### (5) 布局（坐标）怎么存

**答：先做 W1** —— `.storygraph/layout.json` 自动落盘 + 主键换成
`file_path::label_name` + 旧格式迁移。理由：这是**纯增益**（现在"摆好的版式丢了"
是已发生过的痛），**零写盘风险**（不碰 `.rpy`），而且不依赖上面四条任何一条。
