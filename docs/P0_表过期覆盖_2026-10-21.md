# P0：表过期之后导出，程序员的代码被静默吃掉（2026-10-21）

> 起因：用户要"重点寻找并改 P0 bug"。
> 做法：不看文档里的 ✅，而是自己造探针去打一遍**没被覆盖的横切面**。
> 结论：挖到一条真 P0（两个症状、同一条链），已修；另外四个怀疑面实测是干净的。

---

## 一、怎么找的

现有 250 个探针全在量"**内容**"（拍数、行数、句子在不在）。所以这次专挑
**载体**和**时序**这两条几乎没人量过的轴：

| 轴 | 场景 | 实测结论 |
|---|---|---|
| 载体 | UTF-8+LF / UTF-8+BOM+CRLF / 末尾无换行 / GBK | **干净**（BOM 与 CRLF 都原样还回来；GBK 读不出来时报"剧本表为空"退 2，不写盘） |
| 内容 | 台词里塞引号 / 换行 / 反斜杠 / `%` / `[]` / `{}` / `=` 开头 / 2 万字 | **干净**（转义正确，重新解析逐字一致） |
| 配对 | 同 label 两句一模一样的台词，改第二句 | **干净**（只改第二句，第一句不动） |
| **时序** | **表导出之后，程序员又在同一个 `.rpy` 里改了几行** → 策划再导一次 | **P0** ← |

最后这条是真实的协作节奏（50 人团队，策划和程序并行），而它恰好跨越了
"表"和"源码"两个真源。

## 二、P0 长什么样

### 复现（`tools/probe_stale_overwrite.py`）

```python
# 1) 策划导表
label ch1:
    jc "第一句。"
    jc "第二句。"
    jc "第三句。"
    return

# 2) 程序员在同一个文件里加了三行（pause / 一句台词 / 一行 $ 代码）
label ch1:
    jc "第一句。"
    jc "第二句。"
    pause 0.5
    jc "程序员新加的一句。"
    $ flag = True
    jc "第三句。"
    return

# 3) 策划在表里把「第三句。」改成「改过的一句。」，导出回原文件
```

### 改之前

```
退出码 = 0
增量未采用（return 数量从 1 变成 0）→ 已按全量生成
```

而源文件变成了：

```
label ch1:
    jc "第一句。"
    jc "第二句。"
    jc "第三句。"
    jc "改过的一句。"
    return
```

**`pause 0.5` / 程序员新加的一句 / `$ flag = True` 全部消失，退出码 0。**
（这一次是走"全量"那条路丢的；下面还有一个更隐蔽的版本，连"全量"都不报。）

### 症状二（更隐蔽）：增量报"成功"，但删掉了源里的台词

`tools/probe_stale_table.py` 的场景 1：同样的局面，但改动落在**最后一句**。

`patch_export` 返回 `ok=True`、`changed_lines=3`，回执写：

```
增量补丁：只改了 3 行，原文其余部分（含 default / init python / transform）逐字节保留
```

产物：

```
    jc "第一句。"
    jc "第二句。"
    pause 0.5
    jc "改过。"
    return
```

程序员新加的那句台词、`$ flag = True` 没了 —— 而这一次**没有任何报错**，
连"退回全量"都没说。

## 三、根因（两层，都在"猜"）

### ① 对位是"按顺序硬配"，没有拒绝机制

`recover_source_ranges` 用 `difflib` 对齐，而**对齐键刻意不含正文**
（正文正是要改的东西，见 `_align_key`）。表过期时：

```
源：4 拍（第一句、第二句、程序员新加的一句、第三句）
表：3 拍（第一句、第二句、改过的一句）
```

4 个身份键一模一样 → `SequenceMatcher` 只能按顺序配前 3 个：

| 表的拍 | 配到的源拍 | 实际发生 |
|---|---|---|
| 第一句 | 第一句（第 2 行） | 正确 |
| 第二句 | 第二句（第 3 行） | 正确 |
| 改过的一句 | **程序员新加的一句（第 4~5 行）** | **张冠李戴** |

然后源里的"第三句"被当成"用户删掉了这一拍"。两句源台词：一句被替换、
一句被删，产物只剩一句。

现有的对位守卫 `_range_looks_like` 拦不住它 —— 它的判据之一是
"说话人在原文段里出现过"，而 `jc` 这个字符**必然**出现在任何一句
`jc "…"` 里，所以只要有同角色台词就恒成立。

### ② 增量失败后，手写护栏原地失效

退回全量的处置本来是对的（`merge_incrementally` 的 docstring 写明：
"目标若存在就会被门禁拦下"）。但 `write_generation` 里有一条豁免：

```python
if not force and not merged_onto_target and not _copy_of_source(
        out_path, source_text) and _looks_handwritten(out_path):
```

`_copy_of_source` 的判据是"目标当前内容 == 源文本"。**原地覆盖时这是套套逻辑**：
源就是目标，读它必然相等。于是这条豁免把护栏 100% 关掉了。

它本来是给"零改动复制到**另一条路径**"（P1-1：复制的副本没有生成标记，
下次再导会被自己的护栏拦住）开口的，被顺手也用在了原地覆盖上。

## 四、修法（3 处，共 101 行）

| 位置 | 改什么 | 为什么这么改 |
|---|---|---|
| `story/patcher.py` | 新增**表过期守卫**：源里有台词被判"用户删掉了"，**同时**表里有拍的正文在源里找不到 → 拒绝增量、说明原因 | 两件事同时出现时"改了那句"和"漏了一拍"**信息论上分不出来**。按契约 L2/M4（不猜名字、认不出就报）应该拒绝，而不是硬配 |
| `story/generation_guard.py` | 原地覆盖（目标 == 底稿）+ 这一次**不是**增量合并出来的 → 拒绝写，并给专门的说明 | 这正是 docstring 里"全量重生成 → 危险，必须拦"的原意。`_copy_of_source` 豁免收窄到"另一条路径" |
| `story/cli.py` | ① 给了 `--source` 却没配上时，不再说"目标是你手写的 .rpy"（驴唇不对马嘴），改说真话；② 另存新路径时明确警告"这份产物里没有源文件里不在表内的语句" | 前者会把排查方向彻底带偏（用户明明给了底稿，却被告知"再给一次底稿"）；后者让"另存路径"这一半也不静默 |

### 判据（`tests/test_p0_stale_source_guard.py`，6 条）

1. 原地导出 + 增量失败 → `written=False`，源文件**逐字节不变**，理由说清原因；
2. 程序员的 3 行还在（拒写后天然成立，但显式钉住）；
3. `force=True` 仍是逃生舱（明确要求全量覆盖时放行）；
4. 表与源完全对得上时，原地增量照旧能写（**不能把正常路堵死**）；
5. 另存到别的路径照旧写（那是新建文件，不是覆盖别人的章节）；
6. `_copy_of_source` 那条 P1-1 豁免不能因为这次修复失效。

## 五、验证

### 修完的 CLI 行为

```
$ cli.py table xlsx2rpy t.xlsx --out ch1.rpy --source ch1.rpy
生成门禁拦下，未写入目标路径：ch1.rpy
  [block] HANDWRITTEN_TARGET：这一章和表**对不上**（增量合并没成功），
          而目标就是源文件本身：全量重生成只认得表里的拍，源里不在表内的
          语句（程序员新加的 `pause` / 台词 / `$` 代码 / 注释）会一并消失。
          拒绝覆盖。先把这一章重新载入（让表和源码对上）再导出；
          确认产物完整、就是要全量覆盖时用 `--force`。
  ⚠ 这次**没能**增量合并（表与源码对不上，原因见上），而 `--source` 指的
    正是目标文件本身 —— 全量产物会丢掉源里不在表内的语句。
退出码 = 1，源文件一个字节未动。
```

### 真机复跑

| 判据 | 改之前 | 改之后 |
|---|---|---|
| 原地导出（表过期） | 退出码 0，丢了 3 行 | **退出码 1，源文件不动** |
| 另存新路径（表过期） | 退出码 0，静默少 3 行 | 退出码 0，**明说少了什么** |
| 增量误删台词 | `ok=True`，删了 2 行无提示 | 拒绝增量，退回全量（原地则被拦） |
| L1 零改动往返（55 个真机文件） | 55/55 逐字节 | **55/55 逐字节**（没被新守卫影响） |
| L2b 单点编辑 20 例 | 19/20 | **19/20**（同一个已知的 pomodorro 删一拍，与本修无关） |
| 全量测试 | 5485 passed / 2 skipped | **5491 passed / 5 skipped / 1 failed**（见下） |

> 那条 `failed` 是 `test_unity_package.py::test_failed_write_does_not_leave_temp_or_truncate`，
> 被沙箱的"批量删除守卫"拦下（`SAFE_DELETE_BULK_CONFIRM_REQUIRED: count=50/50`），
> 与本修无关 —— 改动前的基线跑的是**同一条**失败。
> 5491 − 5485 = 6，正好是这次新增的判据数。

全量耗时 24 分 21 秒（同机同代码另有 12 分 56 秒的一次）—— 这是记忆里那条
"4 条真机金标主导、方差 ±40%"的老现象，不是回归。

## 七、没修的（都降级为 P1，附理由）

| 项 | 为什么先不动 |
|---|---|
| 另存新路径仍会产出"少了行"的全量产物（退出码 0） | 目标不存在 = 新建文件，全量本来就是它的正当用途。已加显式警告，不再静默 |
| UI 覆盖确认框点"仍然覆盖"仍会全量覆盖 | 是**问过**的（默认按钮是取消），属"人拍板"，不是静默 |
| `$` / `pause` / `show` 这类行在表过期时仍可能被当"清空列"删掉 | 与"用户把舞台列清空 → 那行该删"是同一个判据，分不开。真出现时上游的表过期守卫会先兜（因为同时有台词丢失） |
| 表过期**且只**丢非台词行（源里没有台词被删） | 目前无信号，属已知边界 |
