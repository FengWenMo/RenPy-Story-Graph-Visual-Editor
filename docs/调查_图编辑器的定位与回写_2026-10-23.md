# 调查：图（模块编辑器）到底能不能编辑结构（2026-10-23）

> 用户读到"图是诊断视图"之后的反驳（原话）：
>
> > 图在这里也可以编辑结构啊……？我们的模块编辑器不也是编辑器吗？它决定逻辑和控制流程……
> > 卡片页看的归卡片页看的！但人不能什么都去翻卡片！！！只能在卡牌页面内决定 label
> > 跳转逻辑是非常麻烦的！
>
> **结论：用户是对的，我上一轮那句话错了。** 图**是**编辑器——它编辑节点、边、类型、
> 条件、菜单项、布局，还带撤销/重做。真正的缺口不是"能不能编辑"，而是
> **编辑停在模型层：图上的边是草图，不写回 `.rpy`。**

---

## 一、图今天能编辑什么（代码事实）

| 能做的 | 入口 | 实现 |
|---|---|---|
| 新建章节块（可同时建 `.rpy` 文件 / 同文件新 label） | 双击空白 / 右键「添加新章节」/「在本文件新建 label…」 | `window_nodes.add_node` / `add_label_to_file` |
| 删除块 / 按整章移除 | 右键「删除这个块…」「从剧情图移除整章」 | `RemoveNodeCommand` |
| 移动块、自动布局、按文件顺序排列 | 拖拽 / 工具栏 | `MoveNodeCommand` + `graph/layout.py` |
| **加连线**（jump / call / menu，带条件、菜单项文字） | Shift+拖 / 右键「从这里连一条到…」 | `AddEdgeCommand` + `AddEdgeDialog` |
| **改连线**（类型 / 条件 / 菜单项 / 目标） | 边命令 | `UpdateEdgeCommand` / `RetargetEdgeCommand` |
| 删连线 | 右键 / Delete | `RemoveEdgeCommand` |
| 撤销 / 重做 | 工具栏 / Ctrl+Z | `graph/commands.py::HistoryManager` |
| 保存 / 加载布局（JSON） | 工具栏 | `save_layout` / `load_layout`（`LAYOUT_KEYS = nodes/edges/next_ids`） |
| 从整张图**导出控制流脚本** | 工具栏「⤓ 导出控制流 .rpy」 | `session_graph.export_control_flow` → `<label>_control` |

所以"图不能编辑结构"是不成立的。它一直能编辑。

## 二、真正的缺口：编辑走不到 `.rpy`

三条代码事实（不是推测）：

1. **加连线是"草图"**。`window_nodes.add_edge` 写日志时原话：
   `……（{etype}） —— 草图，只改图，不写 .rpy`；
   状态栏原话：`不写脚本。要写进 .rpy，请打开卡片用「↳ 插入控制流卡」。`
2. **弹窗自己写着**：`AddEdgeDialog` 最后一段：
   > ⚠ 图上的连线是草图：它只改剧情图，不会写进任何 .rpy，也不会生成新 label。
3. **两种边混在同一张图里**：
   · `origin='source'` —— 从拍派生（`story.flow.flow_edges`），**反映**脚本里已有的
     `call` / `jump`；
   · `origin='manual'` —— 用户画的草图，**不参与**任何写回。
   布局 JSON 里两种都存，所以"图上看着改了、游戏里没变"是预期行为。

真正能写进脚本的路径今天只有两条：
- 卡片上的「↳ 插入控制流卡」→ `Beat.raw` → 受控补丁导出；
- 「⤓ 导出控制流 .rpy」→ **另生成** `<label>_control` 文件（不是改这一章）。

**这就是用户说"只能在卡牌页面内决定 label 跳转逻辑是非常麻烦的"的根因**：
图的编辑是**建模**，不是**改脚本**；而卡片的编辑是改脚本，但只能一拍一拍来。

---

## 三、我上一轮错在哪（措辞更正）

- 错在把"编辑不了**脚本**"说成了"**诊断**视图"。诊断是"只看"，而图明明能增删改。
- 也错在把 `竞争格局分析` 里 C6 的行业判断（"节点图编辑器在复杂项目里失效"）套到了
  **本工具的模块编辑器**上——那条说的是"把剧情画成节点图来写作"，而我们的图是
  **label 级接线**（一个块 = 一章），完全不同量级。
- 正确的说法：**图是 label 级结构编辑器**，卡片是拍级内容编辑器；
  两者共用同一批 `Beat` 与 `line_id`（这正是行身份契约的用处）。

## 四、分工建议（按用户的分工，而不是我上一轮的说法）

| 层 | 编辑什么 | 不该在这里做的 |
|---|---|---|
| **图（模块编辑器）** | 章与章之间的 **call / jump / 分支接线**、章的存在与位置、控制流骨架 | 改台词、改立绘/舞台细节（那是卡片） |
| **卡片（拍编辑器）** | 这一拍说什么、怎么演、参数与条件 | 决定"整章跳到哪"（那是图） |
| **左侧导航** | 找到 / 打开某一章 | 编辑 |

用户的原话"卡片页看的归卡片页看的"落在工程上就是：**读的时候别逼人点进去**。

## 五、回写路径怎么补（a / b / c）

### a. 调用卡上的目标摘要（**本轮已做**）

`call side` 的卡片条上直接写：

```
目标 side：6 拍 · 第 173 行（本章 2 处调用）
```

不点进去也能判断"这个 call 是不是我要的"。数据来源：
同文件用当前会话的拍（`story.flow.label_brief` / `callers_of`），
跨文件用左侧导航已在内存里的项目目录（不为了显示一行字去扫盘）。

### b. 「进去看」+ 返回栈（下一步，便宜）

点摘要 → 打开 `side`，面包屑 `main › side`，`←` 回到 main 的**同一拍**。
这不是新视图：复用现有载入链路 + 一个返回栈；解决"点进去就迷路"。

### c. 图上的边**真正写回**（这才是终局）

分两种边，规则不同：

| 边 | 能不能写回 | 怎么写 |
|---|---|---|
| `origin='source'`（脚本里已有） | **能，且应该** | 边上有 `line_id` → 找到那一拍 → 改 `Beat.raw` → 走现有受控补丁导出（只改那一行） |
| `origin='manual'`（草图） | **要选锚点** | 问"插在哪一拍的后面"（默认章末 / 选中的拍）→ 插入一张 flow 拍 → 同样走补丁 |

硬约束（不满足就不做）：

1. **不猜锚点**：没有 `line_id` 的草图边不许"看着像就改"——那等于静默改剧情；
2. **先 diff 后写**：改 `Beat.raw` 也要走「导出前给人看 diff」那条路（铁律 5）；
3. **不碰 menu/if 体**：图能表达"跳转 / 分支"这一层，块体内部仍归卡片；
4. **两种边在画面上必须一眼分出**（实线 / 点划线已经有了，别合并）。

## 六、明确不做

- 把图做成"拍级"画布（一个块 = 一拍）：那是另一个产品，且 88 文件的项目会变成星云。
- 在图里编辑 `menu` 的选项体 / `if` 的块体：块体是台词与演出，归卡片。
- 手画一条线就"自动生成一整章"：图只在**已有拍**上接线（或插入一张 flow 拍），
  不生成新 label 的内容。
