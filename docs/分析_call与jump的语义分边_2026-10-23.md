## 二、你的猜想对不对？——对，而且有业界同行

你说的这句是关键：

> **call 因为过去了还会再回来**

这正是 call/jump 的语义分界，一字不差。业界两处直接印证：

### ink：tunnel vs divert

| ink | 语法 | 语义 | 对应 Ren'Py |
|---|---|---|---|
| **divert** | `-> knot` | 去了不回 | `jump` |
| **tunnel** | `-> knot ->` | **去去就回**（"do the story, then continue from here"） | `call` |
| tunnel 返回 | `->->` | "go on" | `return` |

ink 官方原话：tunnel "functions rather like a **subroutine**"，用调用栈，可嵌套。
**你的"过去了还会再回来"就是 ink 对 tunnel 的定义。**

### Ordfoss（故事工具）：画布上就分虚实

> "Call versus Jump. A Jump is one-way... A Call remembers where it came from...
> **On the canvas a Call is drawn with a dashed purple outline** and a Return with
> a solid one, **because the difference decides whether the line after the node is ever read**."

翻译：**画布上 Call 用虚线框、Return 用实线框——因为这决定"节点后面的行还读不读"。**

所以"jump 上图当边、call 当标注"**一点都不奇怪**——有人已经在用虚实线区分了。
你只是把区分推到了"谁是边、谁是标注"这一步，方向一致。

## 三、你的猜想好在哪（三个真优点）

| 优点 | 为什么重要 |
|---|---|
| **语义轴选对了** | call/jump 是"之后的内容走不走"的分界——比"位置在章末还是章内"更本质。位置是"插哪"，语义是"这是什么" |
| **jump = 命运，call = 绕路** | jump 图上是**边**（故事去哪了）；call 图上是**+**（绕一圈回来了，主线还在）。图变成"命运地图 + 绕路标注"，而不是"什么都往上堆" |
| **途中 call 归卡片** | 插在台词中间的 call，位置是"哪句话之后去趟药店"——这要看着前后台词才定得了。卡片正是看台词的地方 |

## 四、需要微调的两处（不推翻，拧紧）

### 微调 1：插入规则对 call 和 jump 应该**一样**

你的表述里：jump "都显示在图上"（暗示能插？），call "不支持插入途中、末尾支持"。

建议统一成一条：

> **图上只插"章末接线"（call 和 jump 都一样）；途中插入一律走卡片。**

理由：途中 jump 一样要位置判断（`if 坏结局: jump ch_bad` 插在哪句后面？）。
"插在哪"这个问题对 call 和 jump 是同一个问题，不该两套规则。
**不一样的只是画法，不是插入权限。**

### 微调 2：分清两种 menu（这个坑今天就存在）

你说的"menu 选项调用不同的 call"是**叙事菜单**；而图上的 `option_text` 边今天代表的是**章级菜单**——两种不是一回事：

| | 章级菜单（编排层） | 叙事菜单（内容层） |
|---|---|---|
| 例子 | "接下来去哪一章？" → 去 ch02 / 支线 / 结局 | "去屋顶 / 留下" → 各自 call 或 jump |
| 现在图上怎么画 | 边带 `option_text`，写进 `_control` 的 `menu:` | 画不出来（只有草图） |
| 按你的猜想应该 | **实线边**（每项去不回/去去就回都是去向） | **+ 标注**（call 项）或 **实线边**（jump 项） |
| 写到哪 | 控制流层 | 卡片插进选项体 |

**一个叙事 menu 里混 call 和 jump**：

```renpy
menu:
    "去屋顶":
        call roof_scene      # 去去就回 → 图上是 +
        jump ch02            # 接着去下一章 → 图上是实线边
    "留下":
        jump ch_ending       # 去不回 → 图上是实线边
```

图上会看到：`ch01` 有一个 **+**（call roof，虚线/回环）和两条**实线边**（→ ch02、→ ch_ending）。
**不对称，但正确**——一个绕回来了，两个没回来。Ordfoss 的虚实线干的就是这个。

## 五、合成后的完整模型（call/jump × 位置）

两根轴正交：**语义轴**（call/jump）决定**怎么画**，**位置轴**（章末/途中）决定**谁来插**。

| | **jump（去不回）** | **call（去去就回）** |
|---|---|---|
| **图上画什么** | **实线边**（故事去哪了） | **+ 标注 / 虚线回环边**（绕路，回来了） |
| **边上标什么** | 条件 / 菜单项文字 | 条件 / 菜单项文字 / "回到第 N 拍" |
| **图上能改目标吗** | ✅ 能（改一行） | ✅ 能（改一行） |
| **图上能插入吗** | **仅章末** | **仅章末** |
| **途中插入** | 卡片（看得见台词） | 卡片（看得见台词） |
| **章末写到哪** | 控制流层（零碰源） | 控制流层（零碰源） |
| **途中写到哪** | 插一张 flow 拍（受控补丁） | 插一张 flow 拍（受控补丁） |

对照你的猜想：

| 你说的 | 采纳？ | 订正 |
|---|---|---|
| 所有 jump 显示在图上 | ✅ | 画成**实线边** |
| call 默认卡片管理 | ✅ | 但"管理"≠"看不见"——图上有 **+** 标注 |
| 图上 + 显示条件/菜单 call 了什么又回来了 | ✅ | 完全采纳 |
| 支持改 call | ✅ | 改目标 = 改一行，走受控补丁 |
| 不支持插入途中 call | ✅ | **扩成：途中 jump 也不在图上插** |
| 末尾 call 仍支持 | ✅ | 末尾 call/jump 都走控制流层 |

**会不会非常奇怪？** 不会。奇怪的反而是**不区分**——把"去去就回"的 call 和
"去不回"的 jump 画成同一种边，图就分不清"主线去哪了"和"中途绕了一下"。
你这条猜想正好把这层分开了，而且和 ink / Ordfoss 同向。

这一步不写新功能，只回答"三级内容层今天到底通不通"。
通了，后面按合成模型补图上画法；不通，先修插入——比先画 UI 实在。
