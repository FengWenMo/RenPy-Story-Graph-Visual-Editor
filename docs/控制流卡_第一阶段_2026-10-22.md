## 一、用户要的到底是什么

> “我觉得最需要解决的，就是怎么在一个大 label 里面 call 或 jump 其他小 label
> 然后再回到这个大 label。”

原来的状态：

- 解析器和图都能认出 `call side`；
- 但 Beat 表里它只是一张 `kind=narration`、`raw='call side'` 的旁白拍；
- 卡片上只有一行「这一拍还会原样执行：call side」；
- 目标只能去「高级区 · 代码」手改；
- 改完图上的边**不会跟着变**。

所以第一阶段不先重构 Beat，而是把这一行**变成卡片上的一等公民**。

---

## 二、现在卡片上是什么样

```text
┌─ 第 2 拍 ────────────────────────────────────┐
│ ↳ 调用 side          [↳ 调用（会返回） ▾]     │
│ 调用后回到这里，继续第 3 拍                   │
│ 目标 [ side ▾ ]  可手写点号 label             │
└──────────────────────────────────────────────┘

┌─ 第 4 拍 ────────────────────────────────────┐
│ → 跳转 ending        [→ 跳转（不返回） ▾]     │
│ 跳转后不返回：这一章在这里结束                │
│ 目标 [ ending ▾ ]                            │
└──────────────────────────────────────────────┘
```

- 目标下拉里是本文件已有的 label，**可编辑**；跨文件调用直接手写；
- `call` 会算出“返回后继续第 N 拍”；如果后面不是同一个 label 的拍，
  明确写“回到本章末尾”，不会把下一章误说成返回点；
- `jump` 明确写“不返回”；
- 左边拍列表不再显示「（无台词）」，而是
  `2 ↳ 调用 side` / `4 → 跳转 ending`；
- 普通台词拍不显示这条控制流卡；
- 卡片栏新增「↳ 插入控制流卡」：选 call / jump 与目标 label，就插在
  当前拍后面；不用回源文件手写。

## 三、改目标 / 改类型时发生什么

| 动作 | 数据落点 | 图上 |
|---|---|---|
| 点「↳ 插入控制流卡」选 `call side` | 在当前拍后插入一张 `Beat.raw='call side'`、同 label 的拍 | 两端节点都在图上时新增 `main→side` 边 |
| 把 `call side` 改成 `call ending` | `Beat.raw = 'call ending'`；参数 `(…)` 与 `from …` 原样保留 | 两端节点都在图上时，边 `main→side` 改指 `main→ending`，可 Ctrl+Z 撤销这一步图操作 |
| 把 `jump side` 改成 `jump ending` | `Beat.raw = 'jump ending'` | 同上 |
| 把 `call` 改成 `jump` | 先弹确认：“jump 不会返回，这一章在跳转处结束”；确认后参数与 `from` 子句**明确丢掉**（jump 不接受） | 边类型从 call 改成 jump |
| 目标不在图上 | 卡片照常保存 | 状态栏明确说“目标还不在剧情图上，边没有同步；先导入它所在的章节”，**不硬造节点** |
| 目标名不合法 | 不保存，状态栏说清合法写法 | 不动 |

导出走的仍是唯一那条渲染路径：`call ending` 直接写进产物，不会被包成
注释、空拍或 `$` 代码。

## 四、怎么验收

1. 打开一个含 `call side` 的章节，翻到那一拍：
   - 顶部应出现「↳ 调用 side / 返回后继续第 N 拍」；
   - 左边列表同一行不再是「（无台词）」。
2. 把目标下拉改成 `ending`，按「💾 保存这一拍」：
   - 状态栏说已保存；控制流卡标题变成「↳ 调用 ending」；
   - 按「⤓ 导出 .rpy」，产物里是 `call ending`；
   - 剧情图上原来的 `main→side` 边应改指 `main→ending`（前提：两个节点都已导入）。
3. 把类型改成「跳转（不返回）」再保存：
   - 应先弹确认；取消则一个字节都不改；
   - 确认后卡片标题变成「→ 跳转 ending」，下方写明不返回。
4. 打开普通台词拍：控制流卡应消失，不占版面。
5. 在卡片栏点「↳ 插入控制流卡」→ 选「调用」、目标 `side`：
   - 当前拍后面应多出一张控制流卡，并自动选中；
   - 左边列表显示「↳ 调用 side」；导出后是 `call side`；
   - 两端节点都在图上时，图上会多一条 `main→side` 的 call 边。

- 解析：`call` / `jump` / 参数 / `from` / 点号 label；拒绝 `call screen`、

## 六、这一阶段**没有**做（第二阶段）

| 项 | 说明 |
|---|---|
| `Beat(kind='flow')` | 现在仍是 `kind=narration + raw`；结构化字段（type/target/from/args）还没进 Beat |
| 图边从 flow 拍派生 | 现在保存 / 插入时**同步**边，但边和 raw 仍是两份数据；第二阶段删掉双真源 |
| 参数 `(…)` / `from` 的可视编辑 | 现在只保留、不展示；改目标不会丢，但想改参数仍要进高级区 |
| 目标不在图上时补占位节点 | 现在明确提示“先导入”，不硬造幽灵节点 |
| 多张同目标 call 的精确对位 | 图边目前按 `from + type + target` 找第一条；同一 label 里多次 call 同一目标时，第二阶段用源行号/flow id 精确定位 |

这些都属于“图边与脚本同源”的收口，不是再补一个按钮能解决的；按分析文档
继续第二阶段即可。
