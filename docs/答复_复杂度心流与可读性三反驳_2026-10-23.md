## 二、③ 你的弹窗方案：为什么比我上一轮的"零弹窗"更对

我上一轮引 Twine"零弹窗"来反对弹窗。**类比错了**：

| | Twine | 本工具 |
|---|---|---|
| 链接写在哪 | 就写在正文里（`[[目标]]`） | 拍序列里的某一**步** |
| 有没有"位置"概念 | **没有**——写在哪就是哪 | **有**——第几步、哪句后面 |
| 弹窗有没有用 | 没用 | **有用**——位置得看见才踏实 |

**位置是个信息量，藏起来才是罪过。** 你的方案正是业界的
"smart default + live preview"（智能默认值 + 实时预览）：

> "The one thing the preview must never do is **gate the flow**."
> （预览绝不能卡住流程——默认值填好，直接确认就能走。）

所以弹窗的职责要重新定义：

| 弹窗该做的 | 弹窗不该做的 |
|---|---|
| **展示**：会插在哪一步（默认章末） | **审问**："你要跳去哪里？"（拖线时已经知道了） |
| **预览**：前后各一句台词 | **强制**：不选就不能走 |
| **可调**：想挪就点一下换步 | **记忆**：静默沿用上次选择 |
| **可改**：call/jump、条件、菜单 | **堆叠**：5 个字段一起逼问 |

**一句话**：不是"要不要弹窗"，是"弹窗是告知还是审问"。
你这个是**告知**——默认章末、看得见、能调、点确定就完。这才叫给策划用。

### 弹窗长什么样（策划视角）

```
┌─ 加一条 main → side 的跳转 ────────────────────┐
│  形式  [跳转 ▾]  （跳转=去了不回 / 调用=去去就回）│
│  插在  [第 12 步（章末）▾]                       │
│  ┌─ 预览 ────────────────────────────┐          │
│  │ 第 10 步  e "我们出发吧"           │          │
│  │ 第 11 步  e "等等，带上武器"        │          │
│  │ 第 12 步  e "到了"        ← 插这后 │          │
│  └───────────────────────────────────┘          │
│  条件 [          ]  菜单 [          ]（可空）    │
│         [插入]  [取消]                           │
└────────────────────────────────────────────────┘
```

- **不问"跳去哪"**——拖线已经给了；只有松在空白处才出现目标搜索
- **插在**默认章末，点开能换任何一步，**预览跟着变**
- 条件/菜单是可空的进阶项，不填就走
- 确认后状态栏照旧一句话：`已接 main → side（第 12 步）· [撤销]`

**边的详情**（点中线后的侧栏）也显示同一行「插在第 12 步」——你的原话"打开边的详情还能看到插在哪"，完全采纳。

## 三、① 复杂度：砍掉"+"和虚实线，只留文字

你的直觉对：**+ 号会和"添加"混淆，虚实线三套编码编剧记不住。**

订正后的画法（只留一处差异）：

| | jump | call |
|---|---|---|
| 线 | 实线箭头 | 实线箭头（**同款**） |
| 线上的字 | `跳转 side` | `调用 side ↩` |
| 悬停 | "去了不回" | "去去就回，继续第 3 步" |

**为什么文字比符号好**：编剧读的是话，不是图例。
"调用 side ↩" 比 "虚线 + 号" 少一次翻译。

但**语义差异要保留**——这是我要顶回去的半处：
"去了不回 / 去去就回"是**编剧自己的话**（你原话："call 因为过去了还会再回来"），
不是程序员概念。砍掉这个区分，图就分不清"主线去哪了"和"中途绕了一下"。
**砍的是符号，不是语义。**

## 四、④ 可读性：你说到点子上了，但病因要找准

你说得对——**卡片插入照样写源文件**。我上一轮说"卡片插入是干净一行"，
对 call/jump 成立，对**自定义变量/大段 DSL 不成立**。这是我说错了的地方。

### 但"一大坨变量"不是图或卡片造成的

病因是**"生成物该放在剧本的哪一层"**，和从哪个入口插无关：

| 内容类型 | 该放哪 | 现状 |
|---|---|---|
| 台词 / 走位 / 演出 | 台词流里（拍边界） | ✅ 正常，剧本本来就是这个 |
| call / jump | **独立一拍**（一行） | ✅ 干净 |
| 章末接线 | **控制流层**（零碰源） | ✅ 上一轮已定 |
| **自定义变量 / 大段 DSL** | ⚠ **不该散落台词中间** | ❌ 现在可能插得到处都是 |

**"一大坨变量谁受得了"的正解是"归置策略"**，不是"不让图插"：

| 归置选项 | 做法 | 适用 |
|---|---|---|
| **A. label 顶部块** | 变量/初始化集中放在 `label xxx:` 后第一段 | 章级变量、状态位 |
| **B. 专用块头** | 一个 `# --- 变量 ---` 注释块，工具认这个块、只往里加 | 零散但成批的变量 |
| **C. 独立文件** | `story_vars.rpy` / `default` 段，剧本里只留一行 `call init_ch01_vars` | 最吵的、跨章共享的 |
| **D. 台词中间** | 只有"这句台词触发的变量变化"才留现场（`$ flag = True` 这种 Ren'Py 原生习惯） | 语义上就属于现场的 |

**默认走 A/B，D 要克制，C 给开关。** 这是工具该替编剧守的规矩——
否则不管从图还是从卡片插，结果都是"一大坨"。

### 学术界的旁证（protected regions 的教训）

查了"生成代码与手写代码混合"的工业做法（protected regions / `# BEGIN CUSTOM` 标记）：

> "A major drawback of protected regions is that **it cannot be guaranteed**
> that the generator preserves handwritten implementations.
> The reason is that **handwritten code is mixed with generated code**."
> —— SE-RWTH 对 protected regions 的评估

而且 C1 判据"生成与手写分离"：**Unfulfilled**——混在同一文件里就做不到真分离。

**结论**：与其在源文件里划"保护区"，不如**少往里写**——
能进控制流层的进控制流层，能归置的归置，真正留在台词中间的越少越好。
本项目的 patcher（只改真改过的行）比 protected regions 更强，
但它也救不了"你偏要往中间塞一大坨"——**归置策略得先立**。

## 五、订正后的完整图景（三轮下来收敛的样子）

```
策划想接一条线
      │
      ▼
[拖线 A → B]  ── 目标已知，不问"跳去哪"
      │
      ▼
[弹窗：告知型]
   形式：跳转 / 调用          ← 文字，不用符号
   插在：第 N 步（默认章末）   ← 可调，带前后台词预览
   条件 / 菜单：可空
      │
      ▼
[插入] ── 写到哪：
   ├─ 章末接线 → 控制流层（零碰源文件）
   ├─ 途中 call/jump → 插一张拍（一行，拍边界，patcher 保真）
   └─ 变量 / 大段 DSL → 归置策略（顶部块 / 专用块 / 独立文件）
      │
      ▼
[状态栏一句话] + [撤销] + 边上写着"插在第 N 步"
```

| 三轮里的变化 | 第一轮 | 第二轮 | **现在** |
|---|---|---|---|
| 加边弹窗 | 5 问 + 警告 | **零弹窗** | **告知型弹窗**（默认值 + 预览，不审问） |
| call/jump 区分 | 没提 | + 号 + 虚实线 | **文字**：`跳转` / `调用 ↩` |
| 途中插入 | 图上插 | 只能走卡片 | **图上也能插**（弹窗给足上下文） |
| 可读性 | 说"卡片干净" | 说"分三级" | **归置策略**（变量不散落） |

## 六、我顶回去的那半处（保留分歧）

**"call 会回来、jump 不回来"这个语义差异要留**，只是表达换成文字。

理由：这不是程序员概念，是**叙事概念**——"下面的台词还接着演吗？"。
砍掉它，图上 `call side` 和 `jump side` 长一样，
编剧就不知道"选这个之后，原来那段对话还在不在"。

你担心的是**复杂度**，解法是**换表达**（文字替符号），不是**删语义**。

## 七、还剩的两个真问题

1. **归置策略具体怎么定？**（自定义变量放顶部块还是独立文件？）
   这需要看你真实项目里变量/DSL 拍长什么样、有多少。建议：抽一个真机章节，
   数一数"变量类拍"占比和分布，再定 A/B/C/D 的默认规则。
2. **弹窗的"插在"要不要记住上次？** 建议**不记**——每次都默认章末，
   删后加回时才自动还原上次位置。静默沿用 = 改剧情。
