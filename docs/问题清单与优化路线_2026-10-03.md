## 一、仍存在的问题（按严重性）

### P1　功能正确性

**P1-1　分支内舞台指令失去分支保护**　→ **已修（2026-10-05）**

- 实测：全项目「分支内舞台指令」**12 → 3**，9 条被提到块外无条件执行
- 典型：`pomodorro/script_pomo.rpy` 的 `if pomoplace == "ocean" / elif "cafe" / elif "library"`
  三分支背景 → 产物里 `pomoplace` **3 次 → 0 次**，三个背景依次无条件 show
  → 最后一个生效 → **永远显示 library**
- 演出错误，且不报任何错
- 根因：同契约 30。扁平拍装不下"舞台指令属于哪个分支"。
  `elif`/`else` 靠 `not((前一条件))` 展开（14 条）保住了**台词**分支，
  但**舞台指令不进 condition，直接被合并进同一拍**
- **修法**：`beat_build._branch_guard` —— 舞台/音频/语音/`$` 代码在
  **条件与当前拍不一致时先落拍**，各自带上自己的条件（复用 menu 那套
  "扁平拍 + 按结构归组"）。实测 13/13 条分支内舞台指令全部留在自己的分支里。

**P1-2　menu 结构的残余风险**

- 修法是渲染前重新归组，依赖「拍的顺序 + 解析器 `_menu_member` 标记」
- 这是**重建**而非**保持**：策划在 Excel 里重排/插入拍时，分组可能错乱
- 目前无测试覆盖"菜单组内插入新拍"

### 3. `transform` 链路（P2-4）——**查清：通的，但走的不是 `beat.transform`**

`beat.transform` 是**旧模型残留**：只在渲染时被读（`with <transform>`），
解析与 Excel 回导**都不写它**，所以真实项目 2013 拍里有值 0 次。
**自定义 transform 的能力是通的，载体是另外三个字段**：

| 场景 | 字段 | 单元格编码 |
|---|---|---|
| `show eileen happy at leftish` | `beat.at` | 立绘列 `eileen happy@leftish` |
| `scene bg room at bgfit` | `beat.scene_at` | `scene_at` |
| `with Dissolve(0.5)` | `beat.with_` | 转场列 |

新增 `TestCustomTransformRoundtrip`（4 条）把这条路钉住，并**顺手挖出一个
真实缺陷**：

```renpy
show image puzzle_path at Transform(xysize=(1920, 1080))
```

分词器把逗号一律当分隔符，`at` 收成
`['Transform(xysize=(1920', '1080))']`，拼回去（空格连接多目标）变成

```renpy
show image puzzle_path at Transform(xysize=(1920 1080))    # Python 语法错误
```

**产物直接跑不起来**，而语句多重集断言**看不出来**（它把 `at` 列表归一化了，
两边"一样"）。修法：分词器按**括号深度**决定逗号是不是分隔符；
`at` 多目标之间保留逗号（`_join_at_targets`）。
真实项目 `mini_game_puzzle.rpy` 第 262/284 行就是这个写法。

### P1-2　菜单分组在编辑下会不会错乱 —— **补上了，并且真的抓到一个**

新增 `tests/test_roundtrip_invariants.py::TestMenuGroupingUnderEdits`（6 条），
模拟策划真实的四种改法：选项之间插一拍、菜单后追加一拍、两个选项对调、
删掉一个选项。**第 2 条当场变红** —— 而且是最坏的那种坏法：

```
插入一拍之前                     插入一拍之后（修复前）
menu:                            menu:
    "选项A":                         "选项A":
        "A 的内容"                       pass
    "选项B":                     "插进来的旁白"        ← 掉出菜单
        "B 的内容"               if True:              ← 无条件执行了
"菜单之后"                           "A 的内容"
                                 "选项B"              ← 选项变成一句旁白
                                 if True:
                                     "B 的内容"
```

一次误判把**整个菜单拆散**：选项降级成旁白、分支体降级成无条件执行。

**根因**：分组是**重建**的（`_menu_member` 存不进 Excel），
`_in_menu_body` 在插进来的那一拍上判 False，`_take_menu_run` 就当场收尾。

**修法**：组**只能收在"下一个带选项/成员标记的拍之前"** ——
`_menu_looks_unfinished` 往后扫，后面还有 `menu_option` 或
`_menu_member=True` 的拍时，中间那张认不出归属的拍照收不误。

**但"收进来"本身也是改变语义**（那一拍变成"只有选中该选项才播"），
所以再补一层：`_is_menu_foreign` 把"认不出归属"的拍单独标出来，
渲染时**按原位置**放回去并加一句显式警告：

```renpy
menu:
    "选项A":
        # TODO: 这一拍不确定属于哪个选项
        "插进来的旁白"
        "A 的内容"
    "选项B":
        "B 的内容"
```

`.rpy → .rpy`（`_menu_member` 是 True）那条路**不加任何警告**，产出逐字不变。

### P2-10 顺带抓到的真 bug：透传语句丢失分支保护

```renpy
# 原文                          # 产物（修复前）
if flag:
    pause 0.1                   pause 0.1        ← 无条件执行了
"一句"                          "一句"            ← if flag: 整个消失
```

`beats_from_statements` 的 `RAW` 分支**既不看条件、也不落条件**，

修法与 P1-1 同源：`_branch_guard(stmt)` + `pending.condition = ...`。
（真实项目里没有"带条件的透传语句"，所以这条在量化上看不出来 ——
**只有合成用例能抓到**。这也是"先写测试"这次又生效的一次。）
