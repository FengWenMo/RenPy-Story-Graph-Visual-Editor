## 二、那"变量"到底能不能搬？——分两种，一种能一种不能

先看真机章节里 `$` 长什么样（这才是你担心的"一大坨"）：

| 章节 | `$` 行数 | 实际内容 |
|---|---|---|
| chapter0_0 | 0 | 干净 |
| chapter1_1 | 38 | `$ msg_add('L\|叶怀瑾\|images/fnm5.png\|你想好了要来青蓝实验室吗？')` |
| chapter1_2 | 55 | 同上（聊天记录风格的自定义 DSL） |
| chapter1_3 | 63 | 同上 |
| chapter1_4 | 96 | 同上 |
| chapter3_1 | 0 | 干净 |

**关键发现**：这些 `$` **不是变量声明**，是**剧情时刻的函数调用**——
"这一步往聊天记录里加一条消息"。它有**叙事时刻**（哪句话之后弹这条），
**搬进独立文件就等于把剧情时刻删了**。

### 变量的两种身份（决定能不能搬）

| | **声明 / 初值** | **剧情时刻的赋值 / 调用** |
|---|---|---|
| 例子 | `default trust = 0`、`define jc = Character(...)` | `$ trust += 1`、`$ msg_add('…')` |
| 有没有剧情时刻 | **没有**——游戏开始前就该存在 | **有**——必须在那一句之后发生 |
| 能进独立文件吗 | ✅ **能，而且必须** | ❌ **不能**——搬走 = 改剧情 |
| 真机现状 | ✅ 已在 `definitions.rpy`（168 行） | ✅ 留在章节里（`msg_add`） |
| Ren'Py 社区惯例 | `00 variable definitions.rpy`（数字开头保证先加载） | 只能在剧本流里 |

## 四、按你的三条判据核一遍

### 判据 1：最小侵入性

| 内容 | 写到哪 | 碰源文件吗 | 侵入度 |
|---|---|---|---|
| 章末接线 | `chapter_controller.rpy` | **不碰章节** | **零** |
| 变量声明 | `definitions.rpy`（或工具专管文件） | **不碰章节** | **零** |
| transform/工具生成 | `*.generated.rpy` | **不碰章节** | **零** |
| 剧情时刻 `$` | 章节内插一拍 | 碰，但**一拍一行** | 低 |
| 台词/演出 | 章节内 | 碰，但这就是剧本本体 | （不可避免） |

**结论：凡是能进独立文件的都进了之后，章节里剩下的都是"剧本本体"——
这已经是理论上的最小侵入。** 真机 chapter0_0 / chapter3_1 一个 `$` 都没有，就是这个状态。

### 判据 2：最能让人读懂

打开真机的 `chapter1_1.rpy`，编剧看到的是：

```renpy
    $ msg_reset()
    $ msg_add('L|叶怀瑾|images/fnm5.png|你想好了要来青蓝实验室吗？')
    $ msg_add('L|叶怀瑾|images/fnm5.png|这里确实人不多，当然欢迎你进来。')
```

这"一大坨"**不是变量污染，是剧情本体**——这是个聊天记录式的 VN，
`msg_add` 就是它的"台词"。编剧读它 = 读剧情。

**真正影响读懂的是"变量声明混进台词流"**，而那已经全部在 `definitions.rpy` 了。
所以"一大坨变量"的担心，在真机上**已经被结构解决了**。

> ⚠ 但有一个新问题：如果以后工具要插的**不是** `msg_add` 这种剧情 DSL，
> 而是真正的状态变量（`$ trust += 1`），那还是会在章节里留痕。
> 解法是：**状态变更尽量薄**（一行）、**能合并的合并**（一张"状态卡"多条变更），
> 而不是把它们抽走。

### 判据 3：防范所有极端情况（Ren'Py 官方警告 + 真机对照）

| 极端情况 | 后果 | 防范 |
|---|---|---|
| **用 `define` 声明可变变量** | 玩家通关后重开新档，**旧档的值漏进新档**（Ren'Py 文档原话警告） | 可变的用 `default`，不变的才用 `define`；工具生成声明时强制分清 |
| **变量在 `start` 里初始化** | 老存档读进来时**变量缺失** | 声明进 `definitions.rpy` / `00` 前缀文件，**不在 start 里 init** |
| **加载顺序** | 变量用了但还没 default | 文件名用 `00` 前缀（Ren'Py 按字母序加载） |
| **存档兼容** | 变量搬家后老档读不出 | `default` 在独立文件里 = 老档缺变量时自动补默认值（`after_load`） |
| **工具重生成覆盖手写** | 用户改了生成文件被冲掉 | `generation_guard` 的 `HANDWRITTEN_TARGET`（已有） |
| **rollback（回滚）** | 剧情时刻的 `$` 被回滚到别处 | `$` 必须在剧本流里（这正是**不能**搬走的原因） |
| **同名变量/角色冲突** | `define e = Character()` 和 `$ e = 0` 打架 | 工具起名前查重（lint 已能查） |
| **用户手改 `chapter_controller.rpy`** | 跳转乱掉 | 注释已写"请勿手动修改"；可加 lint 检查 |

**最关键的一条**（Ren'Py 文档原话）：

> "It is highly recommended to **default every variable** that is susceptible to change.
> If you use `init python` or `define` to declare a changeable variable … the former game
> will **'leak'** in the newly started one."

→ **工具生成变量声明时，可变的必须落 `default`，绝不落 `define`。**
这条要写进生成规则，是"防范极端"里最贵的一条。

## 五、那工具该怎么写变量？——三条落盘规则

| 规则 | 内容 | 判据 |
|---|---|---|
| **R1** | 变量**声明**一律写 `definitions.rpy`（或 `storygraph_vars.rpy` 工具专管文件）；**绝不**写进章节 | 打开任意 `chapter*.rpy`，找不到 `default`/`define` |
| **R2** | 可变的写 `default`，不可变的才写 `define`；工具生成时按这个分 | 生成物过 lint，无"define 可变变量"告警 |
| **R3** | 剧情时刻的 `$` 留在章节里、**一拍一行**、插在拍边界；不合并进台词、不跨拍堆叠 | patcher 逐字节保真测试照旧 |

配套：`chapter_controller.rpy` 继续工具全权（已做到）；
`*.generated.rpy`（transform 等）继续工具全权（已做到）。

**三件套 + 三条规则 = 你要的"最小侵入 + 最能读懂 + 防范极端"。**

> **变量分两种：声明能搬、必须搬（真机已搬进 `definitions.rpy`）；
> 剧情时刻的赋值搬不走（它就是剧情，`msg_add` 就是台词）。
