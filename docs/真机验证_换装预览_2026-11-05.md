# 真机验证：换装后预览图**真的**换了（2026-11-05）

> 用户：「现在看一眼 B……`aa` 不是脏引用吧……？真实项目内到处都有……别清」

先说清两件事：

1. **`aa` 不是脏引用**（我上一条说错了）。它是"普通服装"的代号，Ren'Py 对
   layeredimage 的未知 attribute **运行时忽略、照常渲染**，所以项目跑得好好的。
   922 处 `show … aa …` 是**正常用法**，不是要清的东西。
2. 这一轮验的是第三轮修的那个 bug：**换了服装，预览图得真的变**。

## 一、解析层（真机 `D:\千连万理\sr_general`）

```
lan happy              ok=True  层=1  ['happy.png']
lan aa happy           ok=True  层=1  ['happy.png']           ← 普通服装 = 不加层
lan clothes2 happy     ok=True  层=2  ['happy.png', 'clothes2.png']
lan base_hand_up happy ok=True  层=2  ['happy.png', 'base_hand_up.png']
lan based              ok=True  层=1  ['indifferent.png']     ← 认不出的词被忽略 → 默认表情
```

模型加载 0.38 s（`load_layer_model_cached`）。

## 二、合成层（像素）

| spec | 合成图 | 中部像素 |
|---|---|---|
| `lan aa happy` | `happy.png`（原图，不合） | `(236, 236, 236, 255)` 灰白脸 |
| `lan clothes2 happy` | `3bf4c31f1ca12afd9540c811.png`（**组合图**） | **`(138, 187, 220, 255)` 蓝色衣服** |
| `lan base_hand_up happy` | `8984ef05dfdd6e3391b799e5.png` | `(236, 236, 236, 255)` |

```
普通 vs 换装：happy.png vs 3bf4c31f1ca12afd9540c811.png -> 不同 ✓
```

**中部那个像素从"灰白脸"变成"蓝色衣服"** —— 这不是"plan 里多了一层"的
文字游戏，是画面真的换了。

## 三、为什么第三轮那个修法是对的

真机 `crop_lan` 写的是：

```python
AlphaMask(图, Crop((0, 0, 4320, 1895), Solid("#fff")))
```

旧解析器只认"`AlphaMask` 的两个参数都是字符串"，判 `error` → `plan.ok=False`
→ 退回单张表情件（于是**换装后还是那张脸**）。

第三轮把 `AlphaMask(图, Crop(矩形, Solid))` 识别成**裁剪**：`AlphaMask` 只看
蒙版 alpha，白色实心矩形 = 矩形内全保留。判据在
`tests/test_sprite_hint_hell_structures.py::TestStagePreviewUsesTheSameResolution`。

## 四、耗时

| 步骤 | 真机耗时 |
|---|---|
| 模型加载（首次 / 有缓存） | 0.38 s |
| 解析单拍 `sprite_plan` | < 0.01 s |
| 合成一张（4320×7680，首次） | 3.6 – 4.2 s |
| 合成同一张（缓存命中） | 约 0 s（文件名是内容哈希） |

合成慢是因为真机立绘是 **4320×7680**。卡片缩略图走的是
`sprite_thumbs.resolve_sprite_thumb_path`（8×8 级别的缩略），不是这条大图路径
—— 大图只在舞台预览用。
