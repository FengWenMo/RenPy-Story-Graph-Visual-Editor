## 1. 「相似放一处」落到了哪

这是这一轮的主线，逐条对：

| 原来散在几处 | 现在只在 |
|---|---|
| 字段行布局：台词区一个 `QHBoxLayout`、舞台三格一个 `QVBoxLayout`、高级区又一个 `QHBoxLayout`、备注/条件各一个 | `card_rows.row(label, widget)` |
| **「下拉 + ⋯」**：舞台三格一份、语句参数格又一份（`_spec_cell_pick`） | `card_rows.picker_button(on_pick)`（按钮本体）+ `picker_row` / `compact_picker`（两种排布，同一按钮） |
| 标签宽：`setMinimumWidth(72)` 两处、备注没设、说话人由文本决定 | `card_rows.LABEL_WIDTH = 88` 一份 |
| 缩进：各处 `setContentsMargins(0,0,0,0)` + 手写 spacing | `card_rows.INDENT_PX` / `ROW_GAP` |

`card_rows` 的对外面：

```
LABEL_WIDTH / NARROW_LABEL_WIDTH / INDENT_PX / ROW_GAP
row(label, widget, *, indent, label_width, stretch, trailing)
picker_row(...)      一行式「下拉 + ⋯」       ← 单独一行时用
compact_picker(...)  标签在上的「下拉 + ⋯」   ← 并排时用（省宽度）
picker_button(...)   ⋯ 按钮本体
section(text, *, indent)   组标题（[Header]）
gap(px)            声明出来的留白（[Space]）
```

### 为什么要两个排布形态（而不是一个）

用户 2026-10-04 明确要过「三格改成两行布局（背景一行、音乐 + 语音一行）」。
如果给并排那两格也各加一条 88px 的标签列，卡片最小宽会从 **340 涨到 352** ——
右栏一窄就出横向滚动条（`tests/test_ui_width.py` 的预算当场抓到，我改的第一版就是被它拦下的）。

所以：**并排时标签回到上方**（`compact_picker`），单独一行时用 `row()`。
「相似放一处」指的是**实现只有一份**，不是"必须长成一样" ——
两个函数都在 `card_rows`，按钮和滚动守卫都只有一处。

## 2. 顺手修掉的暗坑：收起高级区 = 丢字段

改之前 `collect_fields` 是：

```python
if self._adv_open:
    out.update({n: self._get_value(n) for n in ADVANCED_FIELDS})
```

也就是**收起高级区，里面的字段就不算数**。`SayTail` 曾经因此静默丢过一次
（当时的解法是"把 SayTail 挪到主区"，根因没修）。

Unity 的 `Foldout` 语义是：**折叠只影响显示，不改变数据**。现在照这个改：

```python
out.update({n: self._get_value(n) for n in ADVANCED_FIELDS})   # 无条件
```

同时高级区**默认展开**（`_adv_open = True`）—— 折叠是"这屏看完了"的临时动作，
不是"藏起来不用管"。tooltip 里那句"（收起时这些字段不会被写回）"也一起改掉了，
不能留着说谎。

判据：`test_collapsing_the_advanced_area_still_writes_back`（改之前必红）。

## 7. 第三轮：四项（1/2/3/4）

### 7.1 参数格按声明里的 `kind` 选控件

这是"UI 和自定义模块对应"的最后一环。改动沿着**唯一真源**走，没有在卡片里另抄一份判据：

```
pattern 的格子（声明）
  → _declared_kinds(spec)        按列名/文本建"名字 → 类型"索引
  → spec_columns(...)['kind']
  → dynamic_spec_columns(...)['kind']
  → card_editor.SPEC_EDITOR_KIND 分派控件
```

| 声明里的 `kind` | 卡片上的控件 |
|---|---|
| `keyword`（剧本里必须原样出现的固定字） | **只读**（灰字 + 说清"要改去自定义语句"） |
| `choice` / `transition` | 可编辑下拉 |
| `number` | 数字框（`QDoubleValidator`） |
| `variable` / `optional` / `expr` | 文本 |
| 没有 kind（旧声明） | 有候选→下拉，否则→文本（老行为） |

`keyword` 旁边**不再给「⋯」候选按钮**（它本来就不能改）。

判据 `tests/test_spec_cell_kind.py` **8 条**：数据层带没带 kind、只读、无候选按钮、
数字校验、下拉可编辑、旧声明兜底、**只读仍写回**原值。

### 7.2 三处标题统一成 `section()`

「当前舞台（这一拍生效）」「尺寸」「立绘」原来都是 `_section()` + 各自拼，
其中「立绘」还手拼了一个 `QHBoxLayout` 放提示。现在都走
`card_rows.section(text, hint=…)` —— 提示和标题同行，不占高度。

### 7.3 护栏扩到**所有**字段行

`card_rows.row()` / `compact_picker()` 会给宿主打 `_row_kind` 标记；
判据 `test_every_field_row_comes_from_card_rows` 遍历 `_all_names()` 里每个
有控件的字段，**向上找祖先必须有这个标记**。

现在它盘查出 `Speaker / Text / SayTail / Scene / BGM / Voice / Comment /
condition / SFX / CodeBlock / Label / Kind / Stage / MenuName / MenuArgs` 全部合格。
明天谁在调用处自己拼一个 `QHBoxLayout`，这条当场红。

### 7.4 自定义模块的实时预览

新模块 `ui_qt/spec_preview.py`：`SpecPreview`。

- 位置：表单页**「开头词」之后、格子之前**（第一版放在格子列表下面，
  三张格子卡就把它顶出屏幕了 —— 截图当场看到，等于没有）；
- 内容：一个标题 + 每格一行（有候选画成**禁用的下拉**，固定字画成灰字，
  其它画成占位只读框）+ 每个子句一行；
- **只读**：不参与 `collect_fields`、不写盘，纯粹是面镜子；
- 排布走 `card_rows`：与真卡片同一套构造口，否则"预览"和"真卡片"会是两个样子；
- **防抖**：`refresh()` 每按键都会被调，先比签名，没变就直接返回（重建下拉很贵）。

判据 `tests/test_spec_preview.py` **7 条**：空态说人话、一格一行、候选→禁用下拉、
固定字→只读、子句单独成行、同签名不重建、改了才重建。

### 这一轮踩的坑（都记着，别再犯）
