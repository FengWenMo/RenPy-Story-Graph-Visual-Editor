# 分析：控制流要不要写回源文件？——按侵入度分级，别把剧本插成刺猬（2026-10-23）

> 用户两问（原话）：
>
> > ① 如果你接在这一章的最后一步……那控制流 .rpy 还需要吗？
> >    如果它在中间，那就不得不改拍里的内容；相反，如果它在最后一步，
> >    **完全可以用控制流代替，不碰源文件是最安全的**……
> > ② 这么乱改源文件，本来好好的剧本演出，全都被弄乱了……
> >    打开看到一大堆的 if 条件的 menu + 突然一段莫名其妙的跳转……
> >    七零八落散落各处，改一发而动全身，你觉得你能看得明白吗？
>
> **结论先行**：用户两问都对。上一轮方案把"加边"一律设计成"往源文件里插拍"，
> **对章末接线是过度设计、对剧本是破坏性**。正确的模型是——
>
> **写回按"侵入度"分三级；图编辑器主要管第一级。**

## 一、先看两种 .rpy 的真面目（代码事实）

本项目其实**早就**把"编排"和"内容"分开了，只是上一轮没把这层用起来：

| 文件 | 长什么样 | 管什么 | 谁碰 |
|---|---|---|---|
| **内容 .rpy**（手写剧本） | `demo/game/script/ch01.rpy`：scene / 台词 / show / 注释 / menu 选项体 | **这一幕怎么演** | 编剧、卡片编辑器 |
| **控制流 .rpy**（`renpy_exporter.py` 生成） | `label ch01_control:` → `call ch01` → `jump ch02_control` | **章与章之间怎么串** | 图编辑器 |

`renpy_exporter.py` 开头写得很清楚：

> 控制流：每个章节 label 的 `<label>_control` 包装 + 按边写 jump/call/menu；
> **不产台词、不产舞台**。

也就是说：**控制流 .rpy 不是"要不要"的问题，它是章级接线的正解**——
它生成的是"导演本"，源 .rpy 是"演员本"。导演本改一百次，演员本一个字不动。

### 看一眼"干净剧本"被插花的样子

`demo/game/script/ch01.rpy` 现在是这样（节选）：

```renpy
label ch01:
    scene bg classroom
    play music night fadein 1.0
    show eileen happy at leftish
    e "早上好，昨晚睡得好吗？"
    m "还行，就是雨下了一整晚。"
    show mary smile at right
    m "别想了，今天我们还有正事。"
    return
```

如果按上一轮的做法往里插接线，会变成：

```renpy
label ch01:
    scene bg classroom
    play music night fadein 1.0
    show eileen happy at leftish
    e "早上好，昨晚睡得好吗？"
    call side_shop              # ← 从图上加的，插在第 2 拍后
    m "还行，就是雨下了一整晚。"
    if rain_flag:               # ← 剧本原有的分支
        jump ch01_bad_end
    show mary smile at right
    menu:                       # ← 剧本原有的选项
        "去屋顶":
            call ch01_roof      # ← 从图上加的，挂在选项里
            jump ch02
        "留下":
            pass
    call ch01_epilogue          # ← 从图上加的，章末
    return
```

**你说的"一大堆 if 条件的 menu + 突然一段莫名其妙的跳转……七零八落"——就是这个。**
编剧打开文件，原本是"剧本"，现在是"剧本里插满了路由"。
改动一处（比如把 `side_shop` 挪走）还会牵动行号、对位、菜单归属——**改一发而动全身**。

## 二、你的第一问：章末接线，控制流 .rpy 够不够？

**够。而且应该用它。** 对照如下：

| 接线位置 | 写到哪 | 碰源文件吗 | 图编辑器能不能做 |
|---|---|---|---|
| **章末：这章完了去那章** | 控制流 .rpy 的 `_control` 层 | **一个字不碰** | ✅ 图的主场 |
| **章末：call 个子过程再回来** | 同上（`call X` + `return`） | **一个字不碰** | ✅ 图的主场 |
| 章中间：走到一半接一下 | 必须插一张 flow 拍进源文件 | **碰**（受控补丁，一行） | ⚠ 图只展示，改动走卡片 |
| menu 选项 / if 分支里 | 选项体、分支体 | **碰**（最深） | ❌ 图不碰，归卡片 |

**为什么章末用控制流层是"最安全"**（你的原话，成立）：

1. **零字节风险**——源文件不动，patcher 门禁、逐字节保真全都用不上，天然不会弄乱剧本；
2. **可整份重生成**——`_control` 是产物，改坏了重新导出就是，没有"半对的产物"问题；
3. **剧本保持剧本样**——编剧打开 `ch01.rpy` 看到的还是台词和演出；
4. **接线改一百次也不污染内容**——"改一发而动全身"里那个"全身"缩到了导演本。

**唯一的前提**（help 文档里已写）：原 label 末尾要能正常 `return`，
控制流接得上。若某章末尾写的是 `jump ch02`（直接跳走、不 return），
那这章的"去哪"本来就写在源文件里了——图上反映它即可，**不用再写一层**。

> 判断：**章末接线 → 控制流层（或源文件里本来就有的章末 jump）；
> 这两种情况都不该往剧本中间插东西。**

### 那"控制流 .rpy 还需要吗"的准确回答

- **章末接线需要它**（或者用源文件里已有的章末 `jump`）——它是正解，不是备胎；
- **章内接线它替代不了**——位置在内容中间，只能是剧本里的一拍；
- 但章内接线**本来就该少**（见下节），不该成为图编辑器的主路径。

## 三、你的第二问：乱插会不会毁掉剧本？——会，所以要有"侵入度分级"

剧本不是数据表。它是**带演出节奏的可读文本**：哪句之后镜头切走、
哪个 menu 是情感分支、哪里该停顿。乱插跳转的代价有三层：

| 代价 | 表现 | 谁受伤 |
|---|---|---|
| **可读性** | 台词之间突然冒出 `call`/`jump`，叙事线索断掉 | 编剧（天天读这个文件） |
| **结构性** | 嵌套 menu/if 里挂跳转，补丁对位一错就挂错分支（`02_menu_nested.rpy` 测试注释原话："字节看不出问题，语义已经错了"） | 所有人（事故） |
| **改动半径** | 挪一处接线 → 行号变 → 对位变 → 可能牵动邻近拍 | 你（"改一发而动全身"） |

**所以写回必须按侵入度分级，而且图编辑器主要只做最低那一级。**

### 三级模型（本文核心）

```
┌─ 一级：编排层（零碰源文件）──────────────────┐
│  章末跳转 / 章末 call 子过程                    │
│  写到：控制流 .rpy（<label>_control）           │
│  图编辑器：主场，拖线即接，默认章末              │
│  剧本影响：无                                   │
└────────────────────────────────────────────┘
┌─ 二级：流程层（碰源文件，但只插干净一行）─────┐
│  章中间的 call/jump（"走到一半去趟药店"）       │
│  写到：那一拍的位置，一张 flow 拍               │
│  图编辑器：只展示位置（⑫ 徽标）+ 跳过去看       │
│  改动：走卡片编辑器（那里看得见前后台词）        │
│  剧本影响：插一行 call X / jump X，不碰邻近内容  │
└────────────────────────────────────────────┘
┌─ 三级：内容层（碰结构，图永远不碰）───────────┐
│  menu 选项里的跳转 / if 分支里的跳转             │
│  归：卡片编辑器 / 源码                          │
│  图编辑器：只画出来（边上的"菜单项/条件"标注）   │
│  剧本影响：改的是选项体，牵动缩进归属            │
└────────────────────────────────────────────┘
```

### 这个分级和"策划顺手"是同一件事

回看策划的真实意图（上一轮已统计）：

| 策划想说的 | 属于哪一级 | 正确落点 |
|---|---|---|
| "这章完了就去那章" | **一级** | 控制流层，零碰源文件 |
| "这边完了去那边，去完回来" | **一级** | 控制流层（`call X`） |
| "走到一半，他突然想起要去趟药店" | 二级 | 卡片里插一张拍（有前后台词上下文） |
| "这个菜单选项选了之后去屋顶" | 三级 | 卡片里的 menu 选项体 |

**上一轮设计的"加边 → 插 flow 拍"对一级是过度设计**：
明明该写导演本的，却去改演员本。这正是你说"不碰源文件是最安全的"的那件事。

## 四、那"章末"到底怎么判？——不用判，看意图

上一轮纠结"锚点放哪"，因为假设了一切接线都进源文件。
分级之后，"位置"问题大半消失：

| 意图 | 位置 | 要不要问 |
|---|---|---|
| 章末接线（一级） | **固定就是章末**（`_control` 里 `call 原label` 之后） | **不用问**。没有"放哪一步"的问题 |
| 章内接线（二级） | 第 N 拍之后 | 有位置问题，但**归卡片**（看得见前后台词再插） |
| 删了再加（你之前问的） | 原来在哪级就在哪级 | 一级：自动回章末；二级：自动回原拍后 |

**"合适的地方"在一级根本不存在争议**——"这章完了就去那章"，
"完了"就是章末。工具甚至不需要默认值，因为**只有一个位置**。

## 五、"改一发而动全身"怎么破——半径隔离

| 手段 | 作用 | 现状 |
|---|---|---|
| **一级零碰源** | 80% 的接线根本不进剧本 → 动不了全身 | 本方案新增 |
| **patcher 只改真改过的行** | 二级插入也只插一行，邻近台词逐字节不动 | ✅ 已有（相似度 0.994+） |
| **flow 拍是干净一行** | 插入物是 `call X` / `jump X` 一整行，不是拼进台词 | ✅ 已有（`kind='flow'`） |
| **三级图不碰** | menu/if 体永远不在图上改 | 本方案立规矩 |
| **位置徽标** | 一眼看见接在哪，不用猜 | S1（待做） |
| **导出前 diff** | 写盘前给人看改了哪几行 | ✅ 已有（铁律 5） |

二级仍然会碰源文件，但**碰的方式是"插一张干净的拍"**，
不是"把跳转揉进台词中间"。对比上文那个被插花的 `ch01`——
一级接线全走控制流层之后，源文件里只会多出**恰好必要的**那几行，
且每行都是独立一拍，注释/缩进/邻近内容不动。

## 六、业界对照（为什么分级是对的）

| 来源 | 做法 | 对应 |
|---|---|---|
| **ink** | knot（章）/ stitch（节）分层；divert 写在**叙事边界**（选项收束处、beat 末尾）；"branch with choices that snap back to gathers"——分支要**收拢**，不要散 | 一级在章末、二级在拍末；不往台词中间插 |
| **ink 警告** | "Most ink scripts bounce around in a **spaghetti-like mess**" | 你说的"七零八落"就是这个，ink 自己也在防 |
| **ink 组织建议** | "Model story beats as small knots"，每个 knot 有清晰入口出口 | 一章一个 label，章间用控制流串 |
| **对话系统设计通则** | "Separate variables from flow"——状态与流程分开存 | 编排（flow）与内容（prose）分开存 |
| **本项目 `_control` 设计** | "不产台词、不产舞台"，只产 jump/call/menu 骨架 | **已经就是一级的实现**，缺的只是把图接上去 |

## 七、订正后的方案（覆盖前两轮的写回部分）

### 图编辑器的职责（订正）

> **图 = 章级编排编辑器。** 它的写回主路径是**控制流层**，不是源文件。

| 图上的动作 | 落到哪 | 碰源文件 |
|---|---|---|
| 拖线 A→B（章末跳转） | 控制流 .rpy：`jump B_control` | **否** |
| 拖线 A→B（call 子过程，去完回来） | 控制流 .rpy：`call B` 后接续 | **否** |
| 点边看"接在哪" | 一级：显示"章末（编排层）"；二级：显示"第 N 拍" + 前后台词 | 否 |
| 改一条二级边的位置/目标 | **跳到卡片那一拍**，在卡片里改 | 是（卡片路径） |
| 删一条一级边 | 删控制流行 | **否** |
| 删一条二级边 | 删那一拍（卡片确认，写明第几步） | 是 |

### 与"策划顺手"的衔接（上一轮订正仍有效）

一级接线的新体验：

```
从 main 拖线到 side，松手：
  ✅ 线出现（实线 = 已进编排层）
  ✅ 提示：「main → side 已接到章末（控制流层，未改动剧本）· [撤销]」
```

**连 [改位置] 都不必出现**——章末就是章末。更简单了。

### 二级怎么办（章内接线）

- 图上**看得见**（⑫ 徽标 + 前后台词），**不在图上改**；
- 要插/挪/删 → 一键跳到卡片那一拍（那里有上下文）；
- 插入物永远是独立 flow 拍（`call X`/`jump X` 一行），永不揉进台词。

### 三级怎么办（menu/if 里）

- 图上画出来（边带"菜单项：去屋顶"标注），**永不编辑**；
- 双击边 → 跳到卡片里那张 menu 拍。

## 八、还剩的真问题（要你拍板的）

1. **章末"去哪"已经写在源文件里**（`ch01` 末尾 `jump ch02`）时怎么办？
   - 图上这是 source 边。改它目标 = 改源文件那一行（二级代价）。
   - 选项 A：图上只读，改目标跳卡片（最保守）；
   - 选项 B：图上可改，走受控补丁只改那一行。
   - **建议 A**——章末 jump 在源文件里通常是"剧情决定的"，不是纯编排。

2. **控制流 .rpy 和源文件里已有的章末 jump 会并存吗？**
   - 若 `ch01` 末尾已 `jump ch02`，再生成 `ch01_control` 里 `call ch01` 会**跳走不回来**。
   - 所以：**有章末 jump 的章，不生成它的 `_control` 包装**（或生成前体检报警）。
   - 这需要一条明确规则，不然两个"去哪"打架。

3. **游戏从哪启动？** 玩编排版要从 `start_control` 进；
   玩源文件版从原 `start` 进。UI 要说清"你现在接的是编排层"。

## 九、一句话总结

> **章末接线用控制流层，源文件一个字不碰——你说的对，这是最安全的。
> 章内接线才是不得不碰源文件的那一类，而它本该少、且归卡片管。
> "七零八落"不是写回的必然代价，是"不分层往剧本里插"的代价——
> 分了编排层 / 流程层 / 内容层三级，剧本还是剧本，接线还是接线。**

实施顺序相应调整：

| 步 | 内容 | 碰源文件 |
|---|---|---|
| **S1** | 边上显示位置徽标（一级标"章末·编排层"，二级标"第 N 拍"） | 否 |
| **S2** | 一级拖线 → 写控制流层（默认章末）+ 提示条 | **否** |
| **S3** | 二级：图只展示 + 一键跳卡片改 | 否（图侧） |
| **S4** | 删边防弹回 / 还原 | 一级否；二级走卡片 |
