## 2. 缺陷详情

### M1（P1）点号 menu 名整块掉进未建模通道，还折叠进台词拍

- **现象**：`menu main.route:` 不被认作 menu 头。整块（头+选项+jump）落进
  **下一句台词那张拍**的 `opaque` 字段：拍列表里只有 1 张 say 拍
  （`text='菜单之后'`，`opaque='menu main.route:\n    "点号选":\n        jump ch02…'`）。
  后果链：
  1. `menu_brief` / 卡片 / 章节树都**看不见**这个菜单（选项不可见、不可编辑）；
  2. 删除那张台词拍（S1 删拍 / 整拍删）会把绑在上面的整块菜单**一起带走**；
  3. 分级删除"只清空文字"被 M7 拦住，用户被推向"整个删掉"，加速 2 的发生。
- **复现**：
  - `tools/_multiagent_probe_menu_brief_evidence.py`（E1 节：拍 dump）
  - `tools/_multiagent_probe_menu_brief.py`（§1.12）
  - 跑法：`/d/Python/python tools/_multiagent_probe_menu_brief_evidence.py`
- **期望 vs 实际**：
  - 期望：`menu_name='main.route'`、2 张 `menu_option` 拍、`menu_brief` 返回
    `{'name': 'main.route', 'count': 2, 'options': [{'text': '点号选', 'type': 'jump', 'target': 'ch02'}, …]}`
  - 实际：无 menu 拍；`menu_brief(..., 'main.route') == {}`
- **根因方向**：`renpy_parser._RE_MENU_NAME = re.compile(r'\.?[^\W\d]\w*')`
  只吃**一段**标识符（可带前导点）——`main.route` 匹配到 `main` 就断在点上，
  随后 `text[i] == ':'` 不成立 → `_scan_menu_header` 返回 None → 整块走
  "认不出就原样抄"通道。第六轮修过 `patcher._LABEL_LINE_RE` 的同款点号问题
  （`\w` 不含点），这是**同族漏网**（memory 里记过"同一正则另有三处"，此处是第四处）。
- **建议修法**：`_RE_MENU_NAME` 改成与 `flow._LABEL` 同形
  （`[A-Za-z_]\w*(?:\.[A-Za-z_]\w*)*`，最好直接 import 同一份）；补判据：
  点号 menu 名 → 落 menu 拍 + 选项落拍 + 往返逐字节一致。
  顺带评估：合并拍（say+opaque）上删台词卡时是否该提示"上面还驮着整块原文"。

- **现象**：`run.lock` 里的 pid 被**无关进程**复用（Windows 常态）时，
  `RunLock` 认为另一轮 fasttest 活着：`--no-wait` 立刻退 3；默认模式空等
  最多 `--lock-timeout`（默认 1800 秒）后退 3。期间用户只能手动删锁文件。
- **复现**：`tools/_multiagent_probe_fasttest_sim.py` F1c
  （跑法：`/d/Python/python tools/_multiagent_probe_fasttest_sim.py`）
  ——锁文件写本模拟进程的 pid（活着、但不是 fasttest）→ 获取被拒。
- **期望 vs 实际**：期望"无关 pid 不构成互斥"；实际拒绝获取（F1c 红）。
- **根因方向**：`_pid_alive` 只回答"这个 pid 活着吗"，不回答"那是 fasttest 吗"。
- **建议修法**：锁 payload 已存 `started`——补一条陈旧判据（如持有进程的
  创建时间对不上 / 锁文件 mtime 心跳超时 N 分钟即判陈旧）；或写入
  命令行指纹（`sys.executable` + `tools/fasttest/run.py`）比对。
- **对照（这几条是对的，别修坏）**：互斥（F1a）、退场清锁（F1a2）、

### M9（P2）fasttest 失败归因被展示类参数静默关掉

- **现象**：`run.py -x --tb=short`（README/AGENTS 的**官方示例**）跑的仍是
  全量，但"新增失败 N / 上轮失败已消失 M"对比和权重学习都不发生，
  **也没有任何提示**（"定向运行"提示只在带文件/nodeid 时打）。
- **复现**：探针 F3b（断言目标行为"展示类参数不关归因"→ 红）。
- **期望 vs 实际**：期望归因开门（这仍是全量）；实际
  `pure_full = not targeted and not extras` 把 `extras=['--tb=short']` 也算进去。
- **根因方向**：归因门控把"透传参数"当成一个整体。筛选类（`-k`/`--lf`/文件）
  关归因是对的；展示类（`--tb`/`--durations`/`-v`）关归因只会误导。
- **建议修法**：参数分类（白名单展示类不动门控），或至少打印
  "本轮带了透传参数：不做新增/消失对比、不更新权重"。

### M10（P2）`test_disk_hygiene` 的 rglob+stat 与并行 worker 竞态

- **现象**：`test_pytest_basetemps_do_not_accumulate` 对 `.pip-tmp` 每个顶层
  目录 `rglob('*')` 后逐个 `f.stat().st_size`，而**本轮 basetemp 就住在
  `.pip-tmp/fasttest/runs/<轮>/tmp`**，此刻别的 worker 正在建/删临时文件。
  文件在 `is_file()` 与 `stat()` 之间消失 → `FileNotFoundError` → 用例 ERROR
  （偶发，"并行假失败"候选）。排序插件把它钉在第一跑只解决"变慢"，不解决竞态。
- **期望 vs 实际**：期望扫临时目录永不因并发写入而 ERROR；
  实际存在窗口（静态推理 + 结构确认：被扫树包含活 basetemp）。
- **建议修法**：`stat` 包 `try/except OSError: continue`；或跳过本轮 basetemp
  （`--basetemp` 路径从环境/参数透传给用例）。

### M11（P2）`AGENTS.md` 退出码表缺 3 / 130
