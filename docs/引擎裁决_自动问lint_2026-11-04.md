# 引擎裁决：lint 能问什么、不能问什么（2026-11-04，2026-11-05 纠正）

> 用户 2026-11-05：
>
> > 「`aa` 是服装的定义！在 charactercenter.rpy，它根本不对应任何 image。
> >   `show lan aa happy` 在真实项目里完全能跑 —— 你不能去问它是不是 png，
> >   这没有用！」
>
> 以及更早那句仍然成立：「应该从变量入手吧？看变量有没有被定义吧？？」

## 一、先认错：上一版把 lint 的否定当成了"不存在"

上一版把 `renpy lint` 的 `'lan aa happy' is not an image.` 当成最硬裁决，
压在项目声明前面。这是错的，原因在引擎源码里写着（`renpy/common/
00layeredimage_ren.py`，`LayeredImage._duplicate`）：

```python
attributes = set(args.args)
unknown = set(args.args) - 已声明属性
…
if unknown and args.lint:          # ← 只有 lint 模式才登记成"错"
    args.extraneous()
if unknown and config.developer:   # ← 运行时只画一行调试字
    rv = Fixed(rv, Text("unknown attributes: …"))
```

也就是说：

- **运行时**：认不出的属性被**忽略**，图照常显示（开发者模式下多一行小字）；
- **lint**：把"认不出"登记成 `is not an image`；
- `layeredimage` 的属性组合**根本不注册成独立图片名**（项目自己的注释也
  写着：`has_image('ling_cc happy')` 会误判 False）。

真机证据：`sr_general` 跑 `renpy.exe <项目> lint` 共 **949 条**
`is not an image`，其中 100 个不同名字被缓存；游戏照跑，922 处
`show <tag> aa …` 都是这个形状。`aa` 是
`CC_OUTFIT_CYCLE = {"lan": ["aa", …]}` 里的服装代号（"普通"），
`aa.png` **不存在**，它也不是 `layeredimage` 的 `attribute`。

## 二、现在引擎层管什么

| 情况 | 谁说了算 |
|---|---|
| 项目**声明过**这个 tag（`layeredimage` / `image`） | 声明 + 项目变量字面量 + 同名图片；**lint 不参与** |
| 项目**没声明过**这个 tag（`bg_1`、`totally_missing`） | lint 的 `is not an image` = 真否定（注册表里确实没有） |

提示顺序（`storygraph/ui_qt/sprite_hints.py`）：

```
① 项目声明过 → 属性/变量/图片三路都认；错词才报
①′ 只差写法（大小写 / 下划线）
② 引擎否定（仅"项目没声明过"的 tag）
③ 角色表认领
④ 有立绘素材、角色表没认领
⑤ 都没有 → 去资源映射
```

## 三、"变量"这一路的通用判据（不为任何项目加表）

- `init python` / `define` 里**定义位置**的标识符字面量
  （`CC_OUTFIT_CYCLE` 这种 `{tag: [代号]}` 结构由通用 AST 扫描收到 `aa`；
  工具**不需要知道**这个结构叫什么、也不必为它建表）；
- `layeredimage` / `image` 声明的属性名；
- **同名图片真的在**：按该 `layeredimage` 自己的 `image_format` 展开后文件
  存在（声明漏写 `attribute`、但图在时仍算认识，真机 `lan lose`）。

不从"剧本里用过"取证 —— 那是循环论证（用户 2026-11-03 已否掉）。

## 四、错词现在怎么说

`lan based`（真机）：

```
「lan」没有「based」这个属性 —— 项目里声明的是：afraid / agreeable / … / uh。
认不出的词运行时会被忽略，实际显示 `game/images/characters/lan/indifferent.png`
（引擎不报错，但演出不是你要的）。换一个，或者在剧本里补一条 attribute。
```

这句同时给三件事：**哪个词错**、**项目里有什么**、**实际会显示哪张图**
（`Symbols.resolved_paths_of` 走 `layeredimage` 的组条件 / 默认属性）。

## 五、引擎自动化（这部分没变）

`storygraph/assets/engine_images.py`：

```
镜像 .rpy  →  renpy.exe <镜像> lint  →  解析 "'X' is not an image."  →  缓存
```

| 决定 | 为什么 |
|---|---|
| 只镜像 `.rpy`，不拷图片 | 引擎判名字看注册表；用户原话"万一 show 的不是 png" |
| 缓存存用户级目录（逐级回退） | **不写用户项目** |
| 缓存 key 规范化 | `str` 与 `Path` 会算出两个 key |
| 失效判据 = 脚本指纹 + 图片数量 | 改了 `.rpy` 或加了图就重跑 |
| 只给**否定**证据 | lint 只检查被 `show` 用到的名字 |

`AssetRegistryMixin._kick_engine_images()` 在打开项目时：缓存新鲜就直接用，
否则起 daemon 线程跑（真项目约 14 s），不阻塞 UI。

## 六、判据

`tests/test_sprite_hint_engine_verdict.py`（已按新判据重写）：

| 组 | 钉什么 |
|---|---|
| `TestDeclaredTagIgnoresEngine` | 声明过的 tag：变量词不被 lint 推翻；错词照报且给实际图片 |
| `TestUndeclaredTagUsesEngine` | 没声明过的 tag：引擎否定才引用 lint 原话 |
| `TestOrderNormalised` | 同一组属性词顺序无关 |
| `TestItRunsAutomatically` | 缓存新鲜不起线程；没缓存必起 daemon |

另有 `tests/test_sprite_hint_detector.py::TestVariableAndImageEvidence` 与
`tests/test_sprite_hint_hell_structures.py::TestOutfitCodeWithoutAnyPng`
（真造一个 `{tag: [代号]}` 的自定义结构、不写 `aa.png`，断言卡片闭嘴）。

## 七、已知边界

- **变量词是全局的**：`defined_words()` 收全项目标识符字面量，所以
  `hanfu_base`（别的角色的服装）写在 `lan` 上也会被放过。要判到"按角色"
  就得为具体项目建表 —— 那会破坏通用性（用户 2026-11-05 明确否掉）。
  这时"实际显示哪张图"仍可由卡片上的缩略图/诊断看到。
- **不能说"引擎说合法"**：lint 只否定被用到的名字，没被 `show` 过的它不表态。
- `aa` 那 922 处**要不要清**是用户的事；工具不再把它判成错误。
