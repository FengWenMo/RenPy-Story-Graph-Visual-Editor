# 232 条"资源问题"的根因：工具扫了 `game/` 之外（2026-11-04）

> 用户：「按理说这绝对是工具的锅！！！为什么会导致这种情况？」

## 一、先看那 232 条是什么

`asset_health_report()` 的各个"问题桶"：

| 桶 | 条数 |
|---|---|
| `outside_game` | **232** |
| `duplicate_ids` | 0 |
| `duplicate_paths` | 0 |
| `no_path` | 0 |
| `missing`（表里有、盘上没有） | 0 |
| `unregistered`（盘上有、表里没登记） | 0 |

232 条的构成：

```
about_collection_smoke.png            1   ← 项目根下的一张散图
模拟操作/lint_proj/game/images/…    231   ← 一个测试副本目录
```

**你担心的"重复 ID / Path 不存在"一条都没有。** 真正的病只有一种：
**表里混进了 `game/` 之外的路径。**

## 二、这是谁的锅：工具的

调用链：

```
EditorSession.load_assets()
  → load_asset_registry(root)
  → ensure_asset_tables(root)          ← root = **项目根**
      → scan_assets(root)              ← 从项目根开始 rglob
```

`scan_assets(root)` 遍历的是**整个项目根**，而资源表这句话的语义是
「**这个项目的 `game/` 里有什么**」。于是：

- `模拟操作/`（我们自己的测试副本，里面有完整的 `game/`）→ 231 张图被当资源
- 项目根下的 `about_collection_smoke.png`（冒烟脚本留下的）→ 1 张

**用户从没要求扫 `game/` 之外的东西** —— 所以这确实是工具的锅。

### 为什么不能在 `scan_assets` 里加过滤（试过一次，红了）

第一版在 `_scan_file_items` 加"相对路径必须以 `game/` 开头"，结果
`test_scan_golden` 直接红：那个金标测的是**"扫一个装着多个项目的父目录"**
（路径长成 `sr_general/game/…`），在那里按 `game/` 前缀过滤会把**别的项目
一起滤掉**。

⇒ 过滤只该发生在**建表侧**（"这张表代表这个项目的 `game/`"那句话生效的地方）。

## 三、修法

```python
# storygraph/assets/asset_registry.py

def _drop_outside_game(assets, root):
    """丢掉 Path 不在 game/ 下的行 → (干净的 assets, 丢了几条)。"""
    # 没有 game/ 的项目（少见但合法）原样返回 —— 不猜

def _scan_inside_game(root, **kw):
    """扫一次并丢掉 game/ 外的行（建表 / 对账都该走它）。"""
    assets, _dropped = _drop_outside_game(scan_assets(root, **kw), root)
    return assets
```

三处调用全换成 `_scan_inside_game`：首次建表、重建表、对账/补登。

验证（临时项目：`game/` 里 1 张 + `模拟操作/` 1 张 + 根目录 1 张）：

```
建表结果: ['game/images/characters/qing/normal.png']
✓ game/ 外的 2 个被丢掉
```

## 四、顺带补上"显示名当 tag"这项检查

你说的另两类问题里，**"显示名当 tag"以前体检根本查不到** ——
它在**映射文件**里（`storygraph.mapping.json`）：

```json
{"images": {"qing": {"kind": "sprite", "char": "青", "attr": "base"}}}
```

`char` 是填 **image tag** 的槽，真机填了**显示名「青」**。工具照做 →
`show 青 base` → 引擎报"找不到图像"。

新增 `_bad_mapping_rows(reg)`：`char` 不是合法 image 名、也不是项目认的 tag
→ 一条，并计入 `problems`。真机实测抓到 1 条：

```
{'asset': 'qing', 'char': '青',
 'why': '映射把 image tag 填成了「青」—— 那不是合法的 image 名，'
        '`show 青 …` 在引擎里找不到图像。该填项目里的 tag（如 `qing`）'}
```

判据：`_IDENT_RE`（字母/下划线开头、可带点分段）；项目认的 tag 走
`known_tags_of`（characters 表 + 映射 + 声明，唯一真源）。

## 五、你该怎么清那 232 条

两条路（都不该让工具偷偷替你决定）：

1. **重扫一次**：修好之后 `ensure_asset_tables` / 对账不再把它们写进来；
   但**已在表里的老行不会自动删**（那是用户数据）。

   （`模拟操作: 231`、`about_collection_smoke.png: 1`），删这两组就行。

要不要我加一个"清掉 `game/` 外的行"的一键操作（带 diff 预览 + 备份）？
那是**写操作**，得你点头。
