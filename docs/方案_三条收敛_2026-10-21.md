## 一、说话人 + 台词同改：真因不是"退回全量"，是**多出一行**

### 实测

表格路径（`table rpy2xlsx` → 改单元格 → `table xlsx2rpy`），第 28 行
`jc "好了，我休息好了，继续学习吧."` 同时改说话人（`jc` → `yhj`）和台词：

```diff
     hide whitediamond
+    yhj "【同改】这一句连说话人一起改了"
     play sound "pomodorro/music/chime.wav"
     jc "好了，我休息好了，继续学习吧."      ← 旧行还在
```

回执是「改动 2 行」，退出码 0 —— **同一句话在文件里出现了两遍**。

界面路径（`EditorSession.load` → `set_speaker` + 改 text → `export`）没有这个问题：
行号新鲜（`trust_ranges=True`），`_rewrite_line` 直接换掉那一行。

### 真因

`_replace_matched` 的配对键是 `('say', 说话人)`：

1. 说话人和正文都变了 → 与原文哪一行都配不上；
2. 新行走"新增内容"通道被**插入**（区间平整、身份不重复，准入通过）；
3. 旧行是台词，`_may_drop_line` **不许删**（删台词=丢内容）→ 留下。

于是"插入 + 保留" = 重复。未定义角色（拼错名字）更明显：渲染器会写
`# TODO: 缺少资源 角色 'qing'` + 旁白，旧台词同样留着。

### 方案

**同一拍里台词是唯一的**（一拍最多渲染一行台词；菜单选项、`extend`、`voice`
都被 `_say_parts` 排除在外）。所以配对有第三轮，且是确定性的：

> 旧区间剩 1 行台词、生成块剩 1 行台词 → 配成一对，按"槽位替换"处理
> （允许说话人与正文同时变）。

- 只对 `_say_parts` 认得的真台词生效 —— 不碰选项行、不碰 `voice`/`extend`；
- 只在一对一时生效（两边都只剩一行），两行以上不做任何猜测；
- 替换后仍走 `_verify_patch`（重新解析 + 内容全在）兜底；
- 顺带覆盖"未定义角色"：新行是 TODO+旁白时，旧台词被替换而不是并存。

### 判据

- 表格路径：同改后**恰好 1 行**变化，文件里不再出现旧台词；
- 未定义角色：产物里有 TODO 注释，但没有重复台词；
- 现有 5000+ 测试全绿（尤其 `test_incremental_export.py` 的"不许重复行"族）。

## 二、删一拍：真因是"这一拍是分支的唯一语句"（12/45）

### 实测（逐拍删，45 拍全扫）

| 结果 | 数量 | 例子 |
|---|---|---|
| 增量补丁成功 | 33 | `pomodoro.0007`（删 5 行代码） |
| 退回全量 | 12 | 见下 |

12 个失败**全是同一种形状**：被删的拍是某个 `if`/`elif` 分支或菜单选项体的
**唯一语句**。

```
if breakline == 1:          ← 行 229（不是拍，是结构）
    "我需要休息一下."          ← 行 230 = 被删的拍
elif breakline == 2:        ← 删掉上面两行后，这一行成了孤儿
```

patcher 的拒绝是**对的**（`_deletion_empties_block`，10-19 修 P1-3）：
删了会写出 `expected statement`。问题在于**这个"不可能安全"的删除被拖到导出时
才说**，代价是整章退回全量（手写 `default` / `transform` 全靠门禁拦着）。

### 方案：把"删一拍"升级成"删这一拍所在的整条分支"

分三种形状，都只动**必须动**的那几行：

1. **`elif` / `else` 分支的唯一语句** → 删 `[分支头 .. 拍末行]`，链自然合法。
2. **`if` 分支的唯一语句**，后面紧跟同缩进的 `elif` → 删 `[if 头 .. 拍末行]`，
   并把下一条 `elif` 改写为 `if`（**只改这一个词**）。若后面是 `else:`
   （需要把整块内容降一级缩进）→ **不猜，退回全量**并说明。
3. **菜单选项体的唯一语句**（选项头自己是一拍，不能删）→ 把体替换成
   `pass`（与全量重生成的产物**逐字一致**，已实测：`"该休息了!":` + `pass`）。

删除计划仍走 `_plan_deletions`，新增一条"整分支"通道；改行由
`_apply_sequence_edits` 在同一批里做（先改写、再按原行号从后往前删），
最后仍由 `_verify_patch` 重新解析校验。

### 判据

- 45/45 逐拍删除都走增量（`else` 形状那一种若出现，明说退回全量）；
- 产物重新解析后：拍数 = 44，被删的句子不再出现，`elif` 链仍然合法；
- 删菜单选项体的产物里有 `pass`，且与全量重生成逐字相同。

## 三、Unity：从"两个 JSON + 说明"到**可直接导入的 .unitypackage**

### 现状

导出目录里只有 `story_ir.json` / `UnityDialogueData.json` / `UNITY_IMPORT.md` /
`IR_LOSS-unity.md` / `IR_CHECK.md`。数据是全的，但 Unity 侧**一行代码都没有**：
用户要自己写 `DialogueData` 类、自己写加载器、自己挂脚本。

### 方案

新增 `storygraph/pipeline/unity_package.py`，产出 **`.unitypackage`**
（gzip + tar；每资产一个以 GUID 命名的目录，内含 `pathname` / `asset` /
`asset.meta`）。Unity 里 `Assets → Import Package → Custom Package…` 直接导入。

包内容（`Assets/StoryGraph/`）：

| 路径 | 作用 |
|---|---|
| `Runtime/DialogueData.cs` | `JsonUtility` 能吃的纯数据类（与 JSON 字段一一对应） |
| `Runtime/DialogueDatabase.cs` | 从 `Resources` 载入 + 按 `lineId`/`label` 建索引 |
| `Runtime/DialoguePlayer.cs` | 最小播放器：空格前进、显示说话人/台词/背景 |
| `Resources/UnityDialogueData.json` | 数据（`Resources.Load` 直接能读） |
| `story_ir.json` | 中立 IR（给自定义解析用，`TextAsset`） |
| `README.md` | 导入步骤与字段含义 |

三条硬约束：

- **GUID 稳定**：由资产路径派生（同一路径重导 → 同一 GUID → Unity 是**更新**
  不是新增），不随内容变化；
- **字节同源**：`.unitypackage` 里的 `asset` 与散落文件来自**同一份 bytes**，
  测试逐字节比对；
- **不猜 Unity 版本**：`ProjectSettings` 之类一概不写，只给资产。

### 验证（无 Unity 也能验）

1. **结构**：解包后每个 GUID 目录三件套齐全、`guid` == 目录名、
   `pathname` 以 `Assets/` 开头、无重复 pathname、无 `.meta` 冲突；
2. **编译**：`dotnet`（本机 9.0.304）+ 一份 `UnityEngine` 桩（`MonoBehaviour` /
   `JsonUtility` / `TextAsset` / `Resources` / `Debug`）编译三个 `.cs` → 0 error；
3. **往返**：解包字节 == 散落文件字节；同一输入两次导出**逐字节相同**。

### 判据

- `export_ir('unity')` 的产物集合里多一个 `StoryGraph.unitypackage`，
  `expected_files('unity')` 同步（测试逐条对账）；
- 上述三条验证进测试（无 dotnet 时**跳过**编译那条，不静默通过）。

## 四、演出预览的字体：要查，且把"来源"说出来

### 结论：做，但只做"能说清楚"的部分

预览用 PIL 画台词，字体来自 `GuiProfile.text_font_path` / `name_font_path`。
真机 `seiran_project-2` 上解析到的是 `fonts/普力士Plix/Plix-Regular.otf`
（`gui.text_font`），引擎用的也是它 —— **这一项是一致的**。会漂的只有三种：

1. **`gui.dialogue_text_font` / `gui.dialogue_text_size`**：Ren'Py 的
   `gui.text_properties("dialogue")` 会优先用 `dialogue_*`，而 profile 只读了
   `text_*` → 项目一旦覆盖，预览的字号/字体就与引擎不同（**当前没读**）；
2. **`Character(what_font=..., who_font=...)`**：某个角色单独换字体；
3. **`FontGroup`**：混排字体（CJK 常见），预览只能取其中一支。

### 方案

- `renpy_gui` 增读 `gui.dialogue_text_font` / `dialogue_text_size` /
  `dialogue_text_outlines` 与 `Character(..., what_font=, who_font=)`；
  解析后的"有效字体"进 `GuiProfile`（带来源标签：来自哪个 key / 哪个角色）；
- 预览渲染用**有效字体**（不是现在的 `text_font` 一把抓）；
- 预览面板显示一行「字体：`Plix-Regular.otf`（gui.text_font）」；发生替代/覆盖时说清楚
  （「预览用 A，引擎这句用 B（来自 gui.dialogue_text_font）」）；
- **不模拟** `FontGroup` 与 `{font=…}` 文本标签：检测到就在面板与警告里明说，
  绝不让用户以为预览=引擎。

### 判据

- 造一个"`dialogue_text_font` 指向另一支字体"的项目 → 预览加载的是那一支，
  面板显示来源；
- `Character(what_font=…)` 的角色说话 → 预览换字体，面板说"来自角色 X"；
- `FontGroup` → 面板出现"预览不模拟 FontGroup"的说明（不是静默）。
