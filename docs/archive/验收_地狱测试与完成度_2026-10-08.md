## 二、地狱测试都"为难"了什么

### 1. CST（`core/cst.py`）—— `tests/test_hell_cst_edges.py`（15 条）
- **编码头**：带 UTF-8 BOM 的 `.rpy` 必须照常解析（原来**一条语句都解析不到**）。
- **行尾**：CRLF 文件"真迹自洽"（不许 mismatch）；`raw_text` 里不许夹 `\r`。
- **缩进字符**：Tab 缩进逐字保真 + `Trivia.indent == '\t'`。
- **边界**：末行无换行、连续大段空行、`blank_before` 计数。
- **强化不变式**：`label` 内**每个非空物理行恰好被一条 span 覆盖**（`overlaps()` 只抓"重"，
  这一条抓"漏"—— 漏 = 写回时那一行会消失）。
- **自足性**：删掉源文件后 `statement_text()` 仍逐字给原文（含自定义块 / 嵌套块 / 续行）。
- **动态属性契约**：挂了 CST 的语句与干净孪生体必须相等同哈希（协作主键）。
- **判据反空转**：故意拿别的原文核对，`mismatch` 必须 > 0。

### 2. 块状编辑器的语法检查 —— `tests/test_hell_block_editor_syntax.py`（38 条）
这里实际是**两个**检查，判据相反，分开打：
- **块编辑器（双击模块 → 编辑剧情变量 → 「语法检查」按钮）**：10 种坏行**必须报错**、
  12 种好行**不许误报**（`love += 1` 这种"变量未定义"是运行期的事，不算语法错）、
  报错要指到行号、混合输入只报坏行；并在 **offscreen Qt** 里验证对话框真的把错误显示出来。
- **产物 Python 门禁 `PYTHON_SYNTAX_ERROR`（build/导出）**：`l oh "3"`（历史事故）、
  未闭合括号、块里混进 Ren'Py 语句**必须拦**；`$ x = [` 的**续行**、`for` 块、f-string、
  `;`、纯注释**不许误报**（一版逐行编译曾把 `build` 在真实项目上卡死）。

### 3. 静态分析图 —— `tests/test_hell_static_analysis.py`（355 条）
核心是一条**可靠性不变量**，用"枚举具体值"的 oracle 反过来压实现：
> 只要存在某个具体取值让条件成立，`condition_possible` 就**不许**返回 False，
> `apply_condition` 就**不许**返回 None（那是"把可能说成不可能"→ 图上正常剧情被标红不可达）。

外加：浮点字面量具体复现、图级"可达分支不许被判 stranded"、菱形合并、自环/大环（400 节点）
终止性、60 路扇出、入口判定（`is_current` / 标准 label / 权威性）、非权威入口不许断言不可达、
`reachable_from_all_roots` 的真孤岛、加宽到 ∞、空图不崩。

### 4. 自定义语句发现（CST 区域另一侧）—— `tests/test_hell_statement_discovery.py`（20 条）
`register_statement` 字面量提取（多行/嵌套 lambda/字符串含括号逗号）、`find_scripts` 发现范围、
清单 > 宿主 优先级、`declare_statement` 写清单（坏 JSON **拒绝覆盖**、同名更新、别的键保留）。

## 五、完成度评估（含"该修但没修"）

**稳的地方**
- 三层架构 + 单源多视图 + 受控 patch 的契约**成体系**（A–N 二十余组不变量，多数有守卫测试）。
- 端到端链路可用：`.rpy → Excel → 编辑 → 增量写回` 逐字节保真；Qt 界面可起、可导入、可分析、可导出。
- 依赖方向干净（`core ← parsing/excel ← assets/story ← pipeline ← ui`，0 反向边）。
- 真机验收对象 `sr_general`（88 `.rpy` / 3.6 万行）目前 `validate` 仅 1 个资源侧错误。

**该修 / 缺口（按优先级）**
1. **CST 是"验证层"不是"保真主干"**：`statement_text()` 生产零调用、`parse_result.cst_attached` 只写不读。
   要么让它成为 `opaque`/未建模语句的渲染真源，要么接进增量 patch 的"真迹对账"，否则就是
   "能力做了没人看见"（建议优先**收口**：删掉只写不读的 `cst_attached`）。
2. **`project_conventions.py` 三层机制仍零生产调用** —— 用户核心诉求"工具必须能被教会项目结构"只靠 CDS 部分满足。
3. **解析层真 bug**：`if` 内嵌 `menu` 整体降级、分支内 show+say 混合导致 `elif` 消失、
   菜单两选项间插一拍被吸进 menu 组；嵌套菜单≥3 层全量路径静默产坏结构。
4. **转义只有一半自反**：菜单标题 `\n` 每渲染一次反斜杠翻一倍（未修）。
5. **多引擎导出丢接线/行类型**；多章导同一目录静默覆盖。
6. **"程序改代码→表格自动反映"** 仍是 1.5s 轮询 + 全量重解析。
7. **静态分析仍是"整数域 + 保守"**：链式比较、`not` 不做 De Morgan（宁可少报；可靠性已由本次修复守住）。

**体检红线（`tools/health_check.py` 判定"有该修的项"）**
