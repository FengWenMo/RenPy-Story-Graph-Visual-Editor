# 地狱测试：把"最极端的魔改写法"喂进真引擎

### —— 三条线（lint oracle / 定义表覆盖层 / 扫描发现）在极端情况下的承压测试

> 2026-10-10 ｜ 环境：Ren'Py SDK **8.5.3** ｜ 用例：**17 个** ｜ 测试床：临时工程（不碰真机数据）  
> 运行器：**`tools/hell_engine_oracle.py`**（可复跑：`python tools/hell_engine_oracle.py [C3 C7 …]`）

## 一、为什么做这一轮

上一轮的三条线是在**标准写法**上验证的。用户警告："本项目并不完善，没有更多自定义模块……  
**先别动工**，写几个用尽全力魔改的文件喂进去再测一遍。"——于是有了这一轮。

**结论先说**：三条线**主干站得住**，但**被这轮抓出 4 个必须补的洞**，  
其中 2 个是"引擎接受了、我们的 oracle 却是瞎的"。

## 三、四个必须补的洞（都有实测证据）

### 洞 1 ⭐⭐ 扫描盲区：引擎接受、扫描器看不见（C4）

CDS 的名字**不是字面量**时（`_nm = "wea" + "ther3"`），引擎**照常接受** `weather3 雨 0.5`，  
而我们的扫描器（契约 L2：**只认字面量**）**拿不到这个名字** → 这个写法**不在"待认识"列表里**。

**危害**：不是"漏报"，而是**工具会以为项目里没有这个写法**，编剧却在用。  
**补法**：扫描器**永远不能宣称"项目里没有自定义语句"**，只能说"**我认出了 N 个**"。  
措辞必须改（否则就是静默的错误知识——正是我们要防的那类）。

### 洞 2 ⭐⭐ 覆盖内置语句可行，且默认无信号（C7 + C16）

- **C16 证明**：`renpy.register_statement("pause", …)` **真的覆盖了内置 `pause`**。
- **C7 证明**：如果那个覆盖**自己不报错**，**lint 一声不吭**（exit 0）。

也就是说 —— **用户假设的"程序直接改已有语句的解析规则"，可以完全通过 CDS 做到，  
而且今天的工具链对此毫无察觉。** 这是本轮最大的发现。

**补法（纯静态、便宜、必须做）**：

> 扫 `register_statement(<名字>)` 时，**把名字与内置语句表求交**。  
> 非空 → **报警**："本项目覆盖了内置语句 `pause`；工具对它的参数形状**不保证正确**。"  
> （这与既有的 `declared_builtins()` 是同一族做法，只是方向反过来：那条查"声明了内置"，这条查"覆盖了内置"。）

### 洞 3 ⭐ 同组属性冲突，lint 不查（C10）

`show lan happy sad`（`happy`/`sad` 同属一组）→ **lint exit 0，静默通过**。

**危害**：编剧把两个互斥属性同时填上，工具一路放行，**到运行期才出问题**。  
**补法**：**工具自己查** —— 用引擎枚举出的 **group** 做一次"同组是否多选"检查。  
（好消息：**group 就在枚举里**，这条检查的实现成本几乎为零。）  
⚠ 顺带说明：**lint 不是万能的**，它有明确的能力边界；我们不能把所有检查都推给它。

### 洞 4 ⚠⚠ parse error 会**连探针一起杀死**（C13 / C16 / C17）

三个用例里，**只要有一个 parse error，`facts.json` 就不产出**（探针根本没跑到）。  
同时 C13 证明：parse error 存在时，**后面的语义检查（非法属性）全被吞掉**。

**后果**：CI 里若工程处于"有语法错"的状态，**事实采集会静默地什么都没采到**。  
如果代码把"没产出"当成"没有变化"——就是**最坏的一种静默失败**。

**补法（硬前提）**：

> **\`原工程 lint 必须干净（无 parse error）→ 才允许采集事实。**  
> 探针产出缺失 → **必须报"采集失败"，绝不允许当成"没有漂移"。**  
> 这条要写成判据（"没产出 ≠ 没变化"）。

## 八、第二轮的六个结论

### 结论 1 ⭐⭐⭐ 覆盖内置语句 = **完全替换**，不是叠加（D1a/D1b）

把 `pause` 覆盖成"只认 MAGIC"之后：**标准的 `pause 1.0` 直接报错**，只有 `pause MAGIC` 通过。  
→ **内置的 parse 被彻底顶掉了。**  
→ 工具**绝不能假定"覆盖之后内置形状还在"**。

### 结论 2 ⭐⭐⭐ 项目**能覆盖 `show`**（D2）——最高优先级缺口证实

`SG-SHOW: show 已被项目覆盖`。一旦发生：  
**所有基于标准 `show` 的生成/解析/候选逻辑全部失效**，而这是本工具最核心的一条语句。

### 结论 3 ⭐⭐⭐ **默认 say 语句也能被整体替换**（D3）

`name=""` + 报错的 parse → **两行台词都报错** ⇒ say 真的被换掉了。  
→ 工具&#x7684;**"说话人 + 台词"模型**在这种情况下不成立。  
→ ⚠ 而且这一条在**不报错**时（parse 能干活的版本）**完全静默**（对照第一轮的 C7）。

### 结论 4 ⭐⭐⭐ **fork 引擎新增的语句，对工具完全隐形**（D4a/D4b）

在 fork SDK 里**改解析器分派**加一条 `weather6`（模拟"程序真的改了引擎"），  
项目里**一个 CDS、一份声明都没有** → **lint 接受**；换官方 SDK → 拒绝。

⇒ 我们的**扫描器 / lint / 探针 / `--json-dump` 四路全都没有任何信号**。  
**唯一的线索是"用法本身"**（脚本里出现过 `weather6`）——这正是"扫描做发现"这条线的**存在理由**，  
也说明**它不可被取代**。

⚠ **副产品（我们自己的两个坑，都值得记）**：

- 在 `renpy/statements.py` **导入期**调用 `register()` → 闭包进了 ParseTrie →  
  `backup()` 序列化失败 → **引擎直接起不来**（`Can't get local object 'register.<locals>.parse_user_statement'`）。  
  → 说明"引擎自带的语句"必须由引擎在 **bootstrap 之后**注册。
- 在解析器分派里注入语句，**必须自己推进 lexer**（`l.advance()`），否则 `parse_block` **死循环 → `MemoryError`**。

### 结论 5 ⭐ 跨文件同 tag：**后者覆盖前者**，且**性质不同**（D5/D5b）

| 形态                    | lint                             | 结果                           |
| --------------------- | -------------------------------- | ---------------------------- |
| 两个 `layeredimage lan` | **报错** `'lan x' is not an image` | **后者整体覆盖**，枚举只剩后者的属性（`g2/y`） |
| 两个 `image lan x = …`  | **exit 0，静默**                    | 无任何提示                        |

→ 工具必须**自己检测"同 tag 重复定义"并报出**，否则下拉里会出现**实际已不存在的属性**。

### 结论 6 ⚠⚠ 两个操作性结论

**6a 孤儿 `.rpyc` 不会被自动清理**（D6）：  
只删探针 `.rpy`、留下 `.rpyc`，再跑一次 lint → **`.rpyc` 仍在**。  
→ 用户提醒的残留问题**成立**；**清理必须显式包含 `.rpyc`**。

**6b `test` 命令在 headless(dummy) 下不可用**（D7）：  
exit **143**（SIGTERM 终止），测试没跑完。  
→ **行为级验证（`testcase` + `assert`）不能直接进 CI**；  
→ 需要一个**真实显示后端**（Linux CI 的标准做法是 `xvfb-run`；Windows 上则需另想）。  
→ **这是本轮对"终极方案"最重要的一条修正**：行为级验证**不是免费的**，  
它**不能**成为 CI 的默认手段；CI 里能依赖的仍然只有 **lint + 探针**。

# 第二轮之后：终极方案的 4 条追加规则

| #      | 规则                                                                                                             | 依据       |
| ------ | -------------------------------------------------------------------------------------------------------------- | -------- |
| **N5** | 扫到 `register_statement(<内置名>)` **或** 解析器分派被改动 → **报警"内置语句被替换，形状/语义不保证"**；对 `show` / say（`name=""`）**升级为最高级警告** | D1/D2/D3 |
| **N6** | **同 tag 重复定义必须由工具自查并报出**（lint 只覆盖 layeredimage 那一种，普通 `image` 静默）                                              | D5/D5b   |
| **N7** | 探针清理**必须包含 `.rpyc`**（孤儿不会被引擎自动清）；采集前先删旧探针产物                                                                    | D6       |
| **N8** | ⚠ **行为级验证（`test`）不进 CI 默认路径**（headless 不可用）；CI 只依赖 `lint + 探针`；行为级只在开发机/带显示后端的流水线里跑                            | D7       |

**对"什么时候找程序"的最终修正（三种，不是两种）**：

| # | 情况                                 | 为什么                                     |
| - | ---------------------------------- | --------------------------------------- |
| 1 | 引擎被 fork，源码不在项目里                   | **fork 新增的语句对工具完全隐形**（D4 实测）——只能靠用法扫描发现 |
| 2 | 项目用 CDS **覆盖内置语句**（含 `show` / say） | 覆盖=**完全替换**（D1/D2/D3 实测），内置形状立刻失效       |
| 3 | 项目用 CDS 注册了**计算出来的名字**             | 扫描器看不见（C4 实测）；引擎却接受                     |



> 除这三条外，**不需要程序配合任何事**。
