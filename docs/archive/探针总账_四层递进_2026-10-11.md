# 探针总账：四层递进（引擎事实 / 行为验证）· 2026-10-11

> **为什么单独一份**：这一轮往 `tools/` 里加了 13 个 `probe_layer*.py`。
> 探针的价值全在"**它当时证明了什么、结论是什么**" —— 光看文件名看不出来，
> 半年后没人知道哪个还能跑、哪个的结论已经被推翻。
> 这份总账就是那份"证词清单"（口径与 `tests/README.md` 一致：
> **探针负责"向外求真"，判据负责"钉住结论"**）。

## 通用说明（先读这三条）

1. **探针都要真机** —— 需要一个真实的 Ren'Py 项目（默认
   `D:\千连万理\RenpyTest\sr_general`）+ 一个 SDK（`find_sdk()` 自己找）。
   项目不在本机时探针会打印"跳过"并以 0 退出，**不会假装跑过**。
2. **绝不碰真项目** —— 一律 `_copy_for_ask()` 轻量副本（只拷 `.rpy`/`.json`/`.txt`，
   跳过图像音频），跑完删临时目录。⚠ 整份 `copytree` 那个 8GB 项目会把磁盘写满
   （实测事故，别再犯）。
3. **探针不做门禁** —— CI 门禁是判据（`pytest`）。探针是**一次性的求真实验**，
   结论一旦钉住就写进判据；探针留着是为了"以后能重跑一遍看结论有没有变"。

### 第二层 · 隔离合成工程

| 探针 | 证明什么 | 结论 |
|---|---|---|

### 第三层 · 行为级（`test`）

| 探针 | 证明什么 | 结论 |
|---|---|---|
| `probe_layer3_testcase.py` | `testcase` 的断言语法 | ⚠ 裸 Python 表达式被判 `Invalid condition.` → 只认 `( 子条件 )` / `True`/`False` / `eval <表达式>` / `label <名>` / 选择器 |
| `probe_layer3_min.py` | 裸最小工程上 `test` 能不能跑 | ⚠ **无头与有显示都卡住**，而同一工程 `lint` 退 0 ⇒ `test` 需要**完整工程骨架** |
| `probe_layer3_real.py` | 真项目副本上 `test` 能不能跑 | ⚠ 逐步撞出两处缺件：`gui/window_icon.png`、字体 ⇒ **`test` 比 `lint` 多要 `gui/` + `fonts/` + 显示后端** |
| `probe_layer3_testrun.py` | **怎么把结论读出来** | ✅ `test` **不是卡住** —— 它跑完打印报告后**进程不退出** ⇒ 边读边看 `[rpytest] Status:` 再收进程。另：`run` 要**可调用**（`run Jump("x")`） |
| `probe_layer3_label.py` | `assert label X` vs `assert eval` 哪个成立 | ⚠ `assert label` 等的是"**当前停在该 label**"，跳过去秒回就错过去（连"label 里暂停/死循环"都救不了）；✅ **`assert eval` 轮询外部证据成立** |
| `probe_layer3_evidence.py` | ⭐ **断言到底有没有牙**（用"往磁盘写文件"当铁证） | ⚠⚠ **假绿**：`assert eval "False"`、甚至加 `timeout`，**都报 PASSED** ⇒ 判定必须**两把锁**（引擎 PASSED **且**证据文件真的存在） |
| `probe_layer3_api.py` | 用**产品函数**生成的探针能不能跑对 | ✅ ① 语句真执行 → `verified=True` 且证据文件被写；② 没执行 → `verified=False`（引擎仍报 `1 passed`，被复核拦下）。⚠ 路径**反斜杠**会毁掉 `assert eval` → 统一转前斜杠 |
| `probe_layer3_verify.py` | 产品入口 `verify_behavior` + 记进事实 + 报告那一行 | ✅ 三态齐全：`验过 2 个 —— 通过 1 / 失败 0 / 没证明成 1` |
| `probe_verify_button_e2e.py` | ⭐ **真的点一次界面按钮**（窗口 → `_on_verify` → 真引擎） | ✅ 预览区显示 `✅ 通过：…证据文件确实存在`、控制台有 `[验证]`。⚠ 本轮**抓到真缺陷**：`verify_head` 漏拷 `gui/` → 永远"没证明成"（已修：抽 `behavior_copy()`） |

## 四、写探针的纪律（这一轮反复吃过的亏）

| 纪律 | 为什么（都是实测） |
|---|---|
| **别用 PowerShell 的 `@"…"@` 跑含中文/正则/`\$` 的 Python** | 转义被吃掉，我又踩了两次 → **写成文件跑** |
| **中国字进 git 一律走文件 + `git commit -F`** | PowerShell 会毁掉中文 |
| **探针必须能被证伪** | 第三层那套"往磁盘写文件当铁证"的手法要复用（否则探测不到假绿） |
| **对照组不能省** | "不预注册时编译不过""一定不认识的头"这类对照，是判断实验有没有效的唯一依据 |
| **探针自己错了比缺陷更常见** | 本轮三次踩到自己的错：`record_behavior` 形状、`_inject_evidence` 未登记、编辑吃掉判据函数头 |
