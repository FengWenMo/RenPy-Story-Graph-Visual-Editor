# 代码块（CodeBlock）的上下文问题 —— 设计方案

> 用户 2026-10-05：
>
> > 这个代码块实际上有点问题……没有上下文实际上我不知道它是干嘛的……
> > 是否有重复、是否有错误一律不知，因为我没有上下文可供参考啊……
> > emm……这个该如何解决呢？想一个解决方案（先不写代码）
>
> 本文只是**方案**，还没有实现。实现顺序见最后一节。

---

## 一、现在为什么"看不懂"

卡片上那一格（高级区 `CodeBlock`）装的是**这一拍的 `$ …` / python 行**，
在数据层它就是 `Beat.code` 这**一个字符串**（多行拼在一起）：

```
$ renpy.transition(Dissolve(0.1), layer="master")
$ renpy.transition(Dissolve(0.1), layer="master")
```

用户看到它时，缺的是三样东西：

| 缺什么 | 后果（用户原话） |
|---|---|
| **它在源文件里的位置** | "我不知道它是干嘛的" |
| **它和同一拍里 `show` / 台词的关系** | 不知道这两条 `transition` 是跟在 `show ye happy` / `show ye care` 后面的（源文件里本来就是**每条 show 各带一个**），于是看着像"重复" |
| **它跟源文件那一行的对应** | "是否有重复、是否有错误一律不知" —— 分不清"源文件本来就有两条"和"我们把它写重了" |

真实那两行**不是 bug**（源文件 237 / 240 行各有一条），但**界面上无法证明**这一点 ——
这就是问题本身：不是内容错了，是**界面没有把依据摆出来**。

## 二、方案的骨架：把"一坨文本"变成"带出处的清单"

四层，从便宜到贵，**每一层都能单独上线**：

### A. 只读的"这一拍的源文件原文"（最便宜、收益最大）

在 `CodeBlock` **上方**加一块只读面板，显示这一拍在 .rpy 里的**原文那几行**
（`Beat.src_first … src_last`，只读、等宽字体、行号在左）：

```
  236 |     show ye happy at i11
  237 |     $ renpy.transition(Dissolve(0.1), layer="master")
  238 |     # 表情10-可不要之前-表情7 / 表情A10
  239 |     show ye care
  240 |     $ renpy.transition(Dissolve(0.1), layer="master")
```

* 数据来源：`script_path` + `src_first/src_last` —— **解析器早就有**，不用改模型；
* 图没解析出源码区间时（表里读出来的拍 / 新增卡）显示"这一拍还没有落盘位置"，
  并给一句"导出一次就有位置了"。

**为什么先做它**：用户要的就是"上下文可供参考"。这一块直接把上下文摆在眼前，
零语义风险（只读，不参与写回 —— 避免 README 里那条"自己吃自己"的老坑）。

### B. 每行代码标"出处行号 + 挂在哪条 show 后面"

给 `Beat` 加**运行期**元数据（跟 `src_first` 一样，**不进 Excel**）：

```python
code_lines: [
  {'text': '$ renpy.transition(…)', 'src_line': 237, 'after': 'show ye happy at i11'},
  {'text': '$ renpy.transition(…)', 'src_line': 240, 'after': 'show ye care'},
]
```

* `src_line`：解析时按行号直接记（解析器已经在数行号）；
* `after`：这一拍区间内、**它前面最近的一条** `show` / 台词 —— 纯查找，不解语义；
* 写回仍然用 `Beat.code`（那一行行文本），**元数据只用于显示** —— 这样"生成结果
  不变"这条硬契约不会被这次改动碰到。

卡片上的显示：

```
① $ renpy.transition(Dissolve(0.1), layer="master")
      ↳ show ye care 之后（源文件 240 行）
② $ renpy.transition(Dissolve(0.1), layer="master")
      ↳ show ye happy at i11 之后（源文件 237 行）
```

### C. 把"重复 / 错误"变成**判定结论**，而不是让人自己看

拿**源文件那几行**当基准做三条判定（都是纯比较，不猜）：

| 判定 | 怎么算 | 界面上怎么说 |
|---|---|---|
| **本来就是两条** | 同样的文本在源文件区间里出现 N 次、这一拍也 N 条 | 灰字：`源文件里本来就是两条（每条 show 各带一个转场）` |
| **我们写重了** | 这一拍有 2 条、源文件只有 1 条 | ⚠ 橙字：`多出来一条（源文件只有 1 条）` + 按钮「删掉重复那条」 |
| **写进去会被丢掉** | 这一拍的生成结果里没有这一行（`patcher` 的 `unlanded_lines` 已经算出来了） | ⚠ 红字：`这一行没能落到产物里`（这正是不变量 57 兜住的那类事故） |
| **新增（还没落盘）** | 文本在源文件区间里找不到，但人刚编辑过 | 蓝字：`新增` |

这一条直接回答用户的"是否有重复、是否有错误" —— **把依据和结论一起给出来**。

### D. 一键跳到源文件（可选）

每行右边给一个「↗ 源文件 240 行」：用系统默认程序打开 `.rpy`
（`graph.editor_utils.open_with_system_default` 已经有），至少也能复制出
`文件:行号` 让人自己去看。

## 三、为什么不做"把代码拆成结构化语句"

另一种做法是把一拍拆成**有序的行列表**（`[say, show, python, show, python]`，
就是 tkinter 老版的块编辑器模型），代码块自然是列表里的一行。

**现在不做**，理由：

1. 那是**数据模型**的改动（`Beat.code` → 有序语句表），会牵动 Excel 列、
   写回、增量补丁、生成器 —— 与"增量补丁保住注释"这条硬契约正面冲突；
2. 用户的编辑模型是"卡片=一拍，字段=台词/立绘/音乐"，拆成行列表等于换模型，
   违反"不许改用户的交互模型"；
3. A~C 三层能拿到 90% 的收益，而且**随时可以停**。

## 四、实现顺序（每一步都能单独交付）

1. **A**：卡片上加"这一拍的源文件原文"只读面板（半天，零语义风险）。
2. **C 的前两条**：拿源文件区间算"重复是本来就有还是我们写重的"（纯比较）。
3. **B**：`code_lines` 元数据 + "挂在哪条 show 后面"。
4. **C 的后两条 + D**：`unlanded_lines` 提示、跳转源文件。

## 五、要守住的契约（写代码时别踩）

* 元数据**不进 Excel**、**不参与写回**（跟 `src_first/src_last` 一样是运行期字段）——
  否则就是第二个"自己吃自己"（见 README 不变量 43 与 `_apply_stage` 的注释）；
* 卡片上没有源码区间时（表里读出来 / 新插的卡）**不许瞎猜行号**，直说"还没有位置"；
* 判定"是否重复"**必须**以源文件区间为基准；源文件读不到就不下结论（只显示文本）。
