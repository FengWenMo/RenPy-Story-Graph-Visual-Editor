# 设计：自定义语法适应架构

> 2026-10-07 ｜ 触发问题（用户原话）：
> 「若是程序自定义了一个结构，而编剧用这个编辑器编辑时发现：你没有适应到它的
> 自定义结构怎么办？他会立即退出，因为工具没有用！……工具必须能够适应！」
>
> 本文是**诊断 + 架构提议 + 落地记录**。诊断结论都给出 `文件:行号` 证据。
> M1 已实施并验证；M2~M5 与 CST 升级为待办。

## 0. 一句话的重新定位

现在这个工具隐含的假设是：

> **"我必须先理解一句话，才能不弄坏它。"**

工业化工具（Roslyn / MPS / tree-sitter / Ren'Py CDS）的假设是：

> **"我可能永远不理解某些话，但必须能无损地表示它、保存它、并被告知如何理解它。"**

**理解**和**保真**被解耦了。这是全部设计的分水岭 —— 前者是能力，可以慢慢长；
后者是底线，一旦破了，用户就"立即退出"。

## 1. 诊断：为什么现在难以适应自定义结构

### 1.1 分派是硬编码的 if 链，不是注册表

`storygraph/parsing/renpy_parser.py:1833` 的 `_parse_statement` 是一串 **25 个
`_stmt_*` 方法的顺序调用**，注释明写"分派顺序就是匹配优先级，不能重排"。
语句识别靠 30+ 个分散在类属性上的正则常量（`:1104-1172`）。

全仓确认：**不存在任何用于语句/语法的注册表或插件入口**。
唯一真扩展机制是 `assets/asset_registry.py:1823` 的 `load_hooks()` —— 它只覆盖
**资产表导入**，不触达语句解析/渲染。

### 1.2 新增一种语句要在 6 个以上地方同时登记

从"解析 → IR → 拍 → 表格 → 渲染 → 校验"，一条语句类型的登记点：

| 层 | 文件 | 登记点 |
|---|---|---|
| 解析 | `parsing/renpy_parser.py` | 正则常量、AST 数据类、`_stmt_*` 方法、`_parse_statement` 分派序、`_walk` 的 isinstance 分支 |
| IR | `core/statement.py` | `StatementKind` 常量 + `ALL`、`make_xxx` 工厂、`_HASH_FIELDS`、`_FACTORY_FIELDS`、`validate_statement.required` |
| 拍 | `story/beat_build.py` | handler 字典 `:341-356`（**缺项静默丢弃**，见 `:357-360`）+ 实现 `_emit_xxx` |
| 表格 | `story/beat_model.py` | `BEAT_FIELDS`、`BEAT_HEADERS`、`SINGLE_LINE_BEAT_FIELDS`、kind 白名单、`to_row`/`from_row` |
| 渲染 | `story/beat_render.py` | `render_beat_to_rpy` 分支 `:903-958`、透传白名单 `_RENPY_STATEMENT_HEADS:200` |
| 校验/适应 | `pipeline/validate.py`、`story/project_conventions.py` | 规则 + 两张手维护的词表 |

**这不是"支持得少"，而是"每加一种就要改六个地方且漏一处就是静默丢内容"。**
对通用工具而言，这条路走不到"适应任意项目"。

### 1.3 三层适应机制已实现，但**零生产调用**（悬空能力）

`story/project_conventions.py` 实现了完整的三层机制 —— 认形状 / 清单声明 /
不认识就明说（`unknown_statements`）。设计是对的，但：

> 全仓搜索 `detect_conventions` / `conventions_for` / `unknown_statements`：
> **只有 `tests/test_project_conventions.py` 调用，生产代码零调用。**

即：**能力做出来了，但没有一个人能看到它。** 编剧不会去跑单测，所以他感知不到
"工具其实愿意被教"。这一条本身就是"工具没用"的一半成因。

### 1.4 最痛的一点：Ren'Py 自带注册表，而工具把说明书扔了

Ren'Py 官方有 **Creator-Defined Statements (CDS)**：

```python
python early:
    def parse_mycue(lexer): ...
    renpy.register_statement(name="mycue", parse=..., block=True, lint=...)
```

规则：必须写在 `python early` 块里，且该文件必须**先于使用它的文件**加载。
换句话说 —— **项目把自定义语句的语法形状，明明白白写在自己仓库里。**

而我们的工具：

- `parsing/renpy_parser.py:1124` 认识 `python early:` 这个块头；
- `story/project_conventions.py:148` 的 `_CONTAINER_HEADS` **把 `early` 整块跳过**。

**结论：宿主语言已经公布了答案，工具选择了不看。** 这是"通用化"投入产出比最高的
一个缺口 —— 不需要猜、不需要用户配置，解析一个注册调用即可。

### 1.5 ✅ 已实测确认（比预想更糟）：label 内的未知块被**改成假台词** + 块体消失

`parsing/renpy_parser.py:1810-1831`（M1 前的样子）：

```python
def _stmt_unmodeled(self, line, text):
    if not line.subblock:
        return RawNode(..., raw_kind='unmodeled')   # 叶语句：原样保真 ✅
    self.warnings.append(f"...未建模的块语句已跳过（不在演出流内）...")
    return None                                     # 带子块：整块丢弃 ❌
```

而顶层兜底 `_top_level_region()`（`:246`）**只覆盖 label 之外**的内容 ——
它遇到 `label …:` 会跳过该 label **及其块体**（`:252-253`）。

**实测结论**（夹具 `tests/test_unknown_block_preserved.py`，先红后绿）：
真实形态不是"整块消失"，而是**更坏的一种** —— `_stmt_say` 抢在
`_stmt_unmodeled` 之前把块头匹配成了一句台词：

```
原文                                  M1 之前的产物
    mycue "闪电" intensity=3:            mycue "闪电"     ← 变成台词！冒号与参数都没了
        target = ling                    （块体两行**整段消失**）
        hold 0.5
```

也就是说：**工具不但吃掉内容，还凭空造出一句由 `mycue` 说的台词。**
（`mycue "闪电"` 与 `lyj "台词"` 的长相一模一样，只有"带子块"能区分。）

**真机命中**（`D:\千连万理\RenPyTest\sr_general`）：`game/minigame/mini_game1.rpy:50`
是**游戏主循环**，以前连头带块体被整块丢掉：

```renpy
while current_round < game_rounds:
    call mini_game_round from _call_mini_game_round
    $ current_round += 1
```

全量重生成之后循环消失 → 小游戏一轮都不跑。**这不是假想，是线上。**

- 为什么门禁拦不住：丢的内容**没有进任何通道**（`RawNode` 没收、`FileBlocks` 没收、
  也没进 `OPAQUE_LOST` 的判据），门禁无从得知它存在过。

对比 1.1~1.4，前三条是"不好用"，**这一条是"会吃内容"**，性质不同。

### 1.6 M1 交付记录（已完成并验证）

| 项 | 内容 |
|---|---|
| 保真 | 新增 `UnknownBlockNode(RawNode)`：整块原文（头 + 块体，含**空行**与括号续行）。取源走**原文物理行**（`RenPyParser._raw_block_lines`）—— lexer 不产生空行的 `LogicalLine`，且括号续行的缩进是绝对的 |
| 新列 | `Beat.opaque` + 隐藏列 `Opaque`（照抄 `CodeBlocks` 的形态）。渲染走 `emit_opaque()`：**逐字写回，不补 `$`、不包 `python:`、不改缩进** |
| 消歧 | `_stmt_say` 增加守卫：**台词不许带块**（子块里有非注释内容就不是台词）→ 交给未建模兜底 |
| 门禁 | 两条新判据（都 warn、不拦导出）：`UNMANAGED_BLOCK`（自定义块，工具真不懂）、`KNOWN_UNMODELED_BLOCK`（`while`/`for` 这类标准流程块，工具认识形状但没建模）。判据 `core.vocabulary.is_known_flow_block` 是纯函数、解析层与门禁层共用 |
| 判据 | `tests/test_unknown_block_preserved.py` 15 条（全量 + 增量两条路、脏夹具、空行、续行缩进、门禁两条码）；**变异验证 3 次**（关 say 守卫 → 7 红；去 opaque 通道 → 5 红；去门禁判据 → 2 红） |
| 真机 | 只读探针 `tools/probe_unknown_blocks.py`：98 个 .rpy → 命中 1 处（上面那个 `while` 主循环） |

⚠ **过程中被变异验证纠正过一次判据**：第一版只断言"这些行在产物里"，
去掉保真通道后**仍然全绿** —— 因为整块侥幸落进「代码」列，形状
（首行不缩进 + 其余行都缩进）被 `_python_block_indent` 认成 python 块、包了
`python:`：文本还在、**语义全错**。判据已改成**整段相等** + 显式禁止
`$ `/`python:` 被引入。

## 2. 工业化工具怎么做（四个可借鉴的范式）

| 范式 | 代表 | 核心机制 | 对本项目的启示 |
|---|---|---|---|
| **无损语法树（CST）** | Roslyn / Clang / libcst / scala.meta | 语法树**全保真**：空白、注释、预处理指令都作为 **trivia** 挂在 token 上；**完全可逆回原文**；错误用 `SkippedTokens` / `MissingToken` 节点**在树里表达**，不是丢弃；树不可变 + red/green 复用 | "保真"应该是**主数据结构的属性**，不是一条后门通道。未知语句是**树里的一等节点** |
| **投影式编辑（Projectional）** | JetBrains MPS / mbeddr / Gentleman | 不靠 parser：**AST 是唯一真源**，一个 projection engine 把它渲染成文本/表格/图形/数学多种记法；**"可以持久化不完整或矛盾的信息"**（Fowler 的 language workbench 五特征之一）；组合语言**永不含歧义** | 表格和图都是**投影**；投影本身可定义 → 这就是"自定义结构在 Excel 里长什么样"的答案 |
| **容错解析 + 语言注入** | tree-sitter（GitHub/Atom/Neovim） | ①**错误恢复**：局部隔离错误、启发式修复、**仍给可用的部分语法树** —— "代码写一半也不失效"；②**external scanner** 可覆盖词法；③**injection** 把另一种语言嵌进宿主 | 降级必须是**分级且非阻断**的：一行不认识，不该让整张表不能用 |
| **宿主注册表 + 数据化语法** | Ren'Py CDS / Unity `[MenuItem]` / UE 插件元数据 / Yarn 的 `#tag` / Xtext·Langium（语法即声明→生成 parser+IDE） | 扩展点由**宿主/声明**给出：注册 API、特性标注、tag 元数据。**不改语法也能扩** | 三条来源：**宿主注册表 > 项目声明 > 形状识别**。别自己猜，先去读说明书 |

**一句话总结四者**：工具的价值不在于"认识所有语法"，而在于
**不丢、不炸、能告状、能被教会**（lossless / non-blocking / self-reporting / teachable）。

## 3. 提议架构

### 3.1 四层保真等级（Tiered Fidelity）

给每条语句一个"工具能力等级"，**每一级都有确定的、不破坏的处理器**：

| Tier | 名字 | 判定 | 表格里的形态 | 导出行为 |
|---|---|---|---|---|
| **T0** | 已建模 | 命中内置 IR | 结构化列，全功能编辑 | 由渲染器生成 |
| **T1** | 已声明 | 有 `StatementSpec`（来自宿主注册表/项目清单） | **通用行**：按 spec 拆出 `头 / 参数键值 / 块体` 三列，可编辑 | 按 spec 模板渲染 |
| **T2** | 已识别形状 | 只认出"这是块 / 这是调用 / 这是台词" | 只读展示 + 原文 | **逐字节透传** |
| **T3** | 未识别 | 什么都不知道 | 一行 `原样保留（工具不改）` | **逐字节透传** + 计入报告 |

**铁律（这是"编剧不会立即退出"的保证）：**

1. **T2 / T3 绝不阻断其他行的编辑** —— 不许出现"因为有一行不认识，所以整份导出失败"。
2. **等级只降不升地影响"可编辑性"，不影响"可保存性"** —— 任何级别都能原样落盘。
3. **等级必须可见**：表格里能一眼看出哪几行是"工具管的"、哪几行是"工具保真的"。

> M1 落地现状：T2/T3 走**同一条保真通道**（`Beat.opaque`），只在**报告措辞**上分开
> （`KNOWN_UNMODELED_BLOCK` vs `UNMANAGED_BLOCK`）。

### 3.2 一个注册表取代 15 个登记点

```python
@dataclass
class StatementSpec:
    name: str                  # 'mycue'，或别名列表 ['cue', 'mcue']
    kind: str = 'raw'          # 映射到的 IR kind（默认 raw，可扩展）
    block: bool = False        # 是否带子块
    args: list = ...           # 参数形状（位置参数 / 具名参数 / 可选）
    head_style: str = ...      # 'keyword' | 'call' | 'block' | 'mixed'
    render: str = 'verbatim'   # 渲染模板，'verbatim' = 逐字透传
    columns: list = ...        # 投影到 Excel 的列（M4）
    validate: list = ...       # 可选校验规则
    source: str = ...          # 'registry' | 'declared' | 'shape'  ← 可追溯
    docs: str = ...            # 人话说明，进体检报告
```

一个注册表 + 一个 `register(spec)` + **三个加载器**：

```
宿主注册表（renpy.register_statement 扫描）  ─┐
项目清单（storygraph.rules.json）            ─┼→  StatementRegistry  →  解析 / 渲染 / 表格 / 校验
形状识别（detect_conventions）               ─┘        （唯一真源）
```

**优先级：声明 > 宿主注册表 > 形状。** 每条 spec 带 `source`，报告里能区分
"这是你告诉我的" vs "我猜的"（`Conventions.source` 已有此设计，沿用）。

**收益**：`_parse_statement` 的 if 链变成"内置 spec 表 + 项目 spec 表"的查表；
`beat_build` 的 handler 字典变成通用 handler；`beat_render` 分支变成通用渲染器；
`beat_model` 只增加三个通用列。**新增一种自定义语句 = 写一条 spec，不改工具代码。**

> ⚠ 内置部分必须保持现有顺序优先级不变（契约 A2 / B2 依赖它），注册表只在
> **内置全部未命中之后**参与判定 —— 这样"加扩展"不会动到已验证的解析路径。

### 3.3 一处收敛：三张手维护清单改为从注册表导出

现在 `KNOWN_STATEMENT_HEADS`（project_conventions）、`_CONTAINER_HEADS`、
`_RENPY_STATEMENT_HEADS`（beat_render）三张表各自手写、口径不同。它们应当
**全部从注册表派生** —— 否则"加了一种语句"要在四处补，迟早在某处漏掉。

> M1 已先落一小步：`core.vocabulary.RENPY_FLOW_BLOCK_HEADS` +
> `is_known_flow_block()` 成为"标准流程块"的唯一真源（解析层与门禁层共用）。

### 3.4 投影可扩展（M4，呼应"对着表格编排演出"）

MPS 的关键洞察：**同一个模型可以有多种记法**。所以 `StatementSpec` 还应当能声明
"它在表格里长什么样"：

- 不声明 → 通用行（T1 默认投影，能改参数但朴素）
- 声明了 → 专用卡片/列（比如把 `mycue` 的 `intensity` 变成下拉）

**通用行是兜底，专用投影是升级。** 这样"先能编，再好编"，不必一次做完美。

## 4. 工具能力元模型（Capability Meta-Model）

> 这一节是 2026-10-07 补的（评审意见）：前面三节把**保真性 / 可编辑性 /
> 可教性**当三件事描述，但它们其实是**同一个东西的三个投影** ——
> "工具对这句话的能力等级"。不把它显式化，能力边界就只存在于代码分支和
> 未调用的 `project_conventions` 函数里；显式化之后，它才有**生命周期**
> （语句能在等级之间移动，路径与条件可定义、可测试、可报告）。

实现：`storygraph/core/capability.py`（模型与规则）+ `story/statement_registry.py`
（装配与度量）+ `tests/test_capability_model.py`（20 条判据）。

### 4.1 Capability State —— 当前能力等级

| 等级 | 名字 | 判定 | 表格里长什么样 | 产物字节由谁决定 |
|---|---|---|---|---|
| **T0** | 已建模 | 命中内置解析分支，且**完全**结构化 | 结构化列，全功能编辑 | 渲染器 |
| **T0b** | 已建模·块体逐字 | 有内置 IR，但块体只存原文（`while` / `for`，D2） | 头行一格可改 + 块体原文 | 头行由 `LoopHeader`，块体**原文** |
| **T1a** | 已声明·参数可编辑 | 项目声明过 **且** 给了 `columns` / `label` | 参数成为可编辑的格子（通用行的"精装版"） | spec 模板 |
| **T1b** | 已声明·逐字透传 | 项目声明过，但没给参数形状 | 整块原文可编辑 | **原文** |
| **T2** | 已识别形状 | 工具认识"这是什么"（但还没接住头行） | 只读展示 | **原文** |
| **T3** | 未识别 | 什么都不知道 | 只读展示 | **原文** |

> ⚠ **`T0b` 为什么必须与 `T0` 分开**（D2，2026-10-07）：`T0` 的定义是
> "结构化列**全功能**编辑"。循环体做不到 —— `Beat` 是扁平的一维语句流，
> 表达不了"这一段会重复执行"。把 `while` 记成 `T0` 就是**拿"接住了"
> 冒充"完全理解了"**，而覆盖率会因此好看 —— 那正是这一层要防的事
> （`KNOWN_STATEMENT_HEADS` 的注释写着"多写 → 假装懂（危险）"）。

⚠ **这三份集合不是划分关系**（判据第一版在这里写错过）：

- `EDITABLE = {T0, T1a, T1b}`（工具能替你改）；
- `VERBATIM = {T1b, T2, T3}`（产物字节由原文决定）；
- **`T1b` 同时在两边** —— 那不是重复计数，正是它的定义：
  项目声明过（所以工具知道它的身份、能定位、能替你保存），但没给参数形状
  （所以只能整块原文改、逐字写回）。
- 真正该划的界是 **`READONLY = VERBATIM − EDITABLE = {T2, T3}`**："工具既不编辑、
  也不重排，只展示 + 逐字写回"。

### 4.2 Capability Provenance —— 这个等级凭什么成立

| 来源 | 含义 | 强度 |
|---|---|---|
| `declared` | 项目**清单**（`storygraph.rules.json` 的 `statements` 段） | **最强，可覆盖下一行** |
| `host-registry` | 宿主**注册表**（`renpy.register_statement`，即 CDS） | 强 |
| `shape` | **形状识别**（工具从结构上认出"这是个循环块"） | 弱（工具自己的判断） |
| `builtin` | 工具**内置语法**（有专门的解析分支） | —— 不是"被告知"，是"本来就会" |
| `unknown` | 不知道 | —— |

报告里必须能区分 **"这是你告诉我的"** 与 **"我猜的"** —— 同一套口径
（`Conventions.source` 从 10-05 就在用）。

### 4.3 Capability Transition —— 精化 / 退化规则

| 从 → 到 | 什么时候 | 会发生什么 |
|---|---|---|
| T3 → T1b | 在 `rules.json` 写个名字 / `register_statement` 声明它 | **立即不再报警**；内容照旧逐字透传 |
| T3 → T1a | 声明它 **并** 给出 `columns` / `label` | 参数成为可编辑的格子 |
| T1b → T1a | 给声明补 `columns` / `label` | 从"整块原文可编辑"升级为"每参数一格" |
| T2 → T0b | 工具为这种块**接住头行**（**改工具代码**）—— 例：`while` / `for`（D2） | 头行可编辑可校验，块体逐字；不再报"待办" |
| T2 → T0 | 工具新增**完全**结构化的解析分支（**改工具代码**） | 成为结构化拍 |
| T0b → T0 | 给拍模型加上**作用域**（循环体也能被结构化编辑） | 从"头行结构化 + 块体逐字"升到完全建模 |
| T1b / T1a → T3 | 声明被删 / 清单写坏 / 宿主不再注册 | 退回未识别，**并重新开始报警** |

**没写在这张表里的移动就是不支持的** —— 与其让它在分支里悄悄发生，
不如让它无处可去（渐进类型的视角：等级是**显式标注**，不是运行时猜测）。

三条**硬不变量**（元模型存在的全部意义，逐条有测试）：

1. **降级不改字节** —— T1↔T2↔T3 之间任意移动，产物里的**原文逐字不变**。
   等级只决定"工具能不能替你编辑"，不决定"内容长什么样"。
2. **精化不改字节** —— 从 T3 教到 T1a，**第一次导出的产物应当与教之前逐字相同**
   （唯一的差别是少一条告警）。若变了，说明"升级"顺手改了别人的脚本。
3. **T0 不降级** —— 内置判定优先：声明只在**内置全部未命中之后**参与。
   项目不能通过声明把一条 `show` 变成自己的语句。

> ⚠ 判据必须**同时断言"等级真的动了"**（`cov.count_of(T3)` 确实减少、
   `count_of(T1b)` 确实增加），否则等式两边走的是同一条路，测试是**空转**的。
> 这正是本仓库被"判据太松"坑过的地方（见 §5.1 的 M1 记录）。

### 4.4 Capability Coverage —— 项目级的可编辑覆盖率（CAP 视角）

一个数：**"这份脚本里有多少条是工具替得了的？"**

真机实测（`sr_general`）：

```
工具可编辑覆盖率 99.9%（1759/1760 条；其余 1 条逐字保真、内容不会丢）
  · T0 已建模：1759 条
  · T2 已识别形状：1 条
  T2 里的代表：while
    → 这是**标准流程块**（`while` / `for` 等）：…这一条是**给工具作者**的待办
```

覆盖率**下降不是坏事，是信号** —— 它意味着项目里出现了工具跟不上的新结构。
把这个数印在构建报告里，等于给"工具跟不跟得上项目"装了一个仪表盘。

⚠ 没有语句时覆盖率是 **1.0**（不是 0）—— 别把"没事"报成"全废"。

### 4.5 Capability Escape —— 每个等级的"教工具升级"入口

| 等级 | 升级入口（报告里逐字印出来） |
|---|---|
| T3 | 写 `storygraph.rules.json` 的 `statements`，或让程序 `renpy.register_statement` 声明它 |
| T2 | 这是**给工具作者**的待办（内容已安全）；写 issue 即可，**不需要你改脚本** |
| T1b | 给声明补 `columns`（每参数一列）或 `label`（人话说明） |
| T1a | 已经是可编辑的通用行；想更好用就给 `columns` 里的字段加 `choices`（M4） |
| T0 | 原生语句，不需要升级 |

每条等级**都必须有答案**（有测试钉着）—— 没有答案的等级等于死路，
而"死路"正是用户说的"他会立即退出，因为工具没有用"。

### 4.6 与四层分级的关系

**不改变** §3.1 的四层分级，只是给它加上生命周期：

- §3.1 说"每一级长什么样"（**静态投影**）；
- 本节说"它从哪来、能到哪去、怎么度量、怎么升级"（**动态模型**）。

于是架构从"四个范式的集合"变成一个**可演化系统**：能力边界成为一等公民，
新加一种语句的改动落在**一张表**（`TRANSITIONS` / `ESCAPES`）上，而不是
散在解析分支、门禁桶和没人调用的函数里。

### 5.1 M2 交付记录（`cds_registry.py`）

- 读 `renpy.register_statement(...)`：**括号配平**（多行调用几乎总是这么写）、
  顶层逗号切分（`parse=lambda lex: f(a, b)` 不该被切坏）、字符串里的括号/逗号
  不算结构、`#` 注释跳过。
- 名字的两个官方来源（`name=` 关键字 / 第一个位置参数）**都只认字面量**；
  两处都认不出就**跳过** —— 猜一个名字会让 M3 把不是自定义语句的行当成自定义
  语句（静默改语义）。⚠ 这条判据第一版**写反了**（期望"把 `MY_NAME` 当名字
  记下来"），实现比判据先对。
- 接进体检报告第 ⑧ 段（`【⑧ 项目自定义语句（清单声明 + Ren'Py CDS）】`），
  并明确写"这是**能力状态**、不算 problems"。
- 真机 `sr_general`：**没有 CDS**。所以这一层的价值在通用性，不在这一个项目
  —— 报告如实说"没有声明，想被管理就从这两处任选一处写下来"。

### 5.2 M3 交付记录（`statement_registry.py`）

- **三来源优先级**：`storygraph.rules.json` 的 `statements` 段（declared，
  **覆盖**）> `renpy.register_statement`（host-registry）。冲突时听用户的。
- 新增隐藏列 `SpecName`（`Beat.spec_name`）：`''` = 真·未声明（T3，报告要催）；
  有值 = 已声明（T1）。
- **后置标注**而不是改解析器：契约 H1 不许 `parsing` import `story`，而"声明过
  没有"只有 story 层知道 → `annotate_spec_statements()` 在出拍前给
  `payload['spec_name']` 打标。
- **项目根反推 + 缓存**：`beats_from_parse_result` 有 8 个调用点，一处漏传就是
  "那条路上的自定义语句又变成不认识"（本项目已有"三处调用方漏交 `beats`"的
  前科）→ 从 `ParseResult.statements[].source`（文件路径）反推项目根，
  装配结果按根缓存（否则逐章调用 = O(章数 × 文件数)）。
- **顺手修掉一个同类坑**：**叶形态**的自定义语句（`mycue "x" intensity=3`，
  不带块）以前留在 `raw` 通道，会被 `render_code_block` 补上 `$` →
  `$ mycue "x" intensity=3` = 语法错误。与 M1 修的是同一个坑，只是形状不同；
  现在"声明过"就统一走 `emit_opaque()` 逐字写回。
- 门禁分三桶（`block_buckets`）：declared（**不报警**，已管理）/ custom（催用户）/
  standard（`while`/`for`，催我们）。
- build 报告新增一行「项目声明了 N 个自定义语句」；真机输出
  「项目**没有声明**任何自定义语句：…… 从这两处任选一处写下来即可」。

### 5.3 M5 交付记录（词表收敛）

三张手维护清单 → `core.vocabulary` 的**唯一真源**，三处变成**别名**：

| 旧位置 | 新身份 |
|---|---|
| `beat_render._RENPY_STATEMENT_HEADS` | `RENPY_STATEMENT_VERBS` 的别名 |
| `project_conventions.KNOWN_STATEMENT_HEADS` | `RENPY_KNOWN_HEADS` 的别名 |
| `project_conventions._CONTAINER_HEADS` | `RENPY_CONTAINER_HEADS` 的别名 |

⚠ **三份不能简单并成一个集合** —— 差异是**刻意的**：动词表必须排除
`if/elif/else/while/for`（它们在 `raw` 里是**代码块的条件行**，当语句透传会把
`python:` 块弄坏）。所以收敛的做法是"公共内核一份 + 各处显式增减 + 差异写进注释"。

判据（`tests/test_project_conventions.py::TestHeadWordlistsAreConverged`）：
三处**是同一个对象**；流程头**不在**动词表里；**只许加不许减**（历史 58 个词
一个都不许丢 —— 少了会让覆盖度报告凭空多出噪声，用户以为退化了）。

> 实测：收敛后 `RENPY_KNOWN_HEADS` 65 个 ⊃ 历史 58 个（`lost: []`），
> 新增的 7 个是 `renpy.` / `persistent.` / `config.` / `gui.` / `store.` /
> `narrator` / `voice_sustain` —— 它们只出现在 python 块里，而那些块被
> `RENPY_CONTAINER_HEADS` 整块跳过，所以**报告口径实际没变**。

### 5.4 M4 交付记录（投影：T1 的头行可编辑）

- 新隐藏列 **`SpecHead`**（`Beat.spec_head`）= 那条自定义语句的**头行原文**。
  它和 `Opaque`（整块）的分工：
  - **头行**装着"这条语句在干什么"（`mycue "闪电" intensity=3:`）→ **一格可改**；
  - **块体**逐字躺在 `Opaque` 里 → 撞不到。
- **"没改就不动一个字节"是结构上成立的**，不靠调用方自觉：
  `emit_opaque()` 比对 `spec_head` 与首行，**只有真的不同才替换**。
  ⚠ 比对必须用 `strip()`：`SpecHead` 是单行列、经过 `_one_line`，直接比全文会把
  "首行末尾多几个空格"误判成"人改过了"，于是第一次导出就悄悄改了别人的排版。
- `spec_columns()` / `spec_arg_choices()`：把声明的 `columns` / `choices`
  变成**可用的候选**（给 UI / Excel 数据验证）。**没声明就返回空**——
  猜一组候选会诱导人写出脚本里根本没有的值。
- 声明了 `columns` / `label` → 能力等级从 `T1b` 升到 **`T1a`**（见 §4.1）。
- 判据 `tests/test_spec_projection.py`（11 条）。最要紧的一条是
  `test_editing_head_changes_only_that_line`：改头行之后，**逐行比对**产物，
  要求**只有一行不同** —— 只断言"新参数在产物里"是抓不住"顺手重排了块体"的。

### 5.5 D3 交付记录（`core/cst.py`：无损语法树的支点）

- 每条语句挂上 **`Span`（文件 + 起止行）+ `raw_text`（那几行的逐字原文）
  + `Trivia`（前导空行、缩进原文）**。
- ⚠ **刻意不做成 dataclass 字段**：`Statement` 的相等与哈希是**内容指纹契约**
  （协作主键、增量对位都依赖它），把 CST 塞进字段等于把一次保真改动变成
  一次全局契约变更。沿用本仓库已有的做法（`Statement.nest_path`、
  `LogicalLine.inline_comment` 同款）——**挂成动态属性**：
  - 现有测试一条都不用改；
  - 拿不到 CST 就退回 D3 之前，**没有降级风险**。
- **归属规则**（决定 Span 边界，写在 `cst.attach_spans` 的 docstring 里）：
  "这条语句拥有从它自己那一行起，直到**下一条语句的前一行**或
  **第一个顶格行**为止的正文"。前者保证**不重叠**（语句流是扁平的，
  按子树算会父子重叠），后者保证**不吞别人的行**（label 内语句都是缩进的，
  顶格只可能是顶层定义）。
- 验收（`tests/test_cst.py`，10 条）：真机 **3187 条语句 100% 带真迹、
  0 条贴错行、0 处重叠**；并且**把源文件删掉之后** `statement_text()` 仍能
  逐字给出原文 —— 这条才是 D3 的核心判据（真迹在 IR 里，不在文件里）。
- 变异验证：关掉挂载 → **6 条红**（真机那条报"3187 条语句没有真迹"）。

### 5.6 D2 交付记录（把 `while` / `for` 建模为 T0b）

- 解析层：`_RE_LOOP_HEAD`（**要求以冒号收尾**）、`LoopNode`、
  `_stmt_loop`（插在 `_stmt_say` 之前 —— 否则台词兜底会抢）。
- IR：新增 `StatementKind.LOOP`，payload = `{text, header, body}`。
  `text` 是**整块原文**，`header` / `body` 是它的投影 —— 渲染需要一个
  "没改就吐原文"的对照。
- 拍：`Opaque`（整块逐字）+ 新隐藏列 **`LoopHeader`**（可编辑头行），
  与 `SpecHead` 完全同款（`emit_opaque` 比对后才替换）。
- 等级：新增 **`T0b`（已建模·块体逐字）**，计入可编辑（头行能改）。
  ⚠ **为什么不记成 `T0`**：T0 的定义是"结构化列**全功能**编辑"，而
  `Beat` 是扁平的一维语句流，表达不了"这一段会重复执行"。记成 T0
  就是**拿"接住了"冒充"完全理解了"** —— 正是这一层要防的事。
- **真机结果：覆盖率 99.9% → 100.0%**，报告如实拆成
  `T0 1759 条 / T0b 1 条`，并区分「只读」与「逐字」：
  `T0b`/`T1b` 逐字**但可编辑**，说成"只读"会让人以为不归自己管。
- 判据 `tests/test_loop_model.py`（12 条）。最要紧的一条是
  **不许误伤台词**：`for "台词"`（说话人恰好叫 `for`）与 `while "x"`
  都不带尾冒号，必须仍然是台词 —— 正则宽一点点，编剧的台词就没了。

### 5.7 D1 交付记录（`choices` 真正可用）

- **Excel**：导出时给「自定义语句·头行」那一格挂**候选注释**
  （`label` / 每个参数的候选 / `[必需]` 标记）。
  ⚠ **为什么是注释不是下拉**：Excel 数据验证**按列**绑定，而参数名
  每条语句各不相同（`mycue` 有 `intensity`、`battle` 有 `difficulty`），
  一列装不下两套枚举。做"每参数一列"要让 `BEAT_FIELDS` 动态化 ——
  那是一次列契约变更，不混在这一次里。
- **校验**：`W120`（缺声明的必需参数）/ `W121`（值不在候选里）。
  ⚠ `W121` 是**警告不是错误**：候选是"常见取值"、不是白名单，
  拦下来只会让人关掉校验。
- **卡片**：`app.beats.spec_arg_choices_for(beat, statements)`
  → `{参数名: [候选]}`，给 UI 的下拉的用。
- 两条"不猜"的口径：没声明 → **什么都不做**；位置参数**不当成**
  有名字的参数（`mycue 3 ling` 里那两个词与声明里的名字没有可推导的对应，
  硬对齐是猜，猜错会指着一处不存在的错误让人去改）。
- 判据 `tests/test_spec_choices.py`（10 条）。其中一条当场抓到一个真缺陷：
  头行末尾的 `:` 被吸进了参数值（`target=ling:` → `target="ling:"`），
  于是**写对了也报"值不在候选里"**。修法是**先剥尾冒号再扫描**。

### 5.8 往返幂等：真机审计 + 修掉最严重的一族（2026-10-07）

**背景**：既有两个审计都**看不见这类缺陷**——

- `tools/audit_roundtrip.py` 比的是**语句语义指纹**（kind + payload）：
  文件级的"多一行注释""缩进漂移"它一律不算；
- `tools/hell_edit_rounds.py` 的 A2 轴比的是**归一化后**的文本
  （它要过滤"我故意插卡"的噪声）—— 实测它的 verbose 里 `R1 = 5 行 →
  R2 = 7 行`，而它报 `ok`：**生成标记多了一行被归一化抹平了**。

而这类缺陷恰恰是用户最能感知的：**"我只是又点了一次导出，文件就变了。"**

于是新增 **`tools/audit_idempotence.py`**：`t0 → t1 → t2 → t3`，
要求 `t2 == t1` 且 `t3 == t2`（**逐字节**）。真机 53 个文件跑出来：

**修掉的三处**

| 症状 | 根因 | 修法 |
|---|---|---|
| 产物里**生成标记变成 2 条**（第一轮就 2 条） | 我们自己的标记被 `_top_level_region` 当成"作者的顶层内容"带回，渲染时又加一条 | 源头摘掉 + 渲染处保险（老表里可能已经带着） |
| 括号续行缩进 **12 → 20 → 28 → 36 → 44**（**无界**） | `_flatten` 把括号未闭合的多行语句并成**一条逻辑行**，而取块体用的是 `node.text.lstrip()` —— `lstrip()` 对多行字符串**只作用于第一行**，续行带着**绝对缩进**进了 payload，被当成"更深一层"，渲染再加一次基准 | 新增 `_shift_continuations()`：**首行由调用方的 `rel` 负责**（不在这里减 base，否则双重计算）、**续行减 base** |
| 被注释掉的整块（`#label x:` / `#    menu:`）**每轮被推进一层** | `_opens_a_block()` 把以 `:` 收尾的**注释**当成块头 → 后面那串顶格注释被当成它的块体，而 `render_file_block` 给块体统一加 4 | `_opens_a_block()` 排除注释（**注释永远不开块**） |

真机结果：**7 → 5 个不幂等文件**，且最严重的"无界增长"彻底消失
（`12 → 12 → 12 → 12 → 12`，同时**首轮就精确复现了原文的缩进**——
原来第一轮就已经漂到 20）。

**剩下 5 个文件**（同一族，**已量化、未修**）：

```
character_gallery.rpy / credits_screen.rpy / eyes_tracker.rpy / …
    A='# 全局人物页面 screen'   →   B='    # 全局人物页面 screen'
```

根因：`render_file_block()` 给"chunk 的剩余部分"**统一加 4 格**
（因为块体按定义比块头深一层），但那个"剩余部分"有时**不是块体**，
而是一串**顶格注释**。要修得先回答"chunk 的剩余部分到底是块体还是更多
顶格行"——而仓库历史明确记着"试过三种归一化写法都让全项目丢失数变多
（3 → 7）"。

**所以这一族按"已量化、有守卫、未修"记录**：新增
`tools/audit_idempotence.py` 作为守卫（`--excel` 走产品主路），
下次动缩进时先跑它。**宁可留着一条看得见的已知问题，也不要为了指标好看
去引入一类新的缩进语法错**（那是 `PYTHON_SYNTAX_ERROR` 门禁要拦的东西）。

### 8.1 横切维度：能力模型（§4 的来源）

前四个范式回答的是"**工具怎么理解/保存不认识的语法**"，但都没有回答
"**工具对某一句话现在能做到哪一步、怎么变强**"。补上这一层，参考的是：

- **渐进类型（gradual typing）**：`any` 不是失败，是**显式的逃逸**——
  未标注的地方按动态处理，标注的地方逐步收紧。对应本项目：`T3` 不是
  "没做完"，而是**声明的逃逸舱口**，且**逃逸永不丢内容**。
- **能力 / 权限模型（capability model）**：能力是**被授予的、可撤销的、
  可审计的**。对应本项目：`Provenance` 回答"谁授予的"，`Transition` 回答
  "怎么授予/撤销"，`Coverage` 是可审计的度量。
- **能力成熟度模型（CMM 式的分级度量）**：把"等级"当**可度量的状态**
  而不是"完成/未完成"的布尔。对应本项目：`Coverage` 是那个度量。

**这一层的价值不在于它是新理论，而在于它把"能力边界"从代码分支里搬到了
模型里**：新加一种语句时，改动落在**一张表**（`TRANSITIONS` / `ESCAPES`）
上，而不是散在解析分支、门禁桶和一个没人调用的函数里。
