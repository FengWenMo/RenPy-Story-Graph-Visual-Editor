## 一、方案内核（一句话）

> **能用引擎自己拿到的，就不让人填；引擎不提供的语义，才由人补；
> 引擎和人都不说的，靠扫描**发现并报警**——而扫描永不宣称"只有这些"。**

三条线（已确认）：

| 线 | 职责 | 何时用 |
|---|---|---|
| **引擎 oracle（优先）** | 语法合法性、**图像/属性引用**、资源存在性、属性词汇与分组、兼容候选、变换/界面/define 清单 | 每次采集 + 每次 CI |
| **定义表（覆盖层）** | 只放引擎**不提供**的语义：中文名、分组**归并/改名**、候选**过滤**、例子、说明 | 人想改"说法"时 |
| **扫描（发现与校验）** | `discover_undeclared` 找未声明的语句头；喂给探针"该测什么" | 每次打开项目 |

**它们的时序**（来自四缺口与地狱测试）：

```
  ① parse 干净吗？  ── 否 ──▶ 报「采集失败」（不是"无漂移"）   ← 洞4
        │ 是
  ② 采集：lint + json-dump + 注入探针  →  engine_facts.json（每条带来源）
        │
  ③ 对账：定义表 ↔ 引擎事实 ↔ 真实用法   →  冲突一律报出，不静默选一个
        │
  ④ 供给：卡片/表格的候选直接读 ②；定义表只做"翻译"
```

## 二、四个坑（前三个是你点出的，第四个是这轮实测新发现的）

| # | 坑 | 规则 |
|---|---|---|
| **坑 1** | `lint` 默认退出码 **0** | **必须带 `--error-code`**，否则 CI 永远绿 |
| **坑 2** | `lint` 没报 ≠ 没问题 | **先确认无 parse error**；一个语法错会吞掉后面**全部**语义检查（C13 实测） |
| **坑 3** | `has_image()` 不是判据 | 对**不存在**的属性组合也返回 `True` → 任何来自它的候选标「未验证」，不当真值 |
| **坑 4** ⭐新 | **parse error 会连探针一起杀死** | C13/C16/C17 三个用例里 `facts.json` **全部不产出**。→ **"没采到"必须报错，绝不允许当成"没有漂移"**；`probe_complete=false` 是**硬失败** |

## 三、八条新规则（地狱测试两轮逼出来的）

| # | 新规则 | 为什么（实测） |
|---|---|---|
| **N1** | 扫描器**只许说"我认出了 N 个"，不许说"项目里只有 N 个"** | **C4**：CDS 名是拼出来的 → 引擎接受、扫描器看不见 → 我们会静默地报出错误知识 |
| **N2** | 扫到 `register_statement(<内置名>)` → **报警"本项目覆盖了内置语句 X"** | **C7 + C16 + D1**：覆盖**真的生效**（D1a/D1b 证明是**完全替换**），且**默认毫无信号**（C7 exit 0） |
| **N3** | **同组属性多选**由**工具自己查**（用枚举出的 group） | **C10**：`show lan happy sad` → lint exit 0，**引擎静默**。lint 有边界，不能全推给它 |
| **N4** | ⭐ **把程序自己的 `lint=` 回调输出收进构建报告** | **C6**：程序的 `renpy.error("…")` 会出现在 lint 报告里（`SG-LINT: …`）—— **白送的一层校验** |
| **N5** | 内置语句被替换（`register_statement(<内置名>)` 或解析器分派被改）→ **报警"形状/语义不保证"**；`show` / say（`name=""`）**升级为最高级警告** | **D2 / D3**：项目**能覆盖 `show`**、**能整体替换 say**；一旦发生，**本工具最核心的语句模型全部失效** |
| **N6** | **同 tag 重复定义由工具自查并报出** | **D5 / D5b**：`layeredimage` 重复 → **后者整体覆盖前者**（lint 报 `'lan x' is not an image`）；普通 `image` 重复 → **完全静默**。不查就会在界面上下拉出**已不存在的属性** |
| **N7** | 探针清理**必须包含 `.rpyc`** | **D6**：只删 `.rpy` 留下的**孤儿 `.rpyc` 不会被引擎自动清理**，第二次运行后仍在 |
| **N8** | ⚠ **行为级验证（`test`）不进 CI 默认路径** | **D7**：`test` 在 headless(`dummy`) 下被 **SIGTERM 终止（exit 143）**。CI 只能依赖 **lint + 探针**；行为级要真实显示后端（Linux 常用 `xvfb-run`） |

## 四、`engine_facts.json` 结构（合并 `--json-dump` + 探针，**每条带来源**）

> 采纳你的建议：两份数据合并成一份**引擎能力快照**，且**每条事实记来源**；
> 两源冲突 → 进 `conflicts`，**报"来源不一致"，不静默选一个**。

```jsonc
{
  "schema": 1,
  "engine": { "version": "8.5.3", "basedir": "...", "sdk": "..." },
  "fingerprint": {                       // 新鲜度：先比这个，毫秒级
    "engine_version": "8.5.3",
    "inputs": { "game/**.rpy": "<sha1>", "images_tree": "<sha1>" }
  },
  "collection": {
    "parse_clean": true,                 //  ← 坑2/坑4 的闸门
    "probe_complete": true,              //  ← 采不到就是硬失败
    "lint_exit": 0
  },

  "lint": {
    "parse_errors":    [ { "file": "...", "line": 14, "msg": "expected statement." } ],
    "semantic_errors": [ { "file": "...", "line": 282, "kind": "not_an_image",
                           "msg": "'lan sideeye' is not an image." } ],
    "program_errors":  [ { "file": "...", "msg": "SG-LINT: …" } ]     // ← N4
  },

  "facts": {                             // 每条 { value, source }
    "images":     { "value": ["lan", "..."], "source": "probe:list_images" },
    "tags":       { "value": ["..."],        "source": "probe:get_available_image_tags" },
    "attributes": { "value": { "lan": [ {"group":"outfit","attribute":"clothes2"} ] },
                    "source": "probe:get_registered_image().attributes" },
    "candidates": { "value": { "lan": ["clothes2","base_swimsuit","happy","sad"] },
                    "source": "probe:get_ordered_image_attributes" },
    "transforms": { "value": ["bgfit","hover_move_right","..."],
                    "source": "json-dump:location.transform" },
    "screens":    { "value": ["say","choice","..."], "source": "json-dump:location.screen" },
    "defines":    { "value": ["gui.accent_color","..."], "source": "json-dump:location.define" },
    "labels":     { "value": ["start","..."], "source": "probe:get_all_labels" },
    "builtins":   { "value": ["show","hide","with","pause","window","..."],
                    "source": "scanner:RENPY_KNOWN_HEADS" }
  },

  "derived": {                           // 工具自己算的（带判据）
    "overridden_builtins": [ { "name": "pause", "file": "...", "line": 3 } ],   // ← N2
    "group_conflicts":     [ { "tag": "lan", "group": "g", "attrs": ["happy","sad"] } ], // ← N3
    "undeclared_heads":    [ { "head": "weather", "count": 12, "files": ["..."] } ],     // 扫描
    "scan_disclaimer": "以上是「我认出的」，不代表项目里只有这些"                 // ← N1
  },

  "conflicts": [ { "field": "transforms", "sources": ["json-dump"], "note": "探针里没有此项" } ]
}
```

**几个刻意的设计**：
- `facts.*.source` 是**一等字段** → 冲突可报、可追溯（你的建议）。
- `collection.probe_complete` 单独拿出来 → **"没采到"和"没变化"在结构上就是两件事**（坑 4）。
- `derived` 段放**工具自己算的**检查（覆盖内置 / 同组冲突）→ 与"引擎给的"分开，避免混为一谈。

## 五、收窄断言：写**性质**，不写**期望值**（采纳你的建议）

```
对每个 tag：  A = get_ordered_image_attributes(tag)
              B = get_ordered_image_attributes(tag, (a,))   # a ∈ A

断言（性质，不写字面量）：
  1. B ⊆ A                       ← 收窄必须是子集
  2. |B| ≤ |A|                   ← 不许变大
  3. 只有 |B| == 0 或 |B| == |A| 时才报警
     （前者=引擎认为互斥到底；后者=收窄逻辑失效）
```
> **为什么之前"写死期望值"是错的**：引擎升级或项目新增属性后，**期望值要人工更新**，
> 否则 CI 天天误报 → 人就把这条门禁关了。**性质断言不会过期。**

## 六、CI 分类（采纳你的建议：parse error 与语义错误分开）

| 分类 | 判据 | CI 行为 |
|---|---|---|
| **阻塞**（blocking） | 报告里有 `expected statement.` 等 **parse error**，或 `collection.probe_complete=false` | **红，且必须最优先修**；此时**禁止采集事实**（坑 2/坑 4） |
| **需修但不阻塞** | 无 parse error，但有 `is not an image` / `is not loadable` | 红（或按策略 warn），**允许继续采集事实** |
| **程序自定义** | `program_errors`（`lint=` 回调报的） | 按其严重度；**但必须呈现**（N4） |
| **漂移** | `engine_facts.json` 与本仓基线 diff 非空 | 报"引擎行为变了"，附**变更前/后** |

> ⚠ **顺序硬约束**：先 parse → 再事实 → 再对账。**反过来就是错的**（C13/C16/C17 的证据）。

## 七、注入探针的副作用与清理（采纳你的提醒）

| 风险 | 处置 |
|---|---|
| 探针 `.rpy` 会被编译成 **`.rpyc`**，删源后残留 | 删探针时**同时删 `game/zz_*.rpyc`**；并在 `cache/` 里查同名残留 |
| 反复注入/删除污染后续 lint | 采集流程**先在项目副本上做**（本项目既有做法：`tools/probe_*` 一律跑副本）；**真机只读** |
| 探针本身被工程师误提交 | 探针文件名固定前缀（`zz_storygraph_probe.rpy`）+ 写进 `.gitignore` 的脚步；采集完**校验目录已还原** |
| 探针 `init` 与项目 `init` 抢优先级 | 用 `init 999 python:`（实测可用）；若项目已占用 999 → 报错并退让，**不猜** |

**还原校验**（写进验收）：采集前后对 `game/**` 做一次 sha1 清单比对，
**除 `*.rpyc`/`cache/` 外必须逐字节一致**。

## 八、分三步落地（每步独立验收）

### 第一步 · 引擎事实采集
把 `lint --error-code` + `--json-dump` + 注入探针**包成一次运行**，产出 `engine_facts.json`。

**验收（可直接跑）**：
- [ ] `collection.parse_clean == true` 且 `probe_complete == true`
- [ ] `facts.attributes[<角色>]` 里能看到 **`outfit` / `clothes2`**、**`expressions` / `happy`**（真机口径）
- [ ] `facts.transforms` **非空**（真机 155 条量级）
- [ ] `facts.labels` **非空**（真机 106 条量级；`--json-dump` 的 label 恒为 0，**必须从探针补**）
- [ ] 造一个 parse error → **`probe_complete=false` 且被报为失败**（坑 4 的判据）
- [ ] 采集前后 `game/**` sha1 清单一致（除 `*.rpyc`/`cache/`）

### 第二步 · 候选值接入编辑器
卡片与表格的立绘属性下拉**直接读 `engine_facts.json`**。

**验收**：
- [ ] 选角色后，下拉里是**引擎枚举出来的属性**，人**一个都不用填**
- [ ] 下拉按 `attributes.*.group` **分组显示**（`outfit` → 显示为「服装」由**定义表**翻译）
- [ ] 定义表里**没有形状字段**可编辑（形状是派生的、只读）
- [ ] `derived.group_conflicts` 在卡片上给**即时提示**（N3）
- [ ] `derived.overridden_builtins` 非空时，界面**明确警告**"该语句被项目改写过，形状不保证"（N2）

### 第三步 · CI 门禁 + 漂移检测
**验收**：
- [ ] `lint --error-code` 与事实采集进 CI
- [ ] `engine_facts.json` 进版本库；改引擎/加属性 → **diff 出漂移报告**
- [ ] 故意把 `pause` 覆盖一下（C16 那招）→ CI **红**（N2 生效）
- [ ] 故意造同组冲突（C10 那招）→ CI **红**（N3 生效）
- [ ] 故意造 parse error → CI **红且标为阻塞**，且**报告说明"事实未采集"**（坑 2/4）

## 九、什么时候回头找程序（**三种**）

| # | 情况 | 为什么要找 | 证据 |
|---|---|---|---|
| 1 | **引擎被 fork，源码不在项目里** | **fork 新增的语句对工具完全隐形**（扫描器/lint/探针/json-dump 四路全无信号）。`engine_facts.json` **仍然可用**（lint 跑在魔改引擎上），但"引擎补丁即契约"走不通 | **D4a/D4b** |
| 2 | **项目用 CDS 覆盖了内置语句**（尤其 `show`、或 `name=""` 替换 say） | 覆盖 = **完全替换**，不是叠加 → 内置形状**立刻失效**；而默认**毫无信号** | **D1a/D1b（替换）、D2（show）、D3（say）** |
| 3 | **项目注册了"计算出来的名字"** | 引擎接受，扫描器看不见（只认字面量） | **C4** |

> 除这三条外，**不需要程序配合任何事**。

## 九b、行为级验证的现实（N8 展开）

> **2026-10-11 真机重测：本节原来两条结论被推翻了，已改写。**
> 原来是"D7：headless 跑不起来（exit 143）"+"所以不承诺能验证执行语义"。
> 真机实测下来，**能跑，但不容易，而且它的官方判据是假绿的** —— 详见 §十二。

- `testcase` + `assert` 是**官方**的行为测试手段。真机（Windows + 有桌面）实测：
  **`test` 跑得起来**，退出码 1 来自夹具自身的错，**不是** 143/SIGTERM。
- ⚠ 但 `register_command("test", …, uses_display=True)` —— **它需要显示后端**。
  无显示环境（dummy）下会真卡住 ⇒ **CI 默认路径仍然只能是 `lint + 探针`**，
  行为级验证属"开发机 / 带显示的流水线"。
- ⚠⚠ 而且 **`Status: PASSED` 单独不能当判据**（假命题也 PASSED）——
  必须"引擎 PASSED **且**证据文件真的存在"（两把锁，§十二）。
- 所以我们承诺的仍然是 **"工具对语法与引用的认知引擎说了算，且永不静默地错"**；
  行为级从"不承诺"升级为 **"可做，但结论必须带证据、且没证明成要如实说"**。

## 十一、一页速查（贴墙上）

```
顺序（不能颠倒）
  ① parse 干净？ ── 否 ──▶ 报「采集失败」，停止
  ② 采集（lint + json-dump + 探针，每条带 source）→ engine_facts.json
  ③ 对账（定义表 ↔ 引擎 ↔ 真实用法）→ 冲突一律报
  ④ 供给（下拉/表格直接读 ②；定义表只翻译）

三条线
  引擎 oracle = 验证   ｜   定义表 = 翻译（只放引擎不给的语义）   ｜   扫描 = 发现（永不完全）

四个坑
  1 必须 --error-code            2 lint 没报 ≠ 没问题（先查 parse error）
  3 has_image 不是判据            4 parse error 会杀死探针 → 没采到 = 失败

四条新规则（地狱测试第一轮，17 用例）
  N1 扫描只说"我认出了 N 个"       N2 覆盖内置语句要报警
  N3 同组冲突工具自查              N4 把程序 lint 回调的输出收进来

再加四条（第二轮，D1–D7）
  N5 内置被替换（尤其 show / say）→ 最高级警告，形状不保证
  N6 同 tag 重复定义 → 工具自查（普通 image 重复是静默的）
  N7 探针清理必须含 .rpyc（孤儿不会被自动清）
  N8 行为级 test 不进 CI 默认路径（它需要显示后端；实测无头会真卡住）

四层递进的硬事实（§十二，2026-10-11）
  L1 注册表：registry 不是 dict（鸭子类型取）/ 键是元组 / 含内置语句 23 条
  L2 隔离副本：只拷 .rpy+.json+.txt；它承"能不能问干净"，不承"让未知写法可问"
  L3 行为级：test 跑完不自退（读 [rpytest] Status 就收）+ 要显示 + 要 gui/fonts
              run 要可调用（run Jump("x")）；⚠ assert eval 不是硬断言 → **两把锁**
  L4 如实报：没扫描段=不说话；有扫描段但事实不可用=**必须说**；None ≠ False
  ★ 工具认识 ≠ 引擎认识（rules.json 管工具，register_statement 管引擎）
  ★★ 引擎级根因：init 属后面的解析组，一组 parse 出错 → 后面全不解析
     ⇒ 未知写法在哪儿都编译不过，"发现未知"与"问引擎"不能共存
```

## 十二、⭐ "四层递进"与**四件以后一定会再踩的事**（2026-10-11 真机实测）

> 用户给的思路：**从"猜"到"问"到"验"** ——
> ① 运行时注册表对账 → ② 隔离副本注入 → ③ 行为级断言 → ④ 如实报 `undetermined`。
> 四层都落地了。下面是**每一层真正卡住的地方**，以及**引擎那边不可改变的事实**。

### 12.1 ⭐⭐ 一条引擎级根因（它重塑了整个方案的边界）

```python
# renpy/script.py:447-452
for priority, fn, dir in script_files:
    if priority != last_priority:
        if renpy.parser.has_parse_errors():
            skipped += len(script_files) - count
            break          # ← 一组解析出错，后面所有组都不解析
```

`init python`（**注册 CDS 的地方**）属于**后面的解析组** ⇒
**任何未知写法都会让注册代码永远没机会跑。**

三种文件布局全部实测失败（同文件 / 跨文件 / 注册文件字典序在后）；
`register_statement` 不给 `parse=` 也必错（注册进了 registry，解析器那条路是 `None`）。

**所以边界必须这样说**（这一条修正了本方案早期的乐观）：

| 能问引擎的 | 只能靠扫描的 |
|---|---|
| "**能编译**的工程上"的事：注册表里有没有、某句执行了没 | "**这是个未知写法**" —— 未知写法在哪儿都是 parse error，问不到 |

⇒ **"发现未知写法"与"问引擎"在同一个工程里不能共存**；
隔离副本（第二层）**承的是"能不能问得干净"，不是"让未知写法变得可问"**。

### 12.2 第一层（问注册表）：三个反直觉的事实

| 事实 | 后果 |
|---|---|
| ⚠ `renpy.statements.registry` **不是普通 dict**（`isinstance(reg, dict)` 为**假**） | 一句 `if not isinstance(reg, dict): return {}` 就能把注册表**静默滤空**（症状自相矛盾：类型 `dict`、`len()` 却 `None`）→ 只能**鸭子类型**取 |
| 键是**元组**：`('play','music')` / `('pause',)` | 多词语句按词拆开，渲染成"写法"要用空格接 |
| 里面有 **23 条**，**连引擎内置语句都在** | ⇒ **这一层比我们自己的词表更权威** |

真机：`sr_general` 的注册表**本来就是 0 条**（它没用 CDS，与 `scan_project_cds` 一致）。

### 12.3 第二层（隔离副本）：真机跑通，但它救不了未知写法

`build_isolated()`：只拷 `.rpy`/`.json`/`.txt`（跳过图像音频 —— 整份 copytree 会把磁盘写满，
这是实测事故），保留目录结构，**排掉含未知写法的文件**。

```
原始工程（含未知写法）  → ok=False，blocked_by 指出是哪个文件，结论一律 None（不猜）
隔离工程（排掉那个文件）→ 编译干净：注册表 22 条、事实可用
在隔离工程上问          → recognized=False（有效结论）
对照组                  → recognized=False ✅
```

### 12.4 ⭐⭐ 第三层（行为级）：跑通了，但**它的官方判据是假绿的**

**配方**（四条都是撞出来的，少一条就跑不起来）：

| # | 事实 |
|---|---|
| ① | `test` **不是"卡住"** —— 它跑完并打印报告，然后**进程不退出** ⇒ 必须**边读输出边看 `[rpytest] Status:`**，见到就收进程（拿 `subprocess.run(timeout=)` 等会误判成"卡住"） |
| ② | 它**需要显示后端**（`register_command("test", …, uses_display=True)`）—— 无头真卡住 |
| ③ | 它需要 **`gui/` 与 `fonts/`**（起界面就崩：`gui/window_icon.png`、字体文件）—— ⚠ **两处都要**，"行为级专用副本"必须单独抽一个函数，否则漏一处就永远"没证明成" |
| ④ | `run` 收**可调用的 Python 表达式**：裸名 → `NameError`；字符串 → `TypeError: 'str' object is not callable`；**`run Jump("label")` 才行** |

⚠⚠ **假绿**（拿"那句话真的执行了没有"当铁证验出来的：让探针执行时往磁盘写文件）：

| 用例 | 证据文件被写 | `Status` |
|---|---|---|
| 执行 + 断言它执行了 | ✅ | PASSED |
| **不**执行 + 断言它执行了 | ❌ | **PASSED** ← 该红是绿 |
| 执行 + `assert eval "False"` | ✅ | **PASSED** ← 假命题也绿 |
| **不**执行 + `assert eval "…" timeout 3` | ❌ | **PASSED** ← 加 timeout 也没牙 |
| `assert label X timeout T` + `run Jump(X)` | — | ❌ **FAILED**（它等的是"当前停在该 label"，跳过去秒回就错过去了） |

⇒ **判定必须"两把锁"**：① 引擎报 `Status: PASSED`；② **证据文件真的存在**
（产品自己 `Path(...).is_file()` 复核）。只有 PASSED 没证据 → **`verified=False`**，
并明说"即使 test 报 PASSED 也不能当通过"。
**没有可观察证据时一律 `verified=None`**（"没证明成"），绝不退回"只信 Status"。

另两个坑：
- **Windows 路径的反斜杠**会毁掉 `assert eval` 里的字符串（表现是"断言计数 0、
  用例 0.007 秒结束"，看起来像"语句没执行"）⇒ 生成探针时统一转前向斜杠；
- `assert eval` 与 `assert label` **都要"先挂等待、再触发"**（`assert` 在 `run` 之前）。

### 12.5 第四层（如实报 `undetermined`）：两种"没数据"必须分开

| 情况 | 该怎么做 |
|---|---|
| **没有扫描段**（没采过） | 不说话（**不宣称**） |
| **有扫描段、但事实不可用**（项目有 parse error） | ⚠ **必须说话** —— 那恰恰是最该报的情况（那些写法就是测不出来） |

（我第一版把两者一起返回空 → `total_scan=0`、报告沉默，**在最该说话的时候沉默**，
真机 `ask=True` 当场发现。）

口头口径：
```
验过 N 个 —— 通过 x / 失败 y / 没证明成 z
```
`verified=None`（没证明成）**既不叫通过也不叫失败**，绝不折成 `False`。
CI：有 `undetermined` 且 `--strict` → 退 1；不加 `--strict` → 退 0 但**照样打印**
（不偷偷把 CI 变红，那正是"人会把它关掉"的来源）。

### 12.6 ⭐ 最后一条、也是最容易教错人的一条：**工具认识 ≠ 引擎认识**

`storygraph.rules.json` 里写声明，只让**我们的工具**认识这个写法；
**引擎**要认识它，项目里必须有它自己的 `renpy.register_statement` ——
而且因为 §12.1 那条根因，**`init python` 里注册赶不上解析期**。

⇒ 界面上的「▶ 验证它能跑」按钮**当场说清这件事**（并给出"怎么办"），
而不是让用户对着"没证明成"发呆。**能用它验"通过"的，只有引擎本来就认识的写法** ——
这不是按钮坏了，是它诚实地说"引擎跑不了它"。

### 12.7 ⭐⭐ "那能不能由我们**替项目**注册？" —— **不能**（三条路都试过）

想解决 §12.6 那个缺口，只剩一条思路：**在引擎解析之前，把注册代码先执行掉**。
真机把三条路都走了：

| 试法 | 结果 |
|---|---|
| 项目自己的 `init python: renpy.register_statement(...)` | ❌ 永远太晚（§12.1） |
| 往副本里放 `game/*.py`（以为引擎会先跑它） | ❌ **引擎根本不执行项目里的 `.py`**（钩子里那行 `print` 一次都没出现） |
| 外部 runner 挂 `renpy.main.main` / `early_init_emulator` 钩子 | ❌ Ren'Py 会 **pickle 模块属性做备份**（`renpy/__init__.py:341`）→ 新补的函数过不了 pickle（`Cannot pickle …`） |

再叠加 `sort_script_files`（`script.py:389-435`）的排序：`renpy/common` 在前、
`game` 分 libs/mods/大写/小写四档 —— **哪一档都不是"先执行再解析"**。

**⇒ 引擎里不存在"注册代码先于解析执行"的位置。** 所以：

- 项目自己写 CDS，**不可能**让引擎在解析期认识它的写法；
- 我们的工具**只能在"注入副本"里替它预注册** —— 那是**工具的能力**，
  不是项目的能力，所以**绝不能要求作者去改项目**；
- ✅ 但**注册代码是能抽出来的**（`extract_init_python` /
  `collect_registrations`，纯函数，见 `tools/probe_layer5_preparse.py`）——
  真要哪天做"工具预注册"，前提已经具备（把抽出来的代码在启动引擎前执行掉）。
  ⚠ 注意那需要**改动 SDK 侧或走 fork**，与"零依赖、不碰 SDK"的现约定冲突，
  所以**暂时不做，只留证据与入口**。

## 十三、⭐ 程序侧契约：**"依赖程序时成本最低"**（2026-10-11 用户定的框架）

> **用户原话（这一节的总纲）**：
> "CDS 预注册的目的（让工具独立验证自定义语法）是合理的，但 **CDS 预注册这个手段是错的**。
>  正确的实现方式是：
>  · 验证合法性：调用 `lint`（已实现），**或让程序提供验证函数**；
>  · 获取形状：扫描 CDS 代码派生声明，**或让程序写声明文件**；
>  · 测试未知写法：隔离副本 + 数字前缀注入（已实现）。
>  **工具的价值不在于"不依赖程序"，而在于"依赖程序时成本最低"。**
>  程序写一行 CDS 注册，工具自动派生声明；程序写一个验证函数，工具自动调用。
>  这才是团队协作该有的效率。"

### 13.1 框架修正：我原来错在哪

我把"**零依赖**"当成了**目标**，于是把"该由程序花一行解决的事"（写 CDS 注册、
写个验证函数）硬扛成"工具自己想看懂"，最后撞上引擎级不可能（§12.7），
还留着一条"改 SDK 预注册"的邪路。

**改正后的形状**：工具**主动要求**程序提供最小信息，并把它**自动化消费**掉：

| 要什么 | 谁提供 | 工具怎么做 |
|---|---|---|
| 合法性 | 引擎 `lint` **或程序的一个验证函数** | 自动调用（`host_hooks`） |
| 形状 | CDS 代码 **或程序的声明文件** | 自动派生（`cds_registry`）/ 自动读取 |
| 未知写法 | —— | 隔离副本 + 数字前缀注入（不依赖程序） |

⇒ **"程序多写一行，工具自动跟上"**；程序不写，工具**信息不足**（不是没做好）。

### 13.2 契约：`storygraph.host.py`（程序侧要做的**全部**事情）

在**项目根**或 `game/` 下放一个 `storygraph.host.py`，按需定义两个函数：

```python
def declarations():
    """额外的声明（形状同 storygraph.rules.json 的 statements 段）。"""
    return [{'name': 'weather', 'label': '天气', 'columns': [...]}]

def validate_statement(head, text):
    """这个写法这一行长什么样合不合法？

    True        → 我认它，没问题
    (False, 原因) → 我认它，但这一行不对（**原因会原话转述到报告里**）
    None        → **我不管这个**（工具自己判断）
    """
    if head == 'mycue':
        return ('闪电' in text), 'mycue 只认「闪电」'
    return None
```

工具侧实现 `story.statement_registry.host_hooks.load_host_hooks()`。

**三条自我约束**（都成判据，见 `tests/test_friendly_project.py`）：

1. **程序不给就不发生** —— 没有那个文件 → `available=False`，
   工具行为与以前**一模一样**（这是"零成本"，不是"零依赖"）；
2. **它写的代码不许弄坏工具** —— 语法错 / 抛异常 / 返回垃圾 → 只记进 `notes`，
   工具照常干活（"依赖程序"不能变成"被程序拖死"）；
3. **它说什么要能看见** —— `notes` 如实记录；程序给的**理由用原话**，工具不自己编。

⚠ **`None`（程序不管）绝不等于"程序说没问题"** —— 两者必须分开，
否则又会造出假绿（判据 `test_validate_none_is_not_a_yes`）。

### 13.3 ⭐ 一条**边界**（信息不足，不是缺陷）

```
mycue "闪电"      ←→      「角色 mycue 说『闪电』」
```

**字面完全同形** —— 只读文本，**任何**扫描器都分不出来。所以分工只能是：

| 谁 | 管什么 |
|---|---|
| **扫描器** | 同形的东西**不猜**（宁可不报，也不能把台词当写法 —— 那比漏报更糟） |
| **引擎 `lint`** | 说 `expected statement` —— **那才是判据** |
| **程序的验证函数** | 它有语义知识，能一锤定音（`§13.2`） |

⚠ 由此得一条**接线要求**（真机踩到）：工具的形状判据**认不出的行**
（如 `mycue "打雷"` 与台词同形 → head 为空）**也必须先问程序的验证函数** ——
原来那种"`head` 为空就 `continue`"会让程序的验证函数**永远问不到**。

### 13.4 两套项目：一个攻击，一个验证（方法固定下来）

| | **地狱项目** | **友好项目** |
|---|---|---|
| 目的 | 工具**扛不扛得住怪东西** | **程序花最小力气，工具能走多远** |
| 造法 | **借真实项目的规模**（拷真 `.rpy`）+ 塞合成边界 | 全合成：程序写一行 CDS / 一个钩子 |
| 位置 | `tools/make_hell_project.py`（生成物进临时区） | `tests/test_friendly_project.py` |
| 常态 | `tools/attack_hell_project.py`（真机探照灯）+ `tests/test_hell_project_attack.py`（CI 常驻） | CI 判据 |
| 边界清单 | 13 个：自定义写法 / **覆盖内置语句** / **计算出来的名字** / ATL 块冒号 / 内置关键字 / 中文标点 / **同名 label** / 极长行 / 空文件 / 只有注释 / **多词语句** / 缩进不一致 / 裸参数 | CDS 派生声明 / 程序验证函数 / 坏钩子 |

⚠⚠ **造地狱项目时必须一起拷 `asset_tables/`（人物表）** —— 少了它，
`discover_undeclared` 会把台词的说话人当成"未知写法"，攻击就会报出**假缺陷**
（我第一轮就报了一条，差一点去改工具逻辑）。**地狱项目造假 → 攻击结论也假。**

⚠ 另一条教训：第一轮攻击的三条 ❌ 里，**两条是攻击脚本自己的错**
（少拷人物表、`cli.py` 调用方式错）。**探针/判据自己错了，比缺陷更常见。**
