# 前端迁移方案：tkinter → PySide6

> 状态：**完成（2026-10-01）**。tkinter 已**彻底移除**，本文档是迁移与
> 前端架构的"唯一权威"。
> 核心原则：**后端语义一个字都不重写**，只换表现层；并且把"表现层"与
> "编辑语义"彻底分开（见第二节）。

---

## 一、这次到底改了什么（一句话）

原来编辑语义住在 tkinter 里，Qt 前端只能隔着 `ui/` 目录去偷用；
现在中间多了一层 **`storygraph/app/`（框架无关的深模块）**，
前端（以及 CLI、测试）都只跟它打交道。

```
core / parsing / excel / assets / story / pipeline
                    ↓
                app/          ← 深模块：接口小、语义全在这里（禁止 import 任何 UI 框架）
                    ↓
              ui_qt/ (PySide6)      ← 只做"摆控件 / 读表单 / 写表单"
```

**最终形态是单前端**：`storygraph/ui/`（tkinter）整个包已删除，
所以仓库里不可能再出现"两套前端各写一套语义"。
`tests/test_ui_integration.py::test_whole_codebase_is_tkinter_free`
用 AST + `sys.modules` 双重把关。

### 2.1 后端反向依赖前端（已修）

`graph/` 与 `pipeline/` 里的这几个模块曾经为了弹一个提示框而 `import tkinter`：

| 位置 | 原来 | 现在 |
|---|---|---|

所以 `tests/conftest.py` 里塞了 80 行 tkinter 桩来兜。现在后端不弹框了，
它只"汇报事实"：


前端订阅后才决定怎么显示（Qt → 状态栏 + Toast；CLI → stderr；

而 tkinter 全部删除之后，`tests/conftest.py` 里那 **80 行 tkinter 桩**
也一并删掉了 —— 而且**故意不留**"以防万一"的桩：
真有人再往核心里塞 UI 依赖，那里就该当场炸。

### 卡片上的「保存 / 撤销」（用户 2026-10-01 明确要求）

> 我希望卡片端加两个功能：一个是保存该卡片的修改，另一个是撤销修改的操作

| 按钮 | 语义 | 快捷键 |
|---|---|---|
| 💾 保存这张卡片 | 把表单写进这一拍；**只有真改了才压撤销栈** | `Ctrl+S` |
| ↩ 撤销修改 | 把这张卡片恢复成**上一次保存时**的样子（逐拍、单级） | `Ctrl+Z` |

关键设计（`app/editor.py`）：

- **判"改没改"用快照指纹，不用 `Beat.content_hash`** —— 后者是
  **持久化字段**（进 Excel 的「内容指纹」列），编辑之后还是旧值，
  拿它当判据会把"改了"判成"没变"（撤销按钮永远不亮）。
- **撤销是逐拍、单级的**：用户按的是"这张卡片"的撤销，回退整章会把
  别的拍的改动一起抹掉。
- **换章清空撤销栈**：否则会把上一章的快照摊到这一章同拍号的 Beat 上。
- 保存/撤销都在**语义层**，所以工具栏按钮、卡片按钮、快捷键三处
  共用同一份实现（不各写一套）。

### 图的排版：间距**由节点尺寸算出来**（不许两处各写一个数）

模块块是 208×104，而 `graph/layout.py` 的默认间距（180/60）当年是给
**120×60** 的 tkinter 块调的 —— 节点放大了却忘了改间距，同层相邻的块
**垂直重叠 36px**；50 多个块再被 `fitInView` 一压，"结构化模块化的图"
就成了一堵糊在一起的小方块墙。现在：

- `ui_qt/graph_canvas._layout_gaps()` 是**唯一**真源（`NODE_W/NODE_H` → 间距），
  `layout.py` 只负责分层与减交叉，尺寸由调用方传进去；
- 默认**不再无脑适应窗口**：装得下（比例 ≥ 0.70）才 fit，装不下就 100%
  停在入口块 —— 50 个块 fit 进一屏必然缩到 0.4 以下，字全成蚂蚁；
  要给全貌就点「🔍 适应窗口」；
- 连线：**真箭头** + 条件/选项标签 + 按语义着色（选项 / 条件 / 类型），
  自环画成方块右侧一圈；**水平进出**（层次是左右分列的，不是上下）；
- 拖块时连线跟着走；
- 块上只放"人要看的"：label 名 + `文件:行号` + `story_ops.summarize()`
  摘要（`2 剧情变量 · 2 技术代码`）。技术代码**只报数量、不上块** ——
  真实项目一个块能挂 55 条 `renpy.transition(...)`，铺上去就把剧情变量淹了。

### 静态分析从"弹窗"回到"看得见的面板 + 画回图上"

tkinter 版右栏常驻一个"分析结果"文本框；搬 Qt 时变成了**必须点开的对话框**，
结论又只给一段文字 —— 用户还得自己在几十个块里找哪个有问题。现在：

- 「📊 变量分析」→ 逐节点区间明细（也标回图上）；
- 三种结论分得清清楚楚（判据在 `app/editor.analyze_graph_problems`）：

| 结论 | 判据 | 图上 |
|---|---|---|
| 真断了 | 从**任何**入口都走不到（关在没有入口的环里） | 红边 + 粉底 + ⚠ |
| 死分支 | 所有出口条件恒假（下落风险） | 红 |

label，靠菜单 / `call screen` 进入，而解析器只认字面 jump/call/menu。

### 2026-10-03（第三轮）：连线、条件、立绘、舞台说明

用户四条反馈 + 一条追加（"我连了！！！就是它没有反应！这是个bug！"）：

| # | 用户原话（节选） | 根因与处置 |
|---|---|---|
| 1 | 我连线呢！？？？tkinter那一版都有连线，你这个为何显示不出来？ | **两个独立问题**：(a) `if dlg.exec() != dlg.Accepted` —— `QDialog.Accepted` 是类属性、**实例上取不到**，异常被槽吞掉 → **「连线」「新章节」「编辑变量」三个动作从来没生效过**（对话框填完按"创建"什么都不发生，只在 stderr 留 traceback）；(b) 他导入的三章**彼此没有跳转**（`chapter1_1/1_2/1_3.rpy` 各只有一个 label + `return`，串起它们的是 `chapter_controller.rpy`），所以图里确实无线可画 —— 现在控制台会**点名说缺哪个文件**，并提供「🔗 补全相关章节」一键补齐（补齐后 10 块 / 9 边） |
| 2 | 我那个存在条件选择分支，请确保逻辑正确 | `if/elif/else` 的 **`elif` 漏了"前面分支都没走"**：`if score>3: jump X / elif score>1: jump Y` 的第 2 条边写成 `score > 1`（比实际宽）→ 现在写成 `(score > 1) and not ((score > 3))`；`else` 的 De Morgan 本来就对，两条路径（AST / Statement）口径统一。`menu` 选项的**文字**与**条件**分别进 `option_text` / `condition` |
| 3 | 有立绘时图片一开始没有显示？立绘加载得有点久，而 cg 很难出现？ | (a) **过期结果不丢**：`_on_ready` 不看回来的 key，旧请求的结果会吃掉新请求的回调并把旧图缓存到新键上 → 换表情/CG 后图不出来；(b) **没走共享解码内核**：自己 `QImageReader.read()` 整图再缩，而 `app.thumbs.decode_sync` 本来就是"解码器级降采样 + 缩略图 + 磁盘缓存"（注释里写着让 Qt 用它，一直没接）；(c) **CG 不在资源表里**（实测 2828 条图片记录无一条 cg，但 `game/images/cg/cg03.png` 在磁盘上）→ 解析器返回 None 时**退回按目录约定猜**，以前一拿到 None 就放弃；(d) 解码期间显示"tag …"+"正在加载：路径"，不再看起来像坏了 |
| 4 | 为何不写明现在的舞台情况是什么样的，旧版明明都有 | `story.stage_snapshot.stage_digest` **一直在**（旧版预览面板用它），卡片搬 Qt 时没接上。现在卡片上有「当前舞台（这一拍生效）」：本拍变化 + 背景 / 立绘 / **CG 图层** / 音乐 / 音效 / 语音 / 条件 / 备注，外加 `app.beats.inherited_state_hint` 的"继承上一拍：…"。顺带给 `stage_digest` 补了 `CG/图层：` 一行（以前舞台说明里看不出屏幕上有张 CG） |

**这一轮的教训（都写进第七节了）**：

- `dlg.Accepted` 这类"取不到就抛异常"的写法，如果抛在 Qt 槽里就是**静默失效** ——
  三条动作坏了几天，测试全过（测试直接调 `_on_accept()`，从没走"窗口 → 对话框 →
  回窗口改图"这条真实路径）。现在有 **AST 守卫**（禁止实例取 `Accepted`/`Rejected`）
  + 三条**真跑一遍**的用例（patch 掉对话框的 `exec`，断言图里真的多了东西）。
- 异步加载器的结果必须**核对 key**，否则"旧结果顶掉新回调"是必然事件。
- 同一个"图片找不到"的 bug 可以在**两层**里各有一半：路径解析返回 None +
  上层拿到 None 就放弃。只修一层等于没修。

#### ③ 增量生成实机验证（`D:\千连万理\RenPyTest\sr_general`，40 个 .rpy）

脚本：`.pip-tmp/verify_incremental_export.py`（只读原文件，产物写 `incr_out/`）。
**挖出两个 P0**（都已修 + 各配回归用例）：

| 现象 | 根因 | 处置 |
|---|---|---|
| **改一段旁白 → 导出后那句台词原样不动**（`changed_lines=0`） | `_range_looks_like` 用 `beat.text`（**当前**文本）判断"这段原文属于这一拍"，而用户刚把它改掉 → 原文里找不到新文本 → 判成"源码区间对不上"跳过。有说话人的台词因为还能匹配说话人，所以一直没暴露 | 对"没有别的可比信号"的拍（旁白：无说话人、无舞台）补一条判据：原文段与**新生成**段行数相同且相似度 ≥0.6 就认。注意要比**精确区间**，不能比"前后各留一行"的窗口（窗口天然多几行，行数一比就不等，判据会永远失效） |
| **删掉一拍 → 导出后那拍还在文件里**，而且报告"增量成功" | `dropped`（"表里删了拍"）只在 `recover_source_ranges` 里算，而它**只在拍上没有行号时**才被调用；编辑器那条路（载入章节→删卡片→导出）拍上都带行号 → 删拍检测整个被跳过 | 给 `recover_source_ranges` 加 `apply_ranges=False`（只数 dropped、不碰行号），**每次导出都查**。现在会如实报"表里删掉了 1 拍，本轮增量不支持删行"并退回全量 |

**验证结论（实测数据）**：

- 40 个文件里 **12 个逐字节不变**（含多章正文）；
- 28 个有差异，其中**全部**是以下三类**已知且合理**的原因：
  ① 增量的整体校验发现"生成器要的 1~4 行落不进原文区间" → **主动退回全量**
     （安全方向：宁可重写，也不写半对的脚本）。典型是文件里粘了大段报错/
     注释块的块（`chapter1_2` 那种）；
  ② 全量重生成会**带上 transform 定义与自己的文件头**（`chapter1_1` 151 行、
     `chapter3_1` 473 行差异主要来自这里）——原项目把这些放在
     `definitions.rpy`，所以对这类项目**增量成功才有意义**，退回全量就会
     把定义重复写进章节文件；
  ③ 空白归一化（`jc  "…"` → `jc "…"`），Ren'Py 两种都接受，但会让差异行数
     比"真正改动的行数"多。
- **"改一处"用例**：`chapter1_2` 改 1 句台词 → `changed_lines=1`，
  文件头注释、其余台词、控制流**一个字节不动**（控制流行改动 = 无）；
- **幂等**：同一份内容再导一次，产物与上一次**完全一致**；
- **原文件未被修改**（脚本只读原文件）。

**教训**：`src_first/src_last` 是"运行期元数据"，任何**依赖它的检查**都要问
一句"这条路（编辑器 / 剧本表）真的会填它吗" —— 删拍检测就是这么被静默跳过
的；而"用当前值去校验原文"这类写法，在"用户刚改过"的输入下必然失效。

### 2026-10-05（第八轮）：无限舞台 + 缩略图优先级

> 用户："这个拖不动是因为你的这个舞台有限……可是我的 tkinter 做的是无限的舞台

> 优先加载目前在窗口内的图片！"

| 现象 | 根因 | 处置 |
|---|---|---|
| **画布拖到某个方向就再也拖不动**（"舞台有限"） | 旧版 tkinter 是"世界坐标 + `offset`"自己画的，**没有边界**；Qt 版用 `QGraphicsView`，可平移范围由 `sceneRect` 决定 —— 内容 + 60% 余量就是尽头（`setValue` 被滚动条夹住） | `_extend_scene_rect()`：可见区离边界近了就把矩形往外长一截，并用 `centerOn` 把视口摁住（画面不跳）；平移时**先撑再滚**；缩小后也撑一次。实测连拖 10 次累计 3686 场景像素、**一次没卡**，sceneRect 1409×1305 → 5466×4348 |
| **选择器里"窗口内那一屏"出图慢** | 每个请求直接进 `QThreadPool`，而它**先进先出**：滚过去的那几十上百张排在前面，看得见的那一屏排在最后（实测 4.28 s） | `ThumbLoader` 改成**优先级队列**：`_want`（想要什么）+ `_running`（同时最多 N 张）+ `_pump()`（谁空出来按 (优先级, 先来后到) 补一张）。选择器每次算完可见范围就 `focus(窗口内那一屏)`；预取是 `BACKGROUND`，永远不挡路。实测那一屏 **1.76 s**（A/B 真实 9.6 MB 立绘分组：4.48 s → 2.24 s） |
| 上面那条**第一次没修好** | `focus()` 只提"这一次新请求的 slot" —— 但每次都会多留"上 1 行、下 3 行"，滚到下一屏时那一屏**早就排过队了**，于是 `focus([])` 等于谁都没提（时间线里看得清清楚楚：窗口内出图 0/16 一直到 3.5 s） | `focus()` 提"**窗口内、还没有图**"的**全部**格子（不管它是这次请求的还是早就排队的）；正在解的 14 张不打断，但空出来立刻轮到可见项 |

  2. 跑完测试 `sys.modules` 里不许出现 tkinter（抓动态导入）；
  3. Qt 窗口里不许出现 tkinter 的 `command=self.xxx` 写法
     （Qt 不认这个关键字 = 静默不接线）。

## 七、踩坑记录（Qt 特有，记下来免得再踩）

1. **在 `paint()` 里抛异常 = 直接 segfault**（没有任何 traceback）。
   例：`painter.Antialiasing` 在 PySide6 里不存在（要写
   `QPainter.RenderHint.Antialiasing`）。所以自定义 paint 必须用完整枚举路径，
   且整体包在 try/except 里（`StageCanvas.paintEvent` 就是这么写的）。
2. `QGraphicsView` 没有内置的"空白处拖动平移"，要自己接中键/空格+左键。
3. offscreen 截图中文变方块 → 设 `QT_QPA_FONTDIR=C:\Windows\Fonts`。
4. **子控件 `isVisible()` 在窗口没 `show()` 时恒为 `False`** —— 测试里
   要断言"报了错"应该看 `label.text()`，不是 `isVisible()`。
5. `QDialog.Accepted` 是**类属性**，实例上取不到（`dlg.Accepted` 会
   AttributeError）；测试里请 `from PySide6.QtWidgets import QDialog`。
6. 关窗时**不要**阻塞等 `QThreadPool` —— 解码中的图让它自然跑完、
   结果丢掉即可（`_shutting_down`）；阻塞会让"关窗"卡住。
7. **定义了 `eventFilter` 不等于键盘能用** —— 必须
   `installEventFilter`，而且要装在 `QApplication` 上：
   焦点通常在 `QPlainTextEdit`（台词框）里，装在窗口上的话事件根本到不了。
   装完记着在 `closeEvent` 里**摘掉**（不摘的话窗口关了过滤器还活着）。
8. `QLabel[role="x"]` 这类属性选择器**改了属性要重新 polish**，
   否则颜色不会立刻变：`w.style().unpolish(w); w.style().polish(w)`。
9. 应用级过滤器要判"这个事件属不属于我的控件树"
   （`self.isAncestorOf(w)` + 向上找 parent），否则弹出的对话框里
   按回车会被主窗口抢走。
10. 列表类控件（`QListWidget`）自己会处理 ↑/↓ —— 应用级过滤器必须
    **放行**，不然一次跳两拍（tkinter 版踩过同一个坑）。
11. **几何相关的兄弟项要在 `ItemPositionHasChanged` 里刷新，不是
    `ItemPositionChange`**：后者是"位置**将要**变"，此时
    `sceneBoundingRect()` 读到的还是旧坐标 —— 表现是"拖了块，连线不动"，
    而且**不报任何错**。
12. **`QTimer.singleShot(0, ...)` 的启动任务不许改界面状态**：它在第一个
    事件循环回合跑，会把这一回合内用户/调用方刚做的状态改动（页号、
    选中项、展开状态）悄悄覆盖掉。初始状态在构造函数里**同步**定好；
    延迟任务只做"慢活"（塞图这种），且只碰数据。
13. 画布**不要默认 `fitInView` 全图**：节点一多就缩到 0.4 以下，字全成蚂蚁。
    策略是"装得下（比例 ≥ 0.70）才适应，否则 100% 停在入口块"，
    再给一个显式的「适应窗口」按钮让人自己看全貌。
14. `QGraphicsRectItem` 上挂文字子项要
    `setFlag(QGraphicsItem.ItemClipsChildrenToShape, True)`：子项不会自动截断，
    长名字会直接画出框外；文本本身用
    `QFontMetricsF.elidedText(...)` 截。
15. **静态分析的标记密度是功能的一部分**：标红超过约 1/3 就等于没标
    （用户会直接忽略整张图）。分类判据要按"能不能据此断定有问题"来设计，
    而不是"跟当前入口对不上就报红"。
16. 两页导航之后，**快捷键只在它所属的页里生效**（`eventFilter` 里判
    页号）：在结构图上按回车"顺手翻一拍"是最坏的一种 —— 屏幕上看不出变化，
    但会话里的当前拍已经换了，接着按保存就存到错的那一拍上。
17. **不要让 `QAction` 挂快捷键**（在这个两页窗口里）：`QAction` 的快捷键
    不受"当前在哪一页"约束，工具栏隐藏了它照样触发。`Ctrl+S` 挂在动作上，
    用户在结构图上按一下，屏幕毫无变化而**那一拍真的被存了** ——
    看不见的写入。所以键盘只在 `eventFilter`（判页号）里处理，动作只负责
    "点"；卡片页专属动作在结构页 `setEnabled(False)`（工具栏上灰掉，
    用户一眼知道"这个键现在不管用"）。守卫：
    `tests/test_ui_qt.py::test_no_action_carries_a_shortcut_...`。
    ⚠ 验证这条**必须用真按键**（`QTest.keyClick`）：
    `QApplication.sendEvent` 会**绕过** Qt 的快捷键系统，用它测等于没测。
18. **"界面范围"必须有一个明确的输入**：剧情图里放什么，只能由**用户的选择**
    决定（导入哪些章节），绝不能由"项目里有什么"推出来。把两者混成一句话
    （"打开项目 → 建出图"）的那一版，真实项目直接画出 51 个块。
    做法上还留了一道硬边界：**资源加载函数的签名里没有 graph** ——
    以后谁想顺手建图，得先改签名，而改签名会被测试拦住。
19. **扫源码的判据一律走 AST，不做字符串搜索**：这个坑在本仓库踩过两次
    （tkinter 那次是文档字符串里写着"禁止 import tkinter"；这次是注释里
    写着"以前这里 `discover_scripts(root)`"）。注释里提到旧写法是**好事**
    （它记着为什么这么改），不该被自己的测试判成违规。
20. **"要不要自动排版"要看"有没有块没被摆过"，不是"是不是全都在同一点"**：
    累加导入时新块落在解析器默认坐标上，旧判据会认为"已经有布局了"而不排，
    新块就压在别人身上（且不报错）。
21. **`Qt.SpaceModifier` 不存在**（空格是**按键**，不是修饰键）。旧代码里
    `event.modifiers() & Qt.SpaceModifier` 会让 `mousePressEvent` 每次左键
    按下都抛 `AttributeError` —— 症状是**左键点块、拖块全都没反应**，
    而右键菜单照常能用（走的是另一个 handler）。所以看起来像"设计成右键操作"，
    其实是崩了。要平移就自己跟踪按键状态（`keyPressEvent` 里记 `_space_down`），
    或者接受中键。
    ⚠ 这类"事件处理器里抛异常"的坑**只有真发鼠标事件才测得出** ——
    直接调 `window.select_node()` 之类的测试永远看不到它。
22. **纯文本 `QLabel` 会把 `**加粗**` 连星号一起显示**。说明窗口用的是
    "只把 `**x**` 变 `<b>` 的富文本"（`_emphasize`），但对话框里的说明标签
    是纯文本 —— 文案里别再写 Markdown 标记。整篇走 `Qt.MarkdownText` 也不行：
    帮助文本里的 `1. ` 与缩进会被解释成有序列表 / 代码块，排版更乱。
23. **模态对话框会把脚本/测试卡死**（不是失败，是**一直等**）。
    `QMessageBox.question`、`dlg.exec()` 在无头环境不会有人点。
    测试里要么 `monkeypatch` 掉（`QMessageBox.question` → `Yes`），
    要么直接构造对话框来验证内容、别走"真点击触发 `exec()`"那条路。
