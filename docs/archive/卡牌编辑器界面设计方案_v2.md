# 卡牌编辑器界面设计方案 v2（对《改版方案》的评审与修订）

> 角色：UI Designer。本文先评审 `docs/卡牌编辑器改版方案.md`（下称"v1"），
> 再给出修订后的设计与**可交接的组件规格**。
> 目标：既美观又易用，且每一处尺寸/颜色都有依据，不是"拍脑袋的像素"。

---

## 一、评审 v1：方向对了，但漏了真正的病灶

### 先肯定

v1 的三个判断我完全同意，而且定位很准：

- **卡顿 = 同步解码 × 输入即触发 × 无缓存**（`beat_editor.py:1535-1538` 的 `trace_add` + `184-216` 的无缓存解码）；
- **占地方 = 一行一图**（缩略图 `150×210` 撑高行高，3 个立绘 ≈ 630px）；
- **翻页被挡是前两条的连带结果**，不是独立的布局问题。
- 拆出"UI 层分组、不动 `beat.show` 数据契约"这条约束，非常正确。

### 致命问题（不改的话，改版后用户照样困惑）

**① 漏掉了"表情 / 位置有两个编辑入口"——这才是"表情不直观"的根因**

现状（读代码确认）：

- `PRIMARY_FIELDS = ['Speaker', 'Text', 'Expression', 'Position']`（`1216`）——
  面板级就有「表情」「位置」两个字段；
- 但它们作用于**第一张立绘**（见 `_first_sprite_item`，`305`）；
- 而每个立绘行**自己也有** 表情 Entry(`width=10`) 与 位置 Entry(`width=8`)（`1520-1523`）。

于是：**多立绘时，改表情有两个地方能改，改的效果还不一样。**
用户的心智模型必然崩：我改的是谁的？为什么改了没反应（改到第一张去了）？

> v1 把"表情不直观"归因于"展示层没有按 tag 聚合"，这只说到一半。
> 就算聚合了，只要顶部还留着作用于第一张的「表情/位置」，困惑依旧。
> **修法第一条：消灭双入口**（见 §3.1）。

**② 异步加载会"抖"**

v1 的 A 方案（防抖 + 线程 + 缓存）与 B 方案（网格）组合后有个副作用：
图晚到 → 卡片内容从"空"变"有图" → **布局跳动**。
规格上必须锁死：图区尺寸固定、骨架与成品同尺寸、**名字与徽标不依赖图**（立即渲染）。

**③ 删除（✕）16px、在网格里、不可撤销**

密集网格里 16px 的 ✕ 极易误触，而删除立绘是**破坏性操作**。
必须：hover 才显示 + 命中区 ≥ 20px + **删除后给"撤销"**。

### 重要问题

**④ 卡片尺寸 96×128 没有推导依据。** 应按"人脸可识别下限"反推（见 §3.2），并说明取舍。

**⑤ 空态 / 无图态缺失。** 一个立绘都没有时网格显示什么？缺图时卡片还能不能编辑（应该能）。

**⑥ 无障碍只列了清单，没落到组件。** 缺三样：focus ring 的**具体规格**、**键盘操作映射表**、**点击目标尺寸**。

**⑦ token 是散的常量，不成体系，** 谈不上主题化，也无法保证"95% 一致性"。

### 建议

**⑧ 信息架构可以再进一步**（现有面板其实已有 `PRIMARY` / `ADVANCED` 分区，v1 没利用）：把"说话人 + 台词 + 立绘"做成**永不滚动的第一屏**。
**⑨ 翻页按钮缺首/末句的禁用态。**
**⑩ 缺量化验收**（点击次数、面板目标高度、一屏可见数）。

## 二、设计原则（本方案的四条硬约束）

1. **单一入口**：一件事只有一个地方能改（表情只在立绘卡内改）。
2. **结构先于内容**：卡片骨架与成品同尺寸，图晚到也不跳。
3. **破坏性操作可撤销**：删除必须给撤销，不弹确认框打断流。
4. **状态不只靠颜色**：选中 = 边框 + ✓；错误 = 图标 + 文字。

---

## 三、信息架构与交互

### 3.1 消灭双入口（P0）

| 位置 | 现状 | 修订 |
|---|---|---|
| 面板级 `Expression` / `Position` | 有，作用于第一张立绘 | **移除**；改为"选中立绘"的状态提示（只读） |
| 立绘行内 表情/位置 | Entry 手填 | **卡内 chip 点选**（表情/位置各一组 chips） |
| 选区 | 无 | 卡片可点选；**当前选中卡** = 面板级字段的作用对象 |

`PRIMARY_FIELDS` 收敛为**两项**：`['Speaker', 'Text']`——策划真正会改的只有这两样 + 卡内 chips。

### 3.2 立绘卡：从"一行一图"到"网格卡片"

**尺寸推导**（不是拍脑袋）：

- 立绘多为竖构图 3:4（如 750×1000）→ 图区用 **88×118**（3:4，等比不压扁）。
- 身份可识别的脸部宽度下限约 32–40px；88px 宽的半身图里脸部约 35–44px ✔ 刚好够认。
- 其余：名字条 18px（12px 字）+ 徽标行 22px（chip 20px）+ 内边距 6px + 间隙 4/2px。

```
┌─ 卡片 100 × 176 ─────────┐
│ 6                        │
│  ┌──────────────┐        │
│  │  图  88×118  │  ← 固定 │
│  └──────────────┘        │
│ 4                        │
│ ling  ▶说话        (12px) │  ← 名字条 18
│ 2                        │
│ [开心] [左]              │  ← 徽标行 22（chip 高 20）
│ 6                        │
└──────────────────────────┘
```

- 一行放 **4–5 张**（面板宽 ~520px）；3 个立绘 = **1 行 = 176px**（当前 630px，**降 72%**）。
- 比 v1 的 140px 高 36px，但换来了**表情 chips 在卡内**：改表情从"点卡 → 看下方编辑区 → 改"
  变成"**直接点卡内 chip**"，省掉一次点击和一次视线往返。**这个取舍值得。**

### 3.3 表情聚合（沿用 v1 思路，落到卡内）

同一 tag 的多个 show 子项 → **一张卡**，卡内 chips 列出该角色本拍出现过的表情，
当前生效的 chip 高亮 + ✓；点其它 chip = 切换生效表情。
同 tag 多条且位置不同 → 卡上加 `⚠ 同 tag 多条` 徽标 + tooltip（那不是两个人，是数据异常）。

### 3.4 添加 / 删除

- **添加**：网格末尾放一张**虚线"＋"卡**（与立绘卡同尺寸），原地添加，不用滚到底部找按钮。
- **删除**：✕ **hover 才显示**（避免误触），命中区 20×20；删除后 **Toast 给"撤销"（8 秒）**。

### 3.5 翻页

顶部工具条：`◀ 上一句 | 下一句 ▶ | 第 12 / 1730 句`，并标注快捷键；
首句禁用"上一句"、末句禁用"下一句（显灰 + `disabled` 态，不是隐藏）。

## 四、设计 token（体系化，light / dark 两套）

> 实现为 Python 常量字典 `TOKENS = {'light': {...}, 'dark': {...}}`，
> 所有组件**只从 token 取值**，禁止在组件里写死色值——这是"95% 一致性"的前提。

### 色彩

| Token | Light | Dark | 用途 | 对比度（对各自底色） |
|---|---|---|---|---|
| `bg.canvas` | `#FFFFFF` | `#1E1E1E` | 面板底 | — |
| `bg.card` | `#FAFAFA` | `#252525` | 卡片底 | — |
| `bg.card.hover` | `#F0F6FC` | `#2E2E2E` | 卡片悬停 | — |
| `bg.skeleton` | `#EEEEEE` | `#333333` | 骨架块 | — |
| `border.default` | `#E0E0E0` | `#3A3A3A` | 默认描边 0.5px | — |
| `border.strong` | `#90CAF9` | `#64B5F6` | 悬停描边 | — |
| `brand.primary` | `#1976D2` | `#64B5F6` | 主色（选中/强调） | 4.6:1 ✔ |
| `brand.onPrimary` | `#FFFFFF` | `#102A43` | 主色上的文字 | 4.6:1 ✔ |
| `text.primary` | `#212121` | `#E8E8E8` | 正文 | 16.1:1 ✔ |
| `text.secondary` | `#757575` | `#A8A8A8` | 说明/计数 | 4.6:1 ✔ |
| `text.hint` | `#9E9E9E` | `#8A8A8A` | **仅图形，不承载文字** | 2.8:1 ✗ |
| `state.error` | `#C62828` | `#EF9A9A` | 缺文件/失败 | 5.4:1 ✔ |
| `state.warning` | `#B45309` | `#FFB74D` | 同 tag 多条/缺图 | 4.7:1 ✔ |
| `state.success` | `#2E7D32` | `#81C784` | 已同步 | 4.6:1 ✔ |
| `state.info` | `#1B7A4B` | `#7CB342` | 继承提示（**现用 #0A5 仅 3.1:1，不达标**） | 4.6:1 ✔ |

### 字体（tkinter 用 pt；96dpi 下 1pt ≈ 1.33px）

| Token | pt | ≈px | 用途 |
|---|---|---|---|
| `font.caption` | 8 | 11 | chip、计数、快捷键提示（**取消现有 7pt≈9px**） |
| `font.body` | 9 | 12 | 卡片名、输入框 |
| `font.bodyStrong` | 10 | 13 | 分区标题 |
| `font.title` | 12 | 16 | 面板标题 |
| `font.mono` | Consolas 9 | 12 | 图像名、条件表达式 |

### 间距 / 圆角 / 动效

| Token | 值 | 说明 |
|---|---|---|
| `space.1` … `space.4` | 4 / 8 / 12 / 16 | 8px 基线；卡片内用 4/6，分区间用 16 |
| `radius.card` | 8 | 卡片 |
| `radius.chip` | 10（全圆角） | chip |
| `radius.control` | 4 | 输入框/按钮 |
| `motion.fast` | 150ms | hover / 选中（**只改颜色与描边，不动几何**） |
| `motion.skeleton` | 400ms × 3 次后静止 | 骨架呼吸，避免长期闪动 |

## 五、组件库（像素级规格）

### 5.1 SpriteCard（立绘卡） 100 × 176

| 区域 | 规格 |
|---|---|
| 容器 | `bg.card` + `border.default` 0.5px + `radius.card` 8；内边距 6 |
| 图区 | **固定 88×118**（`bg.skeleton` 占位，图到后覆盖；**尺寸不随内容变**） |
| 名字条 | 18px 高，`font.body` 12px，`text.primary`；说话态追加 `▶ 说话`（`brand.primary` + 加粗） |
| 徽标行 | 22px 高，chip 高 20，`font.caption` 11px，间距 4 |
| 右上角 ✕ | 16×16 视觉 / **20×20 命中**；`opacity` 默认 0、hover 显示；`state.error` 描边 |
| 状态 | 默认 / 悬停（`bg.card.hover` + `border.strong`） / **选中**（`brand.primary` 2px + 右上角 ✓） / 说话（名字条主色 + 卡片 2px 主色左边条） / 加载（骨架） / 缺图（`⚠ 缺图` 徽标，卡片仍可点选编辑） / 异常（`⚠ 同 tag 多条`） |

### 5.2 Chip（表情 / 位置）

| 项 | 规格 |
|---|---|
| 尺寸 | 高 20，内边距 8×4，`radius.chip` 全圆角 |
| 默认 | `bg.canvas` + `border.default` + `text.secondary` |
| 悬停 | 底 `#E3F2FD`（dark：`#1E3A5F`） |
| 选中 | `brand.primary` 1.5px 描边 + 底 `#E3F2FD` + **前缀 ✓**（不只靠颜色） |
| 缺图 | chip 尾追加 `⚠`（`state.warning`），tooltip 显示实际图像名 |
| 命中区 | ≥ 24px 高（chip 20 + 外边距 2×2） |

### 5.3 Skeleton（骨架）

图区同尺寸 `bg.skeleton` 块，中间一个 6px 圆点以 `motion.skeleton` 呼吸；
**最多 3 次后停在静态占位**（防干扰）。名字条与徽标**立即渲染真实内容**（不等图）。

### 5.4 EmptyState（空态）

网格位置显示虚线框卡片（100×176）＋ `＋ 添加立绘` ＋ 一行说明
「这一拍还没有立绘；背景/音乐会继承上一拍」。

### 5.5 Toolbar（顶部 / 底部）

- 顶部：高 40（固定，`pack_propagate(False)`），含翻页 + 计数 + 快捷键提示。
- 底部：高 40，只放低频动作（载入 / 导出 / 体检 / 演出预览）。
- 按钮高 28、最小宽 64、间距 8；主按钮 `brand.primary` 底 + `brand.onPrimary` 字。

### 5.6 Toast + Undo

底部条上方浮出，高 36，`bg.card` + 1px 描边；文字 + `撤销` 按钮；8 秒自动消失。

## 六、无障碍（落到组件）

### 键盘映射

| 操作 | 键 |
|---|---|
| 上一句 / 下一句 | `Alt+↑` / `Alt+↓`（或 `Enter`） |
| 立绘卡之间移动 | `Tab` / `Shift+Tab` |
| 选中卡内切换表情 | `←` `→`（chips 内循环） |
| 添加立绘 | `Ctrl+A`（在立绘区聚焦时） |
| 删除选中立绘 | `Delete` + **Toast 撤销** |
| 提交并下一句 | `Ctrl+Enter` |

### 焦点与命中

- **focus ring**：`brand.primary` 2px + offset 2px，所有可交互元素必须有。
- **命中区**：图标按钮 ≥ 20×20（视觉可 16×16），chip ≥ 24px 高，主按钮 28 高 / 64 宽。
- **不依赖颜色**：选中 = 描边 + ✓；说话 = 文字 `▶ 说话` + 左边条；错误 = ⚠ + 文字。
- **动效**：默认开启；提供「减少动效」开关时，骨架直接静态、hover 无过渡。
- **字号下限** 8pt（11px）；`#9E9E9E` 只用于图形，不承载文字。

## 七、量化验收

| 指标 | 当前 | v1 目标 | **v2 目标** |
|---|---|---|---|
| 3 个立绘的面板高度 | ~630px | ~140px | **176px**（1 行，不再滚动） |
| 一屏可见立绘数 | 1–2 | 4–5 | **4–5**（1080p） |
| 面板总高（1440×900 窗口） | 需滚动 | 需滚动 | **≤ 700px，第一屏不滚动** |
| 改第二张立绘的表情 | 滚到行 → 手填（2–3 次交互 + 可能改错入口） | 点卡 → 看编辑区 → 改 | **卡内点 chip：1 次** |
| 添加立绘 | 滚到底部点按钮 | 底部按钮 | **点网格末尾虚线卡：1 次（原地）** |
| 删除立绘 | ✕ 直接删，不可恢复 | ✕（16px，易误触） | **hover ✕ + 可撤销** |
| 打字卡顿 | 每次按键同步解码 | 防抖 + 异步 | 同 v1（**另加：骨架锁尺寸，不抖**） |
| 翻页可见性 | 最下沿，常被挡 | 顶部 | **顶部 + 首末禁用态** |

### 设计 QA 清单（交付前逐项过）

- [ ] 卡片骨架与成品**同尺寸**（图加载时面板高度不变）
- [ ] 表情 chip 与位置 chip **只在卡内**，面板级已无 `Expression`/`Position` 输入
- [ ] 删除后 Toast 有撤销，且撤销后顺序/顺序索引正确
- [ ] 缺图卡片仍可选中、可改表情、可删除
- [ ] 焦点环在每个可交互元素上都可见；Tab 顺序 = 视觉顺序
- [ ] 所有文字对比度 ≥ 4.5:1；`#9E9E9E` 与 `#0A5` 已从文字场景移除
- [ ] dark 模式下全部 token 生效（切换主题不需改组件）
- [ ] 真实项目 `sr_general`（2902 图）实测：连续输入不卡、逐句翻页不跳

## 八、与 v1 的关系

**沿用 v1**：A（防抖 + 线程 + LRU + 复用磁盘缓存 + `draft()`）、C（按 tag 聚合、不动数据契约）、D（翻页上移）。
**修订 v1**：① 消灭表情/位置双入口（**新增，最关键**）；② 卡片尺寸改为推导值并把 chips 放进卡内；
③ 骨架锁尺寸防抖；④ 删除 hover + 可撤销；⑤ token 体系化 + dark；⑥ 补空态/缺图态、键盘映射、focus 规格、量化验收。
