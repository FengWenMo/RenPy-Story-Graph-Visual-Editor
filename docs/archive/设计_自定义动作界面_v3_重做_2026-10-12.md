## 1. 问题（不是感觉，是量出来的）

用 `QT_QPA_PLATFORM=offscreen` 起真弹窗量出来的数（2026-10-12）：

| 量什么 | 实测值 | 说明 |
|---|---|---|
| 弹窗代码里写死的大小 | `resize(1100, 720)` | 屏幕小一点就装不下 |
| 弹窗**建议最小尺寸** | **806 × 994** | **高度 994 > 窗口 720** → 底部按钮当场被裁 |
| 窗口标志 | **不含** `WindowMaximizeButtonHint` | 标题栏**没有最大化按钮**，用户说"不能全屏" |
| 一张空参数卡的**最小宽** | **480 px** | 右栏只有 ~620 px，卡片一宽就顶破整窗 |
| 卡片里那个 6 列网格的最小宽 | 456 px | 132 固定标签 + 222 输入 + 108 标签 + 222 输入 + 2×28 按钮 |
| 参数卡列表最小宽 | 54 px | ← **它自己是好的**：坏在卡片内部 |
| 参数从 1 张加到 8 张 | 卡片最小宽**恒为 480** | **不是"数量"把窗口顶宽，是卡片内部** |

### 1.1 那"挤出去"的机制（一句话）

`ParamCard` 内部用**一个 6 列网格**摆字段，其中两个标签是
`setFixedWidth(132)`；`ChipEdit`（候选值）把方块摆在一个**横排 `QHBoxLayout`** 里，
方块越多、它的最小宽越大。这些最小宽顺着 `QScrollArea`（横向滚动被**明确关掉**）
一路上传成"卡片的 minSizeHint"，再上传成"弹窗的 minSizeHint"。
窗口不能被内容顶大时（屏幕到顶 / 用户没最大化），多出来的部分**只能被裁掉**——
于是"选的一多，后面那个变量就被挤出窗口外"。

⚠ 还有一条**同源**的连带伤：`_Card.field()` 把标签放 `row`、把提示放 `row + 1`，
而 `ParamCard` 自己又往 `row=1/2` 塞控件 —— **同一格叠两个控件**（2026-10-12 已修过
一次"输入框点不动"，病根就是这个网格）。

### 1.2 现状为什么"改不动"（判据绑住了坏结构）

- `test_no_two_widgets_share_a_grid_cell_in_a_param_card` 扫的是 `card.body` 这个
  **网格** → 想换布局必须先换容器（判据是"不叠格"，本质是"别把两个控件放进同一格"）；
- `params.horizontalScrollBarPolicy() == ScrollBarAlwaysOff` → 用户已经明确
  **不接受横向滚动**，这条不能靠"加横向滚动条"绕过。

**结论**：坏的不是"参数多"，是**卡片内部用网格横着摆**。要修的是卡片内部。

## 2. 研究：UI 设计要点（有来源）

> 抓取日期 2026-10-12。**每条只留能落到这个弹窗上的**，不抄泛泛而谈的话。

### 2.1 表单布局与结构

| # | 要点 | 本弹窗怎么落 | 来源 |
|---|---|---|---|
| R1 | **先问"为什么要问这一格"**：不需要的信息不要问（question protocol） | 每一格都必须能回答"它决定代码里的什么"；答不出来的格子不该出现在界面里 | [GOV.UK · Structuring forms](https://www.gov.uk/service-manual/design/form-structure) |
| R2 | **常见场景优先，高级设置延后** | 主路径 = 「动作名 + 中文名 + 要填的几格」；词组/给引擎自带写法加列 = 折叠的"高级" | 同上 |
| R3 | **一次只问一件事**（one thing per page），合并要**研究支持** | 弹窗不是向导，但**每一节只承担一个决定**：①要认识谁 ②叫什么 ③要填什么 ④对不对 | 同上 |
| R4 | 页面标题/区块标题**用一致的说法**（问句或陈述句，别混） | 全文统一"陈述句 + 例"，例：`这个动作要填什么` | 同上 |
| R5 | **避免多列表单**：多列会打乱填写顺序、造成漏填与错读 | 表单本体**单列**（标签在上、控件在下），不摆成 6 列网格 | [Baymard · Avoid multi-column forms](https://baymard.com/research-articles/avoid-multi-column-forms) |
| R6 | **提示文字（hint）只写一句、不加句号**；长解释不要塞进提示（读屏会整段念出来） | 每格的说明走 **tooltip**；界面上一句短提示 | [GOV.UK · Question pages](https://design-system.service.gov.uk/patterns/question-pages/) |
| R7 | **可选项要标出来**（写"(optional)"），**必填项不要打星号** | 本弹窗用反过来的说法：可留空的格写明"可留空" | 同上 |
| R8 | 一组相关字段用 **`fieldset` + `legend`** 成组 | 参数卡内部成组（"这一格是 / 剧本里怎么写 / 表格列名" 三件一起），卡与卡之间留更大间距 | [Scottish Government · Form structure](https://designsystem.gov.scot/guidance/forms/form-structure) |
| R9 | **标签与控件之间的间距要成体系**（同一份 spacing scale） | 全部走 `tokens.SPACE`（4/8/12/16），不写死像素 | [Scottish Government · Form spacing](https://designsystem.gov.scot/guidance/forms/form-spacing) |
| R10 | **"再加一个"是独立模式**（add another），要有条数上限与"改成/删掉"的回路 | 参数：`＋ 加一格` + 每格自带"删掉这一项" + `↑↓` 换序（已有） | [DWP · Add another thing](https://design-system.dwp.gov.uk/patterns/add-another-thing/how-it-works) |

### 2.2 渐进披露（progressive disclosure）

| # | 要点 | 本弹窗怎么落 | 来源 |
|---|---|---|---|
| R11 | **只在主路径需要时展示次要内容**，降低一次要看的量 | 候选值默认收起（勾"只能填这些"才展开）；词组默认收起（已有，保留） | [Progressive disclosure](https://www.uxpin.com/studio/blog/what-is-progressive-disclosure/) |
| R12 | 披露不能**藏掉关键状态**：收起的部分若有值，必须能看出来 | 收起时标题上写清"已有 N 个候选值"，不让人以为丢了 | 同上 |
| R13 | **分支问题只问相关的人** | 选"引擎自带"时换成下拉、并当场说清"这只影响工具、不覆盖引擎"（已有，保留） | [GOV.UK · Structuring forms](https://www.gov.uk/service-manual/design/form-structure) |

### 2.3 桌面弹窗与滚动（Windows / GNOME / Qt）

| # | 要点 | 本弹窗怎么落 | 来源 |
|---|---|---|---|
| R14 | 内容会长/会变的窗口**必须可缩放**；能缩放的窗口就该给**最大化** | 加 `WindowMaximizeButtonHint` + `WindowMinimizeButtonHint` + size grip | [GNOME HIG · Dialogs](https://developer.gnome.org/hig/patterns/containers/dialogs.html) |
| R15 | **窗口有最小尺寸，但最小尺寸要"能用"而不是"内容的全宽"** | 设 `setMinimumSize(720, 520)`；内容一律可滚、可折行 | [Microsoft · Wizards](https://learn.microsoft.com/en-us/windows/win32/uxguide/win-wizards)、[Qt · QDialog](https://doc.qt.io/qt-6/qdialog.html) |
| R16 | **不要"为了放下内容"把窗口撑到超过屏幕**；超出部分应当**滚动**，不是裁掉 | 所有长内容进 `QScrollArea`；滚动条**需要时才出现** | [Qt · QScrollArea](https://doc.qt.io/qt-6/qscrollarea.html) |
| R17 | 主按钮**位置稳定**（贴底右侧），不随内容滚动 | 底部动作条（写清单 / 取消）**固定**；只有中间内容滚 | [Microsoft · Dialog boxes](https://learn.microsoft.com/en-us/windows/win32/uxguide/win-dialog-box) |
| R18 | 动作按钮放在**动作将要发生的地方**；破坏性动作与确认动作分开 | `写进 storygraph.rules.json`（主）/`取消`（次）分开，主按钮在右 | 同上 |
| R19 | 默认按钮不要抢回车（**写盘**这种动作尤其） | 保留 `setAutoDefault(False)`（2026-10-12 已修） | [GNOME HIG · Dialogs](https://developer.gnome.org/hig/patterns/containers/dialogs.html) |

### 2.4 反面清单（"别这么干"，每条都对得上现状里的一个毛病）

| # | 别这么干 | 为什么（本弹窗的实证） |
|---|---|---|
| N1 | **别在一个窄栏里用 6 列网格摆表单** | 卡片最小宽 480 px，右栏 ~620 px，一宽就顶破整窗 |
| N2 | **别给表单标签设固定宽度** | 两个 132 px 固定标签就吃掉 264 px 可用宽 |
| N3 | **别让方块/标签横排无限长** | 候选值方块越多，"最小宽"越大 → 挤出窗口；必须**折行** |
| N4 | **别在关掉横向滚动的同时留下大的最小宽** | 关掉横向滚动 = 承诺"一定放得下"，那就必须让最小宽真的小 |
| N5 | **别用默认尺寸评判一个表单"放得下"** | 现状默认 1100×720 看着正常，最小尺寸其实是 806×994 |
| N6 | **别把窗口最大尺寸写死**（或忘了给最大化标志） | 用户要全屏却按不动最大化 |
| N7 | **别把关键提示塞进 tooltip 才说** | "这格是干什么的"要在卡里看得见；tooltip 只补充 |
| N8 | **别让同一格叠两个控件** | 2026-10-12 实测："输入框点不动"就是叠格 |

## 3. 体验设计（谁在用、怎么用、卡在哪）

### 3.1 两个用户、两条路（不混在一屏里让人猜）

| 用户 | 他要完成的事 | 他要看到 | 他不该看到 |
|---|---|---|---|
| **编剧** | "这个动作我要能点着用" | 「泳装切换」这样的中文名、每一格"填什么/例子" | `attr_groups` / `rules.json` / 位置序列 / T1 |
| **程序/技术策划** | "一次定义、全项目复用、可评审" | 动作名（`swim_suit`）、要填的格子、能写/能改/能删 | 长段解释挡路 |

### 3.2 主路径（4 步，一屏走完，不需要来回找）

```
① 要认识哪个动作   →  ② 它叫什么（中文名）  →  ③ 它要填什么  →  ④ 这样写对吗（当场看）
       ↑ 从项目里发现              ↑ 主字段           ↑ 一格一张卡        ↑ 粘一行真剧本
```

### 3.3 卡点（按"用户在哪一步会停住"排）

| 卡点 | 现状 | v3 怎么解 |
|---|---|---|
| 不知道该填 `show` 还是 `swim_suit` | "发现"列表 + 手动入口 | 保留发现列表；顶端一句话说清"内置的不用声明" |
| 不知道这一格是"变量"还是"固定字" | 下拉（已有） | 保留，但**默认档位**由真实用法反推（已有 `suggest_shape`） |
| 参数一多，格子被挤出窗口 | 6 列网格 + 不折行的方块 | **单列堆叠 + 方块折行 + 内容可滚** |
| 不知道自己写对没有 | 「试切」要手动点 | **实时**：粘一行/改一格，结果区立刻更新；「试切」按钮保留（明示动作） |
| 想要全屏看更多 | 没最大化按钮 | 给最大化 + size grip + 可拖动分隔条 |
| 候选值太多（真实项目：几十个表情） | 一个个敲回车 | 「⚡ 导入候选」白拿（已有，保留） |

## 4. 设计原则（这一版拿它当裁判）

1. **P1 最小宽要真的小**：任何一个控件的"最小宽"都不许超过 ~120 px（除非它是整行控件）。
   → 窗口能缩到 760 px 且不裁任何字、不出现横向滚动条。
2. **P2 会变长的东西必须能折行**：方块、标签、长文本一律折行/换行，**绝不横着无限长**。
3. **P3 一屏一次只做一个决定**：区块之间用标题+间距分开，高级东西收起。
4. **P4 主按钮永远看得见**：动作条贴底固定，内容自己滚。
5. **P5 能不滚就不滚**：默认尺寸下，主路径四步**一屏看完**；滚只发生在"很多格子/很多候选"时。
6. **P6 看得见的必须是真的**：预览/试切/毛病提示都由后端纯函数算，前端只显示。
7. **P7 不许有"点了没反应"**：能点就必须有效果；不能点就灰化 + 说清原因（已有契约）。
8. **P8 说法是人话**：界面不出现实现者词汇（已有契约，继续）。

### 5.1 与 v2 的逐条差异（每条对应一个实测缺陷）

| # | v2 | v3 | 治哪个病 |
|---|---|---|---|
| D1 | 卡片内部 **6 列网格**（两个 132 px 固定标签） | **单列堆叠**：标签在上、控件在下 | 卡片最小宽 480 → 188 px；"挤出窗口" |
| D2 | 候选值方块 **横排不折行** | `FlowLayout` **折行** | 方块再多也不顶宽 |
| D3 | 右栏滚动区**关掉横向滚动** | 改成 `AsNeeded`（放得下就不出现）+ 把最小宽真的做小 | 万一还有宽东西，能拉而不是被裁 |
| D4 | 写死 `resize(1100, 720)` | 初始大小**按屏幕可用区**算（960×660 起） | 小屏被裁 |
| D5 | 没有最大化按钮 | 加 `WindowMinMaxButtonsHint` + size grip | 用户："你这个窗口还不能全屏" |
| D6 | 词组框**标题**写一长串（466 px） | 标题只留短名，长解释放进框内折行标签 | 标题把整块顶宽 → 横向滚动条 |
| D7 | 预览吃掉左栏，发现列表被压成一条缝 | 预览**可收起 + 高度封顶**；发现/已声明按 3:2 分 | 一屏看不完主路径 |
| D8 | 参数区标题 + 两按钮横排 | 折行（`_FlowRow`） | 窄栏被顶宽 |
| D9 | 按钮条在 `root` 最后一项（会随内容滚） | 保持贴底（结构上本来就在滚动区外），并**加判据钉住** | 滚下去点不到主按钮 |

## 6. 组件规格

### 6.1 `FlowLayout` / `_FlowRow`（`ui_qt/param_cards.py`）

| 项 | 规格 |
|---|---|
| 语义 | 横排、**按可用宽折行**；宽度有上限（官方 Flow Layout 同款） |
| `minimumSize` | 宽 = **最宽那一项的下限**（不是所有项之和） |
| `heightForWidth` | ✅ 支持（父布局据此分配高度） |
| `_FlowRow.minimumSizeHint/sizeHint` | 都返回"各子控件下限的最大值" —— ⚠ 这是关键：早期版本返回 `QLayout.minimumSize()`（含 `sizeHint` 的宽），把右栏顶到 466 px |
| `add(widget)` | 加入一项（返回 widget，方便链式） |

### 6.2 `_Card` / `ParamCard`（单列堆叠）

| 项 | 规格 |
|---|---|
| 卡身 | `QVBoxLayout`（**不是**网格）；`body` 名字保留（判据/调用方不改） |
| 每块 | 标签（`wordWrap=True`，在上）→ 控件（`Expanding/Fixed`，在下）→ 可选提示 |
| 卡头 | 标题（可换行）+ `⚡ 导入候选` + `↑ ↓` + `删掉这一项` |
| 字段顺序 | ① 这一格是 ② 剧本里怎么写 ③ 表格列显示什么（可留空）④ ☐ 只能填这些 ⑤ 方块 |
| 最小宽 | ≤ 320 px（空卡 188 px；**16 个方块时仍是 188 px** —— 判据钉"不随数量增长"） |

### 6.3 `ChipEdit`（候选值）

| 项 | 规格 |
|---|---|
| 输入 | 敲回车 / 逗号 → 变方块；**一次收下所有**（与后端 `parse_choices` 同一套分隔符） |
| 摆放 | 折行（`FlowLayout`）；每个方块 `QSizePolicy.Maximum` |
| 回车 | **绝不冒到 QDialog**（否则会点掉默认按钮 → 顺着 `exec()==Accepted` 写盘） |
| 对外 | `text()` 逗号串 / `set_text()` / `add_values()`（导入用，追加不覆盖） |

### 6.4 弹窗壳（`dialog_learn.CustomStatementDialog`）

| 项 | 规格 |
|---|---|
| 窗口标志 | `WindowMinMaxButtonsHint | WindowSystemMenuHint`（**最大化按钮**）+ size grip |

## 9. 实施记录（做完了什么、以及落地时才发现的两条）

落地顺序：`FlowLayout`/`_FlowRow` → `_Card`/`ParamCard`/`GroupCard` 单列化 →
`ChipEdit` 折行 → 弹窗壳（标志/尺寸/滚动/左栏配比）→ 判据 → 渲染看图。

**落地时才发现的坑（都写进代码注释了）**

1. **`QLayout.minimumSize()` 不是"折行后的下限"**：它取"最宽那一项的
   `sizeHint` 宽"。第一版拿它当 `_FlowRow.minimumSizeHint()`，于是
   `[标题][输入框][按钮]` 那一行报 240 px，配上一长串 `QGroupBox` 标题
   （466 px）把右栏顶出横向滚动条。修法：`_FlowRow` 自己算"各子控件**下限**的最大值"。
2. **`QGroupBox` 的标题不折行、会顶宽整块**：标题写
   `词组（可选 · 高级）—— 把立绘候选分成"服装 / 表情"这样的栏` 时，
   整块最小宽 466 px（空标题只要 60 px）。修法：标题只留短名，
   长解释放进框内 `QLabel`（它折行）。

**没做的（诚实记录）**

- 两栏仍是 `QSplitter` 而不是"窄屏自动变上下"：实测窄到 760 px 时两栏各 364 px、
  **都没有横向滚动条**（V4 已证明内容能缩），所以没加自动折叠 ——
  少一条会自己失效的响应式逻辑。若以后真要，可在 `resizeEvent` 里切
  `QSplitter` 方向（判据已给好"窄屏不横向滚"这个不变量）。
- 界面文案仍是`语句名 / 中文名 / 参数 / 候选值`这一套：本节只做**布局与可达性**重做，
  说法的人话化（v2 文档 §五的对照表）留给下一轮 —— 那是一次**全文案替换**，
  与布局改动混在一起会看不清是哪个改坏的。

## 10. 用户第二轮追问挖出的两个真 bug（2026-10-12 当晚修掉）

用户问了两句，两句都问出了真问题：

> ① "这个所谓的'词组'到底有什么用？如果你所谓的'词组'只是给变量一个名字的话……

### 10.1 「词组」到底是什么（①的答案 + 改动）

| 它**不是** | 它**是** |
|---|---|
| 不是"给变量起个名字"（名字在「剧本里怎么写」那一格） | **把一格的可填值按"类"分组**（服装 / 表情 / 姿势）——下拉里分栏显示 |
| 不是必须填的 | **可选**：不填 = 完全平铺（通用性底线） |
| 不是分组结构的来源 | **只是改名层**：结构来自引擎的 `layeredimage` group |

**改动（照用户说的做）**：把"这一格挂哪个词组"的**下拉撤掉**，改成**卡头原地标注**：

```
┌ 参数：outfit（表格里叫「服装」）        分组：outfit   ↑ ↓  删掉这一项 ┐
│ 这一格是            [ 从这些里选 ▾ ]                                  │
│ 剧本里怎么写        [ outfit        ]                                 │
│ 表格那一列显示什么  [ 服装          ]                                 │
└──────────────────────────────────────────────────────────────────────┘
```

- **自动认**：这一格的名字 / 中文列名，对上词组名或它声明的候选值 → 标上（`_match_group`）；
- **认不出就不显示**（不写"无"、不占地方）—— 大多数项目没有"服装"这个词组；
- 词组表一变（增/删/改名）→ 标注**自动跟着变**（回调 `set_groups_changed`）。

### 10.2 卡牌编辑器"完全反应出来"了吗（②的答案 + 修的真 bug）

**修之前：没有。** 端到端实测（临时项目 + 真主窗口）：

声明了 `swim_suit`（三格：角色 / 服装 / 神态）之后，这一行

```renpy
swim_suit lyj "泳装" mood=happy
```

在卡片编辑器里长这样：**`角色` 空、`服装` 空**、`神态`=happy ——
候选下拉是对的，但**值一个都没读出来**。

根因两处（都是"实现了但没接线"的老毛病）：

1. `pattern`（有序格子）**只存在磁盘上**，没进 `RegisteredStatement` ——
   于是"这一格 = 第几个位置参数"这件事在读取侧完全丢失；
2. `spec_columns` 里的 `positional` **只在显式写了才有**，没人按格子顺序补。

**修之后（同一套端到端实测）**：

```
读数：  角色=lyj   服装=泳装   神态=happy          ← 三格全对
改一格：服装 → 校服，保存
内存：  swim_suit lyj 校服 mood=happy
渲染：      swim_suit lyj 校服 mood=happy          ← 写回 .rpy 的那一行也变了
```

**判据**（`tests/test_custom_statement_entry.py` ⑧ 节，4 条）：
位置参数进各自的格子 / 改一格折回头行 / 改 `key=value` 不碰位置参数 /
词组声明能传到参数卡（含"改名后不再乱标"）。

⚠ 顺带说明**为什么 Excel 那侧本来就"对"**：Excel 走的是 `columns[].positional`
（项目手写的表里有这一列），而卡片走的是**声明**（弹窗只写 `pattern`）——
两条路读的是同一份 `Beat.spec_arg_cells`，缺的是"声明 → 位置号"这一步。
现在两边同源了。

### 12.1 bug A：中文列名被丢掉 → 声明里一列都没有 → 永远切不上

- **真因**：`learn_statement.build_declaration` 里，`pattern` 那一段的注释明明写着
  "**列名不套脚本参数那套标识符校验**……中文（「角色」「服装」）天经地义"，
  可 `params` 那一段**还在套** —— 于是「人物/服装/表情」被整条丢掉，
  试切时等于"没有任何格子"。**"注释对了、代码没跟上"的典型**。
- **修**：列名只做两件事 —— **去重**、**剥掉顺手写的 `=`**；不再套标识符规则。
- **判据改写**（重要）：旧判据 `test_build_declaration_reports_bad_parameter_names`
  **把 bug 钉成了"正确行为"**（它断言中文列名必须被丢掉），所以它本身是错的，
  改成 `test_build_declaration_accepts_chinese_column_names`。
  ⚠ 教训：**判据写错时它会替 bug 站岗** —— 出现"用户看到的和判据说的一样矛盾"时，
  先去读那条判据，别先怀疑用户。

### 12.2 bug B：粘一整行必然"多一个词"

- **真因**：格子里描述的是"**动作名后面**的东西"，而人从剧本里复制的一定是**整行**
  （`show lan swim_suit happy`）—— 头部那个动作名不在格子里，于是
  "多出来 1 个词 → 切不上"，而界面只会说"检查顺序、关键字写法"。
- **修**：试切时**行首整词等于动作名就摘掉它**（绝不猜别的）；只粘参数也照旧能切；
  只粘动作名时明说"后面还没写东西，先把那一行粘全"。
- **失败提示改具体**：不再是万能句，而是
  "这些词没人认领：extra1、extra2" / "这些格子没吃到东西：第 2 格"，
  再把 `match_line` 自己的 `reason`（例如"第 2 格要的关键字是 `at`"）接在后面。
- **判据**：`test_cut_accepts_a_whole_line_pasted_from_the_script`（三种粘法：整行 / 只参数 / 只动作名）。

### 12.3 bug C：卡片上"三格只对一格"（同一晚继续挖出来的）

修完 A/B 之后，**卡片编辑器**里仍然只对一格：

```
show lan swim_suit happy
[人物=谁都可以] [swim_suit=固定几个字] [happy=从这些里选]

期望：人物=lan   swim_suit=swim_suit   happy=happy
实测：人物=lan   swim_suit=（空）      happy=swim_suit     ← 串位
```

挖下去是**四个**独立缺陷叠在一起（全都在"读了却没用上"这一类）：

| # | 缺陷 | 后果 |
|---|---|---|
| C1 | `parse_dynamic_full` 用 `[A-Za-z_]\w*` 卡两段 | `show·人物@0` 这种中文列名**认不出** → 那几格永远空（与 A 同一个病根） |
| C2 | 位置号按"只数可填格"发 | 关键字格**吃词却不占号** → 后面的格子整体错位 |
| C3 | 列描述里**不带 `pattern`** | 读值那一侧想"按格子认领词"也拿不到格子 |
| C4 | 摘掉动作名后仍让 `positional_tokens` 跳"第一个词" | 整排再左移一格 |
| C5 | 按位置号替换 → 把 `mood=happy` 当成位置参数追加 | 折回时变成 `… mood=happy shy` |

**修法（一条条对应）**：
C1 → 左边那段必须是 ASCII 标识符（语句名是代码里的写法），**右边那段允许中文**；
C2 → 位置号改成"**与读值同一套走法**"数出来（`WALK_KINDS`，关键字格也占号）；
C3 → `dynamic_spec_columns` 把声明的 `pattern` 一起带出去；
C4 → `positional_values(..., skip_head=False)`（摘过了就别再跳）；
C5 → 折回时先看这一行有没有 `param=`，有就按**具名参数**写回。

⚠ **这一节最值得记的**：`test_build_declaration_reports_bad_parameter_names` 那条判据
当初**把 bug 钉成了正确行为**。判据写错时，它会替 bug 站岗 ——
所以"用户看到的"与"判据说的一样矛盾"时，先怀疑判据。
