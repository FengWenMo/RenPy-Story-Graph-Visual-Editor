## 一、复查：三项功能按真实路径走了一遍

都**不靠截图**：用会话 / 窗口的返回值与磁盘上的字节判断。探针放在
`.ftr/probe_*.py`（临时文件，不提交）。

| 复查项 | 怎么走 | 结论 |
|---|---|---|
| 块首插入 → 原地补丁导出 → 重新解析 | `if` 块首 / `while` 体首 / 顶层首，三种各导一次，再把磁盘那份读回来 | 新行逐字节落在块里；`python:` 块的 `code_blocks` 边界没被挤乱（`[(2, 3)]` 仍指着 `a=1/b=2`） |
| 块首插入 × 2（同一拍） | 一次收齐再插 | 顺序 = 输入顺序 |
| 关窗：真·模态对话框 | 用 `QTimer` 找到 `QMessageBox`、点真实按钮（不是 monkeypatch 返回值） | 「取消」窗口不关、文件不动；「保存并退出」写回原文件、状态栏转「已同步」；「不保存」一个字节不写 |
| 翻页不改写「未导出」 | 改一拍 → 翻页 → 再看状态栏 | 仍是「● 未导出」 |
| 折叠：按文件记住 | 折 `side_b` → 关窗 → 重开；同名 label 另一份 `.rpy` | 折的仍是 `side_b`，另一份不受影响 |
| 折叠：进折着的组 | 导航进 `side_b` → 关窗重开 | 记成"开着"（与关窗那一刻看到的画面一致） |
| 「未导出」判据 vs 面板字段 | 对 13 拍逐页翻、每页都 `apply_current_beat()` | 没有一拍被误判成"表单改了"（`is_modified` 全 False），状态栏不喊 |

> **顺带纠正一个测试夹具**：上一阶段用 `for i in range(2):` 当"循环块"。
> Ren'Py 8.4.1 的引擎 lint 对 **label 顶层的 `for`** 报
> `expected statement`（第 8 行），也就是说那份夹具**引擎根本读不了**。
> 产品对 `for` / `while` 的形状识别是同一条路（`loop_header` + 循环体在下一拍），
> 所以这不影响功能结论；但**新用例一律只用 `if` / `while`**，
> 免得把"引擎读不了的写法"当成验收对象。

复查**没有发现**这三项本身的功能 bug。抓到的那个在下一步。

## 二、假撤销：图退了，拍没退（本轮修的 bug）

### 2.1 现场

变量工作台里加一条 → `Ctrl+Z`：**看起来撤销了**，然后导出，产物里那条还在。

```text
加一条（块首，插进 if）：  beat.code = 'mark = 1\nroute = "roof"\nflag = True'
Ctrl+Z 之后：
   图节点 operations = ['love += 1', 'route = "roof"', 'flag = True']   ← 退了
   beat.code         = 'mark = 1\nroute = "roof"\nflag = True'          ← 没退
   compile() 里还有  = True
```

这是**最坏的一类**：界面说"撤了"，落盘时却照写。用户不会再去核对产物。

### 2.2 为什么会这样

变量工作台 / 变量框的改动是**一份改动、两个去处**：

- 图节点（`node.statements`，`set_node_variables`）；
- 章节的拍（`session.beats[].code`，导出读的是这一份）。

而图级撤销 `UpdateNodeOperationsCommand` 从 2026-10-05 起只认第一个：
`undo()` 把 `node.statements` 换回快照、`on_graph_content_changed()` 刷界面，**拍一动不动**。
两个栈（图历史 / 逐拍内容撤销）各管一半，谁也不知道对方。

### 2.3 怎么修的

不改"两份存储"这件事（图是投影、拍是真源，这条没错），
只让**执行这条改动的命令把两边一起搬**：

1. `EditorSession.apply_node_variable_edits()` 在动手**之前**给每一拍拍快照
   （`remember(beat)`，同一拍只记最早那份），返回
   `{'beats': [...], 'beat_snapshots': {拍号: 快照}}`；
2. 命令多一个可选参数 `beat_states={'session', 'before', 'after', 'refresh'}`：
   - `undo()` → 还原节点 + `session.restore(before 每一拍)` + 重算脏标记 + 刷卡片页；
   - `execute()`（重做那条路）→ 还原节点 + `session.restore(after 每一拍)`；
3. `after` 在**改动生效之后**现拍，两边对称；`refresh` 是"卡片页列表跟上"的回调
   （`adopt_loaded_session`，它不从磁盘重读）。

为什么用**逐拍快照**而不是整份 `beats` 深拷贝：拍对象保持同一个身份，
`ChapterDocument` 的树、卡片页的"行 ↔ 拍"映射都还指得对；深拷贝整份等于换了一批对象，
这些引用会全部指到旧拍上（那种 bug 很难看出来）。

修完之后同一串操作：

```text
Ctrl+Z：图节点、拍、窗口标题栏的「未导出」、导出产物 —— 四样一起退
Ctrl+Y：四样一起回来
```

### 2.4 旧快照不许按拍号硬还原

**原地导出**会把内存重新解析一遍（只有注释的卡会并进后面那张，拍数 / 粒度变），
而图历史里的命令还带着"上一份文件"的拍号快照。按拍号直接还原会**写到别人的拍上**。
所以还原前先对一下"现在的样子"是不是另一头（撤销前应等于 `after`、重做前应等于
`before`）：

- 对得上 → 还原；
- 对不上 → **跳过那一拍**，并在诊断台账里留一行
  （`第 N 拍已经变了，跳过还原`）。

宁可少退一拍，也不能改错拍。用例
`test_undo_after_a_reload_does_not_stamp_onto_other_beats` 钉这条。

### 2.5 顺手：撤销到"与磁盘一致"时不再喊未导出

`_restore_beats` 末尾调 `session.refresh_edits_flag()`（全章重算，只在点击频率上跑），
所以"加了又撤"之后状态栏回到「✔ 已同步」，关窗也不会再问 ——
与第六阶段那条"翻页不算改动"同一套判据。

## 三、块选择器：插到**指定的块**

### 3.1 上一阶段留下的口子

第六阶段的「块首」跟着**选中的那条**走。想往另一个 `if` 的块首插，
得先在下面那串操作里找到那个块里的某条赋值、点它 —— 用户报告原话：

> 现在"块首"跟着选中的那条走；想往另一个 `if` / `for` 的块首插（连选都没选），
> 得先在列表里点那条。

### 3.2 数据：这一章有哪些块

`variable_workbench()` 多返回一项 `blocks`：

```python
{'text': 'if love > 3:', 'beat': 1, 'anchor': 1, 'indent': 8, 'kind': 'if'}
{'text': 'while love < 9:', 'beat': 2, 'anchor': 3, 'indent': 4, 'kind': 'loop'}
```

- 只从**拍**里取块头（`Beat.condition` / `Beat.loop_header`），不重扫源码；
  `source_lines` 只填缩进（给人看层级）；
- 拍号是**文件内绝对下标**，与 `variables[].operations[].beat_index` 同一口径；
- **`anchor` 不一定等于 `beat`**：循环头自己占一拍、块体在下一拍
  （`while x:` 那拍 `code` 是空的），行写进头拍会落在循环**外面** ——
  与 `anchor_of` 的"循环头往后挪一拍"同一条判据；
- 只看本 label 的拍（`label plain` 的块不会混进来）。

### 3.3 界面：一个下拉，三项老 + 每块两项

「新增放在」保持原来三项不变，分隔线下面按块列：

```text
选中这条之后（同一块内）
块首（选中这条的块最前面）
本章末尾（顶层）
──────────────
块首：if love > 3:（第 2 拍）
块尾：if love > 3:（第 2 拍）
块首：while love < 9:（第 4 拍）
块尾：while love < 9:（第 4 拍）
```

- 拍号写的是**落点拍**（循环块 = 循环体那一拍），与右边那句
  "会插进第 4 拍的「while love < 9:」块最后面"**同一口径** ——
  两处写两个拍号只会让人以为插错了地方；
- 选块之后**不需要选中任何操作**，`_anchor_for_new()` 直接给
  `(anchor, 'head')` 或 `anchor`；
- 新操作的列表行照旧标「第几拍 · 在 …」/「· 块首」，`anchors` 形态没变
  （`-1` / 拍号 / `(拍号, 'head')`），所以 `apply_node_variable_edits`
  一行都不用改；
- 没有块的章节（只有台词的 label）：下拉仍是原来三项，不出现空的分隔线。

> 一个细节：源码里嵌套的 `if` 在拍模型里是**合并条件**
> （`if flag:` 套在 `if love > 3:` 里 → `if (love > 3) and (flag):`）。
> 块清单照实显示合并后的条件 —— 那不是块的错，是导出时真会写成的那一行。

## 五、仍然不做（写明，不藏）

- **折叠状态仍不跟项目走**：它是"这台机器上这个文件"的偏好（第六阶段的选择），
  这轮没改 —— 要跟项目走得先决定它进不进 `layout.json`，那是另一个决定。
  > **当天更晚已做**：见 [体验优化第八阶段](体验优化_第八阶段_2026-10-22.md)——
  > 进的是项目根 `storygraph.session.json` 的 `cards` 段（不是 `layout.json`），
  > 键是项目内相对路径。
- **关窗仍没有"先撤销再关"**：只有保存 / 不保存 / 取消。
  复查后仍认为不必加：撤销是"逐拍内容"与"图操作"两条栈，
  在关窗那一刻替用户挑一条来撤，比"不保存"更难解释。
- **块选择器只列 `if` / `elif` / `else` / `while`**：不列 `for`
  （Ren'Py 脚本层没有 `for`，引擎 lint 会拒）；也不重排块结构
  （改条件、换分支、把顶层语句拖进块仍走文本区 / 源文件）。
- **撤销仍是两条栈、按页分工**：结构页 Ctrl+Z 走图历史，卡片页 Ctrl+Z 撤这一拍；
  这轮只保证"同一份改动不会只退一半"，没有合成一条全局栈
  （合成会把"我在卡片里撤一句台词"也变成"撤掉刚才图上的删除"）。
- **变量工作台的新增操作用 `$` 行**：它只写 `name = …` / `name += …` 这种语句，
  不生成 `if` / `while` 块（要加块请用文本区或控制流卡）。
