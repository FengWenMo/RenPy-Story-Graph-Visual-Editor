# 引擎行为探针：契约的"获取"与"验证"是两个轴
### —— 两份反驳之后的更精细方案（附本轮**实测**，不是纸上推演）

> 2026-10-10 ｜ 承接：`docs/设计_契约前提的复核与修正_2026-10-10.md`
> 触发：用户提出两份反驳（CSV 视角），核心一句是：
> > "工具不应该问引擎'你支持什么'，而应该问引擎'**这个具体写法你接受吗**'，

## 一、先看实测（这一节是全文的地基）

### 实验设置

- 引擎：`D:\software\renpy-8.4.1-sdk`（实际为 **8.5.3**）
- 项目：新建的最小探针工程，`layeredimage` 写法**照抄真机 `sr_general/definitions.rpy`**（`group outfit:` / `attribute clothes2:`）
- 命令：`SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy python.exe renpy.py <basedir> lint --error-code`
- **全程在临时目录，没碰你的项目一个字节**

### 实测结果

| # | 问题 | 实测答案 |
|---|---|---|
| 1 | `lint` 能无头跑吗？ | ✅ **能**。`SDL_VIDEODRIVER=dummy` 下直接跑通，退出码 0 |
| 2 | `lint` 期间 `init` 会跑吗？ | ✅ **会**。我在 `init 999 python:` 里写了一个 dump，**lint 之后文件真的出现了** |
| 3 | 运行期 API 能用吗？ | ✅ `renpy.list_images()` → `["black","lan","text","vtext"]`；`get_available_image_tags()` 同上 |
| 4 | **能读到属性分组吗？** | ✅ **能**。`get_registered_image("lan").attributes` → `expressions: happy, sad` / **`outfit: clothes2, base_swimsuit`** —— **分组名和全部属性，从引擎直读，零人工输入** |
| 5 | 能读到"合法候选"吗？ | ✅ `get_ordered_image_attributes("lan", ("happy",))` → `["base_swimsuit","clothes2","happy"]` |
| 6 | **未知语句会被拒吗？** | ✅ **会**。`weather 雨 0.5` → `line 4: expected statement.`，**退出码 1** |
| 7 | **非法属性会被拒吗？** | ❌ **不会！** `show lan 完全不存在` —— **lint 一声不吭**（只报了 weather 那行） |
| 8 | **`has_image()` 能当裁判吗？** | ❌ **不能（重要陷阱）**。`renpy.has_image("lan 完全不存在 happy")` → **返回 `True`** |
| 9 | `--json-dump` 好用吗？ | ⚠️ **存在但这次没给到我们要的东西**。文件出来了，且**必须脚本无语法错**（有错时 `location` 全空）；这次 `label/define/screen/transform` **全是 `{}`** → **它的价值必须先在真机上验证，不许假设** |

### 由实测得出的**三档 oracle 分工**（这是本轮最硬的结论）

| 要问什么 | 谁来答 | 证据 |
|---|---|---|
| **这个语句/语法成立吗？** | **`lint`** | 实测 #6：`weather` 被拒、退出码 1 |
| **这个属性/tag 合法吗？** | **引擎枚举出的集合**（自己比对集合成员） | 实测 #4#5：枚举可靠；实测 #7#8：`lint` 与 `has_image` **都会放行**，所以只能用集合比对 |
| **这个组合兼容吗？** | `get_ordered_image_attributes(tag, 已选)` | 实测 #5 |

> ⚠ **实测 #8 是本轮最值钱的一条**：`has_image()` 对**根本不存在的属性组合也返回 `True`**。
> 如果照我上一轮的写法把它当"成员测试=裁判"，**工具会认为一切都合法** ——
> 这正是本项目文化里反复出现的"看起来对、其实静默错了"。
> **必须写进契约：`has_image` 不是合法性判据。**

## 二、两份反驳：哪些全盘接受，哪些需要更正

### 2.1 全盘接受（我原文确实有这些洞）

| 反驳 | 接受 |
|---|---|
| 缓存新鲜度会变成新的漂移源 | ✅ 对。我上一轮说"diff 出来就是漂移报告"太快了 —— 它要求 CI 配置正确。**修法见 §四。** |
| 第③级"引擎补丁即契约"在你们项目不存在 | ✅ 对。`sr_general` 无 `renpy/`。**且即使 fork，diff 的产物是代码变更、不是语法声明** —— 我原文写得过于轻巧。**第③级应从"契约来源"降级为"该重测什么的路标"。** |
| CDS"扫到"≠"生效"（加载顺序约束） | ✅ 对。官方明确：必须 `python early`、定义文件必须**先于**使用它的文件加载、且**不能在同文件使用**。**CDS 从"契约"降级为"候选"。** |
| 引擎 API 的返回形状可能被魔改 | ✅ 对。**修法见 §五。** |
| `lint` 查不了自定义语句的**语义** | ✅ 对，且我实测到了更狠的一条：**`lint` 连属性合法性都不查**（实测 #7）。 |
| headless 可能不顺利 | ⚠️ **一半对**。实测 #1#2：**lint 无头跑通了，且 init 会执行** → "运行期 API 拿不到"这个担心**被实测推翻**。但"程序若魔改了加载顺序，探针可能读不全"仍成立 —— 而**那正是探针要报的东西**。 |

### 2.2 需要更正（这两条反驳也低估了现实）

**更正一：反驳说"行为探测需要大量工程、覆盖有限、不如 CDS" —— 实测显示 Ren'Py 已经交付了现成入口。**

- **语句接受/拒绝**：`lint --error-code` 一条命令、无头、退出码可判 → **已经是一个可用的 MAT（membership oracle）**，不需要我们发明。
- **属性词汇/分组/兼容候选**：`get_registered_image().attributes` + `get_ordered_image_attributes()` → **零人工输入**。
- **行为回归**：Ren'Py 有**官方自动化测试框架**（`testsuite` / `testcase` 语句 + `renpy.sh <proj> test`，含 `assert`、`renpy.is_in_test()`）。→ **"行为测试套件"不用写框架，用引擎自己的测试语句写。** 跑的是**真引擎** → 天然免疫"源码不在 git / 没用 CDS / API 形状变了"。
- 工程界已有完全同构的成品：**Netzob 就是拿真协议实现当 oracle 跑 Angluin L\***（并带 `MQCache` 缓存查询）。学术上 `L*`（Angluin 1987，MAT = membership query + equivalence query）是这一整套的正式名字，且**已被证明多项式时间**。

**更正二：反驳说"没有裁判 API，所以推不出参数形状" —— 这句话不成立。**

裁判**不需要是 API，只需要是"一次运行"**。而"变异 + 引擎接受/拒绝"**同时产生了负样本和裁判**：
给 `weather` 试 0/1/2/3 个参数、试命名参数、试带块 —— **接受/拒绝的图案**就是参数形状。
（实测 #6 证明这条回路是通的：引擎真的会拒。）

### 2.3 但两份反驳合起来指出的**真正缺口**，我接受

> **我上一轮的"四级阶梯"漏掉了一整类东西：它只列了"候选从哪来"，没列"凭什么信"。**

这是本轮真正要改的地方 —— 见下一节。

## 三、修正后的模型：两个轴 + 一个原语

**"阶梯"这个隐喻是错的** —— 它暗示线性降级，但"获取"和"验证"是**正交的两根轴**。

```
轴一 获取（候选从哪来）
  ① 引擎原生可枚举（图片/属性/tag/变换/角色/标签）
  ② 宿主注册（CDS）
  ③ 引擎补丁 / 就近声明
  ④ 历史用法归纳
  ⑤ 人手写
              ×
轴二 验证（凭什么信）
  ⓐ 无（只用一次，不作数）
  ⓑ 枚举集合比对
  ⓒ lint 判定（语句级）
  ⓓ 行为测试（testcase / 变异探测）
  ⓔ 人确认

原语：**membership query —— "这个写法，引擎接受吗？"**
```

**三条铁律**（补上两份反驳共同指出的那一段）：

1. **任何"获取"到的候选，没经过"验证"之前，只能显示为「未验证」，不许当真值用。**
2. **能验证就验证**：语句级一律过 `lint`；属性级一律过**枚举集合比对**（⚠ 不是 `has_image`）。
3. **验证失败 = 报错，不是"换一个"**（落在既有"要么全对要么完全不动"上）。

## 四、新鲜度：把刷新挂在**必经路径**上（解反驳一的缓存漂移）

反驳一说：缓存会过期，重跑又可能很贵。这里有一个干净的解法：

> **不要把 dump 做成一个独立的、可选步骤 —— 把它做成 `lint` 的副产品。**

理由（实测支撑）：`lint` **本来就要跑**（项目已有的校验路径），而且**实测证明 init 会在 lint 期间执行**（#2）。
所以：

| 做法 | 结果 |
|---|---|
| ❌ 独立 dump 脚本 + 单独 CI 步骤 | 会忘、会漏触发条件 → 反驳一说的漂移 |
| ✅ **把 dump 挂在 lint 同一次运行里** | **忘不掉** —— 要校验就必须跑它，跑它就顺带刷新 |

**新鲜度策略（三层，递进）**：
1. **先比指纹**（毫秒级）：引擎版本 + 参与定义的文件哈希（`game/**.rpy` + 相关 `images/`）。一致 → 直接用缓存。
2. 不一致 → **标注「候选可能过期」+ 后台重跑**；**界面上绝不把过期候选显示成真值**。
3. 写盘前：若这一拍用到了"未验证/过期"的候选 → **构建报告点名**（本项目已有的报告机制）。

> 这正好对上你项目里既有的规矩：**报出来，不静默。**

## 五、四类风险的处置（逐条）

| 风险（来自反驳） | 处置 |
|---|---|
| **API 返回形状被魔改**（`.group` 变嵌套 / `.attribute` 变对象） | ① **防御式读取**（`getattr(x, "group", None)` + 记下 `type(x).__name__`）；<br>② **两个独立来源交叉核对**：`.attributes` 对象 **vs** `get_ordered_image_attributes()` 字符串 —— 实测两者都可用，**不一致就报**；<br>③ **形状自检探针**：断言"结构与预期一致"，不符则报"引擎返回的属性结构不是工具认识的形状"＋原始 repr。（本项目既有规矩：**认不出就报，不猜**。） |
| **CDS 扫描 ≠ 生效** | 扫到的 CDS **只当候选**；再用探针问一句"`mycue "x":` 引擎接受吗" —— **接受才算生效**。另加一条静态检查：定义 CDS 的文件名是否排在首个使用者之前。 |
| **归纳（滞后）与裁判（实时）冲突** | **裁判赢，归纳只出候选。** 且**冲突本身就是最有价值的报警**："引擎变了 —— 这些行现在可能不合法"，给一份**清单**（对魔改引擎的团队，这就是迁移清单）。 |
| **冷启动（新项目、零样本、引擎不说、程序不教）** | 探针仍是唯一手段；**但必须先知道存在 `weather` 这个词**才能拿它去探。这一步的**最廉价输入 = 人只报一个名字**（不是让人填形状）。⚠ **这是诚实的边界**：完全无声的自定义语法，工具无法凭空发现。 |

## 六、诚实的天花板（不粉饰）

1. **探针只覆盖你想得到的**（反驳二说得对）→ 靠"历史用法喂它"：**扫脚本负责发现新东西，行为探测负责验证已知的东西还成不成立**。这正是两份反驳的收敛点。
2. **`lint` 的能力边界是实测出来的，不是猜的**：语句级 ✅、属性级 ❌、自定义语句的语义 ❌（除非程序自己写了 lint 函数）。
3. **`--json-dump` 只实测到"存在且需脚本无错"**，它在真机项目上到底给不给 label/transform 注册表，**必须先跑一次再说，不许假设**。
4. **headless 依赖实测跑通，但只在最小项目上跑通**；8GB 的真机项目**没验证过**（拷贝不动），真机上会不会因为 `init python` 多、平台配置特殊而卡住，**需要一次实测**。
5. **完全无声的语法（零样本 + 无注册 + 无补丁）工具发现不了** —— 只能靠人报一个名字。

## 七、最小可执行的第一步（用实测过的命令，可直接复制）

**目标**：用**真机项目**回答 §六.4 和 §六.3 这两个悬而未决的问题 —— **不写产品代码，只做一次实验**。

```bash
# 0) 永远在副本上做（真机 8GB，只拷 game/ 里的 .rpy + 必要的 images 即可，或先只跑 lint 不 dump）
cd D:/software/renpy-8.4.1-sdk
export SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy

# 1) 真机能不能无头跑通 lint？（= 回答反驳一·反驳六）
./lib/py3-windows-x86_64/python.exe renpy.py <副本路径> lint --error-code

# 2) 官方 JSON dump 在真机上给什么？（= 回答 §六.3）
./lib/py3-windows-x86_64/python.exe renpy.py <副本路径> lint \
    --json-dump <副本>/dump.json
```

**验收**（每一条都是可判定的）：
- [ ] 真机 `lint` 无头跑通，退出码有意义；
- [ ] `dump.json` 的 `location.label / transform / define` **是否非空**（决定它有没有用）；
- [ ] 在副本里加一个探针 `init`（内容照抄 §一 的实验）→ 拿到 `clothes2` / `base_swimsuit` / `outfit` / `expressions`；
- [ ] **加一行 `weather 雨 0.5` → lint 变红、退出码 1**（验证"待认识"发现机制）；
- [ ] **加一行 `show lan 完全不存在` → lint 不变红**（复现实测 #7，钉住"属性不归 lint 管"）。

**这五条跑出来，才知道这套方案在你项目上到底成不成立** —— 在那之前，它只是设计。
