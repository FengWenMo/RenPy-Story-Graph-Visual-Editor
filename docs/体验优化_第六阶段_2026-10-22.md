| 报告建议 | 之前 | 现在 |

## 二、块首插入

### 2.1 落点从"一个整数"变成三种形态

`VariableWorkbenchDialog.anchors` 交给会话的落点现在有三种（旧契约仍然有效）：

| 值 | 意思 |
|---|---|
| `-1` | 本章末尾（label 顶层收尾） |
| `拍号`（整数） | 那一拍拍内容的**末尾**（= 块体尾；第五阶段的写法） |
| `(拍号, 'head')` | 那一拍拍内容的**最前面**（= 块首；本轮新增） |

`apply_node_variable_edits` 里的 `anchor_of()` 认全部三种，并且**两种落点共用**
"循环头往后挪一拍"那条判据：`for …:` 自己占一拍、块体在下一拍，所以块首 =
循环体的第一行（不是 `for` 那一行本身）。

顶层语句没有"块首"，它等于**本章第一拍的最前面**（label 一开始就执行）。
第一拍从数据里取（`variable_workbench()` 新增 `first_beat`），不假设它是第 0 拍 ——
同一个文件有多个 label 时，第 0 拍属于第一个 label。

### 2.2 为什么不是一句 `beat.code = 新行 + beat.code`

`Beat.code` 存的是**块体本身**（缩进由块头在渲染时补），所以"插到 `code` 前面"
确实是块体第一行。但直接拼字符串会踩两个坑：

- **`ordered`** 是 raw / code 在源码里的**交错顺序**。不把新行记进去，
  `_ordered_code_lines` 会判"code 池里多出来一行"→ 整份退回老顺序
  （raw 全部在前、code 全部在后）——同一拍里原有的 `$` 语句会被挪到
  `show screen` **之后**。只是插一条赋值，演出顺序却变了。
- **`code_blocks`** 是 `python:` 块的行区间（1-based，按"raw 行在前、code 行在后"
  编号）。前面插了 n 行，所有区间必须整体后移 n；不挪的话块标记落在别的行上，
  产物直接语法错。

所以新增 `_prepend_beat_code()` 一次做三件事：拼 `code`、往 `ordered` 头部插
`('code', 行)`、把 `code_blocks` 整体 +n。

> 判据：`test_head_insert_keeps_a_python_block_intact` —— 一个 `if` 里同时有
> `python:` 块和 `$` 语句，块首插一行之后编译出来仍是
> `if → $ 新行 → python: → 两行块体 → $ c = 3`。

### 2.3 一次加几条：收齐了再插

用户在工作台里连点两次「新增操作」，中间弹出的输入框让两条都锚到同一个块首。
如果边收边插（每条都插到最前面），产物里的顺序会**反过来**。

所以先把"要放块首的"按拍收集到 `heads`，循环结束后**一次性**按用户输入顺序插。
新增两条 `a1` / `a2` 编译出来就是 `$ a1 = 1` 在 `$ a2 = 2` 上面。

### 2.4 界面上说清楚

- 下拉三项：`选中这条之后（同一块内）` / `块首（选中这条的块最前面）` / `本章末尾（顶层）`；
- 旁边的实时提示跟着变：`会放到第 2 拍的「if love > 3:」块最前面`、
  顶层则是 `会放到第 1 拍的最前面（顶层）`；
- 列表里新增的行会标 `· 块首`，保存前后一眼能对上；
- 选中的那条对不上拍时**不猜**（不许悄悄退到"本章开头"）——
  提示改成"放不了块首，换「本章末尾」"。

## 三、折叠状态记住

### 3.1 存哪儿：偏好，不是布局 JSON

新增 `storygraph/ui_qt/prefs.py`：`QSettings` 上的两个小函数（`load_json` /
`save_json`），org / app 与 `asset_picker` 一致（同一个 Qt 应用 = 同一份偏好），
但**注入点各自保留** —— 卡片页读一个偏好不该为了一个工厂去 import 选资产的对话框。

判据仍然是第五阶段那条：**换成另一个项目还成立吗？**

- 成立（底色、折了哪些 label）→ 偏好；
- 不成立（图上坐标、分栏尺寸、上次打开哪章）→ 布局 JSON / 会话记忆。

折叠是"我这会儿不想看这几个 label"的临时视图，放进布局 JSON 会让
"我只是想换个项目打开"变成"位置和折叠全没了"。

### 3.2 键与写入点

- 键 = **绝对路径**（`Path.resolve()`）：同一份文件可以从项目根、从 `game/`、
  从命令行相对路径打开，三个字符串指同一份文件 —— 用相对路径当键，换个入口就
  "折叠状态没了"；
- 值 = `[label 名…]`；整张表是一个 JSON dict（`cards/folded_labels`），
  最多留 **24 个文件**（偏好不是日志，不清理会越积越多）；
- 写入点两个，语义都是"**用户最后看到的样子**"：
  1. 点标题行（明确的折 / 展）；
  2. 导航进了一个折着的组 → 它被自动展开 —— 这一条也要记，否则
     "折起 A、跳进 A 看一眼、关掉"，下次打开 A 又是折的，与关窗那一刻相反。
- 读取点只有一个：`load_script()` 里、`_reload_list()` **之前**
  （反了的话第一次打开会先全展开、再被"恢复"成折叠）。

单 label 的文件不会产生任何偏好（没有分组行，也就没有折叠这回事）。

## 四、关窗：把"这一章"和"表单"也问上

### 4.1 三种"没保存"分开算

`_close_dirty_state()` 返回：

| 键 | 判据 | "保存"对它意味着 |
|---|---|---|
| `graph` | `_graph_dirty`（既有） | 写 `storygraph_layout.json` |
| `beats` | 会话的 `unsaved_edits()`：内存里的拍 vs 最后一次读/写的基线 | 写回这一章的 `.rpy` |
| `form` | `_panel.is_modified()`：当前这一拍的表单改了还没提交 | 先提交到拍，再随上一行走 |

三者**分开问**是因为"保存"对它们的意思不同。**只有图脏**时仍然走第五阶段那个
三选一（措辞、按钮都不变）——那是用户已经熟悉的一步，不因为多了"这一章"就换掉。

### 4.2 那个会说谎的状态栏

`_show_index()` 以前每翻一页就 `set_dirty(False)`。现在状态栏只有一个判据：
`session.has_unsaved_edits()`（便宜，一个布尔）。它由这些路径立起来：

- `apply()` 里比较这一拍**前后指纹**（翻页顺带提交、内容没变 → 不立）；
- `_renumber()`（插卡 / 删卡 / 撤销结构都走它 —— 一处覆盖全部结构编辑）；
- 变量工作台写回（`apply_node_variable_edits`）；
- `set_speaker()` / `remove_sprite()`（绕过 `apply()` 的直接改拍）。

撤销之后会 `refresh_edits_flag()` 重算一次：插了一张卡又撤销，内存已经与磁盘
一致，状态栏不该还喊「● 未导出」。

### 4.3 保存的顺序与失败

选「保存并退出」：

1. 有表单改动 → `apply_current_beat()`（表单 → 这一拍）；
2. 拍仍然与磁盘不一致 → `session.export(default_output_path())`
   —— **不再弹"导出到哪"**。用户刚在"保存并退出"上表过态，再叠一个文件对话框
   只会让人以为程序卡住；
3. 图脏 → 走既有 `_save_layout_for_close()`。

任一步失败都**不关窗**（弹一句原因，改动还在内存里）。这比"尽力保存然后关掉"
诚实：写不出去的时候，关窗就是真丢。

### 4.4 计数口径：比"产物会不会变"，不比字段快照

第一版用的是**字段快照**指纹（`snapshot().fingerprint()`，撤销那套）。跑真窗口
时撞上了：**只是翻页**（`next_beat` 会顺带 `apply_current_beat()`）之后，
`unsaved_edits()` 报"改了 3 拍"——因为 `apply()` 会把 `At` 这类**投影列**
规范化（`Beat.at` 从 `''` 变成 `i11`），而编译出来的 `.rpy` **一个字都没变**。

所以判据改成**渲染出来的行**：`_beat_edits_print()` 直接调导出用的
`render_beat_to_rpy(beat)`，再补两个不进单拍渲染、但确实要保存的字段
（`label` 换了 = 这一拍要挪到别的章节；`notes` 只在表里）。
`line_id` / `seq` 是身份编号，**刻意不比**。

`unsaved_edits()` 再用 `difflib` 对齐两份指纹序列，于是计数是"产物里会变的拍"：

- 改一句台词 → `changed: 1`；
- 中间插一张卡 → `added: 1`（不会把后面每一拍都报成"改了"）；
- 删一张卡 → `removed: 1`；
- 插了又撤销 → `dirty: False`；
- **把整章翻一遍 → `dirty: False`**（这一条是这轮修出来的，见 §5 的
  `test_walking_the_chapter_is_not_an_edit`）。

关窗那句人话按这个拼：`ch01.rpy：1 拍内容改了，还没导出`。

成本：渲染用的是**只读路径**（`rendered_lines_of` 里那份 `deepcopy` 是给
"预览会删几行"用的，这里不拷贝）——1793 拍实测 113ms，只在关窗 / 弹框时算；
翻页、状态栏都只读那个布尔。载入时记基线也要算一遍（同一量级），
284 拍的一章约 25ms，写在这里免得以后被当成"载入变慢"的锅。

### 4.5 没有人在看的时候不弹框

窗口没显示过（测试 / 嵌入 / 启动失败清理）时**不弹**：图沿用"自动存一份"，
拍的改动没有安全落点（导出要过门禁，不能替用户决定覆盖），只能放弃。
与第五阶段同一条理由：构造完就 `close()` 的路径弹模态框会把进程挂住。

新增判据覆盖：

- **块首**：`(拍, 'head')` 让新行紧跟块头、在原来第一条之前（缩进 8）；
  两条块首按输入顺序排；顶层块首落到本章第一拍、缩进 4；老整数锚点仍追加在块尾；

- **折叠**：折了 `side_b` 关掉再开，`side_b` 仍是折的、`main_a` 是开的；
  跳进折着的组（自动展开）之后下一次打开也是开的；折叠**按文件**隔离
  （同名 label 的另一份 `.rpy` 不受影响）；单 label 文件不写偏好；

  写失败不关窗；只改表单也进询问、选保存会写出去；**翻页不再把「● 未导出」
  翻回「✔ 已同步」**；**把整章翻一遍不算改动**（渲染判据，见 §4.4）；
  干净的窗口不问；
- **计数**：插卡 = `added: 1`、撤销插卡 = 干净、删卡 = `removed: 1`。

## 六、仍然不做（写明，不藏）

- **块首插入只认"语句级"**：它插一行到块体最前面，不会改写块头条件、
  不会把一条顶层语句"包进"一个新的 `if`。要改结构仍然去源文件 / 卡片的高级区。
- **折叠状态不跟项目走**：它是"这台机器上这个文件的视图偏好"。换台机器
  （偏好没同步）就回到全展开 —— 这是偏好与文档分开的代价，写在这里免得被当成 bug。
  > **这一条已在当天晚些时候改掉**：见
  > [体验优化第八阶段](体验优化_第八阶段_2026-10-22.md) ——
  > 折叠状态改存项目根的 `storygraph.session.json`（`cards` 段，项目内相对路径），
  > 搬目录 / 换机器仍认得。本节保留的是第六阶段当时的选择。
- **关窗的"保存"不替你选导出路径**：直接写回原文件（有源文件时）。
  想导出到别处，仍然走「⤓ 导出 .rpy」。
- **不做"自动导出"**：改动仍然只在内存里，直到你按导出或关窗选保存。
  自动落盘会把"我还没想好"的半成品写进 `game/`。
- **卡片删除 / 插入不进关窗的**"撤销"：关窗只处理"保存 / 不保存"，
  没有"先撤销我的改动再关"这一路（撤销按钮仍在卡片页上）。
