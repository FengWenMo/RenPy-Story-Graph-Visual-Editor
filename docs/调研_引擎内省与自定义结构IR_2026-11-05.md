# 调研：打开项目时“问引擎”，把自定义结构变成 IR / 数据库（2026-11-05）

> 用户的问题（原话）：
>
> > 每当遇到这种自定义的写法，为了保持通用性，要么只能够通过自定义模块表注册，
> > 要么通过映射表映射回对应的写法……这个表非常非常非常麻烦！一个自定义写法就有着
> > n 多个变量 + 每个变量几十上百个参数，没有人愿意填……有没有一种可能……它可以在
> > 项目更新与打开此项目时直接询问引擎？然后把变量一类的那些自定义的东西给它转换为
> > IR（后续为多引擎扩展），后全部都纳入数据库……？（只是默认不打成 excel 表，因为
> > 编剧演出有可能不需要这个……），从而避免现在这种工具判别与 rpy 引擎不一致的问题……?
> > 你直接执行搜索，先不做！硬要做的话……巩固现在的数据库结构吧，不过还要考虑到引擎
> > 说它不是个 image，但是却实际上有这个定义，实际上能跑的问题……引擎也不是万能的……
> > 而且 UI 界面和声明怎么办呢……？这是个问题。
>
> **本文只做调研与设计，没有改任何产品代码。**

## 一、结论（先看这一段）

| 问题 | 结论 |
|---|---|
| 打开/更新项目时能不能问引擎？ | **能，而且已经有一半底座**：`pipeline/engine_collect.py` 现在就会注入探针、跑 `lint --json-dump`、把 `images/tags/attributes/candidates/transforms/screens/defines/statements` 写进 `storygraph.engine_facts.json`。缺的是**运行期变量值**与 **LayeredImage 的完整结构**（组/默认/条件/落盘图） |
| 自定义变量/结构能不能自动变成 IR？ | **能**：真机实测 3 秒拿到 184 张图、80 个 tag、10 个 `LayeredImage`、`CC_OUTFIT_CYCLE`/`CC_OUTFIT_LABEL`/`EXPRESSION_MAP` 的**值**；不需要人填“n 个变量 + 几十个参数”的表 |
| 默认不打成 Excel？ | **对**：IR 作为工具内部的**派生索引**（JSON/SQLite），Excel 仍是人维护的资源表；IR → Excel 只做**可选投影**，默认不写 |
| 引擎说“不是 image”但实际能跑？ | **必须建模成三种“引擎视图”**：`lint`（注册表）、`can_show`（属性解析）、`show`（真实运行）在真机上**互相打架**；IR 要保存“谁在什么范围说了什么”，校验按问题选层，**永远不能 lint-only** |
| UI 和声明怎么办？ | 声明仍是 `.rpy`（唯一真源）；IR 是**可重建的观察缓存**；UI 用“证据徽章 + 实体浏览器”，人只做**少量注解**（一个结构一条），不需要填值；注解可丢，丢了工具仍能“不误报” |
| 值不值得做？ | **值得，但别一次做大**：先把现有 facts schema 升到 v2（补 `layered` + `store`），再在它上面加 IR 视图；不要另起一套“全量 AST→IR”，也不要在每次敲键时跑引擎 |

一句话：**不是“让引擎替掉解析器”，而是“把引擎的几种视图 + 脚本声明 + 资源表 + 使用证据”放进同一个带出处的 IR 里，谁回答哪个问题分清楚。**

## 二、现在手里已经有什么（先别重复造）

| 现有件 | 位置 | 已经能做到 | 缺口 |
|---|---|---|---|
| 引擎事实采集 | `storygraph/pipeline/engine_collect.py` | 注入 `zz_storygraph_probe.rpy`（`init 999`）→ 跑 `lint --json-dump` → 写 facts；前后 `sha1` 清单证明没改项目；`mode='copy'` 可整份拷贝 | 探针只取 `images/tags/labels/statements/attributes(组/属性/type)/candidates`；**没有** `default`/`when`/`if_*`/`image_format`/`filename`/组映射；**没有** store 变量值 |
| 事实 schema | `storygraph/core/engine_facts.py` | 每条事实带 `source`（`probe` / `json-dump` / `scanner` / `conflict`）；`gaps`（没采到要留痕）；`conflicts`（来源打架不静默挑）；`is_collectable` 硬闸门 | `FACT_KEYS` 是扁平键；没有实体/关系；`attributes` 只有 `{group, attribute, type}` |
| 事实消费 | `storygraph/core/engine_facts.py`、`storygraph/app/beats.py`、`storygraph/assets/asset_dimensions.py` | `grouped_choices` / `unrecognized_attrs` / `group_conflicts` / 候选表 / 卡片维度 | 没有“变量值”这一层，所以 `aa` 这种**项目变量里的词**只能靠静态 `defined_words` 兜；引擎视图打架时没有分层 |
| 官方 dump | `renpy --json-dump`（`renpy/dump.py`） | `location.label/define/screen/transform/callable` + 文件/行号 | 不含 image / layeredimage / store |
| 现有 lint 缓存 | `storygraph/assets/engine_images.py` | 把 `is not an image` 的 image 名缓存给提示层 | 只能回答“注册表里有没有”，**不能回答“layeredimage 认不认”**（真机 `lan aa happy` 就是反例） |

所以“从零做一个引擎内省系统”是**伪命题**；真正要做的是**把 E1 从“事实快照”升级成“带出处的 IR”**。

⚠ **现状里还差一块“打开即问”**：`engine_collect.collect()` 目前只有 CLI 入口
（`engine-facts --project … [--mode in-place|copy]`）和一次性的“验证自定义语句”调用；
打开项目时只走 `session.engine_facts()` **读现成的 `storygraph.engine_facts.json`**，
**不会自动跑引擎**。所以“打开/更新时问引擎”不是已经做完，而是本文建议补的第一块
（见 §八 P0）。

## 三、实测：三条“问引擎”的通道

### 3.1 官方 `--json-dump` + `quit`：不改项目，拿声明清单

```powershell
# 影子工程（见 3.2）里的实测；对真机项目等价
renpy.exe <project> quit --json-dump out.json
```

真机 `sr_general`（93 个 `.rpy`）实测：

| 项 | 值 |
|---|---|
| 耗时 | `quit --json-dump` **2.8 s**；`lint --json-dump` **3.2 s**（同一影子工程） |
| 输出 | `location.label / define / screen / transform / callable` + 文件:行号；真机 `defines=456 / transforms=179 / screens=96 / callables=174` |
| 项目改动 | **0 个 `.rpy` / 资产**；引擎仍会写自己的 `cache/`（影子工程里）；存档用 `--savedir` 指到临时目录 |

`--json-dump` 是**官方 CLI**（[Command Line Interface](https://www.renpy.org/doc/html/cli.html)），但文档明说 *“The CLI isn't a stable interface — it may change between Ren'Py releases”*；所以要用**版本适配层**包住，失败就退回静态扫描。

它已经能解决“自定义 transform / `define` 转场 / screen / label 认不认识”的**名字存在性**问题；真机 `hell_dissolve` 这种 `define` 也在 `location.define` 里。

### 3.2 影子工程 + post-init 探针：拿运行期对象（不改用户项目）

做法（实测跑通）：

1. 把项目的 **93 个 `.rpy` 拷到临时目录**（不拷图片，1.9 GB 不碰）；
2. 探针 `init -1000 python: renpy.config.searchpath.append('<原项目>/game')`，**资产仍从原项目读**（`renpy.loadable` 实测 `True`）；
3. 探针 `init 0 python: renpy.game.post_init.append(_dump)` —— **在所有 init 之后、`--json-dump` 之前**执行（`renpy/main.py` 的顺序），绕开 `init 999` 的优先级上限；
4. 探针把 `renpy.display.image.images` / `LayeredImage` / `renpy.store` 写 JSON；
5. 跑 `renpy.exe <影子> quit`。

探针关键三行（实测）：

```renpy
init -1000 python:
    renpy.config.searchpath.append(r"<原项目>/game")

init 0 python:
    renpy.game.post_init.append(_sg_dump)   # _sg_dump 里 json.dump(...)
```

真机结果（3.0 s）：

```
images=184  tags=80  layeredimages=10  store_literals=88  loadable=True
CC_OUTFIT_CYCLE = {"ling": ["aa","base_swimsuit","base_arms_akimbo"],
                   "lan":  ["aa","base_hand_up","clothes2"], …}
CC_OUTFIT_LABEL = {"aa": "普通", …}
EXPRESSION_MAP  = {"lan": [[1,"闭眼笑","close_happy"], …], …}
lan.attributes  = [{group:"expressions", attribute:"afraid", default:false,
                    image_type:"Image", filename:"images/characters/lan/afraid.png"}, …]
lan.group_to_attributes = {"outfit": ["clothes2","base_hand_up"], …}
lan.image_format = "images/characters/lan/{image}.png"
```

- **`LayeredImage` 是运行期对象**：`renpy.get_registered_image('lan')` 拿到的就是它；`.attributes` / `.group_to_attributes` / `.image_format` / `.attribute_function` 全在（源码在 SDK 的 `renpy/common/00layeredimage_ren.py`）；
- 属性对应的 `image_type` 有 `Image`（有 `filename`）也有 `AlphaMask`（`filename=None`，真实项目 `crop_lan` 那一条）——**要递归展开 displayable 才能拿到路径**，拿不到就记 `dynamic/unresolved`，不猜；
- `renpy.store` 里 dict/list/tuple/scalar 可 JSON 化；函数/类/displayable 只记类型 + 源码位置 + `repr` 摘要。

**影子工程 vs 现有 in-place**：

| 方式 | 写用户项目 | 成本 | 适用 |
|---|---|---|---|
| 现有 `mode='in-place'` | 写一个 `zz_storygraph_probe.rpy` + 引擎 `.rpyc`/`cache`，随后删除 + 清单校验 | 最省 | 用户手动“采集引擎事实” |
| 现有 `mode='copy'` | 0 | 拷整个 1.9 GB（慢） | 测试 |
| **建议新增 `mode='shadow'`** | 0 | 拷 93 个 `.rpy`（~几 MB）+ `config.searchpath` 指回原 assets；实测 3 s | **打开/更新时自动跑** |

### 3.3 现有 `engine_collect` 跑在最小工程上的输出（缺口证据）

```python
EC.collect(root, sdk=..., mode='copy')
# ok=True, manifest_ok=True, collection={parse_clean:True, probe_complete:True, lint_exit:1}
# attributes['lan'] = [
#   {'group': '', 'attribute': 'happy', 'type': 'Attribute'},
#   {'group': 'outfit', 'attribute': 'coat', 'type': 'Attribute'},
#   {'group': '', 'attribute': 'sigil_77', 'type': 'Attribute'},
# ]
# candidates['lan'] = ['符_77', 'coat', 'happy', 'sigil_77']   ← 没有 aa
```

`lint_exit=1` 正是 `'lan aa happy' is not an image`；`candidates` 里也没有 `aa`（因为它不是 `image_attributes`）。**这不是采集失败，是采集口径只覆盖了“注册表视图”**。

## 四、引擎能回答什么、不能回答什么（IR 分层的根据）

### 4.1 三种“引擎视图”在真机上互相打架

最小工程（`layeredimage lan` + `store.CC = {"lan": ["aa","coat"]}`）实测：

| 问法 | API | `lan aa happy` | `lan aa based` | `lan happy` | `lan nope` |
|---|---|---|---|---|---|
| 注册表 lint / `list_images` | `renpy.list_images()` | **不在**列表 | 不在 | `lan` 在 | 不在 |
| 属性解析 | `renpy.can_show(...)` | **`None`** | `None` | `('lan','happy')` | `None` |
| 真实 show | `renpy.show(...)`（start callback） | **成功，tag 出现** | **成功** | 成功 | **成功** |
| layeredimage 声明 | `LayeredImage.attributes` | `aa` **不是** attribute（被忽略） | 同左 | `happy` 是 | 同左 |

结论：

- `lint`/`list_images` 的 `is not an image` 是**注册表视图**，不是“跑不了”；
- `can_show` 比 lint 严格，但对“layeredimage 会忽略的未知属性”**也说 None**，同样不能当“能不能跑”；
- **真实 `show` 几乎接受一切**（layeredimage 的 `_duplicate` 对未知属性只画调试字、不抛异常），所以它只能证明“不会崩”，**不能证明“作者想要这个属性”**；
- 想判“是不是笔误”，只能靠**声明 + 项目变量词表 + 用法**，不能靠引擎的任何单一 API。

这就是为什么 IR 必须存 **`source` + `scope` + `confidence`**，而不是一个 `valid: bool`。

### 4.2 能力矩阵

| 问题 | 谁回答 | 证据 | 边界 |
|---|---|---|---|
| 有哪些 image / tag | `renpy.list_images()` / `renpy.get_available_image_tags()` | 官方文档 [Image Functions](https://www.renpy.org/doc/html/displaying_images.html#image-functions) | 只有**注册名**；layeredimage 的属性组合不在内 |
| 某 tag 的属性/组/默认/条件/图 | `renpy.get_registered_image(tag)` → `LayeredImage.attributes` / `.group_to_attributes` / `.image_format` | [Layered Images](https://www.renpy.org/doc/html/layeredimage.html) + 源码 | `attribute_function` / `config.adjust_attributes` 是动态的；displayable 可能递归展开不出路径 |
| 某属性组合实际显示哪张图 | 运行期 `Image.filename` / 递归 displayable；或工具侧 `resolve_layers` | 本仓 `storygraph/story/layered_model.py` | `AlphaMask`/`Crop`/`Transform` 要逐类展开；认不出就标 unresolved |
| transform / transition / screen / label / define | `--json-dump` | [CLI](https://www.renpy.org/doc/html/cli.html)、[`renpy/dump.py`](https://github.com/renpy/renpy/blob/master/renpy/dump.py) | CLI 不稳定；只有名字+位置，没有值 |
| 自定义语句认不认识 | `renpy.statements.registry`（现有探针已采） | 引擎运行时注册表 | 只回答“注册了没有”，不回答“这个项目用没用对” |
| 变量值 / 自定义结构 | `renpy.store` | 运行期对象 | 任意对象不可序列化；init 受语言/平台/`config.developer` 影响；只看到一次运行配置 |
| 某个 `show` 会不会崩 | `renpy.show`（start callback） | 真实运行 | layeredimage 未知属性**不会崩**；不能当“意图正确” |
| 哪个 `show` 写法是笔误 | 声明 + 项目词表 + 用法 | 静态 + store + IR | 动态拼名字（`"scene_"+id`）永远判不了 |

## 五、IR 设计（多引擎可扩展）

### 5.1 实体与关系

不要先做“一个大 JSON”；先定**实体-关系**，再选存储。

**实体（`entity`）**

| kind | 例子 | 关键字段 |
|---|---|---|
| `engine` | `renpy 8.5.3` | version / sdk |
| `file` | `game/definitions.rpy` | path / sha1 |
| `image_tag` | `lan` | tag |
| `layered_image` | `lan` | name / image_format / at / attribute_function |
| `attribute` | `lan expressions happy` | tag / group / name / default / variant |
| `layer_group` | `lan outfit` | name / when / if_all / if_any / if_not |
| `displayable` | `Image(images/.../happy.png)` | type / filename / unresolved |
| `transform` | `hell_pose` | params / body / file:line |
| `transition` | `hell_dissolve` | kind / duration / file:line |
| `screen` / `label` / `callable` | `hell_hud` / `start` | file:line |
| `variable` | `CC_OUTFIT_CYCLE` | name / kind / file:line |
| `value` | `["aa","base_hand_up"]` | JSON 预览 / hash / truncated |
| `character` | `lan` | var / display / image_tag |
| `statement` | `show` | registry record |

**关系（`relation`）**

| 关系 | 语义 |
|---|---|
| `declared_at(file, entity)` | 脚本声明位置（`file:line`） |
| `has_attribute(layered, attribute)` | `LayeredImage.attributes` |
| `in_group(attribute, group)` | `group_to_attributes` |
| `default_of(attribute, group)` | `Attribute.default` |
| `renders(attribute, displayable)` | `Attribute.image` |
| `uses_file(displayable, file)` | `Image.filename` |
| `has_value(variable, value)` | `store` 观察值 |
| `references(statement, entity)` | 用法证据（`show`/`at`/`with`） |
| `conflicts(a, b, why)` | 两个来源不一致 |
| `annotated(entity, annotation)` | 人的注解（与观察分开） |

**每条实体/关系都带**：

```
source: declared | runtime | registry | inferred | usage | annotation
scope:  image_registry | layeredimage | store | script | asset_table
run_id / engine_version / language / platform / fingerprint
confidence: 0..1（现有 asset_dimensions 已有 0.9/0.7 这套，直接复用）
stale: bool（脚本/引擎变了但没重采）
```

### 5.2 稳定 ID

```
renpy:image_tag:lan
renpy:layered:lan
renpy:attr:lan/expressions/happy
renpy:group:lan/outfit
renpy:var:CC_OUTFIT_CYCLE
renpy:value:CC_OUTFIT_CYCLE/lan/0
renpy:file:game/definitions.rpy
```

- ID 用 **engine + kind + 业务键**，不用行号（行号会变）；
- 行号只作为 `declared_at` 的属性；
- `value` 用路径（`lan/0`）而不是 JSON 字符串，才能“同一个值在两次采集里对得上”。

### 5.3 存储：JSON 观察 + SQLite 派生索引

| 层 | 内容 | 位置 | 是否进版本库 |
|---|---|---|---|
| **观察（facts）** | 一次采集的原始结果 + source/gaps/conflicts | `storygraph.engine_facts.json`（现有）或 `storygraph.facts/<run>.json` | **可选**（现有设计是进版本库，便于 diff） |
| **IR 索引** | 实体/关系/注解，可重建 | `%LOCALAPPDATA%/StoryGraph/projects/<hash>/ir.sqlite` | 不进；删了能重建 |
| **人注解** | “这个变量是一个维度”这类少量判断 | `storygraph.annotations.json`（工具拥有）或 ir.sqlite 的 `annotation` 表 | **建议进**（人写的，重建不丢） |
| **Excel** | 资源表（人维护） | 现有 `assets/*.xlsx` | 现有 |

SQLite 表（示意，不要求现在建）：

```sql
CREATE TABLE run (
  id TEXT PRIMARY KEY, engine TEXT, engine_version TEXT,
  language TEXT, platform TEXT, fingerprint TEXT,
  started_at TEXT, ok INTEGER, gaps TEXT
);
CREATE TABLE entity (
  id TEXT PRIMARY KEY, run_id TEXT, engine TEXT, kind TEXT, name TEXT,
  tag TEXT, parent_id TEXT, props TEXT,
  source TEXT, scope TEXT, confidence REAL,
  file TEXT, line INTEGER
);
CREATE TABLE relation (
  src TEXT, kind TEXT, dst TEXT, props TEXT,
  source TEXT, scope TEXT, run_id TEXT,
  PRIMARY KEY (src, kind, dst, source, run_id)
);
CREATE TABLE annotation (
  entity_id TEXT PRIMARY KEY, key TEXT, value TEXT,
  author TEXT, updated_at TEXT
);
```

⚠ **不要把 `run_id` 并进实体主键**：实体是跨 run 稳定的；`run_id` 只标“这条观察来自哪次”，查询时取最新 run。

### 5.4 现有 facts → IR 的迁移（schema v2）

在 `core/engine_facts.py` 的 `FACT_KEYS` 里加（**先加观察，不急着建库**）：

| 新键 | 内容 | 来源 |
|---|---|---|
| `layered` | `{tag: {image_format, at, attribute_function, attributes:[{group,attribute,default,variant,when,if_all,if_any,if_not,image_type,filename}], groups:{group:[attr]}, layer_types:[...]}}` | `probe` |
| `store` | `{name: {kind, preview, words, value_hash, truncated, source_file, source_line}}` | `probe` |
| `capture` | `{language, platform, developer, variants, savedir}` | `probe` |
| `dyn` | `{attribute_function, adjust_attributes, default_attribute_callbacks}` 是否存在（只记 bool/名字） | `probe` + 静态 |

`SCHEMA_VERSION` 从 1 → 2；`validate_facts` 认新键；老消费者读不到新键时**不报错**（`value_of(..., default)`），保持向后兼容。

**采集口径的三条纪律（沿用现有三条，不能破）**：

1. 每条事实必须有 `source`；
2. 两个来源不一致 → `conflicts`，不静默挑；
3. 采不到 → `gaps`，不是“没有”。

## 六、UI 和声明怎么办

### 6.1 三个视图，不要混

| 视图 | 内容 | 写不写 |
|---|---|---|
| **声明视图** | `.rpy` 原文 + `file:line`；点一下跳到定义 | 只读（人改 rpy） |
| **运行事实视图** | 引擎探针结果：`LayeredImage` 树、变量值、图/组/默认；带“运行时 / 引擎版本 / 采集时间”徽章 | 工具写，人只读 |
| **资源表视图** | `assets/*.xlsx`：人维护的资产登记 | 人写；工具只在明确操作时改 |

UI 里每个实体一个徽章：`声明` / `运行时` / `资源表` / `推断` / `注解`。**同一个名字可以有多个徽章**（`aa`：运行时 + 用法；`happy`：声明 + 运行时 + 资源表）。这比一个 `is_image` 布尔值诚实得多。

### 6.2 声明：不是让人再填一张表

- `.rpy` 里的 `layeredimage` / `define` / `transform` 就是声明；IR 只是**观察**，不是第二真源。
- 自定义结构（`CC_OUTFIT_CYCLE` 这种）**默认零配置**：IR 从运行时拿到值，知道 `aa` 是项目定义的词；卡片不报错，预览也能算对（忽略 `aa`，显示默认服装）。
- ⚠ **“值”不等于“语义角色”**：`{"lan": ["aa", …]}` 只说明“这是一张 tag → 词的表”，**不能**自动断言它是服装维度（`aa` 恰好是“普通/空”，不是属性）。工具可以**提议**“这像一个维度表”，但必须由一条注解（或项目规则）显式启用；不启用时只把它当“项目词表”，仍然不误报。
- 如果希望 UI **把它当成服装维度**（出 chip、显示「普通/举手/衣服2」），只需要**一条注解**，不是每个值一条：
  ```json
  {"target": "renpy:var:CC_OUTFIT_CYCLE",
   "role": "tag_value_lists",
   "label": "服装循环"}
  ```
  值从运行时自动填；结构变了，注解标 stale，UI 提示“重新确认”，不静默套旧值。
- 注解可以**不写**：不写时工具仍“不误报”，只是不提供维度 chip。这样“n 多变量 + 几十个参数”永远不需要人填。

### 6.3 “引擎说不是 image，但能跑”怎么写进 UI

一条 `show` 的判定顺序（从“意图”到“运行”）：

1. **声明层**：`layeredimage` 有没有这个属性？有 → 合法。
2. **项目词表层**：`store` 里有没有这个词？有、但不是 layered attribute → **软提示**：
   > `aa` 是项目变量 `CC_OUTFIT_CYCLE` 里的词；`layeredimage lan` 没有声明这个属性，运行时会被忽略，实际显示 `happy.png`。
   这不是错误，用户不需要改。
3. **注册表层**：`lint`/`list_images` 说没有 → 只作为**附加证据**显示：
   > 引擎 `lint`（注册表视图）说 `lan aa happy` 不是 image；这是 layeredimage 的已知限制，不影响运行。
   **绝不允许**这一层单独把一句话判死。
4. **运行层**：真的 `show` 一下（可选、按需）→ 只回答“会不会崩”；它接受未知属性，所以**不能**用来判笔误。
5. **笔误层**：以上都没有、且不是任何项目词 → 才报“没有这个属性”，并给出“实际显示哪张图”。

这正好接上 2026-11-05 已修的 `sprite_hints` 顺序（声明 > 引擎 > 拼写 > 角色表 > 素材），IR 只是把每一层的证据**存下来、可查询**。

### 6.4 Excel 的定位

- 默认**不生成、不回写**；IR 是工具内部索引。
- 需要时提供“把当前 IR 的某个子树导出到表”（单向投影），并在表头注明“派生自引擎运行事实，重新采集会变”。
- 资源表仍是人维护的**资产治理**数据；IR 是**引擎语义**数据。两者不一致时进 `conflicts`，不互相覆盖。

## 七、多引擎扩展

IR 的 kind/relation 用**引擎中立**的词（`image_tag`/`layered_image`/`attribute`/`layer_group`/`displayable`/`transform`/`transition`/`variable`/`value`/`screen`/`label`）；引擎特有的字段放 `props`（如 Ren'Py 的 `when`、`if_all`、`image_format`）。

适配器接口（示意）：

```python
class EngineAdapter(Protocol):
    engine: str                      # 'renpy'
    def fingerprint(self, project) -> str: ...
    def probe(self, project, *, mode='shadow') -> EngineObservation: ...
    def lint(self, project) -> list[Diagnostic]: ...
    def can_show(self, project, spec: str) -> bool | None: ...
```

- Ren'Py 适配器先落地；
- 以后 Godot/Unity 适配器只要产出同样的实体/关系；
- UI/校验/导出全部只读 IR，不读引擎。

## 八、建议的落地顺序（不是现在做）

| 阶段 | 做什么 | 验收（可测） |
|---|---|---|
| **P0（先做）** | facts schema v2：探针补 `layered` + `store` + `capture`；`mode='shadow'`（只拷 `.rpy`，`config.searchpath` 指回 assets）；`post_init` 回调替代 `init 999`；保留 `in-place` 给手动采集 | 真机 93 脚本 3 s 内产出 `layered/store`；`manifest_ok=True`；`aa`/`CC_OUTFIT_CYCLE` 在 facts 里；现有消费方全绿 |
| **P1（再做）** | facts → IR builder（纯函数）+ `ir.sqlite`（派生，可删）；查询 API：`attrs_of(tag)` / `groups_of(tag)` / `value_of(var)` / `provenance_of(entity)` | 实体/关系数量与 facts 对得上；删库能重建；同一项目两次采集 ID 稳定 |
| **P2（然后）** | UI 只读“事实/IR”页 + 实体徽章 + `file:line` 跳转；卡片候选/校验切 IR（feature flag，旧路可回退） | 真机 `lan aa happy` 不报错、预览正确；`lan based` 仍点名；`lint` 只作为附加证据 |
| **P3（按需）** | 注解编辑器（一个结构一条）+ 可选 Excel 投影 + 多引擎 adapter | 注解丢失不影响“不误报”；结构变化标 stale |

**不要做**：

- 不要每次敲键跑引擎（3 s 也嫌慢；编辑器里 10–15 ms 才是目标）；
- 不要用 `lint` 替掉声明层（`lan aa happy` 会冤死）；
- 不要让 `show` 运行结果当“意图正确”（它接受 `lan nope`）；
- 不要把所有 store 值原样塞进 `engine_facts.json`（大对象/隐私/版本库膨胀）。

## 九、风险与边界（必须写进产品行为）

| 风险 | 说明 | 对策 |
|---|---|---|
| **运行项目 = 执行任意代码** | `init python` 可以写盘、联网、弹窗；不是沙箱 | 子进程 + 超时 + 临时 `savedir` + dummy 音视频 + 结束进程树；首次自动采集要可见/可关；不自动对“不可信项目”跑 |
| CLI 不稳定 | 官方文档明说会变 | 版本探测 + 失败回退静态；适配器里集中处理 |
| init 顺序 | 游戏/库的 `init offset` 可到 -999..999；`init 999` 可能被同优先级抢先 | 用 `renpy.game.post_init` 回调（实测）；`hasattr` 兼容，失败退回 `init 999` |
| 语言/平台/变体 | `config.language`、`config.variants`、`config.developer` 会改变 init 分支 | `capture` 记录；IR 标注“这次是什么配置”；需要时多跑几次 |
| 动态属性 | `attribute_function` / `config.adjust_attributes` / `default_attribute_callbacks` 可任意计算 | 只记“存在 + 名字”，不宣称穷举；UI 标 `dynamic` |
| 不可序列化 | 函数/类/displayable/大对象 | 深度/节点/字节上限；只存类型 + `repr` 摘要 + 来源；完整值按需重查 |
| 影子工程成本 | 拷脚本很快，但项目可能有 `_ren.py`/`libs`/`mods` | 按官方解析顺序一并拷；`config.searchpath` 指回原 assets；实测 3 s |
| 引擎魔改 | 用户 SDK 可能改过 | `engine.version` + SDK 路径 + 内容指纹；facts 里记录；不假设官方行为 |
| 采集副作用 | 引擎会写 `cache/`、`saves/`、`errors.txt` | 影子工程 + 临时 savedir；manifest 校验；in-place 模式沿用现有“挪开→跑→还原” |

## 十、直接回答你的几个问题

**Q1：能不能在打开/更新时直接问引擎？**
能。分三档：`quit --json-dump`（2.8 s，声明清单）→ 影子探针（3 s，运行期 `LayeredImage`/store）→ `lint`（按需，诊断）。不要每次敲键跑。

**Q2：能不能把变量/自定义结构转成 IR 进数据库？**
能。`store` 的 dict/list/tuple/scalar 可序列化；`CC_OUTFIT_CYCLE`/`EXPRESSION_MAP` 实测完整拿到。函数/类只记类型和位置。IR 存实体/关系/值/出处；SQLite 做派生索引，JSON 做可移植观察。

**Q3：默认不打成 Excel？**
对。Excel 只做可选投影；IR 内部用；资源表仍是人维护的资产数据。

**Q4：引擎说不是 image、实际能跑怎么办？**
把“注册表 lint / can_show / 真实 show / layeredimage 声明 / store 词表”作为**五种证据**存进 IR；校验按问题选层；`lint` 只做附加证据，永不一票否决。真实 `show` 只证明“不崩”，不证明“意图”。

**Q5：UI 和声明怎么办？**
声明 = `.rpy`（唯一真源）；IR = 可重建观察；UI = 实体浏览器 + 证据徽章 + `file:line`；人只写**一条结构注解**（可选），不填值；注解丢了工具仍不误报。

**Q6：多引擎？**
IR 用中立 kind/relation；引擎特有字段进 `props`；`EngineAdapter` 只管 `probe/lint/fingerprint`；Ren'Py 先落地。
