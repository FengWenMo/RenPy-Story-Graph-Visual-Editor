## 建议 1 · 演出词表"人话标注"下拉：别让编剧背 `i11`【P0】

### 1.1 用户场景（编剧第一人称）

> 我在 Excel 的 Beats 表里给第 37 句配演出。立绘列下拉好用——我看图选了
> 「凌跃捷」。可是「位置」列的下拉拉下来是一排 `i11`、`i21`、`f21`、
> `truecenter`、`offscreenleft`……我只知道"上一句她站左边"，但哪一个是左？
> 我不敢乱选（选错了播出来她瞬移），只好去翻上一句填的是什么，抄过来。
> 「转场」列更玄：`dissolve`、`fade`、`pixellate` 还算眼熟，项目自定义的
> `my_flash` 是什么完全不知道。「立绘」格里的属性串 `close_happy@i11` 中
> `close_happy` 是什么表情，我得开资源图库对着缩略图猜。
> 最后一列「舞台（高级）」我根本不敢碰——那是自由文本，写错了要到导出才报错。
>
> 操作步骤具体到：打开 `剧本表_ch01.xlsx` → Beats 表 → 第 37 行 → 「位置」列
> → 点下拉 → 盯着 `i11/f21/…` 发呆 → 翻上面行抄答案。

### 1.2 为什么现在不爽（现状缺口，有据）

- 🟢 `story/beat_model.py:511` `DROPDOWN_COLUMNS` 明确：`At`/`With` 挂
  `transform` 类型候选、`Show` 挂 `image` —— **候选是资产 ID 本体**。
  `beat_model.py:509` 的注释写了设计哲学（"下拉是方便，不是牢笼"），
  但"方便"这半句对位置/转场**没有兑现**：下拉给的是内部标识，不是人话。
- 🟢 中文位置词的词表**已经存在**：`story/dsl.py` 的 `DEFAULT_POSITIONS`
  （`左`/`右边`… 人话 ⇄ 归一化 x）——卡片 UI 的位置 chip 用的就是它
  （`app/beats.py:607` 注释："位置 chip 的候选是中文人话"）。
  **同一个知识，Excel 侧下拉没有用上**——两个入口两种待遇，
  正是第五轮审计认定"最有效的找 P0 探针"的那种口径分裂（只差程度）。
- 🟢 `app/beats.py:1580-1595` 有一条非常重要的既有裁定：
  **"宁可给策划看 `close_happy`（丑但准），也不给人话（好看但会改演出）"**。
  这说明项目已经意识到"自动翻成人话"会毁数据——但它是**在"工具不许猜"**
  的前提下关上了"自动翻"的门，并没有关上**"人自己标"**的门。
- 🟢 `assets/asset_registry.py:338` 注释：transforms 表是**脚本定义的投影**
  ——表里现在连"给人备注一栏"的位置都没有被当作正经交付物
  （资源表保住用户自加列是 10-25 第六轮才修的：`story/xlsx_preserve.py`，
  能力已在，缺的是**把"人标的名字"接回候选显示**这条回路）。
- 🟢 「舞台（高级）」列（`FieldSpec('Stage'…)`，`beat_fields.py:112`）是
  多行自由文本列；`DROPDOWN_COLUMNS` 无 `Stage`（路线图 D4 已立项未决）。
- ⚪ 这条是"Excel 内句子级演出配置上手门槛"的**最痛一格**：其余列
  （Speaker/Scene/BGM…）都有候选 + 资源图库看图选 ID，唯独"位置/转场"
  这两个演出最常用的列，编剧只能靠抄上一行。

### 1.3 建议形态（低保真）

```
「位置」下拉（Excel 与卡片选择器同口径）：
  ┌──────────────────────────────┐
  │ 左 · i11          ← 人标的名 │
  │ 右 · f21                     │
  │ 居中 · truecenter            │
  │ （未标注）offscreenleft      │  ← 没人标就显示原 ID，不装懂
  └──────────────────────────────┘
```

1. **资源表 transforms 页加一列「人话名」（或复用 Notes）**：
   美术/策划自己写"左""右""特写位"。工具只做搬运与显示，
   **绝不自动命名**（铁律 9）。
2. **候选下拉/选择器的显示文本 = `人话名 · 原ID`**；没标注的显示原 ID。
   下拉的**实际值仍是原 ID**（写进格子的还是 `i11`），显示与取值分离——
   字节级上产物零变化。
3. **同机制覆盖**：转场（`With`）、立绘属性（`close_happy` 之类，资源表
   `images` 的 `Value` 列旁加人话列——10-15 "资产维度结构化"已有
   `Group`/`Value` 结构，人话列是顺流而下）。
4. **「舞台（高级）」列**：不摊列、不加下拉（M3-2 已裁定它是兜底、动它
   风险最大），只做两件轻的：
   a. 格子挂**写法模板批注**（`excel_export.py` 已有"候选注释"机制，
      `_write_spec_arg_columns` 是现成先例——同样机制挂 Stage 示例即可）；
   b. 读回/导出时，校验里给出"第 3 行那个 verb 认不出"的具体行号
      （`validate.py` L1 已有该族检查，补 `hint` 到位即可，见建议 3）。

### 1.4 代价与风险

| 面 | 估计 |
|---|---|
| 改哪一层 | **Excel 侧**：`excel_export`（下拉显示串）+ `beat_model`（候选取值/显示分离）；**UI 侧**：`asset_picker`/`sprite_grid` 显示文本；**词表**：`core/vocabulary.py` 不用动（显示层的事） |
| 三护栏 | ✅ 不改引擎（纯显示）；✅ **不改用户字节**——写进格子/写回 `.rpy` 的值仍是原 ID，只是下拉"显示"变了；✅ 能带走——人话名在资源表里，导出 IR 时可作为展示名带走（丢失也无损数据） |
| 动不动用户字节 | **不动**。验收里有逐字节判据兜底 |
| 主要风险 | ① 显示与取值串位（下拉把"左"写进格子）——必须有"写回值=原 ID"的单测；② 人话名重复（两人都标"左"）——显示 `左 · i11` / `左 · f21` 并列即可，**不合并、不报错**；③ 老表没有该列——没标注就是没标注，显示原 ID，不迁移不补空列噪音 |

### 1.5 验收判据（可测、字节级）

1. **产物零变化**：同一工程"标人话名前后各导出一次"，两份 `.rpy`
   **逐字节相同**（现有 `audit_idempotence` / 保真金标口径）。
2. **写回值不变**：Excel 里选"左 · i11"落格的字符串 == `i11`（单测断言
   格值，不是显示文本）。
3. **口径统一**：Excel 下拉、卡片位置 chip、`asset_picker` 三处的显示串
   **同一个函数产出**（一个判定只许有一处——守卫测试扫"显示文本拼装"）。
4. **不猜语义**：给 transforms 表清空人话列 → 下拉 100% 显示原 ID
   （没有"自动补中文"的任何路径；可做突变验证）。
5. **老表兼容**：10-07 前英文表头老表读回、导出、再读回，两路幂等不变。

## 建议 2 · 首启三按钮空状态：第一次打开，别给人一片空白【P0】

### 2.1 用户场景（美术/策划第一人称）

> 我是策划，同事把 `StoryGraph-1.0.0-win64` 发给了我。我解压、双击
> `StoryGraph.exe`——出来一个大窗口，中间是空的，顶上一堆按钮
> （📁 打开项目 / ➕ 导入章节 / ⤓ 导出……）我不知道先按哪个。
> 我按了「打开项目」，弹出目录选择框——"项目根"是什么？我选了解压出来的
> 文件夹，好像没反应。我又按「导入章节」，要选 `.rpy`，我手里只有 Excel。
> 五分钟后我在群里问："这东西怎么开始用？"
> （其实《快速上手_3分钟.md》就在我脚边的文件夹里，但**界面没有指向它**。）
>
> 操作步骤：双击 `StoryGraph.exe` → 看空窗 → 乱点「打开项目」→ 不知道
> 选什么目录 → 放弃。

### 2.2 为什么现在不爽（现状缺口，有据）

- 🟢 `docs/快速上手_3分钟.md` 自己写着：**"第一次打开是空的——它不自己
  找项目"**。文档承认了这个体验，但答案在文档里，不在界面上。
- 🟢 `ui_qt/main_window.py:1592-1597` 有 `EMPTY_HINT`（"别再让人对着一片
  空白猜"）——**但它是剧情图空画布上的文字提示**，且内容是"导入哪些才在
  图里"的口径说明，不是"你现在可以做哪三件事"。
- 🟢 空状态的可点入口是散的：「📁 打开项目」= 资源表路径（`main_window.py`
  文档注释明确它**只加载资源表**，"图一个节点都不加"——2026-10-22 用户
  就被这两个入口搞晕过，`docs/用户反馈与操作体验分析_2026-10-22.md` P1-4
  专门修过一轮"名称与行为不对齐"）；「➕ 导入章节」= `.rpy` 路径；
  剧本表路径在「⤓ 从剧本表写回」。**三条路都对，但没有一个"从这里开始"**。
- 🟢 分发三件套**已经齐了**（`packaging/make_release.py`：exe + demo +
  `剧本空表格.xlsx` + `快速上手.md` + LICENSE；`dist/release/` 实测在）。
  ⚪ 所以这不再是"缺材料"（竞争格局分析里的 P0-1 已落地），而是
  **"材料在包里、界面不递到手上"**——这是纯 UX 缺口，成本极低。
- 🟢 会话恢复已经在（`_boot_restore_session`，"下次打开回到上次那个项目"）——
  空状态只对**首次启动**有意义，不打扰老用户。

### 2.3 建议形态（低保真）

```
┌─────────── 首启空状态（仅无会话时全屏页） ───────────┐
│  StoryGraph · 剧情树编辑器                            │
│                                                      │
│  ① 📂 打开自带示例工程（demo）                        │
│        → 载入 demo，直接进卡片页第 1 拍              │
│  ② 📄 从我的剧本表开始（选 .xlsx）                    │
│        → 走「从剧本表写回」那条既有链路               │
│  ③ 📦 打开我的 Ren'Py 项目（选项目根）                │
│        → 走「打开项目」既有链路                       │
│                                                      │
│  ▸ 3 分钟上手（打开快速上手.md）   ▸ 我先自己看看     │
└──────────────────────────────────────────────────────┘
```

要点：
1. **三个按钮都是既有链路的转发**，不是新功能——只解决"第一步按哪"。
   ①直接把 demo 路径塞给现有载入逻辑（demo 就在 exe 同目录）。
2. 「3 分钟上手」按钮 = 用系统默认程序打开包里的 `快速上手.md`。
3. **只在"无会话恢复"时出现**；点"我先自己看看"记住本次不再显示
   （`core/session_store.py` 是现成的偏好落点）。
4. 顺序刻意是 示例 → 表 → 项目：对非程序员，"先看别人做好的"比
   "先理解什么是项目根"门槛低。

### 2.4 代价与风险

| 面 | 估计 |
|---|---|
| 改哪一层 | **只改 UI**（`main_window.py` 空状态那块 + 一个小转发函数）。链路零改动（`load_script` / `open_project` / 表写回都是现成入口） |
| 三护栏 | ✅ 全不碰：不读写用户 `.rpy`，demo 是包内只读示例 |
| 动不动用户字节 | **不动**（仅启动引导） |
| 主要风险 | ① demo 路径找不到（绿色移动版目录结构变化）→ 找不到就**隐藏 ① 并说清**（"示例不在了，去解压目录看 demo 文件夹"），不静默灰掉；② 和会话恢复打架 → 只在无会话时显示，恢复了就直奔上次的项目（现有行为不变）；③ 与"打开项目/导入章节"两按钮语义重叠 → 空状态是**首次专用**，进项目后照旧，不重构既有工具栏（P1-4 刚修过的命名对齐不回退） |

### 2.5 验收判据

1. **首启只看界面能走完**：全新解压（清空 session 偏好）→ 双击 exe →
   空状态出现 → 点① → 卡片页打开 demo 第 1 拍，全程**不看任何文档**
   （人工走查清单 + UI 自动化点到"卡片页可见第 1 拍"）。
2. **老用户零打扰**：有会话时启动路径与今天**行为一致**（不弹空状态；
   现有 boot 测试全绿不改）。
3. **找不到 demo 时不静默**：把 demo 目录改名 → 点① → 得到一句人话
   （说清去哪找），不是报错堆栈、也不是无反应（静默是最坏反馈）。
4. **无新落盘点**：`tests/test_single_write_entry.py` 的 `WRITERS` 登记
   表**零新增**（引导页不该写任何文件）。

## 建议 3 · 拒因与校验"怎么修"直达：把 `hint` 从 CLI 接到人眼前【P0】

### 3.1 用户场景（文案第一人称）

> 我改完台词点「🔎 检查逻辑问题」，控制台出来：
> `[WARNING] BGM 列写了参数却没有音乐`，然后没了。
> 好，我知道有问题了——**然后呢？**是哪一句？去哪改？"参数"是哪一列？
> 我把 20 条提醒从头读到尾，还是不知道先动哪条。
> 另一天导出被拒了，回执说"目标已存在且不是工具生成的（没有生成标记）"——
> 我连"目标"指的是哪个文件都要猜。
>
> 操作步骤：卡片页 → 「🔎 检查逻辑问题」→ 读控制台 20 行 → 不知所措
> → 群里问程序。

### 3.2 为什么现在不爽（现状缺口，有据）

- 🟢 **"怎么修"的数据已经在模型里，只是界面出口把它丢了**：
  `pipeline/validate.py:77` `Issue.hint: str  # 怎么修`，每条检查都写了
  （如 `validate.py:256`："补台词，或把这一行删掉"）；
  `validate.py:137-138` `Report.format()` 会打 `→ hint` ——
  **CLI 的 `cli.py validate` 看得到**；
  而 UI 侧 `ui_qt/window_graph_ops.py:1806-1816` 的 `_msg()` 只取
  `level` + `message`，还截断 160 字——**hint 在界面出口被静默丢弃**。
  同一件事两个出口两种待遇，正是 10-25 第六轮认定"最有效的找 P0 的探针"
  的模式（这次丢的不是数据是"怎么修"，但体验损失同构）。
- 🟢 "写盘失败说人话"先例已立：`story/xlsx_preserve.py:709-741`
  `save_workbook` 把 PermissionError/磁盘满/只读翻成人话（"这个文件可能
  正被 Excel / WPS 打开着……表还在，一个字没动"）。
  ⚪ 但这条先例**只覆盖了 Excel 写盘一个口**；门禁拒因
  （`generation_guard.py` 的 `HANDWRITTEN_TARGET` / `OPAQUE_LOST` /
  `LABEL_COLLISION` / `SOURCE_NOT_UTF8`）在 `app/tables.py:474`
  `_issue_text` 只是"一句给人看的话"，没有"你现在能做什么"。
- 🟢 诊断分组已经做过一轮（`ui_qt/diagnostics.py`：代码问题/环境未配置/
  资源未加载，2026-10-22 "一大片红字"的修复）——**分组对了，粒度还不够**：
  分组解决"先看哪堆"，没解决"这一条我怎么修"。
- 🟢 定位能力也是现成的：卡片页 `_show_index`（`window_card.py:1294`）
  能跳到第 N 拍；校验 `Issue` 的 `where` 字段带行/拍位置。**缺的只是
  把 `where` 变成可点**。

### 3.3 建议形态（低保真）

把"体检/校验/拒写"三个出口统一成一种卡片式消息（复用 `diagnostics`
的分组骨架，往下钻一层）：

```
[校验] 12 个错误 / 20 条提醒
┌────────────────────────────────────────────────────────┐
│ ✗ E101  说话人 '凌跃捷' 有台词行但内容是空的            │
│   位置：第 37 拍 · ch01.rpy:214          [跳到这一拍 →] │
│   怎么修：补台词，或把这一行删掉                        │
├────────────────────────────────────────────────────────┤
│ ! W103  BGM 列写了参数却没有音乐                        │
│   位置：第 12 拍                        [跳到这一拍 →] │
│   怎么修：补上音乐名，或清空参数                        │
└────────────────────────────────────────────────────────┘
   复制全文    只看错误    导出前必须清零的是哪些？
```

1. **每条 = 现象 + 位置（可点） + 怎么修**。数据源全是现成字段
   （`Issue.message` / `Issue.where` / `Issue.hint`），不新增模型。
2. **拒写回执同款**：`generation_guard` 的每条 issue 带上"你现在能做什么"
   （例：`HANDWRITTEN_TARGET` → "这个文件是你手写的，工具不动它。要生成
   请换个输出路径，或确认后用强制覆盖（会先备份）"）——把
   `save_workbook` 的说人话风格推广到门禁拒因。
3. **顺序按"能不能修"排**：文案自己能修（L1）在最上，要找程序的（L3）
   在最下并标"找程序"——L1/L2/L3 分层数据已在（`validate.py` 三级校验）。
4. ⚑ **更深一层（在 coder 的 menu 工作之上）**：菜单选项的**去向断链**
   （某选项 jump 到不存在的 label）今天只有 `story/exits.py` 的七档出口
   分析兜着；等控制流条能显示选项与去向后，**把"去向不在了"做成校验条目**
   （同款"现象+位置+怎么修"卡片）是顺流而下的下一步——本文只要求
   "卡片形态先统一"，menu 专项由 coder 那条线推进。

### 3.4 代价与风险

| 面 | 估计 |
|---|---|
| 改哪一层 | **UI 为主**（`window_graph_ops.check_logic` 的呈现、`diagnostics.py` 加一层条目渲染）+ **文案补充**（`generation_guard` 每个 code 补"能做什么"字典；`validate.py` 的 `hint` 已齐）；模型零改动或加一个展示字段 |
| 三护栏 | ✅ 纯呈现 + 文案；不碰生成/补丁/引擎 |
| 动不动用户字节 | **不动**（只读诊断 + 展示） |
| 主要风险 | ① hint 文案过长挤爆控制台 → 卡片可折叠，控制台仍留一行摘要（老习惯不破坏）；② "跳到这一拍"跨文件跳转（where 在别的 .rpy）→ 跳不到就说清"在哪个文件哪一行"，**不做假跳转**；③ 20 条刷屏 → 默认只展开"错误"，提醒折叠（沿用 diagnostics 的"默认只展开需要处理的"原则） |

### 3.5 验收判据

1. **hint 覆盖率**：L1/L2/L3 全部 ERROR 级条目 **100% 带"怎么修"**
   （单测扫 `validate.py` 全部 `Issue(...)` 构造点，hint 为空就红）。
2. **两个出口同一文案**：同一份工程 CLI `validate` 与界面"检查逻辑问题"
   的**逐条文本（message+hint）一致**——"一件事一个出口"守卫测试。
3. **跳转命中**：界面上点"跳到这一拍"，落在正确拍（`_show_index` 的
   index 与 `where` 对齐的单测；跨文件跳不到时给文件名+行号，断言有输出）。
4. **拒因人话字典全覆盖**：`generation_guard` 全部 code（至少
   `HANDWRITTEN_TARGET`/`OPAQUE_LOST`/`LABEL_COLLISION`/`SOURCE_NOT_UTF8`
   等）都有"能做什么"文案——新 code 无文案 → 测试红（逼人补，不静默）。
5. **零写盘**：诊断链路不新增 `WRITERS` 登记（同建议 2 判据 4）。

## 建议 4 · 自定义 transform 的声明与复用：位置变换别只活在 .rpy 里【P1】

### 4.1 用户场景（美术/演出设计第一人称）

> 剧本要一个"她从左边走进来停在三分之一处"的走位。我知道要写
>
> ```renpy
> transform walk_in_left:
>     xalign -0.2
>     linear 0.8 xalign 0.33
> ```
>
> 可我不会写 `.rpy`，程序同事在忙。我先在 Excel 里把台词和立绘填好，
> 位置列空着，备注"待走位"。三天后程序补上了 transform，我又要把 12 处
> 空位一个个填回去。更要命的是：**别的章也有"三分之一处"这个位**，
> 但项目里 transform 起名 `f33` 还是 `pos_third`？我只能再问一遍。
> 以后要迁 Unity，这些走位怎么带走？没人说得清。

### 4.2 为什么现在不爽（现状缺口，有据）

- 🟢 transform 的真源**只在 `.rpy` 里**：`assets/asset_registry.py:1424`
  注释原话——"`define e = Character(...)`、`transform i11:` 这些
  **只存在于 .rpy 里**（扫文件扫不出来）"，靠引擎事实/扫描投影进
  `transforms.xlsx`（`:1459-1465`），且是**只读投影**（`:338`
  "characters / transforms 是脚本定义的投影"）。
  ⇒ **策划没有"声明一个新位置"的入口**，只能求程序写代码。
- 🟢 `story/atl.py` 已经能**解析** transform（`parse_transforms` /
  `scan_transforms`）并算出舞台真实位置（`placement_of`）——读的能力在，
  **"写声明"的能力没有**。
- 🟢 声明-学习的先例已经打样：自定义语句有"教它升级"（`dialog_learn.py`
  + `authoring/learn_statement.py` + `cli.py learn`），而且铁律 6 保证
  "教会后产物逐字节相同"。transform 语义比自定义语句**更简单**
  （有限的属性词 + 数值），更该有声明通道。
- 🟢 "能带走"缺口同步存在：`pipeline/engine_exporters.py` 的中立 IR
  有 timeline 事件，但**自定义 transform 的语义**（哪一段是位移、时长多少）
  只能以 ATL 文本形式进损失报告（短板评估 C3：ATL 对等做不到）。
  ⚪ 但"人声明的位置语义"（"这是入场位""这是特写位"）是**引擎无关的**，
  恰好应该活在表里，而不是 ATL 里。

### 4.3 建议形态（低保真）

**声明在表、生成在工具自己的文件、`.rpy` 一个字节不动。**

```
资源表 transforms 页（现在是只读投影，加"声明区"）：
┌──────┬──────────┬─────────┬─────────┬──────────┐
│ ID   │ 人话名   │ 位置值  │ 说明    │ 来源     │
├──────┼──────────┼─────────┼─────────┼──────────┤
│ i11  │ 左       │ (投影)  │         │ 脚本·投影│
│ f21  │ 右       │ (投影)  │         │ 脚本·投影│
│ third│ 三分之一 │ xalign 0.33│ 停点 │ 本表声明 │ ← 策划新加
└──────┴──────────┴─────────┴─────────┴──────────┘
```

1. **声明行 = 人填**：ID / 人话名 / 位置值（用 `dsl.py` 的位置词或
   显式 `xalign n`，二选一，不猜）/ 说明。
2. **生成落点 = 工具独占文件**（与 S2 选择点同哲学："menu 的家 =
   编排层文件，**永不写进剧本文件**"）：
   例如 `game/storygraph_transforms.rpy`，带生成标记、过
   `generation_guard`（走 `write_generation`，进 `WRITERS` 登记）。
   用户手写的 `transform.rpy` **一个字节不动**。
3. **立即进下拉**：声明保存 → `At`/`With` 候选立刻出现 `third`
   （显示文案交给建议 1 的人话名机制）。
4. **能带走**：声明行有"人话名+位置值"，导出 IR 时作为**位置语义事件**
   附带（Unity 侧至少知道"有个叫 third 的停点在 0.33"），损失报告里
   明确写"复杂 ATL 曲线未迁移，仅迁移停点"。
5. **防撞**：声明 ID 与脚本投影重名 → **拒绝声明并点名哪一行重了**
   （铁律 4：说"不知道"好过猜一个）。

### 4.4 代价与风险

| 面 | 估计 |
|---|---|
| 改哪一层 | **Excel/资源表**（声明区读写，`xlsx_preserve` 的保住机制现成）+ **生成侧**（新文件的渲染，落 `story/` 或 `app/`，过门禁）+ **候选链路**（registry 的 transform 候选并入声明行）+ IR 导出（可后置） |
| 三护栏 | ✅ 不改引擎（生成的是标准 Ren'Py transform 语句，引擎原生认）；✅ **不改用户字节**（只写工具独占文件，带生成标记）；✅ 能带走（声明是引擎无关的位置语义） |
| 动不动用户字节 | **不动用户文件**；动的是工具自己的生成文件（有标记、可重建、可删） |
| 主要风险 | ① 声明的 transform 与脚本里同名定义冲突 → 生成前扫描、重名拒写（判据 3）；② "位置值"写错播出来不对 → 校验只查语法（数值范围），**效果对不对由人看预览**（舞台预览已能算 `placement_of`）；③ 复杂曲线（`linear`/`ease`/多段）声明表表达不了 → **表只表达停点/静态位**，复杂的仍走程序写 `.rpy`，界面说明里写清边界（不许半吊子模拟） |

### 4.5 验收判据

1. **用户字节不动**：声明前后，用户全部手写 `.rpy` 的 sha256 **逐字节
   不变**（全目录对账，复用保真证据链口径）。
2. **生成文件自证**：`storygraph_transforms.rpy` 带生成标记、进 `WRITERS`
   登记、二次生成**逐字节幂等**；删掉它 → 从声明重建 → 与之前逐字节相同。
3. **重名即拒**：声明 `i11`（脚本已有）→ 拒绝 + 点名冲突来源文件行号，
   产物零写（要么全对要么完全不动）。
4. **下拉即时可见**：声明保存 → 不重启、不重载，`At` 候选含新 ID
   （UI 测试）。
5. **教会不改字节**（铁律 6 同款）：声明存在与否，**手写脚本的导出产物
   逐字节相同**（声明只影响工具自己的生成文件与候选）。

## 建议 5 · 协作痕迹上桌面：谁锁着哪句，别藏在弹窗里【P1】

### 5.1 用户场景（编剧第一人称，50 人团队）

> 我打开 ch03 想改第 58 句，改到一半保存——系统说这句被锁了？
> 原来小 A 一小时前就开始改这句，锁在协作库里，但**我在卡片列表上
> 完全看不出来**。我要么去点「协作」弹窗翻锁列表（哪一句/谁锁的/租约
> 三列，`dialog_locks.py` 做得挺好，可我改台词时不会想到先去那里报到），
> 要么改完才发现白干。
> 还有一种更闷的：组长问"昨天谁把第 12 句的语气改了？"——审计库里
> 明明有记录，可我要从卡片页跳到协作弹窗再翻审计，**没有人顺手回答
> "这一句最后是谁动的"**。

### 5.2 为什么现在不爽（现状缺口，有据）

- 🟢 协作能力本身**已经很扎实**：`collab/collab_store.py`（SQLite WAL +
  行级锁 + 15 分钟租约 + 角色 + 审计）；冲突界面按用户口径打磨过
  （`ui_qt/dialogs_collab.py`：两栏不显示 base、"你和 TA 改了同一句"、
  "两句都留"、部分提交）——**判断层没问题，露出层有问题**。
- 🟢 锁的展示只在**专门弹窗**：`ui_qt/dialogs_locks.py:145` 表头
  "哪一句 / 谁锁的 / 租约"，还带"租约还剩几分钟直接写出来"的好设计——
  但它是一个要主动打开的对话框。
- 🟢 卡片列表行的文本（`ui_qt/window_card.py:726` `_row_text`）只显示
  拍号/台词/语句/空拍说明——**没有任何协作状态位**。我逐行核对过这个
  函数：没有 locked/author 字段。
- 🟢 导出回执（`app/tables.py` 的 note/回执族）说"改了几行/被保住几行"，
  **不说"这次写入碰到谁的锁/谁最近动过这几行"**。
- 🟢 铁律 5（绝不静默全量覆盖）与协作冲突检测都指向同一个 UX 原则：
  **冲突要在人动手之前就看见**，不是写入失败之后。
- ⚪ 50 人团队的现实是：不可能人人先去"协作"页报到再改稿。
  让协作痕迹**长在编辑现场**（列表行、卡片头、导出回执），
  是把"租约+审计"从防御机制变成协作体验的最短一步。
  （短板评估 C2 说得对：实时协同做不到——但**看得到**做得到。）

### 5.3 建议形态（低保真）

```
卡片列表（只加行尾徽章，不动行文本本体）：
   57  小雨：我们真的要进去吗？
   58  凌跃捷：……嗯。                🔒小A · 还有 9 分钟
   59  旁白：门开了。                  ✎小B 昨天改过
```

1. **行尾徽章两种**：`🔒谁 · 还剩几分钟`（直接用 `dialog_locks.lease_text`
   的文案真源，同一句话不许两处各写一份）；`✎谁 · 何时改过`（审计里
   最近一次该行变更）。
2. **卡片页顶部条**：当前拍被别人锁着时，卡片编辑区上方一条
   "这句小 A 正在改（还有 9 分钟）——你可以看，改了会怎样说清"
   （租约过期可接手，语义照抄 `dialog_locks`，不发明新规则）。
3. **导出回执加一行**："本次写入涉及的 12 句里，2 句昨天被小 B 改过"
   （只报告，不拦截——拦截是锁机制的活）。
4. **不做**：不做强制锁提示弹窗（改稿心流最忌打断）、不做实时头像/
   光标（那是实时协同的皮，架构上不成立）、不在列表上显示完整审计
   （点徽章才展开详情）。

### 5.4 代价与风险

| 面 | 估计 |
|---|---|
| 改哪一层 | **UI 为主**（`window_card._row_text`/徽章绘制 + 卡片页顶条 + 回执文案）+ **查询薄层**（collab 现有 `status_summary`/审计查询直接喂，`collab_store` 判断逻辑零改动） |
| 三护栏 | ✅ 纯展示；锁语义/冲突算法**一行不动**（`dialogs_collab.py` 开头就写明"界面不碰 SQL"，本建议同样遵守） |
| 动不动用户字节 | **不动**（只读 collab 库） |
| 主要风险 | ① 700+ 拍列表逐行查锁卡顿 → 批量一次查询 + 缓存（分级删除那轮的教训："O(1) 判据不渲染"同样适用于锁徽章）；② 本地用（没接 collab）满屏空徽章 → 无 collab 库/无锁时**一个徽章都不画**；③ 徽章与弹窗文案漂移 → 文案取自 `lease_text`/`lock_row_text` 单一真源，守卫测试比对两处字符串 |

### 5.5 验收判据

1. **文案单源**：徽章上的"还剩几分钟"与 `dialog_locks` 弹窗里同一锁的
   文案**逐字符相同**（直接调同一函数，或测试断言相等）。
2. **看不见即不存在**：无锁/无 collab 时列表渲染结果与今天**逐字节
   相同**（行文本本体不动，只在有徽章时追加后缀——追加与否的测试）。
3. **性能线**：700 拍列表开启徽章后，列表刷新时间相对基线劣化 < 20%
   （或单次批量查询断言只发 1~2 条 SQL）。
4. **只读**：徽章/顶条/回执链路对 collab 库**零写**（审计行数不变）。
5. **租约语义不漂移**：租约过期显示与弹窗同一档（"过期可接手"字样同源），
   界面不自创"自动续锁"之类的动作。

## 不建议做的（看起来很美，但会毁掉这个产品）

> 这一节比建议本身更能校准方向。三个高诱惑提案，逐个否掉。

### ❌ 一、实时协同 / 自动合并（"做成 Google Docs"）

**诱惑**：50 人团队，"两个人同时改一句"听起来是刚需；竞品对照表里
协作是我们的卖点（SQLite 租约），升级成实时协同像顺水推舟。

**为什么否**（`docs/短板可行性评估_2026-10-23.md` C2，我复核后同意）：
1. 文本序列 CRDT **不理解 Ren'Py 的块体语义**——`menu:`/`if:` 的归属由
   缩进决定，两人一个插选项一个插 label，合出来的文本字节合法、
   **语义上把选项挂错分支**。这是静默毁剧情，比冲突难受一百倍。
2. CRDT 必须在真源层做，而真源是 `.rpy`（铁律 1）。把 Excel/IR 变成
   真源 = 当场放弃"接管已有项目"这条最硬的赛道，滑向 Excel2Rpy。
3. "不改用户字节"与"无锁并发写"**数学上互斥**：受控补丁基于当前文件
   状态逐行配对，第 2 个写必然基于过期状态——只能覆盖或拒绝。
   租约锁不是缺陷，是承认现实。

**替代**：建议 5（把冲突与锁**看得到**）+ 既有冲突清单（"你和 TA 改了
同一句"，口径已按用户原话打磨得很成熟）。做到"冲突绝不静默、选择
预填、可部分提交"就够舒适了。

### ❌ 二、AI 自动补全演出 / 自动翻人话（"帮我把这句的情绪配上立绘"）

**诱惑**：让 AI 读台词自动填表情/位置/转场；或自动把 `close_happy` 翻成
"开心·微笑"显示。竞品 Excel2Rpy 有 TTS+自动翻译，我们像该跟。

**为什么否**：
1. 铁律 9：**本工具不猜语义，意思由人标注**。自动配表情错一次，
   策划就再也不信表里的演出列——而"工具装懂"恰恰是全项目最忌讳的
  （`app/beats.py:1589` 的裁定原话："宁可给策划看 `close_happy`
  （丑但准），也不给人话（好看但会改演出）"）。
2. 自动翻译写回 = 用概率输出覆盖确定性文本，**直接违反"不改用户字节"**。
  Ren'Py 官方 translation 用正文哈希做 ID、自己都警告"改台词要非常小心"
  （短板评估 B1 引述）——行业都栽在这。
3. 会话内 AI 助手（`panel_ai.py`）的定位是**对话辅助**，不是自动改表。

**替代**：要 AI 可以，但只允许它出现在两个位置——① 提**建议**、人点
确认才落格（且落在工具列，不落生成列）；② 建议 1 的"人话名"由**人**标。
TTS/自动翻译若要做，走短板评估 B1 的"通道"定位（稳定 key + 占位符保护），
且前置是行身份（§4），不是接个 API 完事。

### ❌ 三、"格式化/美化"用户脚本（顺手把缩进、引号、空行统一了）

**诱惑**：程序同事的 `.rpy` 风格不一，工具解析完"顺手整理"一遍，
diff 好看，回写整齐。

**为什么否**：
1. **这是对用户字节的直接攻击**。护栏二的全部价值就在"没碰过的行
   逐字节不变"——一旦允许"美化"，就没有任何办法向用户证明
   "它真的没碰我的代码"（竞争格局分析：这是唯一抄不动的优势，
   也是最难被相信的优势）。
2. 历史实测（竞争格局分析 §3 引）：全量重生成一章就丢 18 行/多 13 行/
   头部重复/参数被吃掉。"美化"与"重生成"只有语气差别。
3. 行尾注释、`#` 块、`U+2028` 软回车、混合 CRLF、非 UTF-8 字节——
  （10-25 三轴审计的全部地雷）**格式化器踩中任何一颗都是无声毁数据**。

**替代**：需要"看清差异"就用 diff（改用户 `.rpy` 先出 diff、未确认零写，
铁律 5 已有）；需要风格约束让程序配 Ren'Py lint / 编辑器格式化，
**在工具之外做**，工具保持"外科手术刀"。

## 我认为最值得先做的一条

**建议 3（拒因与校验"怎么修"直达）。** 理由：

1. **成本最低、确定性最高**：数据全在（`Issue.hint` / `where` /
   门禁 code），CLI 已经在打 hint，UI 只是把它丢了——这是接线不是造轮子。
2. **它兑现产品哲学的最后一公里**："静默是最坏的反馈"已经做到了
> "不静默"（有报错、有分组），但**"说出来之后人不知道怎么办"**
   是半个静默。补上"怎么修 + 跳得到"，50 人里 40 个不写代码的人
   才真正接得住这些报错。
3. **它是其他建议的放大器**：建议 1 的 Stage 列模板批注、建议 4 的
   重名拒写、建议 5 的冲突提示——最终都会汇到同一种"现象+位置+怎么修"
   的卡片形态上。先立这个形态，后面每条都顺流。
4. **护栏零风险**：纯呈现层，不动生成/补丁/引擎，验收判据里连
   `WRITERS` 都不许新增。

建议 1（人话名下拉）紧随其后——它是"Excel 精确编排演出"这条北极星
在日常填表里最疼的一格；若团队本周就要填表干活，先做 1 也成立。
两条都做的话顺序是 **3 → 1 → 2 → 4 → 5**（3、1 服务"每天用"，
2 服务"第一次用"，4、5 服务"50 人一起用"）。
