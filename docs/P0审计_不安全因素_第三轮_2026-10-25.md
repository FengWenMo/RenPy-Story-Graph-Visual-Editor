## 2. 第三轮新发现（均已修复 + 复测通过）

### 2.1 P1-A 新建章节编码腐蚀：非 UTF-8 `.rpy` 加第二个 label

**位置**：`storygraph/ui_qt/window_nodes.py`（`_write_new_chapter`）
→ 病根在 `storygraph/story/source_style.py`（`read_text` 的 `errors='replace'`）。

**攻击链**（`tools/_p0_audit_round3_probe.py` A 组，修前逐字输出）：

```
原文件 55 字节，含非法字节 0xE9：True
返回：'...\game\ch01.rpy'            ← 返回成功路径
状态栏消息：[]                       ← 无声
写后 81 字节
0xE9 还在吗：False
出现 U+FFFD 了吗：True               ← 坏字节被换成 U+FFFD 写回
.bak 备份：[]                        ← 不可恢复
```

Ren'Py 只认 UTF-8，但这种文件已经在用户盘上（别的工具遗留、别处拷来的）。
工具读它 → `errors='replace'` 把坏字节换成 U+FFFD → 连写 → 用户的一个坏字节
变成三个 UTF-8 字节的 U+FFFD，`git diff` 显示这一行"被改过"但用户从没碰过它。
`write_text_atomic` 默认 `backup=False`，原字节不可恢复，状态栏零提示。

**同 hazard 两种待遇（对照组）**：`choice_point.py` 已修——严格 UTF-8 解码、
解不开明确拒绝、字节未动。同一个仓库里两条追加路径两种待遇，本身就是
"修复不完整"的信号。

**修法**（`d4a60d0`）：`_write_new_chapter` 读之前先严格解码探一次，
解不开就拒写、字节不动；同时补上 P2-3 的 label 校验（`is_valid_label`）
与写前复读。

**复测**（修后同探针）：

```
返回：''                                    ← 不再返回成功路径
状态栏消息：["ch01.rpy 不是 UTF-8（Ren'Py 只认 UTF-8）：第 26 字节起。
              先另存为 UTF-8，再往这个文件里加章节。"]   ← 说清 + 带坐标
0xE9 还在吗：True   出现 U+FFFD 了吗：False    ← 字节未动
```

（探针 A-1 显示 `[FAIL]` 是断言"腐蚀存在"——腐蚀消失正是修复生效。）
**验收通过。**

### 2.2 P1-C 引号形式说话人静默旁白化

**位置**：`storygraph/authoring/txt_import.py`（`_detect_speaker` /
`_looks_like_speaker` / `_suspect_speakers`）。

**现象**：txt 导入认两种说话人形状——冒号（`小雨：台词`）和引号
（`小雨"台词"`）。冒号形状有 `_suspect_speakers` 警告网（认不出会**提案 +
警告**）；引号形状只在角色表命中或全大写缩写时才算说话人，其余**静默判
旁白**——无 `define` 提案、无警告、台词原样进产物。编剧用引号形式写台词
很常见（视觉小说圈 `Name"line"` 是通行格式），认不出 → 台词失去说话人，
用户以为导入了，回游戏发现全员旁白。

| C-2 | 空 | `小雨"你回来了。"` | 静默旁白（FAIL） |

| C-4 | 非空（小雨） | `小雨"台词"` | 静默旁白（FAIL） |

| C-6 对照 | 非空 | `小雨：台词` 冒号 | 提案 + 警告（网存在） |

   2 行生成标记（`GENERATOR_MARKER` + 空行），插入后每一行索引错位，
   未碰的行全被判成"意外改动"。改为**构造期望全文**：
   `期望 = [标记, 空行]（首行无标记时才插）+ bl 里那一句台词被替换`。
2. **引号结构**：台词行替换要行内局部换（`old_text → EDIT_TEXT`），
   保留行的引号 / 说话人，不能整行覆盖。
3. **BOM 位移**：BOM 文件插标记时，`read_text` 剥 BOM、`apply` 把 BOM
   加回**全文最前** —— BOM 落在标记行前，原文第一行的 BOM 消失
   （盘上仍只有一个 BOM，位置正确）。期望要照这个构造。

修正后：**阶段一 0 异常、阶段二 0/12**（9 个可改文件全 ✓，含 BOM+CRLF 的
`script.rpy` / `rhythm_game_start.rpy`）。

教训（与项目"接受判据校准"原则一致）：**探针的期望值也会错**——
这轮三次踩到（+2 位移、引号、BOM），每次都是先怀疑产品、逐层二分后
才定位到判据自己。判据必须来自"构造期望全文"这种可解释的形式，
不能靠"同索引 diff"这种隐式假设。
