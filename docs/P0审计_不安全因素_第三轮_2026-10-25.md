## 2. 新发现（未修，需决策）

### 2.1 P1-A 新建章节编码腐蚀：非 UTF-8 `.rpy` 加第二个 label

**位置**：`storygraph/ui_qt/window_nodes.py:113-184`（`_write_new_chapter`）
→ 病根在 `storygraph/story/source_style.py:195`（`read_text` 的
`errors='replace'`）。

**攻击链**（`tools/_p0_audit_round3_probe.py` A 组，逐字输出）：

```
原文件 55 字节，含非法字节 0xE9：True
返回：'...\game\ch01.rpy'            ← 返回成功路径
状态栏消息：[]                       ← 无声
写后 81 字节
0xE9 还在吗：False
出现 U+FFFD 了吗：True               ← 坏字节被换成 U+FFFD 写回
.bak 备份：[]                        ← 不可恢复
含 label ch02：True                  ← 功能"成功"了
原有行还在：True
```

**为什么是问题**：Ren'Py 只认 UTF-8，但这个文件已经在用户盘上（可能是别的工具
遗留、可能是用户从别处拷来的）。工具读它 → `errors='replace'` 把坏字节换成
U+FFFD → 连写 → **用户的一个坏字节变成三个 UTF-8 字节的 U+FFFD**，
`git diff` 显示这一行"被改过"但用户从没碰过它。而且 `write_text_atomic`
默认 `backup=False`，原字节**不可恢复**，状态栏**零提示**。

**同 hazard 两种待遇（对照组）**：`storygraph/story/choice_point.py:251-257`
已修——严格 UTF-8 解码、解不开明确拒绝、字节未动：

```
apply 返回：ok=False error=这个选择点文件不是 UTF-8（Ren'Py 只认 UTF-8）：...
文件字节未动：True
```

**修法建议**（三选一，建议 ①）：
① `_write_new_chapter` 读之前先 `detect()`/严格解码探一次，非 UTF-8 就按
choice_point 的口径拒绝并说清（功能不受影响——那种文件本来就该先转码）；
② `write_text_atomic(p, ..., backup=True)`（只救"可恢复"，腐蚀照旧）；
③ 把 `read_text` 整体改成严格解码（影响面最大，所有调用方要逐一确认，
**不建议**单为这一处动）。

**定 P1 不定 P0 的理由**：不改结构、不吞行、label 追加功能本身正确；
坏字节→U+FFFD 是"内容损坏"而非"代码回退"，且有 U+FFFD 这个可见痕迹
（git diff 能发现）。但**无备份 + 无声**让它满足 fail-unsafe，若并行工作者
认同，可升 P0。

### 2.2 P1-C 引号形式说话人静默旁白化

**位置**：`storygraph/authoring/txt_import.py`（`_detect_speaker` :510-537、
`_looks_like_speaker` :548-576、`_suspect_speakers` :813-814 只认冒号形状）。

**现象**：txt 导入认两种说话人形状——冒号（`小雨：台词`）和引号
（`小雨"台词"`）。冒号形状有 `_suspect_speakers` 警告网（认不出会**提案 +
警告**）；引号形状只在 `_looks_like_speaker` 返回 True（角色表命中，或
`^[A-Z][A-Z0-9]{0,7}$` 全大写缩写且角色表非空）时才算说话人，
其余**静默判旁白**——无 `define` 提案、无警告、台词原样进产物。

**复测**（`tools/_p0_audit_round3_probe.py` C 组 6 用例，4 FAIL）：

| 用例 | 角色表 | 行 | 结果 |
|---|---|---|---|
| C-1 | 空 | `MOM"你回来了。"` | 静默旁白（FAIL） |
| C-2 | 空 | `小雨"你回来了。"` | 静默旁白（FAIL） |
| C-3 | 非空（MOM=妈妈） | `Mom"台词"` | 静默旁白（FAIL） |
| C-4 | 非空（小雨） | `小雨"台词"` | 静默旁白（FAIL） |
| C-5 对照 | 空 | `MOM"台词"` 全大写 | 提案 + 警告（网存在） |
| C-6 对照 | 非空 | `小雨：台词` 冒号 | 提案 + 警告（网存在） |

**为什么是问题**：编剧用引号形式写台词的写法很常见（视觉小说圈
`Name"line"` 是通行格式）。认不出 → 台词**失去说话人**（`"台词"` 变成无主
旁白），且**没有任何提示**——用户以为导入了，回游戏发现全员旁白。
与 P1-A 一样是 fail-unsafe，但损坏的是**语义**不是字节，且导入产物是
`write_generation` 的新文件（不覆盖用户既有 `.rpy`，最坏重导一次即可），
故定 P1。

**修法建议**：`_suspect_speakers` 的网扩到引号形状（与冒号同口径：
认不出 → 列提案让人确认，不静默判旁白）。这是纯导入侧改动，不碰落盘安全面。

### 2.3 P1-5b 删源行遗漏逐行还原：P1-5 修复只传了一半调用点

**位置**：`storygraph/app/source_line_delete.py:301`
（`style.apply(plan.new_text)` 缺 `source=path`）。

**背景**：并行工作者给 `source_style.apply()` 加了 `source=` 逐行还原后，
`control_route`（4 处）/ `control_branch` / `control_takeover` /
`choice_point` / `window_nodes` / `session_export` / `compile` /
`generation_guard` **都传了**；`source_line_delete` 与
`graph/commands`（undo/redo 10 处）**没传**。

`graph/commands` 不传有正当性：undo/redo 恢复的 `old_text` 在读取时就已经
被 `read_text` 统一成 LF，**每行 EOL 信息在内存里本来就不存在**，
逐字节还原 undo 需要另一套设计（计划链里保存原始 EOL），不是这一处签名的事。

`source_line_delete` **没有这个正当性**：它是与 `control_route` 同级的
**原地改写点**（删掉剧本里一跳），`plan.new_text` 就是从当前文件算出来的，
盘上原文就在手里——传个 `source=path` 即可，属于修复遗漏。

**实证**（`tools/_p0_audit_srcline_mixed_probe.py`，前 4 行 CRLF 后 3 行 LF
的混合文件，删掉第 3 行 `jump target_a` 一拍）：

```
计划 ok：删掉 ch01.rpy 第 3 行（jump target_a）
apply ok=True
删后各行 EOL：['CRLF','CRLF','CRLF','CRLF','CRLF','CRLF']   ← 全被统一
期望：        ['CRLF','CRLF','CRLF','LF','LF','LF']
未碰行 EOL 全部原样：False
★ 缺口确认：删一拍把全文换行统一了
对照：单风格 CRLF 文件删一拍 → 仍全 CRLF（老路径无回归）
```

**定级 P1**：与 P1-5 同性质——用户没碰的 3 行 LF 静默变 CRLF，
git diff 脏、版本对照乱；不吞行不改结构。**修法**：一处加
`source=path` 参数 + 回归测试（探针可直接改成断言）。
