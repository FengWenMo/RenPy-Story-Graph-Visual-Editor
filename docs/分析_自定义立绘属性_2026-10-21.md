# 排查：`show lan base_swimsuit happy` 没教过时，工具认不认得？（2026-10-21）

> 用户的怀疑：**"没有 rules.json 时，它能不能识别出这是未定义的？感觉这里会有点问题。"**

先给结论：

| 问题 | 答案 |
|---|---|
| 会不会把它改坏？ | **不会**（四条实测，见第二节） |
| 认不认得"未定义"？ | **认得**，但分两档（见第三节） |
| 哪一档原来缺了？ | **导出时不提**，只有跑体检才报 —— 已修 |
| `rules.json` 管这个吗？ | **不管**。它声明的是自定义**语句**，不是立绘属性 |

---

## 一、先把两件事分开

| 你说的 | 实际归谁管 |
|---|---|
| `rules.json` / `storygraph.rules.json` | **自定义语句**：`dust smoke`、`camera pan` 这种引擎不认识的**动词**（`cli learn` 写进去的就是它） |
| `show lan base_swimsuit happy` 的 `lan` / `base_swimsuit` / `happy` | **资源表** `images.xlsx` 的 `Tag` 列和 `Attributes` 列 |

所以"没写 rules.json"这件事，对 `show` 行**没有影响** —— 它本来就不走那条路。

---

## 二、会不会改坏：四条实测（`tools/probe_custom_show_attrs.py`）

| 场景 | 表里「立绘」列 | 零改动往返 | 改一句台词后 | 改立绘列（happy→sad） |
|---|---|---|---|---|
| `show lan base_swimsuit happy` | `lan base_swimsuit happy` | **逐字节相同** | `show lan base_swimsuit happy`（原样） | `show lan base_swimsuit sad` ✔ |
| `show lan happy` | `lan happy` | 逐字节相同 | 原样 | `show lan sad` |
| `show lan` | （空） | 逐字节相同 | 原样 | — |
| `show lan base_swimsuit happy at left` | `lan base_swimsuit happy@left` | 逐字节相同 | 原样 | `show lan base_swimsuit sad at left` ✔ |

**关键那条是最后一列**：改立绘只替换你动的那一个词，`base_swimsuit` 保住了。
（这靠的是"表里存整串、导出按整串写回"，不是靠猜。）

顺带查了：立绘列**没有挂数据验证（下拉）**，所以不存在"从下拉里选一下就把
自定义属性抹掉"那种事。候选是常见取值，不是白名单。

---

## 三、认不认得"未定义"：原来有两档，只是第二档没在导出时说

`cli validate` 的判据（`validate.py` 的 `_image_ref_issue`）分得很细：

| 情况 | 报什么 |
|---|---|
| 整串都查不到（连 tag 都没登记） | `W110` image `'…'` 未登记 |
| **tag 认识、但属性组合没声明** | `W111` 图片 `'lan base_swimsuit happy'` 的**属性组合未在资源表声明（tag 已存在）**<br>→ 提示：合成立绘按 tag+属性合成；要精确管理就在 images.xlsx 登记该组合 |

实测输出（有 `images.xlsx` 但只登记了 `lan happy` / `lan sad`）：

```
! W111 [ch01.0001] 图片 'lan base_swimsuit happy' 的属性组合未在资源表声明（tag 已存在）
    → 合成立绘按 tag+属性合成；如需精确管理可在 images.xlsx 登记该组合
```

**这条提示是准的**：它知道你写的是合成立绘，也知道 `base_swimsuit` 没登记，
并且明确说"Ren'Py 会按 tag+属性合成，不用登记也能跑"。

### 缺的那一档：导出时不说

`export_table` 的 warnings 只来自生成门禁，**不含这条** —— 用户在界面上
改完直接导出，看不到"这个属性组合资源表里没有"。

**已修**（`app/tables.py` 新增 `_with_image_ref_warnings`）：导出回执里补一句：

```
图片 'lan base_swimsuit happy' 的属性组合未在资源表声明（tag 已存在，ch01.0001）
  —— 合成立绘按 tag+属性合成；要精确管理就在 images.xlsx 登记这个组合
```

### 为什么不直接复用 `validate_level1`

试过，会**得到不一致的第二套结论**：`validate_level1` 的判据要看 `Beat` 上的
`raw` / `stage` / 角色定义上下文；而"从 Excel 读出来的拍"这些字段是空的。
同一份剧本：

- 从 `.rpy` 解析的拍 → `W111`（tag 认到了）
- 从 `.xlsx` 读出来的拍 → `E103`（tag 都没认到，降级成"未登记"）

也就是说**同一条 `show`，体检说一套、导出说另一套**。所以导出这条路改成
只做一件窄而确定的事：拿资源表的 `Tag` / `Attributes` 两张清单逐条比对。

判据见 `tests/test_show_attr_warnings.py`（5 条）：
组合没声明 → 有的说 / 组合已声明 → **一声不响** / tag 都不在 → 措辞要能分开 /
老表没填 Tag → 一声不响 / 没有资源表 → 一声不响。

---

## 四、想让它"认识"这个写法，需要做什么

不是写 `rules.json`，是把**组合**登记进 `images.xlsx`：

| ID | Path | Tag | Attributes |
|---|---|---|---|
| `lan_bs_happy` | `game/images/lan/bs_happy.png` | `lan` | `base_swimsuit happy` |

登记之后：
- 这一格进下拉候选（策划不用手打）；
- 体检不再报 W111；
- 导出回执不再提示。

**不登记也完全能跑** —— Ren'Py 的 layeredimage 本来就是 `tag + 属性` 合成，
文件在不在、组合叫什么，由 `layeredimage lan:` 里的声明决定。工具这边
"登记"只是为了**能对账**（缺文件、废弃资源、引用次数）。

---

## 五、一个已知边界（没修，记下来）

同一个 `show`，`.rpy` 路径与 `.xlsx` 路径给出的诊断码不同（`W111` vs `E103`），
根因是"从表读出来的拍"缺少 `raw` / `stage` / 角色定义上下文。

这会让**体检与导出对同一句话给出不同措辞**。当前的处理是"导出那边不套用体检
的判据，只做窄比对"，所以用户看到的两句话都是对的，只是措辞不同。

要彻底统一，得让 `import_beats_from_excel` 把 `raw` 与 `stage` 也还原出来 ——
那是另一件事，单独排。
