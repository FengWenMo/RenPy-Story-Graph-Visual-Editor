## 二、为什么"金标审计 + 重录"**不值得做**

路线图步骤 1 的前提是"当前行为可能就是错的，别把 bug 固化进金标"。这个担心本身是对的，
但它有两个前提，实测都不成立：

| 前提 | 实测 | 后果 |
|---|---|---|
| 真机上**存在可疑差异**要人判 | **0 处**（55/55 逐字节相同，全量路径 0 内容差异） | 审计没有对象，只剩"确认" |
| 金标**可人审** | 10 个金标里 8 个是 sha256 指纹（`golden_scan_fingerprint.txt` 1MB） | 人眼审不了；"审"只能靠工具，而工具已经给了 0 |

**更关键的是第三条**：重录金标 = 把"当前工具的产物"换成"当前工具的产物"。
- 当前行为**对** → 零信息增益；
- 当前行为**错** → 重录就是**把 bug 固化成基准**，正是路线图担心的那件事。

⇒ **本轮不重录任何金标，`skipif(REAL)` 白名单一个字不改。**
8 个金标的职责改为"**本机回归网**"（它们在本机仍然有效，`patch_golden` 覆盖 53 文件 × 3 条路径），
不再承担"对外证明"的职责 —— 那件事交给可移植样本。

> 这也修正了 [`短板可行性评估_2026-10-23.md`](短板可行性评估_2026-10-23.md) 的一处措辞：
> 它说"逐字节零丢失**现在没有任何自动化护栏**"。准确说法是：
> **有护栏，但护栏全部拴在 `D:\...` 这个绝对路径上** —— 换机就静默失效。
> 差别很大：不是"没测过"，是"测过但带不走"。

## 四、这一轮做了什么

### 4.1 报告工具：`tools/fidelity_report.py`

和 `audit_byte_exact.py` 分工，不合并：

| | `audit_byte_exact` | `fidelity_report`（新） |
|---|---|---|
| 用途 | 冒烟 | **交证据** |
| 差异 | 只给**第一处** | **全部**（unified diff，所有 hunk） |
| 行级 | 无 | **丢了哪几行 / 多了哪几行 / 改了哪几行**（带行号） |
| 分档 | 有差异 / 没差异 | **identical / layout / content** |

**为什么要分档**：全量重生成本来就会重排空白（P1-1 的原话：
"顶层语句之间各插一个空行、行尾空格删除"）。把排版差异和内容差异混成一个
"有差异"的数字，等于让真 bug 淹在噪音里 —— 2026-10-18 那次审计就是这么漏的。

判定口径（写进 [`契约速查`](契约速查_storygraph.md) §33）：

| 判定 | 定义 | 谁该紧张 |
|---|---|---|
| `identical` | 剥生成标记后**字节相同** | 没人 |
| `layout` | 只剩**空白**差异（空行 / 行尾空格 / 换行符 / 末尾换行） | 补丁没跑起来时出现 → 查"为什么退回全量" |
| `content` | 行级内容不同 | **真 bug** |

退出码：`0` = 全 identical（`--allow-layout` 时 layout 也算过）；`1` = 有 content/error；`2` = 用法错。

### 4.2 四份真实结构样本：`tests/fixtures/fidelity/`

每份文件头两行写"**它测什么** + **来源**"。台词全部是 `台词A/B/C…` 占位。

| 样本 | 它带着什么 | 真机里哪类文件有它 |
|---|---|---|
| `01_python_block.rpy` | `init python:` + label 内 `python:` + 块内注释 + `$` 赋值 + 行尾注释 | 5 个文件（历史事故高发区） |
| `02_menu_nested.rpy` | menu + **选项体里再套 menu** + 选项体里 `jump` | 6 个文件 |
| `03_atl_transform.rpy` | 顶层 `transform` + 带参 transform + `block/repeat` + `with` | 10 个文件 |
| `04_conditional_option.rpy` | 菜单选项带 `if` 条件 | **真机 0 个** → 已知缺口（见 §五-A）|

> **为什么是"合成"而不是"真机脱敏"**（这一条与路线图步骤 2 不同，理由要写清楚）：
> ① 真机 55 个文件里，**结构性**的东西（`python:` / `menu` / `transform` / BOM）
>    本来就是通用 Ren'Py，不是项目机密；机密在**台词与资源名**。
> ② 脱敏一个 293 行的 minigame 文件，漏掉一句就是泄密事故；而合成样本可以
>    100% 保证仓库里没有任何真机文本（`git grep` 不到）。
> ③ 真机字节的审计**本来就有** —— 就是本工具在本机跑（§一），它比仓库里放一份
>    快照更新鲜：每次跑的都是当前项目。
> ⇒ 仓库放"结构"，本机跑"真字节"，两者分工，不互相替代。

### 4.3 三层判据：`tests/test_fidelity_structure.py`（24 条）

| 层 | 判据 | 防的是什么 |
|---|---|---|
| ① 样本自检 | 正则断言每份样本**真的带着**它声称的结构 | 样本被谁"顺手简化"成简单对白，用例还绿 |
| ② 逐字节 + **真的走了补丁** | 剥标记后字节相同 **且** `used_patch=True` | 全量碰巧一样，被当成"没碰用户的行" |
| ③ 顶层语句不丢 | `opaque_loss(src, out) == []` | 字节相同但 `define`/`init python` 没进去 |

### 4.4 "要么全对、要么完全不动"的拒绝分支（补上路线图说"没有任何测试"的那半）

| 用例 | 断言 |
|---|---|
| `test_handwritten_target_is_not_overwritten_when_patch_fails` | 补丁配不上 + 目标是手写文件 → `written=False`、**字节不变**、有 `HANDWRITTEN_TARGET`（block 级）且文案说人话 |
| `test_the_preview_is_still_produced` | 拒绝写，但留 `*.blocked.rpy` 预览 —— 否则用户无从判断 |

### 4.5 CI：新 job `fidelity`

只跑 `tests/test_fidelity_structure.py`，不装 PySide6、不碰真机项目；
失败时把 `fidelity_report --md` 的报告贴进 Job Summary（只给一行 `exit 1` 等于没报错）。

> ⚠ **一条必须说清的事实**：`origin/main` 比本地**落后 13 个提交**，
> 也就是说 CI 现在跑的是旧代码。这个 job 会在**下一次 push** 时第一次真正生效；
> 在那之前不要写"CI 已经守住保真"——它还没跑过。

## 五、这一轮抓到的两条

### A. 菜单选项带 `if` 条件 → 补丁退回全量（**layout 级，不是内容级**）

```renpy
menu:
    "去":
        jump ch_roof
    "留" if persistent.flag:
        e "留。"
```

- 现象：`used_patch=False`，`patch_note='1 处新增内容没能落进产物'`，走全量重生成；
- 后果：**一行内容都没丢**，但原文的空行被重排（文件头连续注释之间会被插空行）；
- 真机为什么全绿：**55 个文件里一条条件选项都没有**（我扫过）—— 所以这个洞是"样本没覆盖"，不是"真机没风险"。

**为什么不这一轮修**：修的是"配对身份"（menu 选项的条件要不要进 `_align_key`/`_head_of`），
动 `patcher.py` 核心，会连带 8 个金标重录 —— 正是 §二说不能顺手做的那种改动。
这一轮先把"洞有多大"变成机器可判：`test_the_fallback_only_reflows_whitespace`
断言它**只是排版级**，`test_it_falls_back_to_full_rebuild` 断言它**确实退回了全量**。
修好之后这两条会红，提醒改契约、删缺口。

### B. `opaque_loss` 探针的 BOM 假阳性（**已修**）

- 位置：`tools/probe_opaque_fidelity.py`；
- 根因：读源用 `read_text('utf-8')`，BOM 留在第一行 → 第一条顶层语句"产物里找不到"；
- 修法：改走 `source_style.read_text`（与生产同口径，剥 BOM + 换行归一）；
- 结果：**5 个文件 / 5 处 → 0 个文件 / 0 处**。

## 六、判据的边界（写清楚，防止下次又有人拿它当"全知"）

1. **只覆盖"表 → `.rpy` 写回"这一条路**。`--source` 不给、或目标是新路径时，
   走的是全量重生成，**不承诺逐字节**（只承诺顶层语句不丢，`opaque_loss` 管这条）。
2. **不判断剧情对不对**（铁律 9：语义永远由人标注）。逐字节相同只证明"没碰"，
   不证明"这张表是对的"。
3. **只覆盖仓库里那 4 类结构**。真机 55 个文件是"当前项目"的覆盖，不是"所有 Ren'Py"的覆盖。
4. **真机金标仍只在本机跑**（体积 + 路径依赖）。CI 上绿 ≠ 真机绿；两者是两把尺，别混。
