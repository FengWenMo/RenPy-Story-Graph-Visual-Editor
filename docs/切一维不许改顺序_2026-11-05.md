# 切一维不许改顺序：`lan happy clothes2` 的根因（2026-11-05）

> 用户（截图 `lan happy clothes2`）：「你确定它导入的代码没有写反吗？？？
> 我就切换了一下……怎么两个又不对应了……？我的注册不是 show 人物 服装 表情嘛……？」

## 一、不是"导入写反了"，是**切换时挪位**

`.rpy` 里作者写的是对的（真机抽查 `chapter1_2.rpy:250`

```
show lan aa close_happy at i22          ← 服装在前，符合注册
```

工具**读**进来也是对的。问题出在**点 chip 换一维**那一步。

## 二、病灶（`app/beats.py::apply_attr_slot`）

```python
attrs = _replace_attr_word(toks[1:], hit['value'], value)   # 原位替换 ✓
attrs = [a for a in attrs if a and a != value]              # 把刚换上的删掉
if value:
    attrs = attrs + [value]                                  # 再追加到末尾 ✗
```

`_replace_attr_word` **本来就是原位替换**（它的 docstring 写着"换表情不该让服装
突然跳到后面去"）。后面两行把它白做了 —— 等于**把刚换的那一维挪到末尾**：

```
修复前：lan clothes2 happy  --outfit=base_hand_up-->  lan happy base_hand_up   ✗
修复后：lan clothes2 happy  --outfit=base_hand_up-->  lan base_hand_up happy   ✓
```

## 三、顺带抓到的**第二个**同族 bug

`_replace_attr_word` 在 `old == new`（点了同一个词）时也会挪位：

```python
out = [a for a in attrs if a and a != new]     # 新词被去掉
if old and old in out: ...                     # old 已经不在 out 里
return out + [new]                             # → 追加到末尾
```

修：`old == new` 直接原样返回。**用户在同一格再点一次当前值**就会撞上这条。

## 四、为什么这不止是"看着别扭"

`show` 里的属性顺序**语义等价**（Ren'Py 不看顺序），所以画面是对的 —— 截图里
角色确实穿着衣服。但：

1. **卡片显示的不是作者写的顺序**，人就会怀疑"它到底存对了没有"（用户正是
   这么问的）；
2. **一旦保存，`.rpy` 那一行的字节被改了** —— 违反"不归己的行逐字节不动"，
   `test_patch_golden` 盯的就是这个；
3. 作者按 `人物 服装 表情` 读剧本，顺序一乱就得每次重新对位。

## 五、真机验证（`D:\千连万理\sr_general`）

`attr_slot_rows` 给出两格（引擎的 `expressions` / `outfit`），切换后：

```
lan clothes2 happy         --outfit=base_hand_up-->  lan base_hand_up happy   ✓
lan aa happy               --outfit=clothes2    -->  lan clothes2 happy       ✓
lan clothes2 close_happy   --outfit=aa          -->  lan aa close_happy       ✓
```

## 六、判据

`tests/test_attr_slot_order.py`（**11 条**）：

| 组 | 钉什么 |
|---|---|
| `TestSlotKeepsOrder` | 切服装 / 切表情后那一维**仍在原位**；不认识的词（`_hd_cut`）不许挪；清空一维后其余原位；新增一维才追加；**同词重选不挪**；tag 永不移动 |
| `TestNoSlotNoChange` | 认不出这一维 → **原样返回**（宁可不改，不猜着改） |

## 七、追加：**顺序码就在你的 `rules.json` 里**（我说"不知道"是错的）

用户拍桌子：

> 「我不是已经自定义了结构吗……？我的 json 文件里面难道没有顺序码？
>   你列出来的时候不是按照我说的属性列的吗？」

对。`storygraph.rules.json` 里 `show` 的 `pattern` 就是顺序码：

```json
{"statements": [{"name": "show", "pattern": [
    {"kind": "choice", "column": "角色"},
    {"kind": "choice", "column": "服装"},
    {"kind": "choice", "column": "表情"}]}]}
```

⇒ 作者写的是 **人物 → 服装 → 表情**。而卡片上「属性 1」是 `happy`（表情）、
「属性 2」是 `clothes2`（服装）——**两格正好反着**。这才是"两个又不对应"的
完整病因（不只是切一维挪位）。

### 修法：按声明的列顺序重排

`app/beats.py::_declared_column_order(symbols)` 读 `show.pattern` 的
`choice` 段 → `[(列名, 候选值集合), …]`；`_reorder_by_declared()` 按它排引擎组。

**怎么把"列"认到"引擎组"上**：靠**候选值交集**，不靠列名猜 ——

| 列 | 它的 `options` | 与哪个组的候选交集最大 |
|---|---|---|
| `服装` | `clothes2` / `base_hand_up` / `aa` | `outfit` |
| `表情` | `happy` / `angry` / … | `expressions` |

这是作者自己写下的数据，不是我们猜的语义（铁律 4：只认字面量）。

### 两个必须记住的坑

1. **`角色` 那列（tag）与任何组都无交集** —— 第一版把它当成"认不出"就
   **整体放弃**，于是排序永远不生效（代码看着在跑，顺序一个都没动）。
   现在的判据是"**单列跳过**，一列都认不出才放弃"。
2. **`group_rows` 阶段的键是 `values`**，`options` 是后一步才有的。
   读错键 → 交集恒空 → 又是"静默失效"。

### 真机验证

```
lan clothes2 happy  →  属性 1 = outfit(clothes2)     ✓ 服装在前
                       属性 2 = expressions(happy)
lan happy           →  属性 1 = outfit(—)             ✓
lan aa close_happy  →  属性 1 = outfit(aa) / 属性 2 = expressions(close_happy)
```

没有 `rules.json` 的项目（如 `D://千连万理//sr_general`）→ 保持引擎组顺序，
一个字节都不变。

## 八、这次**没做**的

- **不自动改写已有行**：把 `lan happy clothes2` 那种已经反了的行**改回去**是
  写操作，要你明确点头。现在只是"以后新切的不会再乱 + 卡片按你的列显示"。
- 列的 `options` 为空时无法认列 → 该列被跳过（不猜）。
