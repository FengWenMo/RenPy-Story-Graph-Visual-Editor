# 设计：不绑定引擎 —— 能力协商、退化链、反向导入（2026-11-05）

> 承接 [`调研_引擎内省与自定义结构IR_2026-11-05.md`](调研_引擎内省与自定义结构IR_2026-11-05.md)。
> 回答两个问题：
>
> 1. 引擎升级了、工具没跟上、读不到 —— 退化回解析就行吗？
> 2. 换一个引擎当**源**（比如在 Unity 里读），要求导出 Ren'Py —— 怎么办？
>
> 本文是设计，不是实现；标「已验证」的只有第 1.3 节那条实测。

---

## 0. 结论

1. **"不绑定引擎"不是"一套解析器通吃所有引擎"**，是三件事分开：
   - **语法**不绑定：解析器只认"形状"，引擎特有语义放 profile；
   - **语义**不绑定：IR core 里不许出现引擎词；
   - **判定**不绑定（最容易漏）：每条规则声明"我需要哪个能力"，能力缺失时输出
     `unavailable`，**不是** `pass`，也**不是** `error`。
2. 版本漂移的正解不是"退化到旧解析器"，而是**同一套解析器 + 能力分级 + 事实分层**：
   **静态声明永远是基线，探针只是加"运行期证据"**。读不到 → 事实降级、规则挂起、
   旧事实标 `stale`，**绝不改判**。
3. 换引擎当源：**不解析 Unity 工程**（不可能有保真）。只接受两种"源契约"：
   ① Unity 编辑器里跑一个导出器，吐中立 JSON；② 团队已有的 JSON/CSV/表。
   演出（镜头/位移/时间轴）用**烘焙关键帧**，不翻译语义；对话/分支用 manifest。
4. 导出 Ren'Py **不要写第二个渲染器**：`IR → Beat`，再交给现有
   `story/beat_render.render_beats_to_rpy`（三条生产路径在用的那个）。损失走现有
   `pipeline/ir_loss.py`，只是 target 从 `unity/godot` 加上 `renpy`。

## 1. 先把"绑定"拆开：三种绑定，三种解法

| 绑定 | 症状 | 解法 | 现状 |
|---|---|---|---|
| **语法绑定** | 新语法解析不了；旧解析器把 `init python` 的 2 格缩进切坏 | 宽容扫描 + 未知块整块保留 | 已有 `assets/rpy_blocks.py`、`assets/image_declarations.py`，但只覆盖字面量 |
| **语义绑定** | IR 字段叫 `layeredimage` / `at` / `when` | core + profile 分层 | `story_ir.json` 是**导出格式**，不是 core（见 §4.3） |
| **判定绑定** | 规则里写 `if tag in images`，引擎一变就误报 | 规则声明 `requires` 能力；缺 → `unavailable` | **完全没有**；`ui_qt/sprite_hints.py` 里是隐式的 |

### 1.1 还有一种绑定：环境绑定

`pipeline/_engine.py` 的 `DEFAULT_SDK_CANDIDATES` 写死了
`D:/software/renpy-8.4.1-sdk`。**目录名会骗人**：

```text
D:\software\renpy-8.4.1-sdk\renpy\vc_version.py
  -> {'version': '8.5.3.26051504', 'official': True, 'branch': 'fix'}
D:\千连万理\storygraph_fork_sdk\renpy\vc_version.py
  -> {'version': '8.5.3.26051504', ...}
```

两条结论：

- 版本**只从 `renpy/vc_version.py` 读**（`ast` 解析赋值，**不执行、不 import**，毫秒级）；
- 目录名/路径只当"候选位置"，永不当版本。

### 1.2 detect 不需要跑引擎

```python
# storygraph/engine/detect.py（示意）
def version_of(sdk_root) -> EngineVersion | None:
    p = Path(sdk_root) / 'renpy' / 'vc_version.py'
    tree = ast.parse(p.read_text(encoding='utf-8', errors='replace'))
    vals = {}
    for node in tree.body:
        if isinstance(node, ast.Assign) and len(node.targets) == 1:
            try:
                vals[node.targets[0].id] = ast.literal_eval(node.value)
            except ValueError:
                pass
    ver = str(vals.get('version') or '')
    return EngineVersion.parse(ver) if ver else None
```

`renpy.version_tuple` 的形状（`major/minor/patch/commit`）在 `renpy/__init__.py:122-132`；
但**不要靠 import 它拿版本** —— 那是为了运行时，静态解析已经够了。

### 1.3 已验证

上面那段 `ast` 解析在本机两个 SDK 上都跑通了（输出即 §1.1 的两行）。
顺带证明：**同版本、不同目录名**是现实，不是假想。

## 2. 能力协商：把"引擎会什么"变成数据

### 2.1 能力表（capability tokens）

| token | 含义 | 谁给 | 缺了会怎样 |
|---|---|---|---|
| `CAP_IMAGE_REGISTRY` | `list_images()` / 图像注册表 | 探针 | 图像名只能靠静态声明 |
| `CAP_LAYERED_STRUCTURE` | `LayeredImage.attributes/groups` | 探针 | 分组/默认/`when` 全无 → 维度候选退化 |
| `CAP_STATEMENT_REGISTRY` | `renpy.statements.registry` | 探针 | 自定义语句只能按形状猜 |
| `CAP_TRANSFORM_TABLE` | transform 清单 | `--json-dump` | `at` 目标校验挂起 |
| `CAP_SCREEN_TABLE` | screen 清单 | `--json-dump` | `call screen` 校验挂起 |
| `CAP_LINT_DIAGS` | lint 诊断 | `lint` | 少"注册表视图"这一条证据 |
| `CAP_STORE_SNAPSHOT` | store 变量值 | 探针 | 项目词表只能静态猜 |
| `CAP_RUNTIME_SHOW` | 真跑 `show` | 探针 + start | 只能判"声明/形状" |

能力是**声明**，不是"探测到就算有"：adapter 必须同时给出
`{token: 值 or None}`，`None` 表示"我声明支持，但这次没拿到"——
这两件事在 UI 上必须分开（"不支持" vs "采集失败"）。

### 2.2 Fact 信封（open-world）

现有 facts 是 `{key: value}` + 单独的 `source` 段。改成每条带信封：

```json
{
  "key": "layered",
  "value": {"lan": {"groups": {"outfit": ["coat"]}, "attributes": ["..."]}},
  "source": "probe",
  "scope": "layeredimage",
  "engine": {"id": "renpy", "version": "8.5.3.26051504", "adapter": "renpy/1"},
  "probe": {"schema": 3, "capabilities": ["CAP_LAYERED_STRUCTURE", "..."]},
  "extras": {},
  "degraded": null,
  "confidence": 0.95
}
```

三条硬规矩不变（`core/engine_facts.py` 的 source / conflict / gap），加第四条：

> **不认识的字段进 `extras`，不丢。** 前向兼容靠这个：老工具读新文件不炸，
> 新字段下次采集还在（否则一次降级就把引擎新给的信息永久抹掉）。

### 2.3 能力从哪来：adapter 契约

```python
# storygraph/engine/base.py（示意，不现在写）
class EngineAdapter(Protocol):
    id: str                          # 'renpy'
    def detect(self, root) -> float  # 0..1，这个目录像不像我的工程
    def version(self, root) -> EngineVersion | None
    def capabilities(self, ver) -> dict[str, bool | None]
    def probe(self, root, *, mode='shadow') -> FactBatch      # 可失败
    def parse(self, root) -> FactBatch                        # 永远能跑
    def validate(self, facts) -> list[Diagnostic]             # 纯函数
```

**关键**：`probe` 和 `parse` 都返回同一种 `FactBatch`，只是 `source` 不同
（`runtime` vs `declared`）。调用方不需要知道"现在是哪条路"，只需要知道
"这条事实来自哪一层、置信多少"。

### 2.4 复用已有的能力元模型

`core/capability.py` 已经有一套 **State / Provenance / Transition / Coverage / Escape**
（T0/T0b/T1a/T1b/T2/T3），管的是"一句话能编辑到什么程度"。引擎能力是它在
**引擎维度**的同构扩展：

| 那边 | 这边 |
|---|---|
| T0 已建模 | R0 运行期完整 |
| T0b 有 IR、块体逐字 | R1 运行期部分（缺能力） |
| T1a/T1b 已声明 | R2 仅声明（静态扫描） |
| T2 只识别形状 | R3 仅用法 |
| T3 未识别 | R4 仅文件 |

**不要另起一套语义**：两条硬不变量直接照抄 ——

1. 降级必须留痕（`degraded.reason` + UI 徽章），不许"看起来一样"；
2. 降级不许改判（R0 说错的事实，R1 只能 `unknown`；R2 的"没声明"不许升级成"错"）。

## 3. 退化链：五级，但不是五套解析器

| 级 | 名字 | 拿到什么 | 事实 source | 规则行为 |
|---|---|---|---|---|
| R0 | 运行期完整 | 注册表 + layered + store + 诊断 | `probe` / `json-dump` | 全部可判 |
| R1 | 运行期部分 | 探针部分 API 失败 | `probe` + `degraded` | 缺能力的规则 `unavailable` |
| R2 | 仅声明 | 静态扫描 `.rpy` | `declared` | 依赖运行期证据的规则 `unavailable` |
| R3 | 仅用法 | `show/at/with` 语句 | `usage` | 只能"没出现过"提示，不能判错 |
| R4 | 仅文件 | 文件名/目录 | 无 | 全部 `unavailable` |

### 3.1 R2 不是"退回去"，是永远在跑的基线

这一点是整个设计里最容易被做反的：

- 静态扫描 100 ms 级，探针 3 s 级（实测见调研文档 §3）；
- 打开项目**先出 R2 的结果**，探针在后台补 R0；
- 探针失败 → 页面还在，只是少了运行期徽章。

所以"引擎读不到就退化回原来的解析"这句话，正确的版本是：
**静态解析从来就没停过；探针只是加了一层证据。**

### 3.2 打开项目的状态机

```text
ver  = detect_version()                  # 毫秒，不执行引擎
caps = adapter.capabilities(ver)         # 版本区间 -> 声明
facts = load_last_good()                 # 立刻可用（可能 stale）
ui.render(facts, rung=stale_rung)

if trusted and fingerprint_changed():
    r = probe()                          # 3 s，后台，可取消
    facts = merge(facts, r)              # 静态 + 运行期；冲突进 conflicts
    ui.render(facts, rung=r.rung)        # 徽章变了，判定不变（除非能力真的齐了）
```

`fingerprint` = `game/**/*.rpy` 的 sha + 引擎版本 + `capture`（language/platform）。
**fingerprint 没变就不重采** —— 这是"打开就 3 秒"和"打开无感"的区别。

### 3.3 规则怎么声明 requires

```python
@rule(id='sprite.attr.unknown', requires={'CAP_LAYERED_STRUCTURE'})
def check_attr(ctx): ...
```

能力缺失时，规则引擎产出：

```python
Diagnostic(status='unavailable', missing=['CAP_LAYERED_STRUCTURE'],
           hint='引擎运行期结构没采到；升级工具或手动采集后重试')
```

UI 显示"无法判定"，**不计入错误数、不计入通过数**。

> 这条是"版本漂移不误报"的全部秘密：不是让检查更宽松，是让检查**诚实地缺席**。

### 3.4 版本区间

adapter 声明 `SUPPORTED = '>=8.0,<9'`。超出：

- **仍然跑**（探针是自描述的，`getattr` + `try` 每个能力单独兜底）；
- 每条事实带 `engine.untested=True`，UI 一行黄条：
  "引擎 8.6.0 不在测试矩阵里；已按 8.5 的 API 尽力采集"；
- **不阻断**。阻断比误报更烦人，而误报可以被"能力缺席"挡住。

### 3.5 漂移检测：工具"该更新了"的信号

每次采集存一份 `api_surface`：`{name: bool}`（`hasattr` 结果）+ `version`。
两次采集 diff：

- 新 API 出现 → "引擎加了 X，工具可以支持"；
- 老 API 消失 → "引擎删了 Y，相关规则已自动挂起"。

这是**产品功能**（升级提示），不是内部日志。没有它，工具的支持永远是"猜着更新"。

## 4. IR：core + profile

### 4.1 core 的判据

一句话：**把引擎词全删掉，还能不能表达"作者要什么"**。

| core 实体 | 不是什么 | 是什么 |
|---|---|---|
| `asset` | 不是 image tag | 一个可显示的素材（图/立绘/背景/视频） |
| `variant` | 不是 attribute | 素材的一个可选变体（表情/服装/状态） |
| `variant_group` | 不是 layer group | 互斥的变体集合（同组选一） |
| `state` | 不是 layeredimage | 当前舞台的一组 asset + variant |
| `timeline_event` | 不是 ATL | 带时间/顺序的演出事件（show/move/fade/sound） |
| `line` / `choice` / `condition` | — | 叙事 |
| `transform` | 不是 ATL transform | 具名变换（参数 + 关键帧/曲线） |
| `declaration_site` | — | `file:line` + hash |

profile 里才放：`renpy.layered_image{image_format, at, attribute_function, when, if_all...}`、
`renpy.atl_body`、`unity.prefab{guid, fileID}`、`unity.animator_state`。

### 4.2 守卫（可测）

- `tests/test_ir_core_purity.py`（新增）：扫 `storygraph/ir/core/**` 的字符串与标识符，
  出现 `renpy` / `layeredimage` / `atl` / `with ` → 红；
- 反向：`ir.profile.renpy` 不许被 core import（依赖方向测试）。

这是"不绑定"唯一能长期成立的机制 —— 靠人自觉必然烂。

### 4.3 现有 `story_ir.json` 怎么办

它是**目标格式**（flat、给 Unity 的 `JsonUtility` 读），不是 core。
保留 v1.1 适配器：`core → story_ir`（投影），老消费者不变。

**不要**把 `story_ir.json` 升格成 core —— 它已经被"Unity 只能标量"这个约束塑形了，
那是 target 的形状，不是源的形状。

## 5. 反向：Unity 当源 → Ren'Py 导出

### 5.1 先承认不可能的部分

Unity 工程不是"带语法的文本"：C# 玩法逻辑、ShaderGraph、Timeline 曲线、Animator
状态机、Addressables 二进制。**没有任何解析器能把它们读成叙事语义。**

三条路：

| 路 | 做法 | 保真 | 成本 | 建议 |
|---|---|---|---|---|
| A | Unity 编辑器里跑导出器（EditorWindow / AssetPostprocessor）→ 中立 JSON | 高（能反射、能拿引用） | 一个 C# 文件 + 契约 | **推荐** |
| B | 静态读 YAML（`.prefab` / `.asset` / `.controller`） | 中低（语义要人声明） | 中 | 只做"资源清单" |
| C | 不读 Unity，继续用表/JSON 当源 | — | 0 | 默认 |

**A 就是"问引擎"的 Unity 版**：Ren'Py 的探针是 Python 注入，Unity 的探针是编辑器脚本。
同一个思想，不同宿主。而且本仓库已经在往 Unity 里发 C#（`pipeline/unity_package.py`
的 `DialoguePlayer.cs`），反向发一个 `StoryGraphImport.cs` 是同一类交付。

### 5.2 两份契约，不要混

1. **叙事契约**（对话/分支/变量）：`storygraph.import.json`

   ```json
   {"schema": 1, "engine": "unity", "engineVersion": "...",
    "lines": [{"id": "…", "speaker": "lan", "text": "…",
               "choices": [{"text": "…", "target": "…"}]}],
    "assets": [{"id": "…", "kind": "sprite", "variants": {"expression": ["happy"]}}]}
   ```

2. **演出契约**（镜头/位移/时间轴）：`staging.json`，**烘焙关键帧**

   ```json
   {"tracks": [{"target": "lan", "property": "xalign",
                "keys": [[0.0, 0.5], [0.4, 0.1]]}]}
   ```

为什么烘焙：ATL 和 Unity Transform 没有语义对应（3D/2D、缓动、约束、父子）。
**翻译样本，不翻译概念** —— 30 fps 采样，误差可控，损失可报。
这比"把 Animator 状态机翻译成 ATL"现实得多：后者等于重写一个引擎。

### 5.3 导出 Ren'Py

- **叙事**：`IR.line → Beat → beat_render.render_beats_to_rpy`（复用，不写第二个渲染器）；
- **演出**：`staging.json → ATL`：按关键帧生成 `linear 0.4 xalign 0.1`，末尾可选 `ease`；
- **条件**：只导出可移植表达式（字面量/比较/布尔/变量）；`renpy.` 开头或调函数的 → `manual`；
- **损失**：复用 `pipeline/ir_loss.py`（它已经是 `engine → 字段表` 的形状：
  `LINE_FIELD_MAP.get(engine)`），target 加 `renpy`，产出 `IR_LOSS-renpy.md`；
- **验收**：`renpy lint` 必须过（真 SDK，`pipeline/_engine.run_engine` 已有）；
  再跑一次 `IR → rpy → 解析回 IR` 的 round-trip，diff 只允许白名单字段。

### 5.4 保真分级（写进报告，不写进宣传）

| 能力 | 级别 | 说明 |
|---|---|---|
| 台词/分支/变量 | `exact` | 一一对应 |
| 立绘/背景/音频 | `exact`（名字） | 资源路径要人映射 |
| 位移/缩放/淡入淡出 | `approximate` | 关键帧采样 + 缓动近似 |
| 3D 镜头/Shader/粒子 | `drop` | 不导，列出来 |
| C# 玩法逻辑 | `manual` | 只能人重写 |

⚠ "导出成功"永远不等于"导全了" —— 这条
[`契约速查_storygraph.md`](契约速查_storygraph.md) §18 已经踩过（`IR_LOSS` 就是为它生的）。

## 6. 落地顺序（不是现在做）

| 阶段 | 做什么 | 验收（可测） |
|---|---|---|
| **P0** | `engine/base.py`（协议 + `Capability` + `Fact` 信封）；`engine/renpy_adapter.py` 包现有 `engine_collect`；facts schema v2（`adapter/engine_version/capabilities/extras/degraded`） | 老 facts 文件仍能读；新采集带版本与能力；`detect_version` 有"目录名骗人"用例 |
| **P1** | 规则 `requires` + `unavailable`；先改 `sprite_hints` 一条规则 | 模拟缺 `CAP_LAYERED_STRUCTURE`：`lan aa happy` 不报错，而是"无法判定" |
| **P2** | IR core + profile + 纯度/依赖守卫；`build_neutral_ir` 改为"core → story_ir 投影" | 现有 unity/godot 导出**字节不变**（golden）；纯度测试绿 |
| **P3** | `IR → Beat → rpy` + `IR_LOSS-renpy` + lint round-trip | 真 SDK lint 0 错；round-trip 白名单外 0 diff |
| **P4** | Unity 导入契约（先只收 `storygraph.import.json` + `staging.json`，**不做 YAML 解析**） | 一个 Unity 样例 → 导入 → 导出 rpy → lint 过 |

P0/P1 是小改；P2 才是"真正中立"的那一步，但它是**纯重构**，有 golden 保。

## 7. 反目标

- ❌ 不要在 core 里写 `if engine == 'renpy'`（守卫会红）。
- ❌ 不要为"支持所有引擎"造插件框架/DSL —— 你们路线图自己写了"过度工程"。
  **两个 adapter 证明缝，第三个才抽象。**
- ❌ 不要把 `story_ir.json` 当 core（它是 target 形状）。
- ❌ 不要承诺 Unity → Ren'Py 演出对等（ATL ≠ Transform）。
- ❌ **不要自动对不信任的工程跑 `init`**。`init python` 是用户代码，能读写任意
  文件、联网。这是**信任边界**，不是性能问题：默认"打开只静态；探针一次显式授权，
  按工程记住"。

## 8. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 自动探针执行任意代码 | `init python` 是用户代码 | 显式授权 + 子进程 + 超时 + 影子工程；文档写明 |
| 事实过期 | 改了 `.rpy` 没重采 | fingerprint + `stale` 标记 |
| 平台/语言差异 | 同工程不同 `config.language` 结果不同 | `capture` 段存 language/platform/developer |
| 适配器漂移 | 每个 adapter 自己解释字段 | 共享 conformance 用例（同一份 hell 工程跑所有 adapter） |
| 旧工具读新 facts | 新字段 | `extras` + `schema` 版本 + 拒绝降级写回 |
| "universal" 诱惑 | 想一次支持所有引擎 | 只做"core + 两个 adapter"；第三个再说 |
