# 卡牌编辑器（BeatEditorPanel）改版方案

> 针对三个诉求：**① 缩略图卡顿 + 多个立绘太占地方 ② 表情变化被当成多个立绘 ③ 翻页在最下沿不好点**。
> 本文只做方案设计（含定位、思路、代码骨架、验收口径），**尚未改代码**。
> 目标终端：桌面（tkinter），主窗口宽度以 1280–1440 为基线，最小可用 980。

---

## 〇、现状定位（改动点都能对到代码）

| 现状 | 位置 |
|---|---|
| 翻页按钮在底部条：`下一句 ▶` / `◀ 上一句` | `beat_editor.py:2037-2040`，`bar.pack(side='bottom')` |
| 一个立绘 = 一整行 grid（图像名 26 + 缩略图 Label + 🔍 + 表情 10 + 位置 8 + 说话 + ✕） | `beat_editor.py:1486-1532`（`_add_sprite_row`） |
| 缩略图与控件同一行，高度由缩略图撑开（`max_size=(150,210)`） | `beat_editor.py:1499-1501`、`resolve_sprite_thumb` 默认 `(150,210)` |
| 每敲一个字符就同步解码一次图片 | `beat_editor.py:1535-1538`（`trace_add('write', _refresh_thumb)`） |

## 一、根因分析

### 1. 卡顿：不是"图片多"，是**同步解码 × 输入即触发 × 无缓存**

1. **输入即触发**：`img_var.trace_add('write', ...)` —— 打 `ling` 三个字母触发三次完整解码。
2. **同步阻塞 UI 线程**：tkinter 是单线程 UI，`Image.open` + `thumbnail` + `ImageTk.PhotoImage` 全部在主线程，一次几十~几百 ms，多张立绘线性叠加。
3. **解码成本与"原图分辨率"成正比，与显示尺寸无关**：Pillow 的 `thumbnail` 是全分辨率解码后再缩。立绘常见 1500×2200，显示只要 96×128。
   （Excel 导出那条路已经用了 `im.draft()` 让 JPEG 直接按目标尺寸解码——**UI 这条没用**，是现成的数量级差距。）
4. **无内存缓存**：`load_thumbnail` 每次都重新打开+解码。来回切 Beat，同一张图反复解码。
5. **磁盘缓存没复用**：`_thumbnail_bytes` / `thumb_cache_dir`（Excel 侧）已有"路径|mtime|size|尺寸"的磁盘缓存，UI 这条路是另一套，冷启动各付一次。

### 2. 占地方：立绘"一行一图"，高度随数量线性增长

一个立绘行 ≈ 210px（由缩略图高度决定）。3 个立绘 ≈ 630px，加上台词/音乐/条件区，面板远超窗口高度 → 底部操作条被挤出可视区（**问题①和问题③是同一个根因**）。

### 3. 表情被当成多个立绘：UI 把"show 子项"直接当"场上的人"

`show ling close_happy; ling close_angry` 在 Ren'Py 里是**同一个图像 tag 换属性**（后者替换前者，场上仍是一个人）。
但 `beat_sprite_rows` 把 `_split_show_items` 的每个子项平铺成一行卡，于是出现"两张 ling 卡"。
数据没错（`show` 列就是这么存的），**错在展示层缺少"按角色聚合"这一层**。

## 二、方案总览

| 编号 | 方案 | 解决 | 优先级 |
|---|---|---|---|

## 三、A. 缩略图加载：让"看图"不再卡住打字

### 思路

把"解码"从 UI 线程挪走，并让它**只发生一次**：

```
输入变化 ──防抖 120ms──► 任务入队 ──线程池(2)──► 解码 ──after()回主线程──► 贴到 Label
                                    │
                        内存 LRU(60) ┴ 磁盘缓存(复用 thumb_cache_dir)
```

### 具体改动

1. **防抖**：`trace_add` 回调只做 `self.after(120, ...)` 的重新排程（合并连续输入）。
2. **后台解码**：`ThreadPoolExecutor(max_workers=2)`，只做"读文件 + 缩放"；`ImageTk.PhotoImage` 必须在主线程构造（tkinter 约束），所以 worker 返回**缩放后的字节/PIL 对象**，主线程再转 PhotoImage（转这一步很快）。
3. **内存 LRU**：`key = (路径, mtime, 尺寸, max_size)`，上限 60 张（约 96×128×4B×60 ≈ 3MB）。带 `mtime`/`size` 是为了**文件被替换后自动失效**（Excel 侧已经踩过：缓存键不含 mtime 会拿到旧图）。
4. **复用磁盘缓存**：与 Excel 导出的 `thumb_cache_dir()` 共用目录和键规则——两边第一次各付一次，之后互相命中。
5. **draft 解码**：`Image.open` 后先 `im.draft('RGB', max_size)`（JPEG 按目标尺寸解码），再 `thumbnail`。
6. **降级不变**：无 Pillow 时仍走 `tk.PhotoImage`（png/gif）+ 占位文字；后台线程失败 → 主线程显示"⚠ 无法预览"，不阻塞。

### 骨架代码

```python
# ---- 缩略图加载器（新：storygraph/ui/thumb_loader.py）----
class ThumbLoader:
    """防抖 + 后台解码 + 内存 LRU；只回主线程贴图。"""

    def __init__(self, widget, pool, max_size=(96, 128), debounce_ms=120):
        self._widget, self._pool = widget, pool
        self._max_size, self._debounce = max_size, debounce_ms
        self._cache = {}          # key -> PhotoImage（含引用，防 GC）
        self._pending = {}        # label -> after id
        self._jobs = {}           # label -> future（用于取消过期任务）

    def request(self, label, path):
        """输入变化就调它；真正的解码被防抖合并 + 后台化。"""
        prev = self._pending.get(label)
        if prev:
            self._widget.after_cancel(prev)
        self._pending[label] = self._widget.after(
            self._debounce, lambda: self._start(label, path))

    def _start(self, label, path):
        key = _cache_key(path, self._max_size)
        if key in self._cache:                       # 内存命中：直接贴
            self._apply(label, self._cache[key])
            return
        self._apply(label, None, text='…')           # 骨架占位（见"微交互"）
        fut = self._pool.submit(_decode, path, self._max_size)
        self._jobs[label] = fut
        self._widget.after(30, lambda: self._poll(label, fut, key))

    def _poll(self, label, fut, key):
        if not fut.done():                           # 主线程不阻塞，轮询结果
            self._widget.after(30, lambda: self._poll(label, fut, key))
            return
        if self._jobs.get(label) is not fut:         # 已被更新的任务取代
            return
        photo = fut.result()
        if photo is not None:
            self._cache[key] = photo
            self._apply(label, photo)
        else:
            self._apply(label, None, text='⚠ 无法预览')

    def _apply(self, label, photo, text=''):
        if label is None or not hasattr(label, 'config'):
            return
        label.config(image=photo if photo is not None else '', text=text)
        label.image = photo                          # 必须留引用，否则被 GC
```

### 预期效果

- **打字不再掉帧**：解码移出主线程 + 防抖，输入延迟稳定（<16ms 响应，图随后补上）。
- **切换 Beat**：缓存命中 0ms；未命中也是"先占位后补图"，不阻塞。
- **首次冷启动**：`draft()` 让 JPEG 解码量级下降（实测 Excel 侧冷缓存从"几分钟"降到可感知的几秒，UI 单张同理）。

## 四、B. 立绘区：从"一行一图"改成"网格卡片"

### 思路

**缩略图不该独占一行。** 把立绘区改成横向网格，每张卡 = 图 + 名字 + 徽标，一行放 4–5 张，超出换行；高度与数量脱钩（3 个立绘 ≈ 140px，而不是 630px）。详情编辑放在**选中卡之后的编辑区**（或双击弹窗），不再每行都塞满输入框。

### 具体改动

1. `BeatEditorPanel` 内新增 `SpriteGridView`（`Frame` + `grid`，或 Canvas 内含 `Frame` 以支持滚动）：
   - 卡片尺寸 96×128 缩略图 + 8px 内边距；卡片间距 8px。
   - `grid` 列数按窗口宽度自适应（见"断点"）。
2. **按需加载**：只解码**可视区内**的卡（绑定 `<Configure>`/滚动事件，`after(80)` 批量补）；超过 12 张显示"展开更多"。
3. **选中态**：点击卡片 → `relief='solid'` + 主色边框 2px + 底部编辑区填充该立绘。
4. **保留逃生舱**：卡片右上角 `✕`（移除），`🔍`（选择器）移到编辑区；网格里只留"小 ✕"（避免误触）。
5. **降级**：无 Pillow 时卡片显示"首字母 + tag 名"的色块占位（不空白，仍可点选编辑）。

### 预期效果

- 面板高度**与立绘数量脱钩** → 底部操作条常驻可见（问题③的一半在这里解决）。
- 解码次数下降：可视区 5–8 张 + 按需加载，而不是"打开就解码全部"。
- 信息密度提升：一屏能同时看到所有在场角色（原来要滚动）。

## 五、C. 表情：按角色聚合，卡内用 chips 表达

### 思路

**"场上有几个人" 由 tag 决定，不是由 show 子项数量决定。** 在 UI 层加一层"按 tag 分组"（**不动数据契约**——`beat.show` 仍存原样，`apply_sprite_rows` 原样写回）。

### 规则

1. 同一 `tag` 的多个 show 子项 → **合并成一张角色卡**。
2. 卡上的缩略图 = **当前生效那条**（最后一个子项；或说话角色对应的那条）对应的图。
3. 卡下方显示 **表情 chips**：本拍这个角色出现过的表情词（`beat_expression_word` 已有逻辑，直接用）：
   - 当前生效的 chip：主色描边 + 浅主色底 + ✓
   - 其它 chip：中性底 + 边框（点击 = 切换生效表情，即改 show 的属性）
4. **同 tag 多条且位置不同** → 这不是"两个人"，是数据异常：加**警告徽标**（`⚠ 同 tag 多条`）+ tooltip 说明，而不是静默平铺两条。（Ren'Py 也不会让同 tag 有两个实例。）
5. 缺图 chip 显示 `⚠ 缺图`，避免"改了表情但图没换"的错觉。

### 骨架代码（只改展示层）

```python
def group_sprites_by_tag(rows):
    """
    立绘行 → 按角色聚合的卡片模型（**UI 层**，不改 beat.show）。

    同一个 tag 的多个 show 子项，在 Ren'Py 里是"换属性"（后者替换前者），
    场上仍然是一个人 —— 平铺成多张卡会让人以为站了两个。
    """
    cards, order = {}, []
    for r in rows:
        tag = r.get('tag') or r.get('image', '').split()[0]
        if tag not in cards:
            cards[tag] = {'tag': tag, 'expressions': [], 'current': -1,
                          'position': r.get('position', ''),
                          'image': r.get('image', ''), 'dupe_position': False}
            order.append(tag)
        card = cards[tag]
        expr = r.get('expression') or ''
        if expr and expr not in card['expressions']:
            card['expressions'].append(expr)
        # 最后一条 = 生效的那条（Ren'Py 的替换语义）
        card['current'] = card['expressions'].index(expr) if expr else card['current']
        card['image'] = r.get('image') or card['image']
        if r.get('position') and r.get('position') != card['position']:
            card['dupe_position'] = True
        card['position'] = r.get('position') or card['position']
    return [cards[t] for t in order]
```

### 预期效果

- `show ling close_happy; ling close_angry` → **1 张 ling 卡 + 2 个表情 chip**，而不是 2 张卡。
- 卡片数 = 场上实际人数，与"这一拍到底站了几个人"直觉一致。
- 卡片数下降 → 面板再矮一截（与 B 叠加，问题①进一步缓解）。
- 切换表情变成"点 chip"，不用手改图像名（也避免手写 `close_happy` 这类怪名）。

## 六、D. 翻页：高频操作上移 + 键盘优先

### 思路

"上一句/下一句"是**逐句校对时的最高频动作**（可能占全部操作的 60%），不该和"载入/导出/体检"一起挤在最下沿。

### 具体改动

1. **上移**：`◀ 上一句` / `下一句 ▶` 移到**顶部导航条**（与"换一章/跳到这一章开头/整章改名"同排），并加 `第 12 / 1730 句` 的计数标签（位置感）。
2. **底部条瘦身**：只留低频动作（载入 .rpy / 导出 .rpy / 项目体检 / 🎬 演出预览），固定高度 40px + 顶部分隔线，视觉上明确是"功能区"。
3. **键盘优先**（最有效的一条）：
   - `Enter` / `Alt+↓` → 下一句；`Alt+↑` → 上一句（现已绑定 `Return`，补上下与显式提示）
   - `Ctrl+Enter` → 保存并下一句
   - 按钮文案标注快捷键：`下一句 ▶（Enter）`
4. **不怕被挡**：顶部条 `pack(side='top', fill='x')`，且 `pack_propagate(False)` 给固定高度，窗口再小也不压缩。
5. **Beat 列表联动**：左侧 Listbox 选中项随翻页滚动可见（`see(index)`）——翻页后用户能看到"自己在哪"。

### 预期效果

- 翻页从"视线移到窗口最下方、在一排按钮里找" → "顶部第一排 + 键盘直达"，每次操作省 1–2 次眼动/移动。
- 窗口再矮也不会挤掉翻页（顶部固定）。

## 八、组件清单与状态矩阵

|---|---|---|---|---|---|---|

| 表情 chip | `#EEEEEE` 底 + 文字 | 底 `#E3F2FD` | 主色边 + `✓` | — | `⚠ 缺图` | — |
| 缩略图 Label | 图 | 放大浮层（0.2s） | — | 骨架块 | `⚠ 无法预览` | — |

| 分区标题 | 10pt 加粗 | — | — | — | — | — |

微交互参数：
- 悬停/选中：**0.2s**；仅改颜色与边框（tkinter 无 transform，用 `relief` + 边框色模拟，不动画几何属性）。
- 加载骨架：两个灰阶 `#F5F5F5 ↔ #E0E0E0` 以 **400ms** 交替（`after` 驱动，最多 3 次后停在静态占位，避免长期闪动干扰）。
- 表情切换：点击 chip 后**瞬时**更新选中态 + 缩略图（后台补解码）。

## 九、无障碍检查清单（AA）

- [ ] 正文/说明文字对比度 ≥ 4.5:1（`#757575` 起，不用 `#999` 承载文字）
- [ ] 状态**不只靠颜色**：选中 = 边框 + `✓`；错误 = 图标 + 文字；缺图 = 图标 + 文字
- [ ] 键盘可达：立绘网格可 Tab 遍历；翻页 `Enter / Alt+↑ / Alt+↓`；每处快捷键在界面上有文字提示
- [ ] 焦点可见：卡片/按钮有明确焦点环（`highlightthickness=2` + 主色）
- [ ] 语义优先：`✕`/`🔍` 图标按钮带 `tooltip` 文字说明（tkinter 无 ARIA，用 tooltip + 可读文案兜底）
- [ ] 字号下限：≥ 8pt（≈11px），取消现有 7pt
- [ ] 骨架屏不闪烁超过 3 次；动效可关闭（提供"减少动效"开关更好）

## 十、实施顺序与验收

| 步骤 | 内容 | 验收口径 |
|---|---|---|
| 1 | A 缩略图加载器（防抖/线程/LRU/draft）+ 单测 | 连续输入不卡顿；同图二次加载走缓存（计数器断言）；无 Pillow 时降级不报错 |
| 2 | B 立绘网格 + 选中编辑区 | 3 立绘时面板高度 ≤ 当前 1/3；可视区外不解码 |
| 3 | C 按 tag 聚合 + 表情 chips | `show A x; A y` → 1 张卡 2 chips；写回 `beat.show` **与原值等价**（往返测试） |
| 4 | D 翻页上移 + 快捷键 | 窗口高度压缩到 700px 时翻页仍可见；`Alt+↑↓` 生效 |
| 5 | E token 与无障碍收尾 | 对照检查清单逐项过 |

**风险与约束**
- tkinter 单线程：所有 UI 更新回主线程；`PhotoImage` 必须留引用（否则 GC 后图消失）。
- 虚拟滚动复用卡片时，注意"复用后旧任务的回调"要能取消（用 job token 比对）。
- **C 只在 UI 层分组，绝不动 `beat.show` 的存储格式**（否则会牵动 Excel、校验、渲染、门禁）。
- 缓存键必须含 `mtime`/`size`（文件被替换后要失效）。
- 真实项目 2902 张图 / 146 变换，改动后需在 `sr_general` 上实测冷启动与逐句翻页手感。
