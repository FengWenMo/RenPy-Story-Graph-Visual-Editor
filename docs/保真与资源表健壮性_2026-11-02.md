### 缺陷 A：`U+0005` 被静默吃掉（4 章 9 处）

源：`"“成为机器是一种怎样的感受？”\x05"`（台词末尾一个不可见控制字符）。

链路：`.rpy` → 写 xlsx。xlsx（XML 1.0）**装不下** `U+0000~08 / 0B / 0C / 0E~1F`，
`openpyxl` 会直接抛 `IllegalCharacterError` 让**整份表**导不出来。
2026-10-28 的处理是"**剥掉 + 记 safeguard 日志**"—— 表能写了，但内容被永久改了，
而用户只会在日志里看到一行。**这是"表只是中转站"这个架构下最不能接受的一类**。

修法（`excel/cells.py`）：剥 → **转义**。

* 写表：`U+0005` → 字面 `\x05`（看得见，Ren'Py 也认这个转义）
* 读表：`\x05` → `U+0005`（`xml_unescape_row`，`Beat.from_row` 之前唯一入口）
* 只认 `00-08 / 0B / 0C / 0E-1F`；`\x41` 这种可见字符**不还原**（不猜）
* 语义无损：Ren'Py 字符串字面量本来就认 `\xNN`，引擎读出来与原来**同一个字符**

判据：`tests/test_excel_illegal_chars.py`（29 条，含"用户真写了 `\x41` 不能变 `A`"）。

### 缺陷 B：同一句台词导出后变两份（1 章 2 处）

作者原话（`chapter3_4_4.rpy` 第 90 行）：

```
xqlz "那是上一句的接话！…你不会忘了吧\" <TAB><TAB>#这里出现名字但是不要出现立绘"
```

`\"` 是**转义引号**，所以 `#` 还在字符串里，整行是一条台词。

**根因在 `atl._strip_comment`：它不认 `\` 转义**，把 `\"` 当成字符串结尾，
于是 `#` 之后被当行尾注释截掉。而截断点在两种形态上**不一样**：

| 形态 | 截断后 | `_SAY_RE` | 身份键 |
|---|---|---|---|
| 原文（真 tab） | `…忘了罢\"` | 恰好以 `"` 结尾 → 认得出 | `('say','xqlz')` |
| 渲染（`_quote` 把 tab 写成 `\t`） | `…忘了罢\" \t\t` | 不以 `"` 结尾 → 认不出 | `('other', 整行)` |

于是补丁认为渲染出来的是**新内容** → 插一行；原文那行又因为"台词不许删"
（`_may_drop_line`）留着 → **同一句两遍**，多出来的那条还是 `\t` 形态。

实测：236 行 → 238 行（第一轮），第二轮才稳定 —— 不是无限膨胀，
但**第一次导出就已经脏了**，而且报告只说"改 2 行"。

修法两处（`story/atl.py` + `story/patcher.py`）：

1. `_strip_comment` 在引号内遇 `\` 时**吞掉下一个字符**（`\"` 不是定界符）
2. `_replace_matched` 增加 `_escaped_same`：两行**只差"真字符 vs 转义写法"**
   （`\t\t` ↔ 两个真制表符）→ **保留原文**，`changed` 不加

   `_unescaped` 管不了这个（它只归一空白与引号，`\t` 与真 tab 在它眼里是两回事）。

判据：`tests/test_patch_escaped_say.py`（11 条，含"两次导出不增长"）。

### 修 ①：缺列 → 重复补登（真会毁数据）

表里 `Path` 全空时，"磁盘上每个文件都没登记"与"表头坏了"**长得一模一样**。
补登于是把同一批文件加第二遍（`bg01`、`BG02`、`bg01_2`、`BG02_2`），
人填在旧行的 `Tag`/`Category`/`备注` 留在旧行 —— 一份整理成果劈成两半。

修法（`asset_registry._path_coverage` + `sync_asset_tables` 的补登守卫）：

* **按表分开数**：`{表名: (行数, 有 Path 的行数)}`
  （第一版数的是全局合计，"图片表坏了、音乐表好好的"会被音乐那行放行）
* 某张资源表**有行、但一行都没 Path** → **不补登**，`error` 里点名是哪张表、
  缺哪一列、这次做了什么、下一步怎么走
* 空表放行（那正是补登该做的事）；"部分行没 Path"放行（新加的行常常还没填）

判据：`tests/test_asset_table_guards.py`（9 条，含空表/部分空行两个对照组）。

### 修 ②：编号是数字 → 键类型混用

Excel 把用户手打的 `001` 存成数字 `1`（**前导零当场消失**），
注册表的键就成了 `int` —— 同一个资源有两种键、`get_asset_ids()` 返回的列表
混着 `123` 与 `'abc'`（排序直接 `TypeError`）。

修法（`_norm_asset_id`）：一律 `str`，并把"这一格不是文本"写进 `warnings`
（点名到文件 + 说明 `001` 会变 `1`）。

## 四、市面工具在做什么（调研）

| 做法 | 出处 | 我们可以怎么用 |
|---|---|---|
| **主资产 = 稳定 ID + 注册表**（`Weapon.DragonBreath`），代码按 ID 取，不关心路径 | UE AssetManager / Asset Registry | 现在 ID 来自文件名，**改名即断**。`dialog_asset_rename` 已有基础，缺的是"改名时把所有引用一起改"的闭环 |
| **可保存的校验规则集**（validation profile）：项目自己定义"什么算 ready"，手动/CI 同一套 | Universal Asset Preview Studio | 我们现在是零散 `errors`/`warnings`，没有"跑一次体检给我一份报告" |
| **依赖图 + 出入向引用**，改之前先看会影响谁 | 同上 / ftrack | 有 `broken_references`，缺"改这张图会影响哪些台词"的正向视图 |
| **缩略图缓存带失效清理与预算**（corrupt-entry tracking / cache budget） | 同上 | 我们的舞台缓存按字节预算，缩略图缓存没看到清理策略 |
| **先 dry-run 预览再落库**（映射列 → 逐行报错 → 确认后才写） | PolyDrobe | 资产表"补登"现在直接写盘（有备份），缺"先给你看要加哪几行" |
| **按置信度分级修复**：高置信自动修，模糊的只报告 | MissingLink | 与我们的 `authority` 层理念一致，可推广到资产表诊断 |

**一句话**：我们强在"不改用户字节 + 逐行配对"，弱在**"一次把所有问题列出来"**
（诊断）和**"改名/移动之后引用不断"**（Identity 生命周期）。

## 五、还没做的（按价值排序）

   大小写冲突 / Tag 与目录不一致 / 未被任何台词引用的图 / 引用了不存在的 ID
   —— 一次跑完，P0/P1 分级，可导出 Markdown。
2. **表读不出来 ≠ 没有资产**：`load_asset_registry` 现在失败返回 `None`，

3. **改名闭环**：资产改名 → 扫描所有 `.rpy` 的引用 → 生成 diff → 确认后一起改。
4. **补登 dry-run**：先出"将要新增 N 行"的清单，人确认后再写。
5. `sg_transforms._strip_comment` 是 `atl._strip_comment` 的**第二份实现**
   （同样不认转义）—— 应该合并成一份（守卫：两处行为逐例等价）。

## 六、这轮最贵的一课：**同一条等价，要改在两个地方**

修「真 tab ↔ `\t`」时先只改了 `_rewrite_line`（保留原文），结果
`test_patch_golden` 里 `chapter3_4_4 [edited]` 的 `used_patch` 从 True 掉成
False —— 因为它旁边还有一条**独立的老判据**：

| 函数 | 问的问题 | 判据 |
|---|---|---|
| `_rewrite_line` | 这一行**要不要改** | `_escaped_same`（新加） |
| `_missing_generated_lines` | 生成的这一行**在不在产物里** | `_unescaped`（旧的，不认 `\t`） |

前者说"等价，保留原文"，后者说"生成的那行不见了" → `_verify_patch` 拒绝
→ 整章退回全量。症状是 `reason='2 条生成内容在补丁结果里找不到'`。

**规矩**：判"两行是不是同一行"的函数，全仓只该有一个口径；
加一条等价档时，**搜出所有"比对不对"的地方一起改**（这次是
`_rewrite_line` + `_keys` + 金标）。

## 八、验证范围（诚实版）

**跑绿的**：

| 批次 | 条数 |
|---|---|
| 新增判据（3 个文件） | 49 |
| 资产 / atl / excel 面 | 218 |
| 两个真机金标 | 4（7m18s；把金标写回可读格式后又复跑一次，4 passed / 7m26s） |
| 核心回归（写回保真 / 往返 / 切行 / 地狱 Excel） | 190 |

**没能一次跑完全量的原因（环境，不是代码）**：
这台机器上的删除保护钩子有"**每轮对话累计删除 50 个文件就要求确认**"的阈值，
而 pytest 的 `tmp_path` 清理很容易超过它 → 钩子抛 `SystemExit: 1` 把整个
pytest 进程带走。症状长得很像崩溃：

* `xdist` 里是 `worker 'gwN' crashed`（每条报错指向**不同**用例）
* 单进程里是 `mainloop: caught unexpected SystemExit!`
* 批量跑时是 `178 errors`（全是 setup ERROR）

**判定方法**：看报错文本里有没有 `SystemExit: 1` / `SAFE_DELETE_BULK_CONFIRM_REQUIRED`；
有就是环境，单跑那条一定过（本轮验证过 2 条）。
最后一批 `190 passed / 6 failed` 里，6 条**全部**是 `SystemExit: 1`。

→ 收尾前建议：**关掉编辑器 GUI、一次只跑一轮、分批跑**，
或者在这台机器上把钩子阈值调高再跑全量。
