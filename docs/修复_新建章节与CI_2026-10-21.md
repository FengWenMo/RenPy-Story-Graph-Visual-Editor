## 一、新建章节显示「（无源文件）」，剧本编辑不了

### 用户的原话

> 新建了个节点显示无源文件，这个新建章节我也没搞明白，
> 怎么才能把无源搞成有源，不然打开章节剧本不能用！

### 根因

`add_node` 只往图里加一个内存 `Node`，`file_path` 是空的
（`AddNodeCommand` **本来就支持** `file_path` 参数，只是没人传）。

于是：

- 卡片上显示「（无源文件）」；
- 双击进卡片页，编辑器没有章节可载入 —— 剧本**根本编辑不了**；
- 状态栏只说了句"在内存里；点「⤓ 导出」才会进脚本"，
  而"导出"那时候也还没定文件路径。

### 修法

对话框多一格「**写入文件**」：

```
章节名（label）  [ chapter_02          ]
写入文件        [ <项目>/game/chapter_02.rpy ]   ← 默认跟着章节名走
变量操作        [ …                   ]
```

- 这一格**非空** → 创建节点前先把最小骨架写出来
  （`label 名:` + `return`），节点带上 `file_path` → 双击直接能编辑；
- 这一格**留空** → 不建文件，行为与从前一致（纯结构图）；
- 没打开项目时默认空（不知道往哪写，就不要猜）。

### 判据（`tests/test_new_chapter_writes_source.py`，14 条）

| 判据 | 结果 |
|---|---|
| 文件不存在 → 建出 `label X:` + `return` | ✔ |
| 文件已存在 → 追加，原内容**一个字节不动** | ✔ |
| 追加后 CRLF 不许被改成 LF（裸 LF 计数 = 0） | ✔ |
| BOM 不许丢、也不许重复插 | ✔ |
| 里面已有同名 label → 拒绝，文件不变 | ✔ |
| 那一格留空 → 一个文件都不写 | ✔ |
| 对话框默认路径跟随章节名；手改过之后不再跟随 | ✔ |
| `_has_label` 边界：注释里不算 / 前缀不误伤 / 带参数的认 | ✔ |

## 二、一个 `.rpy` 里写第二个 label 该怎么操作

> 我想在一个 rpy 文件里写出第二个 label 该怎么操作？

### 根因

**工具根本没有这个入口**。以前只有两条路：

- 「新建章节」→ 建 `<章节名>.rpy`（一个文件一章）；
- 「导入章节 .rpy」→ 按 **label** 建节点（一个文件多章能读进来）。

能读、能编辑，但**不能新建**。用户想在一个已有文件里加一章，没地方点。

### 修法

「写入文件」填一个**已有文件**时：

- 文件里没有同名 label → 往**末尾追加**：

  ```renpy
  （原有内容原样不动）

  label chapter1_2:
      return
  ```

- 追加按文件自己的**载体风格**（BOM / CRLF）铺回去；
- 文件里已有同名 label → 一个字都不写（重名 label 会让 Ren'Py 直接起不来）。

对话框的提示也改了，把这两条路写清楚：

> 「写入文件」非空时**先把它写进脚本**（`label 名:` + `return`），双击就能编辑；
> 填一个**已有的 .rpy** 就往那个文件末尾追加第二个 label（一个文件放多章是合法的）；
> 留空则只是图上的一个方块。

## 三、CI 三个版本全红

### 症状

GitHub Actions 三个 job（3.10 / 3.12 / 3.13）**全挂在「跑全量测试」的第 10 秒**
（依赖安装只用了 4 秒 —— 那本身就是线索）。

### 根因

`requirements-dev.txt` 里**只有 pytest**：

```txt
pytest>=8
```

而 CI 只跑 `pip install -r requirements-dev.txt`。于是 `conftest` 一
`import openpyxl` 就炸（本地能过，因为开发机装过 `requirements.txt`）。

### 补依赖之后，还有第二层

本地用"假装没装 PySide6"的假模块复现，补完依赖仍报 **17 个 collection ERROR**：
二十多个测试文件在**模块顶层**就 `from storygraph.ui_qt… import …`，
没装 Qt 时**收集阶段**就挂 —— `pytest.importorskip` 在模块体里，来不及。

两处修：

| 位置 | 改法 |
|---|---|
| `tests/_source_paths.py` | `module_source` 用 `importlib.import_module` 拿文件路径 → **改成 `find_spec`**（只解析路径、不执行模块体）。扫源码的测试只想读文件，不该顺手把 Qt 的顶层 import 跑一遍 |
| 5 个直接 import 的文件 | `pytest.importorskip('PySide6')` 挪到第一次 import 之前 |
| `tests/conftest.py` | 新增 `pytest_ignore_collect`：**没装 PySide6 时整份跳过**"import 了 Qt"的测试文件（按 import 行判，不看注释） |

最后那条是关键：**谁忘写 `importorskip` 都不影响 CI**。本机（装了 PySide6）
走第一个分支直接返回 `None`，行为完全不变。

### 为什么不直接给 CI 装 PySide6

Linux 上还要补 `libegl1` / `libxkbcommon` / `libdbus` 等系统库，多一个失败点；
而 UI 测试的价值主要在**本机真跑**（`QT_QPA_PLATFORM=offscreen` + 真字体）。
CI 的定位是"挡住无界面那 4000 多条回归"，够用。

### 验证（本地）

| 环境 | 改之前 | 改之后 |
|---|---|---|
| 无 PySide6（模拟 CI） | `17 errors during collection`，**一条测试都跑不了** | **4241 tests collected / 0 error** |
| 本机（有 PySide6） | 5506 passed / 5 skipped | 行为不变 |

### ⚠ 还没修完：第三层没定位到

推上去之后 **CI 仍然全红**，但症状变了 —— 三个版本都只跑 **4~8 秒**
（依赖装 6 秒、pytest 只跑 4 秒就退 1），说明**卡在 pytest 启动/收集**，
不是测试失败。

已经做了但没解决：

- CI 里加了 `::error title=pytest::…`，想把每条 `FAILED/ERROR` 变成
  annotation（手机上也能看）—— 结果 annotation 里只有
  「Process completed with exit code 1」，**一条 FAILED 都没有**，
  说明 pytest 连"失败清单"都没输出；
- 又把尾部 25 行原样变成 annotation —— 仍然没出现。

**下一步（需要原始日志）**：点开任意一个 job 的「跑全量测试」步骤，
把最后 20 行贴出来。怀疑方向按概率排：

1. `pytest.ini` 的 `addopts = --basetemp=.pip-tmp/pytest` 在 Linux 上
   解析成了不可写路径；
2. 某个 `conftest` 级 hook 在新参数下抛异常（本轮我加的
   `pytest_ignore_collect` 用了 `collection_path`，需要 pytest ≥ 8，
   而 `pytest>=8` 在 3.10 上装到的版本可能不同）；
3. `tests/` 里某个文件在 Linux 上 import 时读 Windows 路径直接抛错。

这轮不便继续盲改 —— 每改一次 2 分钟，且看不到输出。

## 四、控制台里 173 条静默失败

截图里最扎眼的那几条：

```
[静默失败] ui_qt.stage_preview.warnings ×2
    AttributeError: 'StagePreviewWindow' object has no attribute 'project_root'
[静默失败] thumb.loader.request ×173
[静默失败] recover_guid_find_sdk ×2  FileNotFoundError: 找不到 Ren'Py SDK
```

### 第一条是真 bug，已修

`pose_warnings()` 里写了 `self.project_root`，而这个类在 `__init__` 里存的是
`self._project_root` —— `AttributeError` 被 `swallow` 吞掉，表现是
**「姿势改回普通但没 hide」的提示一条都出不来**（功能整个哑掉，还没有任何报错）。

改成 `self._project_root`。

### 另外两条不是 bug

- `thumb.loader.request ×173`：缩略图加载失败（缺图 / 还没预热完），
  每条是"某一张缩略图没出来"，不影响任何数据；
- `recover_guid_find_sdk`：这台机器没装 Ren'Py SDK（或用环境变量
  `STORYGRAPH_RENPY_SDK` 指定），那几条引擎判据自然跑不了 —— 设计如此。

## 五、这个仓库以后怎么防止同类问题

| 这次漏在哪 | 已经有的守卫 | 补的守卫 |
|---|---|---|
| 对话框/节点字段没接上（`file_path` 支持但没人传） | `test_main_window_mixins` 扫 `self.*` 依赖 | 本轮它抓到 `_project_root` 没写进 `REQUIRES` |
| 属性名写错被 `swallow` 吞掉 | `test_no_silent_except`（禁裸 except） | —— 但 `swallow` 是**故意的**，抓不到拼错的属性名 |
| CI 只在真推上去才发现 | 本地 `pytest` | 本地用假模块模拟"没装 PySide6" |

**下次想看"没装某依赖时能不能跑"**，这条命令就够（`PySide6/__init__.py`
里写 `raise ModuleNotFoundError(...)`，`PYTHONPATH` 指过去）。
