## §0 判据：一条短板值不值得补，问三句

1. **补它会不会破三条护栏**（不改引擎 / 不改用户字节 / 能带走）？
2. **它是"加功能"还是"加引擎"？** 加引擎的一律不做——我们是工具，不是引擎。
3. **它服务的是策划的命脉，还是程序员的脸面？** 后者让给别人。

按这三条，缺口分成 **A 类 3 条 / B 类 2 条 / C 类 7 条 / 明确不做 4 条**，
外加 **§0.5 两条地基级缺口（G1/G2）**——它们**比 §1 的 A 类任何一项都优先**。

## §0.5 地基级缺口（G 类）：**比 A 类任何一项都优先**

> 这一节是复核时补入的。上一版把它们漏了——漏的原因是把它们当"工程卫生"，
> 而不是当**产品地基**。每条都有代码事实。

### G1 · 行为级契约进 CI（脱敏 fixture 当 golden）—— **别人敢不敢贡献的分水岭**

**实测现状**：

| 事实 | 证据 |
|---|---|
| CI 只跑 pytest + **两个** demo 步骤 | `.github/workflows/ci.yml`：`cli.py validate demo` + `cli.py compile demo/剧本表_ch01.xlsx` |
| **21 个**测试文件因 `skipif(not REAL)` 在 Linux CI 上**必然 skip** | `REAL = Path(r'D:\千连万理\RenpyTest\sr_general')` 硬编码 Windows 绝对路径 |
| 被 skip 的里面有**全部 8 个 golden 守卫** | `test_parse_golden` / `test_render_golden` / `test_patch_golden` / `test_hydrate_golden` / `test_scan_golden` / `test_validate_golden` / `test_describe_golden` / `test_golden_baseline` |
| 全部 **10 个**金标文件**已经在仓库里** | `tests/golden_*.txt`（`golden_patch_fingerprint.txt` 35KB、`golden_scan_fingerprint.txt` 1MB） |
| 可移植模式**已经跑通过一次** | `tests/test_fidelity_bytewise.py:45` 用 `demo/game/script/ch01.rpy` 当输入 |
| 但那个输入**太弱** | `demo/game/script/ch01.rpy` **39 行**；`menu` / `python:` / `#` 计数 **0** —— 覆盖不到任何保真边界 |

**所以结论不是"要新建机制"，而是"把已有机制从 1 个弱输入扩成一组边界集"**：
缺的是**输入**（真机项目里最能触发边界的那些 `.rpy`，脱敏后进仓库），不是**判据**。

**做法**：
1. 从真机 53 个 `.rpy` 里挑**边界样本**（嵌套菜单 / `python:` 块 / 行尾注释 /
   条件分支 / ATL transform / 自定义语句 / 同一 label 多段），**脱敏**
   （替换真实台词与资源名、去掉项目专有信息）后放进 `tests/fixtures/`；
2. **金标两边一起重录**：fixture 变了 → 对应 `golden_*.txt` 指纹必须重录，**单独提交**；
3. CI 里跑同一套判据（parse → render → sha256 → 比对），**不许 skip**。

**为什么它优先级最高**：
我们对外的核心承诺是"**逐字节零丢失**"。
这句话**现在没有任何自动化护栏**——fork 的人改 `patcher.py`，CI **不会红**
（守卫全在 skip 里）。**这不是测试问题，是产品承诺没有护栏。**

⚠ 顺带一条（上一版也没提）：项目现在是 `license = { text = "Proprietary" }`，
**没有 LICENSE 文件**。目标是 MIT 的话，"敢不敢贡献"是**三件一起做**才成立：
**LICENSE（MIT）＋ CI 契约护栏 ＋ 可提交的脱敏 fixture**。缺任何一件，别人仍然不敢提 PR。

### G2 · 引擎版本适配层 —— **护城河建在别人家的接口上**

**实测耦合清单**（我们控制不了的接口）：

| 耦合点 | 位置 | 引擎一改会怎样 |
|---|---|---|
| `renpy.list_images()` / `get_available_image_tags()` / `get_all_labels()` / `renpy.statements.registry` / `get_registered_image()` | `engine_collect.py:95-150`（探针源码内） | 取不到事实 → `probe_complete=false` |
| 探针注入机制（`init 999 python:` + 环境变量传路径） | `engine_collect.py:82` | 引擎改 `init` 语义 → 探针不执行 |
| `--json-dump` 输出格式 | `core/engine_facts.py` `SRC_JSON_DUMP` | 静态清单（transform/screen/define）**塌** |
| `lint --error-code` 退出码语义 | `engine_collect.py:559` | "有没有错"判错 |
| 引擎报错**英文文案**（`expected statement.`） | `statement_probe.py:122` `_PARSE_MARKS` | 判"是不是 parse error"失效 |
| `test` 命令输出格式（`[rpytest] Status:`） | `statement_probe.py:126` `_RPYTEST_STATUS` | 行为级验证失效 |
| SDK 路径探测（环境变量 + 硬编码候选 `renpy-8.4.1-sdk`） | `engine_collect.py:56,186` | 换机找不到 SDK |

**已有的**：事实文件**记了** `engine.version` 与 `engine.sdk`（`engine_collect.py:611`），
漂移检测（`diff_facts`）能事后发现"事实变了"。

**缺的（这才是问题）**：
1. **没有"我们支持哪些引擎版本"的声明** —— 没有版本矩阵，就没法在采集前说"这个版本我不保证"；
2. **没有按版本分派的解析层** —— `--json-dump` 换了字段名，代码直接读不到；
3. **降级不够响亮** —— 探针用 `put(key, fn)` 逐项 `try/except`，
   **引擎 API 改名时探针不崩，只是"少一个键"**，事实文件照常生成。
   （采集侧已有 `probe_complete=false` 当硬失败，但**"少了几项但仍然生成了"这一档还没闸门**）

**所以真正的修复不是"支持更多版本"，是三件事**：
① 声明支持矩阵（验过的 Ren'Py 版本 + SDK 路径）；
② 采集时**按版本分派**解析（版本不在矩阵 → 明确告警/拒绝，**不静默降级**）；
③ **降级必须阻断依赖方**：事实不全时，依赖引擎事实的功能（资产下拉、引擎驱动校验）
必须显式禁用并说清原因，不能让人拿到"少了一部分"的表还以为全了。

## §1 A 类：可以补，且**不碰架构**（纯增量，零风险）

| # | 项 | 现状（实测） | 要做什么 | 成本 |
|---|---|---|---|---|
| **A1** | **分发三件套** | 包**已经打好了**：`StoryGraph-1.0.0-win64-2026-10-21.zip`（71MB / 243 条目，含 `StoryGraph.exe` + `StoryGraph-CLI.exe`）。<br>⚠ 但实测 **xlsx = 0 个、md = 0 个、含 demo = 0 个** | ① 剧本空表格模板（Excel2Rpy 随包附，我们没有）<br>② 把 `demo/make_demo.py` 一键重建的示例工程打进包里（**脚本已存在**）<br>③ 3 分钟上手说明 | **小**：打包已有，缺的是"塞什么进去"和"怎么讲" |
| **A2** | **真机演示素材** | CI 里跑不了（`test` 需显示设备 → headless 不可用 → 行为级验证不进 CI 默认路径）。<br>但**本机有 SDK 就能跑** | 在有 Ren'Py SDK 的机器上跑一遍 demo，录屏/截帧成素材 | **小**：环境问题，不是能力问题 |
| **A3** | **引擎事实的用户可见形态** | `engine_facts.json` **已有**（每条带 `source`，冲突进 `conflicts`），但只有 CLI 看得到 | 把"images 317 / tags 235 / transforms 155 / labels 106"翻译成一句策划听得懂的话：**"你表里引用的 12 张图，有 3 张引擎根本不认识"** | **小**：数据已在，缺的是"翻译成人话"的那层 |
| **A4** | **本地化导出侧**（⚠ **只到导出为止**） | 现在走 Excel。行业标准是 **XLIFF / `.po`**（Unity Localization、Godot Dialogue Manager 都是） | 纯导出器 + **占位符保护**（`{}` `[]` `%s` / ATL 表达式不能被译文吃掉） | **小**：纯 IO，无语义 |

> ⚠ **A4 不是"本地化通道"，只是通道的一半。**
> XLIFF 是**双向**的：译者在 XLIFF 里改完翻译，**怎么回来**？
> 导入侧 = **稳定行身份**（§4）+ **受控补丁**（把译文写回 `.rpy`，且不碰别人的字节）
> —— 这两样**都不是纯增量**，分别在 §4 和 B3。
> **只导出不导入的 XLIFF 是个半通道**，单独上线只会制造
> "我导出了，译完发现回不来"的失望。
> **所以 A4 必须与 B3 一起做，且排在 §4 之后。**

> A1–A3 **都不产生新概念**，只是把已有资产暴露出去。
> A4 只有**导出那一半**是纯增量。

## §2 B 类：可以补，但**必须换做法**（做通道，不做引擎）

### B1 · TTS 与自动翻译

**错的做法**：自己造 TTS 引擎、自己造翻译机。
—— 打不过 GPT-SoVITS / VOICEVOX / Azure / ElevenLabs，也打不过 LLM API + Crowdin。

**对的做法**：我们做**三件护栏的事**，服务由外部提供：

| 我们做 | 内容 | 为什么是我们该做的 |
|---|---|---|
| **稳定 key** | 语音/译文 ↔ 剧本行的稳定对应 | **Ren'Py 官方 translation 用正文哈希做 ID → 改一个字就丢翻译**（官方自己警告"修改已翻译过的台词时要非常小心"）。这是全行业最痛的地方，而**我们有内容无关的身份键**（见 §4） |
| **占位符保护** | 译文不得吃掉 `{ }` `[]` `%s` / ATL 表达式 | Crowdin 等 TMS 把占位符 QA 做成卖点——**因为破坏占位符是配音/翻译事故的头号来源** |
| **术语表锁定 + QA 报告** | 漏译 / 占位符破损 / 长度异常 | 这正是"让表当 QA 通道"这条行业共识的落点 |

**边界**：我们**不做音色管理 UI**（那是 Excel2Rpy 的菜，且不影响我们的护栏），
不做自动翻译的"质量"。产物落 `game/audio/` 必须过 `WRITERS` 登记表 + 门禁（铁律 8）。

⚠ **前置条件在 §4**——TTS/翻译**第一步不是接服务**。

### B2 · Unity 侧演出加深

- **能做**：条件求值、菜单 UI、资源寻址。
  已有地基：`docs/unity/StoryIr.cs` 的 schema 1.1 已有 `structure`（path/kind/known）与
  `timeline`（按作者顺序的 scene/show/hide/with/audio/voice 事件）；
  `.unitypackage` 已含 `DialogueData.cs` / `DialogueDatabase.cs` / `DialoguePlayer.cs`（最小播放器）。
- **不能做**：ATL 对等（见 C3）。
- ⚠ **不要绑定具体第三方库**（DOTween / Tween / UniTask）——绑了就给别人打工。
  保持"中立事件 + 参考实现"。

### B3 · 本地化**导入**侧（XLIFF / `.po` → `.rpy`）

**这是 A4 的另一半，依赖两样现成但还没做扎实的东西**：

| 依赖 | 说明 | 出处 |
|---|---|---|
| **稳定行身份** | 译文 ↔ 剧本行要一一对应，且**改字不丢、插删不丢** | §4（当前 `LineId` 会随插删漂移） |
| **受控补丁** | 把译文写回 `.rpy`，**只动译文那一行**，其他行逐字节不变 | 铁律 1/2/5，已有 `patcher` |

**所以 B3 的实际形态**：XLIFF 导入 → 落到一张"待写回"的表 →
**先出 diff 给人确认**（铁律 5：未确认零写）→ 受控补丁写回 → 出写回报告。

⚠ **B3 依赖 §4。** §4 没做之前，B3 只能做到"导入到 Excel 里人工看"，
写回 `.rpy` 那一步会踩"插删位移"这个坑 —— 这正是 §4 说的那个坑。

## §3 C 类：架构上做不到 / **不该做**（每条给根因，不是"太难"）

### C1 · 真调试器（断点 / 单步 / 变量检视）——**不该做**

**根因不是难，是"Ren'Py 的解释器不是我们的"。** 要做，得同时维护：
语句级钩子（`config.statement_callbacks`）+ 栈帧与作用域重建（Ren'Py 作用域是 python frame，跨 label 调用要重建）
+ DAP 协议（断点映射、行号↔语句映射、消息序列）。
RenPy Code 已经做了（闭源，$5 买断，靠这个收费）。

**更要命的是方向相反**：我们说"策划不用碰代码"，做调试器是给程序员用的。

**便宜的替代（这个该做）**：我们的**探针注入机制 + 舞台快照**已经能拼出
"跳到某个 label → 跑 → 抓帧 → 给策划看"。
这回答的是**"我这一句播出来长什么样"**（策划的命脉），不是"这个变量为什么是 3"（程序员的脸面）。
→ **做这个，不做那个。**

### C2 · 实时协同（自动合并）——**架构上做不到**

三层根因：

1. **文本序列 CRDT 不理解 Ren'Py 语义。**
   CRDT 解决的是"同一段文本的并发编辑怎么合"。
   但 Ren'Py 的语义是**结构嵌套**——`if:` / `menu:` 的块体归属由缩进决定。
   两人同时做"menu 里插一个选项"+"menu 前插一个 label"，
   CRDT 合出来的文本**字节上合法，语义上可能把选项挂到错的分支**。
2. **CRDT 必须在真源层做**，而我们的真源是 `.rpy`（铁律 1）。
   想让 CRDT 可行 → 把 Excel/IR 变成真源 → **护栏①（不改引擎、接管已有项目）当场破掉**。
   那就变成 Excel2Rpy 那类工具了——放弃的是我们最硬的优势。
3. **"一个字节都不碰别人"与"无锁并发写"数学上互斥。**
   受控补丁要求基于当前文件状态逐行配对；两人基于同一快照改同一文件，
   第 2 个写必然基于过期状态 → 只能覆盖或拒绝。
   15 分钟租约锁**不是缺陷，是我们承认现实**。

**能做的（已在做）**：冲突检测 + 精确到行的差异 + 审计 + 结构冲突（`NEST_CONFLICT`）。
**做不到**：自动合并**且保证语义正确**。

⚠ 这是**产品决策，不是技术问题**——要实时协同，就得放弃"`.rpy` 是唯一真源"。

### C3 · 跨引擎"演出完全对等"——**做不到，且别承诺**

**根因：ATL 是 Ren'Py 特有语言。**
`at left` / `with dissolve` / `transform` 里的 `xalign 0.1 zoom 1.2` 在 Unity 里**没有对应物**。
"完全对等"必须**在 Unity 侧写一个 ATL 解释器**（等于再写一个引擎），而且永远追不上 Ren'Py 8.x。

**能做（已在做）**：**结构 + 事件顺序对等**（scene/show/hide/with/audio/voice 的顺序）+ **损失报告**。
**做不到**：手感级 / 像素级对等。

⚠ **必须写进对外话术**，否则用户会期待"导出到 Unity 后效果一样"——这是最容易招致失望的承诺。

### C4 · "引擎不认识的写法，探针永远答不了"——**我们自己撞出来的根本限制**

真机实测（`storygraph/pipeline/statement_probe.py` 的"一个根本限制"一节，原文记录）：

- `bare` 形态是**唯一可靠**的信号（`expected statement.` ⇒ 不认识）；
- `block` 形态**连胡写的头都被接受** → 答不了"认不认识"；
- 项目里有 parse error → 引擎**第一处就停** → 探针**整个失效**（连干净文件的问题也答不了）；
- 两种绕法**都失败**：放 `python` 块当字符串（能解析，但扫描器也扫不到）；
  注入 `register_statement("weather", …)` 再用（**仍然** `expected statement.`）。

**含义**：我们**永远无法对"引擎不认识的写法"给出引擎级保证**。
这是**引擎编译器的性质**，不是我们能力不足。

**唯一出路就是现有那条路**：扫描发现 → 报告 → 工程师去引擎那边注册 → "教它升级"。
（对应 `authoring/learn_statement.py` + `cli.py learn`。）

### C5 · Excel ↔ `.rpy` 的"自动合并"——**做不到，但有一个没收口的口子**

两个真源在时间上必然分叉。我们已有仲裁机制：
`_recover_ranges` → `fresh`（行号是否新鲜）、`trust_ranges`（只在行号被证明新鲜时才放宽配对），
以及 2026-10-21 修的"表过期覆盖" P0。

**做不到**：策划和程序**同时改同一位置**时自动合并且不丢。**任何方案都要一方赢。**
我们的解法是对的：**明确谁赢 + 给精确 diff + 绝不静默**。

⚠ **但还有一个没收口的口子**：`FieldSpec`（`storygraph/story/beat_fields.py`）目前只有
`hidden / collab / snapshot / fingerprint` 四个旗标，**没有"可写 / 派生"的旗标**。
也就是说——**"策划能改哪些列"目前没有契约**，全靠 UI 自觉。
两个入口都能改 → 迟早打架。

**建议**：不是新机制，是**把已有契约显式化**——
给 `FieldSpec` 加一个 `editable` 旗标 → 写进《契约速查》→ Excel 端对派生列**明确置灰**。
这一条同时解决"两个入口打架"和"策划误改结构列"。

### C6 · 节点图编辑器 ——**不该做**

- IF 社区 Fabulich 的原话（已记在 `docs/archive/叙事工具行业调研.md`）：
  "可视化只在不需要它的简单样例里有效，在最需要它的复杂环境里失效"；
  另一条是节点图会"悄悄推动作者用节点思考"，项目变大后形成"大陆、半岛与群岛"。
- RenPy Code Pro 已经有 Mermaid 流程图了。
- 我们已经有 `graph/`（结构图），但它的定位是**诊断视图，不是编辑器**——**这个定位是对的，别改**。

### C7 · "引擎事实驱动"的**边界**——**它不是全知**（上一版漏写）

护栏③（引擎事实驱动）**有明确边界**，必须写进对外话术，不能让人以为"引擎事实"是全知的：

| 情形 | 我们能给什么 | 我们**给不了**什么 |
|---|---|---|
| 项目里有引擎不认识的写法（parse error） | 扫描发现 + 报告 + "教它升级" | **引擎级保证**（引擎第一处就停，探针整个失效） |
| fork 引擎新增的自定义语句 | —— | **四路无信号，完全隐形**（《契约速查》已记） |
| 项目本身解析不干净 | `parse_clean=false` 标记 | 完整事实 |
| 引擎 API 改名（G2） | `probe_complete=false` + 逐项 `_error` | 事实缺项（除非按 G2 加了闸门） |

**一句话**：**引擎事实 = "引擎在没有被阻塞性语法错误挡住时，愿意说的那部分"**，
不是"这个项目里所有合法的写法"。超出这个范围的，一律走"扫描 + 人工教"。

⚠ 这条边界**同时是 G2 的动机**：正因为引擎事实的覆盖面取决于引擎的接口稳定性，
我们才必须把"版本支持矩阵 + 降级闸门"做出来，而不是默默依赖它。

## §4 一条被漏掉的**前置条件**：稳定行身份

要做 TTS / 翻译，**第一步不是接服务，是先把"行身份"做扎实**。
我们现有两套身份，各有各的缺口：

| 机制 | 怎么算 | 改台词 | **插入/删除拍** | 唯一性 |
|---|---|:---:|:---:|:---:|
| `LineId`（Excel 列"行号"） | `f"{label}.{seq:04d}"`（`beat_model.py:3405`） | ✅ 稳 | ❌ **后面所有拍整体位移** | ✅ |
| `_align_key`（对齐键） | (label, kind, speaker, condition, 舞台指纹)（`patcher.py:267`） | ✅ 稳 | ✅ 基本稳 | ❌ 旁白拍会重 |

**也就是说**：**"改字不丢"做到了，"插删不丢"没做到。**
而 TTS / 翻译最怕的恰恰是"中间插一句，后面 200 句的配音全错位"。

**行业里的三种做法**：

| 做法 | 代表 | 稳不稳 | 代价 |
|---|---|---|---|
| 内容哈希 | **Ren'Py 官方 translation**（`start_636ae3f5`） | ❌ 改字即丢翻译（官方自己警告） | 零 |
| 显式标签 | Yarn Spinner `#line:` / Godot Dialogue Manager `[ID:KEY]` | ✅ 稳 | **要人写** |
| — | **我们可以做到的** | ✅ 改字稳 + ✅ 插删不位移 | ✅ 工具自动生成 |

**为什么我们能做到别人做不到的**：
我们已经有 `_align_key` 这套"**内容无关特征**"的地基（label/kind/speaker/condition/舞台指纹），
只差一个**不随序号漂移的编号**——
把"编号"从 `seq`（会漂）换成"该位置的身份指纹"（不漂），`LineId` 就同时满足两条。

⚠ **这是 P0-2（TTS/翻译）真正的第一步**，而且它**同时是护栏③（能带走）的底层**：
跨引擎时"哪一行对应哪一行"是同一个问题。**做一次，两处受益。**

## §5 建议顺序

| 序 | 做什么 | 类别 | 为什么排这 |
|---|---|---|---|
| **1** | **G1 行为级契约进 CI**：脱敏 fixture 进 `tests/fixtures/` + 金标重录 + CI 不许 skip | **地基** | 我们对外的承诺"逐字节零丢失"**现在零护栏**；fork 者改 `patcher.py`，CI 不会红。**这是"敢不敢贡献"的分水岭** |
| **2** | **G2 引擎版本适配层**：支持矩阵 + 按版本分派解析 + 降级闸门 | **地基** | 护城河建在引擎的 CLI/内部 API/英文文案上；不设闸门，引擎一升级就静默塌 |
| 3 | **分发三件套**（模板 + demo 进包 + 上手说明）+ **LICENSE（MIT）** | A | 零架构成本；实测包里 xlsx/md/demo **全为 0**；LICENSE 现在是 `Proprietary` 且无文件 |
| 4 | **稳定行身份**（插删不位移） | 地基 | TTS / 翻译 / 跨引擎 / XLIFF 导入**四件事共用**同一个前置 |
| 5 | 引擎事实的用户可见形态 | A | 把已有数据翻译成策划听得懂的话 |
| 6 | **本地化通道**：XLIFF 导出（A4）**＋** 导入写回（B3）**一起做** | A+B | 导出侧小，导入侧依赖第 4 步。**只做导出 = 半通道，不要单独上线** |
| 7 | TTS / 翻译**通道**（接现成服务 + 三件护栏） | B | 依赖第 4 步 |
| 8 | Unity 条件求值 + 菜单 UI + 资源寻址 | B | 依赖第 4 步的稳定 ID |
| 9 | `FieldSpec` 加 `editable` 旗标 + Excel 派生列置灰 | C5 收口 | 防"两个入口打架"，纯契约显式化 |
| — | ❌ **不做**：真调试器 / 节点图编辑器 / 自造 TTS / 自造翻译机 / ATL 对等 / 实时协同自动合并 | C | 见 §3；补了会破护栏或方向相反 |

> **1 与 2 是"地基"，不是"任务"**：
> 它们不做，产品承诺就没有自动化证据；别人贡献时没有安全网；护栏建在别人家的接口上却没有闸门。
> **A 类那几条做得再好，没有地基也传不出去。**
