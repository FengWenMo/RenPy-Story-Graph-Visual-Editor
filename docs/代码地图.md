## 一、一句话

把 Ren'Py 的 `.rpy` 脚本摊成**一张演出表（Excel）**和**一张章节之间的关系图**，
让人在表里改演出、在图里串章节，再**逐行**写回原脚本 —— 原脚本里不归工具管的行，
一个字节都不碰。

三条不可让渡的底线（改任何代码前先读一遍 `.workbuddy/memory/MEMORY.md` 的十条铁律）：

1. **`.rpy` 是唯一真源**，不是"导入后再导出的中间格式"；
2. **要么全对、要么完全不动**，绝不产出"半对"的文件；
3. **认不出的写法原样抄**，不猜语义、不改缩进、不补 `$`。

## 三、三条主轴（改动 90% 落在这三条线上）

### ① 导入：`.rpy` → 拍

```
ui_qt/window_graph_ops.import_chapter_files(paths)
  → app/session_graph.import_chapters(files)
    → parsing/renpy_parser.analyze(files)        # 增量：按 (mtime, size) 复用缓存
      → story/beat_build.build_beats(...)        # Statement 流 →（折叠）→ Beat
        → story/beat_model.Beat                  # 一拍 = 源文件里一段连续行
```

要点：
- `analyze` 有**跨调用缓存**（`IncrementalRenPyAnalyzer`），91 章的项目刷新一次 4 ms；
  绕开它直接 `analyze` 会让"刷新"重新变成 3 秒。
- 拍上带 `source = (路径, 行号)`，**行号是运行期元数据，不写进 Excel**；
  从表里读回来的拍没有行号，要 `patcher._recover_ranges` 现算。

### ② 编辑：拍 ↔ 表

```
app/beats.py（卡片语义）  ←→  story/beat_model.py（单元格编解码原语）
                                ↑
                     story/excel_export.py / excel_import.py
                     story/xlsx_preserve.py（保住用户手写的列与整页）
```

要点：
- **同一个字段只有一份契约**（`story/beat_fields.py`）。卡片上改和表里改必须走
  同一条路，否则"卡片改完导出"和"表里改完导出"会给出两份不同的结果。
- Excel 是**第二份源码**：用户会在里面加自己的列、自己的页。写表一律走
  `xlsx_preserve`，不许整份重建。

### ③ 导出：拍 → `.rpy`（最危险的一段）

```
ui_qt/window_export → app/session_export.export(target)
  → compile()                              # 拍 → 代码文本
  → _patch_note(text)                      # 决定走增量还是全量
      → story/patcher.patch_export(...)    # 只替换真改过的行
  → story/generation_guard.write_generation(text, target, project_root=...)
                                          # 最后一道门禁：拒写手写文件、拒写会跑不起来的脚本
```

`export` 的返回值就是它的契约：`{ok, path, note, todos, blocking, codes}`。
`ok=False` 时 **`text` 不可用**，`codes` 决定界面给不给"强制覆盖"这个逃生舱 ——
只有 `HANDWRITTEN_TARGET` 可覆盖，语法/重名不可。

## 三·五、界面层为什么是一堆 mixin（历史只讲这一次）

`ui_qt/` 里有 6 个 `window_*.py`，每个都是一个 mixin，`MainWindowQt` 由它们拼成。
这段来历从前在**6 个文件的 docstring 里各抄了一遍**（每份 22 行，逐字相同），
现在收在这里 —— 想知道"我这个文件为什么长这样"，看这一节就够了：

- `MainWindowQt` 原本是 **3452 行 / 120 个方法的上帝对象**（`EditorSession`
  是它的另一半，已拆成 6 块）。拆 UI 比拆会话难，因为：
  · UI 层的行为测试薄得多，而且每条都要真起 Qt；
  · 方法之间靠 **Qt 信号**耦合，不能按"主语是什么"干净切开。
- 所以顺序是 **先补网、再拆**：`tests/test_main_window_snapshot.py`（63 步操作
  序列 golden）先把外部可观察行为钉死，拆分全程必须一直绿。
- 做成 **mixin 而不是独立对象**：调用方（菜单、工具栏、信号、`open_editor`）
  一行都不用改 —— 这是**搬家**，不是改契约。

| 文件 | 管什么 |
|---|---|
| `window_card.py` | 卡片页：载入单章 / 拍列表 / 导航 / 增删卡片 / 卡片级撤销 |
| `window_graph_ops.py` | 剧情图：结构分析 / 章节导入导出 / 布局存取 / 图级撤销 |
| `window_nodes.py` | 模块 ↔ 卡片、画布上的增删连边与右键菜单 |
| `window_export.py` | 导出 / 体检 / 舞台预览 / 剧本表 —— 与外部世界打交道的那一批 |
| `window_assets.py` | 资产选择：图片、下拉候选（资源表经会话取，不自己读表） |
| `window_keyboard.py` | 键盘与快捷键 |
| `window_nav.py` / `window_state.py` | 顶部模式条 + 左导航 + 右栏属性表 / 窗口记忆 |

**每个 mixin 自己只声明两件事**：类里的 `REQUIRES`（宿主必须提供哪些成员，
静态扫 `self.*` 得出，`tests/test_main_window_mixins.py` 守着），
以及"本文件只做界面编排、语义一律调 `storygraph.app.*`"这条纪律。

## 五、术语表（读代码时最容易被这些词绊住）

| 词 | 代码里叫什么 | 意思 |
|---|---|---|
| **拍 / Beat** | `story/beat_model.Beat` | 一个演出单元 = 一张卡片 = 源文件里的一段连续行。台词、菜单、`show` 组合、控制流都各是一拍 |
| **章节** | chapter / label | 一个 `label` 及其块体。图上一个方块 |
| **编排层** | `_control` 文件 | 工具维护的跳转骨架（`jump`/`call`/`menu`），**不写进剧本文件** |
| **语句表** | `StatementRegistry` | "哪些语句工具管、管到哪一级"。**不是** `session.registry()` |
| **资产表** | `AssetRegistry` / `session.registry()` | 图片、音效、角色、transform 的登记表 |
| **引擎事实** | `engine_facts.json` | 引擎自己公布的图像名 / 属性 / transform，带 `source` 与 `conflicts` |
| **身份解析** | `assets/asset_identity.Identity` | 一张图 → `(kind, tag, attrs, showable)` 的**唯一判定**；认不出 = `unknown`，不猜 |
| **资源映射** | `storygraph.mapping.json` | 项目级的"这张图是谁"覆盖表（characters / rules / images / attributes），工具没有它也能按目录推断 |
| **真立绘** | `Identity.showable=True` | 能直接写进 `show <spec>` 的图；`cc_preview` 那类预览副本要先换成它 |
| **过场 / Effect** | `story/transition_catalog.Effect` | 项目自定义转场的"效果描述"（kind / 时长 / 颜色 / 遮罩），预览按它演中间帧 |
| **门禁** | `generation_guard` | 写盘前的最后一道：拒写手写文件、拒写会让游戏报错的脚本 |
| **增量补丁** | `patcher` | 只替换真正改过的行，其余逐字节保留 |
| **行身份** | `LineId` | 一行在多次导出之间保持不变的身份，`story/line_identity.py` 发号 |
| **载体风格** | `source_style` | BOM / 换行符。读的时候记住，写回去按原样还原 |
| **IR** | `pipeline/*_ir*` / `engine_exporters` | 中立中间表示，给 Unity 等其它引擎用 |

## 六、代码里已有的书写约定（照着写，读的人才不费力）

1. **每个模块顶部有一段 docstring**：第一行是"这是什么"，中间是"为什么是这个形状"，
   最后往往带"边界（不做什么）"。新增模块请保持这个三段式。
2. **函数体内用 `# —— 小节名 ——` 分段**。超过 80 行的函数，docstring 里要写
   "本函数分 N 段：①…②…"，让人先看目录再读正文。
3. **"为什么"写在注释里，"是什么"写在名字里**。名字里不许有 `_tmp`、`data2`、
   `handle`；`data` 只在确实什么都可能是的时候才用。
4. **错误信息是给人看的中文**，并且要写"有两种可能，我分不开"这种实话，
   不要写"操作失败"。
5. **静默失败是缺陷**。`except: pass` 必须换成 `core/safeguard.swallow(位置, e)`。
6. **注释里的日期与审计编号只用来追溯，不要当成事实来源** ——
   它们描述的是写注释那天的代码，可能已经不准了。
