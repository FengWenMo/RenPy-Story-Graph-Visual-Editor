# 契约 · 行身份（LineId）

> **这份是什么**：`LineId` 的**规则表**。它是 XLIFF 的 `trans-unit/@id`、TTS 语音文件的 key、
> Unity 行映射、协作库主键**共用**的那一个身份。规则先写下来，用例逐条钉住
> （`tests/test_line_identity_contract.py`），实现只有一份
> （`storygraph/story/line_identity.py`）。
>
> 背景：路线图步骤 0（[`路线图_下一步执行.md`](路线图_下一步执行.md)）；
> 为什么身份不稳 = 进不了专业本地化流程：见
> [`短板可行性评估_2026-10-23.md`](短板可行性评估_2026-10-23.md) §4。

---

## 1. 定义

```text
LineId = f"{label}.{NNNN}"      例：ch01.0007
```

- `label` 是这一拍所属的 chapter label；`NNNN` 是**该 label 内**的号（4 位起，老表的 5 位也认）；
- 解析/发号的唯一实现：`storygraph.story.line_identity.parse / allocate`；
- 它**与内容无关**（不含台词、说话人、条件、舞台）——这是与 Ren'Py 官方 translation
  的根本区别（官方拿正文哈希当 ID，改一个字就丢翻译）。

**与 `Beat.beat_fingerprint` 的分工**（别混）：

| | `line_id` | `beat_fingerprint` |
|---|---|---|
| 回答 | "**这是哪一行**" | "**这一行现在长什么样**" |
| 改一个错别字 | **不变** | 变 |
| 用途 | 翻译 key / 语音 key / 锁与评论 / 行映射 | 冲突检测（"我没动，别人动了吗"） |

## 2. 规则表

| # | 操作 | LineId 行为 | 实现点 | 用例 |
|---|---|---|---|---|
| R1 | 改台词正文 | **不变** | 内容在 `Beat` 上，不参与发号 | `test_editing_text_keeps_id` |
| R2 | 改说话人 | **不变** | 同上（⚠ 发号器不许含 speaker） | `test_editing_speaker_keeps_id` |
| R3 | 改条件 | **不变** | 同上（条件**不进** ID） | `test_editing_condition_keeps_id` |
| R4 | 改舞台（show/hide/scene/bgm/sfx/with） | **不变** | 同上 | `test_editing_stage_keeps_id` |
| R5 | 插入 / 复制一行 | 新行拿**全新且不重复**的 ID；其余行**不变** | `editor._renumber` + `line_identity.allocate` | `test_inserting_a_line_keeps_every_other_id` || R6 | 删一行 | 该行 ID **作废**；其余行**不变** | 同上（删除不动别人） | `test_deleting_a_line_keeps_every_other_id` |
| R7 | 移动一行（改顺序 / 跨 label 搬） | **不变** | `seq` 跟着位置走，ID 不跟着 | `test_moving_a_line_keeps_its_id` |
| R8 | 表 → `.rpy` → 表 | **全部不变** | `LineId` 是表里的**存量列**（`Beat.to_row`） | `test_roundtrip_through_the_script_keeps_ids` |
| R9 | 从 `.rpy` **重新摊表覆盖**已有表 | 能对上的行**不变**；对不上的发新号 | `script_table._reuse_existing_ids`（两轮匹配） | `test_rebuild_over_an_existing_table_keeps_ids` |

> **R7 是整张表最关键的一条**：位置不是身份的一部分。
> 2026-10-23 之前 `EditorSession._renumber` 按位置重写**所有** ID ——
> 插一张卡，后面每一行都换身份（协作锁/评论当场错位）。现在它只给"没有身份的行"发号。

> **R5 的发号细则**：从 `.rpy` 解析出来 / 老表里本来没有身份的行，
> **优先用它自己的 `seq`**（`ch01.0007`）—— 这样重解析、老表迁移的编号与从前一致；
> 只有那个号已经被占用时，才退到 `max + 1`。会话里**新插入**的行没有"自己的号"，
> 一律 `max + 1`。

## 3. 不变量

- **I1 唯一**：一个工作簿内不重复（含跨 label）。重复的由
  `line_identity.unique_ids` 重新发号（保留第一次出现的那个）。
- **I2 内容无关**：R1–R4、R7 全部成立（发号器只看 label 与已用集合）。
- **I3 不回收**：删掉的号不再发给新行 —— **在同一文档生命周期内保证**
  （`allocate` 取 max+1 且跳过已用）。⚠ 局限：如果删掉的恰好是**当前最大号**，
  存盘后表里就没有"曾经发到哪"的记录，下次会话可能复用到它。
  要做到跨会话不回收，得在「表信息」里记水位线（本轮没做，见 §5）。
- **I4 重建保号**：重新摊表覆盖时，**内容完全一致**的行按多重集复用旧 ID；
  剩下的行**数量相等**时才按相对顺序配对（"只改文案、结构没动"这一档），
  数量不等就整批发新号 —— **不猜**。宁可换号，也不把 A 的身份挂到 B 上。
- **I5 往返守恒**：R8 全绿（表里存的就是 `LineId` 列，读写都不重算）。

## 4. 反例（会踩的编辑）

| 反例 | 后果 | 由谁挡住 |
|---|---|---|
| 在 `_renumber` 里按位置重写 ID | 插一行 → 后面全换身份 → 翻译/语音/评论错位（**静默**） | R5/R6/R7 用例 |
| 用 `label.seq` 直接发号 | 新行与既存行撞号 → 协作库 `UPDATE ... WHERE line_id` 改错行 | `assign_identity` 里 `allocate` + `unique_ids` |
| 把条件/说话人塞进 ID | 改一个条件就丢翻译（官方 translation 的坑） | R2/R3 用例 |
| 拿内容哈希当 ID | 改一个字就换身份 | §1 的分工（`beat_fingerprint` 才是哈希） |
| 重建时"按行号配对" | 插删过的表整体错位（第 3 行配到别人第 3 行） | I4 的"数量不等就发新号" |

---

## 5. 边界（明确不做）

- **不做 ID 回收池**：ID 一旦作废永不复用（避免旧翻译/旧语音挂到新句子上）。
  跨会话那一档的局限见 I3 —— 要补就在「表信息」加 `ID水位` 键，不是改发号器。
- **不做跨项目稳定**：每个工作簿独立命名空间（`ch01.0001` 在两个项目里互不相干）。
- **不把内容哈希当 ID**：见 §1。
- **不保证"重建时改过的行沿用旧号"**：内容变了、结构也可能变了，硬配会配错（I4 的保守档）。
