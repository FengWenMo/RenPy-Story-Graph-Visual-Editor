# `show` 的顺序：三层保证 + 地狱测试（2026-11-05）

> 用户：「总之我需要你解决这个问题！……顺序不能够错！错了 rpy 就完全不能跑啊！
> 做完后，写地狱测试！」

## 一、先看真项目长什么样（这决定了"顺序"到底指什么）

从 `D:\千连万理\sr_general` 的 8071 拍里统计：

| 形态 | 数量 |
|---|---|
| `show` 拍总数 | 1534 |
| 带**子句**（`at` / `with` / `behind` …） | **14** |
| 带 **`@` 内联位置** | **305** |

实际的样子：

```
show='lan scared at i11 with vpunch'
show='cg cg02_2 at cg38402160 behind ye'
show='ye aa happy@l11'
```

⇒ **`beat.show` 不是纯属性串**。所以"顺序不能错"有两层意思，两个都得治：

| # | 顺序 | 错了会怎样 |
|---|---|---|
| ① | **属性之间** | 语义等价（Ren'Py 不看顺序），但卡片显示对不上、`.rpy` 字节被改 |
| ② | **属性 vs 子句** | **真语法错** —— 属性只能出现在 `at` 之前 |

②是真会炸的：旧实现把 `at` / `i11` / `with` / `vpunch` 全当属性词，
切一维时"替换 + 追加"重拼，追加出来的词落到 `with vpunch` **后面**：

```
show lan scared at i11 with vpunch clothes2      ← 整份 .rpy 跑不了
```

## 二、三层保证

### 第 1 层：拆子句（`split_show_spec`）

```python
'lan scared at i11 with vpunch'
    → ('lan', ['scared'], 'at i11 with vpunch')
'ye aa happy@l11'
    → ('ye', ['aa', 'happy@l11'], '')
```

`clauses` 是**原样字符串**，拼回去时一个字节都不动。
子句关键字取自 Ren'Py 文档：`at` / `as` / `behind` / `onlayer` / `zorder` / `with`。

### 第 2 层：属性区**原位替换**

`_replace_attr_word` 只换它认识的那一个词，其余词（含不认识的 `_hd_cut`）留在原位：

```
lan clothes2 happy  --服装=base_hand_up-->  lan base_hand_up happy    ✓
```

`@l11` 是**附着在属性上**的内联位置 —— 换那个属性时**跟着走**：

```
ye aa happy@l11     --表情=care-->         ye aa care@l11            ✓
lan aa@l11 happy    --表情=angry-->        lan aa@l11 angry          ✓
```

### 第 3 层：列顺序按 `rules.json` 的声明

`show.pattern` 就是顺序码（`角色 → 服装 → 表情`）：
`_declared_column_order()` 读它，`_reorder_by_declared()` 按它排引擎组。
"哪一列对哪个组"靠**候选值交集**（作者自己写的数据），不猜列名。

## 三、三条不变量（判据就钉这三条）

| # | 不变量 | 判据 |
|---|---|---|
| **I** | 切一维**只改一个词**：词数不变、位置不变、其余**逐词相同** | `TestOnlyOneWordChanges`（12 组 × 2） |
| **II** | **子句区逐字节不动** | `test_clause_region_is_untouched` |
| **III** | 新增一维 → 插在**属性区末尾、子句之前** | `TestAddDimension` |

## 五、**引擎实跑**判据（用户："必须保证能跑不报错"）

字符串比不出来"能不能跑"——`lan happy with dissolve clothes2` 和
`lan happy with dissolve` 都是"一串词"，前者却是语法错。所以加了一层
**真让引擎读**：`assets/engine_images.verify_show_specs()`。

做法：镜像项目（只拷 `.rpy`）→ 写 `_sg_verify.rpy`，每条 spec 一行 `show …`
→ 跑一次 lint → 把报错按行分回每个 spec。

**故意分开两类**：

| 桶 | 引擎的话 | 意思 |
|---|---|---|
| `fatal` | `end of line expected` / `expected statement` | **真跑不了**（属性跑到 `with` 后面） |
| `unknown_image` | `'X' is not an image` | 名字不存在（资源没做齐时**是预期内的**） |

拿后者当"顺序写错"会误判，所以只对 `fatal` 判红。

### 实测（小项目，9 条 spec）

```
**跑不了**（2 条）:
  [7] lan happy with dissolve clothes2        end of line expected   ← 正是"属性在 with 后面"
  [8] lan happy at left with dissolve angry   end of line expected
合法的那 6 条里被误判的: 无 ✓
```

### 判据（`tests/test_show_spec_engine_verified.py`，3 条）

| 用例 | 钉什么 |
|---|---|
| `test_every_generated_spec_is_accepted` | 18 组输入 × `apply_attr_slot` 的**每一行产物**丢进引擎，`fatal` 必须为空 |
| `test_clauses_keep_their_order_after_the_change` | 子句**内部**顺序也不变（`at` 在 `as` 前、`with` 最后） |
| `test_a_known_bad_order_really_fails` | **反向对照**：故意错序的行，引擎必须拒 —— 证明判据不是永远绿 |

**这一组故意不写 `storygraph.rules.json`**：靠引擎的 `layeredimage` 分组 +
项目 `transform` 生成，验证"没有 json 也能过"（用户："可能甚至不会有 json
文件给你查"）。

## 六、关键字后面跟**你自己定义的名字**（`with aa` / `at form`）

用户：「把 with at 等关键字也写测试……比如定义一个 with aa form 等……」

`aa` / `form` 长得**跟属性词一模一样**，但位置不同 → 语义不同：

| 位置 | `aa` 是什么 |
|---|---|
| `lan aa happy`（`at` 之前） | **服装代号**（layeredimage 的 attribute） |
| `lan happy with aa` | **transition 名**（`define aa = Dissolve(…)`） |
| `lan happy at aa` | **transform 名**（`transform aa:`） |

判据：**位置决定语义** —— 一旦过了 `at` / `with`，后面的词一个都不许当属性。

### ⚠ 引擎当场抓到我编错了一条用例

我在引擎测试里写了 `('lan happy with aa form', …)`，引擎原话：

```
game/_sg_verify.rpy: line 6: end of line expected.
```

**`with a b` 是非法 Ren'Py** —— `with` 只接**一个** transition
（要组合就先 `define aa_form = Dissolve(…)` 再 `with aa_form`）。
`at` 可以接多个，但要用**逗号**（`at a, b`）。

⇒ 引擎测试里改成合法的 `with aa_form`；**解析层**仍保留 `with aa form`
（工具遇到别人写错的行要能**不崩地原样保留**，那是两件事）。

### 判据（纯字符串层，14 条）

`tests/test_show_spec_hell.py::TestClauseKeywordsWithCustomNames`

| 用例 | 钉什么 |
|---|---|
| 14 种形态（`with aa` / `at form` / `at aa form` / 全组合） | 关键字后一律进 clauses |
| 同一个词两种身份（`lan aa happy with aa`） | 切服装只改属性区那个，`with aa` 不动 |
| 只出现在子句里的名字（`at form`） | 不许被算进属性区 |
| `behind aa` / `as aa` / `onlayer aa` / `zorder aa` | 全都不许当属性 |

### 判据（引擎层）

引擎测试项目里**真的定义**了 `define aa = Dissolve(0.25)` /
`transform form:` / `transform aa_pose:`，然后：

- `lan happy with aa` / `at form` / `at form with aa` / `at aa_pose with aa`
  / `at form zorder 3 with aa` / `behind aa at form` / `as aa at form`
  —— **全部要过引擎**；
- 切维度后子句**逐字节不变**。

## 七、**自定义结构**：5 维 `show` + `with tt form`

用户：「这可不一定！……自定义一个新结构……with 后面跟两个变量，比如 with tt form，
transform 也要这样，还有，show 增添多几个自定义结构，变成 show 角色 动作 服装 表情
特效，一个都不许乱！」

⇒ **不能再硬编码**。工具从 `rules.json` 的 `show.pattern` 读两样东西：

| 从 pattern 读 | 干什么 | 读不到时 |
|---|---|---|
| `choice` / `variable` 段的 `column` 顺序 | 决定卡片「属性 1..N」的列序 | 用引擎组的顺序 |
| `optional` / `keyword` 段的 `text` | **加进**关键字集合 | 只剩 Ren'Py 原生六个 |

⚠⚠ **关键字是并集，不是替换**（用户明确）：

> 「原生+自定义需要并存！at 和 with 实际上是关键字优先，所以不会设置为变量本身，放心」

即：`原生六个 ∪ 项目声明的`。并存不会打架 —— **关键字优先于变量**，
`at` / `with` 永远不会同时是某一列的值。

样例声明（`tests/test_custom_structure_hell.py` 里的 `RULES`）：

```json
{"statements": [{"name": "show", "pattern": [
  {"kind": "keyword", "text": "show"},
  {"kind": "choice", "column": "角色", "options": ["lan","ye"]},
  {"kind": "choice", "column": "动作", "options": ["walk","stand"]},
  {"kind": "choice", "column": "服装", "options": ["blue","white"]},
  {"kind": "choice", "column": "表情", "options": ["smile","cry"]},
  {"kind": "choice", "column": "特效", "options": ["fire","bolt"]},
  {"kind": "optional", "text": "with"},
  {"kind": "variable", "column": "转场1"},
  {"kind": "variable", "column": "转场2"}]}]}
```

于是 `lan walk blue smile fire with tt form` 被拆成：

```
('lan', ['walk','blue','smile','fire'], 'with tt form')
                                          ↑ 两个变量**都**归子句
```

### 判据（`tests/test_custom_structure_hell.py`，15 条）

| 组 | 钉什么 |
|---|---|
| `TestDeclaredStructure` | 5 列顺序按声明；关键字**从 pattern 读**（不是硬编码）；`with` 后**两个**变量都归子句 |
| `TestFiveDimensions` | 切 4 个维度中的任一维 → **只改一个词**；`with tt form` **逐字节不动**；新增插在子句前；清空保住 5 维顺序；卡片「属性 1..4」= 动作/服装/表情/特效 |
| `TestNoHardcodedKeywords` | 没有 `rules.json` → 原生六个照旧；项目声明了 → **并集**（`at` 和 `with` 同时生效）；`lan walk blue at form with tt form` 两边都认 |

## 六、还没做的

- **不自动改写已有行**：`show='lan happy clothes2'` 这种已经反了的行不会**自动**改回
  `lan clothes2 happy`（那是写操作）。现在保证的是"切的时候不再乱 + 卡片按你的列显示"。
- 属性**之间**的顺序仍是"原位保持"（不做全局重排）—— 因为重排会改 `.rpy` 字节，
  而 `test_patch_golden` 要求往返一致。
