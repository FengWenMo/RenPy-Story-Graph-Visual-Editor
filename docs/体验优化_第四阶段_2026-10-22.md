## 一、这一轮解决的是"点得到"的问题

上一轮把控制流卡和图边打通了，但用户在界面上真正会碰到的几个地方仍然是断的：

| 报告项 | 之前 | 现在 |
|---|---|---|
| P1-2 变量 | 一整章 Python 文本框；改完只进图节点，**导出 `.rpy` 不变** | 变量工作台：变量表 + 初值 + 每条赋值在第几拍；改一条、删一条、跳到那一拍；改完**写进拍**，导出就变 |
| P1-5 控制台 | 212 条同格式 `[静默失败]` | 一次操作一行摘要 + 分组诊断面板（代码 / 环境 / 资源），同类聚合，可复制 |
| P1-4 补全/重载 | 点完才知道导入了什么 | 先给预览（文件 / label 增删），名字改成「补全缺失章节…」「刷新已导入章节…」 |
| P1-3 连线 | 画完不知道会不会写脚本 | 手工线画成点划线，状态栏/对话框/图例三处都说"草图，不写 .rpy" |
| P2-4 剧情图 | 关掉就没了，没有提示 | 状态栏「● 剧情图未保存」，关窗自动存 `storygraph_layout.json` |
| P2-2 新建章节变量 | 变量只进内存节点 | 和 `label 名:` 一起写进骨架文件 |
| P2-3 默认目录 | 固定 `game/<名字>.rpy` | 跟随项目里已有章节的目录（通常是 `game/script/`） |
| P1-1 label 边界 | 卡片列表平铺所有拍 | 每个 label 的第一拍尾部标 `〔label 名〕` |

## 二、变量工作台（P1-2）

**入口**：右栏「📋 变量工作台…」，或右键模块 →「变量工作台…」。

上面是变量表：

```text
变量      初值    本拍操作              出现位置
love      0       love += 1            第 5 拍
route     —       route = "roof"       第 7 拍
flag      True    —                    —
```

- 初值来自文件级 `default` / `define`（`_variable_declarations`）；
- 操作来自 `story_ops.narrative_statements(node)`，每条带 `source` 行号；
- "出现位置"由文件解析成拍后按 `src_first..src_last` 对位；
- 只声明、没赋值的变量也列出来（这正是从前"看不到 love 初值"的原因）。

下面是按源顺序的操作列表。选中一条：

- **保存这条修改**：只改这一条，不影响其它赋值；
- **删除这条**：从本章变量操作里移除；
- **定位到这一拍**：关窗并跳到那条赋值所在的拍；
- **＋ 新增变量 / ＋ 新增操作**：追加到当前选中那条的**同一拍**后面；
- **语法检查**：沿用 `check_variable_syntax`。

**关键修法**：新增 `EditorSession.apply_node_variable_edits()`。
它把改动按行号写回 `Beat.code`，再更新图节点。导出读的是拍，所以
"改变量 → 导出"终于闭环。对不上拍的手工操作会在返回值里报 `unplaced`，
不会假装写成功。

> 边界：变量工作台只改**简单一行**赋值；`if` / `for` 的结构重排仍走
> 「编辑剧情变量…」的文本区或源文件。新增操作放到选中拍之后，
> 不改变原有嵌套结构。

## 三、诊断面板（P1-5）

`core/safeguard` 新增 `snapshot()` / `records()` / `report_since()`：

- `_swallow_mark()` 从"总条数"改成"每种 context 的计数快照"；
- `_report_swallowed()` 只报本次**新增**的那些，并收成一行：

```text
[静默失败] 本次 174 次（2 处）：thumb.loader.request ×173（…）、sdk.find ×1
```

- 控制台上方出现一条摘要：

```text
⚠ 本次操作：1 个代码问题 · 173 条资源未加载    [详情] [复制诊断]
```

「详情」按三组展开：

| 分组 | 判据（只看 context 名） | 默认展开 |
|---|---|---|
| 代码问题 | 其余 | ✅ |
| 环境未配置 | 含 `sdk` / `engine_lint` / `recover_guid` … | ❌ |
| 资源未加载 | 含 `thumb` / `asset` / `image` / `audio` … | ❌ |

同类只显示一行（`×173`），可一键复制全文给开发者。

## 四、补全 / 刷新（P1-4）

工具栏与右键菜单改成：

- `🔗 补全缺失章节…`
- `🔁 刷新已导入章节…`

两者都先弹 `SyncPreviewDialog`：

**补全**：列出将导入的文件 + 每个文件里读到的 label；项目里找不到的跳转目标也列出来。

**刷新**：按文件对比图上的 label 与磁盘上的 label，写明"新增 N / 源里已删除 M"；
读不出 label 的文件明确说"这次不会删任何已有模块"（与导入时"解析有错不删"同一条守卫）。

确认后才走原来的 `import_chapter_files`。

## 五、图与布局（P1-3 / P2-4）

- `Edge.origin='manual'` 的线画成 **DashDotLine**，悬停提示
  "手工草图：只画在图上，不写进 .rpy"；
- 画布下方图例：`实线 = 脚本里的控制流 · 点划线 = 手工草图（不写脚本）`；
- 添加连线对话框的说明与按钮改成「创建草图连线」，并指路「↳ 插入控制流卡」；
- 状态栏新增「剧情图」标签：`● 剧情图未保存` / `✔ 剧情图已保存`；
- 判据是布局 JSON 的指纹（`layout_signature`），在 `_set_graph()` 唯一同步点比较，
  拖块、撤销、派生边都不会漏；
- 关窗时若有未保存改动且已打开项目，自动写 `<项目根>/storygraph_layout.json`；
  写失败只在控制台记一条，**不拦关闭**。

## 六、新建章节（P2-2 / P2-3）

`_write_new_chapter(view, path, label, operations)`：

```renpy
label new_ch:
    $ score = 0
    # 备注
    return
```

- 对话框里「变量操作」先做逐行 `ast.parse`，语法错就地提示，不会写出坏脚本；
- 追加到已有 `.rpy` 时保留原文件字节与 BOM/CRLF；
- 默认目录由 `_default_chapter_dir()` 算：取已知章节里最常见的父目录，
  并列时取更深的那个；没有已知章节才退回 `game/`。
