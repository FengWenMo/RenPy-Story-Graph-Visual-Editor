## 二、卡片左栏：label 分组（可折叠）

`_reload_list()` 重建列表时，多 label 的文件会插入**分组标题行**：

```text
▾ main_a　（3 拍）
    1 e：one
    2 e：two
    3 e：three
▾ side_b　（2 拍）
    4 e：four
    5 e：five
```

- 标题行 `Qt.UserRole = -1`，**不可选中**（`ItemIsEnabled` 但不带 `ItemIsSelectable`）；
- 每行 `Qt.UserRole` 存**拍号**，`_beat_rows[拍号] = 行号`；
  从前行号就是拍号，现在标题行会插进来 —— `_show_index` / `refresh_list_row` /
  `_on_select` / `resync_after_export` 全部改走这个映射；
- 点标题行折叠：子行 `setHidden(True)`，**不重建列表**（滚动位置与选中态都留在原处）；
- 折叠的是当前拍所在的组时，"当前"挪到标题行（`_loaded_idx` 不动，卡片还显示那一拍）；
- 任何导航（点节点 / 切 label / 翻拍 / 插入卡片）都先 `_expand_label()`，
  不会出现"跳进折叠区、列表里没高亮"。

**单 label 不加标题行**：没有歧义时多一行只是噪音，也保住了"行号 == 拍号"的常见路径
（老判据与测试不用为它改口）。

> 判据里如实改了 `test_card_selection_sync` 的三处行号断言：现在必须
> `_row_of_beat(i)` 取行，不能把行号当拍号 —— 这正是这轮要钉住的契约。

## 三、变量工作台：`if` / `for` 块内插入

### 3.1 先让界面看得见"在哪个块里"

`variable_workbench()` 新增每条操作的 `block` / `indent`，来源是**源码缩进**
（`_source_block_of`）：往上找最近的、缩进更小、以 `:` 结尾、首词是
`if/elif/else/for/while` 的行。不看 AST —— 块头原文比 AST 节点好读，
也不会把 `elif` 说成 `else: if:`。

```text
变量      初值    本拍操作            出现位置
route     —       route = "roof"      第 2 拍
...
第 2 拍 · 在 if love > 3: · route = "roof"
第 4 拍 · 在 for i in range(2): · counter += i
```

新增一条操作时，对话框会说清落点：

```text
新增放在 [选中这条之后（同一块内）▾]   会放到第 2 拍的「if love > 3:」块内
```

下拉第二项是「本章末尾（顶层）」：要插在 label 顶层、不进任何块时选它。

### 3.2 写回：为什么"追加到那一拍的 `Beat.code`"就是块内

`Beat.code` 存的是**块体本身**（缩进由块头在渲染时补），所以把新行追加到
"那条赋值所在的拍"，就自动落在同一个 `if` / `for` 里面。真正会错的是
**一次插多条**：旧接口只有一个 `insert_beat`，后一条会把前一条的落点覆盖掉。

新增 `anchors={新操作下标: 拍下标}`：

- 工作台把每条新操作各自锚到选中那条的拍；`-1` = 用户明确选了"本章末尾"；
- 没有锚点的退回 `insert_beat`，都没有才落到最后一拍（老调用方不变）；
- 指到"循环头"那一拍（`for …:` 自己占一拍、块体在下一拍）时往后挪一拍 ——
  头拍 `code` 是空的，写进去会落在循环**外面**；
- 返回值新增 `inserted`（实际落在第几拍），控制台日志会说"新增 第 2 拍、第 4 拍"。

真机脚本（同一 label 里 `if` + `for` 各插一条）编译出来：

```renpy
label vars_main:
    $ love += 1
    if love > 3:
        $ route = "roof"
        $ flag = True
        $ luck = 1          ← 新增：在 if 里
    for i in range(2):
        $ counter += i
        $ total += 1        ← 新增：在 for 里
    e "done"
    return
```

### 3.3 删除 / 过滤时的下标重排

`anchors` 的键是"操作在列表里的位置"，删掉前面一条就会整体前移：
`_delete_op` 同步平移 `_anchors` / `_blocks`，`_on_accept` 再按"滤掉空行之后"
的最终下标重排一次 —— 否则空行/删除会让新操作插到隔壁拍。

## 四、关窗三选一

`closeEvent` 先走 `_confirm_close_graph()`：

```text
┌ 剧情图还没保存 ─────────────────────────────┐
│ 剧情图有改动，关掉软件就没了。                 │
│ 保存到：<项目根>/storygraph_layout.json       │
│ [保存剧情图并退出] [不保存，直接退出] [取消]    │
└────────────────────────────────────────────┘
```

| 选择 | 行为 |
|---|---|
| 保存 | 写 `<项目根>/storygraph_layout.json`；**写失败不关窗**（弹提示，图还在内存里） |
| 不保存 | 直接关，控制台记一条"按你的选择：这次改动没有保存" |
| 取消 | `event.ignore()`，窗口与图一个字节都不动 |

两个刻意的边界：

- **没有项目目录**时"保存"会弹文件选择框（不把布局硬塞到某个默认位置）；
- **窗口没显示过**（测试 / 嵌入 / 启动失败清理）不弹三选一，沿用"自动存一份、
  失败也不拦"—— 否则构造完就 `close()` 的路径会把进程挂在模态框上。
  这条是给测试与嵌入方留的活路，不是给真实用户的分支（用户看到的窗口都是 shown）。

## 六、仍然不做（写明，不藏）

- **折叠状态不持久化**：下次打开回到全展开。它是一次性的视图操作，
  存进布局 JSON 会把"版式"与"临时视图"混成一份数据。
- **变量工作台仍不重排 `if` / `for` 结构**：只做"往块里加一条"，
  改条件、换分支、把顶层语句拖进块，仍走文本区 / 源文件。
- **关窗不问"卡片改动"**：卡片的保存走「💾 保存这一拍」，关窗只处理剧情图。
  把两者塞进同一个三选一会让"我到底存了什么"重新变糊。
- **没有"全部展开 / 全部折叠"**：label 数量通常个位数，逐个点足够；
  真到几十个 label 时再加。
