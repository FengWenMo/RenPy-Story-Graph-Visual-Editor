## 4. 剩下的硬伤（按"会不会毁东西"排）

### P0：会毁 / 会误导（1 条）

| # | 问题 | 证据 |
|---|---|---|
| P0-1 | **构建闸门只证明了"这一份产物自己语法对不对"，没证明"拷进 game/ 会不会和原文打架"** | 产物写 `build/renpy/` 时 `labels_in_danger` 返回空集；只有写进 `game/` 才查 label 重名。所以"构建成功"与"进游戏不炸"之间仍有一道缝 |

### P1：能跑但不对（4 条）

| # | 问题 | 证据 |
|---|---|---|
| P1-1 | **结构位与老推断仍是两套判断** | `the_question` 端到端还有 2 条 `NEST_CONFLICT`；产物对，但表格里「结构位（内部）」列与渲染实际用的判断不一致 —— 程序一旦开始消费那列就会踩 |
| P1-2 | **预览不是游戏画面** | 固定尺寸、只画图层、无真实贴图合成；策划看到的"舞台"和玩家看到的不一样 |
| P1-3 | **服装 / 表情没有结构化维度** | `images.xlsx` 仍只有 `Path / Tag / Attributes`，`Attributes` 装的是整串文件名；"一维一格"是靠解析文件名临时拼的，不是数据模型 |
| P1-4 | **多引擎导出是 JSON + 说明书** | 没有 `.asset` / `.prefab` / 可跑的 C# 导入器；Unity 侧要用户自己照 `UNITY_IMPORT.md` 写一遍 |

### P2：观感与效率（3 条）

- `validate` 在真机报 27 条警告，其中 W313「1117/1792 个资产名含空格中文」是**项目现状**而非工具错误 —— 但第一次看会以为满屏是 bug。
- 第一次写回会在文件头插 2 行生成标记（`# 由剧本表自动生成…` + 空行）。功能上没错，演示时要先解释一句。
- 剧情图是"章节级总览"：一章一个方块，双击进卡片。想看 label 之间的跳转，得导入后才发现节点是按 label 展开的 —— 这一步的入口不够明显（我第一遍也以为图是空的）。

## 5. demo 剧本（照着点就能拍）

一镜到底，约 6 分钟，全部用真机项目，**不走"构建"按钮**：

| 步 | 动作 | 你想让人看到的那一句 |

| 1 | 打开项目 → 「➕ 导入章节」选 3–4 章 | "1 秒把 55 章的跳转关系铺成一张图" |
| 2 | 指着图上的虚线与红色标注 | "它自己发现这 3 个跳转目标在项目里不存在" |
| 3 | 双击一个模块 → 进卡片页 | "214 拍，一行一句，说话人、台词、舞台各一格" |
| 4 | 改一句台词 → 保存 → 导出 `.rpy` | "改了 1 行，其余 418 行一个字节没动" |
| 5 | 打开 Excel：「Beats」37 列 + 「资源引用（活）」 | "3222 个公式，不是在表里抄死值" |
| 6 | 在 Excel 里改同一句 → 写回 | "两个入口改的是同一份脚本，谁改都不会破坏另一边" |
| 7 | 把产物丢进游戏跑 | "刚才那句话，游戏里已经是新的了" |

第 7 步是收尾关键。**不要在第 7 步之前点"构建"** —— 见 §1，那是移动靶。
