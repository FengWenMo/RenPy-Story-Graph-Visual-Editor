# 版式自动认领：项目里别处存的布局，打开项目时自己找来（2026-11-05）

> 用户：「为什么我明明导入了项目，却没有成功导入布局……？emm……奇怪……
> 你能自动识别到对应布局的 json 文件，并自动导入吗？（不能就算，没有也静默，
> 不用报错）」

## 一、现场（真机 `D:\千连万理\sr_general`）

| 文件 | 修改时间 | 形状 | 43 块坐标 | 编排线 |
|---|---|---|---|---|
| `.storygraph/layout.json` | 10-26 22:26 | 新版瘦格式（v2） | 竖着一条线（x≈0，y=2412…） | **0** 条 |
| `game/chapter/目前保存的布局(自动生成的，不用看）.json` | 10-28 00:29 | 老版整图（`nodes` 里还塞着 `statements`） | 四列网格（x=0/282/564…，y=0） | **50** 条（`origin=control`） |

两份都是 **43 块、43/43 对得上**，但**坐标 43 处全不同**。

`layout_store.find_existing()` 只认两个固定位置（`.storygraph/layout.json` →
`storygraph_layout.json`），于是：

1. 打开项目 → 贴上的是 **10-26** 那份排列（用户两天前摆的样子）；
2. 老文件里那 **50 条编排线**一起丢了（瘦格式本来就不存 `source` 边，
   但 `control` 边是要存的 —— 只是它从来没被读到）。

用户看到的就是"我明明存过布局，它却摆回旧的样子"。

## 二、修法：认领（不搬家、不写项目）

`storygraph/app/layout_store.py` 新增两件：

| 函数 | 干什么 |
|---|---|
| `scan_candidates(project_root)` | 项目里**所有长得像版式**的 JSON（文件头有 `"nodes"` + 大小/层数上限） |
| `best_for(graph, project_root)` | 给**当前这张图**挑一份：先比"能贴上几块"，一样多再比"谁更新" |

`ui_qt/window_graph_ops._apply_saved_placement()` 从 `find_existing` 换成
`best_for`，贴成功后控制台打**一行**（认领了哪一份必须说出来 —— 项目里可能有
好几份，用户只记得"我最后存的那一版"）：

```
[版式] 用 game/chapter/目前保存的布局(自动生成的，不用看）.json 摆了 43 个模块，补回 50 条编排线
```

### 两条判据为什么不能少

- **只认最新** → 项目里上一章/别的项目留下的版式会把图打散（它很新，但一块都对不上）；
- **只认"能对上"** → 平手时随机挑一份，用户又会问"为什么不是我最后存的那一版"。

所以顺序是：`matched` 降序 → `mtime` 降序（`scan_candidates` 已按新到旧，
平手保留先出现的那份）。

### 安全边界

- **不写项目**：只读。认领之后 `_mark_graph_saved(path)` 把当前图记为"和磁盘一致"，
  不会因为恢复版式把图标成未保存；关窗也不会自动往别处写。
- **失败静默**：没版式 / 坏文件 / 一块都对不上 → 返回 `ok=False`，调用方什么都不说
  （用户明确要求"不能就算，没有也静默"）。
- **性能**：真机实测 `scan_candidates` **14 ms**（8 个 json，扫到 2 份），
  `best_for` **210 ms**（大头是解析 134 KB 的老文件）。导入章节本来就以秒计。
- **护栏**：`images/`、`audio/`、`tl/`、`libs/`、`renpy/` 这类目录不进；
  深度 ≤ 4；文件数 ≤ 200；单文件 ≤ 8 MB（`SCAN_*`）。

## 三、顺带修掉的一个真 bug

`read_placement()` 从前只检查 `'nodes' in data`，没检查它是对象。项目里别的
JSON 只要有个 `nodes` 键、值是列表，就 `AttributeError` —— 而自动认领会把
**每一次导入章节**都过一遍这个函数，等于"一个无关的 json 让整张图导不进来"。

现在：`nodes` 不是对象 → `{ok: False, error: '…（nodes 不是对象）'}`；
新格式里**值不是对象的条目直接丢掉**（`apply_placement` 会 `pos.get('x')`，
拿到列表就是 `AttributeError`）。

`best_for` 里**刻意没有**包一层宽 `except`：`read_placement` 的判据已经够严，
再包一层只会让技术债棘轮（`broad_excepts`）多记一笔，却不多挡住什么。

## 四、验证

`tests/test_layout_autodetect.py`（10 条，含一条真机回归 `skipif` 不存在）：

- 两份都能对上 → 取**更新**的那份（真机那一对）；
- 更新但一块都对不上 → **跳过**；
- 覆盖 1 块的新文件 vs 覆盖 2 块的旧文件 → 取覆盖多的；
- 坏 JSON / 非版式 JSON / 空图 / 没有版式 → 静默；
- `images/` 里和超过 4 层深度的 json **不扫**；
- 挑出来之后 `apply_placement` 真的改坐标、真的补回 `origin=control` 的编排线。

```
python -m pytest tests/test_layout_autodetect.py tests/test_layout_store.py -q
# 24 passed
```

真机复核（同一台机器）：

```
scan: 0.014s → 2 份
best_for: 0.210s → game\chapter\目前保存的布局(自动生成的，不用看）.json
matched 43 / 43 | edges 50
```

## 五、还没做的

- 认领到的如果是**老格式**，不自动迁移成 `.storygraph/layout.json`（写项目要用户点头；
  标准版不许自动写）。下次打开还会重新认领同一份 —— 行为一致，只是多花 0.2 秒。
- `storygraph.rules.json` 缺失时卡片拿不到"人物→服装→表情"的列序（见
  `test_hell_p0_l1_2026-11-05.py::test_without_rules_json_order_falls_back_to_engine`）。
  那是另一条线（预设只在演出专用版落盘），**不影响**本次的"切一维不挪位置"。
