### M3 · Excel 演出配置上限（D4，方案 B）— 🔵 清单已定，待实现
**目标**：策划对着演出配置**选**而不是"记"；`Stage` 从"隐式 DSL"变"显式列"。

**M3-1 指令清单（真源：`story/dsl.py`，已是结构化 IR，不用新造）**

| 动词（中文别名见 `VERB_ALIAS`） | 参数（`StageOp` 字段） | 候选来源 |
|---|---|---|
| `show`（显示/出场/上场） | `target`(角色·图像) + `attrs[]`(表情/属性) + `at`(位置/变换) + `with_`(转场) | 资源表 `characters`/`images` 的 tag；项目属性名；`transforms` |
| `hide`（隐藏/退场/下场） | `target` | 同上 |
| `scene`（场景/背景/换景） | `target`(背景) + `at` | `images`(bg) / `transforms` |
| `with`（转场/过渡） | `with_` | `transforms` |
| `pause`（等待/停顿） | 秒数（数值） | 无（数值输入） |

音频侧**已经是每指令一列**（`BGM`/`SFX`/`Voice`，`AudioOp{channel, action, name, params}`，
`params` 认 `loop/fadein/fadeout/fade/volume/if_changed`）—— 无需改造。

**M3-2 列设计（关键约束：顺序不能丢）**
- ⚠ `Stage` 是**有序** op 序列（C3：顺序唯一真源 `Beat.stage_verbs`，顺序由隐藏列 `StageOrder`/`OpOrder` 承载）。
  "每指令一列"若只表达**参数值**，顺序必须继续由既有 order 列承载 —— **不能拿列位置当顺序**。
- 列命名 = **动词 × 出现序号**：`舞台·显示`、`舞台·显示2`、`舞台·隐藏`、`舞台·场景`、`舞台·转场`、`舞台·停顿`；
  上限按"本项目里该动词的最大出现次数"决定（**正是"按最大项数排"**；九成拍只有一次）。
- 每列**单行**（进 `SINGLE_LINE_BEAT_FIELDS`），按参数绑**数据验证**（资源表候选，复用 `choices_from`）。
- **保留 `Stage` 列作只读复合视图**：由各指令列按 order 拼成人类可读串（展示层，不参与回写与验证）。
- 落地顺序（每步都要求往返幂等 + 增量补丁不回归）：
  1. `pause`（单数值，最简）→ 2. `with`（单值+候选）→ 3. `hide` → 4. `scene` → 5. `show`（多参数，最复杂）。
- 风险：列数增长 → 用"指令类型"作**可折叠分组**（Excel 列分组）组织。
- ⚠ 这动的是**列契约**（F2：基础列永不动、动态列追加末尾）→ 新列一律**追加末尾**，且只在这批拍真出现该动词时建列。
