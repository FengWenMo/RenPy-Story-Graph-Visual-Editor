### M3 · Excel 演出配置上限（D4，方案 B）— 🔵 第一切片 ✅ 已落地（`Show`/`Hide` 摊列）
**目标**：策划对着演出配置**选**而不是"记"；把"一格多指令"摊成"每指令一列"。

#### M3-0 设计审查（2026-10-08 实测；**推翻了我先前两处假设**）
1. **`Stage` 已经是派生视图**：它由 `beat_model.compose_stage()` 从结构化列合成（人话，只在无损时中文化），
   渲染真源是 `beat_render._stage_lines`，两者必须同源（C1/C3）。→ **"保留 Stage 作只读复合视图"是现状，不用新做**。
2. **顺序载体比我以为的更完整**：`OpOrder` = **全类别**逐次序号（实测 `show#0,code#0,show#1,code#1…`），
   `StageOrder` **也带序号**（实测 `show#0,show#1,show#2,show#3`）—— 都**不是**我先前以为的"纯 verb 列表"。
   → 每指令一列的"出现序号"**与既有 token 一一对应**，不需要新造顺序机制。
3. ⚠ **`pause` / `with X` / `jump` 走 `raw`（代码通道），刻意不进 `Stage`**（见 `compose_stage` 的注释：
   "两条通道各出一份，否则同一行语句会被生成两次"）。→ **我先前"M3-2 第一刀选 pause"是错的**。
4. **"一格多指令"的真身 = `Show`/`Hide` 列的 `;` 多值**（真机 `chapter1_4` 实测 1–4 项/拍，
   如 `ling close_happy@i11; ling base_arms_akimbo close_happy`）。

#### M3-2 修正后的落地顺序
| 序 | 切片 | 依据 |
|---|---|---|
| **1** | **`Show` 摊列**（`立绘1`/`立绘2`…，对齐 `show#0`/`show#1`） | 真机就是"一格多值"的主体；已有 `_split_show_items` 与 `show#n` 序号；`Show` 本就是**单行列**，摊列不改变单行/多行分类 |

#### M3-2 第一切片：`Show` / `Hide` 摊列 —— ✅ 已实现（2026-10-09）
**关键决策：模型与渲染**不动**。** `beat.show` / `beat.hide` 仍是 `;` 连接的字符串
（`_stage_lines` / `compose_stage` **一行未改**）→ 渲染/往返风险为 0；摊列只改 **Excel 面**。

| # | 触点 | 实现 |
|---|---|---|
| 1 | `beat_model` | 新增 `show_cell_parts` / `hide_cell_parts`（与原 `compose_*_cell` **同源**，避免第二套过滤）+ `SHOW_EXTRA_PREFIX='立绘'` / `HIDE_EXTRA_PREFIX='退场'` + `extra_field_names` / `extra_index_of` / `extra_columns_in` |
| 2 | `Beat.to_row(..., extra_fields=)` | 摊列生效时原列只放**第 1 项**；第 2+ 项写进追加列 |
| 3 | `Beat.from_row` | 原列 + 按**序号升序**的 `立绘n`/`退场n` 一起拆（少读一边＝静默丢项） |
| 4 | `_row_fields(spec_fields, extra_fields)` | 动态段**两族**：先「每参数一列」后「每指令一列」（唯一拼法，表头/数据行同源） |
| 5 | 单行清洗 | 动态列天然走 `sanitize_single_line_cell`（`_flatten_single_line_cells` 判"不是基础列"） |
| 6 | `excel_export` | 表头/数据行/列宽 + **每格绑图像候选 DV**（摊列的目的）+ `Show`/`Hide` 提示改为"第 1 个…（一格一个）" |
| 7 | 判据 | 新增 `tests/test_hell_show_split_columns.py`（22 条）+ `tools/probe_show_split_real.py`（真机） |

**修掉的两类静默缺陷（在 Phase 1 就被判据抓住）**：
- **项数 > 格数时会静默丢项** → 加安全阀：**放不下就不摊**（整格写，读回来照样全在）；
- **不摊却仍写摊列 → 读回来重复**（`a; b; c; d; b`）→ 摊列只在真摊时写。

**验收（全部通过）**：①渲染产物逐字不变（真机 12 文件 0 失败）②`audit_idempotence` 53/53 逐字节
③`hell_edit_rounds` 增量补丁 0 失败 ④模型/表回归 594 passed ⑤`Show`/`Hide` 多重集与顺序守恒。
**老表/老项目零影响**：没有多值的批次**一个摊列都不加**（表与从前逐列相同）。

`Scene`/`At`/`With` 天然单值，不动；`Stage` 残余（native 透传）**最后**碰。

|---|---|---|
| `show`（显示/出场/上场） | `target`(角色·图像) + `attrs[]`(表情/属性) + `at`(位置/变换) + `with_`(转场) | 资源表 `characters`/`images` 的 tag；项目属性名；`transforms` |

**M3-2 列设计（关键约束：顺序不能丢）**
- ⚠ `Stage` 是**有序** op 序列（C3：顺序唯一真源 `Beat.stage_verbs`，顺序由隐藏列 `StageOrder`/`OpOrder` 承载）。
  "每指令一列"若只表达**参数值**，顺序必须继续由既有 order 列承载 —— **不能拿列位置当顺序**。
- 列命名 = **动词 × 出现序号**：`舞台·显示`、`舞台·显示2`、`舞台·隐藏`、`舞台·场景`、`舞台·转场`、`舞台·停顿`；
  上限按"本项目里该动词的最大出现次数"决定（**正是"按最大项数排"**；九成拍只有一次）。
- 每列**单行**（进 `SINGLE_LINE_BEAT_FIELDS`），按参数绑**数据验证**（资源表候选，复用 `choices_from`）。
- **保留 `Stage` 列作只读复合视图**：由各指令列按 order 拼成人类可读串（展示层，不参与回写与验证）。
- 落地顺序（每步都要求往返幂等 + 增量补丁不回归）：
  1. `pause`（单数值，最简）→ 2. `with`（单值+候选）→ 3. `hide` → 4. `scene` → 5. `show`（多参数，最复杂）。
- 风险：列数增长 → 用"指令类型"作**可折叠分组**（Excel 列分组）组织。
- ⚠ 这动的是**列契约**（F2：基础列永不动、动态列追加末尾）→ 新列一律**追加末尾**，且只在这批拍真出现该动词时建列。
