### M3 · Excel 演出配置上限（D4，方案 B）— 🔵 第一切片 ✅ 已落地（`Show`/`Hide` 摊列）

**目标**：策划对着演出配置**选**而不是"记"；把"一格多指令"摊成"每指令一列"。

#### M3-0 设计审查（2026-10-08 实测；**推翻了我先前两处假设**）

1. **`Stage` 已经是派生视图**：它由 `beat_model.compose_stage()` 从结构化列合成（人话，只在无损时中文化），
     
   渲染真源是 `beat_render._stage_lines`，两者必须同源（C1/C3）。→ **"保留 Stage 作只读复合视图"是现状，不用新做**。
2. **顺序载体比我以为的更完整**：`OpOrder` = **全类别**逐次序号（实测 `show#0,code#0,show#1,code#1…`），
     
   `StageOrder` **也带序号**（实测 `show#0,show#1,show#2,show#3`）—— 都**不是**我先前以为的"纯 verb 列表"。
     
   → 每指令一列的"出现序号"**与既有 token 一一对应**，不需要新造顺序机制。
3. ⚠ **`pause` / `with X` / `jump` 走 `raw`（代码通道），刻意不进 `Stage`**（见 `compose_stage` 的注释：
     
   "两条通道各出一份，否则同一行语句会被生成两次"）。→ **我先前"M3-2 第一刀选 pause"是错的**。
4. **"一格多指令"的真身 = `Show`/`Hide` 列的 `;` 多值**（真机 `chapter1_4` 实测 1–4 项/拍，
     
   如 `ling close_happy@i11; ling base_arms_akimbo close_happy`）。

### 这轮把"踩坑"变成了**工具**（`tools/_extract.py`，重构脚手架）

`extract(path, host, pick, new_fn, params, call_lines, doc=…, ret=…, prologue=…, method=…)`：
  
**搬块之前先在 AST 上审计"自由名"**，不过就**不写盘**。它这一轮抓到了 4 类真错：

1. **宿主局部 import**（`compile_stage` / `resolve_thumb_source` / `load_asset_registry`）；
2. **嵌套闭包**（`control_name` / `_native_line`）；
3. **宿主局部容器/累加器**（`rows` / `dropped` / `outside_total`）；
4. ⚠ **`x += 1` 的目标既是读又是写** —— 第一版把 AugAssign 目标当成"块内定义"放过了，
     
   于是 `outside_total` 溜进去 → `UnboundLocalError`（修：AugAssign 目标算**自由名**）。

### ⚠⚠ 这轮最贵的三类坑（都不是"搬错"，而是"搬对了、调用点错了"）

1. **丢了守卫**：把 `if cond: <块>` 搬走，调用点写成**裸 `return`** —— 于是后半段代码
     
   永远不跑（`_expand_node` / `eventFilter` 都中了）。**调用点必须保留原守卫**。
2. **`if/else` 只包了一半**：`load_assets` 那一块是 `if reg is None: … else:（表已存在→自动对齐）`
     
   —— 我用 `if reg is None:` 包住调用，`else` 支**永远跑不到**。**搬 `if` 前先看它有没有 `else`**。
3. **块内的提前 `return`（错误分支）**：搬成函数后它返回的是**字典**，调用方却在解四元组
     
   → 两条错误路径的判据当场红。修法：给它一个带标记的返回值（`_fail`）让调用方原样透出。
4. 另有两次"零改名"错觉：**传进去的闭包，块里仍写着旧名**（`_native_line`）→ `NameError`。

### 7.5 别名表设计（用户追问："以后遇到更多角色怎么办？怎么方便用户改？"）

**先摆实测结论：你担心的场景，前两层已经**零配置**覆盖了。**

| 剧本里怎么写 | 现在的结果 | 靠哪一层 |
|---|---|---|
| `妈妈"…"`（变量 `mm`、显示名「妈妈」） | → `mm` | **L2 显示名匹配** |
| `mm` / `Mm` / `MM` / `m_m` | → `mm` | **L1 归一化**（大小写/下划线/空格/角括号/引号） |
| `「叶怀瑾」"…"` / `YHJ` / `yhj` | → `yhj` | L2 / L1 |
| `MOM` / `LINGDAO` / `JIAOGUAN` / `TJF` | 保留原样 + **报未映射** | 需要 **L3 别名** |

**四层匹配（能自动的绝不让人配；猜不准的一律不猜）**

```
L0 精确    token == 角色变量
L1 归一    小写 + 去下划线/空格/角括号/引号      ← 覆盖所有大小写变体
L2 显示名  token == characters.xlsx 的 Name     ← 覆盖"写中文名"
L3 别名表  characters.xlsx 新增「别名」列        ← 覆盖"你自己发明的简称"
L4 报出来  都不中 → 报 + 列候选让人挑（**绝不模糊猜**）
```

**为什么 L4 不猜**：`LINGDAO ↔ ld` 之间**没有算法关系**（`ld` 不是拼音、也不是可推的缩写）——
猜错就是**改剧情**（说话人换了人）。宁可报，让人一次敲定。

**L3 别名表放哪：`characters.xlsx` 新增一列「别名」（内部键 `Aliases`）**
- 格式：`MOM|母亲|老妈`（`|` 或 `,` 分隔；别名本身也走 L1 归一，所以 `Mom` 不用再写一遍）
- 落地要登记**三处**（否则会"导出丢列 / 中文表头对不上 / 被自动同步冲掉"）：
  1. `asset_registry._TABLE_FIELDS['character']` 加 `'Aliases'`（写表顺序）
  2. `asset_registry.ASSET_FIELD_LABELS` 加 `'Aliases': '别名'`（中文表头边界翻译）
  3. `asset_engine._CHAR_IDENTITY_KEYS` 加 `'Aliases'` ← **关键**：它是"人写字段"，
     「从脚本导入角色表」**不许**覆盖（D3 契约：人写的 `Name/Color/ImageTag` 一律不动）
- 真机角色表现在是**英文表头**（老表）→ 靠 `_canon_field` 边界翻译，老表照旧能读；
  用户手加的列也**原样保留**（工具既有规矩）。

**"方便用户重定义和修改"的三条做法**
1. **在熟悉的表里改**（不碰 JSON / 不碰代码）：一行一个角色，一列别名；
2. **S3 上线给"一键补"**：导入报"未映射：`MOM`/`LINGDAO`…"时弹「`MOM` 指哪个角色？」→
   选中后**写进别名列**（工具已有 `update_keys` / 写前备份 `*.bak.xlsx` 的基础设施），下次不再问；
3. **撞车必须报**（两条都会踩）：① 同一别名指到两个角色 ② 某角色的别名 == 另一角色的显示名
   —— **不许静默取第一个**。

**以后加角色的实际成本**：角色表加一行（本来就要做）→ 剧本里写**显示名或变量名**自动命中；
只有用了"表里没有的第三种写法"时才需要填别名列 —— 而那种写法**只有你自己知道**。

**待拍板（§五 D10）**：**D10a** 别名存哪（xlsx 新增列 ／ 独立 json ／ 章节旁 roles.json）；
**D10b** 何时做（现在 ／ 与 S3 一起）。

- 四层匹配：`L0 变量名` → `L1 归一`（大小写/下划线/空格/角括号/引号）→
  `L2 显示名` → `L3 别名列` → `L4 报出来`（**绝不模糊猜**）

txt 导入只是告警文案改进）。

### 8.1 北极星（本节的长期目标）

> **能拿到的事实一律问引擎要，不让人填；引擎不提供的语义才由人补；
> 引擎和人都不说的，靠扫描**发现并报警** —— 而扫描永不宣称"只有这些"。**

### 8.2 三条线（职责，无重叠）

| 线 | 职责 | 能改的地方 |
|---|---|---|
| **引擎 oracle（优先）** | 语法合法性、图像/属性引用、资源存在性、属性词汇与**分组**、兼容候选、变换/界面/define 清单 | 只读，跑 `lint` + 注入探针 |
| **定义表（覆盖层）** | **只放引擎不提供的语义**：中文名、分组改名/归并、候选过滤、例子、说明 | `storygraph.rules.json` |
| **扫描（发现与校验）** | 找未声明的语句头、喂探针"该测什么"、对账 | 只读 |

### 8.3 四步时序（**不能颠倒**）

```
① parse 干净？ ——否——▶ 报「采集失败」并停止（坑 2 / 坑 4）
        │是
② 采集：lint --error-code + --json-dump + 注入探针 → engine_facts.json（每条带 source）
        │
③ 对账：定义表 ↔ 引擎事实 ↔ 真实用法 → 冲突一律报出，不静默选一个
        │
④ 供给：卡片/表格候选直读 ②；定义表只做"翻译"
```

### 8.4 四个坑（违反任一条都会静默出错）

1. `lint` **默认退出码 0** —— 必须带 `--error-code`。
2. **`lint` 没报 ≠ 没问题** —— 一个 parse error 会吞掉**后面全部**语义检查。
3. **`renpy.has_image()` 不是判据** —— 对不存在的属性组合也返回 `True`。
4. **parse error 会让探针也拿不到事实** —— 采不到 = **硬失败**，绝不当"无漂移"。

### 8.5 八条规则 N1–N8（两轮地狱测试逼出来的）

| # | 规则 | 依据 |
|---|---|---|
| **N1** | 扫描器只说"我认出了 N 个"，不说"项目里只有 N 个" | CDS 名可计算 → 引擎接受、扫描器看不见 |
| **N2** | 扫到 `register_statement(<内置名>)` → 报警"内置被覆盖" | 覆盖**真的生效**且默认无信号 |
| **N3** | 同组属性多选 → **工具自查**（用引擎给的 group） | `show lan happy sad` lint 静默 |
| **N4** | 把程序 `lint=` 回调的输出**收进构建报告** | 程序的 `renpy.error` 会进 lint 报告 |
| **N5** | 内置被替换（尤其 **`show`**、`name=""` 换 say）→ **最高级警告，形状不保证** | 覆盖 = **完全替换**，不是叠加 |
| **N6** | **同 tag 重复定义** → 工具自查并报出 | `layeredimage` 后者整体覆盖前者；普通 `image` **完全静默** |
| **N7** | 探针清理**必须含 `.rpyc`** | 孤儿 `.rpyc` 引擎不会自动清 |
| **N8** | ⚠ **行为级验证（`test`）不进 CI 默认路径** | headless(dummy) 下 exit 143，跑不起来 |

### 8.6 什么时候回头找程序（**三种**，除此外零配合）

1. **引擎被 fork 且源码不在项目里** —— fork 新增语句对工具**完全隐形**（实测：扫描器/lint/探针/json-dump 四路无信号）。
2. **项目用 CDS 覆盖了内置语句**（尤其 `show` / say）。
3. **项目注册了"计算出来的名字"**（只认字面量的扫描器看不见）。

### 8.8 明确不做（7 条）

不让扫描器断言"项目里只有 N 种写法"｜不用 AST diff 当契约来源（只当"该重测什么"的触发器）｜
不在事实采集里"猜"缺项｜**不依赖 `--json-dump` 的 label**。

### 8.9 候选与资源表如何对齐：**只标注，绝不过滤**（2026-10-11 定案）

> 用户原话："**一切应当以具体有的资源为标准**，excel 和引擎必须对齐！
> 如果做 excel 的过滤是否会导致有的东西被错误过滤了无法导入？"

**答：会。所以不过滤。**

**两个"权威"回答的是两个不同的问题，不能用一个去否决另一个：**

| 权威 | 回答的问题 | 来源 |
|---|---|---|
| **文件系统 / 资源表** | **什么东西"存在"** | 扫 `images/` 得到（真机 1657 行） |
| **引擎声明** | **什么东西"可选"** | `layeredimage` 的 group/attribute（真机 `lan` 20 个） |

真机实测（用产品自己的加载器对账）：**「引擎有、表没有」= 0**，
但**「表有、引擎没有」= 12/9/6/6**（`mask`、`_ss_cut`、`lan_angry`…）——
它们是**内部件（掩码/切图/合成层）**，**文件真实存在、但不是可选属性**。
⇒ 拿引擎的枚举去**删候选**，会连"合法的、只是引擎还没认的"一起删掉 ——
**那正是"东西被错误过滤、无法导入"的来源。**

**三条落地规矩：**

1. **候选基准 = 资源表（实际存在的资源），一行都不删、不隐藏**，下拉内容一个字节不变。
2. **引擎事实只做"标注"**，且标注要**分状态**：
   - ✅ 引擎也认（可直接 `show`）；
   - ⚠️ 引擎未认 → **仍然可选、仍然能导入**，只是提前说清"用它 lint 会报错"。

### 8.10 "报出来"：扫描进事实 + 体检报告【⑩ 段】（2026-10-11 完成）

**⚠ 真机跑出来的两个坑（都成判据了）**：

平铺列表 → `attributes_of` 恒为空 → 判据以"两边都是空集"的假象通过。
现在有一条**夹具自检**（`test_the_fixture_really_carries_facts`）钉住这件事。
