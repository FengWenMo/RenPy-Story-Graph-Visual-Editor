## 3. 设计要点（照这个写，别自由发挥）

### 3.1 能力令牌

放 `storygraph/engine/capabilities.py`。**值是三态，不是 bool：**

```python
CAP_IMAGE_REGISTRY      # renpy.list_images()
CAP_IMAGE_TAGS          # get_available_image_tags()
CAP_LAYERED_ATTRIBUTES  # 现有探针的 attributes（group/attribute/default）
CAP_LAYERED_CONDITIONALS# when / if_all / if_any / image_format（P0 恒为 False）
CAP_STATEMENT_REGISTRY  # renpy.statements.registry
CAP_TRANSFORM_TABLE     # --json-dump 的 transform
CAP_SCREEN_TABLE        # --json-dump 的 screen
CAP_DEFINES             # --json-dump 的 define
CAP_LABELS              # renpy.get_all_labels()
CAP_LINT_DIAGS          # lint 跑过且解析出了诊断
CAP_STORE_SNAPSHOT      # store 变量值（P0 恒 False：store 采集不在这一片）
```

```python
True   # 这次真采到了
False  # adapter 声明引擎/版本根本不支持
None   # 声明支持，但这次失败（探针异常 / dump 没产出）
```

⚠ **`False` 和 `None` 在 UI 上必须分开**："不支持" vs "采集失败"。把它们并成一个 bool 是这一层最常见的塌方。

**不要**把"新鲜度"塞进 capabilities —— 那是另一个轴：

- capability = **引擎能不能回答**；
- freshness = **这份回答还算不算数**（工程改过没有）。

### 3.2 Fact 信封（加法，不改老形状）

现有事实是 `{'value': …, 'source': …}`，`value_of()` / `source_of()` 都认这个形状 —— **保持它**。v2 只加可选键：

```json
{
  "value": {...},
  "source": "probe",
  "scope": "layeredimage",
  "confidence": 0.95,
  "extras": {}
}
```

顶层加四段（它们是**一次采集**的属性，不是某条事实的属性，所以不塞进 `facts` 条目）：

```json
{
  "schema": 2,
  "adapter": {"id": "renpy", "version": 1},
  "capabilities": {"CAP_IMAGE_REGISTRY": true, "CAP_LABELS": null,
                    "CAP_STORE_SNAPSHOT": false},
  "degraded": {"reason": "probe_partial", "missing": ["CAP_LABELS"]},
  "freshness": {"verdict": "fresh", "checked_at": "…", "rpy_stamp": "…"}
}
```

`validate_facts` 的规则：

- `schema` 接受 **1 和 2**（现有 fixture `tests/test_asset_identity.py:538` 就是 `'schema': 1`，不许弄红）；
- v2 才检查 `adapter` / `capabilities` 的结构（`dict[str, bool|None]`）；
- `capabilities` 里的未知令牌**不报错**（让 `engine.capabilities` 在消费时报），core 保持哑。

### 3.3 退化链（纯函数，可单测）

`storygraph/engine/decide.py`：

```python
R0 = 'runtime_full'
R1 = 'runtime_partial'
R2 = 'declared_only'
R3 = 'usage_only'
R4 = 'files_only'

def rung(facts: dict, *, collectable: bool = True,
         freshness: str = '') -> str: ...
def allows(rung_name: str, need: set[str]) -> tuple[bool, list[str]]: ...
```

⚠ `collectable` 是**调用方算好传进来的**（`core.engine_facts.is_collectable()`）——
`engine/` 不许 import `core`，否则 §2 的依赖方向就破了。

判定顺序（固定）：

```
没有 facts / schema 不认识         -> R4
collectable=False                  -> R2（静态仍在；不要因为探针失败就说"没数据"）
capabilities 有 None / 有 degraded -> R1
freshness == 'stale'               -> R1（数据在，但可能过期）
全部为 True                        -> R0
```

三条不变量（**测试要钉住**）：

1. 退化**不改判**：R0 能判"错"的，R1/R2 只能 `unknown`，不许变 `ok`；
2. 退化**必须留痕**：返回的 rung 要能追到 `degraded.reason`；
3. **不许升级**：`source='declared'` 的事实永远不能因为"没冲突"被当成运行时事实。

### 3.4 版本探测

`storygraph/engine/detect.py`：

```python
@dataclass(frozen=True)
class EngineVersion:
    major: int; minor: int; patch: int; commit: int; raw: str

def version_of(sdk_root) -> EngineVersion | None
```

- 只读 `renpy/vc_version.py`，`ast.parse` + `ast.literal_eval`，**不 import、不执行**；
- 解析失败 → `None`，**不猜**；
- `engine_collect._engine_version()` 改成调它（保留同名函数转发，老调用方/测试不动）。

**必测用例**：临时目录叫 `renpy-8.4.1-sdk`，里面的 `vc_version.py` 写 `8.5.3.26051504` —— 返回 8.5.3，不是 8.4.1。（本机真实情况就是这样，见设计文档 §1.1。）

## 7. 已知坑（上一轮踩过的，别再踩）

- **`renpy.statements.registry` 不是 dict**：`isinstance(reg, dict)` 为假，要鸭子类型（`hasattr(reg, 'items')`）。
- **`version_tuple` 是算出来的**：`vc_version.py` 里只有 `version = '…'`；找 `version_tuple` 会永远空。
- **目录名会骗人**：`renpy-8.4.1-sdk` 里实测是 8.5.3。
- **`init 999` 在 lint 期间会执行**；未来影子模式用 `renpy.game.post_init`，但那是 P2，不是这一片。
- **孤儿 `.rpyc`**：探针的 `.rpyc` 要一起删（N7），否则下次被引擎当脚本加载。
- **`errors.txt` 要"挪开→跑→读→还原"**，不能删（可能是用户自己的）。
- **manifest sha**：采集前后 `game/**` 文本必须一致（除 `.rpyc`），不一致进 `conflicts`。
- **不要 `mode='in-place'` 跑真机大项目做实验**：1.9 GB 资产，lint 数分钟；实验用 `--mode copy` 或小工程。
- **`cached_fast` 故意不校验指纹**（3.2 s），别用"加一次 `project_stamp`"来修新鲜度 —— 拆 stamp。
- **`git status` 现在有几十个并行工作者的改动**：不要 `git add -A`；按文件分组提交；文档只追加。

## 10. 与 L2 的接口（留给下一位，别现在做）

这一片做完后，L2 只需要：

- `engine.base.FactBatch` → `ir.core` 的 builder（纯函数）；
- `ir.profiles.renpy` 读 `facts` 的 `scope` 字段；
- `story_ir` 变成 `core → target` 的投影（golden 保字节不变）。

也就是说：**P0/L1 的产出（capabilities / degraded / freshness / rung）就是 L2 的输入**；现在把这三样做对，L2 不用返工。
