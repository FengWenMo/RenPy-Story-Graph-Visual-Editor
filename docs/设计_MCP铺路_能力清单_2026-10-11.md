# 设计：MCP 铺路 —— 把工具的能力翻成"模型能用的动作"· 2026-10-11

> 用户 2026-10-11："后面实际上我还想做一个 MCP，能让大模型读懂工具的操作
> （但这个先暂缓）"，随后："给 MCP 铺路"。
>
> 这份文档**先不写代码**，只做一件事：把工具**已经有的能力**盘清楚，
> 逐个回答"模型要用它，需要什么形状"。**能直接映射的才写，缺的先标出来。**

## 零、一条贯穿全篇的原则（沿用 §十三）

> **工具的价值不在于"不依赖程序"，而在于"依赖程序时成本最低"。**

换成 MCP 语境：**模型的价值不在于"不用工具"，而在于"用工具时成本最低"。**
所以每个 MCP 工具都必须满足**同三条**：

1. **不给就不发生** —— 模型不调它，工具的行为与现在**一模一样**；
2. **模型给的参数不许弄坏工具** —— 参数错/超范围一律**结构化报错**，不崩、不改盘；
3. **结论必须带"谁说的"** —— 引擎说的 / 扫描器认出的 / 程序验证函数说的 /
   **没问出来**，四者**不许混成一个"是/否"**。

⚠ 第 3 条是本项目的血泪（三处假绿全出在这里）。**MCP 一旦把"没问出来"折成
`false`，模型就会当真话用** —— 那比没有 MCP 更危险。

## 四、缺的东西（要补，MCP 才好用）

| 缺口 | 为什么要 | 建议形状 |
|---|---|---|
| **结构化体检** | 现在 `format_asset_health` 是**文本**，模型要解析散文 | `asset_report.health_dict(report)`：与文本**同源**（一份数据两种渲染） |
| **"这次操作改了什么"统一回执** | 写入类最需要"我改了什么" | `{'written': [路径…], 'diff': '…', 'backup': '…'}` —— 所有写入口返回同一种回执 |
| **一次调用给全上下文** | 模型最怕"分五步问五次，每步都可能猜错" | `storygraph_context(root)`：一次给 facts 摘要 + 未知写法 + 声明的动作 + 环境（SDK 版本） |
| **能力自描述** | 模型要知道"现在能做什么、不能做什么" | `storygraph_capabilities()`：列出上面这些工具 + **各自的已知边界**（例如"同形的写法问不出来，§13.3"） |

## 五、⭐ 一条 MCP 特有的纪律：**把"不确定"做成返回值的一等公民**

本项目的三处假绿（`assert eval` 恒真、`Status` 单独用、`None` 折成 `False`）
在 MCP 场景下会**放大**：模型不会自己去怀疑工具的返回值，它会**直接写进答案**。

所以：

1. 每个判断类工具的返回里，**必须有一个字段说明"这个结论是怎么来的"**：
   `source: "engine" | "scanner" | "host" | "none"`；
2. **三态而非布尔**：`true` / `false` / `null`（= 没问出来）；
3. `null` 那档**必须带 `reason`**，且 `reason` 要能被人直接读懂
   （"引擎在第一处 parse error 停下了：`game/x.rpy:12`"）。

## 六、建议的落地顺序（先做哪个）

| 步 | 做什么 | 为什么这个顺序 |
|---|---|---|
| 1 | **`storygraph_context` + `storygraph_capabilities`** | 模型最缺的就是"开局一次拿全"；且**纯只读、零风险** |
| 2 | 六个**只读/判断**工具（1–8） | 已经都有实现，只差一层薄封装 + 三态约定 |
| 3 | **结构化体检**（`health_dict`） | 让第 2 步的"体检"能给机器读 |
| 4 | **写入类**（9–10）+ 统一回执 | 有护栏与回执之后才敢开 |

⚠ **不做的事**：不把"改 SDK / 预注册"做成 MCP 工具（§12.7）——
那是引擎级不可能，做成工具只会让模型学会一条错路。
