## 一、这一轮改了什么

| 项 | 之前 | 现在 |
|---|---|---|
| 源里删掉 `call` / `jump` | 重载后边还在，成了幽灵 | 重载时按 `flow_edges(beats)` 删除失效 `source` 边 |

## 二、删边：只删"认领过"的边

`app/session_graph.rebuild_source_edges(graph, beats, allow_remove=True)`
现在在补 / 改之后多做一步：**同一批 label 下，已经没有任何一拍对应的
`source` 边，删掉。**

安全边界（比"多一条线"重要得多）：

1. **只删带 `line_id` 的 `source` 边**  
   有 `line_id` 说明它确实由上一轮 `flow_edges` 派生过，现在那一拍不在了。
   老版解析器留下、还没被认领的边（`line_id` 为空）保留，避免升级后
   第一次重载就误删历史数据。
2. **不动 `manual`**  
   用户手画的草图不参与派生，也不在删除范围里。
3. **解析有错就不删**  
   `import_chapters` 发现 `parse_result.errors` 非空时传
   `allow_remove=False`，并且不删幽灵节点。"没读到"不等于"被删了"，
   半份 AST 清理会把整章连线吃掉。
4. **菜单选项的边同样处理**  
   `menu:` 选项里的 `jump` 也是 `flow_edges` 的一行；匹配上就保留
   `option_text` 原样，选项删掉后才删边。有真实导入路径的测试钉着。

### `line_id` 重排（插卡 / 删卡）

`EditorSession._renumber()` 会把后面的拍全部改成新 `line_id`。旧的边还挂着
旧 ID，如果只按 ID 配，就会匹配不上、再画一条新的。

派生现在分两轮：

1. **精确配**：`line_id` 相同的边 → 改目标 / 类型 / `from`；
2. **结构配**：没配上、但 `(from,to,type)` 对得上的边，按顺序认领一条，
   并把 `line_id` **改成新拍的 ID**（计入 `identified`），不新建。

所以插一张卡 / 删一张卡之后，后面那些 `call` 的边不会翻倍。

## 三、重载删幽灵（P2-1）

`import_chapters` 在解析成功之后做一次对账：

```text
节点.file_path 属于这次重载的文件
且 节点.label_name 不在 parse_result.labels 里
→ graph.remove_node(nid)      # 连同入边 / 出边
```

只碰"有源文件、且这次确实重载了那个文件"的节点：

- 用户手建的块（没有 `file_path`）不碰；
- 缺章占位块（没有 `file_path`）不碰；
- 别的文件的 label 不碰；
- 解析有错时**节点对账整步跳过**；边派生仍可增 / 改，但
  `allow_remove=False`，一条旧边都不删。

返回值新增 `removed_nodes`（label 名列表），界面写进控制台并说在状态栏；
整次导入仍然走 `ReplaceGraphCommand`，Ctrl+Z 可以整体撤回。

## 四、界面显示 `skipped`

`rebuild_source_edges()` 的 `skipped` 是"目标还不在图上"的控制流边。
现在两条路都会说：

**导入 / 重载后的状态栏**

```text
✔ 已导入 1 章（flow.rpy）：新增模块 3 个 / 连线 2 条，图上共 3 个模块 · 2 条连线；
  移除 1 个源里已不存在的模块；⚠ 1 条边没画全（目标未导入）
```

控制台会点名缺的目标：

```text
[连线] ⚠ 有 1 条控制流边没画全：目标「nowhere」还不在图上。
       先导入它所在的章节（或点工具栏「🔗 补全相关章节」）。
```

**卡片保存后**

```text
✔ 已保存到这一拍（main.0002）。⚠ 有 1 条边没画全（目标「nowhere」不在图上）；
  改动在内存里，点「⤓ 导出 .rpy」时才落盘。
```

文案只在 `ui_qt/flow_notes.py` 一处拼，导入与卡片保存共用。

## 五、`_sync_flow_edge` 退休

删掉了 `window_card._sync_flow_edge`（手动找一条边、发命令改它）。现在只有
一个派生入口：

```text
保存控制流卡        → _refresh_flow_edges()
翻页 / 预览前顺带提交 → 目标 / 类型 / from 变了才 _refresh_flow_edges()
插入控制流卡        → _refresh_flow_edges()
插入普通卡 / 删卡 / 恢复卡 → _refresh_flow_edges()   # line_id 会重排
撤销这一拍的修改    → _refresh_flow_edges()   # 目标改回去，图边也回去
导入 / 补全 / 重载  → session.import_chapters 里的 rebuild_source_edges()
```

`_refresh_flow_edges()` 只扫**当前这一章的拍**和图上这些 label 的边；
没有变化时（`added=retargeted=removed=0`）**连画布都不重建**。
只有端点 / 条数 / 类型真的变了才调一次 `_set_graph()` —— 老路径的动作命令
本来也会重建一次，所以没有多出一倍开销。

图边是**派生物**，不再单独进图级撤销栈：要撤回一次控制流改动，用卡片页的
「↩ 撤销修改」—— 它会把拍改回去，再重新派生图边（有测试钉住）。
导入 / 重载这种整图动作仍然走 `ReplaceGraphCommand`，Ctrl+Z 可整体撤回。

### 实测（Windows / Python 3.12，`rebuild_source_edges` 单次）

| 规模 | 无变化 | 一次改指 |
|---|---:|---:|
| 3,000 拍 / 30 条边 | 0.48 ms | 0.48 ms |
| 10,000 拍 / 100 条边 | 2.23 ms | 2.69 ms |
| 20,000 拍 / 200 条边 | 9.44 ms | 9.24 ms |

结论：正常章节（几百到几千拍）远低于一帧（16 ms）；20,000 拍也在 10 ms
量级，而且无变化时不碰画布。保存时重新派生**不会拖慢编辑**。

## 七、还没做的 / 边界

| 项 | 说明 |
|---|---|
| 源文件整个被删掉 | 「重载已导入章节」只重解析还存在的文件；文件不在范围里，不会触发删节点。要从图上移除请用「从剧情图移除这一章」 |
| 老图第一次升级 | 没有 `line_id` 的 `source` 边这一轮不删；下一次成功导入会认领它。之后删源才有边可删 |
| 解析有错 | 这一轮不删任何东西（节点 / 边都保留）—— 先把语法错修掉，再重载一次 |
| 手工边与源边同端点 | 两条都保留，派生的只认 `origin='source'` 的那些；手工边不参与对账 |
| `option_text` 的显示 | 删除 / 改指时保持原字面，不重算菜单文案（它不是 flow 拍的字段） |
