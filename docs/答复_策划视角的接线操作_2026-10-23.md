## 一、先看业界证据：为什么"每次都问"是错的

| 证据 | 出处 | 说了什么 |
|---|---|---|
| **弹窗习惯化** | CHI 2015 神经影像研究《How Polymorphic Warnings Reduce Habituation in the Brain》 | 同一警告**第二次出现起**，大脑视觉处理显著下降——弹窗恰恰在你看熟之后失效 |
| **"要用撤销，就别用警告"** | Aza Raskin（A List Apart, 2007）《Never use a warning when you mean undo》 | 标题即结论 |
| **平台规范** | Apple HIG / Google Material Design | 可撤销的常见动作**不要弹确认**；Material 给的是 **snackbar + 撤销**，不是提问 |
| **Gmail 模式** | Gmail Undo Send | 发出去了 → 保留 5~30 秒撤销窗。**事前不问，事后能回** |
| **摩擦与后果成正比** | GitHub 删仓库要你**手打仓库名** | 真不可逆才上高摩擦；平常动作零摩擦 |
| **关键路径禁止模态** | 工具类 UX 通行原则 | 用户最常做的那一两个动作**不能有确认弹窗**；别的功能可以有摩擦 |
| **撤销是架构，不是贴纸** | 多篇一致 | "能撤销"必须在数据模型里设计进去（软删/日志/缓冲），不能最后补 |

**一句话**：策划每天做几十次的动作，弹一次窗就是每天被盘问几十次。
安全不靠事前盘问，靠**事后一键回退 + 动作本身说清做了什么**。

### 叙事工具怎么做的（作家向）

| 工具 | 加一条"跳转/连线"怎么做 | 有没有弹窗 |
|---|---|---|
| **Twine** | 就在正文里写 `[[去屋顶]]`，**关掉编辑窗就画出箭头**；目标不存在？**自动建一个** | **没有**。连按钮都没有，更没有"你要跳去哪里？" |
| **Arcweave** | 画布上拖线即连，文档原话："Write without breaking focus"（别打断写作心流） | 没有阻塞式弹窗；复杂条件/变量放侧栏，**不挡在主路径上** |
| **Chat Mapper** | 拖线即连；"Every change lands as one revision you can review or roll back"（每次改动落成一个可回滚的修订） | 用**修订+回滚**，不是事前确认 |

三家给作家的共同承诺是：**"以思维的速度构建"**（Arcweave 原话："at the speed of thought"）。
弹窗问"插在哪一步"会直接违背这个承诺。

## 二、那"放在合适的地方"怎么办？——换一个问法

上一轮我答"工具判断不了合适"，然后让你每次选。**问法错了。**

策划的日常不是"设计一个新位置"，而是三种情况：

| 真实场景 | 频率 | 策划心里想的话 |
|---|---|---|
| **A. 跳过去看看 / 改改** | 最高 | "我从 main 跳到 side 瞧一眼" |
| **B. 接一条线（新建跳转）** | 高 | "这边完了就去那边" |
| **C. 删了再加回来 / 改位置** | 中 | "刚才删错了 / 想挪个地方" |

**只有 B 需要决定"放哪"，而 B 的正确答案是：给默认值，别问。**

业界对"默认值"的判据（表单研究）：预填最常用值能同时降低错误率和完成时间；
但默认必须是**诚实的**（是用户真会要的，不是方便工具的）。

对"这边完了就去那边"这句话——**章末**就是那个诚实默认。
（"完了"本身就是"这一章的末尾"。）

## 三、订正后的操作体验（给策划看的版本）

下面每一段都是**策划实际会看到/做到的**，不出现"锚点""草图""line_id"这种词。

### 场景 B：接一条线（最常做）——零弹窗

```
策划操作：从 main 块拖一条线到 side 块，松手。

立刻发生：
  ✅ 图上出现连线，边上有小标「⑫」= 接在第 12 步
  ✅ 底部一条提示（5 秒）：
     「main → side 跳转已加，接在第 12 步（章末）· [撤销] [改位置]」
  ✅ 剧本里第 12 步后多了一行 jump side（存盘时写入，和其他改动一起走 diff）
```

**没有弹窗。** 要改？两个去处，都不打断：

- 点提示里的 **[改位置]** → 列出 main 的全部步骤（每步带一句台词摘要），点一下就挪
- 以后随时点边上的 **⑫** → 侧栏同样能挪

> 为什么默认是"章末"：策划说"这边完了就去那边"——"完了"= 章末。
> 不是工具猜剧情，是把最常见的那句话直接变成默认值。
> **写在提示里、边上看得见、一键可挪** —— 这不叫猜，叫默认值。

如果拖线时**没松在某个块上**，而是松在空白处 → 弹一个"接到哪一章？"的搜索框。
**只有这种情况问"你要跳去哪里"**——因为目标真的还不知道。

### 场景 A：跳过去看看 —— 单击，零弹窗

```
策划操作：双击 side 块（或点边上的「→ 跳过去」）。
立刻发生：打开 side 章，顶部面包屑「main › side」，点 ← 回到 main 的同一步。
```

这是**看**，不是**改**。永远不问。

### 场景 C：删了想加回来 —— 自动放回原处，零弹窗

```
策划操作：右键那条线 → 删除。
立刻发生：
  ✅ 线没了；底部提示「已删掉第 3 步的 call side · [撤销]」

（过了一会儿，又想加回来）
策划操作：从 main 拖到 side。
立刻发生：
  ✅ 线回来了，**直接落在第 3 步**（就是它原来待的地方）
  ✅ 提示「main → side 已恢复到第 3 步（『带上武器』之后）· [撤销] [改位置]」
```

**"加回来"是还原，不是重新设计。** 工具记住了上次的位置，直接放回去——
这正是你说的"我的期待是它能放在合适的地方"：
**你原来放的地方，就是合适的地方。**

> 业界依据：Gmail 的撤销窗、Chat Mapper 的 revision 逻辑都建立在
> "动作可逆、历史可回"上。删除不是销毁，是**收起来**——所以放回来时知道原处。

### 真需要"改条件 / 变菜单"时 —— 侧栏，不是弹窗

```
点中那条线 → 右侧栏（就是现在卡片用的那个检查器）：
  ┌─ 这条线 ────────────────────┐
  │  main → side                 │
  │  接在第 3 步（『带上武器』之后）│   ← 位置一眼看见
  │  形式  [跳转 ▾]              │   ← 跳转 / 调用
  │  条件  [           ] (可空)   │
  │  菜单  [           ] (可空)   │
  │  [改位置…]  [删除]           │
  └──────────────────────────────┘
```

条件/菜单是**进阶**，放在侧栏里可填可不填。**不挡在拖线的路上。**
（Arcweave 同款布局：复杂度在侧栏，主路径是拖线。）

## 四、重新回答你的两个问题

### Q1：删掉再加回，怎么放回"合适的地方"？

**工具不用"判断"合适——它直接还原。**

| 情况 | 做法 | 要不要问 |
|---|---|---|
| 刚删不久，又加同一条 | **放回原处**（第 3 步），提示里写明"已恢复到第 3 步" | **不问** |
| 从来没接过的线 | **默认章末**（或卡片里正看着的那一步），提示里写明 | **不问** |
| 想放别处 | 点提示 [改位置] 或边上的 ⑫ → 列出台词摘要点一下 | 这时才出现列表 |

**"合适"三个来源，一个比一个强**：
① 它原来就在那儿（还原）→ ② 你正看着的那一步 → ③ 章末（"完了就去"）。
三者都**明说**放在哪了，都**一键可挪**，都**一键可撤销**。

### Q2：草图锚点是什么？

**这个词本身就该从策划面前消失。** 它是内部实现概念：

| 内部叫 | 策划看到的 | 为什么 |
|---|---|---|
| 草图（origin=manual） | 不该看到——拖完就是真线 | Twine 写完链接就是真链接；"草图"是实现细节，不是用户的阶段 |
| 锚点（anchor） | "接在第几步"（边上小标 ⑫ / 提示里一句话） | 策划想的是"接在哪句后面"，不是"时间轴插入点" |
| 锚点确认（弹窗） | **取消**。改成默认值 + 提示条 + [改位置] | 业界证据：常用动作弹窗 = 反模式 |
| line_id | 永远不见 | 程序的身份，和策划无关 |

上一轮说"必须弹窗问，因为不能猜"——**过度了**。
不猜 ≠ 每次都问；不猜 = **不说谎**：放在哪就告诉你哪、让你一眼能改。
默认值 + 可见 + 可改 + 可撤销，四样齐全时，猜的风险已经被拆掉了。

## 五、那"不猜锚点"的铁律呢？——重述，不撤销

铁律的本意是**不静默改剧情**。拆开看：

| 禁止的 | 不禁止的 |
|---|---|
| 不声不响插到"看着像"的第 5 步 | 给章末做默认值，**并且明说**"接在第 12 步（章末）" |
| 不知道却假装知道 | 知道（它原来在第 3 步）就直接放回第 3 步 |
| 改了不告诉人 | 提示条 + 边上小标 + 一键改 + 一键撤销 |

**判据**：任何一次接线，策划**不点开任何东西**就能回答"它接到哪了？"
——看边上的 ⑫ 或看提示条即可。做到这条，就不是猜。

## 六、现在的弹窗到底有多烦（代码事实）

今天的 `AddEdgeDialog`（`ui_qt/dialogs.py:1514`）一次问 **5 件事**：
从、到、类型、条件、菜单项——外加一段 4 行的警告说明。

而策划拖线时**已经给出了两件事**（从 A 拖到 B）：

| 弹窗问的 | 拖线时知道吗 | 处理 |
|---|---|---|
| 从 | ✅ 知道 | 删掉这一问 |
| 到 | ✅ 知道（松手的那块） | 删掉这一问；**只有松在空白处才问** |
| 类型 | 默认"跳转"即可 | 默认值；要调用进侧栏 |
| 条件 | 多数为空 | 侧栏可空字段 |
| 菜单项 | 多数为空 | 侧栏可空字段 |
| 那段警告 | —— | 换成提示条一句话 |

**结论：常见路径 5 问 → 0 问。** 这就是"每次又要问：你要跳去哪里？"的直接解法。

## 七、实施调整（覆盖上一轮的 S 顺序）

| 步 | 做什么 | 策划能感知的变化 | 判据 |
|---|---|---|---|
| **S1** | 边上显示位置小标 ⑫ + 悬停看前后两句 + 点击跳过去 | "这个跳转接在哪"一眼看见，**不再瞎猜** | 打开真机项目，任意线都能说出"第几步、前一句是什么" |
| **S2** | **拖线直接成线**：默认接章末（或当前步）→ 提示条 [撤销][改位置]；弹窗只留给"松在空白处"和"精确放置" | 接一条线**从 5 问变 0 问** | 拖完立刻有线、提示条写明第几步、撤销能回、改位置能挪 |
| **S3** | 删线：提示条 [撤销] + 记住原位置；刷新不弹回 | 删错了能回；不会"删了又冒出来" | 删后刷新原地消失；撤销还原 |
| **S4** | 再加同一条线 → **自动放回原处** | 删了想加回 = 一下搞定 | 加回后落点 = 上次落点，提示条写明 |
| **S5** | 侧栏（检查器）承接条件/菜单/改位置 | 进阶不挡路 | 拖线路径上零弹窗 |

**S1 依旧最先**（只读、零风险、解掉"不知道在哪"）。
**S2 的形态与上一轮不同**：不是弹窗选拍，而是**默认值 + 提示条 + 可挪**。
S4 直接回答你的核心场景。

## 八、给策划的一句话说明书（可直接抄进帮助）

> **想让故事从这章跳到那章？** 从一块拖一条线到另一块，松手——就接好了，
> 接在这一章的最后一步。底下会提示你接在哪，点 **[改位置]** 可以挪到别的步后面。
> 拖错了按 **[撤销]** 就当没发生过。
> **想看看接在哪一步？** 看线上的小数字，或把鼠标停上去——前后两句都会显示。
> **删错了想加回来？** 重新拖一条到同一块，它会回到原来的位置。
