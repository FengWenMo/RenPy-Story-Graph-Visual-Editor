# 资源映射（storygraph.mapping.json）：让工具认识你项目的图

> 适用：任何用 Ren'Py 做的项目，**不只**本工具作者测的那几个。
> 读者：项目的程序 / 主策（懂一点点 JSON 就行）。
> 相关：`docs/规划_二轮反馈修复路径_2026-10-30.md` §2.4 / §2.6。

## 0. 一句话

工具默认能自己猜出"哪张图是哪个角色的哪个表情"（看资源表「标签」列、看文件夹名），
猜不出来时**不瞎猜**（会标成「未识别」）。**资源映射文件**就是给项目的图写一份
"人话对照表"，让工具 100% 认对：哪张是立绘、哪张是预览副本、哪张是头像/背景/CG、
哪个角色叫什么名字。

- 文件格式：**JSON**（可 diff、可提交、可单独发人）；
- 文件名：`storygraph.mapping.json`（放**项目根**或 **`game/` 下**，打开项目自动加载）；
- 也可以放在任何地方，用界面「🗂 资源映射 → 载入映射…」加载。

## 1. 三步上手

### 1) 先生成初稿

打开项目 → 菜单栏「🗂 资源映射」→「导出映射初稿…」→ 存成
`storygraph.mapping.json` 放到项目根。

初稿是工具**按你项目实际目录**自动汇总的 `rules` + 从 `characters.xlsx` 读出的
`characters`；通常只需要改几行。

### 2) 改你项目里"猜不对"的那几条

最常见的三种情况（下面有示例）：

| 现象 | 改哪里 |
|---|---|
| 立绘分类被拆成一堆单图（`立绘：resigned`、`立绘：refusing`…） | 加 `rules`：把 `cc_preview/<角色>/` 这一类声明成 `preview` + `char: "<tag>"` |
| 选了预览图/头像，工具换不到真立绘 | 加 `rules`：真立绘目录声明成 `sprite`（`char: "<tag>"`, `attr: "<stem>"`）；`characters` 里写 `avatar` |
| 角色显示名是英文/编号、不认识 | 在 `characters` 里写 `display`（可加 `aliases`） |

### 3) 校验

「🗂 资源映射 → 资源对照表」会列出每张图的：路径 / 推断出的类别（`kind`）/
角色 tag / 属性 / **来源**（映射 / 标签列 / 文件夹 / 未知）/ 能不能直接上舞台。
筛选「只看未识别」就能看到还缺哪些。

## 2. 文件结构

```json
{
  "schema": "storygraph.mapping/1",
  "name": "千连万理 · 资源映射",

  "characters": {
    "ling": {"display": "凌跃捷", "aliases": ["凌", "LTJ"],
             "avatar": "game/cc_preview/avatar/ling.png"}
  },

  "rules": [
    {"glob": "game/images/characters/<tag>/*.png", "kind": "sprite",
     "char": "<tag>", "attr": "<stem>"},
    {"glob": "game/cc_preview/<tag>/*.png", "kind": "preview",
     "char": "<tag>", "attr": "<stem>"},
    {"glob": "game/cc_preview/avatar/<stem>.png", "kind": "avatar",
     "char": "<stem>"},
    {"glob": "game/images/bg/*.png", "kind": "bg", "attr": "<stem>"},
    {"glob": "game/images/cg/*.png", "kind": "cg", "attr": "<stem>"}
  ],

  "images": {
    "refusing": {"kind": "preview", "char": "ling", "attr": "refusing"},
    "avatar_ling": {"kind": "avatar", "char": "ling"}
  },

  "attributes": {"expressions": {"label": "表情"}}
}
```

四个键（**未知键只警告、不失败**，方便以后扩展）：

- `characters`：角色表。key = 角色在 `characters.xlsx` 的编号或立绘 tag；
  `display` 显示名、`aliases` 别名、`avatar` 头像图（项目相对路径）。
- `rules`：**按顺序匹配**的路径规则，先中先得。`glob` 支持 `*`（不跨 `/`）、
  `**`（跨 `/`）、`?`，以及命名占位 `<tag>` / `<stem>` / `<char>` / `<attr>`；
  `char` / `attr` 里可以引用这些占位。
- `images`：**精确覆盖**（优先级最高）。key 可以是资源表里的**资产 ID**
  （如 `refusing`）或**项目相对路径**（`game/.../x.png`，Windows 反斜杠自动归一）。
  用来处理"一条规则覆盖不到的单张图"。
- `attributes`：属性中文标签（可选）。写 `{"expressions": {"label": "表情"}}`
  会让卡片上的属性格显示中文。

`kind` 必须是下面之一：

| kind | 含义 | 能不能上舞台（写进 `show`） |
|---|---|---|
| `sprite` | 真立绘（引擎里真有这张图） | ✅ |
| `preview` | 预览副本/缩略图（同一张脸的第二份拷贝） | ❌ 选它时工具会自动换成对应 `sprite` |
| `avatar` | 头像 | ❌ 选它时工具会自动换成对应 `sprite` |
| `bg` | 背景 | ✅（`scene`/`show bg`） |
| `cg` | CG | ✅（`show cg`） |
| `ui` | 界面图 | ✅（作为图层） |
| `other` / `unknown` | 其它 / 认不出 | ❌ 会明确提示 |

## 3. 匹配优先级（工具怎么判断一张图）

1. `images` 精确覆盖（资产 ID 或相对路径）；
2. `rules` 按顺序第一条命中的；
3. 资源表「标签」列（**且**这个 tag 是已知角色 tag）；
4. 路径里出现已知角色 tag 的**目录段**（如 `.../ling/refusing.png` → `ling refusing`）；
5. 文件名 stem **恰好等于**角色 tag；
6. 都不是 → `unknown`，**不猜**（卡片上会显示提示，不会静默写出非法 `show`）。

只要加了映射，第 1、2 步优先于推断，所以**你的映射永远说了算**。

## 4. 分发

- **随项目提交**：把 `storygraph.mapping.json` 放进游戏仓库根目录（或 `game/`），
  谁打开这个项目都自动加载；提交前会走 diff 确认。
- **单独发给组员**：把 JSON 发过去，对方「🗂 资源映射 → 载入映射…」选中即可，
  **不需要**放进项目；工具会记住这份映射（下次打开同一项目自动重载）。

> 给别的项目做映射：流程一样——先「导出映射初稿…」，再改几行。
> 工具里**没有任何**写死的项目名/目录名，全部来自你项目的文件与这份映射。

## 5. 常见问答

**Q：必须写映射吗？**
不用。没有映射时工具也按标签列/文件夹推断；映射只是把"猜"变成"确定"，
并修掉猜不对的部分。

**Q：映射写错了会怎样？**
打开项目时会在状态栏/对话框里给一句警告（未知键、坏 JSON 都不会崩）；
「资源对照表」里能直接看到每张图最终落在哪个 kind、来源是什么。

**Q：工具会自动改我的映射或写 `at` 吗？**
不会。工具**不自动写**任何东西；写映射、保存到项目根都是你点按钮触发的。
舞台变换（`at`）同理：只在"你手动选了一个项目里已有的 transform"并确认后
才会写，走既有补丁 diff 门禁、可撤销。

**Q：中文/空格路径行吗？**
行。项目相对路径会归一成 `/` 分隔再比较；JSON 用 UTF-8 保存。
