# 资源映射：让工具认识你项目的图（JSON / Excel 两种写法）

> 适用：任何用 Ren'Py 做的项目，**不只**本工具作者测的那几个。
> 读者：项目的程序 / 主策（懂一点点 JSON 就行；用 Excel 的话连 JSON 都不用懂）。
> 相关：`docs/规划_二轮反馈修复路径_2026-10-30.md` §2.4 / §2.6。

## 0. 一句话

工具默认能自己猜出"哪张图是哪个角色的哪个表情"（看资源表「标签」列、看文件夹名），
猜不出来时**不瞎猜**（会标成「未识别」）。**资源映射文件**就是给项目的图写一份
"人话对照表"，让工具 100% 认对：哪张是立绘、哪张是预览副本、哪张是头像/背景/CG、
哪个角色叫什么名字。

- **两种写法，同一份内容**（写哪份都行，工具都认）：
  - **JSON**：`storygraph.mapping.json` —— 可 diff、可提交、适合 review；
  - **Excel**：`storygraph.mapping.xlsx` —— 1700 行的大表，在 Excel 里维护才现实。
- **一行文件都不想写也行**：界面「🗂 资源映射 → 逐条编辑」就是一张表 ——
  选段落、点「新增一行」、下拉选「是什么」、填角色/属性，点「保存到项目根」，
  它写出来的就是下面那份 JSON。**界面、JSON、Excel 是同一份内容的三个入口**。
- 位置：**项目根**或 **`game/` 下**（打开项目自动加载）；
- 也可以放在任何地方，用界面「🗂 资源映射 → 载入映射…」加载。
- **两份都在时以 Excel 为准**（同一目录里 `.xlsx` 优先于 `.json`），
  工具会在状态栏写 `（Excel）`、在「资源映射」里提醒"还有另一份、别改错了"。

> 想先看一眼长什么样：仓库 `examples/mapping/` 下有同一个项目的两份样例
> （`.json` 和 `.xlsx`，内容完全等价）—— 直接把 `.xlsx` 拷走当模板用。

## 1. 三步上手

### 1) 先生成初稿

打开项目 → 菜单栏「🗂 资源映射」→「导出映射初稿…」→ 存成
`storygraph.mapping.json`（或 `.xlsx`）放到项目根。

初稿是工具**按你项目实际目录**自动汇总的 `rules` + 从 `characters.xlsx` 读出的
`characters`；通常只需要改几行。存成 `.xlsx` 的话，表头、下拉、冻结行都造好了，
打开就能填。

> ⚠ 存成 `.xlsx` 并且放在项目根 = **把它设成生效源**（同一位置 Excel 优先）。
> 想先试试就把表存到别处（桌面），看完再挪进项目。

### 2) 改你项目里"猜不对"的那几条

最常见的三种情况（下面有示例）：

| 现象 | 改哪里 |
|---|---|
| 立绘分类被拆成一堆单图（`立绘：resigned`、`立绘：refusing`…） | 加 `rules`：把 `cc_preview/<角色>/` 这一类声明成 `preview` + `char: "<tag>"` |
| 选了预览图/头像，工具换不到真立绘 | 加 `rules`：真立绘目录声明成 `sprite`（`char: "<tag>"`, `attr: "<stem>"`）；`characters` 里写 `avatar` |
| 角色显示名是英文/编号、不认识 | 在 `characters` 里写 `display`（可加 `aliases`） |

### 3) 校验

「🗂 资源映射 → 工具怎么认的」会列出每张图的：文件 / 工具认为它是（`kind`）/
角色 / 表情（`attr`）/ **凭什么这么判**（映射 / 标签列 / 文件夹 / 未知）/
能直接写进剧本吗（能不能 show）。筛选「只看未识别」就能看到还缺哪些。

### 4) 不想写文件：在界面里直接填表

打开「🗂 资源映射」，第一个页签 **「逐条编辑」** 是同一份映射的表格视图。
屏幕上的表头是给编剧看的说法（2026-10-30 改过一轮，见开发日志 §60），
括号里是它对应的 JSON 键：

| 左栏 | 一行是什么 | 屏幕上要填的（JSON 键） |
|---|---|---|
| 角色 | 一个角色 | 剧本里的写法（`tag`）/ 名字（`display`）/ 别的写法（`aliases`）/ 头像图（`avatar`） |
| 单张图片 | 一张图（精确覆盖） | 是哪张图（`images` 的键：资产 ID 或相对路径）/ 它是哪种图（`kind`）/ 属于谁（`char`）/ 表情／状态（`attr`） |
| 一类图片 | 一类图（批量） | 文件在哪儿（`glob`）/ 它是哪种图（`kind`）/ 属于谁（`char`）/ 表情／状态（`attr`）；顺序有意义 |
| 表情怎么叫 | 一个维度（`attributes`） | 界面上叫它（`label`，例如「表情」） |

- **「新增一行」** 加一条；「它是哪种图」是下拉（屏幕上写「背景」、文件里存
  `bg`，认不出的值不会让你选错），「属于谁」可以挑已有角色，也可以照写
  `<tag>` 这种占位符。每列悬停有"这一格怎么填"。
- **从认图结果补**：切到「工具怎么认的」，选中几张**未识别**的图 →
  **「加进表里…」**，它会按工具已经推断出的那部分先填好，你只补空着的。
- **改完点「保存到项目根」**：先给你看 diff，确认后才写；旧文件备份成 `.bak`。
  表里那一行在你点确认之前**一个字节都没写**。
- 空着的行（点了新增但没填）**不会写进文件**；表里改过什么，底部会说一句。

> 生效源是 Excel 时，这一页顶部会有一条横幅：你改的是 JSON，保存只会写一份
> 同目录 JSON 快照，游戏里仍然用那份 Excel（工具**从不回写**你做的表）。

### 5) 哪几段空着是正常的（2026-11-01 补）

打开时你可能会看到「角色 0 / 单张图片 0 / 一类图片 0 / 中文叫法 0 /
表情怎么叫 0」—— **不是没读到，这五段是覆盖层**：留空就照项目自己的说法走，
写了才叫"我说了算"。

| 段 | 空着时靠什么 | 什么时候才要写 |
|---|---|---|
| 角色 | 资源表 `characters.xlsx` 里的名字（`ling → 凌跃捷`） | 想改谁的名字、或给谁补头像 |
| 单张图片 | 按文件夹 / 文件名 / Tag 列自己判 | 工具**判错**的那几张 |
| 一类图片 | 同上（按目录批量） | 想让一整批图统一算成同一种 |
| 中文叫法 | 显示剧本里的原名（`i11`、`bg9_2`、`bgm/嗯？.mp3`） | 想让屏幕说人话 |
| 表情怎么叫 | 用默认名（表达情绪的那组叫「表情」） | 想换掉默认叫法 |

只有**服装代号 / 表情编号**会在打开时自己长出来：`B`（哪身衣服）和
`7`（几号表情）只存在于剧本注释（`# 表情B7`）和角色文件夹的 `对应.txt`，
别处没有 —— 映射是它们唯一的家。

想把资源表里的角色**固定**进这份映射：角色段空着时有
**「把资源表里的角色写进来」** 按钮。抄进来以后**这一段优先**（以后改
`characters.xlsx` 的名字不会生效）；留空就一直是"照表走"。

## 2. 用 Excel 维护（推荐给大项目）

### 2.1 七张表 + 一张说明

一张表 = JSON 里的一个键：

| 表名（认这些写法） | 对应 JSON | 列（认这些写法） |
|---|---|---|
| `映射` / `mapping` / `meta` | `schema`、`name` | 键 / 值 两列 |
| `角色` / `人物` / `characters` | `characters` | `tag`(角色/编号) / `display`(显示名) / `aliases`(别名) / `avatar`(头像) / 备注 |
| `规则` / `rules` | `rules` | `glob`(路径) / `kind`(类型) / `char`(角色) / `attr`(属性) / `showable`(能否 show) / `display` / 备注 |
| `图片` / `images` | `images` | `key`(资产 ID 或图片路径) / `kind` / `char` / `attr` / `showable` / `display` / 备注 |
| `服装代号` / `服装` | `outfit_codes` | `char`(角色) / `code`(代号 A/B/C) / `attr`(剧本里怎么写) / `label`(说明) / 备注 |
| `表情编号` / `表情` | `expression_codes` | `char`(角色) / `no`(编号) / `attr`(剧本里怎么写) / `label`(说明) / 备注 |
| `中文叫法` / `词汇表` | `vocabulary` | `是什么`(种类) / `原名` / `叫什么` / `编号` / `角色` / 备注 |
| `属性` / `attributes` | `attributes` | `维度` / `label` / 备注 |

「说明」表是工具写给你的使用提示，**随便改、删掉也不影响**读。

> **工具写出去的 .xlsx 表头是中文**（`路径 / 类型 / 角色 / 属性 / 能否 show /
> 显示名 / 代号 / 编号 / 剧本里怎么写 / 说明`）—— 模板是给人照着填的。
> 读的时候英文键名（`glob` / `kind` / `char` …）照样认，两种都行。

#### 后两张表是干什么的（2026-10-31 加）

美术需求表里的写法是 **`B7` ＝ 服装字母 + 表情编号**：`B` 是这个角色第 B 身
衣服，`7` 是第 7 号表情。剧本和美术对稿时说的是 `B7`，Ren'Py 里要写的是
`show lan base_hand_up angry` —— 中间那层换算就是这两张表：

```jsonc
"outfit_codes":     [{"char": "lan", "code": "A", "attr": "aa", "label": "常态"},
                     {"char": "lan", "code": "B", "attr": "base_hand_up", "label": "举手"}],
"expression_codes": [{"char": "lan", "no": "7", "attr": "indifferent", "label": "不在意"}]
```

填好之后，工具里「服装代号 / 表情编号」页上方那个框，两边都认：

| 你写 | 它给 |
|---|---|
| `lan base_hand_up angry` | 代号 `lan B8` |
| `lan B8` | `show lan base_hand_up angry` |
| `lan 举手 生气` | 代号 `lan B8`（中文说明也认） |

**这两张表一般不手填**：界面里点「按项目自动填」，它会

1. 读 `game/images/characters/<角色>/对应.txt`（有几份读几份，`中英对应.txt`
   也认；三种真实写法都吃：`7 不在意-indifferent` / `2 close_happy-闭眼微笑` /
   `表情1-哈哈 — haha`）；
2. 数剧本注释里的代号：`# 表情B7` 后面那条 `show` 说了 `B` 是哪身衣服；
3. 某一项数不出来（剧本里没出现过那种号）就**留空**，并在问题条里点名 ——
   不按顺序硬凑一个字母。

⚠ 两份编号表对不上时（真实项目 lan 的 `对应.txt` 与 `中英对应.txt` 就不同），
工具会用**和剧本注释对得更多**的那份，并在提示里说明另一份对上了几处。

#### 「中文叫法」那张表：屏幕上说人话，剧本里写原名（2026-10-31）

一张表管**所有**"想给它起个中文名"的东西 —— 位置、音乐、背景、角色、
过场、服装、表情，差别只在 `是什么` 那一格：

| 是什么 | 原名（写进剧本的那个） | 叫什么 | 编号 | 工具里会变成 |
|---|---|---|---|---|
| 位置 | `i11` | 1人，近处 | | 立绘卡的「位置」chip + 右键候选列表 |
| 音乐 | `bgm/嗯？.mp3`（或资产 ID `night`） | 嗯？ | 18 | 音乐那格的下拉：`18 嗯？` |
| 背景 | `bg9_5`（或 `classroom`） | 储物间 | bg9.2 | 背景那格的下拉：`bg9.2 储物间` |
| 角色 | `DY` | 大爷 | | 说话人下拉 + 左栏「参与角色」 |
| 过场 | `Fade(0.2, 0.0, 0.2)` | 闪白 | | `with …` 那格的候选 + 「⋯」里能搜 |
| 服装 | `base_swimsuit` | 泳装 | B | 立绘卡的服装 chip（`B 泳装`） |

三条要点：

1. **`原名` 才是真值**：屏幕上换成中文，点「⤓ 导出 .rpy」写出去的**还是原名**
   —— 词汇表不认识的东西一律原样显示，所以只登记三条也不会把别的变空白。
2. **过场那一条特别有用**：`with` 是"过场动画"的落点，你在词汇表里登记过的
   过场（`Fade(...)` / 自己写的 `my_wipe`）会出现在那一格的下拉里，
   显示成中文；旁边「⋯」开了个**输入即筛**的列表，中文名和原名都能搜到。
   也可以不写这张表，走「🧩 自定义语句 → 技术调用…」填「中文名」那一列 ——
   两处都读，**映射表优先**。
3. **服装/表情的行要写「角色」**：同一个代号 `B` 在 lan 和 ye 身上不是一件衣服
   —— 不写角色就是"通用"的。这两类也可以继续用「服装代号 / 表情编号」两张表
   （那边填过就以那边为准）。

### 2.2 五条规矩（都是"人一定会遇到"的）

1. **行的上下顺序 = 规则的先后**。「规则」表是**先中先得**，所以 `avatar` 那种
   "一个人一个文件"的规则要放上面、`<tag>` 那种"一个目录一群角色"的放下面。
   想调顺序就整行挪（Excel 里最自然的操作，正好对上 JSON 数组的顺序）。
2. **空单元格 = 不写这个键**（不是写了空字符串）。所以"这张图让工具自己推断"
   就是**把 kind 那格留空**，别填 `other`。
3. **`备注` 列是给人写字的**，工具刻意不看 —— 随便写，不会变成警告。
4. **表头不必在第 1 行**：前 10 行里找第一个认得出的表头，上面可以写标题、
   写日期、写"这张表谁维护"。
5. **单元格里写数字也行**：资产 ID `13.2` 按文本读回来（`13.0` 会变成 `13`；
   想保住 `007` 这种前导零，先把那一列设成"文本"格式再填）。

`能否 show` 认：`是/能/可以/1/y/true` 和 `否/不能/0/n/false`；
认不出的值会给一条警告，并当成"没写"（让工具自己判断）。

### 2.3 改完怎么生效

存盘 → 工具里点「🗂 资源映射 → **重读**」。不用重启工具，也不用重新打开项目。

### 2.4 工具会不会改我的 Excel？

**不会。** 工具**只读**这份 `.xlsx`，一个字节都不写。所以：

- 「保存到项目根」写的是**同目录的 `storygraph.mapping.json` 快照**
  （原子写 + 旧文件 `.bak`），**不碰**那份 Excel，也不改变"以 Excel 为准"；
- 需要提交进仓库 / 发给组员时，用那份 JSON（可 diff、可 review）。

> 为什么不回写：改一份人做的表要 `load` → `save` 走一轮，而 Excel 库会**丢掉**
> 它不认识的东西（图、图表、条件格式）。映射表里如果夹着项目截图，
> 静默丢图是不可接受的。

### 2.5 两份都有时怎么办

**同一目录里 Excel 优先**（项目根 / `game/` 各自内部按这个规则；目录的远近
先于格式：项目根的 JSON 胜过 `game/` 里的 Excel）。

工具会明说：

- 状态栏：`映射：项目文件（Excel）`；
- 「资源映射」里：「项目里还有 storygraph.mapping.json，但当前以
  storygraph.mapping.xlsx 为准 —— 改别的那份不会生效」。

不想要那份 Excel 的优先级：把它改名 / 挪走 / 删掉即可（工具不会自动删）。

## 3. 文件结构（JSON 写法）

```json
{
  "schema": "storygraph.mapping/1",
  "name": "千连万理 · 资源映射",

  "characters": {
    "ling": {"display": "凌跃捷", "aliases": ["凌", "LTJ"],
             "avatar": "game/cc_preview/avatar/ling.png"}
  },

  "rules": [
    {"glob": "game/images/characters/<tag>/*.png", "kind": "sprite",
     "char": "<tag>", "attr": "<stem>"},
    {"glob": "game/cc_preview/<tag>/*.png", "kind": "preview",
     "char": "<tag>", "attr": "<stem>"},
    {"glob": "game/cc_preview/avatar/<stem>.png", "kind": "avatar",
     "char": "<stem>"},
    {"glob": "game/images/bg/*.png", "kind": "bg", "attr": "<stem>"},
    {"glob": "game/images/cg/*.png", "kind": "cg", "attr": "<stem>"}
  ],

  "images": {
    "refusing": {"kind": "preview", "char": "ling", "attr": "refusing"},
    "avatar_ling": {"kind": "avatar", "char": "ling"}
  },

  "attributes": {"expressions": {"label": "表情"}}
}
```

四个键（**未知键只警告、不失败**，方便以后扩展）：

- `characters`：角色表。key = 角色在 `characters.xlsx` 的编号或立绘 tag；
  `display` 显示名、`aliases` 别名、`avatar` 头像图（项目相对路径）。
- `rules`：**按顺序匹配**的路径规则，先中先得。`glob` 支持 `*`（不跨 `/`）、
  `**`（跨 `/`）、`?`，以及命名占位 `<tag>` / `<stem>` / `<char>` / `<attr>`；
  `char` / `attr` 里可以引用这些占位。
- `images`：**精确覆盖**（优先级最高）。key 可以是资源表里的**资产 ID**
  （如 `refusing`）或**项目相对路径**（`game/.../x.png`，Windows 反斜杠自动归一）。
  用来处理"一条规则覆盖不到的单张图"。
- `attributes`：属性中文标签（可选）。写 `{"expressions": {"label": "表情"}}`
  会让卡片上的属性格显示中文。

`kind` 必须是下面之一：

| kind | 含义 | 能不能上舞台（写进 `show`） |
|---|---|---|
| `sprite` | 真立绘（引擎里真有这张图） | ✅ |
| `preview` | 预览副本/缩略图（同一张脸的第二份拷贝） | ❌ 选它时工具会自动换成对应 `sprite` |
| `avatar` | 头像 | ❌ 选它时工具会自动换成对应 `sprite` |
| `bg` | 背景 | ✅（`scene`/`show bg`） |
| `cg` | CG | ✅（`show cg`） |
| `ui` | 界面图 | ✅（作为图层） |
| `other` / `unknown` | 其它 / 认不出 | ❌ 会明确提示 |

## 4. 匹配优先级（工具怎么判断一张图）

1. `images` 精确覆盖（资产 ID 或相对路径）—— **点名某一张**，可以改项目自己的声明；
2. **项目自己在 `.rpy` 里声明过的图像名**（`image` / ATL 块 / `layeredimage`）；
3. `rules` 按顺序第一条命中的 —— **只补空缺**，改不动第 2 步；
4. 资源表「标签」列（**且**这个 tag 是已知角色 tag）；
5. 路径里出现已知角色 tag 的**目录段**（如 `.../ling/refusing.png` → `ling refusing`）；
6. 文件名 stem **恰好等于**角色 tag；
7. 都不是 → `unknown`，**不猜**（卡片上会显示提示，不会静默写出非法 `show`）。

> **2026-10-31 起，第 2 步夹在中间了**：以前"映射（精确 + 规则）"整体在最前，
> 于是一条 `game/**` 的规则就能把项目自己声明的名字整片改掉 —— 而规则是
> "这一类大概都这样"，它该**只补空缺**。
> **要改某一张**就写进 `images`（第 1 步，一行一张）；**`rules` 只管没人声明过的图。**
> 同一套顺序的唯一真源是 `storygraph/core/authority.py`。

## 5. 分发

- **随项目提交**：把 `storygraph.mapping.json` 放进游戏仓库根目录（或 `game/`），
  谁打开这个项目都自动加载；提交前会走 diff 确认。
- **在 Excel 里维护的团队**：把 `storygraph.mapping.xlsx` 放进仓库（或 `game/`）。
  它优先于 JSON，所以别再放一份旧的 JSON 在旁边 —— 工具会提醒，但人也容易忘。
- **单独发给组员**：把 JSON 或 Excel 发过去，对方「🗂 资源映射 → 载入映射…」
  选中即可，**不需要**放进项目；工具会记住这份映射（下次打开同一项目自动重载）。

> 给别的项目做映射：流程一样——先「导出映射初稿…」，再改几行。
> 工具里**没有任何**写死的项目名/目录名，全部来自你项目的文件与这份映射。

## 6. 常见问答

**Q：为什么我按 `B7` 换算，它说「服装代号里没有 C」？**

表里没有那个字母。去「服装代号」那段补一行（角色 / 代号 / 剧本里怎么写），
或者点「按项目自动填」让它先照着剧本注释数一遍。

**Q：`B7` 里的 B 和 7 是从哪儿来的？**

`7` 来自角色文件夹里的 `对应.txt`（有几份读几份）；`B` 来自剧本注释 ——
`# 表情B7` 后面那条 `show` 里用的服装属性就是 B。两样都不靠工具"猜顺序"。

**Q：我不想要自动填的表，能清掉吗？**

能。「服装代号 / 表情编号」两段里「删除选中」，或者保存前别点保存；
模板也可以先用「存一份空模板…」导出一份空表照着填。

**Q：必须写映射吗？**
不用。没有映射时工具也按标签列/文件夹推断；映射只是把"猜"变成"确定"，
并修掉猜不对的部分。

**Q：映射写错了会怎样？**
打开项目时会在状态栏/对话框里给一句警告（未知键、坏文件都不会崩），
Excel 那条警告还会带**表名和行号**（`「图片」表第 12 行：kind 不认识`），
照着找就能改。「资源对照表」里能直接看到每张图最终落在哪个 kind、来源是什么。

**Q：我改了 JSON，怎么没生效？**
看状态栏有没有 `（Excel）` —— 同一目录里 `.xlsx` 优先。这时改的是 Excel 那份，
或者把 Excel 改名/挪走。

**Q：Excel 里写了公式，读出来是空的？**
读的是**缓存值**。用 Excel 打开、保存一次，值就有了；从没保存过的公式读出来是空，
那一格会被当成"没写"（工具会给一条提醒）。

**Q：工具会自动改我的映射或写 `at` 吗？**
不会。工具**不自动写**任何东西；写映射、保存到项目根都是你点按钮触发的；
Excel 那份更是一个字节都不碰。舞台变换（`at`）同理：只在"你手动选了一个项目里
已有的 transform"并确认后才会写，走既有补丁 diff 门禁、可撤销。

**Q：中文/空格路径行吗？**
行。项目相对路径会归一成 `/` 分隔再比较；JSON 用 UTF-8 保存，Excel 也没有额外要求。
