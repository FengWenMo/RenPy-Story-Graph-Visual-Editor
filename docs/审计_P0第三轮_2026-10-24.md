## 二、新 P0

### P0-9 · 带标题的 `menu`，标题改不动（真机命中）

```rpy
    menu "是时候和青一起学习了.":     ← 改这一句的标题
        "开始":
            $ renpy.block_rollback()
            jump pomodoro
```

改 `Text` → 导出 `ok=False`，零 diff，拒因：

```
1 处新增内容没能落进产物
```

（合成样本同构：`menu "标题":` 改标题 / 改选项 / 改选项体里任何一拍
都会整块对位失败。**不带标题的 `menu:` 改选项正常**。）

**影响**：菜单标题是高频编辑（"这一章的问句写错了"），改完导不出、
文件一个字节不动 —— 用户的工作直接丢在内存里。真机 `script_pomo.rpy`
稳定复现。

**根因方向**：`storygraph/story/patcher.py` 对 `menu` 头行的保护 ——
`_PROTECTED_RE` 认 `menu\s*:`，`_rewrite_line` 的"保留原文"通道拦住了
标题改写；生成结果里标题已变 → 校验说"生成内容在补丁结果里找不到" →
整份拒绝。和上一轮的 call/jump"只插不删"同源（那一支已修，menu 头没有）。

**判据**：`menu "旧标题":` 改成 `"新标题"` → 导出后只有一行变化；
同块的选项/选项体一个字节不动。

### P0-10 · 删一拍会把相邻的 `elif` 改写（改坏没碰过的行）

真机 `script_pomo.rpy`，删 idx25（`elif breakline == 2:` 那一拍）：

```
-    elif breakline == 2:
-        q "您可能需要休息了."
+    if (breakline == 3) and not ((breakline == 1) or (breakline == 2)):
```

**作者写的 `elif` 被展平成了 `if … and not (…)`** —— 语义上等价，
但这正是 `_rewrite_line` 里明文禁止的：

> `elif` / `else` 头不许被"展平"改写（2026-10-05，增量 O1）…
> 用户改的是台词，凭什么顺手把作者的 `elif` 改掉？

删拍路径绕开了这条守卫。而且连带把**相邻分支的条件行**改了：
用户删的是第 25 拍，第 24 拍那条 `elif` 也被卷进"重排段"重写。

**影响**：删一句台词 = 重写分支结构。合 20+ 个 `elif` 的章节里，
分支写法会被悄悄换掉（git diff 一大片，评审时看不出是工具干的）。

**判据**：删一拍 → 产物只少那一拍的行；`elif` / `else` / `if` 行
**逐字节不动**（结构行改动必须由用户显式改条件字段触发）。

### P0-11 · 移动拍可以越过 `return`（静默把台词变成死代码）

```
move(0, 3)（把第一句挪到最后）
→ 产物：
    e "二"
    e "三"
    return
    e "一"        ← 永远不会执行
```

```
move(2, 0)（把 return 挪到最前）
→ 产物：
    return        ← 整章立刻结束
    e "一"
    e "二"
```

两次都是 `ok=True`、无警告。**剧情直接丢台词/整章截断**。
（真机上移动会被"重排段里有认不出的行"拒掉，所以真机暂时安全；
合成章节 / 表格入口 / API 都会踩。）

**判据**：`move_beat` 拒绝任何让 `return` 离开 label 末尾的落点
（或至少返回 `ok=False` + 原因）；不许"成功了但剧情断"。

## 三、判据校准（我误报的，别当 bug 修）

1. **"改选项体台词会插入新行"** —— 那一拍是**代码拍**
   （`$ renpy.block_rollback()`，text 为空）。给代码拍加 Text = 新增一句
   台词，渲染成 `$ …` + `"X"` 两行，**是正确行为**。
2. **`Kind='narration'` 改了不生效** —— kind 是说话人的投影（设计）。
3. **插空卡不落盘**（`ok=True` 零 diff）—— 空卡不产生行，属设计；
   但"ok=True 且一个字节没动"建议在 UI 上说一句"空卡没有可写内容"。

## 五、给修的人的顺序

1. **P0-9（menu 标题）** —— 高频编辑直接被拒，用户体验最差；
   修法与上轮 call/jump 那支同源（`_rewrite_line` 放行"同一件事的

2. **P0-10（elif 展平）** —— 删拍路径要复用 `_rewrite_line` 的
   "elif/else 不许展平"守卫；删拍只许删它自己的行区间。
3. **P0-11（return 越界）** —— `ChapterTree.move_beat` 加一条结构守卫：
   `return` 拍必须是 label 的最后一拍。

判据建议（三条共用）：**"只动该动的行"** ——
改动波及 `elif/if/else/menu` 等结构行时，一律先红。
