# L1 加固：兼容读取 + 失败回退静态（2026-11-05）

> 用户原话：「如果引擎读不到或者版本不对应的话，尝试一下兼容地读取，如果还是
> 失败……不要弹窗，直接在控制台界面说失败，回退回静态解析就好。」

L2 先不做。这一片只把 L1 的三条缝补实。

## 一、兼容读取：命令**阶梯**

`storygraph/engine/compat.py`（纯 stdlib）：

```
① lint --error-code --json-dump <path>   全：诊断 + 清单 + 退出码
② lint                                    简：只要诊断
```

一档跑不动就退下一档。`pipeline/engine_collect._run_lint_ladder()` 执行它，
返回 `(rc, out, 真正跑成的那一档)` —— 第三项进 `facts.engine.lint_argv`，
出问题时一眼看出"这次退到了第几档"。

### ⚠ 判"要不要退"看的是**引擎不认旗**，不是 exit code

第一版想法是"非 0 就退"。**错了**：项目有语法错时 lint 的 exit code 就是 1，
那是**正常结果**（我们正需要那些诊断）。按 exit code 退阶会把每次"项目有错"
都变成"再跑一遍最简 lint"—— 真机多花几十秒，什么都没多拿到。

判据：输出里出现 `unrecognized arguments` / `no such option` / `invalid option`
/ `unknown option` / `error: argument` 才算"引擎不认这面旗"（`compat.reject_reason`）。

### 版本太老就**不试**带 dump 的那一档

`--json-dump` 是 Ren'Py 7.4+ 才有的。`lint_ladder(version)` 在
`version < 7.4` 时直接给 `[['lint']]` —— 省一轮（那一档必定被拒）。
版本探不到（`None`）时**照试全档**（不因为"不知道"就放弃）。

## 二、不弹窗

采集链路（`pipeline/engine_collect.py` / `pipeline/renpy_adapter.py` /
`engine/compat.py`）**零 GUI 依赖** —— AST 扫出来的，判据
`test_collection_path_never_imports_a_dialog`。

顺带查过：UI 层 `window_engine.py` 里那 16 处 `QMessageBox` 全是**引擎试玩**
的交互确认（"从这一拍还是章首"），与 facts 采集无关，没动。
`app/notify.py` 是通知端口（订阅者模式，状态栏用），也不是弹窗。

## 三、失败 → 控制台说一句 → 回退静态

CLI（`storygraph/cli.py::_print_collect_failure`）：

```
  ⚠ 引擎事实**采不到**：工程未通过语法检查（有 parse error）……
  → 已回退到**静态解析**（声明 / 资源表 / 剧本用法），功能不受影响，只是少了运行期证据
```

两行，**不弹框、不中断**。档位落到 R2（`decide.rung(collectable=False)`），
`allows(R2, [运行期能力])` 一律拦住 —— 于是"引擎读不到"这件事在
**判断层**也表现为"无法判定"，而不是"没问题"。

## 五、这一片**没做**的（留给 L2 或以后）

- **不改探针源码**：现在的 `probe_source()` 一份，8.4 / 8.5 共用。真要分版本，
  等出现"某个 API 在 8.x 里变了"的实测证据再说（现在没有）。
- **不按版本禁能力**：`lint_ladder` 只影响**命令**，不影响 `capabilities` 的判定；
  "这个版本没有某能力 → `False`"还需要一张版本-能力表，等第三个 adapter 出现再谈。
- L2（IR core / profile）按用户要求**暂缓**。
