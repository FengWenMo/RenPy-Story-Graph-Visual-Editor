## 三、裁决（自主敲定）

### ④ 坏表整份重建 → **修（第一位）**
- **理由**：四条里唯一在**丢用户工作**的（列/行/页/批注推平），且用户为同类问题
  （P0-F 资源表）已明确表态"不要做隔离备份，这解决不了根本问题，要直接保住"。
  产品派"读不出的表物理上保不住"的反驳**部分成立但不全对**——实现派实测
  zip 级抢救能完整读回用户行（workbook 坏/缺 styles 仍可救），先抢再判。
- **修法**：复用 `xlsx_preserve` 口径（按编号对行、认不出按真实文件）+
  zip 级抢救；重建**只在抢救失败后**才发生，且必须 ①回执点名丢了什么
  ②原件不删（带时间戳留底）③"被 Excel 占用"不得算坏表。
- **红线**（把关派）：抢救后若行数/关键列对不上 → `ok=False` + 原封不动，不许"半保住"。

### ① 无标题 menu 加标题 → **修（收口）**
- **理由**：编剧高频场景（补标题必撞），产品派判"只修一半不能接受"成立；
  主体已修说明这条路走得通，剩死角是口径不统一（extras/嵌套），不是结构鸿沟。
- **修法**：嵌套 menu 加标题走 `_body_lines()` 剥 `if` 头；单拍 extras 与整份渲染
  同口径（顺手治"补 `$` 改坏脚本"）。小改 + 判据红绿对照。
- **红线**：改不动就 `ok=False` 说清哪个形态被拒，不许静默丢标题。

### ② 移动拍被拒 → **只修报错体验，行为不放宽**
- **理由**：把关派红线答辩成立——"空隙里那行 `$ renpy.pause(hard=True)` 跟谁走"
  答不上就不许动；静默换位毁剧情且 diff 无痕，事后三方都发现不了。
  实现派窄口（放行 define/image）诱人，但"认不出的行都是 init 期声明"是
  **样本结论不是保证**，放宽判据 = 把保险丝换粗。52% 已可增量 ≠ 需要冒险到 80%。
- **修法**：拒因点名**具体哪一行、为什么危险、绕路是什么**（清条件再挪 /
  复制到目标+删原卡）。产品派"能接受只修一半"成立。
- **红线**（永不放开）：跨块头/跨 label/带条件的移动 = 改剧情，永远拒。

### ③ 改 if 条件 → **不修行为，拒因说人话**
- **理由**：三方一致。elif 表里存的是展平累积条件，反解 own 条件 = 猜语义
  （铁律 3/4）。链头/独立 if 已可增量，覆盖高频。
- **修法**：拒因明说"改条件请走全量导出到 build/renpy/"。产品派的"elif 原文行
  编辑"是新编辑面，**留给用户定**，不擅自上。

**根因教训（① 最值钱的一条）**：`_range_looks_like` 的身份判据只认
`text == MENU_NO_CAPTION`（无标题形态）—— 用户加了标题后 `text` 是**新**标题、
原文里根本没有 → 每条身份判据都失效 → 判"错位" → `allow_edit=False` →
标题通道被关在门外。**"用户正在改的那一位"绝不能当身份**（标题正文、台词正文
同理）。改成"菜单拍的身份是 `menu:` 头行"后六形态全通。
