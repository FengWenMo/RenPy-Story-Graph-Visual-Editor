## 1. P0-A 行边界：`splitlines()` 认的"换行"比 Ren'Py 多 7 种

### 1.1 攻击链（`tools/_p0_audit_round5_primitive.py`，修前逐字输出）

```
[FAIL] 5 行内 U+2028：字节一个不动（只该改第 3 行）
       got=b'label ch1:\n    "hi\xe2\x80\xa8there"\xe2\x80\xa8    "B"\n'
       exp=b'label ch1:\n    "hi\xe2\x80\xa8there"\n    "B"\n'
```

第 3 行 `"b"` 确实改成了 `"B"`，**但第 2 行的 `\n` 被换成了 `U+2028`**。
Ren'Py 的 lexer 只认 `\n`，于是这两条语句在引擎眼里是**一条**
（`"hi…there"    "B"`）—— 产物直接语法错。用户从没碰过第 2 行。

四种字符 × 中段插入 = **4/4 全部被改写**：

| 字符 | 名字 | 谁带进来的 |
|---|---|---|
| `U+2028` | LINE SEPARATOR | 网页 / Word 的"软回车"，粘台词十次里有几次 |
| `U+2029` | PARAGRAPH SEPARATOR | 同上 |
| `U+0085` | NEL | 老式换行，从某些 PDF / RTF 粘进来 |
| `\x0b` `\x0c` | VT / FF | 复制表格、分页符 |

### 1.2 根因：两处口径不一致（两个方向都坏）

`str.splitlines()` 把上面这些都当行边界，Ren'Py 不认。于是：

* **切开再拼回**（`source_line_delete` / `control_route` / `control_branch`
  都是 `text.splitlines()` → 处理 → `'\n'.join(...)`）：
  一个 `U+2028` **变成真正的换行**，一行变两行 —— 注释后半截成了顶层语句；
* **按"每行自己的换行符"还原**（`source_style._restore_line_endings` 用
  `splitlines(keepends=True)` 算每行的 EOL）：
  那个 `U+2028` 被记成"第 2 行的换行符"，写回时**把真 `\n` 顶掉**。

实测 `control_route`（编排层接线）R2 组：`call ch02 # 注<U+2028>释`
接线之后，注释被拆成两行，`释` 单独成行 → 脚本语法错。

### 1.3 修法：一处实现，全仓统一

新增 `storygraph/core/textlines.py`：

* `split_lines(text)` —— **只按 `\n` 切**，特殊分隔符留在行内；
* `split_eols(text)` —— 同口径的 `(行内容, 行 EOL)`；末行没有换行时 EOL 是 `''`；
* `join_lines(rows, eols)` —— 逆运算（往返逐字节相同，有判据）。

接上它的是**所有会拼回文本的地方**：`source_style._split_eols`、
`renpy_parser`（6 处）、`source_line_delete`、`control_route`（9 处）、
`control_branch`（8 处）。

> 为什么连解析器也要改：`src_first` / `src_last` 是解析器给的物理行号，
> 而改写点按自己的行号去删行。两边口径不一致时，症状不是"字节变了"，
> 而是**删错行**——那是更坏的形态。改完的副产品：含 `U+2028` 的章节
> 从前**根本载入不了**（V1 组"解析不出 jump"），现在能正常解析。

### 1.4 复测

```
[PASS] 5 行内 U+2028：字节一个不动（只该改第 3 行）
[PASS] 5 行内 NEL U+0085：字节一个不动
[PASS] 5 行内 VT \x0b：字节一个不动
[PASS] 5 行内 FF \x0c：字节一个不动
汇总：11/11 通过
```

`control_route` R2（编排层 + U+2028）：原有行逐字节还在、`U+2028` 计数不变、
总行数不变。`source_line_delete` V1b（尾注里 U+2028）：删一拍后其余字节不变。

## 2. P0-B 编码腐蚀：修在调用点上，必然漏

### 2.1 攻击链（`tools/_p0_audit_round5_paths.py` R3 组，修前）

```
[FAIL] R3 编排层 CRLF+非法字节：原有行逐字节还在
       before=b'... # \xff\xfe\r\n label ch02_control: ...'
       after =b'... # \xef\xbf\xbd\xef\xbf\xbd\r\n label ch02_control: ...'
```

`apply_control_route` 返回 `ok=True`、`error=''`。**用户文件里的两个坏字节
变成了两段 U+FFFD（6 个字节）**，`git diff` 说这行改过，而人只是"接了一根线"。
`write_text_atomic` 默认 `backup=False` —— 原字节不可恢复。

### 2.2 为什么第三轮"修过了"还漏

第三轮的 P1-A 修法是**在两个调用点上各加一次严格解码预检**
（`_write_new_chapter`、`choice_point`）。同一个仓库里于是出现两种待遇：

| 路径 | 读到坏字节时 |
|---|---|
| 新建章节 / 选择点 | 拒写 + 说清坐标 ✅ |
| **接线 / 取消接线 / 改条件 / 删源行 / undo / 编辑器导出** | **照写，坏字节变 U+FFFD** ❌ |

`read_text()` 是 `errors='replace'` 的（解析器要能读完整份文件，一个坏字节
不该让整章打不开）—— 这个设计没错，错在**"读回来再写回去"的路径也用它**。

### 2.3 修法：拦在唯一的末班车上

`SourceStyle.apply(text, source=路径)` 本来就要读一遍源字节（判断每行换行符），
**它天然就是所有落盘点的共同末班车**。改成严格解码，解不开抛
`SourceNotUtf8`（带第一个坏字节的下标）。

八个落盘点各自把它变成"拒写 + 人话"：

| 落盘点 | 拒写后的表现 |
|---|---|
| `apply_control_route` / `_unroute` / `_edit` / `_init` | `ok=False`，`error` 带文件名与字节坐标 |
| `apply_control_branch` | 同上 |
| `apply_source_line_delete` | `ok=False`，命令层抛 `RuntimeError`（沿用既有"为了不覆盖新改动"的通道） |
| `undo` / `redo`（9 处） | 同上 |
| `apply_choice_point` / `_write_new_chapter` | 保留原有预检，多一层兜底（极小窗口） |
| `write_generation` | 新增 **block 级** `SOURCE_NOT_UTF8`，产物不落盘、进 `.blocked.rpy` 供对比 |
| `compile`（pass-through 复制路径） | `written=False` + `patch_note` 说清 |

### 2.4 复测

```
[PASS] R3 编排层 CRLF+非法字节：拒写且字节未动（说清原因）
       err="…ch.rpy 不是 UTF-8（Ren'Py 只认 UTF-8）：第 6 字节起。为了不改坏原字节，这次没有写。"
[PASS] 6 非 UTF-8：read_text 有损、apply(source=) 拒写（不腐蚀）
```

## 3. P0-C undo/redo：整份写回却不还原逐行换行

`graph/commands.py` 有 9 处 `write_text_atomic(path, style.apply(old_text))` ——
**没有 `source=`**，于是 `apply` 走"整份统一成一种风格"的老路。

修前行为推演（`apply` 层的判据在 P0-A 已实测）：混合换行文件里，
没碰过的 CRLF 行会被整份改成 LF —— 用户按一次 Ctrl+Z，`git diff` 满屏。

第三轮的 §6「下一轮候选面」把它记成"设计题"（要还原得另存原始 EOL）。
这一轮判定：**它不属于设计题，属于漏传参数** —— `apply(source=)` 会按
**当前盘上那一份**逐行对齐，恢复的正是每一行自己的换行符；
剩下"被删掉的那一行借钱一行的换行"是唯一的近似，且只在混合换行文件里出现。

修法：9 处补 `source=`；并加一条**结构守卫**
（`tests/test_p0_round5_carrier.py::test_no_line_boundary_regressions`）：
`graph/commands.py` 里任何 `style.apply(` 都必须带 `source=`，
`renpy_parser` / `source_line_delete` / `control_route` / `control_branch`
里不许再出现 `.splitlines()`。

## 4. P0-D 表过期丢行：CLI 说了，编辑器不说；后面还补一句反话

### 4.1 复现（`tools/_p0_audit_round5_stale.py`，普通 LF 文件，无任何诅咒）

```
① 策划：cli.py table rpy2xlsx ch1.rpy        → ch1.xlsx
② 程序员：在 ch1.rpy 的「第二句」后面加 4 行
     pause 0.5 / $ flag = True / # 程序员备注 / play music "bgm.ogg" fadein 1.0
③ 策划：cli.py table xlsx2rpy ch1.xlsx --source ch1.rpy --out ch1.rpy
```

结果：`$ flag = True` 与 `play music …` **消失了**，退出码 0。

### 4.2 三个出口三种待遇

| 出口 | 修前 |
|---|---|
| CLI `_report_incremental` | ✅ 点名："其中**删掉了源文件里 2 行**：- $ flag = True - play music …" |
| CLI `format_compile_result`（紧跟其后打印） | ❌ "增量补丁：只改了 4 行，**原文其余部分（含 default / init python / transform）逐字节保留**" —— 反话，而且它排在后面，用户读的是这句 |
| 编辑器 `session_export._patch_note` | ❌ 一个字都不提，只有"改动 4 行" —— 它是**编辑器导出唯一的回执来源** |

> **一处必须说清的边界**：编辑器那条路上，"载入之后别人往同一个文件里加了行"
> 已经被 2026-10-21 的"表与源码不同步"守卫**拒写**了（本轮实测，见 §4.5：
> `ok=False`、文件一个字节没动、理由说清）。所以编辑器那条路的静默删行
> 只发生在**用户自己把某一格的舞台/代码清空**时 —— 那是**有意**的，
> 但按铁律 #7「不许静默丢行」，有意也要说：卡片视图里删掉一张卡的舞台内容后，
> 没人会去数源文件少了哪几行。

删本身是设计内的（表里没有对应格子），问题只在**没说**。

### 4.3 修法：一句话只写一份

`patcher.removal_note(res)` —— 唯一实现，三个出口共用：

```
增量补丁：只改了 4 行，原文其余部分…逐字节保留；**删掉了源文件里 2 行**
（表里已经没有对应内容 —— 表是不是在源码改动之前生成的？）：$ flag = True / play music "bgm.ogg" fadein 1.0
```

### 4.4 复测（判据改成"每行要么还在、要么被点名"）

端到端判据（`tests/test_p0_round5_carrier.py::TestStaleChapterExportIsNeverSilent`）
钉的是**不变量**，不是某一句措辞：源里消失的行，**要么导出被拒，要么回执点名**。

```
实跑（编辑器导出 + 载入之后程序员又加两行）：
  ok = False
  blocking[0] = 表与源码不同步：源里有 1 拍台词不在表里（例如「第三句」）…
  盘上：一字未动
```
两个出口分别落在"拒写"和"点名"上，两种都算通过 —— 覆盖两条路的是同一条判据。

```
程序员加的 4 行，导完后丢了 2 行：
   LOST:     $ flag = True
   LOST:     play music "bgm.ogg" fadein 1.0
静默丢行？否（都点名了）（丢 2 行，其中没点名 0 行）
```

## 7. 没修的（逐条给理由，不是"来不及"）

| 项 | 级别 | 为什么先不动 |
|---|---|---|
| 孤立的 `\r`（老 Mac 换行）仍会被折成 `\n` | P2 | Ren'Py 自己也读不成行（它只认 `\n` / `\r\n`）；这种文件在 renpy 项目里等于坏文件。真要处理得先定"`\r` 算不算换行"，属引擎语义题 |
| undo 恢复**被删掉的那一行**时，混合换行文件里它可能借到前一行的换行符 | P2 | 计划里没存"原始 EOL 向量"，信息在计划期就丢了。要彻底修得给 `SourceLinePlan` 加字段（下一轮，5 行代码） |
| 表过期时"只丢非台词行"仍会丢（但会点名） | P1 | 与"舞台列清空 → 那行该删"是同一个判据，**分不开**。真正的解法是让表记住"导入时源文件的指纹"（xlsx 隐藏表加一行），导出时对不上就拒 —— 属设计变更，要用户拍板 |
| CLI 一次导出打印两段回执（`_report_incremental` + `format_compile_result`） | P2 | 现在两段说的是同一件事（都点名删行），不影响正确性；但读起来啰嗦，建议合并 |

## 9. 一句话总结

前三轮修的是"**已知形状上的错**"（某条路径漏了个判断）；这一轮修的是
"**判据本身的错**"——`splitlines()` 的行边界、`errors='replace'` 的读、
以及"同一个事实三个出口三种说法"。这三类错误的共同点是：
**它们不会在真机上当场报错，只会让用户的字节悄悄变掉**。
所以判据从此钉在三处：字节（`apply(source=)`）、行（`textlines`）、
回执（`removal_note`）——每一处都只有一个实现。
