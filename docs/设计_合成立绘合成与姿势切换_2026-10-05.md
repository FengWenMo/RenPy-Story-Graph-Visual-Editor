# 设计方案：合成立绘（layeredimage）与姿势切换

> 用户 2026-10-05 的目标（原话）：
>
> 1. 解析 layeredimage 的 group/attribute + 读那张裁剪表 + 在预览里叠图层；
>    同时保持工具的通用性（要适配所有用 Ren'Py、用资源分离方式编排演出的用户）
> 2. 真实项目有个问题：代码这边改立绘的动作，为了能让同一个角色有多套立绘，
>    真实项目自定义了结构，工具跟不上：从 B 改到 A 的时候是要先隐藏 B 才行的，
>    不然改动作/服装无效……好像原因是因为 A 动作是无编号，导致 B 改 A 相当于
>    只检测到表情没检测到动作。例子：`"ye": ["", "base_handdown", "base_swimsuit"]`，

>    而 show 只会叠加/替换属性，永远不会清空没提到的属性。所以 `show ye care` 的
>    真实含义是"表情改成 care，其它保持不变"。综上，我希望你能够在保持工具通用性的
>    情况下，最大可能考虑到这种自定义编排立绘和演出的情况。
>
> 先写一个设计方案，后根据这个设计方案执行代码的修改。

## 2. 真实项目实测（设计的事实基础）

来源：`D:\千连万理\RenpyTest\sr_general`（只读）。

### 2.1 声明形态

`game/definitions.rpy:601`：

```renpy
layeredimage ye:
    image_format 'images/characters/ye/{image}.png'

    # 没有服装 → 全身表情
    group expressions when not base_handdown and not base_swimsuit:
        attribute happy default:
            'happy'                       # 整图

    # base_handdown：手放下来姿势
    group expressions when base_handdown:
        attribute happy default:
            ye_clip_expr('happy', '_hd_cut.png')      # 只有面部

    # 身体件（带 alpha 裁剪）
    group outfit when base_handdown:
        attribute base_handdown:
            ye_clip_outfit('base_handdown.png', '_hd_keep.png')
```

`game/definitions.rpy:431`（`init -1 python` 里的辅助函数）：

```renpy
def ling_clip_expr(expr):
    return AlphaMask(
        "images/characters/ling/" + expr + ".png",
        "images/characters/ling/" + "_ss_cut.png"
    )
```

**结论**：分离方式是 Ren'Py **标准 displayable** `AlphaMask(图, 蒙版)` ——
`AlphaMask` 只读蒙版的 **alpha 通道**（项目注释里写得很清楚：
`_hd_cut` 面部 alpha=255、身体 alpha=0；`_hd_keep` 反之）。
所以"读那张裁剪表" = **解析这些 displayable 表达式**，不需要读像素表。

### 2.2 关于"无头"的**更正**（我一开始量错了）

我最初的判断是"`ye/base_handdown.png` 只有身体没有头"，依据是"头部区
非黑像素 10935 vs 37152"。**那个量法是错的**：项目的图是
"**白底 + alpha**"（见 `definitions.rpy:733` 的注释），`convert('L')`
会把白底也算成"有内容"，所以那个数字量的是**背景**，不是人物。

把四张图直接**看图**（缩到 220×391、垫深色底）之后的事实是：

| 文件 | 实际内容 |
|---|---|
| `ye/happy.png` | 完整立绘（抬手、闭眼） |
| `ye/base_handdown.png` | **也是完整立绘**（手放下、另一套姿势的默认表情） |
| `ye/_hd_cut.png` | 蒙版：**白 = 保留面部**（身体透明） |
| `ye/_hd_keep.png` | 蒙版：**白 = 保留身体**（面部透明） |

所以"无头骑士"的真相不是"某张图没有头"，而是**工具没有按项目的
layeredimage 去合成**：它只挑了**一张**图（身体件 / 蒙版 / 或错的组合），
于是画面上要么少了头、要么表情/姿势对不上。
`AlphaMask` 的语义因此是**必须实现**的那一环：只把蒙版 alpha>0 的像素留下。

**验证方式也改了**：不再用"像素统计"当判据（那种代理指标被白底骗过），
而是把合成结果与源图**并排渲染出来看**（见 9 节 P2 的验收）。

## 3. 通用模型

### 3.1 layeredimage 声明

```
layeredimage <tag>:
    image_format '...{image}...'
    always:                      # 永远叠加的层（可选，可多条）
        <displayable>
    attribute <name> [default] [<position>] [<displayable…>]
    group <gname> [auto] [variant <expr>] [when <expr>] [if_any <attrs>] [if_all <attrs>]:
        attribute <name> [default] [<displayable…>]
```

数据结构：

```python
@dataclass
class LayerAttr:
    name: str
    group: str            # '' = 不属于任何 group（全局属性）
    default: bool
    exprs: list[str]      # 该 attribute 的 displayable 表达式（多行=多层）

@dataclass
class LayerGroup:
    name: str
    condition: str        # when/if_any/if_all 归一化后的布尔表达式（''=永远成立）
    attrs: dict[str, LayerAttr]

@dataclass
class LayeredImage:
    tag: str
    image_format: str
    always: list[str]
    groups: list[LayerGroup]      # **顺序 = 叠放顺序（后面的在上）**

@dataclass
class LayerModel:
    images: dict[str, LayeredImage]
    helpers: dict[str, str]       # 项目里的辅助函数名 -> 函数体（用于展开）
    poses: dict[str, list[str]]   # tag -> 姿势循环表（含 ''）
    pose_labels: dict[str, str]   # 姿势值 -> 人话标签（'普通'）
```

### 3.2 displayable 表达式子集（要支持的标准写法）

| 写法 | 语义 | 我们的处理 |
|---|---|---|
| `'happy'` / `"a.png"` | 单图（配合 `image_format`） | 一层，`{image}` 替换 |
| `AlphaMask(img, mask)` | 取 `img` 中 `mask.alpha>0` 的像素 | 两层 → `(path, mask_path, None)` |
| `Crop((x,y,w,h), img)` | 裁剪 | 一层 + `crop` |
| `Composite((w,h), (x,y), img, …)` / `LiveComposite(…)` | 按坐标叠 | 多层（带偏移，本版按**原尺寸直接叠**并保留顺序） |
| `Transform(img, …)` | 变换 | **降级**：取内层图，忽略变换（并在报告里说明） |
| 其它（`im.` / 变量 / f-string / 条件） | 认不出 | **降级**：该层跳过 + 记一条 `unresolved` |

展开算法：把项目里 `init python` 的函数体当"模板"，
对 `name(args…)` 做**参数代入 + 常量折叠**（只做字符串 `+`、字面量、元组），
再解析出上面那几种构造函数。**不执行项目代码**（安全：不 import、不 eval 用户逻辑）。
实在认不出 → 用 attribute 名按 `image_format` 回退（本版"完整立绘"那条路，见 6.2）。

### 3.3 条件求值

`when <expr>` 里只有属性名、`not` / `and` / `or` / 括号 / `True` / `False`。
求值 = "这个属性名在当前属性集合里吗"。
`if_any [a,b]` = `a or b`；`if_all [a,b]` = `a and b`。
认不出的表达式 → 该组**不参与**（并在报告里说明），绝不当成"成立"。

### 3.4 空姿势（本项目最关键的一条）

- 一个 tag 的**姿势维度** = 在 layeredimage 里那些"只出现在 `when` 条件里、
  自己不作为图片层出现"的属性（这里：`base_handdown` / `base_swimsuit` /
  `clothes2` / `hanfu_base`）；**空姿势** = 一个都不选。
- 也可以从项目的循环表（`CC_OUTFIT_CYCLE` 这类）**自动认出**：
  `{tag: [str, …]}` 且第一个元素是 `''`、键都是 layeredimage 的 tag →
  当作姿势维度；兄弟字典 `*_LABEL` 提供人话标签（`'' → '普通'`）。
  **不写死 `CC_OUTFIT_CYCLE` 这个名字**，只认这个**形状**。

## 4. 语义：`show` 是按组替换，永远不会清空

Ren'Py 语义（用户描述，与引擎文档一致）：

```
show ye care          # 表情组 := care；其它组（姿势/服装）保持不变
show ye base_handdown care   # 姿势组 := base_handdown；表情组 := care
hide ye
show ye care          # 回到"普通"姿势 + care 表情
```

**推论（工具必须建模）**：

1. 舞台状态里每个 tag 的属性是**按组累积**的，不是"最后一次 show 覆盖一切"。
   现在的 `Beat.show` 是一整串属性、状态推进是"整串替换" —— 这在
   `layeredimage` 项目里会**与游戏不一致**（游戏保留没提到的组）。
2. **回到空姿势**（`''`/普通）在 `show` 语法里**表达不出来** → 必须
   `hide <tag>` 再 `show`。工具需要：
   - **校验**：检测"上一拍是 B 姿势、这一拍想变回普通、但没有 `hide`" → 报警告
     （附人话解释 + 一键修法）；
   - **导出/补丁**：在需要时自动补一行 `hide <tag>`（默认**不自动写**，
     先只警告；给出开关，见 5.4）。
3. 预览的状态推进要**按组**推进，才能忠实反映"B 没被清掉"这个事实
   （这样用户在预览里就能看见"你想要的普通姿势没生效"）。

## 11. 自定义结构怎么适配（用户 2026-10-05 追加要求）

> 实际上真实项目内会有更多的这种自定义立绘需要编辑，你需要从一个通用工具的
> 视角考虑问题……若是程序自定义了一个结构，而编剧用这个编辑器编辑时发现：
> 你没有适应到它的自定义结构怎么办？他会立即退出，因为工具没有用！
> 你现在这个编辑器实际上只支持标准的 rpy 语法，但很多时候结构是有人自定义的，
> 工具必须能够适应！

这条要求把设计从"支持 layeredimage"提升为"**支持项目自己的约定**"。
三层机制，缺一不可：

### 11.1 第一层：**认形状**（能猜就猜）

不认变量名/角色名，只认**结构形状**。已有的例子：

| 约定 | 形状 | 现状 |
|---|---|---|
| 合成立绘 | `layeredimage <tag>:` + group/`.when` | ✓ P1 |
| 分离贴图 | `AlphaMask(图, 蒙版)` / `Crop` / `Composite` | ✓ P1 |
| 姿势循环 | `{tag: ['', …]}`（键是 layeredimage tag，列表里有空串） | ✓ P3 |
| 姿势人话标签 | `{姿势值: '中文'}` | ✓ P3 |
| 资源路径基准 | `Path` 能对到磁盘（多基准逐个试） | ✓ 既有 |

### 11.2 第二层：**让它自己声明**（猜不到就写下来）

新增项目级清单文件 `storygraph.rules.json`（放项目根或 `game/` 下，
**声明覆盖自动识别**）：

```json
{
  "version": 1,
  "poses": {"ye": ["", "base_handdown", "base_swimsuit"]},
  "pose_labels": {"": "普通", "base_handdown": "手放下"},
  "hide_before_pose_switch": true,
  "path_bases": ["game/", "assets/"],
  "notes": "本项目的自定义约定"
}
```

- 编剧/程序**不用改代码**就能把工具"教"会自己的结构；
- 认不出的结构可以在 `notes` 里写清，工具会把它抄进体检报告；
- 缺这个文件时**一切照旧**（自动识别 + 老行为）。

### 11.3 第三层：**不认识就明说，别乱改**

新增**覆盖度报告**（`iter_unknown_statements()`）：扫全项目 `.rpy` 的语句头，
列出工具**不认识的语句头** + 出现次数 + 例子。

- 出现在「📦 资源体检」报告里（新增一段：**本项目的自定义结构**）；
- 语义是承诺："这些我**原样保留**，但**不会替你编辑**" —— 而不是
  "假装懂、然后写坏"；
- 编剧看到"哪一块工具管不了"，可以决定：① 写进 `storygraph.rules.json`
  教它；② 用工具的"第三类内容"通道（`default` / `init python` / 自定义语句
  一律原样保留）继续手工维护。

### 11.4 P4 = 这条机制的第一个使用者

"改回空姿势要先 `hide`"不是硬编码规则，而是：

1. **认**：姿势表形状（或清单里的 `poses`）+ "空姿势无名"这个事实；
2. **声明**：清单里 `hide_before_pose_switch: true` 才**自动补**（默认关）；
3. **报告**：无论开关如何，预览/体检都会说出"这一拍要先 `hide`"；
4. **写回**：补的 `hide` 走**生成内容**那条路（`render_beats_to_rpy` 的
   `pose_hides`），因此照旧经过增量补丁的校验 + 备份，**不手工改源文件**。
