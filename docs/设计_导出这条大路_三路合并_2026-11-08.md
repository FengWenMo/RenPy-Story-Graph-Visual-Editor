# 导出这条大路：别人也改过这个脚本（三路合并）

> 2026-11-08 · 第十五轮。上一轮（第十四轮）给**原地小改**那八个家族接上了
> `write_gate.commit_text`：能合就合、撞了就拒。这一轮轮到**导出**——
> 也就是"改一句台词 → 导出"这条每天都在走的大路。
>
> 结论先给：**这条路今天的问题不是"拒写"，是"静默把别人改的那一行改回去"。**

## 一、先量（探针 `probe_r15_export_drift.py`）

最小项目，一个 `label` 三句台词。我在编辑器里改**第 2 句**（整卡重写：说话人 + 正文），
然后让"别人"在文件里动一笔，再导出：

| 别人改在哪 | 指纹发现了吗 | 导出 | 文件动了 | 我的改动落地 | **他那一行还在吗** |
|---|---|---|---|---|---|
| 谁也没改（对照） | — | ok | 是 | 是 | — |
| 文件开头加一行注释 | 是 | **拒** | 否 | 否 | 在（没写） |
| 末尾加一句台词 | 是 | **拒** | 否 | 否 | 在（没写） |
| label 后插一句 | 是 | **拒** | 否 | 否 | 在（没写） |
| **改了我没动的那一拍（第 1 句）** | 是 | **ok** | 是 | 是 | **没了** |
| **改的正是我在改的那一拍（第 2 句）** | 是 | **ok** | 是 | 是 | **没了** |

最后两行是这一轮的起点：**补丁报"对位 3/3 拍，改动 N 行"，回执照样说成功，
而别人的那一句被改回了原样。** 不是拒写，是**静默吞掉**。

它比拒写严重的地方在于：拒写会让人再试一次；吞掉没人会发现——
直到那个写台词的人说"我明明改了"。

## 二、为什么会这样

三条机制叠在一起，正好留出一个洞：

1. **`trust_ranges` 只看一个布尔**：`_patch_note` 用
   `source_unchanged()`（磁盘内容 == 载入时那份）决定要不要相信拍上的行号。
   文件一变 → 一律不信行号 → 每一拍都得靠**内容证据**认行。
2. **内容证据在"改台词"这件事上本来就没了**：用户改的正是那一拍的正文
   （以及常常还有说话人），拿新正文去原文里找，当然找不到。
3. **于是退回"靠说话人认行"**：`_range_looks_like` 里有一条
   "说话人在这一段里就算这一拍"——`e "换成别的说法甲"` 里有 `e`，
   于是**别人的那一行被判成我的那一拍**，`_replace_matched` 按句位配对，
   顺手把它改回我的版本。`changed_lines=2`、`ok=True`。

而"表过期守卫"（`_patch_step_locate`）只在他**加了新行**时才响
（判据是"源里有台词不在表里 + 表里有句子在源里找不到"，两件事同时成立）——
他改的是一行换一行，行数没变，守卫不响。

**所以这不是"保守点好"的问题：判据本身缺一个东西 —— 底稿。**

## 三、做法：底稿、三路、两张嘴

### 3.1 底稿（baseline）

`load()` 解析完顺手把**解析时那一份文本**留在会话里（`_source_baseline_text`，
LF、已剥 BOM —— 与 `source_style.read_text` 同一个形态）。

**为什么必须留文本，而不是只留指纹**：指纹只能回答"盘上还是不是那一份"，
回答不了"**我**动了哪几行"。而"谁动了哪几行"正是三路合并的输入。
一份章节 15～60 KB，多留一份的代价可以忽略。

另一样东西**不**用留：字节级指纹已经有了（`_source_fingerprint`），
它管"盘上变了没有"；底稿管"我这一刀从哪来"。

### 3.2 把补丁打在**底稿**上，而不是打在盘上

文件被外人动过时，今天是把补丁打在**现在这份盘上的文件**上 —— 可拍上的行号
是**底稿**的行号。两者本来就对不上，于是只能靠猜（第一节那两条）。

改成：**打在底稿上**。这样 `trust_ranges` 的前提从"磁盘没动过"变成
"**我拿来当底稿的那份文本没动过**"——后者是我们自己手里的字节，
不是别人的文件，可以逐字节核对。

落在代码上是 `patch_export(..., base_text=…)`：

* 第 ② 步读源 → 用 `base_text`（不再读盘）；
* 第 ③ 步"给没行号的拍找行号 / 数被删的拍" → `recover_source_ranges(..., source_text=…)`
  也解析**底稿**。这一处必须一起改：它数出来的 `dropped` 会进删除通道，
  拿现在这份盘去数，就会按**别人的行号**删行（当年"整体下移 1 行、259 行被改写"
  那次事故的形态）。

⚠ **默认值 `''` = 照旧读盘**：表格那条路（拍上本来没有行号、行号是现算的）
不受影响，一个字都不变。

### 3.3 合：三路

`res.text` = 底稿 + **我**的改动（逐行配对改出来的，铁律 1 不变）。
盘上那份 = 底稿 + **他**的改动。于是：

```
merge_three_way(base=底稿, disk=盘上, ours=res.text)
```

`write_gate` 里已经有这个算法（第十四轮的 `merge_text` / `Kept` / `clash`），
这一轮只把它提成**公开的纯判定** `merge_three_way()`，与 `commit_text` 共用一份：

| 盘上是 | 结局 | 写法 |
|---|---|---|
| 我这份（合并出来了，但他没动） | `same` | **不写** |
| 底稿（他其实没动，只是刚才探针骗了我们） | `wrote` | 照补丁写 |
| 底稿 + 他的改动，且与我不重叠 | `merged` | 写合并结果，`kept` 说清保住了他哪几处 |
| 撞在同一处 | `conflict` | **一个字不写**，`clash` 指出第几行 → 翻成"第几张卡" |

### 3.4 两张嘴（沿用第十四轮的规矩，不新发明）

* **短句进状态栏 / Toast**（≤40 字，`wordWrap=False`，长了会被裁）：
  「别人也改过这个脚本（不是同一处）：两边都落上了，他改的 1 处也保住了」
* **长句进告警**（窗口日志的"提示"段 + 剧本表导出的"提醒"列表）：
  「他在第 3 行加了 1 行「…」。那几处已经写进磁盘，界面要重新载入这一章才看得到。」
* **撞了就拒**，理由要说**人话**，而且要点到**哪一张卡**：
  「你在改的第 2 张卡（第 4 行）那几行，别人也改过 —— 两边改的是同一处，
   这次一个字节都没写。」

## 四、边界（哪些**不**合）

1. **重叠的一律不合**：`merge_text` 的判据没变（插入算一个点，落在别人的替换段里
   也算撞）。宁可让人二选一，也不猜顺序。
2. **相邻的也拒**（他插的那一行正好贴着我改的那一行）。这是第十四轮定的，
   **本文档初稿写反了**（写成"相邻必须能合"）—— 地狱测试
   `TestAdjacent::test_adjacent_insert_is_refused_and_says_so` 把它钉回来了。
   为什么仍然拒：插入点落在替换段的端点上时，"他这行是加在我这行前面还是后面"
   在**行级坐标**里分不出来（第十四轮：宁可二选一，不猜顺序）。代价是最常见的
   一种协作形态（他在你改的那句旁边加个注释）落不了地。
   ⚠ 措辞必须分开：这种拒**不是**"改到了同一处"（见 §四·六 第 3 条）。
3. **缩进结构看不见**：逐行合并不知道"他插的是一行 `if cond:` 头"。
   这种合并可能合出语法坏的文件。兜底**不是**我新写的检查，而是**已有的引擎闸门**：
   `write_generation(engine_lint=True)` 会拦住"产物引擎读不了"的那一刀，
   留 `.blocked.rpy` 给人对照。判据见
   `tests/test_hell_export_merge.py::TestFailsSafe::test_his_broken_syntax_is_refused_and_the_file_stays_his`。
4. **底稿没有时（老会话 / 手工塞 beats / 表格那条路）→ 照旧保守拒绝**。
   没有底稿就没有"谁动了哪几行"，那就还是"不猜"。

## 四·五、写判据时撞出来的三件事（都记在这儿，免得下次再撞）

### 1. G1 已知缺口：同一拍"旁白 → 台词 **+ 顺手加一张 show**"今天仍然做不到

写"内容证据全没了也要能落地"那条判据时撞上的，**与这一轮无关**：

```
label a:
    "旁白第一句"          ← 我：改成台词（e），并且顺手给她加一张立绘
```

补丁报 `1 条生成内容在补丁结果里找不到（例：'show ling happy at d11'）`，
**没有外部改动、没有底稿时也一样**（`.pip-tmp/dbg_r15_narration.py` 的 C 组）。
根因在 `_patch_walk_blocks` 的两条分支：

* 旁白被整句换掉时走 `_narration_slot_replaced`（邻居自洽），它**只做一对一替换**
  （`allow_edit=False`）—— 加不了行；
* 而 `trust_ranges` 那条能加行的分支在它**之后**，轮不到。

好消息是它**拒绝**，不是静默丢。修它在"拍匹配"那一层（要把一对一与增删的准入
重新排一遍），不属于这一轮。

### 2. 真正需要 `trust_ranges` 的是"**连说话人都换了**"

同一个探针（H / I 两组）量出来的：

| 我改了什么 | trust 开 | trust 关 |
|---|---|---|
| 只换正文（说话人不变） | 落地 | 落地（守卫靠说话人认得出） |
| 旁白 → 台词（一对一） | 落地 | 落地（`_narration_slot_replaced` 兜着） |
| **`e` → `jc` + 换词** | 落地 | **`对位率不足（1/2 = 50%）`** 整份拒绝 |
| 旁白 → 台词 **+ 加 show** | 拒绝 | 拒绝（见 G1） |

所以判据写成"换说话人 + 换词"那一条 —— 先前写成"旁白 → 台词"时，
"底稿补丁不开 trust"这个变异**活下来了**（变异测试第 7 条），是它把我逼到这里的。

### 3. 一个真 bug：补丁**没用上**时也会走合并

第一版把 `_settle_with_disk` 接在 `_patch_note` 后面**无条件**调用。
补丁失败时 `text` 还是 `result.rpy_text`（**全量重生成**，只认得"拍"），
拿它去合并 = 把全量写进用户文件（P0 那条要拦的形态），而且还会把真正的拒因
（"某句生成内容找不到"）盖成一句"撞在同一处"。

判据当场抓到（`test_a_speaker_swap_...` 一开始报的是假原因）。
现在合并只在 `note['used_patch']` 为真时进 —— 一行 `if`，但它守的是 P0。

## 四·六、地狱测试（`tests/test_hell_export_merge.py`，23 条）抓到的三件事

功能判据（16 条）证明"正常配合下它对"。地狱那一轮问的是另一类问题：
**在脏数据上、在第二次、在看不见的字符上、在他把文件改坏之后，会不会弄坏用户的文件。**
抓到三条，都修在这一轮：

### 1. `write_gate` 用 `str.splitlines()` 切行 → **静默把一行撕成两行**

一行中间的 U+2028（从 Word / 网页粘台词常带）会被 `splitlines()` 当换行切开，
`'\n'.join()` 再拼回去 —— `"你好␨世界"` 变成两行 `"你好` + `世界"`，
台词没结上引号。而回执是 **`ok=True`**：静默写坏，只有打开游戏才会发现。

实测（`.pip-tmp/evidence_u2028.py`）：

| | 合并结果 | 重新解析 |
|---|---|---|
| 旧（`splitlines`） | `    e "你好` / `世界"` 两行 | **1 拍，正文空** |
| 新（`split_lines`） | `    e "你好␨世界"` 一行 | 2 拍，正文原样 |

`patcher` 早就只用 `core.textlines.split_lines`（只认 `\n`），
`write_gate`（第十四轮）和 `generation_guard`（更早）是**漏网的两处**。
判据：`test_a_line_with_an_invisible_separator_stays_one_line`（三种字符）
+ `test_no_splitlines_in_the_merge_chain`（AST 扫源码，防止改回去）。

### 2. 同一个坑的**另一种后果**：`OPAQUE_LOST` 假拒写

`generation_guard.top_level_chunks` 也拿 `splitlines()` 切：那半截 `世界"`
看着像一条**顶层语句**（行首没缩进），于是"产物里少了顶层语句" → 拒写。
补丁明明是对的，用户却被告知"你给的那份底稿没能和表对上"。

修法同样是换成 `split_lines`（连带把那一组"逐行播报行号"的地方一起换，
否则 U+2028 之后所有报出来的行号都是错的）。

### 3. 措辞：**紧挨着 ≠ 同一处**

他在你改的那一行**旁边**加一行 → 拒写（判据没变，见 §四 第 2 条），
但消息说"别人也改过，而且改的正是同一处"。用户会去找"他什么时候改了我这句"，
找不到 —— 然后就不信这个提示了。

`_clash_kind()` 现在把两种分开（`overlap` / `touching`），两种都拒，说法不同。
判据：`test_adjacent_insert_is_refused_and_says_so`（上下两侧各一条），
以及 `test_hell_export_merge.py` 里那条"给用户的那句话必须是一行"
（台词里带换行时不许漏进提示 —— 顺手在 `card_at_lines` 里压平了空白）。

### 还量了这些性质（都过了，判据留着防回归）

| 性质 | 判据 |
|---|---|
| 合过之后再导一次：不写、不多留一代旧版本 | `TestIdempotent` |
| 他再改一笔还能再合（不是"一次就不灵"） | 同上 |
| 拒绝时文件**逐字节**不变 | `TestByteForByte` |
| CRLF / BOM / 末尾无换行 / 混合换行：没碰过的字节一个不动 | 同上 |
| 他删掉的一行不许被**复活** | `TestAdjacent` |
| 源被删 / 只读 / 他改坏语法：不崩、不写 | `TestFailsSafe` |
| 2000 拍 + 他两处远处改动：三处都对、< 30s | `TestScale`（实测 1.9s） |
| 200 组随机不重叠改动的**对称性**（左右交换结果不变） | `TestRandomDisjointEdits` |


## 四·七、地狱测试第二轮（`tests/test_hell_merge_structure.py`，22 条）

上一轮问的是"会不会弄坏他的字节"。这一轮换一个角度问：
**合出来的那份，到底能不能启动？** 行级合并只认行、不认缩进，所以两边
**各自合法、又确实不重叠**的改动，合起来可以是坏的 —— 三种，都修了。

### 1. 你的改动会被挪进别的块里（最严重）

他删掉 `    menu:` 那一行、我改了菜单项：两段不重叠（差 3 行），行级合并
**成功**，产物是

```
label a:
        "改过的左边":          ← 8 个空格，上面没有块头
            e "左边"
```

一个**两边谁都没写过**的文件：Ren'Py 一启动就报缩进错，而回执是 `ok=True`、
"两边都落上了"。`renpy_parser` 也拦不住（它是宽松的逐行解析，实测 0 个 error），
`evaluate_generation` 同理（只报 `OUTSIDE_BUILD_DIR`）—— 没有 SDK 时，
**没有任何一道闸在看这件事**。

现在的判据（`write_gate._merge_plan`）：**我改的每一段，合完之后必须还嵌在
同一个父语句下面**。父语句 = 上方最近一条"缩进更浅"的语句（`_parent_at`），
空行与整行注释不构成块。父语句被删掉 → 拒写（`CLASH_REPARENTED`），
并指出是**哪一行**（`Commit.parent = (行号, 原文)`，那条会被 `error()` 引用）。

**不算**换父语句的两种情况（写进去就是误伤，判据反向钉住）：

| 他的改动 | 结论 |
|---|---|
| `menu:` → `menu 选项:`（同缩进、仍以冒号收尾） | 块还在，**照合** |
| 删掉块头上面的一行注释 / 一个空行 | 不是块，**照合** |
| 改同一块里的**别的**选项（同缩进） | 父语句没变，**照合** |
| 在块**外面**加一句 | 父语句没变，**照合** |

已知**不拦**的一种（另一半记在这里，别以为关死了）：他把 `if b:` 删掉、
我的那几行正好接在 `if a:` 的块尾 —— 层级没变、父语句也只是"换了一个同龄
的块头"，这一条判据看不出来。要真拦住得做完整的块树对位，那是拍级合并那件事。

### 2. 合起来会变成空文件

两边各删一半（他删上半、我删下半）→ 合并结果**空文件**。而 `''` 同时是
"空结果"和"合不了"的哨兵，于是拒写、理由却说"撞在同一处"（假话）。
现在单独判 `CLASH_ERASED`，`Commit.error()` / `sentence()` /
`_merge_conflict_reason` 三处各说各的实话。

### 3. 文件末尾那个换行归"收尾那一行"

基线末尾没有换行、他往文件末尾追加一行（**带**换行）时，从前一律按基线的
结尾拼 → 他那行的 `\n` 被吞掉，`git diff` 报 `\ No newline at end of file`。
现在按"最后一段来自哪一侧"取那一侧的结尾。

### 判据与量

* 22 条：拒写 + 逐字节不变（4）、**误伤方向**（4）、空文件（2）、末尾换行（4）、
  随机对照（600 组唯一行 + 200 组重复行 + 200 组"拒因必须说真话"）、
  "判定只有一处"（AST + 行为）、2 万行 × 时间上限。
* 变异 `mutation_r16.py` **9/9**（含三条**误伤**方向：块头改名照合、
  删注释/空行照合）。
* 判据 22 条；相关套件（合并 / 导出 / 原地小改）**169 条**全过；
  全量 **10365 / 10369 passed / 0 failed**（12 进程 6m33s）。

## 四·八、地狱测试第三轮：**谁先导出，决定这份文件坏不坏**（第十七轮）

上一轮那道闸只问"**我**改的那几行还挂在同一个块里吗"。可"合出来那份能不能
启动"是**文件**的性质，不是我这半边的性质 —— 拿上一轮那个例子量两个方向：

| 方向 | 盘上是 | 我这一版 | 第十六轮修完 | 第十七轮修完 |
|---|---|---|---|---|
| A | 他删了 `menu:` 那一行 | 我改菜单项 | 拒写 | 拒写 |
| B | 我改的菜单项 | **我**删了 `menu:` | **合上了**，写出 8 个空格悬空的选项 | 拒写 |

同一个剧本、同两个人，**谁先导出**决定这份文件坏不坏。探针
`.pip-tmp/probe_r17_symmetry.py`（A 方向 `CLASH_REPARENTED`、B 方向原来是
`ok=True`；修完 B 方向 `CLASH_REPARENTED_OTHER`，点到的还是基线第 4 行
`    menu:`）。

### 1. 做法：两边改过的行都查，父语句的身份按**基线坐标**算

每一行合完之后，必须还挂在**它自己那一份**里的同一个父语句下面：

* 父语句 = 上方最近一条"缩进更浅"的语句（空行 / 整行注释不算）。
  `_parents()` 用一次扫描（单调栈）算出全文每一行的父语句 —— 不是"每行往回
  扫"，2 万行那条时间判据还在（`TestScale`）。
* "同一个" = **基线里的同一条语句**：`_home_of()` 把两边各自的坐标映回基线
  （照抄的行 1 对 1；改/加出来的行落到那一段的段首）。于是"块头只是换了个
  写法"（`menu:` → `menu 选项:`）**自然**算同一条，不用再猜"是不是以冒号
  收尾、缩进一样吗" —— 上一轮那个按形状的豁免条款被这一条取代了。
* 两种原因分开说：`CLASH_REPARENTED`（你的几行会被挪，第十六轮）/
  `CLASH_REPARENTED_OTHER`（他那几行会被挪，第十七轮）。措辞三处各说各的
  实话：`Commit.error()`、`Commit.sentence()`、导出那条路的
  `_merge_conflict_reason()`（**这一处最容易漏**：漏了就会看到兜底那句
  "别人也改过，而且改的正是同一处"—— 两边根本没碰同一行）。

### 2. 顺带补上"末尾换行"的另一半

第十六轮把末尾换行归给"收尾那一行"，但"收尾那一行谁都没动"时只看**盘上**
那份的结尾 —— 于是又变成"取决于谁是盘上"。实测：

    base  = 'a\nb'      （末尾没有换行）
    mine  = 'A\nb'      （我改第 1 行）
    his   = 'a\nb\n'    （他只在末尾加了换行；行 diff 看不见）

一个方向得 `'A\nb\n'`、另一个方向得 `'A\nb'`（他那边的换行被吞）。现在按
"**谁改了文件末尾**"定：盘上那份和基线不一样就听盘上的，否则听我这边的。

### 4. 已知**不拦**：谁都没动过的那几行（记在这儿，别以为关死了）

**两边都没碰过**的基线行不在检查范围里（见 `write_gate._orphan` 的说明）。
一个块头被**删掉**、块里其余的行两边都没动时，合并会把它们留在原处：

```

            "A":          ← 12 个空格，上面没有块头
                e "x 改"   ← 我改的那一句

                e "y"
        e "收尾"
```

正当改动），以及剩下的行归谁 —— 那就是**块树对位**，也是拍级合并那件事
（§六）。这里记一笔，不假装关死。

## 五、`test_1d` 那条判据：意图没变，判法变了



`tests/test_export_acceptance.py::test_1d`：
「文件被外部改过之后，同一刀必须拒绝」。

它的**意图**是"不许按旧行号覆盖别人的行"，这一轮不放弃这个意图 ——
恰恰相反：今天那两条**静默覆盖**的场景（第一节表格最后两行）说明
"一律拒绝"根本没守住这个意图，它只是守住了"三个场景里的一个"。

所以 1d 拆成两条：

* **1d**（改在别处）→ **能合上**：他那一行逐字还在，我改的那一拍也落地；
* **1e**（撞在同一处）→ **仍然拒绝**，文件逐字节不变。

新增的守卫保证"一律拒绝"不会悄悄回来：
`tests/test_export_three_way.py` 里那条"外部改在别处却被拒"的用例，
以及 patcher 那一层的等价性用例（`base_text=盘上内容` 与不传必须**逐字节相同**）。

还有一条**别的文件里的判据被放宽了**（说清楚，别让它看着像偷偷改判据）：

`tests/test_p0_round5_carrier.py::test_dropped_lines_are_either_refused_or_named`
原来只认两种结局（拒绝 / 点名说删了哪几行）。现在多出第三种：**合上了**。
那两行（`$ flag = True` / `play music …`）在第三种结局里**根本没被删** ——
比"点名"更强，所以判据写成"盘上还在"，而不是"说了没有"。
