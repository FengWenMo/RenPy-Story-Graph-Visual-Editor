## 一、折叠状态跟项目走

### 1.1 以前为什么不跟（以及它错在哪）

第六阶段的实现是：**偏好**（`QSettings` 注册表）里存
`cards/folded_labels = {绝对路径: [label, …]}`，最多记 24 个文件。

理由当时写的是"折叠是这一台机器上这一份文件的临时视图"。但真实使用里
这句话不成立：

- 把项目目录**搬到别处**（改个名、从 D 盘到 E 盘）→ 绝对路径变了 → 全展开；
- 换台机器 / 换个用户 → 全展开；
- 团队里两个人看同一份项目 → 各折各的（这条其实无所谓，但"跟项目走"之后
  至少**一个人换机器**不丢）。

用户要的是："这是**这个项目的这一章**的样子，不是我这台机器的样子。"

### 1.2 现在存哪

**项目根**的 `storygraph.session.json`，新开一段 `cards`：

```json
{
  "layout": { "page": 1, "card_index": 3, "geometry": [1600, 950, 200, 120] },
  "cards": {
    "folded": {
      "game/script/ch01.rpy": ["ch01_roof"],
      "game/script/ch02.rpy": []
    }
  }
}
```

- 键是**项目内相对路径**（正斜杠）：项目整目录搬走仍然对得上；
- `[]` 与**没有这个键**是两件事（见 1.4）；
- 这份文件本来是"可选的项目级布局"（第五阶段定的，工具**只读不写**）。
  这一轮**破例**：`cards` 段归工具写，`layout` 段仍然只读。

破例的三条约束（都写进 `core/session_store.py` 的模块文档）：

1. **读-改-写**：整份读出来、只替换 `cards.folded` 里的那一个键再写回；
   `layout` / 用户手写的注释性字段一字不动（判据里钉着 `note` 字段）；
2. **原子替换**（`*.tmp` + `os.replace`）：写一半断电不会留下半截 JSON；
3. **失败不拦人**：项目目录只读 / 文件被锁 → 返回 `ok=False` + 原因，
   调用方退回用户偏好，界面继续用当前状态（控制台说一句，不弹窗）。
   另加一条：**读不懂的那份不覆盖** —— 这份文件人也会手改（团队往里放
   `layout`），"解析失败就写回一个只有 `cards` 的新文件"等于删掉别人的内容；
   那种情况直接失败、退回偏好（判据里钉着：坏文件逐字节不变）。

### 1.3 为什么用相对路径，而不是"把绝对路径也存一份"

绝对路径在两个场景里**必然**失效（搬目录、换机器），而这两个场景正是
"跟项目走"要解决的。多存一份绝对路径只会多一个**冲突源**：项目里那份
说 `side_b` 折着、注册表里那份说开着，谁赢都不对。

所以规则是**单一口径**：文件在项目根里面 → **只**认项目里那份；
不在项目里 / 没打开项目 → **只**认偏好。

### 1.4 迁移（换版本的人不该丢状态）

读的顺序：

```text
有项目 且 项目里已有这个文件的键   → 用它（不再看偏好，哪怕是空的）
有项目 但 项目里没有这个键        → 读旧偏好；有就写进项目、把旧条目删掉
没有项目 / 文件在项目外           → 只读偏好（与从前一致）
```

第一次迁移会在控制台留一行：

```text
[折叠] 这个文件的折叠状态已改记到项目里（storygraph.session.json 的 cards 段）
       —— 换台机器 / 把项目挪个目录都还认得
```

**展开**也要写：`_save_collapsed_pref` 在"都展开"时写的是 `[]`，不是删键。
删键会让下次打开误以为"从没折过"，于是又去翻旧偏好 —— 状态会来回跳。

### 1.5 不写盘的那些时候

- 翻页 / 展开一个本来就开着的组 / `_reload_list` 重建 → **不写**
  （判据用 mtime 钉住：只在 main_a 里翻三页，项目文件的 mtime 不变）；
- 键的内容没变 → `remember_cards` 自己判掉（`changed: False`）。

## 二、一个 `.rpy` 里多个 label：怎么用、图怎么排

### 2.1 先说结论：不需要任何特殊写法

Ren'Py 就是按文件从上往下执行的，"一个文件一个 label"不是约定：

```renpy
label ch01_start:          # 第 1 行
    e "……"
    jump ch01_choice       # 有自己的跳转就跳走

label ch01_choice:         # 第 5 行
    menu:
        "去屋顶":
            jump ch01_roof
```

工具这边的三步（`help_dialog` 的「剧情结构图」页里也这么写了）：

1. 「➕ 导入章节 .rpy」选这个文件**一次**（不是每个 label 导一次）：
   文件里每个 label 都成为图上一块，块上写着 `文件名:行号`；
2. 点某一块 → 双击 / 右栏「✎ 打开本章剧本」→ 卡片页落在**那个 label 的
   第一拍**（`load_script(label=…)`，不是文件第一拍）；左栏按 label 分组，
   点标题行折叠；
3. 「⤓ 导出 .rpy」写回**同一个文件**（整章；没动的地方走增量补丁）。

### 2.2 图以前为什么"不像文件"

导入只建 `label` 节点 + `jump` / `call` / 菜单边；排版 `layout_graph` 是
**分层布局**：入度为 0 的块在最左，按跳转逐层往右。它回答"谁跳到谁"，
**完全不看行号**。于是三个 label 里只有第一个有入边时，另外两个会被
甩到最左一列 —— 与文件里的先后无关。

`tests/test_feedback_p5_file_layout.py` 里最小复现的输入就是下面这个
（坐标是照它真跑出来的，间距 282 / 134 与画布一致）：

```text
文件：ch_a(第1行, jump ch_c) → ch_b(第5行) → ch_c(第9行)

按跳转排（layout_graph）：
    ch_a (0, -67)   ch_b (0, 67)        ch_c (282, 0)
    └─ 同一列里的上下顺序由"减交叉"决定，与行号无关；
       ch_c 被推到第二列，只因它有一条入边。

按文件排（layout_by_file）：
    ch_a (0, -134)  ch_b (0, 0)  ch_c (0, 134)
    └─ 一列、从上到下就是文件里的先后。
```

### 2.3 加的那一种排法

`graph/layout.py` 新增两个函数（纯数据、可单测）：

| 函数 | 作用 |
|---|---|
| `file_order_groups(graph)` | 按 `file_path` 分组、组内按 `line_number`；文件按路径排、无源文件的排最后 |
| `layout_by_file(graph, col_gap, row_gap)` | **一个文件一列**，列内 y 随行号递增，每列各自垂直居中；返回"第几列是哪个文件"的摘要 |

入口（两个都指向同一个方法 `window_graph_ops.arrange_by_file`）：

- 工具栏：「▤ 按文件顺序排列」（紧挨「⤢ 自动布局」）；
- 画布右键空白：「按文件顺序排列」。

排完会：控制台逐列念（`[排版] 第 1 列 ch01.rpy：ch_a、ch_b、ch_c`）、
状态栏一句话、**标脏**（坐标进了布局指纹 —— 不标的话关窗不会提示保存，
下次打开又是旧位置，用户会觉得"我明明排好了"）。

### 2.4 什么时候自动用哪一种

`GraphCanvas.set_graph` 在"有新块还没摆过"时排一次，按**来源**选路：

- 图上所有块**都来自同一个 `.rpy`** → 文件顺序（一个文件里多个 label 时，
  这才是"这一章的样子"）；控制台会说一句"这一批只有同一个 .rpy：按文件顺序排好了"；
- 跨文件 / 有手画的占位块（没有 `file_path`）→ 仍走按跳转分层
  （章与章之间靠 `jump` / `call` 相接，文件顺序在那里没有意义）。

⚠ 这是"**新块怎么摆**"的选择，不是"每次重建都重排"：只要每个块都有各自的
坐标，`set_graph` 一律保留（撤销 / 连线 / 改内容都不会把拖好的位置冲掉）。

### 2.5 顺延：图上看不见，但文件顺序看得见

一个 label 结尾**没有** `jump` / `return` 时，Ren'Py 会**接着执行文件里的
下一个 label**。图上的线只画**显式**跳转 / 调用，所以"顺延"画不出来 ——
它恰好是"按文件顺序排列"能看出来的东西（同一列相邻两块，中间没有线）。
这句话写进了使用说明，免得有人以为"没线 = 不会执行到"。

## 四、仍然不做 / 说明

- **项目文件只多写 `cards` 这一段**：`layout` 仍然只读（第五阶段的分工没变）。
  想固定一份团队布局，照样手工放 `storygraph.session.json`。
- **折叠状态不进 `storygraph_layout.json`**：那份是"图长什么样"（坐标 /
  连线），进不去卡片页的视图状态；混在一起会让"我只想挪一下窗口"变成
  "布局未保存"。
- **不按文件顺序自动重排老图**：只有"有新块还没摆过"时才自动排；
  已经摆好的图不会因为升级就在打开时被重排（用户拖过的位置更贵）。
- **不给"顺延"画线**：它没有对应的 `Statement`（不是一条 `jump`），
  画出来就得在模型里造假边 —— 那种边会被"重载删幽灵"清掉，或者被导出
  写成真的 `jump`。宁可不画，写在说明里。
- **`for` 仍不参与块选择器**（第七阶段的结论不变：引擎 lint 拒 label 顶层的 `for`）。
