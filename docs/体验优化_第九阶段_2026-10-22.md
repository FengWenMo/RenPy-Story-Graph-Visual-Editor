# 体验优化 · 第九阶段（把 `python:` 块里的赋值搬回脚本层）

> 依据：用户 2026-10-22 对这一刀方向的判断（原文）：
>
> > python块别介入内部，但有一件事方向相反、值得做
> > 真机那 26 条里 21 条是脚本层 `$` 就写得出来的赋值。它们待在 python 块里
> > 不只是"工具管不着"，而是有害的 —— 存档粒度是整块。
> >
> > 所以正确的方向不是"工具去适应 python 块"，是 "工具帮用户把语句从
> > python 块里搬出来"……
> > 介入内部 / 搬出来：服务对象 0.49% 的代码 vs 那 0.49% 里的 81%；
> > 对引擎 强化反模式 vs 修正反模式；工具变成 半个 IDE vs 仍然是演出编排器；
> > 能不能过 IR → Unity：不能（黑盒） vs 能（变成标量事件）。
> >
> > 不做局限性不大 —— 但前提是：你那些"不做"是边界声明，不是欠账。

这一阶段就做这一件事：**给用户一条从 `python:` 块里走出来的路**。

工具对块本身的态度**一个字没变**（K1/K6：读进来、原样保留、逐字节写回）；
变的是：块里那些本来就属于"脚本层演出的变量"的赋值，现在可以**一键搬出来**，
搬出来之后它们才进得了变量工作台、进得了 IR —— 这正是用户说的
"21 条如果留在块里，也跟着搬不过去"。

---

## 一、边界（先把它说死，免得被当成"工具开始拆块了"）

| | 这一阶段做了什么 | 没做什么 |
|---|---|---|
| `python:` 块 | 给一条**出口**：把简单赋值变成 `$` 行 | 不解析、不改写、不拆分调用/嵌套 |
| 判定 | 只认"原样挪到 `$` 语义不变"的行 | 不做"理解这段代码想干什么" |
| 触发 | 用户点「⤴ 搬出 python 块」并勾选 | 不自动改任何文件、不自动搬运 |
| 块里剩下的行 | 原位、逐字节不变 | 不重排、不重缩进、不加注释 |

一句话：**工具仍然只编排演出；它只是不再把"本来就是演出变量"的赋值关在块里。**

---

## 二、判定：哪些行能搬（`story/python_lift.py`）

`analyze_block(lines)` 是纯函数（不碰文件、不碰 Qt），只回答一个问题：
这一块里哪些行原样挪到 `$`、语义不变。**五条判据**，缺一不搬：

1. **块体顶层**（缩进等于块体基准）：`if` / `for` / `with` 体里的行不算 ——
   搬出去会丢掉嵌套结构（也会让块头没有块体，直接语法错）；
2. **单行语句**（`ast` 的 `end_lineno == lineno`）：续行 / 三引号串不搬，
   否则 `$` 只能跟第一行；
3. **简单赋值**：`name = …` / `name op= …`，目标是**一个普通变量名**。
   `persistent.x = …`、`对象.属性 = …`、`d[k] = …`、元组解包都不算剧情变量；
4. **名字不以 `_` 开头**（Ren'Py 私有约定；与 `story_ops.is_narrative_code`
   同一口径）；
5. **不能把块拆出"只有注释的块"**：`python:` 块里只有注释是语法错。
   所以夹在两条被搬语句中间的那条注释，会拦住**离它最近的一条**搬动
   （那一条留下陪注释）—— 只退一条，不白丢可搬的行。

> 为什么**不需要**依赖分析：搬出来的行留在**原来的行位置**上
> （块体前半 → `$` 行 → 块体后半），执行顺序一字不动。
> 顺序不变，就不存在"变量还没定义"的问题 —— 这也让"中间那条也能搬"
> 成立（块会被拆成两个 `python:` 块，两个都还有语句就合法）。

块体解析不了（作者写了非 Python 内容 / 半截代码）→ 整块不动，
原因原样报给用户（`WHY_PARSE`）。**绝不猜**。

### 2.1 真机上"搬不动"的是哪些（就是用户说的那 0.49%）

| 留在块里的东西 | 为什么 |
|---|---|
| 调用 / 控制流（`msg_add(...)`、`renpy.*`、`if` / `for`） | 它们是引擎侧的实现，工具不进去改 |
| 多行语句（续行、列表 / 字典字面量） | `$` 只能跟第一行 |
| 属性 / 下标 / 解包赋值、`persistent.*` | 不是剧情变量，也不该进表格 |
| 以下划线开头的变量 | 私有约定（与既有分类同一口径） |

minigame 那 9 个块仍然**整块**读进来、整块写回去 —— 这是正确方式，不是缺陷；
这一阶段只是不再让"本来能写成 `$` 的赋值"跟着它们一起被关在块里。

## 三、落地：三处一起改，少一处就是假动作

```text
python:                          $ route = "roof"
    route = "roof"               $ love += 2
    love += 2                    python:
    flag = True                      msg_add("x")
```

`Beat.code` **一个字符都不改**（行数没变，`ordered` / `op_order` /
`src_first..src_last` 全都不用动）；改的是：

1. **`Beat.code_blocks`**（导出真相）：把块区间按"留下的连续段"重写。
   渲染层按标记决定出 `python:` 还是 `$`（`beat_render_code.render_code_block`）；
2. **`Node.statements`**（工作台 / 分析 / 摘要的真相）：原来一条多行语句
   拆成"每条 `$` 一句"；新语句的 `source` 按"`python:` 头行 + 块内偏移"推算，
   变量工作台的「定位到这一拍」才对得上；
3. **撤销历史**：`LiftPythonStatementsCommand` 存**整份**语句表 + 逐拍快照。
   不复用 `UpdateNodeOperationsCommand` 的原因：它按代码字符串重建语句
   （`python_operation(text)`），`source` / `condition` 会丢 —— 搬完再改一次，
   行号全指错。

撤销 / 重做：节点与拍**一起退**（`restore_beat_states`，含第七阶段的
"旧快照守卫"：导出重载过、拍粒度变了就跳过那一拍，不硬还原）。

## 四、入口

- 右栏「⤴ 搬出 python 块…」，或右键模块 →「⤴ 搬出 python 块里的赋值…」；
- 对话框把这一章所有 `python:` 块列出来：**能搬的每行一个勾选框**，
  不能搬的置灰并写原因；下面实时预览"搬完之后是什么样"；
- 变量工作台里那段 `python:` 块旁边会提示"为什么这里只能整段改"以及去哪搬。

## 五、判据

`tests/test_python_lift.py`，**23 条**，分四层：

| 层 | 钉住什么 |
|---|---|
| 纯函数 | 纯赋值全搬 / 调用与嵌套留下 / 注释要一条语句陪（中间、开头、结尾三种）/ 多行不搬 / 属性·解包·下划线不搬 / 空行不碍事 / 语法错给原因 / 只有调用时没得搬 / 单行 `for` 不算赋值 |
| 报告 | 块 ↔ 拍 ↔ 图节点语句对上号（含"两个块被折叠进同一拍"）/ **只读**（不换会话的章节）/ 没源文件时说清 |
| 落地 | 编译文本真的变 `$` / 节点语句拆开且行号递增 / 只搬一条时块还在 / 条件块搬完仍在 `if` 里 / 撤销·重做两边一起动 / 导出文本再解析**同构** |
| 界面 | 按钮文案 / 走窗口那条路（含日志与 Ctrl+Z）/ 没有块时说"没有" / 说明与工作台都指向它 |

实现时被两条**真实数据**教育过，都写进了用例：

1. **同一拍里可能有两个 `python:` 块**（中间没有台词/演出时会被折叠进一拍，
   `code_blocks` 是 `[(1,4),(5,7)]`）—— 报告和落地都按区间逐块处理，
   不是"一拍一块"；
2. **两个块的文本可能一模一样** —— 落地时必须按顺序**配对**语句
   （`used_idx`），否则第二个块会抢走第一条语句、把前一个块的拆分覆盖掉。

## 六、仍然不做（边界，不是欠账）

- **不自动搬**：不扫描整个项目、不在导入/导出时顺手改。要搬是用户的决定
  （每一行都可能在"演出变量"和"引擎状态"之间，只有作者知道）。
- **不改块里的调用 / 控制流 / 嵌套**：那是引擎侧实现，工具只保证逐字节写回。
- **不反向合成**：不会把一串 `$` 又合成一个 `python:` 块（方向是单向的）。
- **不跨 label 报告**：现在按"点了哪个模块"看这一章；全项目扫描是候选，
  但要先想清楚"报告要不要动文件、要不要缓存"。
- **不改 `python:` 块的行文本**：搬出来的是"标记"，不是"重写"——
  这也是导出文本能再解析成同样文本的原因（判据里钉着）。
