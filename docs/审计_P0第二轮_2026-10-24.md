## 二、P0-4 ★ menu 吞掉台词与选项行（解析层丢行）

### 最小复现（3 行代码就能看见）

```rpy
label start:
    e "台词"
    menu:
        "选项一":
            e "1"
    return
```

### 实测

```
statements:
  kind='menu'   payload={'caption': '', 'extras': ['e "1"']}     ← 只有 1 条 extras
  kind='return'

beats（2 拍）:
  [0] kind='menu'  text='\x00menu'  raw='e "1"'
  [1] kind='flow'  raw='return'
```

`e "台词"` 和 `"选项一":` **在解析阶段就没了**（不是渲染丢、也不是补丁丢）。
全量渲染跟着缺内容：

```
compile.rpy_text →
    label start:
        menu:
            e "1"          ← 台词没了、选项没了
        return
```

### 为什么平时看不出来（这是它最阴的地方）

- 原地导出走**增量补丁**：补丁拿源文件原文 + 逐行对位，"改动 0 行"
  → 走零改动分支、连盘都不写 → 文件看起来一切正常；
- 一旦 **导出到新路径**（"另存为 / 导出给程序"）、**补丁失败 force**、
  **表格 → rpy 全量生成**、**多引擎导出** —— 就直接把丢掉的内容暴露出来。

### 根因方向

`storygraph/parsing/renpy_parser.py` 的 `menu` 语句分支：`payload['extras']`
只收了 `e "1"`，**menu 前面那条 say 被吃掉**，`"选项一":` 也没进 payload。
（对照：`menu` 前面**没有**台词时，`menu / 选项 / 选项体 / return` 四拍正常 ——
所以是"menu 前有内容"这条路上的合并/flush 把前面的拍吞了。）

### 修法方向

1. `renpy_parser`：menu 块**不得吸收**块外语句；`"选项":` 必须有自己的 statement
   （`menu_option`），选项体单独成块；
2. 顺手加守卫：`parse → beats` 后**正文行数必须守恒**（不许比源文件少）——
   这正是铁律 7（不许静默丢行），但现在没有任何测试在管"行数守恒"。

### 判据（建议）

```python
src = 'label start:\n    e "台词"\n    menu:\n        "选项一":\n            e "1"\n    return\n'
# 1) beats 数 = 4（say / menu / option+body / return）
# 2) render_beats_to_rpy 的正文行集合 == 源文件正文行集合（允许缩进变化）
# 3) 导出到新路径，产物与源文件逐字节相同
```

## 三、P0-5 · 改控制流目标 = 剧情多一次跳转

### 现场（UI 风格：`_flow_code_synced` 先同步代码格再提交）

原文：
```rpy
label start:
    call side from _call_side
```
把目标改成 `other_side` 后导出：
```rpy
label start:
    call other_side from _call_side
    call side from _call_side        ← 旧的没删
```
→ **先调用 other_side，回来再调用 side**，剧情跑两遍。
`jump` 同理（`+ jump third` / `jump other` 两条都在）。

### 根因（两处叠加）

1. `storygraph/app/session_table.py::apply` 的**写回顺序**：
   `update_beat_flow` 把新行写进 `raw` 之后，后面的 `CodeBlock` 分支又把
   `raw` 清空、降级成 `code`（因为显示值和新 raw 对不上）。
   UI 层用 `_flow_code_synced` 把 CodeBlock 一起改掉才绕开 —— **核心层没修**。
2. `storygraph/story/patcher.py::_rewrite_line`：控制流行落在 `('other', 原文)`
   上，"不是同一件事 → 不许换"（`_same_thing_unless_rewritten` 最后 `return False`）
   → 补丁**只插不删**（旧 call/jump 是 `_PROTECTED_RE` 保护行，不许删）。

### 修法方向

- `apply`：raw 真变了就把 CodeBlock 一起同步（把 UI 那条 `_flow_code_synced`
  **下沉到 `session_table.apply`**，前端只负责显示）；
- 补丁：`call/jump` 行允许"同类型换目标"（`_same_thing_unless_rewritten`
  加一支：`_line_key` 是 `('other','call …')` 且两边都是 call/jump → 放行）。

### 判据

改 `FlowTarget` → 导出后**只有一行** `call/jump`，且是新目标；
`call → jump` 类型改动同理（参数与 `from` 按 Ren'Py 语义清掉）。

## 四、P0-6 · API 路径改控制流：静默失效 + raw 降级

`EditorSession.apply(idx, session.fields(idx), advanced_open=True, …)` 之后：

```
内存 raw=''          ← raw 被清掉
渲染 → call side from _call_side   ← 还是旧的
导出 → ok=True，"文件没有被改动"
```

`session.fields(idx)` **恒含** `CodeBlock`（`beat_to_fields` 里有），而
`update_beat_flow` 先改 raw、CodeBlock 分支后清 raw —— 谁都可能踩：
CLI、脚本、表格导入、AI agent、测试。

修法与 P0-5 的第 1 条同源；判据：
`update_beat_flow` 之后 `parse_flow(beat)['target']` 必须等于新目标。

## 五、P0-7 · 移动一拍导出后顺序不变

```
内存顺序: ['二', '三', '一', 'return']
渲染逐拍: e "二" / e "三" / e "一"        ← 内存全对
导出: ok=True，"对位 4/4 拍，改动 0 行……文件没有被改动"
产物顺序: 一 / 二 / 三                    ← 还是旧顺序
```

### 根因

`patcher._recover_ranges_for_groups` 用 `_align_key`（label/kind/speaker/
condition/stage_tokens，**不含顺序语义**）做内容对齐：每一拍都能在源文件
里找到"同一个键"的行 → 全部 `equal` → "改动 0 行" → 零改动分支跳过写盘。

### 修法方向

对齐时如果**行号映射不是单调递增**（拍 i 的 src_first > 拍 j 的 src_first，
而 i < j），必须判"重排"，走重排通道（按新顺序重写这些行，或退回全量并明说）。
`graph/commands.py::MoveBeatCommand` 是真实调用方（模块编辑器里挪拍）。

### 判据

`move_beat(0, 2)` 后导出，文件里三句台词的顺序 == 内存顺序；
且 `ok=True` 时产物与内存渲染**逐行一致**（这是所有 P0 的总判据）。

## 六、P0-8 · SayTail / MenuName / Label 改了不落盘

| 改什么 | 内存 | `render_beat_to_rpy`（单拍） | `compile().rpy_text`（全量） | 导出 |
|---|---|---|---|---|
| `SayTail='(id="l1")'` | ✅ 有 | ✅ `e "台词" (id="l1")` | ❌ **连台词都缺**（P0-4 的连带） | 零 diff |
| `MenuName='my_menu'` | ✅ 有 | ✅ `menu my_menu:` | ❌ 只剩 `menu:`（选项行也丢） | 零 diff |
| `Label='new_name'` | ✅ 有 | —（label 不在单拍行里） | ⚠ `label new_name:` + **多出一个空的 `label start:` 块** | 零 diff |

### 根因方向（两处）

1. 全量渲染（`pipeline/compile.py:443 → render_beats_to_rpy`）与单拍渲染
   **不是同一套口径**：菜单结构、SayTail、label 分块在全量路径上处理不同；
2. `_rewrite_line` 的"保留原文"保护通道（`body == pick_body` / `_squash` /
   `_unescaped` / 行尾注释 / `_same_thing_unless_rewritten`）把**用户真的改了**
   的这些行也判成"没改"→ `return old_line, False`。

### 修法方向

- `Label` / `MenuName` / `SayTail` 各补一条"改一格 → 产物只动一行"的用例；
- 全量渲染与单拍渲染必须**同源**（`render_beats_to_rpy` 应该是
  `render_beat_to_rpy` 的分组拼装，不允许各写一套）。

## 七、判据校准（这几条不是 bug，是我第一版误报）

1. **`Kind='narration'` 改了不生效** → 是设计：kind 是说话人的投影
   （`kind_from_speaker`），有说话人就会变回 `say`。
2. **"改一句 → 撤销 → 导出仍是新值"** → 我调用方式错了（`save()` 内部
   会再 apply 一次，`undo` 回到的是 save 时的 before）。
3. **"删一拍 → 恢复 → 导出零 diff"** → 零 diff **正是预期**（恢复后与原文相同）。

## 八、P1（会咬人，但没到改坏剧情）

- **注释替换只插不删**：`# 旧注释` 改成 `# 新` 之后，旧注释还在、新注释
  插进去（越改越多）。`_rewrite_line` 对纯注释行有放行，但"一对多"的替换
  （1 行注释 → 2 行）走的是插入通道。
- **删 `jump` 拍被拒**（`PATCH_FAILED`："1 处删除不安全"）—— 是安全拒绝、
  有报错，但用户删了内存里的拍却落不了盘，建议提示里说清"内存已删、文件没动"。
- **改 if 条件被拒**（"条件与要写的拍对不上"）—— 同上，`ok=False` + 详细
  提示，属"明确失败"，不是静默。
