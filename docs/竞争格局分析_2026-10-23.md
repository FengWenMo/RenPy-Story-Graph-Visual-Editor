# 竞争格局分析：这个工具到底有没有优势（2026-10-23）

> **一句话结论**：在"**从零做一个新 VN**"这条赛道上，你**打不过** Excel2Rpy（已有安装包 + TTS + 自动翻译）和
> RenPy Code（VS Code 一键装、$5 买断就带调试器和流程图）。
> 在"**接管一个已经在做的 Ren'Py 项目、还要留着以后换引擎的可能**"这条赛道上，
> **目前没有第二个工具能做到你现在做的事**——不是功能多，是**三件事同时成立**：
> **不改引擎、不改用户字节、能带走**。

> 所以意义不在"更好用的 VN 编辑器"，而在**Ren'Py 项目的资产工业化运维层 + 跨引擎迁移层**。
> 这个定位很小，但它**只有你能占**。

## §3 三条护栏：为什么竞品做不到

这是全文最要紧的一节。三条护栏**同时成立**，目前找不到第二个工具。

### 护栏一：不改引擎

| 做法 | 要你付出什么 |
|---|---|
| 换 Naninovel / articy / Arcweave / VNU | 剧本重写、资产重导、插件重写、**团队重新学** |
| **留在 Ren'Py + 用本工具** | **零迁移成本** |

⚪ 判断：**50 人团队的引擎迁移成本，大到等于项目重做。**
这条护栏本身就是产品价值——它值多少，取决于团队敢不敢赌"以后可能换 Unity"。

### 护栏二：不改用户字节

这是**技术上最难、最不容易被抄**的一条。

- Excel2Rpy / Scenario_Tool 的模型是"**生成一份脚本**"：它们从表格出发，写出完整 `.rpy`。你手写的 `$ persistent.lock_lst[...]`、`renpy.transition(Dissolve(0.1))`、文件头注释、
  一行行尾内联注释——**全都不在模型里**，所以要么丢，要么被改写。
  本项目历史上就实测到过：全量重生成一章，**丢 18 行 / 多 13 行 / 头部重复两遍 / `fadeout 1.0` 参数被吃掉**。
- 本工具的模型是"**受控补丁**"：按行身份配对，**只替换真改过的行**，没碰过的行逐字节不变，
  且**任一行配不上就整份放弃 + 报错**，绝不产出"半对"的产物。
  实测：增量路径相似度 **0.9947 / 0.9944**，零丢失零多出。

⚪ 判断：竞品**能抄功能，抄不了这条**，因为这是三年踩坑踩出来的**契约**，不是设计文档里的一行字。

### 护栏三：能带走

| 工具 | 能不能把你已有的资产带走 |
|---|---|
| Excel2Rpy / Scenario_Tool / RenPy Code | ❌ 锁死在 `.rpy` |
| Naninovel / VNovelizer | ❌ 锁死在 Unity |
| articy / Arcweave | ❌ 锁死在自己格式 |
| **本工具** | ✅ 中立 IR → Unity 资产包 / Godot / JSON / CSV + **损失报告** |

🟢 只有 **STool / Ultra Ren'Py Translator** 做"跨引擎"，但它们是**逆向**——面向已经卖完的游戏。
**没有任何工具做"正向"：把一个在做的 Ren'Py 项目的资产，原样带走。**
⚪ 而这恰好是你项目说明里写的那个恐惧："他们后续可能改用 Unity"。

## §6 那意义到底是什么

**先说不好听的**：如果目标只是"做一个更顺手的 Ren'Py 表格编辑器"，
那意义**有限**——Excel2Rpy 已经做得不错，而且是别人在做，还有中文教程在传播。
在这个定位上，你是在**追一个已经有人占的位置**，而且对方有安装包、有 TTS、有教程。

**但下面三件事，只有你能占：**

### 位置一：已有项目的**外科手术刀**（brownfield）

竞品全是"**从零开始填表**"。你的模型是"**接管一个跑了三年的 Ren'Py 项目**"，
而且**不碰用户一个字**。

对一个已经有 88 个 `.rpy`、36,688 行、317 张图的团队来说，
"重新把剧本录进 Excel"是不可接受的；"让工具吃下我们的现有代码，而且我们不用改"才是。

⚪ 这条护栏（不改字节）**是三年踩坑换来的**，也是竞品抄不动的。

### 位置二：**资产与演出配置的治理层**（不是剧本编辑器）

50 人团队里最贵的从来不是"写台词"，是这些：

- 这个立绘到底是哪一版？（资产版本）
- 这句台词现在在哪个文件第几行？（可检索）
- 翻译改一句会不会砸掉演出？（**逐字节可验证**）
- 这个 image tag 在引擎里真的存在吗？（**引擎事实**）
- 谁改了这一行，改了什么？（审计）

这些活**可检索、可审计、可批量**——正好是工具该干的，而且**没有一个竞品在干**
（竞品要么不碰你的文件，要么只从表格生成）。

⚪ 更准确的说法：**storygraph 的产品定位不是"VN 编辑器"，是"叙事资产与演出的运维系统"。**
剧本编辑只是它最显眼的一个入口。

### 位置三：**跨引擎的逃生舱**

这条不是"以后可能用得上"，这是**唯一能接住那个恐惧**的东西。
所有引擎一旦选定就锁死：你换 Naninovel 要重写一切；换 Unity 要重做资产管线；
换 Godot 要重写演出层。**你的 IR + Unity 资产包 + 损失报告，是把"资产"和"引擎"解耦的唯一尝试。**

⚪ 而"资产和引擎解耦"这件事，在 2026 年的 VN 工具生态里**几乎没人做**——
大家都在赌"我选的这个引擎能撑到最后"。

## §8 一句话总结

> 你的工具**不是**"更好的 Ren'Py 编辑器"（那赛道有人占，而且占得不错）。
> 它是**"不改引擎、不改字节、能带走"**的叙事资产运维层。
> 三条护栏同时成立 = 竞品没有替代品；
> 但**分发、TTS、真机 demo** 这三个 P0 没解决之前，
> **护栏再硬，也传不到策划手里**。
>
> 所以下一步的第一优先级不是加功能，是**让别人能装、能看、能信**。
