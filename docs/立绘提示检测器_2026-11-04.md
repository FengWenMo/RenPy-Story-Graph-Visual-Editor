# 立绘提示检测器：两个真 bug + 一份专门的测试（2026-11-04）

> 用户（截图）：`lan aa happy` 报「没有 aa 这个属性」，`lan happy aa` 不报；
> 而且"`aa` 明明就有定义"。要求"专门写一个检测器的测试"。

## 一、bug 1：结论取决于**属性词的顺序**

```
lan aa happy   → 提示「lan 没有「aa」这个属性」   ← 报了
lan happy aa   → 什么都不说                      ← 没报
```

两层原因叠在一起：

1. **提示只看第二个词**：`want = spec.split()[1]` —— `aa` 排第二就撞上，
   排第三就漏掉；
2. **工具自己会重排**：`preferred_image_attrs(['aa','happy'])` →
   `['happy','aa']`（表情在前、其它在后）。所以"在编辑器里切一下就好了"
   —— 不是资源变了，是**顺序变了**，把 `aa` 挪出了第二位。

修：

- 看**全部**属性词（`wanted = parts[1:]`），报**每一个**不认识的；
- 坏词**排序去重**（`「aa」「i11」` 与 `「i11」「aa」` 必须是同一句话）。

真机验证（`D:\千连万理\sr_general`）：

```
lan aa happy      → （不吭声）
lan happy aa      → （不吭声）
lan nosuchword    → 「lan」没有「nosuchword」这个属性
```

## 二、bug 2：`aa` 是**项目自定代号**，工具不认识

我先按"脚本声明 / 资源表 / 磁盘文件"三路找 `aa`，全都没有 —— 于是以为
用户记错。**是我查的方向不对**。

真相：`aa` 在 `game/charactercenter/charactercenter.rpy:6`：

```python
init python:
    CC_OUTFIT_CYCLE = {
        "ling": ["aa", "base_swimsuit", "base_arms_akimbo"],
        "lan":  ["aa", "base_hand_up", "clothes2"],      # ← aa
        ...
    }
    CC_OUTFIT_LABEL = {"aa": "普通", ...}                 # ← aa = 普通
```

它是**界面换装循环的代号**（"普通"），不是 `layeredimage lan` 的
`attribute`（`definitions.rpy:381` 里只有 21 个表情 + `clothes2` /
`base_hand_up`），资源表里也没登记。

而剧本里 `show lan aa …` 用了 **922 处**。

### 修法（**第二版**）：加第三路证据 —— **`init python` 里定义过的词**

⚠ 第一版用的是"**剧本里 `show` 过就算认识**"，用户当场否掉：

> 「万一剧本错了呢！万一我用了 `ba` 呢……？这你也当认识？太粗糙了，
> 我不接受！」

那是**循环论证** —— 剧本里写错的词也"被用过"，于是永远不报。

第二版把判据从**使用位置**挪到**定义位置**：

「项目认识」从此是三路的并集：

| 路 | 来源 | 为什么算证据 |
|---|---|---|
| ① | `layeredimage` / `image` 声明 | 项目自己写的 |
| ② | 资源表的 `Attributes` 列 | 项目自己登记的 |
| ③ | **剧本里 `show <tag> …` 用过的词** | **项目自己一直在用的** |

新增 `assets.asset_identity.project_literal_words(root)` → `{str}`：
切出 `.rpy` 里的 `init python:` / `python:` 块，`ast.parse` 之后**只收**
**dict 的键** 与 **list / tuple / set 的元素**（不收 dict 的值 ——
`{"aa": "普通"}` 里"普通"是说明，不该因此变成合法属性名），并且只收
**像标识符的短词**（`[A-Za-z_]\w{0,31}`，把 `bgm/ed.mp3` 这类路径挡掉）。

真机结果：**80 个词**（含 `aa`、`clothes2`、`base_hand_up`…），耗时 0.08 s。

`Symbols.defined_words()` 暴露给提示层，「项目认识」= 声明 ∪ 表 ∪ **定义位词表**。

### 边界（写清楚，免得下次又猜）

- **剧本里写什么都不算数**：`show lan ba happy` 写三次、`ba` 没定义 → **照样报**
  （判据 `TestItDoesNotMiss::test_word_used_in_the_script_but_never_defined`）。
- `init python` 里的**通用键**（`text` / `name` / `id` / `accent`）也会进词表 ——
  那是"放过"方向的误差（最坏情况是少报一个错词），用户明确更烦误报。
- `init python` 写坏了（语法错）→ 这一路空转，**但不许崩**（有判据）。
- 行尾注释会被剥掉（`show ling happy  # 27无图片…` 里的中文不算属性）。

## 三、检测器测试（用户点名要的）

`tests/test_sprite_hint_detector.py`，**25 条**。核心是不变量 **I12**：

> **结论只取决于属性词集合，与顺序无关。**

| 组 | 钉什么 |
|---|---|
| `TestOrderDoesNotMatter` | 5 组词 × **全排列**，结论必须完全一致（含文案） |
| `TestReportsEveryBadWord` | 两个坏词都要点名；好词不许被点名 |
| `TestLayersInOrder` | 声明 / 表 / 剧本用过 / 都没有，四层的准入 |
| `TestSpellingLayer` | 大小写、下划线给正确写法 |
| `TestAtSuffix` | `@left` 不是属性 |
| `TestUsedInTheScriptIsEvidence` | `aa` 放过；没进过剧本的新词仍报；不跨 tag 串 |
| `TestDoesNotResurrectKnownBugs` | 前几轮修过的三条不许被这次改动弄坏 |

⚠ 这套判据第一次跑就抓到**第二层顺序敏感**（文案里坏词的顺序跟着输入变）——
顺手把坏词排序了。

## 五、顺带发现（没改，记一笔）

`game/charactercenter/charactercenter.rpy:151` 的 `cc_preview_name()` 会把
`cc_current_outfit`（可能是 `"aa"`）**直接拼进 image 名**：

```python
parts = [s.cc_current_outfit, s.cc_current_expr]
return " ".join([s.cc_current_char] + [x for x in parts if x])
```

如果引擎不认 `aa`（它不是 `layeredimage` 的 attribute），点"普通"那一档
会拼出 `show lan aa happy`。这一点**需要你确认**：游戏里切到"普通"时
立绘正常吗？正常 = 引擎宽容（工具的第三路证据正是为此而加）；
不正常 = 那段界面代码该把 `aa` 当"无服装"处理。
