# 怎么用：AI 助手 / 自定义模块 / 纯文字导入（2026-10-11）

> 这份是**上手说明**，不是设计文档。每条都对着当前代码核过。
> 三个入口都在**主窗口工具栏**上；找不到入口是本仓出过的历史问题
> （4 项功能做完却没人找得到，见 `docs/定位重审.md`），所以这份把位置写死。

## 一、AI 助手（工具内 agent）

### 1. 第一次：填一次 API key
工具栏点 **🔑 AI 助手 · 填 API key**：

| 填什么 | 说明 |
|---|---|
| 服务商 | `deepseek` / `openai` / `anthropic` / `openai-compat`（第四个填自己的 `base_url`，如本地或中转） |
| 模型 | 不填就用该服务商的默认模型 |
| API key | 存进 **`%LOCALAPPDATA%\StoryGraph\ai.json`**（`C:\Users\<你>\AppData\Local\StoryGraph\ai.json`）；🔒 只存本机、不进项目、不进 git |
| base_url | 只有 `openai-compat` 需要 |

⚠ 想让 key 存别处：设环境变量 `STORYGRAPH_AI_CONFIG` 指向你的 json。
⚠ 想清掉：同一个弹窗里有「清掉已存的 key」。

### 2. 用起来
工具栏点 **🤖 AI 助手** → 右侧面板 → 直接说话，例如：

- "看看这个项目里有哪些**你不认识**的写法"
- "`swim_suit` 这条我该怎么声明？先别写，给我看你会写成什么"
- "把 `1-1到达青蓝实验室` 这一章的体检跑一遍，告诉我最该先修哪条"

面板会显示**对话** + **工具调用轨迹**（它调了哪个工具、拿回什么）。

### 3. ⭐ 最重要的一条：**写盘要你点头，而且是代码强制的**
- agent 想改文件（`declare` / `table_export`）时，**代码**先强制它 `dry_run`
  跑一遍、拿到"会改成什么样"，然后**弹窗给你看 diff**；
- **你不点批准，一个字节都不写** —— 就算模型被诱导着说"直接写吧"也写不进去
  （闸门在代码里，不在提示词里）；
- 弹窗里拒绝 → 什么都不发生。

### 4. 另一条路：把工具当 **MCP server** 接给别的 AI 客户端
```powershell
python -m storygraph.mcp.server
```
它通过 stdio 讲 JSON-RPC，**9 个工具**（`storygraph_capabilities` /
`project_context` / `scan_unknown` / `ask_engine` / `verify_behavior` /
`host_validate` / `health` / `declare` / `table_export`）。
此时 API key 由那个客户端的订阅/额度承担，**不用往本工具填**。

⚠ 诚实说明：
- `storygraph_table_export` 目前是**占位**（`status: planned`，调用会明确说"还没做"）——
  故意不做假的；
- 工具自己**不联网**；只有你点了"发送"它才去请求你填的那个服务商。

## 二、「🧩 自定义语句」（给项目里自己的写法建声明）

工具栏点 **🧩 自定义语句**（它在工具栏**第一个**）。

> **2026-10-18 第六版：信息架构重做**（不是换皮，也不是在旧页签上缝补）。
> 旧版是四个编号页签（① 认识新动作 ② 填一条声明 ③ 候选分栏 ④ 已有声明），
> 编号看着像"四步"，其实 ① 和 ② 是同一件事的两半、③ 是 ② 的一个属性、④ 是管理
> —— 于是点 ① 选一行，界面**自己跳**到 ②，编号更假了。
>
> 现在只有**两页**：
>
> | 页 | 它回答的唯一问题 |
> |---|---|
> | **列表**（打开就在这） | 工具还不认识哪些写法 / 已经认识哪些 |
> | **编辑**（从列表点进去，左上角「← 返回列表」回来） | 这一条怎么写：开头词 → 后面跟什么 → 切一下 → 保存 |
>
> 另外两件"整个项目共用"的事也各有一页，从列表页底部进：**候选分栏**、
> **项目清单**。底部那行字只回答"现在按保存会发生什么"（或者为什么按不了）；
> 引擎内部的话挪进了右上角「使用说明」。

### 0. 先认六个词（界面上只出现这六个）

| 词 | 意思 | 例子 |
|---|---|---|
| **语句** | 剧本里的一行 | `swim_suit 小明 泳装` |
| **开头词** | 这一行的第一个词 | `swim_suit` |
| **格** | 开头词之后的每一个位置；从上到下就是剧本里的顺序 | 第 2 格 = 服装 |
| **列名** | 这一格在表格里那一列叫什么 | 角色 / 服装 / 神态 |
| **候选值** | 这一格允许写的词（不填 = 谁都能写） | 泳装、校服 |
| **项目清单** | 项目根目录的 `storygraph.rules.json` | 可评审、可 diff、可回滚 |

### 1. 在列表里挑一个词

打开就是列表页。上面那张表 = **工具还不认识的写法**（剧本里真的出现过、但没声明过），
每行带**原文样例**，一眼认得出是哪个。点一行 → 下面「教工具认识这个词」亮起 →
按它进编辑页。

- 剧本里还没出现的词：按「＋ 手动输入一个写法」直接写；
- 下面那张表 = **已经认识的**（来自项目清单，或脚本里的 `renpy.register_statement`）。
  选中一条按「查看 / 修改这一条」就能改它现在是怎么描述的 ——
  **保存是覆盖那一条，不会写第二条**。

> **最容易卡死的问题在这里当场回答**：开头词下面那行字会跟着你写的词变。
> 写 `show` 这种引擎本来就有的 → 它说"**按保存只让工具多几列，不会动引擎**"；
> 写 `swim_suit` 这种项目自己的 → 它提醒你"要让**引擎**也认识，项目里得有一段
> `renpy.register_statement`"。

### 2. 说清它后面跟什么

每个位置是**一张卡**（第 1 格、第 2 格…），从上到下就是这个顺序：

| 卡片上的项 | 意思 |
|---|---|
| 这一格是 | `固定的字`（剧本里必须原样出现）/ `任意文字`（人名、数字…）/ `从候选值里选` / `固定的字 + 一个值`（如 `at left`，整段可省略） |
| 表格里这一列叫什么 | **只填这一个**（可以写中文，如「角色」）—— 不用管代码里那串字，那由下面的「切一下」和项目里真实的资源告诉你 |
| 可以连着写多个 | 这一格能连着写好几个词。真机例子：`show lan happy sad`（同一格两个表情属性） |
| 这一格可以不填 | 空着也算写对。**`show` / `scene` / `hide` 的属性格默认就勾着**（Ren'Py 的属性本来就可选，`show ye happy` 没写服装是合法的） |
| 编剧只能从下面这些里选 | 勾上才**限死**；不勾 = 候选只是下拉里的备选，写别的也照样通过 |
| 候选值 | 按「从项目里导入候选」可以**按立绘分开**导入（`lan 的 outfit` / `lan 的 expressions`…），不会把别的角色的属性混进来；也可以「📋 批量粘贴一大段…」 |

⚠ **候选不必求全，也不要随便勾"只能从下面这些里选"**：真实项目的资源一直在变
（新加的立绘、别人的分支），限死之后剧本里任何一个没列进去的值都会判"切不上"。
候选的作用是**让你在下拉里少打字**，不是当白名单。

### 3. ⭐ 粘一行真实剧本，按「切一下」

粘一行（例：`show 小明 泳装 开心`，从剧本里连开头词一起粘最准）再按「切一下」，
它会按你现在的格子切开，显示：

```
切出来是这样：show（固定）｜小明（角色）｜泳装（服装）｜开心（神态）　—　共 4 格
```

切不上会**说清是哪一格、哪个词**（例如"第 2 格「服装」的 2 个候选里没有「泳装」；
这些词没人认领：泳装"），而不是一句"检查顺序"。

### 4. 保存 / 验证

- **「保存这条语句」= 唯一的写入口**（写项目根的清单文件，可审查、可 diff、可回滚）。
  **保存就生效**，列表里当场多出这一条，不用关窗重开；保存失败**不关窗**，
  底部那行会写清为什么（例如"有 1 格还没起列名 —— 它们不会被保存"）。
- 「用引擎验证」：真的叫引擎跑一次，如实分成**通过 / 失败 / 没证明成**，
  并说清引擎把错误指到了哪一行、下一步该怎么办（例如项目里缺 `renpy.register_statement`）。
- 「▸ 会写进项目清单的内容」：给程序看的预览，平时收着，点开才显示。

### 5. 删除 / 重置（项目清单页）

列表页 → **项目清单**：能看到 `storygraph.rules.json` 里**实际写着什么**
（语句、候选分栏、以及会自动保留的其它键），也能「删除选中的语句」、
「清空候选分栏」、「重置所有自定义声明…」。这些动作**都会先备份**整份清单到
`storygraph.rules.backup/`，其它键（例如 `host_hooks`）原样保留。

> **「候选分栏」是什么、什么时候才需要它**（旧名"词组"早就不用了）：
> 它只是把候选值**分组显示**的一层"改名 + 归类"，把 `outfit` 显示成「服装」。
> - **立绘属性**（`show ye base_handdown happy` 这类）：分栏**引擎自己就有**
>   （`layeredimage` 的 `group`），你什么都不用填；
> - **自定义语句的格**：想让「服装 / 神态」这种候选分开显示，才去建一栏；
> - 建完**不用去格子上下拉选** —— 这一格属于哪一栏是**自动认**的
>   （名字或显示名对得上就认），认出来会在卡片标题行标一句「分栏：outfit」，
>   认不出就什么都不显示（不是每个项目都有「服装」）。
> - 分栏页有自己的「保存候选分栏」：**只动分栏，语句一个字都不动**。
>
> ⚠ 同一个字段**同时**用在两处（语句的格 + 立绘属性）时，让它们**名字一致**
>    或用中文列名对上，否则自动认不出来。

### 6. 声明之后：这条语句在**卡片**上长什么样（2026-10-18）

> 用户原话：「不是每个写法都跟 show 一样与图片相关……有的可能是声音（多音轨、
> 多声部），有的可能是文字（比如给文字添加有色字体）」。所以卡片**按内容排版**：

| 你看到的 | 什么时候出现 | 它是什么 |
|---|---|---|
| 顶部一条 **`◆ 语句名 · 标签`** | 这一拍是一条语句（不是台词） | 语句条，下面附**原文**一行，逐字可核对 |
| **参数格**（紧跟语句条） | 声明里有格 / 参数列 | 这一拍唯一要改的东西；**排在台词框之前** |
| 「这一拍还会原样执行：…」 | 这一拍里有工具没建模的行 | 例如 `play ambience`（自定义声道）；它躺在「高级区 · 代码」里 |
| 「舞台：这一拍没有改动」+「＋ 改舞台」 | 这一拍**没有**背景/立绘/音乐 | 收成一行的舞台块，点开才是立绘网格（有舞台内容时照旧全显示） |
| 「这一句台词带后缀：…」 | 台词后面跟着 `(what_color=… )` 这类子句 | 它就是**这句台词的样式/控制**；在「高级区 · 台词后缀」里改 |
| 台词框的空提示「这一拍还可以说一句（可选）」 | 语句拍 | 语句 + 台词可以同在一拍（导出时语句在前） |

几个具体的写法：

- **声音（多音轨）**：`sfx_mix se se2 "se/a.ogg" gain=-6`
  → 卡片上是「声道 = `se se2`」+「文件」+「音量」三格；
  "这一格能装好几个词"会写成一行小字「可写多个（空格分隔）」。
- **文字（有色字体）**：`styled "他说…" "#ff0000" 32`
  → 三格：文字 / 颜色 / 字号。**颜色那一格旁边有色块**，改完立刻看到颜色。
  ⚠ 颜色值一定要带引号（`"#ff0000"`）—— Ren'Py 里 `#` 是注释，工具会自动补引号。
- **多声部**：`chorus lan ling "一起说"` → 「人物」那格是 `lan ling`，改成 `lan`
  就真的写回成 `chorus lan "一起说"`。
- **台词带样式**：`jc "台词" (no_skip=True)` → 台词框下面一行提示 + 高级区里可改，
  **导出后括号原样还在**（从前会被静默删掉）。

## 三、纯文字 / Word 章节导入

1. 剧情图工具栏点**「➕ 导入章节」**（过滤器里现在有 `*.txt *.docx`）；
2. 选 `.txt` 或 `.docx` → 工具转成 `.rpy` → 走**同一条**既有链路
   （过生成门禁 → 加进剧情图）；
3. ⚠ 两个诚实行为：
   - **有角色没确认就一个字都不写**（未映射的写法落盘会让 Ren'Py 崩），
     界面会把它要你确认的名字念出来；
   - 确认的决定会**写回 `characters.xlsx` 的别名列**，下次不用再问；
4. 「看着像谁在说话、但我不认识这个名字」的行会被**明确报出来**
   （例如 `小明：谁啊？`）—— 不会安静地当旁白。

## 四、改台词更快一点

卡片页工具栏有**「💬 下一句台词 ▶」**：一句一句跳，**跳过没有台词的拍**，
并把光标放进台词框。跳到头会说"后面没有台词了"。
（它只**移动选中**，不会把没台词的拍藏起来 —— 藏了下标会和拍错位。）

## 五、出错时怎么把信息给回开发者

界面上任何"没反应"的地方都可能被 `safeguard.swallow` 记了一笔。
控制台/体检里能看到 `[swallow] <模块.函数>: <异常>`。
把那一行发出来，比"它不动了"有用得多。

## 六、"服装 / 表情"这类多属性立绘怎么调（2026-10-12 新增）

先说结论：**`服装` 和 `表情` 不是要你去「自定义语句」里声明的东西**。
Ren'Py 自己就写着它们属于哪一组：

```renpy
layeredimage ye:
    group expressions when base_handdown:   # ← 这一组叫 expressions（表情）
    group outfit when base_handdown:        # ← 这一组叫 outfit（服装）
```

工具把这份分组从引擎里读出来，于是卡片上**一个分组一个格子**：

```
show ye base_handdown gratified
      [表情：gratified]  [服装：base_handdown]  [位置：—]
```

- **点哪格只改哪一维** —— 换表情不会把服装吃掉，反之亦然；
- 左键 = 换下一个候选，**右键 = 带搜索的候选列表**；
- 右键列表里给的是**完整的一条**（例如 `ye base_handdown happy`），
  挑一条就是这一拍的 `show`。
- 只有**一个**属性词的立绘（`show ye happy`）仍然是**一个**「表情」格子 ——
  单个词的项目行为与从前一字不差。

**候选列表里怎么选**（列表是"输入即筛"）：打几个字筛出来，然后
**回车**或**双击**即选定；`Esc` 取消。⚠ 2026-10-12 修：以前在弹窗里按回车
会被主窗口当成"下一拍"，看着就是**按了没反应**——现在弹窗开着时，按键归弹窗。

**「🧩 自定义语句」里的「候选分栏」呢？** 它只做一件事：
把某一格的候选值**分成几栏 + 改个显示名**（把 `outfit` 显示成「服装」）。
键名**不要盲填**：点「项目里的组…」从项目 `layeredimage` / 引擎事实
读到的组名里选（例如 `outfit`）；只填「服装」不会生效。
⚠ 立绘属性那套分栏**来自引擎**（`layeredimage` 的 `group`），不用你填；
没有声明时卡片不显示内部组名，只用「属性 1 / 属性 2」+ tooltip 说明。
⚠ 如果引擎把动作/姿势也塞进同一个 `group outfit`（例如 `stand`/`wave` 和
`swim_suit` 同组），给「动作」那一栏勾上**从引擎组里拆出来** —— 它会把
这些词从服装格里取走、单独成一格（只影响卡片，不改引擎语义）。

**什么时候才会报"不对"？** 只有真的会出错才报：

| 情况 | 工具说什么 |
|---|---|
| 同一组写了两个词（`show ye happy sad`） | 卡片提示：「expressions 组里同时选了 happy、sad，引擎只认其中一个」，并说清**哪个没生效** |
| 写了引擎不认的属性（掩码/切图这类内部件） | 「引擎没认（导出时它会报错）」—— **只是提示，不拦你** |
| `base_handdown` + `gratified` 这种**跨组组合** | **什么都不说** —— 它完全合法，预览也能叠出来 |

## 六、「记忆」：下次打开自动回到上次那个项目（2026-10-13）

> 用户："再给这个工具加个'记忆'功能，当第二次打开时自动读取之前打开过的那个
> 项目，如果项目内部有保存布局，一并读取，能做到吗？"

**能，而且默认就开着、而且没有界面。** 你什么都不用做：第二次双击 exe，它会自己
回到上次那个项目、载入上次在改的那一章、并把你拖过的分栏宽度摆回去，
**控制台里留一行**：

```
已自动读取项目：D:\千连万理\RenPyTest\sr_general（上次那一章：ch01.rpy）
```

> ⚠ 用户明确否掉了第一版做的 UI：
> "我让你自动打开！而不是加个 UI……没有必要……更不需要我手动点击说打开上次项目！
> 那跟我手动打开项目有什么区别？？？"
>
> 所以**没有菜单、没有勾选框、没有"打开上次的项目"按钮**：
> 有记录就读（在控制台说一行），没有就**空白打开**（一个字都不多说）。
> 唯一的口子是环境变量 `STORYGRAPH_NO_SESSION=1`（给自动化/自检用，不是给人用的开关）。

### 它记得什么

| 记得的东西 | 说明 |
|---|---|
| 上次打开的项目 | 目录**不在了就不自动打开**（记录留着，插回移动硬盘还认得） |
| 上次在改的那一章 | 同时记**绝对路径**和**相对项目根**那份 —— 项目搬过家也找得回来 |
| 当前页 + 停在第几拍 | 回到卡片页、回到你那一拍 |
| 两处分栏的宽度 | 结构页（画布 / 右栏）与卡片页（拍列表 / 编辑器） |
| 窗口大小与位置 | 位置已经不在任何屏幕上（拔了外接屏）就**只摆大小**，位置交给系统 |
| 最近项目列表 | 存在文件里（最多 8 个），但**界面上不显示** —— 它就是没有 UI |

### 存哪儿（两处，分工明确）

| 位置 | 谁写 | 用途 |
|---|---|---|
| `%LOCALAPPDATA%\StoryGraph\session.json` | **工具自己写** | 只属于**这台机器的这个人**；改路径用 `STORYGRAPH_SESSION_CONFIG` |
| `<项目根>\storygraph.session.json` | **你手写**（工具只读不写） | 想让一份布局跟着项目走（团队共用 / 进 git）就放这儿，它的字段**覆盖**上面那份 |

⚠ 为什么工具**不往项目里写**：那份记忆是"我上次把左栏拖多宽"，写进项目会污染
git diff，多人协作时还会互相打架。

### 想关掉

**环境变量 `STORYGRAPH_NO_SESSION=1`**：这一趟完全不读也不写记忆
（自动化、打包自检、"今天想空着开"都用它）。

⚠ 想清掉自己的记录？直接删那个 `session.json` 就行 —— 这是**文件**，
不需要为它做一个界面（要做的话又是一个"用户根本没要的 UI"）。

### 两条"它不抢"的规矩

1. **命令行走命令行**：`StoryGraph.exe 某项目根` 或 `... 某章.rpy` 时，
   记忆**一个字都不读** —— 你明确指了哪个就开哪个。
   但**只是"当前工作目录恰好是个项目"这种猜出来的**不算指定，
   那时记忆照常生效（不然双击 exe 就永远用不上记忆了）；
2. **记忆坏了不拦路**：文件损坏 / 项目没了 / 布局是坏的 → 照常启动，
   只在控制台留一句人话。
