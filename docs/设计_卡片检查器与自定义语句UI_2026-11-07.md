# 设计：卡片检查器与自定义语句的 UI —— "Unity 那种"到底该抄哪一半

> 2026-11-07 · 含一次真跑（临时项目，`tools/_probe_clause_card_shot.py`）与一次截图对照
> 触发：用户「我打算弄成Unity那种的UI，你觉得合适吗？……现在是理论上完全能支持
> 这样的源代码自定义，可是UI界面根本显示不出来！」

## 一、先纠正一个判断：不是"全都显示不出来"

实测（`tools/_probe_clause_card_shot.py`，临时项目，`mycue` 带 4 个子句）：

```
columns = ['mycue·文字@1', 'mycue·位置~at', 'mycue·挡在~behind',
           'mycue·转场~with', 'mycue·层级~zorder']
values  = {'mycue·文字@1': '闪电', 'mycue·位置~at': '左 右',
           'mycue·挡在~behind': 'ye', 'mycue·转场~with': 'Dissolve(0.3)',
           'mycue·层级~zorder': '5'}
```

卡片上真的长出了这 5 格，连"可写多个（空格分隔）"的提示都在
（`tools/out_custom_audit/clauses/01_mycue.png`）。

**声明驱动那条链路是通的。** 坏了的是另一条：**没有声明、也没人认领的数据**。

## 二、诊断：字段的"归宿表"

一张卡上能改什么，取决于这个字段有没有人认领。现在的实际情况：

| 数据 | 现在住在哪 | 卡片能编辑 | 备注 |
|---|---|---|---|
| 说话人 / 台词 / 拍级转场 | `card_editor` 硬编码 | ✓ | |
| 背景 / 音乐 / 语音 / 备注 / 条件 | 硬编码 | ✓ | |
| 立绘 tag / 属性 / **位置** | sprite chips | ✓ | `lan happy @左` |
| 立绘 `behind / as / with / onlayer / zorder / screen` | `sprite_rows[].clause` | **✗** | 代码原话：「卡片看不见」（`app/beats.py:655`） |
| 自定义语句参数 + 子句 | 声明驱动 `spec_columns` | ✓ | 本轮实测 |
| 高级区 7 项 | `ADVANCED_FIELDS` 硬编码**英文名** | ✓ 但看不懂 | `SFX/CodeBlock/Label/Kind/Stage/MenuName/MenuArgs` |
| 块体内容（`body`） | `beat.opaque` 整段原文 | 只能整段改 | |
| 没认出来的行 | `opaque` | 只能整段改 | |

两个事实要一起看：

1. **不丢数据**。`write_back_show`（`app/beats.py:680`）会把"表达不了的项"按原来的位置
   插回去——那是 2026-10-24 的 P0 修复（`show bg … with dissolve` 整条消失，
   `with` 还被套给了别的立绘）。所以现在是"**看不见，但没弄坏**"。
2. **看不见就等于改不了**。用户原话"根本无法从工具中编辑到这样的效果"说的是这个。

所以真问题不是"缺一套新 UI"，是：**一半的数据没有归宿**。
Unity 的检查器之所以好用，正因为每个字段都有 `SerializeField` 认领；我们没有那一层。

## 三、"Unity 那种 UI"：合适，但要抄对那一半

Unity 的检查器（Inspector）由两件东西组成，官方叫
[Property Drawer](https://docs.unity.com/zh-cn/engine/6000.7/manual/uitoolkits/ui-imgui/extending-the-editor/editor-property-drawers)：
**一个字段类型 → 一种画法**（`[Range]` 出滑条、`Color` 出色块、引用出对象槽），
**一个组件 → 一套字段**（`CustomEditor`）。这套东西值得抄的正是这两条。

### 该抄

| Unity 的做法 | 我们的等价物 | 现状 |
|---|---|---|
| 字段类型 → Property Drawer 一张表 | `FieldSpec(key, label, editor, group, source, tooltip)` 一张表 | **有三张**（硬编码布局、spec columns、advanced fields），互不知道 |
| 每个组件一个可折叠标题 | 每组一张"组件卡"：标题 + 来源徽章 + 折叠 | 只有 spec 组有 `group` 标题，其余散着 |
| `[Tooltip]` / `[Header]` | 每字段一行说明（`_spec_label_tip` 已有雏形） | 只有参数格有 |
| Add Component / Remove | **可选子句、可选参数**用"＋添加"，而不是留一个空框 | 缺 |
| Debug / Raw 视图 | 卡片上常驻"原文这一行" | 有（`原文：mycue …`），只读 |

### 不该抄（这三条会直接搞坏产品）

1. **顺序无关**。Unity 组件顺序无意义，属性就是属性；我们的**语句顺序就是语义**——
   `show` 的先后决定遮挡，`with` 作用于哪一段，`at` 谁先谁后。所以卡片必须是
   "**有序语句列表 + 每条的检查器**"，不能退化成一堆无序属性。
2. **场景文件当真源**。Unity 存的是序列化对象；我们存的是 `.rpy` 文本。检查器只能是
   **视图**，写入仍要走行级 patch（`write_back_show` / `spec_clauses.set_clause_value`）。
3. **一切皆组件**。台词是一大段文本（要字数、要换行、要语气），不是一行属性。
   硬套成"Text 组件"会把它做成最小的那个框。

**一句话结论**：方向对，但准确说法是
「**把卡片做成 Unity 式的检查器，同时保住行序与原文**」，
而不是「把整个界面做成 Unity」。

## 四、落地：四步

### P0 · 一张字段表（不改视觉，先让数据有归宿）

新增 `storygraph/ui_qt/field_specs.py`：

```python
FieldSpec(key='zorder', label='层级', group='立绘·附加',
          editor='int', source='show_clause',
          tooltip='数字越大越靠前；同层按 show 的先后',
          write='show_clause:zorder')
```

三处硬编码改成读它：`ADVANCED_FIELDS`、say 那几格、spec columns。
**判据**：每个 `Beat` 的可写字段都能在表里找到；找不到的必须落进 `RAW_ONLY`
并在卡片上显示徽章「只能改原文」——不允许"静默消失"。

### P1 · 给两个没归宿的补家

- **立绘附加子句**（`behind/as/with/onlayer/zorder/screen`）：立绘 chip 旁边一个
  「⋯」小按钮 → 折叠面板；数据结构现成（`sprite_rows[].clause`），写回走
  `write_back_show` 已有的通道。**零解析改动**。
- **高级区 7 项**：中文标签 + 对的控件（`Kind` → 枚举、`Stage` → 多行、`CodeBlock` → 代码框、
  `MenuArgs` → 键值对）。这一块纯 UI，风险最低、收益最直观。

### P2 · 组件卡视觉

每组一张卡：`▸ 立绘（3） ［内置］`，标题行右对齐折叠箭头；空组自动收起；
「＋添加」放在组尾。

### P3 · 原文常驻 + 可编辑

卡片顶部那行原文从只读变双击可编辑（写回前先 diff、先备份）。
这是"任何未来语法都不会完全没有出口"的兜底。

## 五、验收判据（可测，不是"看着像"）

1. 给定任意一行 `.rpy`，卡片上要么有它的输入框，要么有一个明确的
   「这一段只能在原文里改」徽章——**不许两者都没有**；
2. 把卡片上所有能改的格子改一遍再保存，**没被认领的部分逐字节不变**
   （现成的 `write_back_show` 判据扩展一条）；
3. `field_specs` 覆盖判据：`ADVANCED_FIELDS ⊂ FieldSpec`，
   且 spec columns 的每一个 `kind` 都有对应的 `editor`。

## 六、开放问题

- 立绘子句是放在 chip 上（就近）还是卡片底部一个统一的「附加」组？
  就近更直观，但一屏多张立绘时会长；
- `onlayer` / `as` 这种"改名/换层"的操作要不要可视化（`as` 会改变立绘的身份，
  风险高，可能需要单独的确认）；
- 高级区中文名要不要在 `beat_fields.COLUMN_SPECS` 里统一登记
  （现在 `docs/schema.json` 只登记表头，没有"给人看的标签"）。
