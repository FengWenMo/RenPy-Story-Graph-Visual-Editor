# 自定义模块：从「填表」改成「指一行给工具看」

> 用户 2026-11-07：
>
> 「想一想到底有没有更简便的操作方式，上网嗖一下，谁会填那个逆天的表啊！！！」

这篇记的是**改法**、**为什么这么改**、以及**改到什么程度**（含一条真 bug）。

---

## 1. 原来到底有多"逆天"

两处入口，都是"结构化表格"，都要人手填：

**① 自定义语句（`ui_qt/dialog_learn.py` 第 2 步）**

一条语句要几格，全靠人自己想。每加一格，一张卡上有 **5 个决策**：

| 要填的 | 例子 | 难度 |
|---|---|---|
| 这一格是 | 固定字 / 任意文字 | 还要理解"固定字"= 剧本里必须原样出现 |
| 这一列叫什么 | 角色 / 服装 / 神态 | 得想一个能当表头的词 |
| 可以连着写多个 | `happy sad` | 只在"多值"时需要 |
| 可以不填 | 省略就写默认 | 只在"可选"时需要 |
| 只能从这些里选 | `泳装 校服` | 要再维护一份候选列表 |

3 格 = 15 个决策 + 3 次「＋加一格」。

**② 技术调用（`ui_qt/dialog_calls.py`）**

一列「参数列」要手写 DSL：

```
转场@0; 层=layer        ← `@0` = 第 0 个位置参数，`=layer` = 关键字参数
```

**这是在让人把 `parse` 函数翻译成另一种语法**，而剧本里明明写着 `$ my_wipe("left", 0.6)`。

---

## 2. 调研：这件事**本来就不该由人做**

查了 Ren'Py 官方文档（`[cds]` / `[wiki·User-Defined Statements]`），结论很干脆：

> `renpy.register_statement(name, parse=..., execute=..., lint=...)`
> —— **名字只是一个词，语法全在 `parse` 那个任意 Python 函数里**。

也就是说：**CDS 没有 schema**。没有 `schema.json` 可读，没有 `parameters=[...]` 可解析。
所以"这条语句吃几个词、每格什么类型"只有两个可能的来源：

| 来源 | 可靠性 | 能不能自动 |
|---|---|---|
| 读 `parse` 函数体（`lexer.word()` 调用顺序） | 中（函数可以任意复杂、有分支/循环） | 理论上能，实际容易读歪 |
| **剧本里真实写出来的那一行** | **高**（这就是引擎要吃的输入） | **能，而且工具已经扫到了** |

而工具**早就**在扫了 —— `statement_registry.discover_undeclared()` 会给出
每条未知写法的 `count` / `samples`（文件:行 + 原文）/ `block`。

**答案一直在手里，界面却还在问人。** 这就是"逆天"的根源，不是界面丑。

---

## 3. 改法：三处落点，共用一份"自动拆"

新增 `storygraph/authoring/autospec.py`（纯函数，**不碰 Qt**）：

| 函数 | 干什么 |
|---|---|
| `split_sample(line, head)` | 一行剧本 → 格子草稿（`name` / `label` / `kind` / `sample`） |
| `call_columns(line, head)` | 一行 `$ f(...)` → 技术调用的参数列（`position` / `kw`） |
| `guess_call_heads(texts)` | 一堆代码行 → "哪些名字反复出现在 `$ 名字(`"（带次数与样例） |

切词**复用 `authoring.pattern.tokenize`**（和试切/读值/卡片同一份词法，不另写一套）。

### 落点 ①：点一条「还不认识的写法」，格子已经建好

`dialog_learn._on_pick` 现在把样例一起带进去：

```python
_load_statement(None, head=..., block=..., sample="mycue \"闪电\" intensity=3")
    → _fill_params(decl=None)        # 一个空卡
    → _autofill_from_sample()        # 立刻按样例重建：2 格，名字都填了
```

截图 `docs/shots/learn_autofill_2026-11-07.png`：点「泳装切换」→ 进来就是
**3 格（小明 / 泳装 / 开心）**，底部写着"按保存会新增『泳装切换』（3 格 → 表格里的列）"。
**两步**：点一条 → 按保存。

### 落点 ②：一个按钮「照着这行建格子」

第 4 步「拿一行剧本试试」旁边。粘任意一行 → 一键把格子重建（名字取原文，
`at` 这类子句词自动认成"固定字"）。人手上有别的写法时不用回列表。

### 落点 ③：技术调用表「扫一遍剧本」

`dialog_calls.scan_project()`：扫项目里所有 `$ 名字(...)`（跳过 `renpy.` /
`print` 这类），把**还没在表里**的补进来，参数按逗号拆好。
截图 `docs/shots/calls_autofill_2026-11-07.png`：两行自动填成
`fade@0; 参数2@1; layer=layer` / `left@0; 参数2@1`，人只改中文名。

**只加不改**：已经填好的中文名/效果一个字都不动（有判据）。

## 4. 顺带修的一条真 bug：中文语句头发现不了

`discover_undeclared` 的闸门②是：

```python
if not re.match(r'^[A-Za-z_][A-Za-z0-9_]*$', head):   # 纯 ASCII
```

而 Ren'Py 的 CDS 名字**可以是中文**（`renpy.register_statement("泳装切换")` 合法）。
于是**中文项目的自定义语句永远进不了"待认领"列表** —— 用户看到的是"这个模块
根本不认识我的写法"。`learn_statement._STMT_RE` 在 2026-10-14 就改成
`[^\W\d_]`（任意 Unicode 字母）了，**这里当时漏了**。

改：`^[^\W\d_]\w*$`（吃中文，仍拒 `$` / 数字 / 下划线开头）。
判据 `test_chinese_statement_head_is_discovered` + `test_symbols_and_numbers_are_still_refused`。

## 6. 三条取舍（以及为什么不做更多）

| 取舍 | 为什么 |
|---|---|
| 只给 `keyword` / `variable` 两种类型，**不猜**"这是服装还是表情" | 猜错会让那一格变只读（`keyword`），比留成 `variable` 难查得多。领域词根 `_role_word_kind` 只在**够确定**时才用 |
| 名字就取原文（`闪电` / `intensity` / `参数2`），不翻译 | 翻译要词典，词典要维护；原文人一眼能认出来，改一个词的成本低于维护词典 |
| 手填**保留**，只是不再是要走的路 | 有些项目的写法扫不出来（动态拼接、模板生成）。留着手填是兜底，不是主路 |

## 8. 第二轮：把"准确"补上（子句不是位置格）

第一版有个不准确的地方，是"准确"两个字逼出来的：

```
mycue "闪电" at left
```

第一版拆成 **2 个位置格**（`闪电` / `at` / `left` 里的后两个）。可是：

- `at left` 在 Ren'Py 里是**子句**（`at` 是关键字，`left` 是它的值）；
- 工具本来就有「复杂子句」这一层（`story/spec_clauses.py`，2026-10-30 加的）；
- 把它当位置格喂给 `pattern.match_line`，试切会直接报
  `leftover: ['at','left']` —— **工具认错，却指责人写错**（实测）。

### 改法

`split_sample` 现在返回 **`(位置格, 子句)`** 两份：

| 输入 | 位置格 | 子句 |
|---|---|---|
| `mycue "闪电" at left` | `闪电` | `at` → 位置（多个词） |
| `mycue "闪电" with Dissolve( 0.3 )` | `闪电` | `with` → 转场（表达式，不切碎） |
| `mycue "闪电" at 左, 右 zorder 5` | `闪电` | `at`（左, 右）+ `zorder`（数字） |
| `at left`（第一个词就是 at） | `at` / `left` | —（不抢，说明这是普通词） |

只认**已知那六个**（`at` / `with` / `behind` / `zorder` / `as` / `onlayer`）——
自定义语句的关键字是项目自己定的，猜不出来，**不认识的词老老实实当位置格**。

子句进「复杂子句」表（`dialog_learn._build_clause_section` 那张），一格不占。

### 顺带修掉的既有缺口

**声明了子句之后，试切永远失败。** 因为 `pattern.match_line` 只吃位置格，
`at left` 就成了"多出来的词"。现在试切**先把已声明的子句从行里摘掉**再切：

```python
line = self._strip_declared_clauses(line)   # 复用 set_clause_value(..., '')
```

复用 `set_clause_value` 的"清空 = 连关键字一起删"语义，不另写正则 ——
正则版会误删引号/括号里的同名词（`mycue "a at b"`）。

判据：`test_cut_succeeds_after_the_clause_is_stripped`（改之前必红）。

### 「快速」的小事

`scan_project` 读几百个文件（真机 88 个 rpy ≈ 0.2s），按钮会先变成
「正在扫描…」并置灰 —— 不然人会以为点了没反应，连点三下。

## 9. ⚠ 一条工具链教训（今天踩了两次，都误判成产品 bug）

**用 `cat > x.py <<'PY'` 写 Python 源码，会把里面的 `\n` 改成字面 `/n`**
（Git Bash / MSYS 的 heredoc 行为）。于是写进项目的样本文件变成一行
`label start:/n    mycue ...`，解析器当然读不出第二行 —— 我据此得出
"解析器会吞掉 label 第一行"的结论，还差点去改解析器。

第二次同样的坑：`test_autospec.py` 里两条用 heredoc 追加的用例
（`'label start:/n    mycue …'`）被改成 `/n`，于是"子句表 0 行"红了一轮。

**规矩**：改动源码/测试一律用编辑工具（Edit / Write）；只在"跑一次性探针"
时才用 shell，而且**探针里不写含 `\\n` 的字符串**（用三引号真实换行）。

## 10. 撤销那一版「代码格右键」，改成真正该做的事

上一版把"教工具认识这一行"挂到了**卡片高级区的「代码」格**右键菜单上。
用户当场否了，三条理由都成立：

> 我觉得不应该在代码的那个高级上面配置吧……？自定义模块归自定义模块，
> 别挪到高级那里去……而且工具本来就认识啊！这是标准 renpy 写法！
> 这么整理太乱了！！！所以我才三番五次说卡片编辑器右边的 UI 和
> 自定义模块定义出的模块一定要对应！UI 要重构……

1. **概念错位**：「代码」格是保真后门（不认识的语句原样进出），它不该承担
   "教工具语义"这件事 —— 那是「自定义模块」的职责；
2. **它还认错**：`CodeEditor` 拿不到声明表，`teachable_head()` 只能判"像不像
   一条语句"，于是**已经声明过的写法也会出现"教工具认识"** —— 用户看到的就是
   "工具本来就认识啊"；
3. **真正乱的地方不是入口**，是右栏。

已全部撤回（`code_edit` / `card_editor` / `window_graph_page` /
`window_graph_ops` / `dialog_learn` 五处 + 那份测试），入口回到工具栏
「🧩 自定义语句」。

### 真正要改的：右栏的组跟着"这一拍是什么"走

`BeatCardEditor._sync_field_groups()`（`set_spec_args` 末尾调用）：

| 这一拍 | 台词区 | 舞台块（背景/立绘/音乐/语音输入） |
|---|---|---|
| 台词拍 | 显示 | 显示（"说着话顺手 show 一个"是真写法） |
| `show` / `scene` 拍 | **收起**（没台词） | 显示 |
| **自定义语句拍**（`泳装切换 …`） | **收起** | **收起**（它不动舞台） |

截图 `docs/shots/card_statement_groups_2026-11-07.png`：一条
`泳装切换 小明 泳装 开心` 的卡片从上到下只剩 ——
语句标题 → **角色 / 服装 / 神态** 三格（就是自定义模块里声明的那三格）→
当前舞台摘要（只读）→ 备注 → 条件 → 高级区。**没有一个无关的空框**。

对照 `docs/shots/card_say_contrast_2026-11-07.png`：普通台词拍照旧。

### 两条不能碰的线

1. **收起 ≠ 不写回**：`collect_fields()` 按 `PRIMARY_FIELDS` 遍历，不看可见性。
   高级区那套"展开才收"是反例（`SayTail` 曾因此静默丢过），判据
   `test_hidden_groups_are_still_collected` 钉住了这条。
2. **判据读"源文件里的字段快照"**（`_loaded_raw`），不读控件：`Show` 背后是
   立绘网格（chip），`_get_value('Show')` 在没有 sprite items 时恒为空 ——
   用它判会把"这一拍真的在改立绘"当成"没动舞台"（判据当场抓到）。

判据：`tests/test_card_field_groups.py` **7 条**；相关子集 **413 全绿**。
