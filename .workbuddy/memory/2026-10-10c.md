## 一、新增 `storygraph/authoring/txt_pipeline.py`（纯逻辑）

形状：`.txt` →（S4 后含 `.docx`）→ `.rpy` → **先问清未映射写法** → 过生成门禁
落盘 → `EditorSession.import_chapters`（复用既有链路的校验/门禁/剧情图）。

### 为什么分两遍（本模块最重要的设计）

未映射写法直接落盘 = 产物里是**未定义变量** = Ren'Py 到那句 `NameError` 崩
（真机 5 章 1373 行里 23 处）。所以：

    ① **规划**（纯，不写盘）：转文本 + 收集未映射写法 → 弹窗问人
    ② **落地**：决定写回 `characters.xlsx` → **重跑转换** → 过门禁落盘 → 导图

于是只有两种结局：**产物是干净的**，或者**什么都没写**。没有"写了一半"。

### 命名与落点（实测校准过）

- 落点 `<项目根>/game/<标签>.rpy`（没有 game/ 就放项目根）。
  ⚠ 与 `generation_guard.planned_output_path`（表格导出走 `build/renpy/`）
  **刻意不同**：那条是"表格→脚本"的产物目录，这条是"作者要把章节加进项目"。
- 目标名优先级：**章节头推出来的 label** > 文件名 `1-2` 前缀 > 文件名规范化。
  ⚠ 真机实测：文件名编号与章节头**差一位**（`1-0初入大学-定稿.txt` 的头是
  `chapter0-0`）→ 拿文件名命名会得到 `chapter1_0.rpy`，与作者心里的那一章
  对不上、还会抢 `chapter0_0` 的 label。**这一条是我第一版写反的**。
- 同批两个文件算出同一个目标名 → 自动错开（`chapter1_2_2.rpy`）。

## 二、会话层 `EditorSession.import_plain_text`（S3 的接入点）

```
session.import_plain_text(files, graph, ask=弹窗, import_chapters=窗口的入口)
```

- `apply_character_decisions()`：把决定写进 `characters.xlsx`，
  **写完必须重读角色表**（只替换 `registry.characters`，不整项目重扫）——
  不重读的话同一个写法**下次导入还会再问一遍**（实测踩到）。
- ⚠ **导入那一步必须走调用方自己的入口**：`EditorSession.import_chapters`
  只**返回**图，不负责装进窗口（窗口那边还要进历史、写控制台、更新符号表）。
  我第一版传的是 session 自己的方法 → UI 拿 `res.get('graph')`（**根本没有这个键**）
  去 `_set_graph` → **图一直是空的**（实测抓到的真 bug）。

## 三、UI 接线

## 四、用户拍板的两条口径都落地了

- **"同一个写法在不同章指不同角色先不考虑，留出接口即可"**：
  决策是**项目级**（`characters.xlsx`，一次决定全项目生效）。
  接口留在 `txt_pipeline` 的模块 docstring：`Decision.by_file` ——
  以后要做，就让每条决定带"只在某文件生效"的限定，落地时按文件分组应用。
- **"建新角色时立绘留空是对的（可能是龙套）"**：
  `plan_new_character` 只写 `ID`/`Name`（+备注），**`ImageTag` 一律不填**；
  判据 `test_a_new_character_decision_creates_a_row_without_a_sprite`
  直接断言那一格是空的。`.docx` 也明确报"还没实现（S4）"，不静默。

## 五、实机演练（**决定性验收**）

`tools/probe_s3_real_landing.py`：真机项目副本 + **把已有章节挪走**（模拟"还没
放进项目"）→ 5 个定稿 txt 走完整流程：

```
挪走已存在章节 7 个（真机在 game/chapter/ 子目录里，要递归找）
落盘 5 个：chapter0_0 / chapter1_1 / chapter1_2 / chapter1_3 / chapter1_4
导入结果：added_nodes 5 · 往返逐字节 5/5 · 产物里有 define 的：无
说话人全部对得上角色（对新角色 A/B/BAOAN/… 的说话人也一样）
决定统计：新建角色 6 · 加别名 2（MOM→mm、TJF→txf）
```

⚠ 另一条实机结论（**值得记住**）：真机 `game/chapter/` 里那 5 章**本来就在**
（同一个 label）→ 全量生成会被 `LABEL_COLLISION` 拦下、**一个字都不写**。
这是对的（B1/B2 护栏），所以那条命令只适合"导入**新**章节"；
要在已有项目上改章节，走卡片编辑器（增量补丁）。UI 预览现在会**先**把这件事
说清楚（否则用户点完才发现"什么都没发生"）。

## 六、实机抓到的三个真缺陷（都已修 + 判据）

| # | 缺陷 | 为什么以前没人发现 |
|---|---|---|
| **E1** | **老角色表没有「别名」列** → `_update_row_cells` 遇到表头里没有的键是**静默跳过** → "给真人项目加别名"整个动作**什么都没发生**（返回成功） | S1 加列时只测了新建表；真机表是加列**之前**建的（5 列）。修法：`append_rows_to_table` **把缺的列补到末尾**（⚠ 只追加、绝不挪动已有列 —— 挪列会连带数据错位，我第一版只改表头就把整行搞乱了，判据当场红） |
| **E2** | **UI 第二遍导入拿不到图**：`EditorSession.import_chapters` 只**返回**图，`res` 里**根本没有 `graph` 键** → `_set_graph(None)` → 图一直空的 | 只有"从 UI 走一遍"才暴露；`no_undefined_names` 那种静态网也看不出（不是名字错，是**语义接错了**）。修法：`import_plain_text` 收 `import_chapters=` 回调，UI 传**窗口自己的** `import_chapter_files` |
| **E3** | **dry_run 的 `ok` 恒为 False**（它什么都没写）→ UI 第一遍判 `if not ok` 就 return → **这条链一次都不会往下走** | 语义正确但被当成错误用了。判据改成"有没有规划出文件" |

**教训（同类）**：E1/E3 都是"**返回值语义被想当然**"——「成功」和「有内容」不是
一回事，「返回图」和「把图装进界面」也不是一回事。凡是跨层传值，**先写一条
"从最外层真的走一遍"的判据**（E2 只有那种判据抓得到）。
