# 2026-10-10（续 6）：词组分组 —— 把"服装 / 表情"分开，但**不写死任何组名**

> 用户：
> > 对啊！实际上需要分组显示……但因为我这个要求通用！所以一般人其实是没有服装
> > 这个选项的！所以事实上应当通过 B 这个自定义模块，做到把服装跟表情这种东西分开！

这句话定了设计口径：**主语是项目，不是工具**。工具不认识"服装""表情"，
它只认识"项目声明了几组词"，然后按声明分栏。

## 一、声明形状（`storygraph.rules.json`）

```json
{
  "attr_groups": [
    {"name": "outfit", "label": "服装", "options": ["swim_suit", "clothes2", "swim_*"]},
    {"name": "expression", "label": "表情", "options": ["happy", "shy", "sigh"]},
    {"name": "rest", "label": "其他"}
  ]
}
```
`options` 留空 = **兜底组**（没归到别的组的词都进它）。

## 二、归属规则（`authoring/spec_groups.py`，纯函数）

1. **逐字命中**：`clothes2` 在组里 → 进那一组；
2. **整段词序列命中**：`swim_suit_glad` 里 `swim_suit` 是**连续两整段** → 进"服装"；
2b. **前缀通配**：`swim_*`（真机项目 1657 张图 / 一个 tag 692 个属性，
   逐个列词不现实，通配是必需的）；
3. **兜底组**装 1/2/2b 没归到的；
4. **没有兜底组**时没归到的词**留在原地**（单独一组、没有标题）——
   "分了组"绝不等于"能藏词"。

⚠ 刻意**不做子串包含**：`unhappy` 里含 `happy`，按子串会把它归进"开心" ——
这正是 `Symbols.attr_for` 当初踩过的坑（"猜错一个表情是演出事故"）。
实测 `group_of('unhappy') == ''`。

⚠ **通用性底线**（判据钉住）：没声明 → `group_choices()` 返回 `[]`，
调用方走原来的**平铺候选**，行为一个字节不变 ——
"一般人没有服装这个概念，他就不该看到任何分栏"。

## 三、接进了哪几处

| 层 | 改动 |
|---|---|
| 清单 | `statement_registry.declare_attr_groups()`（与 `declare_statement` 同一份清单、同样"同名=更新 / 坏清单拒写 / 其它键保留"） |
| 装配 | `StatementRegistry.attr_groups`（`for_project` 时读 `ATTR_GROUPS_KEY`） |
| 应用层 | `app.beats.expression_groups_for(tag, symbols, groups)` —— 值走**界面显示名**（与 chip 同一套 `_expression_display`，否则下拉是 `happy`、chip 是「开心」） |
| 会话 | `EditorSession.declared_attr_groups()`（只递数据给前端） |
| 界面 | ① 右键 chip 的候选列表插**不可点的粗体组标题**（`choice_picker`：`filter_groups` 筛掉了的组连标题一起消失）；② 立绘网格 `set_choice_groups_provider(tag→分组)`（**现取不缓存**：同一个词在不同角色下显示名可能不同）；③ 「🧩 自定义模块」里多一节**词组表**（组名/中文名/候选词）+ "把词组一起写进清单"，而且**可以只写词组**（语句名留空也行） |

## 五、这一轮踩的坑（都值得记）

① **面板漏一个转发方法 = 模态弹窗卡死**：我加了 `set_choice_groups_provider`
到**网格**上，忘了 `BeatCardEditor` 面板要转一手 → `AttributeError` 落进
`load_script` 的 `except` → `QMessageBox.critical` **模态** → 测试挂死、用户看到"卡住"。
定位手法：`faulthandler.dump_traceback_later` 打出卡在哪一行，再把
`QMessageBox.critical` 换成打印拿到真消息。
守卫：`test_every_panel_method_the_window_calls_really_exists`
（静态扫窗口源码里 `self._panel.xxx(` 的调用，逐个断言面板上真有）。

② 静态网 `test_single_write_entry.py` **抓到了新写入口**
（`declare_attr_groups`）—— 这正是它的用途，登记即可。

③ 真机探针**挑错了 tag**：按"属性最多"挑到 `ui`（692 个界面控件属性：
button/frame…），演示毫无意义。改成按"像表情的属性最多"挑 → `lan`。

④ 覆盖率**假警报**：`expression_choices` 有 `limit=500` 截断，
拿它当基准比"分组有没有丢词"会得出"丢了词"的错结论。
要比就跟**这个 tag 的全部属性**比。

⑤ 又是"构造期刷新早于控件创建"：`_refresh_preview` 里读 `self.write_groups`
时它还没建出来 —— 一律 `getattr` 守卫 + 末尾重刷（这是同一类坑第三次，
以后新对话框一律这么写）。

⑥ Qt 的 `QListWidgetItem.setForeground(Qt.gray)` 在浅色主题下几乎看不见，
改**粗体**（出图才发现）。
