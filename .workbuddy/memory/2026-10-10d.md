## 一、`.docx` 就是个 zip

```
a.docx
  ├─ [Content_Types].xml
  ├─ word/document.xml      ← 正文在这里（<w:body> 下一串 <w:p>）
  └─ word/styles.xml / media/…
```
段落 `<w:p>` → run `<w:r>` → 文本 `<w:t>`；`<w:br/>` 是行内换行、`<w:tab/>` 是制表符。
项目没有 python-docx（依赖只有 openpyxl/PySide6/Pillow），所以自己抽。

## 二、`storygraph/authoring/docx_import.py`（纯函数）

**抽取规则**（只做"变成纯文字"这一件事）：

| Word 里的东西 | 处理 | 为什么 |
|---|---|---|
| 段落 | 一行（`\n` 分隔） | 与 `.txt` 的"一行"完全同构 → 后续链路直接复用 |
| `<w:br/>` 行内换行 | **也当一行** | 作者按 Shift+Enter 就是想换行 |
| 多个 run | 原样拼接（不加空格） | Word 改个词就切 run，加空格会改台词 |
| 表格 | 每格各自成段（按 XML 顺序） | `<w:p>` 本来就在 `<w:tc>` 里 |
| 超链接 / 文本框 | **一起抽** | 那是作者写的台词，静默丢就是改剧情 |
| 页眉/页脚/批注/脚注 | 不抽 | 不是章节正文（页眉往往是书名/页码） |
| 样式（加粗/字号/颜色） | 全丢 | 纯文字只有"谁说了什么" |

⚠ **刻意不做语义猜测**：不把"标题样式"当章节头、不把列表转成 menu。
章节头仍由 `txt_import._HEADER_RE` 认（`1.0 chapter0-0 初入大学`）。
文档里"看着像标题"的东西太多，**猜错就是改结构**。

⚠ 遍历用 `paragraph.iter()` 而不是只找直接子 `w:r`：run 可能包在
`w:hyperlink` / `mc:AlternateContent`（文本框）里 —— 只认直接子节点会**静默丢掉**
那些文字（判据里各有一条钉住）。

## 三、读不出来要说"能照做的"原因

| 输入 | 报什么 |
|---|---|
| 老 `.doc`（OLE 魔数 `D0CF11E0`） | "这是老的 .doc…请在 Word/WPS 里**另存为** .docx（或直接存成 .txt）" |
| 非 zip（rtf/pdf 被改名成 .docx） | "不是 .docx（zip）文件：开头没有 PK 标记" |
| zip 坏了 | "`.docx` 解不开（zip 损坏）：…" |
| zip 里没有 `word/` | "不像 .docx（是不是 .odt / .epub？）" |
| 有 `word/` 但没有 `document.xml` | 点名缺哪个成员 |
| `document.xml` 不是合法 XML | "不是合法 XML：…" |
| 空文件 | "空文件" |

**都不静默**：`build_plan` 把这些收进 `skipped`（带原因），UI 与控制台都看得见。

## 四、与 `.txt` 是**同一条链路**

`docx_import` 只产文本 → 之后完全复用 `txt_import.convert_text`
（行型判定 / 括号当注释 / 角色映射 / 往返逐字节）。所以判据里有一条
**"同一份文字，`.txt` 与 `.docx` 两条路给的产物逐字节相同"** ——
这条比"能读出来"强得多：它保证不存在"两套转换规则"。
