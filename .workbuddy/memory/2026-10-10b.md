# 2026-10-10（续）：角色决策层 —— "问一句"的弹窗方案落地（纯逻辑部分）

> 用户在这一轮定案（原话）：
>
> > **A**（保留+告警），但是先这样：在转换时搜索已定义的相似字符，可以搜索相关的
> > define，比如 `Ljk` 和 `ljk` 最像 `L_J_K` 也有可能，`mom` 在游戏内显示为妈妈等……，
> > 然后写一个弹窗，问是不是已定义的这个角色？如果是，自动标上别名，如果不是，
> > 自动生成新角色 define 并输出。
>
> 三个待决点用户也拍了：① 新角色**变量名/显示名默认=token 原样**，弹窗里可改；
> ② 新角色**追加到 `characters.xlsx`**（只追加不覆盖），define 交给既有同步链路；
> ③ **"有相似候选"和"完全没候选"都进同一个决策列表**（没候选的给"建新角色/跳过"）。

## 一、为什么这个方案成立（一句话）

**"问一句"就是安全边界。** 字符串相似度永远分不清"同一个人写错了"和"两个长得像的人"
（用户担心的正是后者）；把判定交给人点一下，它就从"猜"变成"确认"。
所以新模块只做两件事：**给候选 + 说清凭什么** → 人决定 → **按决定改表**。

## 二、新增 `storygraph/authoring/char_decisions.py`（纯逻辑，28 条判据）

### 建议层 `suggestions(conversion, chars, rows)`（纯函数，弹窗的数据源）

每个未映射/歧义 token 一条 `Suggestion`：出现次数、**原文样例**（人要看上下文才知道
`MOM"跟妈客气啥"` 是妈妈）、候选角色 + **证据**。

| 证据 | 判据 | 实测例子 |
|---|---|---|
| `case` | 忽略大小写后与**该角色的任一写法**（变量/显示名/别名）相同 | 别名 `Mom` ↔ token `MOM` |
| `sep` | 再去掉下划线/空格后相同 | `L_J_K` ↔ `ljk` |
| `fuzzy` | 编辑距离 ≥60%（单字母 token 要 ≥80%） | `MOM`↔`mm` 80%、`TJF`↔`txf` 67% |

⚠ **刻意不做拼音首字母匹配**（试过又撤掉，理由留档在模块里）：
`LINGDAO`↔`ld`（校领导）看着像能算，但项目**零拼音依赖**（只有 openpyxl/PySide6/Pillow）。
我先按"GB2312 一级汉字按拼音排序"推了一版区间表，**实测不可信**：
`吧` 判成 `a`（实际 `b`）、`瑾` 判成 `z`（实际 `j`，真机角色是 `yhj`）。
没有权威数据源时手写字表 = **造一个假权威**，而候选列表的质量决定弹窗的价值
（给一串"排最前却毫不相干"的候选，用户会学会不看候选，比没有候选更糟）。
`MOM↔妈妈` 这类**本来就不是字符串问题**，靠弹窗里的**手工挑选**兜住。

### 噪音过滤（两条都是探针实测出来的）

1. **填充名**：`A"卷王——"` 的候选第一位曾是 `aaa`（舍友A），相似度 **100%**
   —— 因为 `a` 与 `aaa` 在编辑距离上完全包含。判据：短 token（≤2）**不许**匹配
   "≤2 种字符组成的短名字"（真机 `aaa`/`aabb` 是拼出来的组合行）。
2. **前缀假象**：`score_candidates` 的第 0 档是**前缀命中**，于是单字母 token 会把
   半张表拉进候选。所以召回可以用它，**排序必须按证据分档**（否则等于没候选）。

### 决定层（纯：先算清后果，再落盘）

- `plan_alias(rows, token, var)` **四道闸门**：
  ① 角色必须存在；② ⚠ **token 归一后等于某个变量名 → 必须拒绝**（见下）；
  ③ token 不该已经是某个写法；④ 加完跑 `CharacterMap` 预检**不许撞车**，
  且加上去之后 `lookup(token)` 必须真的解析到目标角色。
- `plan_new_character(rows, token, var?, name?, …)`：默认 `ID=Name=token`；
  **重名要报**（ID 已存在 / 显示名已被别人用 —— 后者正确动作是"加别名"而不是建第二个人）；
  新建也要过撞车预检（`Ljk` vs `ljk` 那种）。
- `apply_alias_plans` / `apply_new_character_plans`：落盘走
  `asset_registry.append_rows_to_table(...)`（**只追加 + 列白名单**，唯一写盘入口契约）。

### ⚠ 最要命的那一格：用户举的 `LJK` 例子

用户说"`Ljk` 和 `ljk` 最像 `L_J_K` 也有可能" —— 但如果表里的变量叫 `ljk`，
给 `LJK` **加别名**的后果是：`Aliases` 里出现一个"归一后等于变量名本人"的写法
→ 该键变**歧义**（`CharacterMap` 会主动拒绝映射）→ **别名白加、更糟**。
所以 `plan_alias` 现在**专门拦这一格**并说清处置：
> "`LJK` 与变量名 `ljk` 只差大小写 —— 加别名解决不了（别名归一后等于变量名本人，
> 该写法会变歧义）；请把 txt/脚本里改成 `ljk`，或把变量名改成不靠大小写区分的写法"

## 三、顺带修掉一个**静默**缺陷（写盘 API）

`append_rows_to_table(asset_dir, table_key, …)` 的键是**复数**
（`_STANDARD_TABLES = {'characters': …}`），而 `_TABLE_FIELDS` 是**单数**
（`'character'`）—— 我第一版就写成了单数，于是**静默返回 0**：
调用方以为写成功、用户以为别名加上了，其实什么都没发生。
现在：抽出唯一解析点 `_table_file_name()`，未知键**抛 `KeyError` 并列出可用键**；
`append_rows_to_table`/`update_table_paths`/`delete_rows_from_table` 三处统一。
（判据 `test_a_typo_in_the_table_key_is_not_silent`。）

另：`append_rows_to_table` 判"值变没变"用 `(cell.value or '') != (row.get(k) or '')`，
而 openpyxl 读空单元格给 `None` —— 空串列会被判成"没变化"（表里也不会出现空列，
效果一样）。所以 `plan_new_character` 的行里**只放有内容的列**，并写成判据。

## 六、用户追问的"显示名对得上就是同一个人"—— 实测确认：**一直就是这样**

> 用户 2026-10-10：
> > 通常来说都会定义显示出来的名称，如果显示出来的名称跟写在 txt 的字符串
> > 完美对应，那也是同一个人物啊？比如 `mm` 对应为妈妈，我在剧本里就写"妈妈"……
> > 不是无法匹配的

**✅ 对的，而且这是 `CharacterMap` 的 L2 层**（`Name` 列），一直生效。
`tools/probe_display_name_match.py` 实测真机 **16/16 命中**：

```
真机 characters.xlsx:  ID=mm  Name=妈妈   ID=jc  Name=「蒋忱」  ID=ld  Name=校领导
lookup('妈妈') -> ('mm','display')   lookup('「蒋忱」') -> ('jc','display')
lookup('蒋忱') -> ('jc','display')   lookup('校领导') -> ('ld','display')
整段：妈妈/「蒋忱」/蒋忱/校领导/保安/教官/校医 → mm/jc/jc/ld/ba/jg/xy，未映射 0
```
角括号/引号会自动归一 → 写 `「蒋忱」` 或 `蒋忱` **都行**。
**已补判据**：`test_writing_the_display_name_directly_just_works`（以前只有
`test_token_is_matched_by_display_name_too` 一条，且只测了带角括号的形式）。

⚠ 我当时说"`MOM`↔`妈妈` 算不出来"指的是**另一件事**：真机 txt 里写的是
`MOM"跟妈客气啥"` —— `MOM` 与 `妈妈` 之间**没有任何字符对应**（不是显示名对应），
所以它进弹窗要人点一下。**这两件事必须分清楚**，否则会误以为 L2 没做。

### 由此改掉的弹窗缺陷（用户提醒才看见）

### 之前的实机截图抓到的一个真 UI 缺陷（判据抓不到的那种）

"指到已有角色"那一行里**照样飘着「变量/显示名」两个输入框**：因为
`QLineEdit(token)` **没给 parent** → 它们属于**对话框**而不是那一行，
既不受该行布局管理、`setVisible(False)` 也管不住。
修法：建 `new_row = QWidget(self)`，控件挂在它上面，整块一起显示/隐藏。
（教训：Qt 里"没 parent 的控件"是隐形逃逸；**判据测得到状态，测不到摆位** ——
所以这条只能靠出图看。）
