# 2026-10-09 工作日志：M3-2 第一切片（`Show`/`Hide` 摊列）

> 前因（10-08 晚）：M3-0 设计审查推翻了"第一刀选 pause"等假设，改为 **`Show` 摊列**，
> 但当时没动手（见 `2026-10-08.md` §9）。今天按"模型侧纯函数 + 判据 → 再接 export/DV"两段走。

## Phase 1：模型侧纯函数 + 判据
- `beat_model` 新增：
  · `show_cell_parts` / `hide_cell_parts` —— 与 `compose_show_cell` / `compose_hide_cell` **同源**
    （原来那两处各写一套过滤，摊列再写第三套必然漂移）；
  · `SHOW_EXTRA_PREFIX='立绘'` / `HIDE_EXTRA_PREFIX='退场'` + `extra_field_names` /
    `extra_index_of` / `extra_columns_in`（**按序号升序**：`立绘2` 排在 `立绘10` 前）。
- `Beat.to_row(..., extra_fields=)`：摊列生效时**原列只放第 1 项**，第 2+ 项写进追加列；
  `Beat.from_row`：原列 + 摊列一起拆（**少读一边＝静默丢项**）。
- `_row_fields(spec_fields, extra_fields)`：动态段变**两族**（先「每参数一列」后「每指令一列」）——唯一拼法。

### 当场抓修的两类静默缺陷（判据驱动）
1. **项数 > 格数 → 静默丢项**：`to_row` 原来会把放不下的项**直接丢掉**（不报错）。
   修法=**安全阀**："放得下才摊"，放不下退回整格写法（读回来照样全在，只是这一行没有摊列下拉）。
2. **不摊却仍写摊列 → 读回来重复**（`a; b; c; d; b`）：修法=摊列**只在真摊时**写。

## Phase 2：接 export / 数据验证
- `excel_export._extra_headers_for(beats)`：列数上限 = **这批表里该列的最大项数**；
  没有多值的批次 → **一个摊列都不加**（"新功能不许动老项目"的底线）。
- 表头 / 数据行 / 列宽接上；**摊列每格绑图像候选 DV**（这才是 D4 的收益：一格一个才能挂下拉）。
- `Show`/`Hide` 的提示语在被摊时改为"第 1 个…（一格一个）"——否则提示会教人写回多值，把摊列绕回去。
- 表头自然连成族：`Show` 的中文表头本就是「立绘」→ `立绘 / 立绘2 / 立绘3`。

## M4 开工：`sync_asset_tables` 圈复杂 133 → 28（同日）
**做法：先录金标，再做纯结构拆分**（"只许动结构、不许动行为"）。

### 金标（`tests/test_sync_pipeline_golden.py` + `tests/golden_sync_fingerprint.txt`）
- 合成一个**确定性项目**，把四个现场一次摆进去：❶ 文件没了 → 删（占位行除外）
  ❷ 指向嵌套副本 → 改指  ❸ 改指后同文件重复 → 合并  ❹ 建表后才出现的文件 → 补登。
- 指纹 = **所有资源表逐格** + **返回 dict**，归一化后 sha256。
- ⚠ **归一化不是可选项，我在这连踩两次**：
  · 返回体里 `reconcile.table_resolved` 是 **set 的 repr 字符串** → Windows 路径反斜杠**双写**，
    只按单反斜杠替换一条都匹配不上；且 **set 的 repr 顺序随机** → 必须把 `{...}` 里的元素排序。
  · **单元格里也有绝对路径**（扫出来的行 Path 是绝对路径）→ 逐格哈希也要过同一套归一化。
  · 后来 `test_fingerprint_is_deterministic`（连跑两次必须相同）把"指纹可重复"也钉成判据。

### 拆分（行为一字不改；每拆一步都跑金标）
| 拆出 | 原来是什么 |
|---|---|
| `_reload_tables_and_diff` | 三处一模一样的"重读表 + 重算对账"（失败留痕、返回 None 让调用方保持原值） |
| `_sync_prune_stage`（❶）+ `_junk_nested_paths` / `_missing_paths`（两把纯查询） | 339 行里的删行段（嵌套副本 + 文件缺失两条判据） |
| `_sync_relink_stage`（❷） | 改指段（判据用路径尾巴不用 ID） |
| `_sync_dedupe_stage`（❸） | 合并同一文件的重复行 |
| `_sync_append_stage`（❹） | 补登 + 记侧车（按解析后真实文件判重） |
| `_sync_report` + `_ASSET_KINDS` | 两处几乎重复的返回体 + 反复出现的四类元组 |

**结果**：`sync_asset_tables` **133 → 28**（339 → 157 行），官方 `tools/health_check.py` 的
复杂度头部里**已看不到它**（头部变成 `render_beat_to_rpy` 81）；静默 except 回到 1 处。
