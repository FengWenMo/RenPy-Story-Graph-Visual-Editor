## Phase 1：模型侧纯函数 + 判据
- `beat_model` 新增：
  · `show_cell_parts` / `hide_cell_parts` —— 与 `compose_show_cell` / `compose_hide_cell` **同源**
    （原来那两处各写一套过滤，摊列再写第三套必然漂移）；
  · `SHOW_EXTRA_PREFIX='立绘'` / `HIDE_EXTRA_PREFIX='退场'` + `extra_field_names` /
    `extra_index_of` / `extra_columns_in`（**按序号升序**：`立绘2` 排在 `立绘10` 前）。
- `Beat.to_row(..., extra_fields=)`：摊列生效时**原列只放第 1 项**，第 2+ 项写进追加列；
  `Beat.from_row`：原列 + 摊列一起拆（**少读一边＝静默丢项**）。
- `_row_fields(spec_fields, extra_fields)`：动态段变**两族**（先「每参数一列」后「每指令一列」）——唯一拼法。

### 当场抓修的两类静默缺陷（判据驱动）
1. **项数 > 格数 → 静默丢项**：`to_row` 原来会把放不下的项**直接丢掉**（不报错）。
   修法=**安全阀**："放得下才摊"，放不下退回整格写法（读回来照样全在，只是这一行没有摊列下拉）。
2. **不摊却仍写摊列 → 读回来重复**（`a; b; c; d; b`）：修法=摊列**只在真摊时**写。

## Phase 2：接 export / 数据验证
- `excel_export._extra_headers_for(beats)`：列数上限 = **这批表里该列的最大项数**；
  没有多值的批次 → **一个摊列都不加**（"新功能不许动老项目"的底线）。
- 表头 / 数据行 / 列宽接上；**摊列每格绑图像候选 DV**（这才是 D4 的收益：一格一个才能挂下拉）。
- `Show`/`Hide` 的提示语在被摊时改为"第 1 个…（一格一个）"——否则提示会教人写回多值，把摊列绕回去。
- 表头自然连成族：`Show` 的中文表头本就是「立绘」→ `立绘 / 立绘2 / 立绘3`。
