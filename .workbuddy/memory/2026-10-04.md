### 为什么 B 是当前架构下**唯一正确**的选择（不只是"退而求其次"）

**"Notes 想不进产物"与契约 A1（`.rpy` 是唯一真源）根本冲突**：

  · 不进产物 → `.rpy` 里没有痕迹 → 从 .rpy 重新导入时它**必然为空** →
    这才是**真丢**（比现在严重）；
  · 要往返保真 → 必须进 `.rpy` → 而 `.rpy` 里能装自由文字的地方只有注释
    → 于是它**注定**会变成 `# 注释` 进产物。

所以"独立的、不进产物的私人备注"在这个架构下**不存在**。想"既要又要"，
唯一出路是把它做成**带标记的注释**（`# NOTE:` 前缀 —— 渲染时写、
解析时认回 notes 字段），而那是**新增功能**，不该混在修 bug 里做。

→ 结论：`Notes` 与 `Comment` 语义完全重叠（都是注释、都进产物），
删掉它、让用户用主区本来就有的 `Comment`，是**唯一自洽**的选择。

### "空壳 label"取舍的变异验证（决定性实验）

他问：给边界③加了"不产生空壳 label"，原始理由"防合并构建重名"实测
没能复现，已把注释改成与证据一致的口径——这个取舍如何？

我用变异给出硬答案：临时删掉 `beat_render.py` 的跳过行为
（`and False`）跑 `test_file_level_opaque_blocks.py`：

- `test_definition_only_file_gets_no_stub_label` **红** —— 单文件往返
  产物真的出现空壳 `label start: pass return`；
- `test_merged_build_has_no_duplicate_labels` **仍绿** —— 合并场景下块挂在
  第一张真拍上，**即使行为回退也不会重名**。

→ 结论三段：①"防合并重名"理由**确实是假的**（变异证明），删掉它是对的；
②行为本身**有真实价值**（防单文件产物被污染 + 防一次 LABEL_COLLISION 误拦，
危害可复现但有门禁兜底 → 定位是"省一次误报"）；③他的处理（留行为 +
注释如实 + 测试钉行为）是对的，且 `test_merged_build_has_no_duplicate_labels`
虽不构成"重名复现"，却钉住了"将来行为回退时合并产物不因此坏掉"。

**方法论沉淀（可推广）**：注释里的"防 X"理由三档处理——
危害能复现 → 留行为 + 补复现测试（理由从声称升级为证据）；
危害存在但有兜底 → 留行为，理由改写为"省一次误报"并注明兜底；
行为无法触发 → 删。**理由必须能被测试钉住，否则它只是注释。**
