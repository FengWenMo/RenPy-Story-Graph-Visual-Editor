# 2026-10-10（续 4）：补上"教工具认识自定义写法"的**入口**（用户报的缺口）

> 用户 2026-10-10：
> > 你说支持自适应的解析……但是我并没有找到一个入口可以教这个工具学会
> > 我自定义的项目模块……至于什么 `swim_suit` 一类的貌似无法做到呢……
> > 至少我想要个能够自定义的模块入口放在最上方

## 一、先说结论：后端一直是齐的，缺的是**发现 + 入口**

实测（`tools/probe_custom_statement_learn.py`）：

| | `swim_suit` 未声明 | 声明之后 |
|---|---|---|
| 能读写吗 | ✅ 解析成 `raw`、产物**逐字保留**（`swim_suit lyj "泳装" intensity=3`） | 一样 |
| 工具"认识"它吗 | ❌ **T3**：`工具完全不知道它是什么`（`readonly`） | ✅ **T1a**：`项目声明过…并给了参数形状`（`editable`） |
| 参数列 | 无 | `intensity` 成为表格列 |
| 候选值 | 无 | `spec_arg_choices` 给出 `1/2/3` → 下拉 |
| 产物字节 | — | **一个字不变** |

"教它"的写入口早就存在：`story_registry.declare_statement()`（CLI `storygraph
cli learn` 在用）。**但"该声明哪些名字"只能靠人自己知道** —— 界面上也没有
任何地方提示这件事（那句提示藏在 `describe` 的 `escape` 字段里）。

## 二、补的两半

### ① 发现：`statement_registry.discover_undeclared(project_root)`（纯函数，只读）

扫项目脚本，列出**未建模语句的头**（`{'head','count','samples','block'}`，
按出现次数降序）—— 这就是"发现"那一步。

⚠ 判据**照抄 `coverage_of_statements` 的口径**（不另立一套）：
`raw_kind` 在 `Statement.payload` 里、**不是 beat 属性**；`loop`/`camera`
没有 `raw_kind` 要显式认。**我第一版就是按 beat 属性取的** → 恒为空 →
一个候选都发现不了（探针当场看出来）。已被判据钉住。

### ② 入口：工具栏**最上方**「🧩 自定义模块 / 语句」+ 弹窗

`ui_qt/dialog_learn.py`（`CustomStatementDialog`）：左边是**发现**（写法/出现次数/
是否带块/原文样例）+ 已有声明；右边填一条声明（语句名、中文名、说明、是否带块、
参数表：参数名/中文名/候选值），下方实时预览"这会写什么"。
点左边一行 → 名字与"带块"自动填好。

表单 → 后端参数走纯函数 `authoring/learn_statement.build_declaration()`
（判据在这里，弹窗自己一条判据都不写）。它专门处理**表单里最脏的输入**：

| 用户可能写成 | 处理 |
|---|---|
| `intensity=3` | 按 `intensity` 处理 + **报出来** |
| 参数名写中文（`泳装`） | **丢掉并在预览里报**（后端对坏条目是**静默跳过**的，必须出声） |
| 同一个参数写两遍 | 只留第一次 + 报出来 |
| 语句名 `mycue cue`（多词） | **合法**（后端会拆成别名） |
| 语句名 `9bad` | 拒绝（按钮直接不可点） |
| 没勾"带块" | **不写** `block` 键（后端默认 `possible`，不确定就别写死） |
