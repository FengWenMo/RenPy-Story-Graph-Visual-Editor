## 三、⭐ 但挖出一个**引擎级根因**：这条路被引擎堵死了

引擎源码 `renpy/script.py:447-452`：

```python
for priority, fn, dir in script_files:
    if priority != last_priority:
        if renpy.parser.has_parse_errors():
            skipped += len(script_files) - count
            break          # ← 一组解析出错，**后面所有组都不解析**
```

`init python`（注册 CDS 的地方）属于**后面的组** ⇒
**任何未知写法都会让注册代码永远没机会跑**。

配合实测（三种布局全失败）：

| 布局 | 结果 |
|---|---|
| 注册与使用同文件 | ❌ `expected statement.` |
| 注册 `cds.rpy` + 使用 `script.rpy` | ❌ |
| 注册文件字典序在后 | ❌ |
| **没有 `parse=` 参数**的 `register_statement` | ❌（注册进了 registry，解析器那条路是 None） |
| 注册了但**不使用** | ✅（注册表里能看到 —— 这证明第一层的读取是好的） |

⇒ **"发现未知写法"与"问引擎"在同一个工程里不能共存**，
隔离工程**也救不了**（未知写法在哪儿都是 parse error）。

**所以四层方案要调整**：能问的是"**能编译**的工程上的东西"——
第一层（注册表里有没有）、第三层（行为断言），而不是"让未知写法变得可问"。
"未知写法"的判定仍然只能来自**扫描器**（它不需要引擎）。
