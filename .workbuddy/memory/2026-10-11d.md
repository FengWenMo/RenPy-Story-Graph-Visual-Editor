## 一、做了什么

新增 `storygraph/pipeline/statement_probe.py`：**把扫描出来的写法丢给引擎跑一遍**，
让引擎作证"认不认识 / 什么错"，而不是让人凭猜去填声明。

链路：`discover_undeclared`（发现，不需要引擎）→ **探针（作证）** →
结论进 `engine_facts.derived.undeclared_heads`（`ask=True` 时）。

判据 `tests/test_statement_probe.py` **21 条**。

## 二、真机三次实验换来的一条判据（每一步都是踩出来的）

| 试过的路子 | 结果 |
|---|---|
| ① "在 label 里留执行凭证" + 看 lint 文本 | ❌ **lint 不执行 label**（只跑 `init`）→ "没产出"分不出"项目有别人的 parse error"和"我们这行被拒" |
| ② 引擎自己的 `renpy.game.script.load_string()` | ❌ 真机实测它**不做词法校验** —— 连 `sg_definitely_unknown_xyz` 都"接受" |
| ③ **看 lint 报错行 + 紧跟的源码行** | ✅ 有效。真机形状：<br>`File "game/zz_storygraph_ask_bare.rpy", line 4: expected statement.`<br>`    weather sg_arg1`<br>**报错行与源码行是分开两行**，语句头在下一行 |

还有一条反直觉的实测：**带 `:` 的未知头会被接受**
（`sg_definitely_unknown_xyz sg_arg1:` + 缩进体 = 解析通过，Ren'Py 把它当合法的带块语句）。
⇒ 所以 `bare` 是"认不认识"**唯一可靠**的信号；`bare` 被拒时，`block`/`params`
的"没报错"**什么也证明不了**，必须留 `None`（判据钉住）。

## 三、又踩两个坑（都成了判据）

### ⚠ 把用户整个 C 盘写满了（真事故）

我第一版对**8GB** 项目整份 `copytree`，五个用例拷五份 → **磁盘 0 字节可用**，
一堆 `WinError 112 磁盘空间不足`。
⇒ 改成**轻量副本** `_copy_for_ask`：只拷 `.rpy`/`.json`/`.txt`，
跳过 `images`/`bgm`/`fonts`/`cache`/`saves`… 这些与语法无关的重目录
（缺失只会多几条 `is not an image`，**不影响 parse 结论**）。
真机实测 **8GB → 4.1 MB**，目录结构保留（空目录也建）。

### ⚠ 我第一版"一次 lint 问完一批"是**假绿**

引擎**报第一处 parse error 就停**。真机注入 `weather` 后跑批量：

```
File "game/zz_demo_custom_actions.rpy", line 2: expected statement.
    weather rain 强度=3
```

引擎在**用户自己的文件**上就停了，**根本没走到探针** —— 而我的判据把
"lint 没提到探针"当成"接受"，于是**把不认识的头判成了认识**。
⇒ 改成**一个头一次 lint**；并在跑之前先检查"项目自己干不干净"，
被挡住时返回 `ok=False` + **`blocked_by`（被哪个文件挡住）**，
**一个结论都不许给**（判据 `test_ask_many_says_who_blocked_it`）。

## 四、⭐ 一个**根本限制**（试过两种绕法都失败，如实记录）

> **项目里只要有引擎不认识的写法，引擎就编译不过，于是也答不了我们任何问题。**

因为那种写法本身就是 parse error，而引擎第一处就停。
⇒ "扫描扫到未知写法"与"引擎能回答"这两件事，**当前形态下不能同时成立**。

试过的绕法都不行：把写法放进 `python` 块当字符串（能解析，但**扫描器也扫不到**）；
注入 `register_statement("weather", …)` 再使用（仍然 `expected statement.`）。

**所以这条链路的正确用法**：

- **扫描线**负责"发现"（不需要引擎，自己就能判"这个头没人认领"）；
- **探针线**负责"作证"—— 回答**引擎能解析的那些**：头是认识的、只是工具没建模时，
  `bare` 被接受 = 引擎确实认识它；以及在干净项目上确认我们猜的参数形态；
- 项目**本身有 parse error** 时一律 `ok=False` + 说清被谁挡住。

## 五、真机验收

- 对照组（一定不认识的头）：`recognized=False` ✅，`blocks/params=None` ✅
  （头不认识时那两项测不出来，**不假装支持**）；
- 被挡住的情形：`ok=False` + `blocked_by` 指出是哪个用户文件 ✅；
- 磁盘：全程只用 4MB 级副本，跑完 `sg_ask_*` 临时目录为 **0** 个。
