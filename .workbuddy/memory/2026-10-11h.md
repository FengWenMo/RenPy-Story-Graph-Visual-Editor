## 二、⭐ 假绿①：`assert label X` 等不到

我原以为"证明执行了"该用 `assert label X timeout T`（它**确实有牙**：
等不到会 `RenpyTestAssertionError`）。但真机实测它**在正常执行时也判 FAILED**：

| 试法 | 结果 |
|---|---|
| `assert label X` + `run Jump(X)` | ❌ FAILED（它等的是"**当前停在该 label**"，而跳过去秒回、错过去了） |
| 让 X 里 `renpy.pause(20)` 停住 | ❌ 仍 FAILED，**证据文件也没落地**（jump 似乎没真跑起来） |
| 让 X 里 `while True:` 死循环 | ❌ 同上 |
| **`assert eval "证据文件存在" timeout T`** | ✅ **PASSED，且证据文件真的被写** |

⇒ 改用**证据轮询**：断言问的是"**那句话的副作用发生了吗**"，不是"引擎在哪"。

## 三、⭐ 假绿②（更阴）：`assert eval` 在条件不成立时也会 PASSED

反例跑出来 **`Status: PASSED` + `Assertions: 1 passed`，而证据文件根本没被写**。

⇒ 判定必须**两把锁**：
1. 引擎报 `Status: PASSED`；
2. **证据文件真的存在**（产品自己 `Path(...).is_file()` 复核）。

只有两条都满足才 `verified=True`；`PASSED` 但证据不在 → **`verified=False`**，
并明说"⚠ 即使 test 报 PASSED 也不能当通过"。
（判据 `test_status_passed_alone_is_not_enough_without_the_evidence` 钉住它。）

## 四、还有一个坑：Windows 路径的反斜杠

`assert eval "os.path.exists(r'C:\Users\…')"` —— 反斜杠把字符串弄坏，
表现为"**断言计数 0、用例 0.007 秒就结束**"（看起来像"语句没执行"）。
⇒ 生成探针时**统一转前向斜杠**（Ren'Py 自己就认这种），之后一切正常
（证据被写、`1 passed`、1.9 秒 PASSED）。

## 五、真机决定性验证（`tools/probe_layer3_api.py`）

用**产品函数**生成的探针、真跑引擎、读回结论：

```
① 语句真的执行  → verified=True   证据文件被写=True    （引擎 PASSED + 证据在）
② 语句没执行    → verified=False  证据文件被写=False   （引擎仍报 1 passed，但证据不在）
```

两条都符合预期 ⇒ **第三层现在是"有牙且不假绿"的**。

## 六、口径（给以后的人）

- 第三层**能证明**的：`run Jump(label)` 让脚本真的执行 + **外部证据**（写文件/改标记）；
- `Status: PASSED` **单独不足以**当判据 → 必须复核证据；
- 证据必须是"**只有真的执行了才会出现**"的东西；
- 抽不出证据路径时，**宁可造一个永不成立的条件**，绝不生成恒真条件假装通过。
