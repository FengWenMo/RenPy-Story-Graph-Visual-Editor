### menu 的修法（重要：没按我建议的改 IR）

我上一轮建议"给 Statement 加 `children`"，实际做法是**在渲染前把扁平拍重新
归组**（`beat_render.py:675` 拍序列 → 渲染单元序列，`_take_menu_run` 取整个
菜单组）。分组依据 = 解析器 `_walk` 里打的 `_menu_member` 标记（"这条语句在
菜单块内部"）+ "下一张 menu 拍即新组开始"（防连续菜单被并成一块）。

**权衡**：不动 IR 数据结构、Excel 仍是二维表 —— 务实。
**残余风险**：菜单结构现在依赖"拍的顺序 + 解析器标记"，是**重建**而非**保持**；
用户在 Excel 里重排/插入拍时分组可能错乱。这条值得后续观察。

### 追查"剩下 8 条丢失"时挖出的新问题（P1）

脚本 `tools/show_losses.py`（逐条列出丢失）+ `tools/audit_branch.py`（分支存活统计）。

**8 条的真相：只有 1 条是真消失，其余 7 条是表示形式变化。**

| # | 内容 | 定性 |
|---|---|---|
| 1 | `file "c:\admin_script.py", line 24, in <module>` 被识别成 say | **真消失**，但那是 traceback 垃圾数据，丢了无害 |
| 2 | python 多行块 `drag_puzzle(...)` ×2 | **没丢**，行号 250/271 → 9/26，内容完好（归一化比对误判） |
| 3 | `call screen drag_puzzle_game_screen` ×2 | **没丢**，kind 从 `raw` 改名 `code_line` |
| 4 | `show qing base at h11` / `show whitediamond at sessiontimerside` | **没丢，但被加了 `with dissolve`** |
| 5 | `l oh "3"` → `$ l oh "3"` | 被加 `$` 前缀（原文本身非法语句） |

**真问题（P1）：分支内舞台指令失去分支保护。**
全项目 `if` 182→27、`elif` 40→0、`分支内舞台指令 12→3`。
但要正确解读：带 condition 的 Beat 只有 **26 条 ↔ 产物 if 27 条**，
说明**演出流内的条件全部保住了**；182 的大头在 init python / screen /
function 这些**本就不归表格管**的区域，不进 Beats 是设计如此。
剩下真问题是 **9 个分支内舞台指令被提到块外无条件执行**。
典型：`script_pomo.rpy` 的 `if pomoplace == "ocean"/elif "cafe"/elif "library"`
三分支背景，产物里 `pomoplace` 出现 **3 次 → 0 次**，三个背景依次无条件
show → 最后一个生效 → 永远显示 library。**演出错，且不报错。**

根因同契约 30：扁平拍装不下"舞台指令属于哪个分支"。
`elif`/`else` 靠 `not((前一条件))` 展开（现 14 条）保住了台词分支，
但**舞台指令不进 condition，直接被合并进同一拍**。
