## 二、⭐ 由此定出的**三档 oracle 分工**（本轮最硬的结论）

| 要问什么 | 谁来答 |
|---|---|
| 这个**语句/语法**成立吗 | **`lint`**（实测 #6 有负样本验证） |
| 这个**属性/tag**合法吗 | **引擎枚举集合 + 自己比对成员**（实测 #7#8：lint 与 has_image **都会放行**，只能集合比对） |
| 这个**组合**兼容吗 | `get_ordered_image_attributes(tag, 已选)` |

⚠⚠ **`has_image` 不是合法性判据** —— 它对不存在的属性组合也返回 True。**这是"看起来对、静默错"的典型，必须写进契约。**

## 三、对两份反驳的评判

**全盘接受**：缓存新鲜度是漂移源｜第③级（引擎补丁）不可行且 diff 产物是代码不是契约 → **降级为"该重测什么的路标"**｜CDS"扫到"≠"生效"（加载顺序）→ **CDS 降级为"候选"**｜API 返回形状可能变｜lint 查不了语义（且实测连属性都不查）｜探针覆盖有限。
**需要更正**：
- "行为探测要大量工程且不可靠" → **错**：Ren'Py 已交付现成入口（`lint` 无头 + **官方 `testsuite`/`testcase` 框架含 `assert`** + 枚举 API）。工程界同构：**Netzob 拿真实现当 oracle 跑 Angluin L\***（带 `MQCache`）。
- "没有裁判 API 所以推不出参数形状" → **错**：裁判不需要 API，只需要**一次运行**；**变异即负样本**（实测 #6 证明回路通）。
- "headless 可能不行" → **一半被实测推翻**（#1#2）。

**真正缺口**（两份反驳合起来指出）：我上一轮的"四级阶梯"**只列了"候选从哪来"，没列"凭什么信"**。

## 四、修正后的模型：**两个轴 + 一个原语**

```
轴一 获取：① 引擎原生可枚举 ② CDS ③ 引擎补丁/就近声明 ④ 历史归纳 ⑤ 人手写
轴二 验证：ⓐ 无 ⓑ 枚举集合比对 ⓒ lint 判定 ⓓ 行为测试/变异探测 ⓔ 人确认
原语：membership query —— "这个写法，引擎接受吗？"
```
三条铁律：①未验证的候选只能显示「未验证」，不许当真值；②能验证就验证（语句→lint；属性→集合比对，**不是 has_image**）；③**验证失败 = 报错，不是"换一个"**。

## 五、新鲜度：把 dump 做成 **lint 的副产品**（解缓存漂移）

`lint` 本来就要跑，且实测 init 会在其中执行 → **把刷新挂在必经路径上，忘不掉**。
三层：①先比指纹（引擎版本 + 参与文件哈希）→ 一致直接用缓存；②不一致 → 标「可能过期」+ 后台重跑，**绝不把过期候选显示成真值**；③写盘前用到过期候选 → **构建报告点名**。

## 六、四类风险的处置

- **API 形状被魔改** → 防御式读取（`getattr` + 记 `type().__name__`）+ **两个独立来源交叉核对**（`.attributes` 对象 vs `get_ordered_image_attributes()` 字符串，实测都能用，不一致就报）+ 形状自检探针。
- **CDS 扫描≠生效** → 扫到的当**候选**，再用探针问一句"接受吗"才算生效；另查文件名加载顺序。
- **归纳(滞后) vs 裁判(实时) 冲突** → **裁判赢**；**冲突本身就是最有价值的报警**（"引擎变了，这些行可能不合法"= 迁移清单）。
- **冷启动** → 探针仍是唯一手段，但**必须先知道存在 `weather` 这个词** → 最廉价输入 = **人只报一个名字**（不是让人填形状）。**这是诚实的边界。**

## 七、诚实的天花板
探针只覆盖想得到的（靠历史用法喂）｜lint 边界是实测的（语句✅/属性❌/自定义语义❌）｜`--json-dump` 内容未验｜headless 只在最小工程验过，**真机 8GB 未验**｜完全无声的语法发现不了。
