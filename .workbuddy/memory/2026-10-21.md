## 用户问两个取舍（未入库的两处）—— 实测验证

### 取舍 1：章节作用域用 label（`line_id = label.序号`）
**结论：对，而且不用二选一 —— 当前实现已同时做到三件事。**
实测四场景（脚本 `D:/tmp/p0/scope_*.py`）：
| 场景 | 结果 |
|---|---|
| 表没改 + 源文件多一个 label | 不动文件（298→298） |
| 表改 1 行 + 源文件多一段 | 只改 1 行，新段保住（298→300） |
| 表删 1 行 + 源文件多一段 | 该删删、该留留（297→298） |
| 同上换成 10 个 label 的 `pomodorro` | 同样成立；`-8+2=-6` 数目严丝合缝 |

label 全局唯一由 Ren'Py 保证（真机 57 个 label，重名 **0**），所以"作用域串章"原理上不成立。

**真风险不在作用域，在粒度可见性**：`breakend.0027` 这一拍 = 7 行
（`$ renpy.block_rollback()` / `hide screen ×5` / `play sound`）+ 1 句台词。
删一拍 = 删 8 行，表里「代码」列有据可查，但 Excel 单元格默认一行高，视觉上看不见。
→ 建议删除时报「将移除 N 行 + 前 2 行预览」，比改作用域便宜。

**结构性隐患**：`表信息` 只记「来源文件」绝对路径，**不记覆盖了哪些 label**。
现在靠读源文件现算（实测撑得住），若将来改成"按记录的 label 集合"就会踩手工改 label 那一档。

### 取舍 2：`role_of` 只收紧「登记了但角色认不出」→ viewer，空串仍走 editor
**结论：对，但它是"防误操作"，不是安全边界。**
前提事实：`--user` 默认 `anonymous`（cli.py:879），**没有任何认证**；
`ensure_user` 默认角色就是 `editor`（collab_store.py:283）。
→ 陌生人第一次 push 就被自动登记成 editor；换个 `--user` 名就重新拿到编辑权。
→ 所以 viewer 只是"建议"。在无认证前提下收紧"未登记"只会锁死老库，一分安全都不多。

**一处设计味道**：空串同时表示"未登记"，而"空串 = editor"分散在三处兜底
（`_can` 的 `role or ROLE_EDITOR` / 两处 `role_of(...) or ROLE_EDITOR` / `ensure_user` 的 else）。
新增消费点忘兜底 → 静默变只读。建议 `role_of(conn, uid, default=ROLE_EDITOR)` 或返回 `ROLE_UNREGISTERED`。

**两个隐患**：①「无 owner 可认领」口子 = 空库里谁都能自封 owner（迁移必需，应"只用一次"+ 审计）；
② `role_of` docstring 与 `_can` 注释各说一半，容易只读一处。
