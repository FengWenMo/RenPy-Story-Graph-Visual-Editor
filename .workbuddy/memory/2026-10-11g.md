# 2026-10-11（续 7）：第三层——**跑通了，但发现了它的假绿**（结论要改口径）

> 用户："去第三层"。这一轮把行为级断言**真跑通了**（在真项目副本上），
> 但同时发现**它的判据是假绿的**，所以第三层的**正确用法要改**。

## 一、跑通了：`test` 的四条"前置知识"（都是实测）

| # | 事实 | 怎么发现的 |
|---|---|---|
| ① | `test` **不是"卡住"** —— 它跑完并打印报告，然后**进程不退出** | 我先前用 `subprocess.run(timeout=)` 等退出，误判成"卡住"。改成**边读边看 `[rpytest] Status:`**、见到就收进程 |
| ② | 它**需要显示**（`register_command("test", …, uses_display=True)`） | 无头真卡住；本机有桌面 → 能用 |
| ③ | 它需要 **`gui/` 与 `fonts/`** | 逐步撞：`Couldn't find file 'gui/window_icon.png'` → 补 gui；`Could not find font 'fonts/普力士Plix/Plix-Regular.otf'` → 补 fonts |
| ④ | `run` 收 **可调用的 Python 表达式** | 裸名 → `NameError: name 'sg_target' is not defined`；字符串 → `TypeError: 'str' object is not callable`；**给 Action `Jump("label")` 才行** |

于是拿到了第一个 **PASSED**：

```
[rpytest] Test cases : 3 | 1 passed | 0 failed | 2 skipped
[rpytest] Assertions : 1 | 1 passed
[rpytest] Status: PASSED
```

## 二、⚠⚠ 但它是**假绿**（这一轮最重要的发现）

我拿"**语句真的执行了没有**"这个铁证（探针执行时**往磁盘写一个文件**）来验断言有没有牙：

| 用例 | 证据文件被写 | `[rpytest] Status` |
|---|---|---|
| ① 执行 + 断言它执行了 | ✅ 写了 | PASSED |
| ② **不**执行 + 断言它执行了 | ❌ 没写 | **PASSED** ← 该红却是绿 |
| ③ 执行 + `assert eval "False"` | ✅ 写了 | **PASSED** ← 假命题也绿 |
| ④ **不**执行 + `assert eval "…" timeout 3` | ❌ 没写 | **PASSED** ← 加 timeout 也没牙 |

⇒ **`assert eval` 不是硬断言，而是"轮询条件"**：条件不成立时
**不会判红**，断言计数照样记 `1 passed`。
有牙的只有 `assert label X timeout T`（等 label 到达，等不到才 error）与
`assert True/False`（静态条件）。

## 三、所以第三层的口径要改成两条

1. **能证明的**：`run Jump("label")` 让脚本**真的执行**，再用**外部观察**
   （写文件 / 读变量 / 截图）拿证据 —— 这部分**有效**；
2. **不能当判据的**：`[rpytest] Status: PASSED` 本身**不足以证明断言成立**
   （假命题也 PASSED）—— 拿它当门禁就是第四层要防的那种**假绿**。

⇒ 第三层的正确形态是"**执行 + 外部证据**"，而不是"看 test 的状态"。
若要用 `test` 当门禁，**只能用带 `timeout` 的 `label` 断言**
（它等不到会 error）；`eval` 一律只当"辅助观察"。

## 四、状态

- 结论：**第三层跑通了，但它的官方判据是假绿的** —— 这条必须写进口径，
  否则以后有人拿 `Status: PASSED` 当"行为正确"的证据，就会把第四层辛苦做的
  "不当假绿"从后门放掉。
- 相关脚本：`tools/probe_layer3_testrun.py`（跑 + 读状态）、
  `tools/probe_layer3_evidence.py`（**用铁证验断言有没有牙** —— 这个手法值得复用）。
