## 二、核心结论（拍板口径）

**两个角度不是二选一，是一条环的两半** —— 学术名 **往返工程（Round-trip Engineering, RTE）**。
分水岭不是"选哪端"，而是 **"规则的真源放在哪、由谁维护、过期了谁报警"**。

**排座次（三层，不是单选）**：
| 层 | 用哪个 | 为什么 |
|---|---|---|
| **主干（写作面）** | **角度二 定义驱动** | 瓶颈在"编剧写"不在"工具读"；生成比解析简单；冷启动不依赖样本；行业同构（Naninovel / Yarn / articy） |
| **上游（规则来源）** | **角度三 契约驱动** | 定义不该人手写（会忘会漂）；从**引擎自己的声明**读 → 不漂移 + 冷启动 + 跨引擎 |
| **护栏** | **角度一 扫描反推** | **只做两件事**：发现未声明的写法 + 验"声明 ≠ 真实用法"的漂移。**永不当真源** |

**角度三 = 契约驱动**：引擎公布的契约（`renpy.register_statement` / Yarn `[YarnCommand]` / Naninovel `[CommandAlias]`）
是唯一真源；向下生成控件、向上识别校验，两向共用同一份；扫描只做对账。
**这正好是"能迁 Unity"的钥匙** —— 跨引擎的注册机制本身就是契约。

## 三、对那张对比图的评判（要点）

**对**：冷启动 / 生成器更简单 / 加一行就够 / "官方术语表"的比喻。
**错/漏**：
1. **"真源之争"混淆了两层** —— 本工具的一号铁律是 `.rpy` 是唯一真源；定义表集中起来的只是**形状(schema)**，不是内容。内容真源 vs 形状真源，不打架。
2. **漏了角度二自己的死穴 = 漂移**，且把"重新扫描"这个**解药**写成了缺点。定义表人手维护、引擎代码程序手改，两者**没有机制保证同步** → 工具会自信地生成"引擎不认"的东西。工业界（Protobuf/GraphQL/OpenAPI）的答案是 **schema-first + CI 漂移门禁**。
3. **漏了角度二验不了自己的产物** —— 定义写错，工具没有能力发现（它本来就不懂这门语法）→ 必须配"写出去让引擎/lint 检查"的回路。

## 四、调研要点（可复用）

- **RTE 的权威定义**（Wikibooks / TU Tampere / Visual Paradigm / arXiv 2608.05612）：
  "常被错误地定义成'同时支持正反两向'；真正的特征是**让两个各自演化的产物增量地互相反映**。"
  最可行的一种 RTE 是**框架 API 形态**："API 规定了正确用法 → 可**精确、完整**地识别用法并生成用法"。
- **语法归纳的能与不能**（Queen's Univ. Survey / MDPI MAGIc / arXiv 2608.05493 Autogrammar）：
  DSL **可**归纳，但**必须有负样本 + 人纠正**，否则过度/欠泛化；**GPL 太复杂**至今学不动。
  最新研究（Autogrammar）转向"**文档 + 执行数据**"一起学 —— 即**回到契约**。
- **schema-first**（codesparring.dev / api-contract-testing.com / thenodebook.com）：
  "把机器可读的契约作为唯一真源，实现由它生成或对它校验 → **契约不能在实现里静默漂移**"。
  CI 里跑 breaking-change diff，让漂移在构建期就红。

## 五、对项目的落点（重要）

**三件东西项目里已经有了，缺的是"摆正地位 + 补门禁"**：
| 角度 | 项目里是谁 | 现状 | 应变成 |
|---|---|---|---|
| 角度三 | `story/cds_registry.py` | 已做，但藏在体检报告里 | **定义的首选来源**；界面提示"让程序加一句注册" |
| 角度二 | `rules.json` 的 `statements[]` + `spec_args` + 卡片参数控件 | 已做，但界面是程序话 | **主干入口，全中文** |
| 角度一 | `statement_registry.discover_undeclared()` | 被当成"另一个入口" | **降级为后台**：发现 + 报警 |

**真缺的门禁（两个对账）**：
1. **定义 ↔ 真实脚本**：声明说 2 项、脚本里出现第 3 项 → 报；
2. **定义 ↔ 引擎契约**：CDS 说 3 项、定义说 2 项 → 报。
→ 这两个对账才是防漂移的东西，且正好落在既有的"要么全对要么完全不动"哲学上。

⚠ **诚实代价**：定义驱动 = 多一份要维护的 schema。只做"定义 → 生成"、不做"对账 → 报警，
**一年后得到一份漂亮但和引擎对不上的定义表**，比现在更糟。
⚠ 真机 `sr_general` **目前 0 个 CDS** → 角度三今天还没输入，但它是方向。
