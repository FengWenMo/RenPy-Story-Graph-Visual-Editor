## 一、最重要的发现：**工具在教错人**

真项目 `sr_general` 根目录下有一份 v1 界面**误导用户写出来**的声明（19:47）：

```json
{"statements": [{"name": "pause", "label": "等待", "columns": [{"name": "pause"}]}]}
```

`pause` 是 Ren'Py **内置**语句（`pause 1.0`，时长本来就是它的参数）——
**根本不需要声明**。所以这不再是体验问题，是**工具在输出错的知识**。

真项目"待认识"列表**一共 3 行，两行是噪声**：
```
with   x39   ← Ren'Py 内置（转场），且大多来自 screens.rpy 这种模板文件
window x9    ← Ren'Py 内置（开关对白框）
l      x1    ← **其实是台词**（`l oh "3"`，`l` 是角色表里「蓝」的 ID）
```

## 三、⚠ 我自己在这轮抓到的两个错（都值得记）

① **误诊用户写错**：第一版判据是"语句头 ≤2 字符 **且** 行里有引号 → 疑似写错"，
于是把 `l oh "3"` 说成"说话人写错了"。可 `l` 是**角色表里的角色 ID**，
那是**台词** —— **骂错人比不提示更糟**。现在先问角色表，且措辞改成陈述事实
（"这一行是台词"而不是"你可能写错了"），判据专门钉住这一点。

② `Statement.source` 是 **`(路径, 行号)` 元组**，我按纯路径取 → 样例显示成
`ch01.rpy', 2)`（判据当场抓到）。现在统一切开：文件名进 `files`，行号进样例。

③ 静态网 `test_single_write_entry` 又抓到新写入口 `remove_statement`（登记即可）。

## 四、设计方案（`docs/设计_自定义动作界面_v2_编剧版_2026-10-10.md`）

口径：**主语是编剧**。三段式单栏（不用左右对照）：

```
① 要认识哪个动作？   只列真正不认识的（内置的已会，不在此列）
② 给它起个编剧看得懂的名字   在编辑器里显示为：[ 泳装切换 ]  ← 编剧点这个
③ 这个动作要填什么？  每项**一行竖向**（名字 / 例子 / 只能填这些），多少项都放得下
④ 以后在编辑器里长这样（真控件，能直接点着试）    [ 就这样，教会它 ]
```

关键：**"要填什么"由工具从真实脚本反推** —— 编剧不知道参数名与候选，
但他已经写过这个动作若干次，那就别让他填：

```
outfit lyj "泳装" mood=happy   （出现 5 次）
  → 第1项 角色（候选=角色表：「凌跃捷」…）
  → 第2项 内容（候选=项目里写过的值：泳装、校服 —— **只出现一次的不算候选**）
  → 第3项 mood（作者自己写了名字，直接用）
```
⚠ **猜不出就不猜**：反推不出名字的项默认「第1项」「内容」「对象」，
**绝不生成 `intensity` 这种看着像真、其实是我编的英文名**。

`v1 → v2` 抄写对照（"语句名→动作名"、"参数→要填什么"、"候选值→只能填这些"、
"写进 rules.json→就这样，教会它"…）见设计文档 §五。
