### 调研结论 → 落地映射
- 表格作为唯一真源必然衰减（无字段约束/状态会烂/版本互相覆盖），
  "唯一值得升级成带必填字段的数据库的地方" → 八 用 SQLite 做后端。
- Story Architect 最受好评的小功能是"说话人乒乓"（回车自动换下一位
  说话人，双人对话 ping-pong）→ beat_editor 的 participants/next_speaker。
- "Project Health 视图：把结构问题集中一处，别让程序跑游戏时一个个撞见"
  → 七 三级校验 + graph_view「项目体检」面板。
- "不要自己叠加舞台状态"（同行普遍在客户端重算 scene/show/hide 导致漂移）
  → 二 舞台快照，且 Unity 导出文档明确要求直接读它。
- renkit / renpy-lint-action（构建自动化 + CI 校验）→ 七 build 命令 + cli.py。
- 稳定 line id 是存档/埋点/翻译/协作锁的共同主键 → Beat.LineId。

### 二 舞台快照 + 动态下拉
- 新模块 `stage_snapshot.py`：逐拍推导舞台状态（背景 / 立绘"谁·在哪" /
  音乐 / 音效 / 语音），严格按 StageOrder；同 tag 的 show 是**换表情**
  而不是叠人；bg/cg/ui 等非角色 tag 不算立绘（`_NON_ACTOR_TAGS`）。
- Excel 新增「舞台快照」派生表（导出与刷新候选时都会重写）。
- 应用内 `BeatEditorPanel.set_stage_snapshot()` + `stage_digest()` 实时预览。
- **动态下拉**：工作簿级名称 `CAND_<TYPE>`，公式
  `OFFSET(候选表!$A$3,0,0,MAX(COUNTA(...),1),1)`；下拉 formula1 指向名称。
  候选表里加一行，Excel 立刻能选到，不必再点"刷新候选"。
  名称写不进去时自动退回固定区间（兼容 WPS/旧 Excel）。

### 五 多引擎导出（`engine_exporters.py`）
- 架构：**先引擎中立 IR，再适配器**。`build_neutral_ir()` →
  `to_unity()` / `to_godot()` / CSV；`export_ir(engine, ...)` 落盘。
- IR 刻意做"平"（list of dict + 字符串数组），因为 Unity 的 JsonUtility
  **不能反序列化嵌套字典**；Godot 保留 stage 嵌套（JSON.parse 支持）。
- Unity 产物：`UnityDialogueData.json` + `UNITY_IMPORT.md`（含建议的 C#
  结构、"不要自己叠加舞台状态"、"lineId 是主键"两条约定）。
- Godot 产物：`STORY_IR.json` + 可直接用的 `dialogue_importer.gd` 载入样例。
- CSV 带 UTF-8 BOM（Excel 直接打开不乱码）。

### 七 三级校验 + build（`validate.py` / `build.py` / `cli.py`）
- 分级对应三种人：L1 单条（文案自己修）/ L2 表内（策划、组长）/ L3 全库（程序+主策）。
- `Issue(level, code, severity, message, where, hint)` + `ValidationReport`
  （`ok` / `to_json` / `format`），可被 CI 直接消费。
- **关键分级**：资产"未登记"在该类资产**已有资源表**时才算错误（E103），
  项目压根没建这类表时降级为警告（W110）——否则新项目 build 直接失败。
- 纯 `stop music` 不算空台词（否则 M1 的 stop 落表反被自己的校验判错）。
- `build.py`：`collect_report()`（只体检、不写盘，给编辑器用）+
  `build_project()`（体检 + 出产物 + build_report.json）。
  排除 `tl/`、`common/`、`renpy/`、`*.generated.rpy`（避免自我循环）。
- `cli.py`：`validate` / `build --engine` / `table rpy2xlsx|xlsx2rpy` /
  `collab ...`；退出码 0 通过 / 1 有错误 / 2 用法问题。

### 八 团队协作（`collab_store.py`，Excel 前端 + SQLite 后端）
- 表：`users` / `beats`(line_id 主键, payload JSON, content_hash, status,
  revision, locked_by) / `assets` / `audit` / `meta`。
- `push` 冲突规则：被别人锁着 → 拒；库里 revision 大于你 pull 时的
  revision → 冲突（不静默覆盖）；表里消失的行 → 软删除并留审计。
- `pull` 写出 Beats + 候选表 + **「协作信息」工作表**
  （LineId/Revision/LockedBy/Status/UpdatedBy/UpdatedAt）——push 靠它判冲突。
- 锁：`lock` / `unlock` / `lock_range`（整章认领）。
- 状态机 draft→in_review→approved + `audit` 全量留痕 + `status_summary`
  （按章统计 approved/in_review/locked、持锁人、最近变更）。

### 本轮又修掉的真 bug（都是"生成出来的脚本跑不了"级别）
- `render_transform_definitions` 用 `.strip()` 整段去空白，**吃掉 ATL 第一行
  缩进** → 块体首行顶格、后续缩进，生成的 transform 是语法错误。
  改为"去公共缩进后统一缩进 4"，兼容手填无缩进与解析自带缩进两种来源。
- 图像名被无条件 `空格→下划线`：对用 Ren'Py 原生 `tag attribute` 命名的项目
  （`show eileen happy`）反而改坏了。新增 `_emit_image_name`：**有资源表时
  优先保留作者写法**（能解析就原样），解析不了才退回下划线形态；
  无资源表保持旧行为（test_scale 依赖）。
- Doc 与 ATL 首个字符串字面量重复时不再重复输出注释。
- `Beat.ContentHash` 若沿用表里带过来的旧值，push 会把"改了内容"判成"未变"
  静默丢改动 → `_assign_identity` 改为**一律重算** ContentHash。
- 舞台快照曾把 `show bg rooftop` 当成"台上站着 bg rooftop" → 加非角色 tag 过滤。
- build 在项目没有资源表时 IR 里只有角色变量名没有显示名 → 用
  `registry_from_parse_result` 兜底。
