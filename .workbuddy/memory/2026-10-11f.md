## 三、③行为级断言 🔵：机制确认，工程前提未解决

✅ **断言语法确认**（读 `renpy/test/testparser.py:812-835` + 实测）：
`assert` **不认裸 Python 表达式**（我写的 `assert x == "ran"` → `Invalid condition.`）。
只认：`( 子条件 )` / `True` / `False` / **`eval <表达式>`** / `label <名>` / 选择器 /
`and`·`or`·`not`。⇒ 要写 `assert eval "标记 == 'ran'"`。

⚠ **未解决**：裸最小工程上 `test` **无头与有显示都卡住**（120s 超时），
而同一个工程 `lint` 退 0 ⇒ 与显示后端无关，`test` 似乎需要**完整工程骨架**
（主菜单/`start` 入口能被 test 机器人点动）。另两条实测：
夹具必须"能往下走"（直接 `return` → 停在主菜单 → 报 **Possible infinite loop**）；
夹具里的语句必须**引擎本来就认识**（用 CDS 注册的会撞下面的根因）。

## 四、⭐ 引擎级根因（重塑方案边界，必须记住）

```python
# renpy/script.py:447-452
for priority, fn, dir in script_files:
    if priority != last_priority:
        if renpy.parser.has_parse_errors():
            skipped += len(script_files) - count
            break          # ← 一组解析出错，后面所有组都不解析
```

`init python`（注册 CDS 的地方）属于**后面的组** ⇒
**任何未知写法都会让注册代码永远没机会跑**。三种布局全部实测失败
（同文件 / 跨文件 / 注册文件字典序在后），`register_statement` 不给 `parse=` 也必错。

**⇒ 方案边界的正确说法**：
- 第一层、第三层能问的是"**能编译**的工程上的东西"（注册表里有没有、某句执行了没）；
- "这是个未知写法"**只能**来自扫描器（它不需要引擎）；
- 第二层"隔离副本"承的是"**能不能问得干净**"，**不是**"让未知写法变得可问"。

用户把隔离副本放在第二层是对的 —— 它确实承重，只是承的不是那一件事。
