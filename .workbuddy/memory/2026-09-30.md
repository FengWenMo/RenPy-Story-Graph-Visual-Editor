## 卡片编辑器：修三个用户实测反馈的 bug

### Bug 1：**已导入的立绘不显示**（"确认台上确实有人"）

**两个根因，都只有真实数据才暴露**：

1. `asset_preview_path()` 返回 **`Path` 对象**，而 `thumb_loader.request()` 写了
   `path.strip()` → `AttributeError` → `SpriteCard` 构造失败 → `_make_card` 抛出
   → **整个 `load_beat` 崩掉** → 立绘区空白。**不是"没数据"，是"崩了"**。
2. 立绘区只读 `beat.show`，而历史数据里**大量立绘写在 Stage 列**
   （`[显示] 凌跃捷 开心 左`）→ 台上有人、界面空白。

**修复**：
- `thumb_loader.request`：`str(path or '').strip()`（接受 Path 与 str）
- `_sprite_thumb_path`：统一返回字符串（不再把 Path 往下传）
- `sprite_card.refresh_thumb` + `_make_card`：**加容错**——一张卡建不出来
  绝不能毁掉整次面板刷新（宁可少一张卡，也不能白屏）
- 新增 `stage_sprite_rows()`：把 Stage 列的 `[显示]` 读成立绘卡。
  **复用 `beat_sprite_rows`**（把 op 还原成 `X 开心@左` 片段再交给它），
  表情/位置识别逻辑**只有一份**——第一版自己拆 attrs，把裸词位置"左"
  当成了表情，迁移后 `凌跃捷 开心 左` → `凌跃捷 左`，**吃掉了"开心"**。
- 立绘区下方给明示 + 一键收敛：只有 Stage 有 → "迁移到立绘区"；
  两列都有 → "保留立绘区，清掉 Stage 里的"。**绝不自动改用户数据**。

### Bug 2：参与角色没有高亮"正在说话的人"（用户提了很多次）

`_highlight_speaker()`：对应行上底色 + 主色字，**标题旁再写出"正在说话：X"**
（颜色之外再给一处文字，不靠颜色单编码）。
注意：**高亮 ≠ 选中**——选中是轮转用的，混在一起会让列表选中随翻页乱跳。

### 需求 3 + 4：布局提前 + Stage 职责明确

- `PRIMARY_FIELDS` = `['Speaker','Text','Scene','BGM','Voice','Comment']`
  （Scene/BGM/Voice/Comment 从折叠的高级区**提上来**，并新开"舞台"小节）

## 用户报的两个严重错位 bug（"不信你拿真实项目查"）—— 查证并修复

### 用真实数据查证的结果（用户全说对了）

```
chapter1_3.rpy 第 45 拍： speaker='lyj'  show='ling disappointed@i11'
资源表： id='oh'   Tag='lan'  → characters/lan/oh.png     ← oh 属于 lan！
         id='_oh'  Tag='ling' → characters/ling/oh.png    ← ling 的 oh 是 _oh
```

### Bug A（用户标记为最严重）：说话人被**静默改写**

`next_beat()` 里有一段"参与角色轮转"：

```python
        speaker = next_speaker(self.rotation, cur_speaker)
        if speaker:
            self.beats[nxt].speaker = speaker      # ← 覆盖了用户已写好的值
```

按回车翻页时，它把**下一拍本来写好的 `lyj` 改成了 `dhy`**（轮转列表里的下一个）。
用户看到的"说话人不对"，根因在这里，不在解析器（解析器给的是对的）。

**修法**：`_advance_speaker()` —— **只在下一拍说话人为空时才补**，
已有值一个字符都不碰。轮转仍是"辅助输入"，不再是"改写数据"。

### Bug B：立绘**跨角色串图**

`_sprite_thumb_path` 的候选里有 `parts[-1]`（最后一个词）这一档：

```
'ling oh' → 'ling oh' 查不到 → 'ling_oh' 查不到 → 'oh' 命中 ← 那是 lan 的图！
```

**修法**：新增 `lookup_image_id(images, tag, rest)`，**先按 Tag 收窄**：

1. `Tag == tag` 且 Attributes 含 `rest[0]`（把中文名先用 `actor_image_tag` 归一）
2. `Tag == tag` 且属性为空
3. 名字直配（候选**必须带 tag**：`ling oh` / `ling_oh` / `ling_oh`）

**故意去掉了"裸属性名"和"_属性"两档** —— 它们在 tag 对不上时会命中别人的图。
结果：`ling oh → ling/oh.png`、`lan oh → lan/oh.png`、`叶怀瑾 oh → ling/oh.png` ✔

- **跨角色解析必须按 tag 收窄**：资源表里同名属性（`lan.oh` / `ling.oh`）很常见，
  用属性名裸查必然张冠李戴

## 下半场：把"逐句校对会不会改数据"当成体检项，一次挖出 5 条静默改数据的通道

用户仍在报"说话人/立绘错位"。上一轮只堵了"覆盖已有说话人"一条，但**同样的
症状还有别的入口**——于是换了个体检手法：

> **全章 305 拍逐句 `_show_index` + `apply_current_beat`，然后比对
> `render_beats_to_rpy` 的产物**。产物只要有差异，就说明"看一眼就改了数据"。

这个手法一次暴露 5 条通道（全部用真实 `chapter1_3` 复现，不是假数据）：

| # | 通道 | 后果 |
|---|---|---|
| 1 | 轮转写进**旁白拍** | `"旁白。"` → `aaa "旁白。"`（32 处相邻位置） |
| 2 | 轮转写进**纯舞台拍**（`hide ling` 自成一行，kind 仍是 say） | 凭空多一句台词 |
| 3 | `beat.at` 被填成"第一张立绘的位置" | 渲染时兜底套给所有没写 `@` 的立绘：`show ye care` → `show ye care at i11`（**立绘错位**） |

- `load_script` / `collect_beat` 一律用 `compose_stage_extra`（只放结构化列
  表达不了的部分）而不是整份投影；投影**标记成"已吸过"**，不再 hydrate
- `normalize_expression_words()`：表情词**逐词**归一 + 属性个数对不上就不动

顺带挖出并修掉的（同一片区域）：

- **主区四项写不回去**：Scene / BGM / Voice / Comment 明明在主区（永远可见），
  写回却和高级区共用一个 `_adv_open` 闸门 → 收起时（默认）改了**静默丢失**
- **高级区永远空白 + 展开就清空**：控件建的是 `state='disabled'`，而**只读的
  Tk `Text` 会静默吞掉程序化写入**（不报错、内容仍空）→ Stage / 代码块 /
  SFX / 备注 全显示空白；"看着是空的"又让写回把它们清掉。改为可编辑，

  `image_var`（载入时冻结）→ 点了 chip 数据变 `ling happy`、卡片还显示
  `ling oh` + oh 的图。现在三者同步；换图时也把新属性同步进 `expression`

## 第三场（用户第二轮反馈）：回车彻底不填说话人 + ↓ 翻页 + **批准 Stage 投影重构**

### 1）回车 = 纯翻页（用户原话："回车不要自动填说话人！！！回车是下一张卡片的意思！！！"）

上一轮只给轮转加了"三道闸"，用户要的是**整个删掉**——只要它还挂在导航
路径上，就有下次被改回来的机会。所以：

- `next_beat` 不再调用任何写说话的辅助；`_advance_speaker` / `_active_rotation`
  / `next_speaker` / `has_stage_content` / `AUTO_SPEAKER_KINDS` **全部删除**
- 便利性用**显式动作**保留：「参与角色」列表双击 = 把这个人填进**当前这一拍**
  （只改眼前这一拍，看得见、可改回）。标题同步改成"参与角色（双击＝填进这一拍）"
- 全章 305 拍走一遍回车：**说话人/类型被改动 0 处**

### 2）`↓` / `↑` 也是翻页（用户原话："按住下箭头也是下一张卡片"）

难点是**不能跟"移动光标"打架**，规则写进 `_on_arrow_key`：

| 焦点在哪 | 行为 |
|---|---|
| 左列表（Listbox） | **放行**——列表自己移选择＝换一拍，再翻一次会一次跳两拍 |
| 多行「台词」（Text） | 光标**已在最后一行**（↓）/第一行（↑）才翻页，否则让光标走 |
| 单行 Entry / 按钮 / 卡片 | 直接翻页 |

**踩到的坑**：`Text.count(..., 'displaylines')` 在**首行会返回 `None`**，
取下标就抛异常 → 被 `except` 吞掉 → "永远放行"→ ↓ 在台词里完全失效。
改用**逻辑行**（`widget.index('insert')` 的行号）判断：折行的长台词按 ↓
直接翻页（用户要的就是"按住下箭头翻卡片"），只有用户自己敲过回车的多行
才在行间移动光标。

### 3）Stage ↔ 结构化列的投影语义重构（用户明确批准）

**先只读分析真实数据**（这一步决定了修法）：

- 6 张表 1056 行里 Stage 列只有 65 行非空，且内容**全是结构化列能表达的**
  （`show` 32 / `[显示]` 23 / `[隐藏]` 12 / `scene` 8）
- `chapter1_2.xlsx`：**55 行的立绘只写在 Stage 列**（老写法）→ 所以 hydrate
  **必须保留**，不能"迁到新列就不读老列"
- 复杂 show 子句（`show cg … behind ye`）真实存在（chapter1_2 ×2、script.rpy ×1），
  也确实落在 Stage 列
- `chapter1_3/1_4` 的 Stage 列已清空

**三条契约**（写进 `tests/test_stage_projection.py`，23 个用例）：

1. **结构化字段是唯一真源**；Stage 只承载"结构化列表达不了"的东西
2. **hydrate 必须幂等** —— 真凶找到了：`_join_show_items` 早就带"同名同参数去重"，
   而 **`_join_hide_items` 漏了**，所以 `hide cg03` 被吸两次就翻倍
   （这就是"305 拍里 11 拍被改写"的来源）。补上去重 + 两处编码收敛成
   `show_item_part` / `hide_item_part` **一份实现**
3. **同一条指令只由一个通道输出**：
   - Stage 里的**原生真迹**（作者手写）→ 由 Stage 尾段**逐字原样**输出
     （`test_roundtrip` 明确要求"不做下划线改写"）；结构化列里那份只是
     hydrate 留下的**影子**，`_stage_lines` 跳过它（`_stage_native_show/hide/scene`）
   - Stage 里的**中文化写法**（`[显示] 凌跃捷 开心 at f11`）→ 已吸进结构化列，
     尾段按**语义**判断"已被承载"就跳过（`_stage_op_covered`，用的是与
     结构化列同一套片段编码，不再靠"输出字符串完全相等"）

### 一、增量编辑：先审计，量出 5 条硬伤（用户："不然恢复起来会非常麻烦"）

`patcher.py` 会**改写用户的 .rpy**，风险最高。用真实 chapter1_3 + 一个合成脚本
（含注释/空行/if/menu/jump/transform）量了一遍，**旧实现不能给你测**：

| 用例 | 实测（旧） |
|---|---|
| A 不改任何东西 | 产物 ≠ 原文：少 2 空行、挪 1 行、掉 1 个行尾空格 |
| B 只改一句台词 | 改动 5 行，且多/少行 |
| C 带 if/menu 的脚本 | **缩进被压平 → 语法坏掉**；`if` 变 `if not ((...))` 双写 |
| D 区间错位（源被手工改过） | **照样写入**，259 行被改写（没有任何守卫） |
| E Excel 导出路径 | 覆盖率 **0%** —— `src_first/src_last` 根本不进表，功能是死的 |

根因：① 替换行来自"无符号表的单拍重渲染"（与真实产物写法不一致）；② 缩进靠
"区间第一行"猜，嵌套块必错；③ 没有校验；④ 没有对位守卫；⑤ 行号传不过来。

**重写原则：要么全对，要么完全不动。**

- **一对一替换，行数永不变化**：按"行身份"配对（台词配台词且**说话人必须一样**、
  `show ling X` 配 `show ling Y`、`play music` 配 `play music`，其余只和逐字相同
  的行配对）。于是"什么都不改 → 逐字节等于原文"**天然成立**
- **缩进只来自原文**：替换 = 原文那一行的缩进 + 生成器的内容。缩进是结构，补丁不碰
- **纯色不算缺图 / 图名拼写不许改写**：`ling close_happy` 不会被压成 `ling_close_happy`
- **`recover_source_ranges()`**：表里读出来的拍没有行号 → 解析源 .rpy 按
  **内容**（不含台词正文！）对齐找回。Excel 路径因此从 0% 变成 97.4% 覆盖
- **两道闸**：逐拍"对位守卫"（原文这段得真属于这一拍）+ 整体校验
  （能解析 / 每句台词都在 / **生成器要的每条内容行都在** / label·return 不许少）；
  不过 → `ok=False` → 调用方退回全量。`ok=False` 时 `text` 不可用
- 表里删掉的拍会被 `dropped_beats` 发现 → 直接退回全量（不然源文件与表永远不一致）

**验证**（真实数据）：不改 → **571 行逐字节相同**；改一句台词 → **只差 1 行**；
真实数据里 **416 条生成内容行全部**能在原文找到同身份行（所以"内容行都在"这条
校验不会误伤）；`chapter1_2`（老表）也 OK。测试从 15 个加到 **31 个**。

**仍未支持**（按用户原话"新增跟删除行之后一步再做"）：加行/删行会让补丁
**拒绝**（退回全量），注释/代码内容不参与替换（保持原文）。
