# 2026-10-02 下半场：端到端往返实测（比上午那次更狠，抓到真 bug）

上午只测了"解析 + CLI"，**没测 Excel 往返**。下半场补上，结论翻转。

比对 Statement 多重集（归一化空白，排除纯空格差异后才是"真实丢失"）。

## 数据

- 全量测试 **1731 passed / 1 skipped / 556s**（比上午 1673 多，git 新提交
  "修复双IR问题"后新增）
- 真实项目 `sr_general/game` 41 文件 → **3803 Statement，解析 0 失败**，
  降级率 5.8%（raw 221：screen 129 / unmodeled 81 / call_screen 11）
- 往返**真实丢失 76/3803 = 2.0%**，但分布致命：
  **menu 5/5 = 100%、menu_option 20/20 = 100%、call 7/8 = 87.5%**；
  python 4.7% / raw 5.0% / show 1.3% / say 0.3%；
  comment·scene·hide·play·extend·jump·return **全 0 丢失**

## 三个确认缺陷

1. **P0　menu 块往返后整体消失**（`beat_render.py:314`）
   最小复现：2 选项 menu → 产物 `"选项A"` / `jump b` / `"选项B"` / `jump c`
   ——`menu:` 没了，选项降为**裸旁白**，jump b 无条件执行，**第二分支死代码**。
   游戏能启动、不报错、剧情全错。
2. **P0　`Beat.condition` 不落 Excel**：`to_row()` 22 个值里没有 condition，
   `from_row()` 也不读。`mini_game1.rpy` 往返 7 条条件 → **0 条**，
   产物 `if` 行数 5 → 1。注意**渲染层是对的**（`beat_render.py:329` 会写
   `if {condition}:`），丢在**序列化层**——所以 .rpy→.rpy 不出错，
   **一过 Excel 就丢**。
3. P1　台词尾部空格被吃（`'元神，启动！ '`→`'元神，启动！'`），
   `chapter0_0.rpy` 一处 116 条。语义无害，但违反"逐字节不变"契约。

## 根因（这次最值钱的判断）

**IR 是"语句流"，不是"语句树"，无法表达嵌套。** 15 个 kind 没有一个能带子语句。
同一根因的第二症状：`elif`/`else` 被展开成 `not((前一条件))` 的合取
（真实项目里 `not ((player_score == game_rounds))` 就是 else）。
`Beat` 是扁平拍 + `render_beat_to_rpy` 是**单拍**渲染器 → 结构上不可能重建
跨拍的 menu 块。

次因：**弱类型 IR + 过程式分派**。`payload: dict`，15 kind 共用 dataclass，
描述 kind 的声明有 4 份（`_HASH_FIELDS`/`_FACTORY_FIELDS`/
`validate_statement.required`/工厂签名），`validate_hash_contract()` 只串了 2 份
——实证：`_FACTORY_FIELDS[CALL]` 漏了 `from_clause`，自检没抓到（CALL 不参与
哈希被跳过）。**加第 16 个 kind 要改 N 处，编译器不提醒漏改** → menu 静默漏实现。
转换层是巨型 if/elif 而非按 kind 注册（`_parse_statement` 375 行 cc=59）。

## 为什么 1731 个测试全绿却没抓到（关键方法论）

**测试只测 A→B 半程，不测 B→Excel→B' 全程。**
`test_script_table.py:123 test_condition_from_if_block` 和
`:133 test_menu_option_becomes_own_beat` 都断言到 `beats_from_parse_result()`
就结束了，**没有导出 Excel、没有回导、没有重编译**。
做过 `export_beats_to_excel` 的只有 5 个测试文件，断言 menu/condition 的≈0。
→ **测试数量 ≠ 测试有效性，缺的是"往返不变式"这一整类测试。**

- 上午写"模块级 import 环 = 0"是对的，但**包级逻辑环有 4 条**（靠延迟 import
  压住）：assets↔story、parsing↔graph、pipeline↔story、app↔graph。
  **没有任何测试守卫依赖方向** → 契约 14 是"口头契约"。
- 修正我自己的误判：`graph/commands.py:4` 与 `pipeline/renpy_exporter.py:2`
  顶层 import 的是 `app/notify`，那是**设计正确的通知端口**（文档明令禁止
  import UI 框架），是依赖倒置不是泄漏。真问题在 **`app` 包是职责混杂的篮子**
