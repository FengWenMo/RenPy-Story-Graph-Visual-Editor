## 第十五轮：**导出这条大路** —— 先验发现的是"静默吞掉"，不是"拒写"

第十四轮补的是原地小改（接线 / 断线 / 留多久）。这一轮补**每天都在走的那条**：
改一句台词 → 导出。上一轮结尾我写的缺口是"被别人动过就退回"，
**量完发现说轻了**。

### 先验（`.pip-tmp/probe_r15_export_drift.py`）

最小项目、我改第 2 句（整卡重写），让别人在文件里动一笔再导出：

| 别人改在哪 | 从前 | 他那行还在吗 |
|---|---|---|
| 开头加一行注释 / 末尾加一句 / label 后插一句 | 拒写 | 在（没写） |
| **改了我没动的那一拍** | `ok=True`、写出去了 | **没了** |
| **改的正是我在改的那一拍** | `ok=True`、写出去了 | **没了** |

最后两行是这一轮的起点：补丁报"对位 3/3 拍，改动 N 行"、回执照样说成功，
而别人那一句被改回原样。**不是拒写，是静默吞掉。**

三条机制叠出来的洞：`source_unchanged()` 一假 → `trust_ranges` 关 →
只能靠内容证据认行 → 而用户改的正是那句台词（证据全没了）→ 退成
"说话人一样就认这一拍"（`_range_looks_like`）→ 把别人的行当成自己的改回去。
而"表过期守卫"只在他**加/删行**时才响，换行不响。

### 做了什么

- `load()` 多留一样东西：`_source_baseline_text`（解析出这些拍的**那份文本**，
  LF / 剥 BOM）。指纹回答"盘上还是不是那份"，底稿回答"**我**动了哪几行"。
  三方契约：`load` 写、`EditorSession.__init__` 初始化成 `''`、
  `ExportMixin.REQUIRES` 声明（`test_editor_session_mixin_contract` 守着）。
- `patch_export(..., base_text=…)`：**第 ② 步不读盘**，用这份当原文；
  `recover_source_ranges(..., source_text=…)` 也解析底稿（它数的 `dropped`
  会进删除通道 —— 数盘就是按别人的行号删行）。`RenPyParser.parse(path, text=)`
  是这一条的实现（沿用 `_src_cache`，`source_texts()` 仍然诚实）。
- `write_gate.merge_three_way(base, disk, draft)`：**纯判定**
  （`commit_text` 也改调它 —— 判定只有一处）。四态 `same` / `wrote` /
  `merged` / `conflict`。
- `session_export._settle_with_disk(...)`：导出的**第二道门**。
  只在"目标就是这一章的源文件"时合（导出到 build/ 是"我这一版"，不碰他的文件）；
  撞车 → 拒写，理由点到**第几张卡**（`card_at_lines`，用户面对卡片不是行号）。
- 两张嘴沿用第十四轮：短句进状态栏、长句进 `warnings`（控制台"提示"段 /
  剧本表确认框的"提醒"）。

## 第十五轮·续：**地狱测试**（`tests/test_hell_export_merge.py`，23 条）

功能判据证明"正常配合下它对"；地狱那一轮问的是"脏数据上、第二次、看不见的
字符上、他把文件改坏之后，会不会弄坏用户的文件"。判据全是**性质**：
幂等、逐字节、边界、失败时不脏、规模、对称性。

### 抓到的三件事（都修在这一轮）

1. **`write_gate` 用 `str.splitlines()` 切行 → 静默把一行撕成两行**。
   一行中间的 U+2028（从 Word 粘台词常带）被切开、`'\n'.join()` 拼回去，
   `"你好␨世界"` 变成 `"你好` + `世界"`，台词没结上引号 —— 而回执 **`ok=True`**。
   实测（`.pip-tmp/evidence_u2028.py`）：旧写法合并出来的那份重新解析是
   **1 拍、正文空**；新写法 2 拍、正文原样。`patcher` 早就只用
   `core.textlines.split_lines`，`write_gate`（第十四轮）是漏网的那一处。
2. **同一个坑的另一种后果**：`generation_guard.top_level_chunks` 也拿
   `splitlines()` 切 —— 那半截 `世界"` 看着像一条**顶层语句** → `OPAQUE_LOST`
   **假拒写**（补丁明明对了，用户被告知"底稿没能和表对上"）。连带把那组
   "逐行播报行号"的地方一起换了，否则 U+2028 之后报出来的行号全是错的。
3. **紧挨着 ≠ 同一处**：他在你改的那一行**旁边**加一行 → 拒写（判据没错），
   但消息说"改的正是同一处" —— 用户会去找"他什么时候改了我这句"，找不到，
   然后就不信这个提示了。`_clash_kind()` 现在把 `overlap` / `touching` 分开，
   两种都拒、说法不同。

### 还量了这些性质（都过，判据留着防回归）

合过之后再导一次不写也不多留旧版本 ｜ 他再改一笔还能再合 ｜ 拒绝时**逐字节**
不变 ｜ CRLF / BOM / 末尾无换行 / 混合换行时没碰过的字节一个不动 ｜ 他删掉的
一行不许被复活 ｜ 源被删 / 只读 / 他改坏语法：不崩不写 ｜ 2000 拍 + 他两处
远处改动（实测 1.9s）｜ 200 组随机不重叠改动的**对称性**（左右交换结果不变）。

### 探针本身的两个陷阱（写判据时同样要躲）

- `Path.write_text()` 在 Windows 上把 `\n` 翻成 `\r\n` —— 拿
  `read_bytes()` 跟 `text.encode()` 比就永远"文件变了"（我第一版探针报了
  两个假 P0）。比字节时**必须** `write_text(..., newline='')`。
- 别把"我的改动"也写进"他那份"里 —— 那当然撞车，测的是自己的构造错误
  （第一版 U+2028 用例就是这么假的）。
