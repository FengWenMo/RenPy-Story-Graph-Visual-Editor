## 第十轮：**关窗之后也能退** —— 磁盘上那几代备份，翻得到、放得回

起点是第九轮留下的那句话：撤销只有一次、且只在扩展窗口活着的时候（关窗就只剩
`.bak`）。这一轮先把"关窗之后到底有多没退路"量出来，再补上。

### 先验（`.pip-tmp/probe_r10_versions.py`，四个问题四个答案）

| 问的 | 量到的 |
|---|---|
| 连存三次，`.bak` 是不是每次保存前的逐字节原话？ | 是。两代（第一次时文件还不存在），内容与 `save#2/#3` 的 `undo.before` 逐字节相同 |
| 关窗重开之后「撤销上次保存」？ | 灰的（窗口里改一条 → 保存 → 材料有、按钮亮、按下去 `ok=True`；关掉重开 `_undo=None`） |
| 界面上读得到 `.bak` 吗？ | 读不到（`ui_qt/` 33 处全是提示文字；唯一真读的是 `asset_extensions.rollback_rename_patch`，资源表专用） |
| 手工整份复制回来？ | **单向门**：`copyfile` 前后备份数 3 → 3，刚顶掉的那版没进任何 `.bak` |

顺手量到两条没在清单上的：

1. **`save()` 内容一样也重写**：`ok=True`、`undo=None`，但文件 mtime 跳、备份
   5 → 5（新写一份、按上限把最老的带戳那份删了 = **白烧一代**）。
   `authoring/txt_pipeline` 2026-10-26 就为同一个毛病立过规矩，registry 漏了。
2. **`_reread()` 之后右栏是死表单**（`.pip-tmp/probe_r10_stale_form.py`）：
   `_current` 置 None、树重建，右栏还显示刚才那格；接着改 + 点保存 →
   `_save` 里 `if self._current is not None` **静默跳过**：界面"甲改过了"、
   文件还是"甲"。**这条上一轮（撤销）就踩过**，只是没量。

  `read_text_exact` 的世代读取、`restore()`（锁里：读现在 → 比对 → 写回，
  写前 `backup=True`）。

  `ext/registry._read_text_exact` 改成转发（同一份读者，不许两份）。

  返回多一个 `'unchanged'`；窗口状态栏如实说"没有重写（也就没多一代备份）"。
- `storygraph/ui_qt/dialog_versions.py`（新）：列表（时间 / 文件 / 内容摘要）+
  只读预览 + 「放回这一版」；放回成功发 `restored`，调用方重读。
- `dialog_extensions`：底栏「历史版本…」；`_after_restore()`（重读 + 撤销按钮灰）;
  `_reread(keep)` 现在**要么重选同一条、要么 `_detach_form()` 停用清空**；
  开窗没选中任何一条也停用。

### 坑

- **`**` 在 QLabel 里不渲染**：截图上是四个星号。界面标语用「」，文档里才用 `**`。
- **`QTableWidget` 默认 `wordWrap=True`**：一行一代会被折成两行，看起来像两代。
  `setWordWrap(False)`；最后一列用 `QHeaderView.Stretch` 才不被截断。
- **`reload()` 会盖掉状态栏**（它调 `_fill_status()`）：成功与拒绝两条路都踩了
  一次 —— 顺序必须是"先 reload，再写状态"，否则人只看到"现在：3 条"。
- **`Path.read_text()` 不认 `newline=`**（`TypeError`）：要逐字节读只能自己
  `open(..., newline='')`。这就是 `read_text_exact` 存在的理由，探针里也踩了一次。
- **探针的静态筛查不能太聪明**：我第一版用"去掉 `#` 之后还有没有 `.bak`"来判
  "代码里有没有读备份"，33 处全是字符串和文档字符串 —— 这不叫证据。真正的
  答案是去找**打开** `.bak` 的那几行（只有 `asset_extensions.rollback_rename_patch`）。
- **判据自己会把自己废掉**：`... == first ... or True` 写出来仍然"通过"。
  自己抓到、当场改掉；写断言时别在末尾挂 `or True`。
- **变异脚本的 `originals` 也要包括所有会被改的文件**：漏一个就是 `KeyError`，
  而它会以"变异失败"的面目出现，容易误读成"判据没抓住"。

## 第十一轮：**剧本也有磁盘退路了** —— 原地小改不再"什么都没留"

第十轮那句话只对 `.ext.json` 成立。这一轮看的是**真正值钱的文件**：章节 `.rpy`。
设计文档：`docs/设计_脚本历史版本_2026-11-08.md`。

### 先验（`.pip-tmp/probe_r11_rpy_backup.py`）

| 问的 | 量到的 |
|---|---|
| "改一句 → 导出"（`write_generation` + `merged_from_source`） | **有** `.rpy.bak`；连推 8 次正好 5 代（`KEEP_BACKUPS` 真在生效） |

结论：保护不对称 —— 整份覆盖有退路，频率高、专切手写稿的小改**一点没有**
（只有内存撤销，关窗即失效）。

### 做了什么

- `storygraph/story/version_store.py`（新）：`history_dir()`（判据是
  `relative_to(<根>/game)`，不是文件名猜测）/ `snapshot()`（写盘前存一代，
  去重 + 空转不存）/ `versions_of()`（历史目录 **+** 老 `.rpy.bak` 合并）/
  `restore_version()` / `summarize_script()` / `SCRIPT_STORE`。
- `story/version_store` 的落点：`<项目>/.storygraph/versions/<相对目录>/`，
  目录里放自忽略的 `.gitignore`（`*`），**不动**用户自己的 `.gitignore`。
- `core/atomicio`：`backup_file/write_text_atomic` 多一个 `backup_dir=`，
  命名与裁剪规则不变（固定名那份永不裁）。
- `core/versions`：`backups_of(where=)` / `restore(where=)`；新增
  `Store`（一个壳：怎么列 + 怎么放回）+ `CORE_STORE`；`UNCHECKED` 公开。

  原地小改家族全罩住了（`graph/commands` / `control_*` / `choice_point` /

- `story/roots.py`（新）：`project_root_of` / `guess_project_root` 搬出来，
  `paths` 里两个老名字保留成转发 —— 为了断掉 `paths ↔ version_store` 的导入环。
- 界面：菜单「🕘 这个脚本的旧版本…」（`window_recover.show_script_versions`）+
  `_script_restore_guard`（脏就不放回）+ `_after_script_restored`（重读 + 报拍数）；
  `VersionsDialog` 多两个注入口 `store` / `before_restore`。
