### 读到的机制（`story/beat_model.py:2578 _ordered_code_lines`）
它是**把 `ordered` 当消费序列**：逐条按记录的类型去 `raw` / `code` 两个行队列里取，
取不成就 `return None`；**`None` = 退回"raw 在前 / code 在后"的兜底顺序**。
⚠ 兜底存在的**理由**是"不猜"（注释：'此时返回 None 走历史行为，绝不猜'）。
⚠ 后果：兜底会把 raw 段与 code 段的相对位置抹平 → **相邻舞台指令 / `$` 行翻序** = 缺口 4。

### 5 个失效点（全部可测）
1. `ordered` 为空；
2. 条目解包失败 / `kind` 不在 `{raw, code}`；
3. ★ `pool[i] != line`（**池行 ≠ 记录行**）；
4. ★ `skip_raw` 没排空（`beat.raw_tokenized()` 与 `ordered` 口径不一致）；
5. ★ 末尾：两池**未"恰好"取完**（多一条、少一条都算）—— 只要有一条池行没被
   `ordered` 覆盖，整份作废。
（空行分支只 `append('')`、**不动游标**，所以它本身要成立的前提是"ordered 里空行条数准确"。）

## ⚠ 更正上面这条假设：**不是"缺口 4 / `_ordered_code_lines` 回退"** —— 已定位并修好

上面把 A 归到「缺口 4 家族的排序回退（`_ordered_code_lines` 取不到 → 退历史顺序）」。
**探针否掉了这条**：那条拍的 `ordered` 通道**是好的** ——

    beat #6: code='fc_moves += 1'  ordered=[('code','fc_moves += 1')]  → 正常产出
    beat #3: 15 条 code + raw      ordered 逐条消费干净                   → 正常产出

真正的根因**不在排序机制**，而在"**注释这条发射支**"：

1. **`beat_build._emit_comment` 漏了条件转发**：`branch_guard` 只做"条件不同就落拍、
   开新拍"，**不写条件**；舞台/透传那些发射器紧接着都会写
   `pending.condition = stmt.condition or pending.condition`，**只有注释这一支漏了**
   → 分支内的注释成了 `condition=''` 而 `nest_path='if:2'` 的**孤立拍**
   （结构位说"在 if 里"、条件却是空的）。
2. **`beat_render` 把注释无条件排在条件头前面**：`pre + [cond_head] + 块体`
   → 改成 `[cond_head] + (pre + 块体)`。
   依据：**能跟条件拍并进同一拍的注释一定来自分支内部** —— `if` 之前的注释带的是
   外层条件（通常空串），与分支条件不同，会被 `branch_guard` 拆成它自己那一拍。

"一轮之内不稳定"的机理：产物里注释已在 `if` 前 → 再解析时它归属到**上一拍** →
第 2 轮又换位置 → 审计报"第 1→2 轮变形（不幂等）"。

## 要治的病（不是"词表不一致"，是"切分口径有六份"）

## 做了什么（全部在新文件 `core/vocabulary.py` 里）

1. **`tokenize_show_words(text, keep_commas=True)`** —— 分词**真源**。
   从 `renpy_parser._tokenize_show` **整块搬来**（逐字），那边改成薄转发。
   为什么必须搬：朴素的 `str.split()` 会把
   `at Transform(xysize=(1920, 1080))` 切成 `Transform(xysize=(1920,` ——
   **一个 Python 语法错误**（真机 `mini_game_puzzle.rpy` 实测）。
2. **`ShowWordRoles`**（`tuple` 子类，NamedTuple 风格）+ **`classify_show_words(text, intros=)`**
   —— 纯函数，返回 `target` / `intro_kind` / `clauses` / `words`。
   `intro_kind` 五种：`image` / `expression` / `screen` / `layer` / `none` / `unknown-intro`。
   `intros=` 参数用来表达 verb 差异（`hide` 只有 `onlayer`；`scene` 不认 `expression`）。
3. 四个站点改成**只声明语义**、切分交给真源：
   · `renpy_parser._parse_show_scene` —— 只做"角色表 → dict"的翻译；
   · `beat_stage_parse._clause_image` —— `intros=()`（**刻意**：它切的是"舞台片段"，
     不是"资产引用"，口径与从前逐字相同）；
   · `excel_export._unknown_show_words` —— 非 `image` 直接跳过（`show screen …` 没有立绘属性）；
   · `asset_registry._extract_image_spec` —— 非 `image` 返回 `''`（调用方跳过）。
4. **删掉三个"别名表"**（它们只是同一份集合的第二个名字，是下次漂移的落脚点）：
   `renpy_parser._SHOW_KEYWORDS` / `_SCENE_KEYWORDS`、`beat_stage_parse._SHOW_ARG_KEYWORDS`、
   `excel_export._SHOW_KEYWORDS`（后者历史上正是那张"漏 `onlayer`、多带 `on`"的表）；
   顺手删掉 `renpy_parser._NO_IMAGE_INTRO`（同一件事的第二份口径）与两处悬空 import。
   剩下两处**刻意保留**为"取词边界"（各自注释写明语义）：`learn_statement._NOT_A_VALUE`、
   `asset_registry_constants._SHOW_STOP_WORDS`；`generation_guard` 那一份（`at` 之后）也在。

## 两个"逐字一致"的坑（探针抓出来的，不是推断）

1. **`_strip_show_comma` 不许贪心**：`show expression Text("SEIREN PROJECT",
   color="#89c7fe", size=60, bold=True) as title:`（真机 `screens.rpy:1439`）里
   逗号是 **Python 参数分隔符**。第一版写成 `while tok.endswith(','): tok = tok[:-1]`
   → 得到 `Text("SEIREN PROJECT" color="#89c7fe" size=60 bold=True)` ——
   **一个语法错误**。改成只剥**末尾那一个**（`removesuffix` 语义）。
2. **`_extract_image_spec` 要先剥行尾注释**：`scene white with Dissolve(1.5) #白色转场`
   （真机 `screens.rpy:1448`）在**旧循环**里是"注释恰好排在 `with` 后面"才没进图像名；
   换成 tokenizer 之后注释会黏在最后一个词上（旧实现也会把
   `ling close_happy  # 27号图片…` 的注释吃进名字里 —— 那是个**旧 bug**，顺手修好）。
