## 一、先认框架错在哪

我把"零依赖"当目标，于是把**该由程序花一行解决的事**（写 CDS 注册、写验证函数）
硬扛成"工具自己想看懂"，最后撞上引擎级不可能（§12.7），还留着一条"改 SDK"的邪路。

**正确形态**（用户原话，写进口径）：
- **验证合法性**：调 `lint`（已实现）**或让程序提供一个验证函数**，工具去调；
- **获取形状**：扫描 CDS 代码**派生声明**，或**让程序写声明文件**；
- **测未知写法**：隔离副本 + 数字前缀注入（已实现）；
- ⇒ **"工具会自动派生 / 自动调用"** —— 程序多写一行，工具自动跟上。

**删掉那条邪路**：不在"改 SDK 预注册"上继续投入（证据与入口留在 §12.7 备查）。

## 二、地狱项目（`tools/make_hell_project.py`）

**造法 = 借真实项目的规模 + 塞进合成边界**：

- 外壳借 `sr_general` 的 `.rpy`（105 个，真实的章节结构、真实的对白规模）
  —— 让工具面对**真规模**，不是玩具；
- 里面塞 **13 个地狱文件**，每个针对一个具体边界并写明"攻击目标"：
  ① 自定义写法 ② **覆盖内置语句**（`pause`）③ **计算出来的名字**
  ④ ATL 块冒号（曾经的 31 假阳性）⑤ **内置关键字**（with/window/at/pause）

  ⑩ 只有注释 ⑪ **多词语句**（键是元组）⑫ 缩进不一致+行尾注释 ⑬ 裸参数；
- 生成物在 `.pip-tmp/hell/`（**临时区**，含真实项目内容 → 不进版本库），

## 三、攻击结果（`tools/attack_hell_project.py`）：✅3 ｜ ❌2

### ❌ 缺陷 1（**静默漏报**，最危险）—— 已修 ✅

```
unknown_statements(地狱项目) → 0 种     ← 而项目里明明有 weather！
discover_undeclared(地狱项目) → ['lyj', 'weather']   ← 两个出口互相矛盾
```

根因：未知写法的判据是"带**具名参数**"，而那个正则**只认 ASCII 标识符**
（`\b[A-Za-z_][\w]*\s*=`）⇒ **中文参数名**让整行被判成"不是语句"：

```
_statement_head('weather rain 强度=3')  →  ''    ← 整行被丢掉
_statement_head('swim_suit lyj intensity=3') → 'swim_suit'
```

⇒ **工具会说"你的写法我都认识"**。中文项目里 `强度=3` 太常见，所以这是必踩的。
**修法**：标识符正则改认 Unicode 词字符（`(?<![\w])\w+\s*=`）；
判据 `tests/test_build_report_undeclared.py::test_a_chinese_parameter_name_is_not_dropped`
（**同时钉住台词不许被误报** —— 修这条时最容易顺手弄坏的地方）。
修后：`unknown_statements` 正确报出 `weather×1`。

### ❌ 缺陷 2（**用户会直接看到**）—— 待修 ⏳

`discover_undeclared` 把**台词的说话人**当成"工具还不认识的写法"：
`lyj "台词"` → 报出 head `lyj`（`lyj` 是**人物**，不是语句）。

为什么危险：这个列表就是界面「🧩 自定义模块」**左边那一栏** ——
编剧一打开就看到"`lyj` 是还没声明的写法"，会以为工具坏了。

已有的闸门（文档里写的三条）拦不住它：`lyj` 是 3 个字符，
不满足"名字 ≤2 字符 **且** 行里有引号台词"那条"疑似写错"规则。

**该怎么修**（下一步）：判据要**问项目的人物表** ——
"这一行是 `人物 + 引号台词` 的形状，且这个人物的 id 在人物表里" ⇒ 是台词，不是语句。
⚠ 不能简单用"有引号就是台词"：CDS 完全可以是 `mycue "闪电"`（用户自己的例子）。

### ✅ 扛住了的三条

- **采集**：13 个地狱文件里有 parse error → `ok=False` + 指名道姓；
  `collection.parse_clean=False`，**没有假绿**；
- **lint 分类**：`parse_errors` 正确指出 `hell_bare_param.rpy:6: expected statement.`；
- **UI 后端**：`discover_undeclared` 能发现（虽然带了 `lyj` 假阳性）。

⚠ 一条**已知限制**（不是新缺陷）：**同名 label 没被单独认出来** ——
因为引擎"一组解析出错后面全不解析"，所以重名 label 那条 lint 根本轮不到。
这与 §12.1 那条根因同源，**预期之内**。
