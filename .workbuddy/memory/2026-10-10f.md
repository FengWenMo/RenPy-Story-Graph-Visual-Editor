## 一、按钮为什么"点了没反应"（真根因，已修）

`window_graph_ops.learn_custom_statement()` 里我写的是：

```python
reg = self._session.registry()          # ← 这是 **资产注册表**（AssetRegistry）
report = SR.format_registry_report(reg) # ← 它要的是 **语句注册表**
```
→ `TypeError: 'AssetRegistry' object is not iterable`
→ **异常在 Qt 槽里被吞掉** → 用户看到的就是"点了毫无反应"（按钮本身可用）。

修法：改用 `SR.StatementRegistry.for_project(root)`。

**为什么我的判据没抓到**：我只写了"工具栏里有这个动作"的**存在性**判据 ——
**存在 ≠ 能跑**。现在补了 `test_the_toolbar_action_actually_opens_the_dialog`：
真的 `action.trigger()` 一次（把弹窗类换成桩），并断言控制台里**不许**出现
"失败/没写/Traceback"字样 + 必须打出"扫出 N 个"。
另加 `test_the_statement_registry_is_not_the_asset_registry` 把"两个 registry
不是一回事"钉死（全仓扫过：**只有我这一处**混用，其余 22 处调用点都对）。

## 二、"服装"该怎么让工具理解 —— **两条正解，机制不同**

### 路 A（推荐给"换衣服"）：服装 = 立绘的**属性**，靠资源表

实测 `tools/probe_costume_attr.py`：把图登记成该角色的属性之后，

```
images.xlsx:  Tag=lyj  Attributes=swim_suit / uniform / casual / happy / calm
attrs_of_tag("lyj") = ['swim_suit', 'uniform', 'casual', 'happy', 'calm']
              ↑ 这就是编辑器"立绘/表情"那一格的**下拉候选**
attr_for("lyj", '开心') = 'happy'      # 词表翻译
脚本：show lyj swim_suit → 产物逐字保留、候选里可选
```
**所以"服装"本来就能编辑** —— 只要它在 `images.xlsx` 里是这个 tag 的属性，
它就和"表情"一样出现在下拉里。它和表情**共用同一个候选池**（都是该 tag 的属性），
这正好对应引擎里 `show lyj swim_suit happy` 本来就合法这件事。

### 路 B（给"自定义指令"）：语句 = 声明出来的**参数列**

`swim_suit` 这种**指令**（带自己的参数，例如 `swim_suit lyj "泳装" intensity=3`）
用「🧩 自定义模块」声明，声明里写的每个参数都变成：
· **卡片**里的一组控件（实测 `spec_arg_fields_for` 给出 `swim_suit·pose=intensity`，
  候选值 `['happy','calm','sad']` / `['1','2','3']`，改完折回头行）；
· **表格**里的动态列（`swim_suit·pose` / `swim_suit·intensity`）。

**卡片编辑器确实有这一组**（`window_card._sync_spec_args` → `panel.set_spec_args`），
之前"看不到"是因为**没声明** —— 没声明时它只当「代码」列里的一行原文躺着。

### 所以该怎么选

| 你想做的 | 用哪条 | 判据/机制 |
|---|---|---|
| "这个角色现在穿泳装"（演出、要能选） | **路 A**：图进 `images.xlsx`（Tag=角色，Attributes=`swim_suit`） | `attrs_of_tag` 出候选；`attr_for` 翻译 |
| "自定义指令 / 状态开关"（带参数的语句） | **路 B**：「🧩 自定义模块」声明参数 | `dynamic_spec_columns` / `spec_arg_fields_for` |
| 两者可以同时用 | `show lyj swim_suit` + `swim_suit lyj "泳装" intensity=3` | 前者是舞台指令，后者是语句 |
