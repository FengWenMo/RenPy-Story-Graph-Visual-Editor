实测结论（都有探针输出，别只信文档）：
1. **假成功（P0）**：`show 小明 泳装开心` + 后两格 multi → `ok=True`，
   表情=`泳装开心`（不存在的值）。中文「有任意一个空格就不再按候选补切」
   是根因（`_tokens` 只在 `len(parts)==1` 时回退）。
2. **假失败（P1）**：分词用贪心最长匹配，DP 只拿得到已经定死的词 →
   `ab|cd` 能切的行，因候选里有 `abcd` 被切成假失败。
3. **引号（P0）**：不是没做，是"做了但值带引号" —— `"base swimsuit"` →
   服装值 = `'"base swimsuit"'`，且 `ok=True`。读值侧 `_unquote` 会把引号去掉
   → 试切与卡片两个答案（同一个旧病复发）。
4. **报错与界面互相否定（P1）**：`_assign_report`（单趟、多值格尽力吃满）与
   `best_spans`（partial 全局）两套口径。8000 例随机里 17 例：
   reason 说"第 N 格没词"，界面第 N 格却有值。拼错 `show`→`shw` 时，
   `shw` 还被当成角色值显示。
5. **代价临界（P1/待定）**：`COST_STOLEN=6 == 3*COST_UNKNOWN`，平局靠
   `range(0,n)` 的尝试顺序断；`dirty` 放前面被服装焊成 `dirty base_swimsuit`，
   放后面反而切对 —— 同一种垃圾两个结果。
6. `policy='candidates'` 跳过词不进 spans 但 `used` 算满 → **静默丢词**。
7. 性能：300 词 ≈1.4s，200 词护栏 2s 通过（multi 分支 O(m) × cost O(m)）。
