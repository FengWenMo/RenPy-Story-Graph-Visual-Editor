### 引擎语义（核实过，别再猜）

- `renpy.transition(t, layer=None, always=False)` = **登记"下一次交互"的转场**，不是立即执行
  （`[文档·other]`；renpytom 在 issue #1358：「scene 和 show 不产生交互」）。
- `layer="master"` 走的是 dict 层转场那条路径 → **不阻塞**、只动 master、台词照显。
  `[源码]` `with_statement()` 的 dict 分支对每层调 `renpy.exports.transition(v, layer=k)`
  后**直接 return、不调 do_with**。
- 所以「放 show 后面」在无 `with` 时与放前面等价；真正的敌人是中间的 `with` /
  `window show|hide`（都走 `with_statement(clear=True)`）会把它清掉。
- 更优：`define dis_master = {"master": Dissolve(0.1)}` + 表里「转场」列填名字；
  或 say 属性改立绘的项目用 `config.say_attribute_transition(_layer)`（官方、非阻塞、全书生效）。

### 实测数字（探针在 `.pip-tmp/probe_*.py`，6 个）

- 13 行样本：`show:sprite` + `after_last_show` 插 **3 处**；同拍两条 show 只插 1 次（插最后一条后）；
  有 `with dissolve` 的拍跳过；**重跑 0 处**（幂等）；
- 但 **`hide lan` 那拍漏插** → `change:sprite` + `after_last_change` 补上那 1 处；
- 表格路径（「代码」格）渲染顺序 = `show` → `$ renpy.transition` → 台词 ✅；
- ⚠ **手改 `Beat.code` 不重算 `ordered` → 这行跑到 `show` 之前**。位置真源是隐藏列 `ordered`，
  任何"给拍加一行代码"的新入口都必须同步维护它；
- `{"master": Dissolve(0.1)}` 填「转场」列逐字保留（清洗不动花括号/引号）。

### 真缺口（报告 §4 有证据）

P0-1 规则漏 hide（改 `change`）；P0-2 `when.transition:none` 不认 `window show|hide`
→ 插了静默失效（`_with_lines` 只认行首 `with`）；P1-1 不判"变化是否真的发生"（可用
`stage_entry` 做 `change: effective`）；P1-2 批处理是快照、需接进导出前 preflight；
P1-3 `define` 出来的 dict 转场不进「转场」候选。

### 否决

不加 `post_cue` 字段（会与「代码」格形成第二真源）；不给 `renpy.transition` 开代码特例
（批处理"不认识具体语法"才是通用性来源）。

## 重构自定义模块：从「填表」改成「指一行给工具看」

### 调研结论（决定了整个改法）

Ren'Py 的 CDS **没有 schema**：`renpy.register_statement(name, parse=...)` 里
`name` 只是一个词，语法全在 `parse` 这个**任意 Python 函数**里（`[文档·cds]`）。
所以"参数形状"只有两个来源：读 parse 函数体（容易读歪）／**剧本里真实写的那一行**
（可靠，而 `discover_undeclared` 早就在扫、还带 count+samples）。
→ 结论：**不是界面丑，是"手上有答案却还在问人"。**

### 改法（`authoring/autospec.py`，纯函数）

- `split_sample(line, head)` → 格子草稿（复用 `pattern.tokenize` 的词法，不另写）
- `call_columns(line, head)` → 技术调用参数列（`position`/`kw`，用 `call_expr.find_calls`）
- `guess_call_heads(texts)` → 哪些 `$ 名字(` 反复出现（排 renpy./内置/单字母）

三处落点：① `_on_pick` 带样例进表单 → **格子已建好**（点一条→按保存，两步）；
② 第 4 步「照着这行建格子」按钮；③ `dialog_calls.scan_project()` 扫剧本补表（只加不改）。

### 顺带修的真 bug

`discover_undeclared` 的语句头闸门是 `^[A-Za-z_][A-Za-z0-9_]*$`（纯 ASCII）→
**中文项目的自定义语句永远发现不了**（`renpy.register_statement("泳装切换")` 合法）。
`learn_statement._STMT_RE` 早在 2026-10-14 就改成 `[^\W\d_]` 了，这里漏了。
改成 `^[^\W\d_]\w*$`。

### 四类范式的共同点（结论）

**没有一家是"手写每个字段"的**：都让用户写一份声明，编辑器按**类型**机械生成控件。
且**一份声明多个消费者**（VS Code 同一份 schema → 设置页 + settings.json 补全 + 校验）。

| 来源 | 类型→控件 |
|---|---|
| Godot `@export` 家族 | `_range`→滑块、`_enum`→下拉、`_multiline`→大框、`_file/_dir`→选择器、`_color`→取色、`_flags`→多选勾、`Array[T]`→可增删列表、`_category/_group`→分组 |
| Unity | `[Range]`→滑块；`[CustomPropertyDrawer(typeof(X))]`→整类型换布局 |
| VS Code `contributes.configuration` | `boolean`→复选框（description 当 label）、`string/number`→输入框、`enum`→下拉、**`object/array`→不生成控件，给「Edit in settings.json」**；键名 `a.b.c`→层级分组 |
| RJSF | `schema`（数据）+ `uiSchema`（`ui:widget` 覆盖）两层分家；`if/then/else` 是声明里的条件字段 |

⚠ Godot 的 **Default Value Trap**：Inspector 改过的值盖住脚本默认值。
我们等价场景 = 表里已有的值不会因声明改候选而变（对的，但卡片上没说）。

### 我们真正的缺口（核对过实现）

`card_editor._spec_cell_editor` **只有两个分支**：`if opts → QComboBox else → QLineEdit`。
**`kind` 一次都没读** —— 所以 `keyword`（固定字，改了写坏脚本）现在是可编辑输入框，
`multi` 只有一句提示不是 chip，`number` 没数字框。
`_add_spec_cell` 也不读 `group`（只读 label/param/positional/multi）。

## 调研 2：Unity Inspector 为什么"舒服"（与我们的对照）

文档 `docs/调研2_Unity式Inspector为什么更舒适_2026-11-07.md`（本轮**未改产品代码**）。

### Unity 的五条硬规则（代码级）

1. **一行一条控件是架构事实**：IMGUI 的 `PropertyDrawer.OnGUI(Rect, SerializedProperty, GUIContent)`
   只拿到一块矩形，"By default there's only one control per line"（Unity 论坛原话）。
2. **层级=缩进**：`EditorGUI.indentLevel++/--`；Unity 画子字段时自动 +1/-1；
   自己做多列要先归零再恢复（`var indent = EditorGUI.indentLevel; ... = 0; ... = indent`）。
3. **标签宽度是全局常量**：`EditorGUIUtility.labelWidth` / `fieldWidth` ——
   所有行右对齐到同一条竖线，这是"整齐感"的物理来源。
4. **组标题/留白/说明是装饰器（DecoratorDrawer）**：`[Header]`、`[Space(10)]`、`[Tooltip]`
   都不绘制属性，只画装饰元素；`PropertyAttribute.order` 排顺序。**呼吸感是声明出来的**。
5. **绑定一行代码**：`new PropertyField(serializedObject.FindProperty("x"))` = 标签+控件+类型转换+
   prefab override+Undo；写回 `ApplyModifiedProperties()`。**且没有"保存"按钮**。

### 我们的六条差距（对到文件）

横竖混排（`_spec_form` QVBox / 台词 `QHBoxLayout` / 立绘 `_grid` QGrid / 备注条件横排）｜
label 宽度三处口径不同（`_spec_cell_label` 与高级区都 `setMinimumWidth(72)`，备注 `cap` 没设）｜
用**折叠**代替缩进（`_adv_host`）｜`T.SPACE` xs/sm/md 混用｜多个滚动区｜**有「保存这张卡片」**。

### 判断（用户问"哪个最符合编剧"）

**Unity Inspector 排第 1**，理由：编剧是**线性读者**，"读一列"和读剧本同一种眼动。
Godot 次之（机制像，但允许折叠）；RJSF 是问卷式；VS Code 设置页是**搜索优先**（找配置，不是顺读）。

⚠ **不能照抄的三点**：
1. 一拍是**复合**的（主句+附带），照抄会把主次抹平 → 保留"这一拍是什么"标题 + **附带缩进一级**（不要折叠）；
2. 立绘 chip 网格是例外（视觉素材要看得见），但一行只放一维（已做对）；
3. 卡片上**去掉提交按钮**（改成状态点 + 离开时统一提交），但这要用户拍板。

第 6 条建议最关键：**把"一行一个字段"做成守卫**（唯一构造口 `_row(label, widget)`），
否则"约定"三天就破 —— 本仓已有"一个落盘点一个登记"的先例。

## 调研 3：自定义模块面板怎么办（用户点名"最头疼"）· 仍未改产品代码

文档 `docs/调研3_自定义模块面板怎么办_2026-11-07.md`。

### 先纠正上一条

**Unity 完全能折叠**（`SerializedProperty.isExpanded` / `Foldout` / `[FoldoutGroup(expanded:false)]`）。
正确说法是"**默认展开 + 缩进表层级**，只有复合的、不常改的才折叠"——
我上一轮把"缩进 vs 折叠"对立起来是错的。

### 根因（一句话）

**它逼人直接编辑底层数据结构**（`pattern` 槽位 / `clauses` / `columns` 的
positional+multi）。Odin 给策划做工具的实战文章原话：
「为策划设计工具时，**最大的禁忌是直接暴露底层数据结构**。他们不需要知道 List 是什么。」

### 两条可直接照搬的做法

1. **`[SerializeReference]` + 子类下拉**：选类型 → **只画出该类型的字段**（foldout）。
   → 我们的"格子类型"就该这样：选「从候选选」才出现候选框，选「固定字」不出现。
2. **给非程序员的三条原则**（Odin 实战）：一眼看出该动哪里（左分类右内容，像打开 Excel）｜
   就地编辑不跳文件（`InlineEditor`）｜留自由但难改坏（`ReadOnly` 锁内部键 / `InfoBox` 说明）。
   另有"中央表格 + **侧边预览**"这一标准形制 —— 我们现在是"列表 → 跳页 → 表单"，中间缺一环。

### 建议（按性价比）

A. 格子改"一行一格"+ 类型驱动可见字段（中风险，有地狱测试守着）；
B. **右侧实时预览卡片**（低风险、观感最大）：`build_declaration()` → `dynamic_spec_columns()`
   → 复用 `BeatCardEditor._add_spec_cell`，因为它已经是"声明的消费者"；
C. `pattern`/`clauses` 合并成"带固定词的一格"（高风险，动契约，先不做）。

已用 mockup 画了改造后原型（左分类 / 中一行一格 / 右预览），用户看过后再定。

## 扩展平台第四轮：**一条声明只有一个能改的地方**

### 收尾时顺手抓到的第四个：**插件那条的「是否使用」关不掉**

`.pip-tmp/probe_plugin_switch.py`：插件声明调用 + ext.json 记
`{"id":"my_wipe","enabled":false,"override":true}` → 注册表里**还有**，
树上还显示 enabled=True（rules.json / 项目自己的那条都正常）。
根因：装载顺序 `内置 → 旧清单 → ext.json → 插件`，插件最后
`upsert(replace=True)` 把开关记录整个换掉；窗口里对插件点**还是开放编辑**的，
存进去的字段下次被插件盖回来 = 又一次"保存成功、实际没变"。

修：`ext/registry._apply_switches()`（开关记录留到插件之后再贴，只盖
enabled/batchable/batch）+ `dialog_extensions._switch_only()` 把 `plugin:` 也归进
"只能改开关"（字段表/种类锁上、保存只写 override、删除按钮说清"删了也会装回来"）。
判据 `tests/test_ext_switch.py` **11 条**。

## 扩展平台第六轮：**存盘前先对表**（两扇窗改同一份 `ext.json`）

先验 `.pip-tmp/probe_ext_conflict.py`（两份 `ExtensionRegistry` = 两扇窗，
各自在不同时刻读同一份文件，再依次 `save`）：

```text
① 甲窗改 alpha 的名字 → 存；乙窗（更早打开的）改 beta 的开关 → 存
   实到 alpha.label 变回 '甲'，两次都 ok: True            ← 甲的改动没了
② 甲窗新加 gamma → 存；乙窗跟着存一次
   乙又存了一次: [alpha, beta]                            ← gamma 整条消失
③ 别人加的顶层键（$comment / owner）→ 存完多出来的键: []  ← 被悄悄删掉
④ 甲窗删掉 alpha → 存；乙窗只改 beta → 存
   alpha 回来了吗： True                                  ← 删掉的又回来
```

再加一个 `.pip-tmp/probe_ext_shadow.py`：项目 `ext.json` 声明 `my_wipe`，
插件也声明 `my_wipe` → 窗口只剩插件那条、`problems=[]`（一个字都不说），
而且**什么都不改直接存 = 整份文件清空**（`save -> {'ok': True, 'count': 0}`）。

改的东西：

- `ext/registry.py::save`：**三方合并**（`base`=`_baseline` 装载时文件原话 /
  `mine`=`records()` / `theirs`=`_read_ext_records` 此刻磁盘），按 id 逐条判；
  决策逻辑拆成两个纯函数 `_merge_records` / `_compose`；`on_conflict` 只认
  `abort|mine|theirs`（别的值拒，不猜）；返回多 `conflict/conflicts/absorbed`。
  `_base_for` 处理"手工搭出来的注册表"（不知道 base → 只对自己写的几条有主张）。
- `_read_ext_records`：**落盘前对表**用的读法（与装载用的 `_from_ext_manifest`
  分工不同）—— 别人的顶层键、认得出 id 但读不懂形状的条目、没有 id 的条目
  全部**原样写回**。
- `records()` / `_record_of()`：形状归别处（插件/内置/旧清单）时写回的是
  "**文件里那条 + 只换开关三样**"。以前这里一个字都不写，于是被插件盖住的
  项目声明在下次保存时**整条被删**。
- `for_project`：`ext.json` 里**每一条**都在插件之后重贴一遍开关（不只
  `override` 记录）—— 开关跟着 id 走，形状才分来源；`_note_shadow()` 让
  "同名两条声明"进 `problems`（左树 ⚠ + 状态栏都能看见）。
- `set_enabled` / `set_batchable`：形状归别处的点自动置 `override`（探针
  `probe_builtin_switch_before.py`：以前关 `renpy.transition` 存完重装又开着，
  因为 `payload()` 把内置点整个过滤掉了）。
- `ui_qt/dialog_extensions.py`：`_save(on_conflict='abort')` → 冲突时
  `_ask_conflict()`（默认「否」= **这次不存**，「是」才 `on_conflict='mine'` 重存，
  且**刻意不先 `_reread`**）→ 存完 `_reread(keep)`（盘上重装 + 重建树 + 选中原条目）；
  `_delete_point` 被冲突挡住时不装成功（树也不许骗人）。

判据 `tests/test_ext_merge.py` **24 条**（六组：合并 4 / 别人的东西 3 / 冲突 4 /
同名两条 4 / 程序化开关 3 / 窗口 6），窗口那组有一条是**真点按钮**再回读文件。
变异验证（`.pip-tmp/mutation_r6.py`）：合并退回整份覆盖 → **13 红**；
`records()` 退回旧 `payload` → **17 红**；`_apply_switches` 只认 `override` → **1 红**；
`_record_of` 不换开关 → **2 红**。

坑：

- **`clicked.connect(self._save)`**：`_save` 多了 `on_conflict` 参数之后，Qt 把
  `checked=False` 当第一个实参喂进去 → 点"保存到项目"变成"不认识，没存"。
  `tools/audit_qt_signal_slots.py`（静态闸门）当场抓到；改成 `lambda: self._save()`，
  并补一条"真点一下"的判据。
- **分支数也是判据**：第一版把合并整个写在 `save` 里 = 34 分支，
  `test_tech_debt_budget` 立刻红（`complex_functions 195 → 196`）；拆成两个纯函数后 18。

  Command 参数值"）—— **写文件再跑**，这次又踩了一次。
- 合并的"我没动"必须用**规范形**比（`to_dict()` 两边同一套），否则每一条都会
  被当成"改过" → 全是假冲突。
