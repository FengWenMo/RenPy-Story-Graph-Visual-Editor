## 本轮修掉的 3 个真 bug

### BUG-1（最值钱）：编译器不认"路径形态"的音频引用 → 27 条假 TODO

真实项目脚本按惯例用**整条路径**引用音乐
（`play music "bgm/bgm02.mp3"`、`"pomodorro/music/cafe.ogg"`），
资源表里存的却是 ID（`bgm_bgm02`）。

`asset_registry.AssetIndex.resolve` **本来就实现了**"路径逐级退化"
（去目录名 → 去扩展名），引用抽取/校验都走它——**但编译器的
`dsl.Symbols.audio_row` 自己另写了一套**"ID + 剥 `bgm_`/`sfx_` 前缀别名"
比对，漏了路径退化。后果：文件存在、资源表也登记过，照样被写成
`# TODO: 缺少资源`。

- 修复：`audio_row` 改为走 `resolve_references(...)`（唯一解析链），
  再回本类别的表里取行（把住类型，避免音乐名撞上图片前缀被误判存在）
- 效果：全项目音乐 TODO **47 → 20**

### BUG-2：生成的脚本里带项目文件夹前缀 → 全是死引用

资源表 Path 的基准是扫描根，三种形态并存：
`sr_general/game/bgm/x.mp3`、`game/images/x.png`、`images/x.png`。
`audio_ref` 直接把 Path 抄进脚本，于是生成
`play music "sr_general/game/bgm/bgm02.mp3"` —— **游戏里必然找不到文件**。

- 修复：新增 `dsl.renpy_asset_path()`，只削 `game/` 之前那段
  （Ren'Py 素材基准就是 `game/`）；**没有 `game/` 段就原样保留**
  （`bgm/spring.mp3` 本来合法，猜错前缀比多留一个目录更糟）
- 效果：渲染结果含 `sr_general` 的行 **0**

> 第一次写这个函数时把"没有 game/ 段"的情况也压成纯文件名，
> 立刻被 3 个老测试抓住（`sfx/door.wav` → `door.wav`）。
> 这就是测试的价值——**改共享的路径语义一定会碰倒东西**。

### BUG-3：UI 按钮指向不存在的方法

`graph_view` 的「批量导入章节」按钮挂的是 `self.batch_import_chapters`，
可这个方法**根本不在 UI 类里**——函数住在 `renpy_parser.py`。
点下去直接 `AttributeError`。而且**没有任何测试覆盖 UI 接线**，
所以 846 个用例全绿也照样漏掉。

- 修复：在 UI 类上实现 `batch_import_chapters()`：多选 `.rpy` →
  `_run_async` 后台导入（避免窗口假死）→ `ReplaceGraphCommand` 提交，
  Ctrl+Z 可整体撤销 → 完成后报"新增几个章节节点"
- 顺手接上 `ReplaceGraphCommand`（它早就写好了、注释也写着"用于批量导入后
  撤销"，却**从来没被 import 过**）
- 补**静态接线检查** `TestUiWiring`：AST 扫源码里所有
  `command=self.xxx`，比对类里真的定义了哪些方法。无头环境实例化不了
  `GraphView`，这个检查能在 CI 上挡住同一类悬空回调

## 结论 / 教训

1. **"记忆说做完了"不等于代码里真有**。这次又靠"读代码 + 跑真实项目"
   才发现记忆里的 16 列/21 列说法都对不上实际的 20 列。
2. **共享语义（引用判定、路径输出）只许有一处实现**。BUG-1 就是
   "编译器自己又写了一套引用比对"的直接后果——一.3 那条"收敛为一处"
   当时只收敛了校验侧，**漏了编译器侧**。
3. **UI 接线要有测试**。846 个用例全绿，一个按钮却一点就崩，
   因为没人测"按钮指向的方法是否存在"。静态 AST 检查很便宜，值得有。
4. **改路径/引用语义前先跑全量测试**——本轮 3 个老测试当场抓住了
   过度削前缀，省了一次线上事故。
