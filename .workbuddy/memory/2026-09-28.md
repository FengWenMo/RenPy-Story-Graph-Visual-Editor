### 找到并修掉的 5 个独立缺陷

**F1. raw 与 code 的交错顺序丢失（最严重）**

真实项目那种"手机消息"演出是交替的：
`$ msg_add(…)` → `show screen` → `pause` → `hide screen` → `$ msg_add(…)`

`Beat` 把原生语句放 `raw`、python 放 `code`，各自保序，但**两者之间**的顺序
没有任何地方记。`compose_code` 直接 `raw + code` 拼接，导出会变成
"先全部 show/pause，再全部 $ msg_add"——**画面全乱，每张图都多停一会**。

修：`Beat.ordered` 记 `[('raw', 行), ('code', 行), …]`；`compose_code` 按它
还原（`_ordered_code_lines` 用"消费序列"校验，对不上就退回旧行为，绝不猜）。
读 Excel 时 `_split_code_cell` 重新按语句形态分类并重建 ordered。

**F2. 老表迁移把新表也吃了**

`LEGACY_STAGE_COLUMNS` 含 `Show/Hide/At/With`，而**当前 20 列表也有这些列**
→ `any(k in row for k in LEGACY_STAGE_COLUMNS)` 对每一行新表都成立 →
走进迁移分支执行 `beat.raw = g('Raw')` → 把刚从 CodeBlock 拆出来的 raw 行
（`show screen`/`pause`/`with`）**整批清空**，9 条 `hide screen` 全丢。

修：判据改成 `set(LEGACY_STAGE_COLUMNS) - set(BEAT_FIELDS)`（只认老表专属列），
且老表 Raw 列改为**追加**而不是覆盖。

**F3. 图像名被改写（把能跑的脚本改坏）**

`_emit_image_name` 用 `Symbols.image_ok`（校验用，严：要求资源表里有这个属性
组合）来决定生成写法。`show ling base_arms_akimbo close_happy` 在资源表里查不到
这个组合 → 被改写成 `show ling_base_arms_akimbo_close_happy`。**Ren'Py 里
这是完全不同的东西**，而且是"修好了能跑的脚本"。

修：新增 `Symbols.image_spec_ok`（宽松：tag 存在就放行——`tag + 多属性` 是
合法的 Ren'Py 写法）；解析来的 Beat（`Beat._from_script`）**逐字还原**，
连下划线都不换。`image_ok` 仍留给校验用。

**F4. `scene ... at X` 的 at 丢失，还被错套到立绘上**

`beats_from_statements` 的 SCENE 分支把 `payload['at']` 写进了 `pending.at`
（立绘位置）而不是 `pending.scene_at`。后果是双向错：背景的 `at bgfit` 丢了，
同一拍后面的 `show` 又莫名被套上 `bgfit`。

**F5. hydrate 追加导致 show 生成两遍**

`hydrate_from_dsl` 是"追加"语义（结构化列 + 高级列是同一条流水线的两段输入），
而 Stage 列往往已经写了结构化列的内容 → 同一项被追加第二次 → 导出两遍
`show`（重复执行转场，画面会闪）。

修：`_join_show_items` / `_join_hide_items` 按"同名同参数"去重。

## 本轮修掉的 3 个真 bug

### BUG-1（最值钱）：编译器不认"路径形态"的音频引用 → 27 条假 TODO

真实项目脚本按惯例用**整条路径**引用音乐
（`play music "bgm/bgm02.mp3"`、`"pomodorro/music/cafe.ogg"`），
资源表里存的却是 ID（`bgm_bgm02`）。

`asset_registry.AssetIndex.resolve` **本来就实现了**"路径逐级退化"
（去目录名 → 去扩展名），引用抽取/校验都走它——**但编译器的
`dsl.Symbols.audio_row` 自己另写了一套**"ID + 剥 `bgm_`/`sfx_` 前缀别名"
比对，漏了路径退化。后果：文件存在、资源表也登记过，照样被写成
`# TODO: 缺少资源`。

- 修复：`audio_row` 改为走 `resolve_references(...)`（唯一解析链），
  再回本类别的表里取行（把住类型，避免音乐名撞上图片前缀被误判存在）
- 效果：全项目音乐 TODO **47 → 20**

### BUG-2：生成的脚本里带项目文件夹前缀 → 全是死引用

资源表 Path 的基准是扫描根，三种形态并存：
`sr_general/game/bgm/x.mp3`、`game/images/x.png`、`images/x.png`。
`audio_ref` 直接把 Path 抄进脚本，于是生成
`play music "sr_general/game/bgm/bgm02.mp3"` —— **游戏里必然找不到文件**。

- 修复：新增 `dsl.renpy_asset_path()`，只削 `game/` 之前那段
  （Ren'Py 素材基准就是 `game/`）；**没有 `game/` 段就原样保留**
  （`bgm/spring.mp3` 本来合法，猜错前缀比多留一个目录更糟）
- 效果：渲染结果含 `sr_general` 的行 **0**

> 第一次写这个函数时把"没有 game/ 段"的情况也压成纯文件名，
> 立刻被 3 个老测试抓住（`sfx/door.wav` → `door.wav`）。
> 这就是测试的价值——**改共享的路径语义一定会碰倒东西**。

### BUG-3：UI 按钮指向不存在的方法

`graph_view` 的「批量导入章节」按钮挂的是 `self.batch_import_chapters`，
可这个方法**根本不在 UI 类里**——函数住在 `renpy_parser.py`。
点下去直接 `AttributeError`。而且**没有任何测试覆盖 UI 接线**，
所以 846 个用例全绿也照样漏掉。

- 修复：在 UI 类上实现 `batch_import_chapters()`：多选 `.rpy` →
  `_run_async` 后台导入（避免窗口假死）→ `ReplaceGraphCommand` 提交，
  Ctrl+Z 可整体撤销 → 完成后报"新增几个章节节点"
- 顺手接上 `ReplaceGraphCommand`（它早就写好了、注释也写着"用于批量导入后
  撤销"，却**从来没被 import 过**）
- 补**静态接线检查** `TestUiWiring`：AST 扫源码里所有
  `command=self.xxx`，比对类里真的定义了哪些方法。无头环境实例化不了
  `GraphView`，这个检查能在 CI 上挡住同一类悬空回调

### 影响后续扩展的障碍（新发现，按卡人程度排序）

1. **扁平导入 + 通用模块名**（`models`/`utils`/`build`/`compile`/`commands`/`layout`/`dsl`/`cli`）：
   不能作为库被 import（要靠 conftest 塞 sys.path），撞名风险高。
   这是"未来迁 Unity / 多语言复用"的**硬障碍**——现在这套代码无法被别的
   工具链复用，只能整体复制。
2. **无扩展点/插件机制**：`SUPPORTED_ENGINES` 硬编码元组 + if/elif；
   校验码（E101/W311…）是散落字符串；资产类型映射 5 份。
   加引擎 / 加校验 / 加资产类都要在多个文件里找点。
3. **"程序改代码 → 表格自动反映"是 1.5s 全目录轮询 + 全量重解析**

   全量解析 + 全量引用重建）。真实项目首次加载就要 `_run_async` 才不假死，

   更危险：`_apply_rename_patch` 会**正则直接改写用户的 .rpy**（带 .bak 备份），
   改名还是靠编辑距离推断（`_infer_character_renames`）——50 人团队里
   误判一次就是源码事故。
4. **Excel 前端的物理上限**：Stage 列无格级下拉（待办 7 已记）；
   候选表每次**整表删旧建新**（用户自定义格式/批注全丢）；无增量导出。
