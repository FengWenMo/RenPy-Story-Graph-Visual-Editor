## 二、⭐⭐ 推翻我自己：`lint` **会**校验属性引用

- 上一轮我写进契约："lint 不查属性"。**错。**
- **决定性实测**：单独放 `show lan 完全不存在`（去掉 `weather`）→
  `game/zz_bad_attr.rpy:2 'lan 完全不存在' is not an image.`，**退 1**。
- **上一轮为什么错**：`weather 雨 0.5` 是 **parse error**，**一旦发生，后面的语义检查根本不跑** → 我看到"零报错"就误判。
- ⚠⚠ **新铁律（已写进契约）**：**`lint` 没报 ≠ 没问题；必须先确认「没有 parse error」。**
- 真机 lint 报出**项目现有的真问题**（带文件:行号）：`'lan sideeye' is not an image` ×N、`'ye uh' is not an image` ×N、`'bgm/lyj01.mp3' is not loadable`、`'cg cg05' is not an image`…
- **修正后的 oracle 表**：语法 ✅ / **图像属性引用 ✅** / **资源存在性 ✅** / 兼容性 → `get_ordered_image_attributes` / 词汇与分组 → `.attributes` / 变换界面 → `--json-dump` / label → `get_all_labels()` / **`has_image` ❌ 不是判据**。

## 三、四个激进想法的评判（尽量实测）

| 想法 | 实测 / 判断 |
|---|---|
| 一 解析器当 oracle | ❌ **原形态不成立**：`import renpy.parser` → `ModuleNotFoundError: No module named 'renpy.cslots'`（先 `import renpy` 也不行）→ 解析器**只能在 launcher 进程内**用。⭐ 替代路：`renpy/arguments.py:285 def register_command(name, fn, uses_display=False)`（⚠ 注册时机待验证） |
| 二 MODIFICATION 注释 | ⚠ 可用，但只是"提醒"不是契约；**与项目既有"就近声明"一致**；必须配"改了源码+没注释=红灯"。**本项目无 fork → 今天无对象** |
| 三 AST diff | ⚠ **降级为"该重测什么"的触发器**；前提（源码在项目里）不成立；且 diff 产物是**代码不是契约** |
| 四 引擎自画像 | ⭐ **方向最对，我已用等价形态跑通**；但**它给的 API 清单有几处是错的**：`renpy.statements.registry` **不是 dict**、`renpy.display.transform.transform_functions` **不存在**。**正确做法：工具生成探针 `.rpy` → 注入副本 → 跑 lint → 收割 JSON**（零配合、不污染引擎、升级不丢） |

**最优组合**：`lint --error-code`（7 秒，覆盖语法+引用+资源）＋ `--json-dump`（155 transform）＋ 注入探针（词汇+分组+兼容候选），**三者合并成一次运行**，产出 `engine_facts.json`（可 diff、进版本库），探针**挂在 lint 必经路径**上 → 不会忘、不会过期。
