### 自动保存（`core/autosave.py` / `app/session_recover.py` / `ui_qt/window_recover.py`）

- 整章（`asdict` 全字段）+ `file_blocks` + 源文件 sha1，一次原子写。
  实测 284 拍 270 KB / 3 ms（`tools/_probe_autosave.py`）；不存差量
  （差量靠 `seq`/`line_id` 定位，而它们正是插删卡最先变的东西）。
- 30 秒一跳，**只在"可见 + 脏"时写**；看不见的窗口（测试/嵌入）不写不弹。
- **恢复 ≠ 已保存**：不调 `take_edits_baseline()`，基线仍停在磁盘 →
  `unsaved_edits()` 说的是真话，用户必须点「⤓ 导出」才落盘。
- **不重排 `line_id`**（协作主键、拍级三路合并的地基）。
- 源文件变过 → `src_first/src_last` 清零（交给 `patcher._fill_missing_src`），
  因为旧行号配新文件 = 把改动写到别人的行上。
- 两次防假警报：`_recovery_is_noop`（快照与磁盘逐拍相同 → 不问）；
  定时点发现"已经干净"→ 收掉快照（否则撤销回原样后重启仍会问）。

### 三条设计判据

1. **同一文件里换 label = 跳拍，不重读**（`_same_file`）；重读会冲掉未导出改动。
2. **换章前先抄快照**（`autosave_now()`），不弹"要不要保存"——每次翻章都问，
   三天就被闭眼点"否"；但丢掉的那份必须能捡回来。
3. **判 dock 开没开用 `isHidden()`**：恢复布局时窗口还没 `show()`，
   `isVisible()` 一律 False → 工具栏那个勾莫名消失。

### 坑

- **QSS 会把 `QTreeView` 的展开三角吞掉**（`::branch` 没样式就不画）：
  文件行左侧一片空白，想折叠找不到点哪儿。改自己在文字前写 `▾ / ▸`。
- 第一版 dock 标题 + 自绘标题重复两行；第一版模式条和十几个动作挤同一行
  （`addToolBarBreak()`）；第一版双击文件行 = 打开第一章（想折叠的人被换章）。
- `↻`(U+21BB) 在 offscreen 字体里是个点 → 按钮改文字「刷新」。
- **`QListWidget` 没有 `QApplication` 是直接 abort**，不是抛异常
  （新用例前 14 条过、第 15 条进程消失、无 traceback）。测试类补 `qapp` autouse。
- 信号审计抓到 `textChanged → _on_search_changed(_text='')`：**带默认参数的槽**
  正是"Qt 的 bool 被当第一个实参"那个坑的形状。显式收 `text`。
- ⚠ **别用 shell 文本管道改中文源码**：`Get-Content | Set-Content` 按 ANSI 读、
  UTF-8 写，整个 `ui_qt/inspector.py` 中文注释变乱码（恢复方式：整份重写）。

## 短板可行性评估（同日下午，接上一节）

**产出**：`docs/短板可行性评估_2026-10-23.md`（新建）。

**判据三问**：①补它会不会破三条护栏 ②它是"加功能"还是"加引擎"（加引擎一律不做）
③服务的是策划的命脉还是程序员的脸面。

**A 类（纯增量，零架构成本）**：分发三件套（**实测 zip 243 条目，xlsx/md/demo 全为 0**，
但 `demo/make_demo.py` 已存在，只是没进包）｜真机演示素材（环境问题非能力问题）
｜引擎事实用户可见化（`engine_facts.json` 已有，只是没人话层）
｜本地化走 XLIFF/PO（行业标准，现在走 Excel 是落后）。

**B 类（做通道不做引擎）**：TTS/翻译 → 只做三件护栏（**稳定 key** + 占位符保护 + 术语表/QA），
服务接 GPT-SoVITS/VOICEVOX/LLM；Unity → 加条件求值+菜单 UI，**不绑具体第三方库**。

**C 类（架构做不到 / 不该做，含根因）**：
- **真调试器**：根因是 Ren'Py 解释器不是我们的（要维护语句钩子+栈帧重建+DAP），
  且**方向相反**（我们说"策划不用碰代码"）。替代品该做：**探针注入 + 舞台快照 = "跳到某 label 抓帧给策划看"**。
- **实时协同自动合并**：①文本 CRDT 不懂 Ren'Py 的**结构嵌套**语义（选项可能挂错分支）
  ②CRDT 必须在真源层做 → 改 Excel/IR 当真源 → **护栏①当场破掉**
  ③"不碰别人字节"与"无锁并发写"数学上互斥 → 租约锁是承认现实不是缺陷。
  ⚠ 这是**产品决策不是技术问题**。
- **ATL 对等**：ATL 是 Ren'Py 特有语言，对等需在 Unity 侧写 ATL 解释器（=再写一个引擎）。
  能做结构+事件顺序对等+损失报告；**别承诺手感对等**。
- **探针的根本限制**（我们自己撞出来的）：引擎有 parse error 就答不了任何问题，
  两种绕法都失败 → 永远无法对"引擎不认识的写法"给引擎级保证。出路只有"扫描+教它升级"。
- **FieldSpec 没有 editable 旗标** → "策划能改哪些列"没契约 → 两个入口迟早打架。
  建议：**不是新机制，是把已有契约显式化**（加旗标 + Excel 派生列置灰）。

**⭐ 被漏掉的前置条件：稳定行身份**。
`LineId = f"{label}.{seq:04d}"`（beat_model.py:3405）→ **改字稳、插删后面全部位移**；
`_align_key`（label/kind/speaker/condition/舞台指纹，patcher.py:267）→ 改字稳、插删基本稳、**但不唯一**。
行业三种做法：Ren'Py 官方**正文哈希**（改字丢翻译，官方自己警告）｜Yarn `#line:` / Godot DM `[ID:KEY]`
（稳但要人写）｜**我们可以做到"内容无关+工具自动生成+插删不位移"**（地基已有，差一个不随 seq 漂移的编号）。
⚠ 这是 TTS/翻译/跨引擎**三件事共用的同一个前置**，做一次两处受益。

**建议顺序**：分发三件套 → **稳定行身份** → 引擎事实人话层 → XLIFF/PO → TTS/翻译通道
→ Unity 演出 → FieldSpec editable。
**明确不做**：真调试器 / 节点图编辑器 / 自造 TTS / 自造翻译机 / ATL 对等 / 实时协同自动合并。
