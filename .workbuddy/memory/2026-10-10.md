## 二、实测到的缺陷（按危险度）

### ⚠⚠ 缺陷 1：未映射说话人 = **产物里的未定义变量，Ren'Py 运行期必崩**

真机 5 章实测 **23 处**：`MOM`×13 / `A`×4 / `B`×4 / `LINGDAO`×4 / `JIAOGUAN`×3 /
`XIAOYI`×2 / `BAOAN`×3 / `TJF`×1。产物的形状是

```
    MOM "跟妈客气啥，上班顺手的事儿。"
```

而产物里**没有** `define MOM` —— Ren'Py 解析到这一句就是 `NameError`
（不是"显示成 MOM"，是**崩**）。校验器其实认识这种错（`E102 说话人 'MOM'
不在资源表角色里`），但**只在带资源表时**才报；txt 导入这条路上它跑不跑得起来
还要等 S3 接线。

**修法（两条一起）**：
1. 每个未映射 token 除原有告警外，**再报一条**："⚠ 若直接落盘，Ren'Py 会在这一句
   因**未定义变量**崩掉：先把它加进角色表（或补 `define X = Character("X")`）"；
2. 形状判据**收紧**（见缺陷 3）：必须"角色表非空 + 短缩写 + 不含下划线"才认。

### ⚠⚠ 缺陷 2：`Ljk` 与 `ljk` 是两个人时被**静默合并**（用户点名问的那件事）

```
旧：ljk 与 Ljk 在同一条归一化键上 → by_key 只留先登记的 ljk
    ljk"我是李佳凯"  →  ljk "我是李佳凯"     ✅
    Ljk"我是陆嘉珂"  →  ljk "我是陆嘉珂"     ❌ 说话人换人了，而且**只是"同一句"**
告警：只有一条"别名冲突"（还指错地方——让用户去改「别名」列，可变量名根本不是别名）
```

**修法**（`CharacterMap` 三层设防，语义想清楚了再写）：
- 只差大小写、且都在**变量层**的两个变量 → 该归一键进 `_shadowed`：
  **精确写谁就是谁**（`ljk`→`ljk`、`Ljk`→`Ljk`），
  任何不规范写法（`LJK`/`L_J_K`）→ `lookup` 返回 `Ambiguity`，
  产物**保留原文 token** + 告警，**绝不替人挑一个**；
- `Conflict` 分 `case` / `cross` 两类，`kind='case'` 的告警文案说的是
  "若他们**是两个人**，请改成不靠大小写区分的变量名（`ljk_li`/`ljk_lu`）"。

**踩过的坑（第一版我写错了，被既有判据当场抓住）**：
"精确写法压过归一化"如果做成"遍历 `by_key` 找相同变量名"，会把契约里的
**强层赢**（显示名 > 别人的别名）打掉 —— `lookup('乙')` 从 `('b','display')`
变成 `('a','variable')`（先登记的那个）。`tests/test_character_aliases.py`
**当场红了**。最终版：跨层撞车仍按强层赢 + 记 Conflict；只有同层大小写撞车
才进 `_shadowed`。

### ⚠ 缺陷 3：形状判据收得太松 —— `OK"好的"` / `L_J_K"…"` 也进产物

- `OK`/`USA` 这种英文词被当"全大写缩写"→ 产物里又一个未定义变量；
- `L_J_K` 更阴：归一化把下划线**丢掉** → 命中 `ljk`（作者根本没写过这个角色）。

**修法**：`_ABBREV_TOKEN_RE = ^[A-Z][A-Z0-9]{0,7}$`（短、不含下划线）
+ 要求角色表非空。边界**明确写进判据**（`test_shape_boundary_is_explicit_and_two_sided`）：
认 `MOM/TJF/A/B/OK/USA`（都报未映射），不认 `L_J_K`（下划线）、`LINGDAO2X`（>8）。

> ⚠ 我在这里**返工过一次**：先加了"英文停用词黑名单"去挡 `OK`，又为了挡 `USA`
> 想收成 ≤3 字母 —— 那是**为了让自己的判据变绿而发明规则**。停下来问"我的判据
> 真的对吗"，改成"边界写清楚 + 两头都钉住"，并把取舍（认英文大写字 vs 丢说话人）
> 写在 docstring 里。**判据错比缺陷更常见（J3）**。

### ⚠ 缺陷 4：整段 `.rpy` 被当纯文字粘进来 → **零告警**

一段 18 行的 Ren'Py 代码会被逐行变成旁白字符串（`menu:`/`jump`/`show` 全成台词），
`label start:` 成了一句旁白，**没有任何提示**。产物自洽、往返逐字节一致 ——
所以任何"往返/幂等"判据都发现不了它。

**修法**：`_looks_like_renpy_code()`（label / `$` / `python:` / scene|show|hide /
menu|jump|call|return|if|while|for），**≥3 行命中**才提示（纯文字里偶尔出现
`show`/`if` 不算），结果放 `ConversionResult.looks_like_script`，
告警建议走「导入章节 .rpy」。**只提示不改产物**（作者可能就是要在台词里演示代码）。

### ⚠ 缺陷 5：UTF-16 被"成功"读成 GBK 乱码，零告警

`read_text_file` 的 `utf-8 → gbk` 链：UTF-16-LE 的字节 `J\x00C\x00` **恰好是
合法 GBK 双字节** → 整章变乱码，`utf-8-sig` 只在**有 BOM** 时才报错。

**修法**：① 先看 BOM（UTF-16/32，长的先试）；② `utf-8` 之后若解出 NUL
→ 判定"这不是这种编码"，继续试下一个；③ 全失败抛
`UnicodeDecodeError`（错误信息里写清每一步为什么失败）。
实测：带 BOM 的 UTF-16/UTF-32 **现在能读对**；无 BOM 的抛错（可接受，调用方能报）。

### 🔸 缺陷 6：候选被单字母角色名污染（误导）

真机里有 `l`（「蓝」）→ `LINGDAO` 的"相近角色"提示是 `l`（前缀命中），
`ld` 的候选也是 `l`。**这不是提示，是误导**。
**修法**：单字符键不参与候选；反向包含只在 token ≥3 字符时才做。

### 🔸 已确认**不是**缺陷（省下来的时间）

- **括号在引号里**（`JC"他说（笑）了"`）会被"挖洞"成 `JC "他说了"` + 注释 `笑`：
  真机 5 章实测 **0 处**这种写法 → 属理论边界，不改（改了要动注释语义）。
- 生僻字符（全角拉丁 / 西里尔 / 零宽空格 / 软连字符 / 组合附加符 / 变体选择符 /
  半角片假名 / 阿拉伯-印度数字 / RTL 覆盖符）：**10/10 往返逐字节一致**，不改。
- 规模：1 万行转换 0.06 s、往返 0.62 s，无丢行。
- 单独代理对（`\ud800`）：转换不抛，是"写盘/编码"时才报 —— **合法输入不该有它**，不改。

## 四、留给用户拍板的一件事

未映射 token（真机 23 处）现在**保留作者写法 + 显著告警**，产物直接跑会崩。
两条路用户选一条：

- **A（现状）**：保留 + 告警，**逼**用户填别名/改 txt（"要么全对要么完全不动"）；
- **B**：为每个未映射 token 在产物**顶部注入** `define MOM = Character("MOM")`
  （带生成标记，游戏不崩、显示名就是 token 本身，一眼能看出该改）。

我倾向 A（B 会让"没填别名"这件事在游戏里看起来是好的）；但 A 的代价是
**产物在修好之前不可运行**。S3 接入 UI 时这个决定会直接变成"导入按钮"的行为。

## 五、顺带：全量回归暴露的**两个既有真缺陷**（静态网抓的，与本轮改动无关）

跑全量时 `tests/test_no_undefined_names.py` 报了 2 条。**用临时 worktree 在 HEAD 上复现过
（同两条）**，确认不是我引入的。两条都修了，因为它们是同一类"搬运行漏了东西"（M4 那批重构）。

### ① `patcher._is_new_content_row` 用了签名里没有的 `old_lines`

```python
def _is_new_content_row(body, old_heads, old_squash, file_squash):   # 旧
    ...
    if _is_missing_note(body) and any(_mentions(body, o) for o in old_lines):  # ← NameError
```

后果叠加：走到那一行 → `NameError`（补丁直接炸）；而这条判据本来正是
"`# TODO: 缺少资源 …` **不许顶掉作者原有的行**"（真机实测过：不做这条
"什么都不改"的导出会把 12~16 行 `play music` 变成注释）。修法：补参数 + 调用点补传。
判据加在 `tests/test_patch_grow_shrink.py::TestNoUndefinedNames`（含签名检查 +
"TODO 说明不许当新内容"直测）。

### ② `layered_model._expand_node` 给 `_expand_composite_call` 传了不存在的 `idx`

搬出 `_expand_composite_call` 时签名挂了 `idx`，调用点写 `..., idx)` —— 该作用域里没有
`idx` → **任何 `Composite(...)` / `LiveComposite(...)` 都是 `NameError`**（不是"展开失败"）。
函数内部本来自己算 `idx`，所以删参数 + 同步调用点。

顺手把同一函数的两处**静默丢图层**也修了（先按官方文档核对签名
`Composite(size, (x,y), 图, (x,y), 图, …)`，Ren'Py 8.5 文档已核）：

| 输入 | 修前 | 修后 |
|---|---|---|
| `Composite((300,600), (0,0), "body", (50,60), "face")` | ✅ 两层（这是唯一被测过的形状） | ✅ 两层 |
| `Composite((300,600), "only.png")` | ❌ "没展开出层"（整幅丢） | ✅ 一层 |
| `Composite("a","b")`（缺位置） | ❌ 只剩 `b` | ✅ 两层（`offset=None`） |

⚠ **诚实标注影响面**：真机项目 `sr_general` 的 layered model 里 `Composite` 出现 **0 次**
（helpers 147 个，模型条目 0）→ 这两条在**当前真机**上不触发，是"换个项目就炸"的
**既有**炸弹，不是本轮引入。判据加在 `tests/test_layered_model.py`（3 条，按真机
`definitions.rpy` / `effects.rpy` 的真实写法）。
