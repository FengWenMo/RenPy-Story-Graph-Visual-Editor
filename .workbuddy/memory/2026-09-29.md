# 2026-09-29

## 卡牌编辑器改版方案（已出方案，**尚未实施**）

用户提三个诉求：① 缩略图卡顿 + 多个立绘太占地方 ② 表情变化被当成多个角色立绘
③ 翻页（上一句/下一句）在最下沿、经常被挡住。
本轮角色是"界面交互设计专家"，**只出设计文档，未改代码**。

### 现状定位（都能对到代码行）

| 问题 | 位置 |
|---|---|
| 翻页按钮在底部条：`下一句 ▶` / `◀ 上一句` | `beat_editor.py:2037-2040`（`bar.pack(side='bottom')`） |
| 一个立绘 = 一整行 grid，缩略图与控件同行 | `beat_editor.py:1486-1532`（`_add_sprite_row`） |
| 缩略图 `max_size=(150,210)` 撑高行高 | `resolve_sprite_thumb` 默认值；`1499-1501` |
| 每敲一个字符就同步解码一次图 | `1535-1538`（`trace_add('write', _refresh_thumb)`） |
| 解码无缓存/无防抖/无后台线程 | `load_thumbnail`（`184-216`） |
| 表情与立绘并列成两张卡（同一 tag 换表情） | `beat_sprite_rows`（`318-348`）→ `_split_show_items` 逐项一行 |

### 根因

- **卡顿** = 同步解码 × 输入即触发 × 无内存缓存；且 Pillow 的 `thumbnail` 是
  "全分辨率解码后再缩"，成本与原图尺寸成正比（Excel 侧那条路已用 `im.draft()`，
  UI 侧没用——现成的数量级差距）
- **占地方** = 一行一图，行高由缩略图决定（≈210px/个），3 个立绘 ≈ 630px
- **翻页被挤** = 上面两条的**连带结果**，不是独立的布局问题
- **表情不直观** = 展示层缺"按 tag 聚合"。Ren'Py 里 `show ling happy` 后
  `show ling sad` 是**换属性**（场上仍一人），数据没错，是展示平铺错了

### 方案（文档：`docs/卡牌编辑器改版方案.md`）

- **A 缩略图**：防抖 120ms + 线程池(2，只做解码，`PhotoImage` 回主线程) +
  内存 LRU(60，key 含 `path|mtime|size|max_size`) + 复用磁盘缓存 `thumb_cache_dir` +
  `im.draft()`；无 Pillow 时降级不阻塞
- **B 立绘区**：网格卡片（96×128，一行 4~5 张），高度与数量脱钩；只解码可视区；
  选中卡 → 编辑区（不再每行塞满输入框）
- **C 表情**：按 tag 聚合成一张卡 + 表情 chips（当前生效高亮 + ✓）；
  同 tag 多条且位置不同 → 警告徽标（不是两个人，是数据异常）。
  **只在 UI 层分组，绝不动 `beat.show` 的存储格式**
- **D 翻页**：高频上移到顶部条（+ "第 N / 总数" 计数）+ `Enter / Alt↑↓` +
  底部条只留低频动作 + 固定高度不被压缩
- **E token**：对比度达标（取消 `#999` 承载文字，改 ≥`#757575`）、字号下限 8pt、
  状态不只靠颜色、骨架屏最多闪 3 次

### 下一步

等用户确认后按 **A → B → C → D → E** 顺序实施；每步都要在真实项目
`sr_general`（2902 图 / 146 变换）上实测手感，尤其"连续输入不卡"与"逐句翻页"。

## 卡牌编辑器界面设计方案 v2（评审 v1 后的修订）

角色切换为 UI Designer，**评审 v1 并给出修订版**：`docs/卡牌编辑器界面设计方案_v2.md`。

### 评审：v1 漏掉的致命问题

1. **表情 / 位置有两个编辑入口（真病灶，v1 完全没提）**
   - 面板级 `PRIMARY_FIELDS` 含 `Expression`/`Position`（`beat_editor.py:1216`），
     作用于**第一张立绘**（`_first_sprite_item`，`:305`）
   - 每个立绘行**自己也**有表情 Entry(w=10) / 位置 Entry(w=8)（`:1520-1523`）
   - 多立绘时两个入口改的东西不一样 → 用户必然困惑（"我改的是谁的"）
   - v1 只归因于"展示层没按 tag 聚合"，**只说对一半**
2. **异步加载会抖**：图晚到 → 卡片内容变化 → 布局跳动（应锁死图区尺寸，骨架同尺寸）
3. **✕ 16px 在密集网格里、删了不可撤销**（破坏性操作）

### v2 核心决策

- **消灭双入口**：`PRIMARY_FIELDS` 收敛为 `['Speaker','Text']`；表情/位置**只在卡内 chip** 改
- **卡片 100×176**（图区 88×118，按"脸部可识别下限 32–40px"推导，非拍脑袋）；
  3 个立绘 = 1 行 **176px**（当前 630px，降 72%）。比 v1 的 140 高 36px，
  但换来"chips 在卡内" → 改表情省 1 次点击 + 1 次视线往返（已写明取舍理由）
- **骨架锁尺寸**：图区固定，名字条/徽标不等图，消除加载抖动
- **删除 hover 才显示 + Toast 撤销**（不弹确认框打断流）
- **token 体系化**：light/dark 两套字典，组件只从 token 取值（一致性的前提）
- 补齐：空态、缺图态、键盘映射表、focus ring 规格（2px + offset 2px）、
  命中区（图标 ≥20×20、chip ≥24 高）、翻页首/末句禁用态、
  添加立绘改网格末尾虚线卡（原地 1 次点击）
- 现有继承提示色 `#0A5` 对比度仅 3.1:1（不达标）→ 改 `#1B7A4B`

### 待用户确认

卡片高度取舍（176 vs v1 的 140）、是否要 dark 模式、翻页是否保留底部副本。

## 卡牌编辑器界面改版：**已实施**（用户测试前）

新增 3 个模块 + 改造 `ui/beat_editor.py`。**1127 用例全绿**，真实项目体检 0 错误。

### 新增

| 文件 | 作用 |
|---|---|
| `ui/tokens.py` | 设计 token 唯一来源（light/dark 两套，含对比度核算）；**界面代码禁止写死色值/字号** |
| `ui/thumb_loader.py` | 缩略图异步加载：防抖 120ms + 线程池 + 内存 LRU(60) + 复用 Excel 侧磁盘缓存 + `im.draft()` |
| `ui/sprite_card.py` | `SpriteCard`（Canvas 100×176，圆角/骨架/名字/说话标记/chip/✕/选中✓）+ `AddCard`（虚线添加卡） |

### 改造（beat_editor）

- **立绘区**：一行一图 → **网格卡片**（一行 4–5 张，3 个立绘 630px → 176px），末尾虚线添加卡，空态说明
- **表情/位置**：只在**卡内 chip** 上点选（1 次点击循环切换），面板级不再有入口
- **按 tag 聚合**（`group_sprites_by_tag`，纯函数）：同角色换表情 = 一张卡；
  其余条目存 `extra_rows` 原样写回（**显示聚合、数据不丢**）；
  同 tag 多条且位置不同 → 卡上加 `⚠` 警告
- **删除**：hover 才显示 ✕ + Toast「已删除立绘「ling」」+ 8 秒撤销
- **翻页**：上移到**顶部条** + `第 n / total` 计数 + 首末句**禁用态** + `Alt+↑/↓`
- **声明纠正**：`PRIMARY_FIELDS` → `['Speaker','Text']`；`pick_expression`/
  `pick_position` 标注为无人调用的死方法

### 三个坑（都花了时间）

1. **`_resolve_thumb_source = resolve_thumb_source` 定义顺序**：别名写在函数定义**之前**
   → 模块导入即 `NameError` → **15 个测试文件全部收集中断**。
   改成函数包装（`def _resolve_thumb_source(...)` 转发）✔
2. **ThumbLoader 在无事件循环时退化到线程池**：测试桩没有 `after`，
   第一版 fallback 直接 submit → 每个实例化面板的用例建线程 + 解码真实大图
   → 全量跑到 41% 被拖死（SIGTERM）。加 `_can_schedule` 守卫：**没有事件循环就完全不加载**。
3. **pytest 临时目录累积**（与代码无关的老问题）：系统 TEMP 下 `pytest-of-*`
   累积近万文件 → 全量越跑越慢（200s 只到 63%，单文件跑却全过）。
   `pytest.ini` 加 `addopts = --basetemp=.pip-tmp/pytest`（固定 + 每次清空）✔

### 未做（v3 规格里剩下的）

dark 主题**切换**（token 已备，未接 UI）、Tooltip 组件、台词字数统计、
完整键盘导航（←→ 切 chip）、滚动条样式、Sticky 分组头。

### 上轮判断的修正（诚实记录）

上轮我说"表情/位置有**两个编辑入口**，用户必然困惑"——**说过头了**。
实际读代码后：面板级 `Expression`/`Position` **根本没有控件**（`_build` 只建了
Speaker/Text），`pick_expression`/`pick_position` 无人调用。
所以真问题是"**声明与实现不一致**"（会误导后来人），不是用户可见的双入口。
用户看到的困惑来自**展示层**：每个 show 子项摊成一行 → 同角色换表情像两个人 ✔

## 卡牌编辑器界面设计规格 v3（细节级，可直接开发）

文档：`docs/卡牌编辑器界面设计规格_v3.md`（v1 方向 → v2 方案 → **v3 实施规格**）。

**覆盖**：窗口骨架精确分区（1440×900：顶部条 40 / 左栏 340 / 右栏 1060 / 底部条 40，
C1–C4 第一屏不滚动）；降级（<980 宽每行 5→3 张、<860 卡片紧凑档 64×86、
<700 高继承条压缩）；**tkinter 实现策略**（无原生圆角/阴影 → 立绘卡用 Canvas 画圆角、
不用阴影、动效只改颜色不改几何）；完整 token（light/dark 两套，每项标对比度）；
11 个组件的像素规格与状态矩阵；分区级元素清单；微文案定稿；4 个任务流逐步反馈；
10 类边界场景；Tab 焦点顺序 + 键盘映射；QA 清单。

**关键规格（实施时直接照抄）**
- 立绘卡 **100×176**：图区 88×118 **恒定**（骨架同尺寸，加载不跳）、名字条 18
  （12px 字，超 12 字符截断 + tooltip）、徽标行 22（chip 20，表情在前位置在后，
  最多 2 个、第 3 起 `+N`）、✕ 视觉 16 / **命中 24** 且 hover 才显示、
  选中 = 2px 主色描边 + ✓、说话态 = 左边条 3px 主色 + `▶ 说话`
- 翻页移入顶部条 + `第 n / total` 计数 + 首末句**禁用态**（不是隐藏）
- Toast 8 秒可撤销，文案带具体名字（「已删除立绘「ling」」）
- 最小字号 **8pt**（取消现有 7pt）；焦点环 **2px #1976D2 + offset 2px**
- 继承提示色 `#0A5`（3.1:1 不达标）→ `state.info #1B7A4B`；`#9E9E9E` 仅图形不承载文字
- 台词输入用 `font.text` 10pt（比其它输入大一档）+ 字数统计（>200 字转警告）
