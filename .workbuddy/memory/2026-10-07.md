### 提议架构（四层 + 一注册表）
- **四层保真等级 T0~T3**：T0 已建模（全功能）/ T1 已声明（通用行可编辑）/
  T2 已识别形状（只读+透传）/ T3 未识别（透传+告状）。
  铁律：**T2/T3 绝不阻断其他行编辑**；等级只影响"可编辑性"，不影响"可保存性"。
- **StatementSpec 注册表**取代 15 个登记点；三来源优先级 **宿主注册表 > 项目清单 > 形状识别**；
  每条 spec 带 `source` 可追溯。内置判定必须保持优先，注册表只在内置全未命中后参与。
- **三张手维护清单**（`KNOWN_STATEMENT_HEADS` / `_CONTAINER_HEADS` / `_RENPY_STATEMENT_HEADS`）
  改为从注册表派生。
- 里程碑 **M1 止血 / M2 读 CDS 说明书 / M3 注册表接入 / M4 投影（spec 声明表格形态）/
  M5 收敛**。M1+M2 可并行。
- **三个决策点待用户拍板**：D1 未知块默认透传+报警还是拒写；D2 T1 通用行默认可编辑与否；

  保真需求就再加一个后门"。
- 明确**不改**的契约：A1（强化）、A2 / B1 / B2 / H1（不变）。

### ⚠ 性能事故（同轮踩到并修）：注册表在"不是项目"的目录上也被扫
- 现象：全量测试 **10 分钟 → 19 分钟**；定位到单条用例
  `test_incremental_patch_keeps_unknown_block` 竟耗时 **227 秒**。
- 真因：`root_of()` 推不出项目根时**退回父目录**，而上层是系统临时目录 ——
  `rglob` 去扫了成百上千个目录。
- 修法两条：① `root_of` 的"项目"判定收紧到 **有 `game/` 或 有 `rules.json`**，
  否则返回 `''`；② 出拍前 `_has_unmodeled()` **短路**（没有未建模语句根本不装配
  注册表）；③ `find_scripts` 顺带跳过**点号开头的目录**（`.pytest-tmp` 不在
  原 `_SKIP_DIRS` 里，只比全名会漏）。
- 结果：47 个用例 **240 秒 → 10 秒**。
- 教训：单元测试单条耗时异常时，**先怀疑"扫了不该扫的目录"**，别怀疑算法。

### D2 把 `while` / `for` 建模为 **T0b**（本轮第二个方向之一）
- 解析：`_RE_LOOP_HEAD`（**要求冒号收尾**）+ `LoopNode` + `_stmt_loop`
  （插在 `_stmt_say` **之前**，否则台词兜底会抢）。

### 真机首跑：7 个文件不幂等，两族

续行带着**绝对缩进**进了 payload，被当成"更深一层"，渲染再加一次基准。
→ `_shift_continuations()`。

⚠ **我第一版改错了并在同轮被抓住**：新函数对**首行**也减了 base，而调用方

**首行由调用方的 `rel` 负责、我只管续行**。

**③ 被注释掉的整块每轮被推进一层**：`#label startpomodoro:` 以 `:` 收尾，
`_opens_a_block()` 把它当成块头 → 后面那串**顶格注释**被当成它的块体，
而 `render_file_block` 给块体统一加 4 格。→ **注释永远不开块**。

### ① CST：机制是稳的，但**有三个真窟窿**，都补了

- **文档与实现相反**：模块 docstring 说 `span.end` = "子树最大行号（parser
  递归算）"，实现是"到下一条语句前一行 / 第一个顶格行"。→ 改成实现的口径
  （这正是"记忆说的和代码里的对不上"那一类坑，而且是**最权威的那份文档**）。
- **真迹可能贴错行**：`Span` 行号来自 AST（解析时），而原文切片是**挂载时又
  读一遍盘**（`analyze` 里 `fp_path.read_text`）。两次读之间文件被改写
  （本仓库"程序改代码 → 表格自动反映"就是 1.5s 轮询 + 重解析）→ 行号与内容
  不是同一份快照 → **把 A 的内容写到 B 的位置**（CST docstring 自己说这比
  "没有真迹"危险得多）。→ 修：`parse()` **整份文件只读一次**（喂给 lexer /
  顶层区间 / CST 三处），`IncrementalRenPyAnalyzer` 把解析时那一份交给
  `attach_spans`；缓存元组也带上源文本（第二次 `analyze` **一次盘都不读**）。
- **度量函数零生产调用**（又一个"悬空能力"）：`cst_coverage` /
  `format_cst_report` 只有单测在调 → 真迹退化没人看得见。→ 接进 **build
  报告**（CI 走 CLI build 每次都会打）：
  `语句原文真迹覆盖率 100.0%（3187/3187 条带逐字原文）`。

⚠ **判据第一版是空转的**：外部在 `analyze()` **返回之后**改文件，两条实现
都给出旧原文（都是"改之前"读的）→ 变异验证全绿。改成"**会变心的
`read_text`**"（第二次读同一文件就返回新版本）才真正钉住。判据 4 条 + 变异
2 次（各红 1~2 条），含"一次 analyze 只读一次盘"的**计数**判据。

### ③ 每参数一列 + 原生下拉（`BEAT_FIELDS` 动态化）

**新模块 `story/spec_args.py` = 头行参数的唯一真源**（原来扫描器长在
`pipeline/validate.py` 里，现在消费者有三个：导出摊列 / 读表折回头行 / 校验；
契约 H1 不许 `story` import `pipeline`，所以真源必须下沉）。

设计要点（**不做第二份数据**）：

- 动态列名 = `语句名·参数名`（`·` 是可见的非标识符，机器能切、人能读）；
- 列**追加在末尾**（`BEAT_FIELDS` 的下标一个都不动），且**只给这批拍里真的
  出现、且声明了 `columns` 的语句**建列 → 没有声明的项目**逐列不变**；
- 读表时把**真的改了**的参数**折回头行**（`from_row`）→ `SpecHead` 仍是单
  真源，渲染/校验/协作/卡片四条路**都不需要知道有"参数列"**；
- **等式守卫**（`set_spec_arg`）：值没变 → 头行**逐字节原样**。没有它，
  `target="ling"` 会被改写成 `target=ling`（一次导出就吃掉别人的引号）；
- 改了 → **只替换那一个值 token**（参数顺序、多余空格、行尾块标记都不动）；
  清空一格 = **删掉这个参数**；值带空格/引号 → 自动加引号（`intensity="7 8"`）；
- 下拉是**原生数据验证**（`showErrorMessage=False`：手打新值不被拦）；
  候选串 >240 字符或含逗号 → **不挂下拉**、退回注释（"少一个便利，不要坏
  一个文件"—— Excel 内联公式有 255 上限）；
- 动态格也过 `sanitize_single_line_cell` 并**留痕**（`sanitized_cells` →
  W114），否则又是"静默改数据"。

判据：`tests/test_spec_args.py`（16 条，纯函数：**引号里的 `a=b` 不是参数**

⚠ **判据是"这一列的 token"**：`stage_order` 与 `op_order` 都记，渲染器先读
`op_order` —— 变异只改 `mark_stage` 时判据**全绿**（假通过），改 `mark_op` 才红。

**② 同名同参数的重复被按内容去重**（`_join_show_items`/`_join_hide_items`）：
它的本意是挡 hydrate 的影子重复，顺手把作者写两遍的那条也吃了 →
`show A / hide A / show A` 变成 `show A / hide A` = **收尾画面与作者要的相反**
（玩家看到的画面不同，这才是最贵的一类）。
修法：加 `dedup` 参数 —— **作者那条路 `dedup=False`**（`from_row` 读表、
`_emit_show/_emit_hide` 解析）；**影子那条路**改成"只追加结构化列里**还没有的**"

⚠ 还不能只改 `emitted` 那个集合：它是**按文本**记账的，同名两条会在那里
再被合一次 —— 必须再加一个**按下标**的 `emitted_idx`（`(verb, 下标)`）。

（假阳探测：diff 一有假阳，人就会忽略冲突报告）+ **变异**（真机里改一拍台词
