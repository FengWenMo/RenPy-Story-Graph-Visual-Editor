## 二、E1 实现（两个模块 + CLI + 41 条判据）

| 文件 | 角色 |
|---|---|
| `storygraph/core/engine_facts.py` | **纯数据层**（零依赖）：schema / 校验 / 查询 / 合并。**任何层都能用**（不违反 H1） |
| `storygraph/pipeline/engine_collect.py` | **采集器**：找 SDK → 生成探针 → 跑 `lint --error-code --json-dump` → 收割 → 清理 → 写盘 |
| `storygraph/cli.py` | 新命令 **`engine-facts`**（`--project/--sdk/--out/--mode/--timeout`） |
| `tests/test_engine_facts.py` | **42 条**（纯层 + 采集器；E2E 那 6 条真跑 SDK） |

**关键设计（都对着实测的坑）**：
- **每条事实带 `source`**；没有 source **校验不过**（查不出来源就没法判"引擎变了没有"）。
- **两个来源不一致 → 记 `conflicts` + `source='conflict'` + 值取并集** —— 不许静默挑一个。
- **`is_collectable()` 是硬闸门**：`parse_clean` / `probe_complete` 任一为假 → 采集不可用（坑 2/坑 4）。
- **lint 三类分桶**：parse（阻塞）/ semantic（图像引用、资源）/ **program（程序自己的 `lint=` 回调，N4）**；
  ⚠ `clean=False` 时把 semantic **重分类为 parse** —— 引擎中止了，"没有语义错误"不可信。
- **探针由工具生成、注入、跑完连 `.rpyc` 一起删**（N7）；`_write_probe` **同名非本工具写的就拒写**。
- **`errors.txt` 是「挪开→跑→读→还原」，不是删掉**（真机根目录本来就有这个文件）。
- `--json-dump` 与探针的产出**合并成一份** facts，各带来源。
- `_sha1_manifest` 只哈希 `game/` 下的**文本**文件（真机 1.9GB 图片不哈希；我们从不写它们）。
