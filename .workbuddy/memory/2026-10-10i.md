## 二、设计稿的骨架（给未来的自己留一份索引）

1. **三种"不认识"**：保管（底线）/ 认人（可长）/ 懂业务（永远靠人点）—— 核心洞察；由此推出"宁可说不认识，也绝不装作认识"。
2. **现状七病**：满嘴机器词 / 参数表一行一个 / **把内置语句当不认识（在教错人）** / 候选要手填 / 学习与使用两条链断开。
3. **三条地基**：保真（结构性保证）、通用（不写死任何项目的词）、易用（编剧三层信息：清单/要填什么/长什么样）。
4. **四条"学会"途径 + 优先级**：宿主说明书（Ren'Py CDS）> 项目声明（`rules.json`）> 从真实脚本反推 > 人当场教（落成声明）。
5. **一处声明、四处生效**：表格列 / 卡片控件 / 校验 / 报告（"投影"思想，抄 MPS）。
6. **卡片里的落点**：卡片「＋加一个动作」（中文名下拉）+ **动作清单页**（回答"一共有多少动作"，含"工具自带"标注 + 导出给编剧）+ 三段式弹窗（参数竖排、真实控件预览）。
7. **`swim_suit` 两条正路**：A 服装=立绘属性（与表情共用下拉，分栏用词组分组）；B 自定义指令（声明参数 → 卡片控件 + 表格动态列）。口诀：改画面上的角色→A；是个事件→B。
8. **新模块闭环**：程序改代码 → 工具发现 → 人点头 → 落成声明 → 立刻生效；三条不可破规矩（不偷偷写、不猜意思、先问角色表）。

10. **调研六条**（附来源）：Ren'Py CDS / Yarn Spinner 定义文件+自动发现 / articy:draft 模板 / MPS 投影编辑 / Roslyn·tree-sitter 无损+容错 / 渐进类型。

## 三、调研要点（以后可复用）

- **Ren'Py CDS**：`python early:` 里 `renpy.register_statement(name, block, parse, lint, execute, predict, next, scry, init, translatable, ...)`。规则：必须在 `python early`；定义文件必须**先于使用它的文件**加载（文件名前缀数字）。→ **宿主已公布语法形状，工具不该不看**。
- **Yarn Spinner**（最贴切的样板）：`.ysls.json` **定义文件**、或**直接从 C# 源码自动发现**命令/函数 → 插件给编剧**自动补全 + 类型检查 + hover 文档**。同一份 `.yarn` 在 **Unity / Godot / Unreal** 都能跑。
- **Naninovel**（Unity VN）：`[CommandAlias("hello")]` + `[ParameterAlias]` + `[RequiredParameter]`，C# 类自动被引擎拾取；**改了 C# 命令实现要 Reimport 场景脚本**（导入期解析编译）。
- **articy:draft 模板**：三层（属性定义→特征→模板）；对象挂恰好一个模板；**改模板 → 所有对象自动更新**。
- **MPS 投影编辑**：同一模型可多记法（文本/表格/图/数学）；不靠 parser 因此能组合语言。→ 表格与卡片都是"投影"。
- **Roslyn / tree-sitter**：trivia 全保真、可逆、错误用节点表达（不丢弃）、容错解析（一行坏不搞坏全份）。
- **渐进类型**：`any` 是**显式逃逸**不是失败 → 对应 T3"声明的逃逸舱口，且逃逸永不丢内容"。

## 四、口径（本轮拍定的说法）

- **说人话**：设计稿正文不用 `T1a`/`rules.json`/`spec_args`/IR/opaque 等词；必须提时用**小字【给程序看】**标出，编剧可跳过。
- **每个观点附"为什么"**：这是用户明确要求；写"不许"而不知道理由，下一个人会当教条绕过。
- **"没有声明 = 完全平铺"**（通用性底线）：一般人没有"服装"概念，就不该看到分栏。**少了是保守，多了是骗人。**
